# Add the sanitized audit projection and consolidated report over an archived Attempt

Implement BP6a: a pure, read-only projection of an already archived Attempt directory into a shareable `audit.json` (schema `wfc.audit/1`), and a consolidated `wfc report` computed from that projection. Governing text: BP6 in docs/backlog/beta1_execution_plan.adoc and docs/backlog/beta1_productization.adoc (read the BP6 sections and the DG-1/DG-2 rows), and in docs/warm_storage/concepts/wfc_beta1_product_boundary_review_second_pass.adoc the sections `Audit projection`, `What stays verifiable without the raw files`, `contract-audit` and `contract-report`. BP6a does NOT wire anything into `wfc run`/`wfc resume`, does NOT add `evidence.raw` configuration, does NOT touch `wfc init` and does NOT commit anything: those are BP6b. Decisions already made: DG-1 (b): token usage is not a release gate; every Hop carries a nullable `usage` field that is `null`, never zero, because no adapter reports it yet. DG-2 specifics (maintainer-recommended): the projection is derived from persisted facts only; no retention cap; raw retention (`local|commit|discard`) is a BP6b setting and only recorded here as a caller-supplied string.

Inputs: an archived Attempt directory as written by frontdoor/archive.py (`manifest.json`, `run/operator-plan.json`, `run/operator-summary.json`, `run/checkouts/<id>/run.json`, `.../execution-evidence.json`, `ops/*`). Real read-only examples live in the sibling Evidence repository `../workflow-coordinator-run-evidence/archive/unclassified/`: `wfc-beta1-bp4-lifecycle-controller-001-20261119-01` (completed, two blocking Finding cycles) and `wfc-beta1-bp4b-candidate-preservation-001-20261119-01` (stopped `awaiting_human_budget`); if that path is not readable, derive the shapes from the engine writers in src/workflow_coordinator. Never use those directories in tests: tests build SYNTHETIC archive trees with a helper in tests/fixtures/bp6/ (completed, finding-bearing, stopped `awaiting_human`, stopped `awaiting_human_budget`, `reconcile_required`, a Run with an anomaly) carrying a known fake home directory, user name, scratch path, state and ops paths and provider prose so the privacy property can be tested.

Deliver:
1. `frontdoor/audit.py`: `project_audit(attempt_dir, *, raw_retention="local", lifecycle=None, private_strings=()) -> dict` and `write_audit(...)`. The projection is built by an explicit allow-list of fields (default deny): never copy-and-scrub a source object. Field list (frozen, version `wfc.audit/1`): `schema`, `attempt_id`, `run` {run_id, work_item_id, status, stop_reason, hops_used, hop_limit, baseline_head, final_head, worktree_clean, human_question_present (bool; the question text is excluded), semantic_stop_present (bool)}, `governance` {policy_id, policy_revision, profile_id, profile_revision, agent_contract {id, version, sha256}, governing_inputs (repository-relative path -> sha256 as in the plan), component digests, role_bindings {role: adapter, model, reasoning}, executable {name (basename of the authored name only), no path}}, `hops` [per Hop: hop_id, sequence, phase, role, adapter, model, reasoning, outcome, applied_route, commits (hashes only), finding_delta_ids, usage (null), trusted evidence [command_name, status/error_class, exit_code, argv_digest, stdout/stderr digests when present, executable identity stability only if both fingerprints are persisted]], `findings` [finding_id, state, blocking, disposition, introduced_by_hop, changed_by_hop; NO invariant text, NO evidence prose], `anomaly_count` (anomaly text is provider/engine prose and is excluded), `lifecycle` (null, or the supplied facts: classification, and an optional preservation fact {outcome: result|refused|not_needed, ref, commit, tree, file_count, bytes, quiescence, reason_code}; reason strings that are free text are excluded), `raw` {retention, manifest_sha256, files [{path, sha256, bytes}] copied exactly from the raw manifest}. Facts not persisted are omitted or null, never guessed; a missing source file for a field makes that section null with a named `limits` entry, not a crash. `limits` is an array of stable machine codes such as `usage_not_reported`, `preservation_not_recorded`, `no_lifecycle_facts`.
2. Privacy as a mechanism, not a convention: after building, a final guard refuses to produce output (ProjectionError naming only the JSON path, never the value) when any string value is an absolute path (POSIX or Windows) or contains any caller-supplied private string (home, user name, scratch/state/ops paths) or a Git remote URL. Persona text, provider prose, diagnostics, summaries and Finding text must be unreachable by construction (test with canary strings planted in every source field).
3. Determinism and integrity: byte-identical output for identical input (sorted keys, stable ordering by sequence, newline-terminated, no timestamps); every raw digest equals the manifest's; `write_audit` writes `audit.json` beside `manifest.json` create-only via a temporary file and rename, treats identical existing content as a no-op, refuses different existing content, never edits manifest or raw files, and performs no Git operation.
4. `frontdoor/report.py`: `build_report(audit) -> dict` and a text renderer following the `contract-report` block (outcome, run and program, hops used of limit, commits, evidence line, findings, archive reference when supplied, explicit `not done`/limits lines). For a stop the outcome carries status and stop_reason, open blocking Finding identifiers, and ONE line naming the next human choice from a fixed table keyed by status (`awaiting_human`, `awaiting_human_budget`, `reconcile_required`, `stopped`, `interrupted`, `uncertain_launch`); unknown statuses are reported as unknown, never as success. The report interprets nothing the engine did not persist and never claims anything was pushed or verified beyond the audit's own facts. `--json` emits the same content.
5. CLI: `wfc audit <attempt-dir> [--raw-retention local|commit|discard] [--lifecycle-json FILE] [--private-string S ...]` and `wfc report <attempt-dir-or-audit.json> [--json]` dispatched from frontdoor/cli.py (minimal additive dispatch; existing dispatch unchanged). Exit codes: 0 ok, 2 refusal/usage, 3 projection refused by the privacy guard.
6. Developer-facing limitations record: the projection is derived from the archived Evidence, not independently verifiable beyond the listed digests; trusted outcomes are the Coordinator's attested observation; usage is reserved and null; lifecycle/preservation facts are only present when a caller supplies them (BP6b wires them in); pre-projection archives are not rewritten.

Hard rules: no engine change; no change to archive.py, journal.py, lifecycle.py, preservation.py, git_facts.py, reducer, Finding, review, routing, adapter or admission code; no lifecycle wiring, no `evidence.raw` configuration, no `wfc init` change, no archive or Git commit written by the new code; no new Findings schema beyond fields already persisted; no lineage/continuation fields; no fabricated values; no network, no pip; Python 3.10-3.13 stdlib only; kernel modules never import frontdoor; no edits to the operator manual or backlog. CommitIntent: name every changed/new/deleted leaf individually, never directories; avoid rename-shaped changes. Deliver ONE complete candidate in the first Worker Hop; subject must contain WI-WFC-BETA1-BP6A-AUDIT-PROJECTION-001 and the actual Hop ID. No Git writes by the agent.

Reviewer (fresh, adversarial): evaluate the ENTIRE product against the baseline and this task. For each acceptance case require a test that fails against a mutation of the guarded behavior; reproduce the privacy property with canary strings in every source field including list elements and nested keys; check that every field in the projection is on the frozen allow-list and no free text can reach it; check digests equal the manifest's; check determinism and create-only/idempotent writing; check the report never reports success for an unknown or stopped status. Scope of "blocking": a reproduced violation of an explicit acceptance case, of the privacy property, or a crash on a plausible archive of this repository's own Runs. Exotic inputs outside the acceptance list (for example hostile non-JSON bytes in an archive that the archiver itself would have refused) are non-blocking observations, not Findings. `finding_authority: [resolve]` does not authorize residual transitions: report non-blocking observations in the review artifact and summary only. Coordinator full task-check is mandatory and not replaceable by agent-side tests.


## Acceptance

Each case is covered by a test with a mutation-sensitive assertion: (1) completed Run projects every field of the frozen list with the exact source values; (2) privacy: for a Run with known home directory, user name, scratch/state/ops paths and canary prose in every source field, `audit.json` contains none of them, no absolute path, no persona, no provider prose, no diagnostics, no Finding text; (3) every raw file digest and byte count in `raw.files` equals the raw manifest's, and `manifest_sha256` equals the manifest file's digest; (4) finding-bearing Run: Findings appear as identifier/state/blocking/disposition only; (5) stopped `awaiting_human`, `awaiting_human_budget` and `reconcile_required` Runs project truthfully, with `human_question_present` and stop_reason, never as completed; (6) supplied lifecycle facts (interrupted, uncertain_launch, a preservation result and a preservation refusal) are projected, absent lifecycle facts yield `lifecycle: null` plus the `no_lifecycle_facts` limit; (7) `usage` is null for every Hop and never zero; (8) missing optional source file yields a null section and a named limit, not a crash; (9) deterministic bytes for identical input, different bytes when one fact changes; (10) `write_audit` is create-only, idempotent for identical content, refuses different content, leaves manifest and raw files byte-identical, and creates no Git object; (11) the privacy guard refuses an injected absolute path or private string with exit 3 and writes nothing; (12) `wfc report` for completed, finding-bearing and every stop status, text and `--json`, with the fixed next-choice line and no claim of success for a stop or an unknown status; (13) CLI dispatch and exit codes; existing dispatch unchanged; (14) the architecture import-direction guard, BP4a/BP4b/archive tests and the existing suite pass unchanged; (15) a BP6a limitations record states the derivation limits, null usage and the absent lifecycle wiring. Independent review with no blocking Findings; Coordinator full task-check passes; completed Run.

Escalate a genuine need for new authority or design, any conflict with DG-1/DG-2 as recorded, any field whose source cannot be established from the archived files (omit it with a limit and say so), or inability to meet the matrix without changing archive or lifecycle behavior.
