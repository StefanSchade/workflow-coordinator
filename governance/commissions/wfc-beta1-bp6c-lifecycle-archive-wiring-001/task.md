# Wire archive, audit projection and report into the installed lifecycle after classification

Implement BP6c: after `wfc run`/`wfc resume` has recorded `classified` (and run the pending BP4b preservation step), archive the Attempt into the configured Evidence repository with the configured raw retention, project `audit.json`, and print the consolidated report. Governing text: BP6 in docs/backlog/beta1_execution_plan.adoc and docs/backlog/beta1_productization.adoc (including the 2026-11-20 package-boundary paragraphs), the second-pass review sections `Lifecycle` (exit codes, resume table), `Commit ownership, idempotency and integrity`, `contract-report`; read the BP4a, BP4b, BP5, BP6a and BP6b limitations records and review artifacts and the code of frontdoor/lifecycle.py, journal.py, preservation.py, archive.py, audit.py, report.py, config.py first. The accepted BP4a/BP4b products are FROZEN: their records, classifications, exit codes, transitions and preservation behavior do not change.

Decisions already made (do not reopen): the Evidence repository is a configurable archive destination, never an engine state root; the STATE root stays where the engine wrote it and is only READ by the archive; `evidence.raw` is `local` (default) | `commit` | `discard`; nothing is ever pushed; Level-1 style intervention inside a live Run is not part of the design; the lifecycle controller adds steps AFTER the engine ended and never reinterprets the engine outcome.

Deliver:
1. New `frontdoor/postrun.py` and minimal additive hook calls in lifecycle.py: after `classified` and after `run_pending_preservation`, `run`/`resume` execute ONE pending post-run step per checkout, idempotent and crash-safe: (a) read the Consumer Config from the checkout's cached authorized materials; resolve the Evidence settings with `config.resolve_evidence`; (b) for classifications that have engine state (completed, awaiting_human, awaiting_human_budget, reconcile_required, stopped, interrupted) archive from the engine state root with `archive.archive_run(..., raw_retention=settings.raw)`; never for `engine_exited_before_state` (no state) or for non-terminal/refusal classifications; (c) when the Evidence repository does not exist, record `ext.archive.skipped{reason: "evidence_repository_absent"}` and print a loud `ARCHIVE SKIPPED` line naming the configured location and `wfc init`; this is NOT a failure and does not change the exit code; (d) project the audit with the lifecycle facts supplied: the BP4a classification and the latest BP4b `ext.preservation.*` fact (result | refused with reason code | not_needed), then print the consolidated report (text) built from the audit; (e) a second `run`/`resume` after success is a no-op (no second archive commit, no second report side effect other than the read-only print).
2. Journal records, all opaque `ext.*` per the BP4a contract and ignored by BP4a decisions: `ext.archive.intent` before the archive effect, `ext.archive.result{outcome, commit, destination_relative, retention}` , `ext.archive.refused{reason_code}`, `ext.archive.skipped{reason}`; a crash between archive commit and result record is resolved by the archive's own idempotent no-op detection (no second commit). ## Acceptance

Each case has a mutation-sensitive test: (1) completed Run: archived once with the configured retention, audit.json in the same single commit, report printed, exit code 0 as before; (2) stopped (awaiting_human, awaiting_human_budget, reconcile_required, stopped) and interrupted Runs: archived and reported with their own classification and unchanged BP4a exit code, never as success; (3) `engine_exited_before_state` and non-terminal classifications: no archive; (4) Evidence repository absent: `ext.archive.skipped`, loud ARCHIVE SKIPPED line, exit code unchanged, nothing created; (5) archive/audit failure or privacy-guard refusal: `ext.archive.refused`, additive `archive_failed` exit code, engine classification unchanged, `wfc resume` retries and succeeds once the cause is removed; (6) idempotency: a second run/resume produces no second commit; crash after commit before result record and crash before the archive both resume correctly; (7) the audit carries the BP4a classification and the BP4b preservation fact (result, refused, not_needed); (8) `wfc status` read-only and reports the archive facts; STATE root, OPS and scratch byte-identical before/after the post-run step; (9) all three retention modes through the lifecycle (git ls-files per mode); (10) ext.* archive records contain no absolute path or provider prose; (11) short user-name substring no longer causes a false refusal, a real user-name path-component leak is still refused; (12) BP4a/BP4b/BP5/BP6a/BP6b tests, the architecture import-direction guard and the existing suite pass unchanged; (13) BP4a exit-code values and the `classified` record fields unchanged; (14) a BP6c limitations record states the semantics and limits.
