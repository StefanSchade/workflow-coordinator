# Implement consumer-neutral Commission compilation with separate execution bindings

Implement BP2b only, using docs/backlog/beta1_execution_plan.adoc and docs/backlog/beta1_productization.adoc and the current source as the basis. BP1, BP8 and BP2a are independently accepted; BP2a candidate `c7b84e2` and its independent Opus audit RUN-99950ca4171448f5885eadfa0bf1dffc are evidence, not a replacement for inspecting current code. The simplified API sketches in the plan are proposals: current `operator.admit_parsed` and its explicit caller obligations are binding starting conditions. Inspect current `_preflight`, `admit_parsed`, `commissioning.py`, `evidence.py`, tests, resource and packaging mechanisms and BUG-WFC-EVIDENCE-COMMAND-CONSUMER-NEUTRALITY. Current `commissioning.py` implements v1 `render_commission`/`verify_render_manifest`; `compile_commission`/`verify_commission` do not yet exist. Add the needed BP2b entry points while preserving v1 render, verification and self-development semantics.

Implement a narrow consumer config and bounded request, with package-owned product resources and consumer-specified repository guidance frozen at Commission creation, traceable origin and digests. Bind the same guidance into the existing `repository_policy` component slot for every phase; role behavior remains with existing role components. Guidance cannot widen scope, actions, routing, authority or Finding authority. Support only existing `simple@v1` and `robust@v1` for this product path; do not invent new Workflow Programs, revisions or direct@v1 product support. Consumer projects need not have WFC self-development governance or Python structure. Consumer evidence command must support a bounded own shell check through existing trusted evidence mechanisms while keeping the legacy WFC-specific exact Python policy validation unchanged. Policy/permission scope, actions, components and evidence remain bounded and A1-safe; do not relax Python safeguards or any old admission behavior.

Implement deterministic compile/verification and frozen-resource tamper refusal, including provenance and exact path ownership. Execution bindings are not part of immutable business Commission bytes: reject binding/provider/model/effort fields in the request; put execution choices in a separate resolver conceptually `resolve_execution(config, overrides, roles)` with its own stable identity/digest. Same request/config guidance produces byte-identical Commission artifacts across at least two different permitted provider/model bindings, with differing execution-envelope digests; no mixed adapters within a Run. Product resource tampering and consumer guidance tampering must be detected. Preserve every semantic field of existing v1 simple and robust profile output except deliberately changed guidance/component paths, and document those differences.

For the consumer path, reuse `operator.admit_parsed`; do not duplicate admission. Its docstring explicitly makes the caller responsible for strict parse of corresponding objects, exact binding source/config provenance, matching normalized paths and pinned texts, repository identity, full clean expected HEAD with resolved submodules, nonexistent resolved state root, and operating-contract validity. Establish and test all of these before the call, including validation that any matching texts were read at the pinned revision. Verification and admission must refuse frozen-asset tampering and do not merely rely on advisory docstrings or a different unchecked working-tree object. Keep old `_preflight` order, behavior and security invariants unchanged; a minimal shared adapter/helper is allowed if it demonstrably preserves old observable behavior, no broad refactor.

Acceptance uses a real disposable non-Python Git repository with an executable shell check, no WFC governance/self-development files and no inherited Python-project assumptions. For both simple and robust: create bounded request and config, compile, verify, manually commit (or simulate the existing authorized commit path inside the disposable test only), establish all admission preconditions and pass existing admission. Compare fixed Commission bytes with at least two execution configurations and differing execution digests. Verify negative cases: forged binding keys in request, changed pinned guidance and product resources, uncommitted/changed/mismatched text/provenance/repository/HEAD and binding provenance, scope/path traversal and authority widening. Prove frozen resources reach the existing engine authority boundary, not merely that a standalone hash helper notices a mutation. Confirm the v1 compiler and self-development route remain compatible, all current tests and security checks run without relaxed assertions.

No BP3 init/plan or trusted commit product mechanics, BP4 lifecycle/preservation, BP5 archive, BP6 audit, BP7 cutover, BP9 product qualification, direct@v1, continuations, mixed providers within a Run, ASE integration or new Workflow Programs. No changes to provider adapters, reducer, WFC runtime or existing governance programs; do not mutate external Evidence. New packaging resource declarations only if actually needed. Use `tests/` for bounded code/acceptance tests and current documentation/controlling BUG record only for the actual implementation milestone; distinguish independent acceptance and product closure, do not claim either prematurely. An inability to safely satisfy the admission trust contract is a concrete blocker; do not work around it by reducing authority checks.

Use verified offline inputs and existing isolation when testing; no package-index dependency, disabled checks or hidden skips. The Coordinator independently runs the full configured task-check. Report local checks and limits. CommitIntent lists exact changed repository-relative leaves, with a Conventional Commit subject containing WI-WFC-BETA1-BP2-CONFIG-COMPILER-001 and actual Hop ID as separate tokens; agents do not write Git commits. Review artifacts belong to their respective reviewer phases.

Fresh independent Opus broad reviewer inspects real source, caller preconditions and real consumer-neutral end-to-end tests, not merely worker statements: compare strict parsing and matching pinned inputs, repository/HEAD/clean-state and state-root/binding/contract provenance before `admit_parsed`, tamper and A1/authority failures, separate Commission/execution identity, profile equivalence and unchanged legacy render/self-development behavior, shell-evidence and retained Python-policy protections. Confirm all negative cases reach real production boundaries, not test-only stubs. Inspect concrete scope and no excluded package implementations. Raise only material reproducible Findings; route corrections and focused/fresh broad review under robust@v1. No extra governance gates or speculative requirements.

Consumer-neutral simple@v1 and robust@v1 compilation, verification and existing admission against a clean non-Python Git repository and real shell check; frozen guidance/resource tamper and authority/path/binding failures rejected; original v1 and self-development behavior retained; separate execution-envelope identity with unchanged Commission bytes under different bindings; BP2a caller preconditions established. Independent broad review accepts without blocking Findings and Coordinator full task-check passes.

No additional Commission, live-provider tests beyond this Run, push, merge, rebase, Runtime promotion, historical review edits, agent Git writes or Evidence repository mutation.
