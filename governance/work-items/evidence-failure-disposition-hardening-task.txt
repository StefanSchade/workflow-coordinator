======================================================================
WHAT THIS COMMISSION MEANS
======================================================================

Today, `ReviewDescriptor.failed_evidence_route` may only name a route whose
effect is `RouteEffect.GOTO`. Omitting the field, and declaring it pointing
at anything else, both currently fall back to the same generic human stop
(`required_evidence_failed_without_route`) -- making an accidental omission
and a deliberate human-disposition choice structurally indistinguishable at
authoring time. Three P2 Runs
(RUN-90c24baad80645b0958ed96ae0a2cc3f, RUN-d5ae5bd0eadb41dba2c10c1d085e6c4d,
RUN-6fa0b56e3b844896a55f147f4ee41fea) stopped before ever reaching an
independent review because of exactly this ambiguity in their Commission
topology -- not because of any defect in the trusted-evidence or routing
mechanics. The corrected successor, RUN-26e233c979554260bcca8529d1b72c1f,
completed in two Hops using the canonical shape of
docs/wfc_operator_manual.adoc section 22.4.

This Commission makes the deliberate choice machine-checked at NEW-launch
admission time, reusing the existing `RouteEffect.AWAIT_HUMAN` effect as a
second valid target for `failed_evidence_route`, rather than inventing any
new schema concept. The full semantic detail is already fully specified in
the design record; this task text governs what THIS Commission must
additionally do to implement, review, and land it.

======================================================================
STATIC ADMISSION INVARIANT (verbatim from design section 6)
======================================================================

Every newly admitted phase whose Coordinator-required evidence tuple is
non-empty must be a gate review (`review.authority == GATE`) that explicitly
declares `review.failed_evidence_route`. That key must name one of the
phase's own routes whose effect is either `GOTO` or `AWAIT_HUMAN`. A phase
whose evidence tuple is empty is exempt from this invariant entirely.

Valid: any phase with `evidence: []`; a gate with non-empty evidence and a
`GOTO` failed_evidence_route; a gate with non-empty evidence and an
`AWAIT_HUMAN` failed_evidence_route.

Invalid, for NEW-launch admission only: a non-gate phase declaring
non-empty evidence; a gate declaring non-empty evidence with
failed_evidence_route omitted; failed_evidence_route naming an unknown
route or a route whose effect is neither GOTO nor AWAIT_HUMAN.

======================================================================
NO NEW SCHEMA CONCEPT
======================================================================

Do NOT introduce: `evidence_failure_disposition`; a new disposition enum; a
sentinel such as `failed_evidence_route: human`; another route namespace;
another routing mechanism; another persisted Run field. Reuse
`failed_evidence_route` and the existing `RouteEffect.AWAIT_HUMAN` exactly
because the design (section 4) rejected every alternative that would
duplicate routing semantics already present in `Route`/`RouteEffect`.

======================================================================
PRODUCTION CHANGE SHAPE
======================================================================

Bounded to exactly three files:

  src/workflow_coordinator/serialization.py
  src/workflow_coordinator/reducer.py
  src/workflow_coordinator/operator.py

serialization.py
----------------
- Permit `failed_evidence_route` to resolve to `GOTO` or `AWAIT_HUMAN`
  (currently the per-phase route-shape check at the profile level rejects
  anything but `GOTO`). Preserve rejection of every other `RouteEffect`.
- Adjust the existing v3 evaluator's permitted-goto-key accounting: it
  currently adds `phase.review.failed_evidence_route` unconditionally to
  `permitted_goto_keys`, then compares that set for exact equality against
  `goto_route_keys` (routes whose effect IS `GOTO`). If
  `failed_evidence_route` resolves to `AWAIT_HUMAN`, it will never appear in
  `goto_route_keys`, so the unconditional add would make the exact-set
  comparison fail incorrectly for an otherwise-valid v3 evaluator profile.
  Fix the accounting so an `AWAIT_HUMAN`-targeting failed-evidence route is
  not counted as a `GOTO` route in that comparison.
- Do not redesign WorkflowProfile serialization otherwise.

reducer.py
----------
- In `reduce_result`, the clean-required-evidence-failure absorption
  condition currently requires `failure_route.effect is RouteEffect.GOTO`.
  Widen it to accept `GOTO` or `AWAIT_HUMAN`. Reuse the existing
  `_apply_route` dispatch unchanged -- `_apply_route` already owns
  `AWAIT_HUMAN` semantics (mandatory authored `question`,
  `_stop_for_human(run, f"route:{route_key}", route.question)`). Do not
  create a separate evidence-specific human-stop branch.
- Preserve existing behavior for evidence `PASS`, `ERROR`, malformed
  evidence, and `not_run`/mechanical evidence failure.

operator.py
-----------
- Add one small, self-contained new-launch admission predicate,
  conceptually `_admit_evidence_disposition(profile)` (exact naming may
  follow repository convention), structurally a sibling to the existing
  `_admit_a1`. It enforces exactly the invariant above: for each phase, if
  `phase.evidence` is empty, no restriction; otherwise the phase must be a
  gate review declaring `review.failed_evidence_route`. Route
  existence/effect validity (unknown route, wrong effect) is already owned
  by serialization/profile validation -- do not duplicate that check here.
- Invoke it from `_preflight()` and from `_prepare_successor()`.
- Do NOT invoke it from `_export_salvage()`.
- Do not redesign general preflight architecture.

======================================================================
WORKER-EVIDENCE SEMANTICS
======================================================================

Preserve the accepted design decision: a NEW admitted non-gate phase
(worker, advisory, or a v3 convergence corrector) may not declare non-empty
Coordinator-required `evidence:`. This does not prohibit an agent from
executing tests diagnostically in its own shell. Keep the distinction:
agent-side tests are diagnostics; `phase.evidence` is Coordinator-required
trusted acceptance evidence. Worker completion remains "bounded candidate
coherent and ready for its declared next step," never "proof that
downstream acceptance evidence already passed."

======================================================================
AWAIT_HUMAN SEMANTICS
======================================================================

Do not invent new human-stop behavior. Reuse the current
`RouteEffect.AWAIT_HUMAN` behavior exactly. A failed-evidence route
targeting `AWAIT_HUMAN` must use the route's existing authored `question`
and normal `_apply_route()` / human-stop semantics. Expected observable
clean-failure shape: `stop_reason == "route:<route-key>"` with the
explicitly authored question surfaced through existing Run mechanics. Do
not fold this into `required_evidence_failed_without_route` -- the whole
point is that this is now an EXPLICIT authored disposition.

======================================================================
WORKER COMPLETION SEMANTICS
======================================================================

Per docs/wfc_operator_manual.adoc section 22.2: worker `status: completed`
means the bounded candidate for this phase is coherent and ready for its
declared next step. It does NOT mean the worker has proven all downstream
trusted acceptance evidence -- Coordinator-trusted evidence runs after the
semantic result and after any admitted Coordinator-owned commit. Agent-side
tests, including a full-suite run in the agent's own sandbox, are
diagnostic input, never Coordinator-trusted evidence. A red agent-side
suite is NOT by itself a reason to return `blocked`; inability to run the
full suite in the agent sandbox is NOT by itself a scope escalation.
Report diagnostic limitations truthfully in `summary`. `blocked` is
reserved for a real missing authority, scope, prerequisite, or capability
needed by THIS Hop -- never for a downstream gate that has not run yet.
