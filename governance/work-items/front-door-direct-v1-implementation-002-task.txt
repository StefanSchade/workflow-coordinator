IMPLEMENTATION (phase `implement`):

1. New module `src/workflow_coordinator/commissioning.py`, a non-authoritative
   parser/renderer. It must not be imported by reducer.py and must not alter
   operator.py::_preflight's admission semantics. It provides at least:
   - `commission_intent_from_yaml(text) -> CommissionIntent`: parse and
     validate a Commission Intent against exactly the field contract in
     design section 3's table and the forbidden-parameter list in section
     2.1. Reject (do not silently drop or widen) any forbidden field: phase
     or route declarations, route effects, initial-phase overrides,
     WorkflowRole creation, phase actions, gate descriptors/breadth/context,
     `finding_authority`, evidence command argv/timeout,
     `failed_evidence_route`, program components, policy governance paths, a
     model/adapter/binding, or a switch that omits a program-required
     review. Define `CommissionIntent` and any other new data shapes
     locally in this module (not in model.py).
   - `render_commission(intent, *, repository, ...) -> RenderedCommission`
     (exact signature your choice): perform exactly the deterministic
     projection steps in design section 4.1 -- resolve program/policy-basis/
     component-manifest at their pinned `source_commit`s; verify roles,
     evidence-profile identifier, artifact keys, hop bound, A1-normalized
     paths, and scope against the selected closed program and policy basis
     (reject rather than add a fallback; narrow, never widen); render the
     WorkItem, WorkflowProfile, RepositoryPolicy, and task text using the
     *existing* schemas consumed by `work_item_from_yaml`,
     `workflow_profile_from_yaml`, and `repository_policy_from_yaml`
     (serialization.py, unchanged); reference the existing component
     manifest unchanged. For direct@v1 specifically, the rendered profile
     must be byte-for-byte equivalent (modulo the Intent's own `scope` S and
     evidence selection E) to the literal record in design section 5.1:
     phase `implement` is role `worker`/`[worker]`, no artifact,
     `authorized_scope: S`, `[edit, commit]`, no evidence, `review: null`,
     only `verify: {effect: goto, target: verification}`; phase
     `verification` is role `worker`/`[worker]`, no artifact,
     `authorized_scope: S`, `[review]`, evidence `E` (`[]` for `none`,
     `[task-check]` for `task-check-v1`), review descriptor exactly
     `purpose: deterministic task-check disposition only; no semantic
     review`, `breadth: verification`, `authority: gate`, `context: fresh`,
     `blocking_policy: blocking_only`, `trigger: profile_selected`,
     `exit: declared_route`, `finding_authority: []`,
     `failed_evidence_route: correction`, and only
     `accept: {effect: complete}` / `correction: {effect: goto, target:
     implement}`. Every phase has `human_gates: []`, `components.modifiers:
     []`, `components.repository_policy: []`.
   - `verify_render_manifest(...)`: emit the non-authoritative render
     manifest described in design section 4.1 item 4 (source identities,
     target paths, and a digest for every governing input and selected
     component) and implement the equivalence procedure in design section
     4.3 steps 1-4: given an observed clean repository HEAD `H`, read the
     Intent and proposed governing blobs from tree `H`; resolve the
     program/policy/component-manifest/selected-component source objects at
     their Intent-pinned `source_commit`s (reject missing, ambiguous, or
     mismatched objects before considering the rendered tree); rerun the
     projector into a fresh temporary output from only the Intent blob and
     those pinned source objects; byte-compare the projected WorkItem,
     profile, policy, task, and render manifest against the blobs at `H`,
     and byte-compare the unchanged component manifest and every component
     selected by the projected profile against their declared pinned
     source blobs. The manifest itself must never contain the observed
     bundle HEAD `H` -- `H` is an input to the check, not a tracked field
     (this is the FDC001 fix; do not reintroduce the self-referential
     commit field the corrected design removed).
   - Only after every comparison in the step above succeeds, delegate to
     the real `operator._preflight()` (import it; do not reimplement any of
     its checks) with that same `expected_head=H` and the same five paths
     (work_item, profile, policy, components, task), using a disposable
     temporary `--state-root` that you create and the caller is responsible
     for cleaning up (or that you clean up yourself if that is simpler and
     documented). `_preflight` independently requires clean `HEAD == H` and
     retains every current A1, role, artifact, action, evidence, and
     Finding-admission predicate -- you are not weakening or duplicating
     any of them.

2. Catalogue entry `governance/workflow-programs/direct/v1.yaml` and
   immutable policy basis `governance/policy-bases/repository-standard-v1.yaml`

   overlaps repository policy `governance_paths` (`governance`), so no

   anywhere under `governance/`; these two files are maintained exactly
   like `governance/self-development/components.yaml` and
   `governance/self-development/repository-policy.yaml` already are. Read
   them; do not attempt to create, move, or edit them from `implement` or
   `correct` (that authorized_scope does not include `governance/` at all,
   so any such attempt is itself rejected by `_preflight`). If their

   what the fixture is missing -- a maintainer may then author a new
   revision; do not work around it by inventing a second, Run-writable
   copy of program/policy-basis data.

   The catalogue entry's actual schema (read it) encodes the literal
   direct@v1 phase graph from design section 5.1 with exactly two string
   sentinel slots, `scope: S` and `evidence: E`, on the `implement` and
   `verification` phases respectively; `evidence_profiles.none.evidence`
   is `[]` and `evidence_profiles.task-check-v1.evidence` is
   `[task-check]`. `render_commission` must substitute `S` with the
   Intent's A1-normalized `scope` and `E` with the list named by the
   Intent's selected `evidence_profile`, and must otherwise copy every
   other field of the catalogue's phase records unchanged into the
   rendered profile.

   The policy basis is an ordinary `RepositoryPolicy` (schema_version 3)
   naming `task-check` (argv `python -m pytest -q`, 900s timeout) as its

   `[src, tests, scripts, docs]` that the compiler must narrow to the
   Intent's own requested `scope` when rendering the WorkItem-specific

4. CLI seam in `scripts/wfc_op.py` (the file the design names explicitly),
   adding a new `commission` subcommand group alongside the existing
   `prepare`/`launch`/`status`/`archive` commands, without touching those
   existing commands or `run_canonical_preflight_seam`:
   - `commission render --intent <path> [--out-dir <dir>] [--check]`:
     deterministic projection only (design section 4.1). Writes the
     rendered WorkItem/profile/policy/task and the render manifest to
     ordinary working-tree files; makes no provider call and no admission
     decision. With `--check`, additionally prints the compact render
     report required by design section 3.3: the full Intent digest;
     program and policy ID/revision/source commits; rendered paths and
     SHA-256 digests; task path and digest; literal `authority_source`;
     requested scope and every effective phase scope; effective actions,
     evidence commands, gate breadth/purpose/Finding authority; required
     artifacts; selected component paths/digests; and the user-supplied
     persona text -- each fact labeled `user`, `program`, `policy`, or
     `runtime at PREPARE`, never presented as user authority when it is
     derived.
   - `commission check --intent <path> --repository <path> --expected-head
     <sha>`: runs `verify_render_manifest`'s full equivalence-then-
     `_preflight` procedure (design section 4.3) against the named
     repository at the named clean HEAD, using the rendered bundle already
     committed there. Exits non-zero and prints a clear refusal on any
     equivalence mismatch, missing/ambiguous/mismatched source object, or
     `_preflight` rejection; exits zero only when every comparison and the
     real `_preflight` both succeed. This command is deliberately
     independent of the full multi-repository Harness `prepare` envelope
     (no Runtime/Evidence pinning, no venv construction) -- it is
     preview/verification tooling usable in the current Development/
     evidence environment, not a replacement for the maintainer's existing
     authorized PREPARE/LAUNCH act.
   Exact flag names and output formatting beyond the content listed above
   are your implementation choice; keep them consistent with this file's
   existing `argparse` style.
