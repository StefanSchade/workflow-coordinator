== Exact DR1-IR-001 problem ==

The proposed schema-4 execution-evidence row required `hop_summary_sha256`
over the complete final persisted HopSummary. But a future current evaluator
Hop may need its trusted qualification while the reducer is deciding its
convergence/escape route. The final HopSummary contains reduction-owned facts
such as the applied route and stop reason. The proposed protocol is therefore
circular:

1. the trusted qualification row requires the final HopSummary digest;
2. the final HopSummary requires the completed reduction/routing decision;
3. the convergence routing decision wants to consume the trusted
   qualification row.

The H002 reviewer also rejected an implicit transient-observation shortcut as
incomplete: if live reduction uses transient trusted observations, selects an
escape route, and the authoritative Run snapshot is persisted before the
corresponding trusted evidence becomes durable, a crash can leave an
authoritative Run route selected because the Hop qualified live, but no
authoritative durable qualification input from which replay can reproduce
that decision. A stale checkpoint cannot repair an already-authoritative Run
route.

== Required correction ==

The correction must resolve DR1-IR-001 completely. The corrected Design
Revision must define:

1. EXACT CURRENT-HOP LIVE TRUSTED INPUT. State precisely what the
   reducer/integration layer consumes for the current evaluator Hop before
   final semantic routing. It may be a staged immutable attempt, a bounded
   trusted transient overlay, or another explicitly defined representation,
   but it must be Coordinator-owned, exact, deterministic, and derived from
   the same admitted required-command plan and trusted Observations used by
   durable replay. Agent prose or `evidence_refs` may not qualify the Hop.

2. NON-CIRCULAR CORRELATION ANCHOR. Remove dependence on a final
   route-dependent HopSummary digest at the point where qualification must be
   consumed. Define an exact stable correlation anchor available before the
   dependent route decision, OR define a publication/commit protocol in which
   the trusted evidence becomes authoritative before the semantic route
   depending on it becomes authoritative. Do NOT weaken exact Run identity,
   Hop identity, invocation identity, repository/base/end-head correlation,
   role/outcome constraints where legitimately available, or trusted
   required-command-plan correlation. Do not use route inference. Do not
   create a mutable `qualified=true` truth field merely to bypass the
   problem.

3. LIVE/REPLAY EQUIVALENCE. For any evaluator Hop that affects convergence
   routing: `live qualification decision == replay qualification decision`,
   using the same semantic predicate and the same trusted mechanical
   predicate. No authoritative persisted convergence route may survive if its
   authoritative replay inputs would treat the source evaluator cycle as
   unqualified.

4. CRASH/WRITE-FAILURE MATRIX. Specify the authoritative result for every
   relevant boundary, including at minimum: before trusted current-Hop
   qualification becomes durable; after trusted qualification publication but
   before Run publication; after Run publication but before
   execution-evidence publication, if the selected protocol still permits
   that state; after both authoritative inputs but before checkpoint
   regeneration; partial/failed atomic replacement; crash with dispatch
   marker present; duplicate continuation/publication attempt. For every
   boundary state, state which artifact is authoritative, whether the current
   evaluator cycle qualifies, whether a convergence/escape route may be
   present, and whether recovery continues, regenerates projection,
   reconciles, or stops fail-closed.

5. PUBLICATION ORDERING. State an exact finite sequence. Avoid prose such as
   "persist appropriately" or "ensure both are available." The sequence must
   make it impossible for authoritative semantic routing to depend on a
   trusted qualification fact that authoritative replay cannot later
   reconstruct. No generalized event store, transaction database, two-phase
   commit framework, or new persistence substrate.

6. CHECKPOINT IMPLICATIONS. Checkpoint remains derived. It may project
   convergence facts and relevant input digests, but it must never repair or
   authorize an inconsistent authoritative Run/evidence pair.

7. IMPLEMENTATION SEAMS. Amend the proposed future implementation scope
   honestly. If fixing the protocol requires mutation to any of
   vertical.py, slice4.py, operator.py, persistence.py, reducer.py, model.py,
   or serialization.py, the corrected design must name that fact explicitly.
   Do not preserve an artificially narrow future mutation union when the
   protocol requires another seam. This successor does NOT authorize those
   implementation changes; it only designs them.

8. DETERMINISTIC ACCEPTANCE TESTS. Require future implementation tests for:
   current evaluator cycle reaching the goalpost live and identically on
   replay; current evaluator cycle failing required evidence; crash/write
   failure at every publication boundary; no route surviving without
   replayable qualification authority; no partial qualification; exact
   correlation; duplicate/missing/stale evidence; checkpoint regeneration;
   preservation of earlier execution-evidence rows; failure-closed recovery.
