docs/backlog/BUG-WFC-FINDING-DELTA-COMPATIBILITY-SHIM.adoc, "Desired future

internal `FindingDelta(...)` compatibility constructor only. It does not
reopen, resume, or mutate completed predecessor
`WI-WFC-IMMUTABLE-FINDING-ECHO-FIX-002` (Run

IMPLEMENTATION (phase `implement`):
- Remove the `FindingDelta(...)` compatibility constructor/helper from
  `src/workflow_coordinator/model.py` (currently `:220-255`). It accepts a
  non-`None` `finding_id` together with `invariant`/`blocking` arguments and
  silently discards them while constructing an `ExistingFindingDelta`, whose
  type deliberately has no such fields; that silent-discard construction
  path must not remain. `ExistingFindingDelta` and `NewFindingDelta` remain
  the two explicit semantic model forms (`model.py:193-217`) and are not
  themselves changed by this correction.
- Migrate `tests/support.py`'s `delta(...)` fixture helper
  (currently `:178-196`, the sole remaining internal caller of
  `FindingDelta(...)` with a non-`None` `finding_id`) so that the test
  support API makes the new-Finding / existing-Finding distinction explicit
  at the call site. Do not solve this by moving an equivalent permissive
  dispatch (one helper that still accepts an existing `finding_id` together
  with `invariant` or `blocking` and silently ignores them) into
  `tests/support.py`; that would recreate the same defect one file over. A
  likely shape is two explicit helpers, e.g. `new_delta(...)` and
  `existing_delta(...)`, but an equally explicit and equally small
  alternative is acceptable if it is a better fit for the actual call sites;
  no helper may accept an existing `finding_id` together with a replacement
  `invariant` or `blocking` value and discard it.
- Migrate every `delta(...)` call site in the three authorized test files --
  `tests/architecture/test_replays.py`, `tests/unit/test_slice5b.py`,
  `tests/unit/test_reducer.py` -- to the explicit replacement helper(s),
  choosing the call that matches what each test actually constructs: a
  `finding_id=None` call is a new-Finding proposal; a non-`None` `finding_id`
  call is an existing-Finding delta and must carry only fields valid for an
  existing Finding.
- Pay particular attention to the two call sites that pass `invariant` or
  `blocking` together with a non-`None` `finding_id` -- these are the ones
  the silent-discard behavior actually affects today:
  * `tests/unit/test_slice5b.py:111`,
    `delta("F001", "open", blocking=False, evidence="smuggled")` inside
    `test_changes_required_artifact_does_not_grant_finding_disposition` (or
    its current equivalent) -- the assertion that follows checks that
    `blocking` stays derived from ledger state rather than the agent-
    supplied `"smuggled"` value; and
  * `tests/unit/test_reducer.py:98`,
    `delta("M-5", "resolved", invariant="Historical review label.")` inside
    a test asserting `ReductionError` for an unknown Finding ID.
  For each, determine from the test body and its assertions whether the
  discarded argument is (a) fixture noise that never reached the boundary
  being tested (in which case drop it and migrate the call to the explicit
  existing-Finding helper with only the fields that matter), or (b) actually
  intended to exercise rejection of an attempted immutable-field rewrite on
  an existing Finding (in which case that rejection must be exercised at the
  real boundary where such untrusted input can still occur -- the
  parser/wire validation in `serialization.py` -- not preserved as an
  impossible in-memory model construction). Do not mechanically translate
  either call in a way that changes what the test is actually proving; do
  not weaken any existing fail-closed assertion.
- Inspect the complete bounded scope for any other fixture or assertion that
  still assumes the pre-correction `FindingDelta(...)` call shape; the two
  sites above are known, not necessarily exhaustive.
- Make one semantic implementation commit referencing this BUG.
- Touch only the exact files this WorkItem's `implement`/`correct` phases
  authorize: `src/workflow_coordinator/model.py`, `tests/support.py`,
  `tests/architecture/test_replays.py`, `tests/unit/test_slice5b.py`,
  `tests/unit/test_reducer.py`. No other source or test file, and in
  particular not `src/workflow_coordinator/serialization.py` (already
  correct and out of scope for this correction) and not
  `tests/architecture/test_self_development_governance.py`.
