WHAT SLICE 2 ACTUALLY IS -- from the accepted FTR's "Exact later implementation
scope and slicing" section: "Implement pure per-ID/per-generation derivation,
checkpoint/replay projection, and threshold tests, still with no escape."
Concretely, drawing on the accepted FTR's "Convergence facts and bounded
goalpost" section:

1. THE QUALIFIED-CYCLE RULE. For one tracked Finding and one strategy
   generation, a cycle is qualified only when all of the following are
   mechanically observable in accepted Slice-1 state:
   a) a corrector Hop made an `addressed` coverage claim for that open
      Finding;
   b) the next applicable evaluator correlated its assessment to that
      correction Hop and the same Finding ID;
   c) the evaluator recorded `carried_new_counterexample` with evidence
      genuinely absent before that evaluator Hop (per the already-enforced
      Slice-1 freshness invariant -- S1-IR-002); and
   d) after the evaluator's authorized Finding delta, that Finding remains
      `open` and `blocking`.
   The following must NOT increment the qualified-cycle count: allocation of
   a new blocker; a renamed prose label; a worker `blocked` result; a worker
   escalation claim; failed evidence; uncertain/unaccepted execution; an
   uncorrelated assessment; `carried_unmet`; stale/duplicate evidence; or a
   cycle belonging to a different strategy generation. History remains
   retained even when it does not qualify. The already-accepted Slice-1
   reducer validation (`_validate_convergence_records_before_apply()` and
   `_validate_assessments_after_apply()` in reducer.py) already enforces the
   freshness, correlation, and totality invariants this rule depends on; you
   are deriving a read-side fact from already-validated, already-persisted
   Slice-1 history, not re-implementing its admission rules.

2. THE DERIVED FACT. Implement a pure function (reducer.py is the natural
   seam, consistent with Slice 1's existing validation helpers there) that
   derives, from a Run's complete ordered `hops`/`findings` history plus a
   finite qualified-cycle limit, a `ConvergenceFact` per tracked Finding ID
   and strategy generation it has participated in:
   `ConvergenceFact { finding_id, strategy_generation, qualified_cycle_count,
   qualified_cycle_limit, goalpost_reached, source_evaluator_hops }`.
   `source_evaluator_hops` identifies, in deterministic order, the exact
   accepted evaluator Hop IDs whose assessment qualified under rule 1 above.
   `goalpost_reached` means only that the configured limit has been consumed
   for that still-open obligation; it MUST NOT mean accepted, resolved,
   false, impossible, correct, or diagnosed, and no count/threshold/goalpost
   may synthesize Finding disposition or semantic acceptance. Add
   `ConvergenceFact` to model.py alongside the existing Slice-1 records.

3. NO MUTABLE SHADOW STATE -- this is load-bearing. Do not add a mutable
   cycle counter to `Finding`, a mutable `goalpost_reached` flag to `Run`, a
   second convergence ledger, another authoritative state file, or any cache
   state whose correctness is required for replay. `run.json` remains
   authoritative for persisted Run/Hop/Finding facts exactly as Slice 1 left
   it; do not add any new persisted field to the Run/Hop/Finding wire for this
   slice (serialization.py is out of scope precisely because nothing new is
   persisted). `ConvergenceFact` values must be fully reconstructable, byte-
   for-byte, by re-deriving from the same ordered history and the same finite
   limit input -- never read from a stored value.

4. CHECKPOINT/REPLAY PROJECTION. Extend `checkpoint_projection()` in
   persistence.py to expose the derived per-generation `ConvergenceFact` set
   and each fact's source evaluator Hop IDs as a derived view, clearly
   distinct from the authoritative `run.json` contents it already projects.
   Do not implement the complete prompt/operator convergence projection
   described by the accepted FTR's "Checkpoint, summary, and prompt
   projection" section -- that integrated projection requires Slice 3's real
   profile selection and is explicitly out of scope here; exposing the derived
   facts through `checkpoint_projection()` alone satisfies this slice.

5. DETERMINISM. Replaying the same accepted ordered history with the same
   finite derivation inputs must produce byte-identical `ConvergenceFact`
   values, including a stable, deterministic ordering of
   `source_evaluator_hops`. Interruption, uncertain, rejected, or unaccepted
   Hop history must fabricate no convergence event. A legacy (v1/v2) or
   simple (non-convergence) Run must acquire no fabricated convergence facts
   -- the derivation over such a Run's history must yield an empty fact set.

REQUIRED TESTS AND ACCEPTANCE CRITERIA -- derive the exact tests from the
accepted FTR's "Required deterministic tests and acceptance" section,
subsection "Goalpost and routing" (the derivation/threshold parts only -- not
the routing-substitution parts, which are Slice 3) and the Slice-2-relevant
parts of "Wire, persistence, replay, and simple profiles". At minimum,
preserve deterministic coverage of:

* positive qualified cycle: a corrector `addressed` claim followed by a
  correlated evaluator `carried_new_counterexample` with genuinely new
  evidence, leaving the Finding open/blocking, increments the count by
  exactly one and records the evaluator Hop as the sole source;
* below-threshold / at-threshold: using a finite deterministic test limit
  (prefer 2 unless inspection of current seams establishes a better bounded
  setup), one qualified cycle yields count 1 and `goalpost_reached: false`; a
  second qualified cycle for the same Finding/generation yields count 2 and
  `goalpost_reached: true`; no routing or escape occurs as a result;
* carried-unmet exclusion: `addressed` followed by `carried_unmet` does not
  increment the count;
* stale-evidence exclusion: evidence already present in the prior same-
  Finding ledger/coverage/assessment history does not qualify as new (this
  must reuse and preserve the accepted S1-IR-002 freshness invariant rather
  than reimplementing a weaker check);
* different Finding identity: a new blocker / new Coordinator Finding ID
  starts its own independent count and does not increment an older Finding's
  count;
* closed/superseded result: if the evaluator authoritatively resolves or
  validly supersedes the Finding in the relevant evaluator Hop, that Finding
  produces no still-open qualified-cycle fact;
* unaccepted/uncertain history: malformed, uncorrelated, rejected, failed-
  before-acceptance, or uncertain Hop history fabricates no qualified cycle;
* replay determinism: the same accepted ordered history derives the same
  `finding_id`, `strategy_generation`, `qualified_cycle_count`,
  `goalpost_reached`, and ordered `source_evaluator_hops` on every replay;
* legacy/simple non-regression: existing current profiles and historical Run
  versions (v1/v2, and Slice-1 v3 Runs with no convergence-tracked Finding)
  remain behaviorally unchanged and derive an empty convergence-fact set;
* the full repository `pytest` suite remains green.
