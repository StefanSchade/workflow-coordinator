======================================================================
WHAT P2 MEANS
======================================================================

P2 makes worker-vs-review category mistakes structurally unrepresentable,
not merely rejected after the fact by the reducer. A worker/corrector
invocation selects `WorkResult` (`status: completed | blocked`, plus the
genuinely applicable existing semantic/evidence/effect fields); it MUST NOT
be able to express `changes_required` or any other review-only verdict --
absent from the type and the provider schema. A review/rereview invocation
selects `ReviewVerdict` (`verdict: accept | changes_required`, plus Finding
proposals/updates, evidence, summary); it MUST NOT expose worker-only
status vocabulary. Every phase with `phase.convergence_role is not
ConvergenceRole.NONE` (Slice 4: CORRECTOR, DIAGNOSIS, REFRAME,
STRATEGY_GATE, EVALUATOR) remains on the existing generic `RoutingResult`
contract, untouched by P2. Selection extends the one existing P1 selector,
`select_result_contract(profile, phase, run) -> ResultContractKind`
(model.py:545), never a second mechanism, never a phase-key string branch.
The full semantic detail -- worker/review field contents, the P1 seam
(selector -> AgentExecutionRequest -> adapter -> kind-specific parser ->
reducer), prompt/schema/parser synchronization, the Finding P2/P3
boundary, the escalation bounded decision, and what P4/P3.5 must not be
"cleaned up" into P2 -- is already fully specified in
governance/work-items/projected-result-contracts-p2-task.txt and the
original WorkItem's `authority_source`
(governance/work-items/projected-result-contracts-p2.yaml). Read both
completely; their exact wording controls P2's semantic boundary. This task
text does not repeat that specification; it governs what THIS successor
Run must additionally do.

WHY DIRECTORY SCOPE IS INTENTIONAL
======================================================================

The predecessor's `implement`/`correction` phases used a deliberately
file-exact `authorized_scope` -- exactly fifteen named paths -- while the
governing policy simultaneously required trusted full-repository `pytest`
evidence. The P2 contract change had consumers in existing tests outside
that predicted file set; full-suite evidence exercised that wider surface
and failed, exactly as docs/wfc_operator_manual.adoc's "Commission
mutation-scope granularity" section now documents: scope is an authority
boundary, not an implementation plan. This successor's `integration` and
`correction` phases therefore use bounded DIRECTORY/AREA authority:

  src/workflow_coordinator
  tests

No wildcard syntax; no bare repository-wide scope; no reconstructed
predicted file list. This lets legitimate integration work reach whichever
file genuinely needs correction -- including a test file the predecessor's
file-exact list omitted -- without widening authority beyond the
production/test areas the P2 task already governs. It does NOT authorize
`governance`, `docs` generally, `project_memory`, `scripts` generally,
Runtime, Evidence, `.git`, or any other repository area.
