This Commission authorizes only (1), reframed as described below, and a

ITEM 1 -- AGENT-FACING PROMPT/CONTRACT HARDENING
======================================================================

Goal: for any phase whose admitted facts declare `durable_artifact:
required`, the agent-facing prompt must (a) carry the concrete declared
artifact path(s), and (b) carry one Coordinator-composed, phase-specific
sentence stating the operational obligation plainly enough that the agent
understands when it must create/update the artifact and truthfully supply a
CommitIntent naming it, and that blocked/failed/requires_human/
escalation/scope_changed dispositions must never fabricate one.

Repository truth as of Commission authoring (RE-VERIFY YOURSELF -- do not
trust this paragraph blindly): the concrete path(s) already ARE projected
into the agent-facing prompt today, via
`operator.py::_reconstructed_context`'s `durable_artifacts=<comma-joined
path(s)>` context line, which is folded into every Hop's `[context]` block
by `assemble_prompt` (`src/workflow_coordinator/prompt.py`). This is
exercised by `tests/unit/test_slice5b.py`'s
`test_unsuccessful_outcomes_do_not_require_artifact_or_route`-adjacent
fixtures and, most directly, the `assert "durable_artifacts=payload.txt"
in adapter.requests[0].prompt` / `assert "durable_artifacts=\n" in
adapter.requests[1].prompt` assertions, and by
`test_reconstructed_context_encodes_agent_values_and_attributes_outcome`'s
`sum(line.startswith("durable_artifacts=") for line in lines) == 1`
assertion. The same function also already projects
`review_authority=<GATE|ADVISORY>` whenever `phase.review is not None`.
If your own fresh inspection confirms this is still accurate, do NOT
re-plumb either fact -- there is no missing parameter to add for the raw
path or the raw authority value. The real, remaining gap is purely the
missing natural-language sentence connecting these already-available facts
into an explicit, unambiguous rule.

Compose that sentence Coordinator-side, derived only from `phase.durable_artifact`
and `phase.review.authority` (both already in scope wherever you choose to
compose it), never left for the model to resolve itself across GATE vs
ADVISORY. Required shape:

* For a phase with `durable_artifact: required` whose review (if any) is
  not `ADVISORY`, or which has no review at all (a worker phase): state
  that a route-eligible completing disposition must create/update the
  named artifact path(s) and supply a CommitIntent naming them, and that
  blocked/failed/requires_human/escalation/scope_changed dispositions must
  not supply one.
* For a phase with `durable_artifact: required` AND `review.authority ==
  ADVISORY`: do NOT tell the model that `changes_required` needs a
  CommitIntent at all. `vertical.py`'s existing `permitted_intent`/
  `review_artifact_commit` mechanics only permit a non-null CommitIntent on
  `changes_required` when `review.authority is GATE`; telling an ADVISORY
  phase otherwise would instruct something the Coordinator would then
  reject, which is exactly the hazard this WorkItem's authority_source
  names and forbids. Whether an ADVISORY + required + changes_required
  phase shape is sound at all is an open, separate, future P3.5 question;
  do not resolve it, do not note it as a defect to fix, and do not widen
  the sentence's logic to work around it -- simply never emit the
  contradictory instruction for that composition.
* For `durable_artifact: optional` or `durable_artifact: none`, do not
  fabricate any obligation sentence implying a requirement that does not
  exist.

Placement: use whichever existing per-Hop prompt/context composition site
already has `phase` (and, if needed, the resolved artifact path tuple) in
scope -- `src/workflow_coordinator/prompt.py` (`assemble_prompt`, `_header`,
or the `[workflow_policy]` block) and/or
`src/workflow_coordinator/operator.py` (`_reconstructed_context`) are both
in authorized scope for this purpose. Choose the smallest coherent seam
after inspecting current source; do not introduce a new enum, boolean
parameter, `AgentExecutionRequest` field, or persisted identity merely to
carry a fact that a function in the call chain already holds directly.

Explicitly out of scope for this item: `src/workflow_coordinator/resources/agent_operating_contract_v6.txt`,
and the `CONTRACT_ID`/`CONTRACT_VERSION`/`RESOURCE`/`REVIEWED_SHA256`
constants in `prompt.py` that pin it. That resource is generic across every
phase and role and is not where a phase-specific, path-bearing sentence
belongs; do not bump its version or its pinned hash for this Commission.

ITEM 2 -- EXISTING DURABLE-ARTIFACT DIAGNOSTIC HARDENING
======================================================================

Bounded to `src/workflow_coordinator/vertical.py::_durable_artifact_anomalies`
only. Keep its signature, its call site, its gate condition (which phases/
outcomes it applies to), and its Run-visible disposition consequences
(still `mechanical_preemption:...`, still `RunStatus.AWAITING_HUMAN`,
never `RECONCILE_REQUIRED`) unchanged. Today its first branch returns one
generic message, "required durable artifact is missing, unrepresented, or
uncommitted", whenever any of several distinct conditions hold. Replace
that single generic message with deterministic, mechanically distinguished
messages for (at least) these causes, wherever distinguishing them is
straightforward from facts the function already has:

* no CommitIntent was supplied at all for a disposition that reaches this
  enforcement path (`result.commit_intent is None`);
* a CommitIntent was supplied but does not name the required artifact
  path(s) (the required path(s) are not a subset of the CommitIntent's own
  `paths`);
* the required artifact path(s) are not actually among the Hop's observed
  changed/committed paths (no actual commit was made, or the required
  path(s) are not in the Git delta's changed-path set).

The existing later branch ("required durable artifact is absent or not a
regular Git-tracked file at end HEAD", the Git-truth check against `end
HEAD` via `git ls-tree`) is already a distinct cause and must remain
exactly as authoritative and unchanged in meaning -- it is the only layer
that can know actual Git ground truth, and this Commission does not modify,
weaken, or duplicate it.

If your inspection finds a required phase can be reached with an empty
declared-artifact-path configuration (i.e. `durable_artifacts` is empty
while `phase.durable_artifact` is `required`), and distinguishing that as
its own message is equally straightforward and deterministic, you may do
so; do not build speculative handling for a case your own inspection proves
unreachable.

Do not invent a taxonomy, enum, or exception hierarchy for these causes --
plain distinct message strings, chosen by ordinary conditional logic
reading facts the function already computes, are sufficient and are all
this item asks for.
