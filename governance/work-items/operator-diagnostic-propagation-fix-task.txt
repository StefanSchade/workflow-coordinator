Implement, independently review, and (if needed) correct the bounded
propagation correction authorized by
docs/backlog/BUG-WFC-OPERATOR-DIAGNOSTIC-PROPAGATION.adoc, "Desired
correction". This closes the FD-04 gap recorded in
docs/warm_storage/concepts/workflow_coordinator_front_door_priority_and_profile_commission_boundary_plan_2026-10-26.adoc
§§7-8: a provider invocation that fails (nonzero exit, timeout, missing
candidate result, or structured-result validation failure) must leave the
maintainer able to determine, from durable local state alone, which
Run/Hop/Invocation failed, which of those known failure classes occurred,
the actual exit code, and where to inspect the already-captured bounded
diagnostic text -- without inventing a provider-side root cause, without
adding retry/recovery/resume, and without widening what the separate Git
Evidence archive repository (workflow-coordinator-run-evidence) copies.

DO NOT invent or assert a root cause for either cited incident
(wfc-p35-requirements-archaeology-reassessment-001-2026-10-26-01,
wfc-front-door-contract-design-001-20261028-01). Both remain unexplained;
this WorkItem only fixes why they could not be investigated.
