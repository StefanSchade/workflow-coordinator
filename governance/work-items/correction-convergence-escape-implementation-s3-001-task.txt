REQUIRED SLICE-3 SEMANTICS (implement and independently review the complete
accepted contract; where this summary and the accepted FTR/Design-Revision
text differ, the FTR/Design-Revision controls):

1. Opt-in profile schema version 3. Profile schema version 2 retains its
   exact current closed shape and behavior unchanged. A convergence-aware
   profile uses schema version 3 and the closed top-level declaration:
     convergence:
       protocol: repeated_counterexample_v1
       qualified_cycle_limit: <finite integer, 2 through the Coordinator
         hard Hop maximum>
   No value is a correctness score. No executable YAML, predicate,
   expression, callback, template, dynamic graph, or user-defined
   convergence logic is introduced. Unknown protocol names, keys, roles,
   invalid route combinations, or mixed v2/v3 shapes fail closed.

2. Closed phase convergence roles. Profile-v3 phases use the accepted closed
   role set: `convergence_role: none | corrector | evaluator | diagnosis |
   reframe | strategy_gate`. Slice 3 owns grammar/topology validation for
   these declarations. Do NOT implement Slice-4 typed diagnosis/reframe/
   strategy semantics merely because their role names become valid
   declarative profile vocabulary -- a diagnosis/reframe/strategy_gate phase
   may be declared and targeted as a routing destination, but its own typed
   result content (DiagnosisReport/StrategyRevision/StrategyAssessment)
   remains structurally null, exactly as Slice 1/2 already force for every
   phase.

3. Evaluator normal and RESERVED escape routes. An evaluator phase declares
   `normal_correction_route` and `escape_route`. Both must name existing
   finite routes on that phase. The normal route must be `goto` a
   `corrector`. The escape route must be `goto` a `diagnosis` phase. THE
   ESCAPE ROUTE IS COORDINATOR-RESERVED: it must be omitted from the agent's
   ordinary `permitted_routes`/`permitted_route_keys`, and an agent directly
   requesting the reserved escape route must fail closed. The evaluator does
   NOT decide that the goalpost has been reached -- it makes its ordinary
   semantic gate decision (e.g. `changes_required` requesting its declared
   normal correction route). Only Coordinator-owned deterministic reduction
   may substitute the escape route.

4. Deterministic escape substitution. Preserve the accepted reducer
   precedence exactly: (a) validate correlation/profile/state and capture
   semantic stop observation; (b) apply existing mechanical, repository,
   policy, evidence-command, and human-authority preemptions exactly as
   today; (c) reject failed results, scope-change attempts, unknown/
   forbidden routes, and malformed convergence records; (d) atomically apply
   authorized Finding deltas and validated annotations; (e) apply the
   existing required-evidence-failure route, when configured, which still
   takes precedence; (f) if and only if the evaluator returned
   `changes_required`, requested its declared normal correction route, and
   the trusted post-Hop convergence facts (derived via the accepted Slice-2
   composite predicate, consuming the pinned `qualified_cycle_limit` and the
   current evaluator's exactly correlated staged qualification attempt) show
   at least one still-open Finding whose goalpost is reached, substitute the
   profile-declared escape route; (g) apply the existing Hop-budget and
   supervisor checks to the SELECTED route, then apply it normally. If the
   relevant Finding was resolved or superseded in the evaluator Hop, it is
   not an escape trigger. If several Findings exist, only still-open
   goalpost Findings cause the escape payload/reason; new blockers have
   their own identity/count and do not inherit another Finding's
   convergence.

5. Trusted Slice-2 qualification remains authoritative. Consume the SAME
   trusted qualification protocol implemented in revised Slice 2: use the
   pinned finite profile limit; use the exact trusted qualification index;
   for the current evaluator, use the strictly parsed already-published
   staged qualification attempt; for history, use only exact authoritative
   Run/evidence pairs. Do NOT recreate the rejected Run-only qualification
   overload, infer mechanical evidence success from semantic route/result
   prose, treat checkpoint contents as route authority, finalize a
   convergence-dependent route before the required staged attempt exists,
   add a mutable qualification boolean/counter/goalpost state, or bypass
   evidence-before-route-bearing-Run ordering. Missing, inconsistent,
   conflicting, unpaired, or otherwise mechanically invalid trusted
   qualification input must fail closed per the accepted Design Revision /
   Slice-2 protocol rather than manufacturing escape.

6. Requested versus applied routing truth. Preserve the accepted FTR's
   requested/applied distinction. When substitution occurs, durable/
   projected state must truthfully distinguish the evaluator's REQUESTED
   normal route from the Coordinator-APPLIED escape route, plus a
   deterministic route reason identifying sorted triggering Finding IDs.
   Inspect current model/wire ownership before adding fields: `Hop.
   applied_route` and `RoutingResult.requested_route` already exist; do not
   create duplicate semantic state merely because another field name is
   possible, but do add whatever Hop/HopSummary wire is actually missing
   (durable `requested_route` and `route_reason` on the Hop/HopSummary,
   since the current model persists only `applied_route`). Never misattribute
   the escape decision to the evaluator.

7. Budget and preemption. Escape does not refund a Hop, increase
   `max_autonomous_hops`, override mechanical/human/policy/evidence
   preemption, or synthesize acceptance. Escape occurs before the normal
   route's budget transition per the accepted reducer precedence, but the
   existing Hop-budget check still controls whether the next diagnosis Hop
   may actually run; if no Hop remains, existing budget exhaustion wins.

8. Result-v2 live dispatch for convergence profiles. Slice 1 already
   introduced the result-v2 envelope and direct adapter support (contract
   version 2, dispatched generically in vertical.py whenever
   `phase.convergence_role is not ConvergenceRole.NONE`). Slice 3 wires the
   REAL profile-selected path so an admitted profile-v3 convergence phase
   dispatches the correct result contract end to end, including diagnosis/
   reframe/strategy_gate phases (whose typed result fields remain
   structurally null). Ordinary profile-v2/result-v1 behavior remains
   unchanged. Do not weaken either strict schema.

9. Run/profile integration. Existing profile-v2 Runs remain unchanged; only
   `new_run()` against an admitted profile-v3 convergence profile creates a
   convergence-aware Run/schema shape (Run schema version 3). No in-place
   v1/v2 historical migration or convergence backfill occurs. Implement
   only the Slice-3 portion of this; do not synthesize diagnosis/strategy
   history.

10. Complete checkpoint/operator/prompt projection. Wire the accepted
    Slice-2 derived convergence information into REAL production callers.
    The real pinned `qualified_cycle_limit` must reach convergence
    derivation/projection: `operator.py` must pass it (sourced from the
    pinned profile's convergence declaration) into `persistence.
    checkpoint_projection()`'s existing optional parameter, and `vertical.
    py` must compute the pre-dispatch `ConvergenceFact` tuple from Run
    history, the qualification index, and the limit, and hand it to
    `prompt.py`'s prompt assembly. Fresh prompt/operator/checkpoint
    projection must expose the complete bounded convergence context
    required by the accepted FTR: the complete open tracked-obligation set;
    latest relevant coverage/evaluation per ID; derived per-generation
    convergence facts; source evaluator Hop IDs; triggering Finding IDs;
    requested versus applied route information; clear Coordinator-derived
    versus agent-attributed labeling. Do NOT implement Slice-4 non-null
    diagnosis/strategy data.

11. Simple-profile non-regression. Existing schema-version-2/simple profiles
    must remain behaviorally unchanged -- this is a PRIMARY acceptance
    requirement, not incidental compatibility. They must not acquire
    fabricated convergence facts, acquire reserved routes, dispatch result
    v2 merely because the implementation exists, change route availability,
    change normal correction behavior, gain diagnosis/reframe phases, or
    persist new convergence state.
