Reducer (reducer.py):

  (`derive_convergence_facts` or an equivalent seam) taking the trusted

* exact Run/evidence pair validation (the correlation rule in Design
  Revision 001's "Exact durable and live correlation rule");

* idempotent duplicate-publication semantics (byte-identical row is
  idempotent; differing content is a deterministic conflict);
* dual-input checkpoint identity (`run_json_sha256` plus
  `execution_evidence_sha256`);
* fail-closed inconsistent-pair handling;
* the recovery semantics the accepted design assigns to this seam (or to
  slice4.py -- see below; pick one closed division of labor and document it
  in the review artifact).

  required command plan and trusted Observations -- never from agent

  selection;

  replay into live reduction for the current Hop;

Slice4 (slice4.py):

* dispatch-marker lifecycle and recovery integration (recognizing a

  validated pair and a regenerated checkpoint);
* the complete crash/write-failure behavior required by Design Revision
  001's normative matrix, to the extent this module owns dispatch
  orchestration (as opposed to the file-level atomic-write/validation

Operator (operator.py):
* schema-4 attempt accumulation that preserves every prior row across a
  continuation (never re-initializes an empty array);

* final checkpoint regeneration from the paired authoritative inputs;
* serialization of the required identity / plan / provenance facts into the
  published schema-4 document, sourced from the same prepared commands it
  actually executes (never reconstructed from observation presence after the
  fact).
