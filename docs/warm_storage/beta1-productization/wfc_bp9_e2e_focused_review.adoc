=== `F001` resolved: `wfc audit` is now genuinely driven, and the prose matches

H002's Finding was that the happy path never invoked `wfc audit` although
the task's scenario (a) enumerates it, and that the test name, the mutation
comment and the docstring all claimed otherwise. Both halves are closed.

*The invocations are real and they hold as committed.* Because `pytest` is
not installed in this sandbox (see the limitation note below), scenario (a)
was replicated line for line as a standalone harness -- same env isolation
(`HOME`, `XDG_STATE_HOME`, deleted `XDG_DATA_HOME`, the `wfc` `PATH`
wrapper), same non-Python consumer repository, same scripted provider, same
command sequence -- and executed against the reviewed checkout. Every
assertion of the scenario held, including the two new ones. Observed:

* bare `wfc audit <attempt-dir>`: exit `2`, stderr
  `wfc audit: refusing to overwrite existing audit.json with different
  content: <attempt-dir>/audit.json`, stdout empty, `audit.json` bytes
  unchanged;
* `wfc audit <attempt-dir> --lifecycle-json <facts>` with
  `{"classification": "completed", "preservation": null}` read back from the
  archived document: exit `0`, stdout exactly
  `AUDIT: <attempt-dir>/audit.json`, bytes still identical;
* the Evidence repository `git status --porcelain=v1` is empty afterwards,
  and the archive holds exactly one attempt directory, the one the test
  computes through the product's own `postrun._attempt_identity`.

The exit-`0` assertion is what makes "byte for byte" real rather than
decorative: `audit._create_only_write` (`audit.py:508-513`) returns early
only when the recomputed text equals the existing file and otherwise raises,
which `audit.main` maps to exit `2`. A drifted projection therefore cannot
pass this assertion quietly.

*The two new assertions are mutation-sensitive.* Both mutations were applied
to a throwaway copy of `src/` and `tests/` outside the reviewed checkout,
never to the checkout itself:

. *create-only guard removed* -- `_create_only_write`'s `raise AuditError`
  dropped so a differing `audit.json` is silently overwritten: *killed*.
  Observed `bare audit rc 0` and
  `AssertionError` at `assert bare_audit.returncode == 2`. This is exactly
  the mutation the corrected comment names.
. *`wfc audit` ignores caller-supplied lifecycle facts* -- `audit.main`
  forced to `lifecycle = None` after parsing `--lifecycle-json`: *killed*.
  Observed `audit rc 2` with the refusal message and `AssertionError` at
  `assert audit.returncode == 0`. So the second assertion pins the agreement
  between the manual CLI projection and the automatic postrun projection,
  which is the recovery contract an operator meets, and not merely the
  presence of a file.

*The prose is now accurate.* Each clause was checked against observed
behavior: `audit` really is called twice; the first call really is refused
fail-closed; the second really does reproduce the archived document; the
`init`/`plan`/`run --yes`/`status`/`audit`/`report` chain in the test name
and in the docstring is now the chain actually executed as subprocesses. The
docstring's remaining scenario-(a) claim -- that the dispatcher is entered
twice over, once as the outer CLI and again as `frontdoor.lifecycle`'s inner
bare-flag engine re-entry -- is confirmed by the replay: the inner engine
printed its own `STATE ROOT:` line under the per-run throwaway
`XDG_STATE_HOME` and consumed the scripted provider step, which only happens
if the re-entry resolved through the `PATH` wrapper.

*Hermeticity of the added lines.* The lifecycle-facts file is written under
`tmp_path`; the two new subprocesses inherit the already-patched
`HOME`/`XDG_STATE_HOME`/`PATH` (`monkeypatch.setenv` mutates `os.environ`,
so the inherited environment is the isolated one) and need no
`WFC_BP9_SCRIPT` because no provider is launched; nothing is written outside
`tmp_path`; no network is reached.

agent-local environmental limitation, not a product defect and not a
dependency to be downloaded. It was worked around rather than asserted
over: the scenario under review was replicated verbatim outside pytest, with
the same environment isolation, so the behavior the committed assertions
depend on was observed rather than trusted. Scenarios (b)-(e) were not
re-executed in this Hop; `git diff 043dc45..1c161ef` shows H003 changed
nothing in them, and H002 executed them. The authoritative answer on
required mode remains the Coordinator's own `task-check` for this Hop.
