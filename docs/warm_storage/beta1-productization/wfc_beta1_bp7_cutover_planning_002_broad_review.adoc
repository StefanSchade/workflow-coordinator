=== Method

Three passes, deliberately not organised around the plan's own narrative:

. *Citation pass.* Every file/function/line citation in the plan was opened
  in the real tree at the review base HEAD and checked on three axes: the
  symbol exists, it is in the named file, and it does what the plan says.
. *Independent-search pass.* `tests/`, `pyproject.toml`, `.gitignore`,
  `governance/` and the packaging metadata were searched independently of
  the plan's own claims, to find what the plan does *not* mention. Blocking
  Finding 1 came out of this pass, not out of the plan's text.

  was executed: the recommended `.wfc/config.yaml` body from

=== Blocking Finding 1 -- C5's acceptance cannot be met within C5's own stated scope: `tests/conftest.py` pins six required-real `test_wfc_op.py` node ids

*Where.* `<<sequence>>`, row C5 (`wfc-beta1-bp7-retirement-001`): scope
"Remove or stub `scripts/wfc_op.py` and its own direct test,
`tests/unit/test_wfc_op.py`; ... and the parts of
`tests/unit/test_commissioning.py` and
`tests/architecture/test_self_development_governance.py` that exercise it";
acceptance "Full suite green without `scripts/wfc_op.py`, without the v1
compile path, and without any quarantined file".

*What is actually in the tree.* `tests/conftest.py:21-33` defines

[source,python]
----
_REQUIRED_REAL = frozenset(
    "tests/unit/test_wfc_op.py::" + name for name in (
        "test_prepare_positive_produces_complete_envelope_and_leaves_state_absent",
        "test_status_completed_run",
        "test_prepare_final_revalidation_refuses_on_drift_during_preparation",
        "test_canonical_preflight_refusal_propagates_and_proves_pinned_runtime_code",
        "test_launch_uses_the_frozen_prepared_path_not_a_later_ambient_path",
        "test_launch_sh_safely_quotes_shell_significant_paths",
    )
) | frozenset({
    "tests/architecture/test_offline_distribution.py::test_clean_isolated_distribution_and_wheel_install",
    "tests/unit/test_neutral_consumer_evidence.py::test_shell_consumer_uses_real_evidence_runner",
})
----

and enforces it, in required (non-`--wfc-partial`) mode only:
`pytest_collection_finish` (`tests/conftest.py:36-40`) records which of
those node ids were selected, `pytest_runtest_makereport`
(`tests/conftest.py:43-49`) records their per-phase outcomes, and
`pytest_sessionfinish` (`tests/conftest.py:134-144`) computes
`missing = sorted(node for node in _REQUIRED_REAL if node not in
state.get("selected_real", set()) or reports.get(node) != {"setup":
"passed", "call": "passed", "teardown": "passed"})` and, if that list is
non-empty, sets `session.exitstatus = pytest.ExitCode.TESTS_FAILED`.

*Why this is blocking, not polish.* Six of the eight required-real node ids
live in the module C5 deletes. Deleting `tests/unit/test_wfc_op.py` without
amending `tests/conftest.py` makes every required-mode suite run fail by
construction -- including the Coordinator's own `task-check`, whose argv is
`("python", "-m", "pytest", "-q")` with no `--wfc-partial`
(`commissioning.py:334`, the `repository-standard` evidence-command
literal). C5's stated acceptance ("Full suite green without
`scripts/wfc_op.py`") is therefore not reachable from C5's stated scope: the
one file that decides it is not named anywhere in the plan. This is exactly
the class the task calls "an unfulfillable acceptance" and "a missing
essential package", and it is the single most load-bearing acceptance in the
whole decomposition, since C5 is the Commission that performs the cutover.

*A second, semantic half the plan should not leave implicit.* Those six node
ids are not incidental coverage: they are the suite's designated *real*
(un-faked) proof that preparation pinning, final revalidation, canonical
preflight refusal, frozen launch paths and shell quoting actually work. The
plan must say what happens to that guarantee -- whether the required-real
set simply loses the Harness entries at retirement, or whether equivalent
product-path node ids (for example from
`tests/unit/test_lifecycle_controller.py` or `tests/unit/test_postrun_archive.py`)
take their place. That is a bounded technical choice the plan should
recommend, not an open maintainer decision; but it must appear, because the
required-real set is the mechanism by which this repository refuses to
accept a green suite that never really ran the critical paths.

*What would resolve it.* Inside the plan document: add `tests/conftest.py`
to C5's scope with its `_REQUIRED_REAL` amendment named explicitly, state
the recommended disposition of the six Harness node ids, and extend C5's
acceptance to assert the required-mode (not partial) suite is green. No
product change is implied by this Finding, and none is authorized by it.

For completeness, two neighbouring items were checked and are *not* part of
this Finding: `tests/fixtures/offline-test-inputs/py313-linux-x86_64-collected-nodes.txt`
contains 49 `test_wfc_op` lines, but no code in `scripts/`, `src/` or
`tests/` reads a `collected-nodes` file, so it is an informational record
rather than an enforced gate; and `pyproject.toml`'s `[project.scripts]`
declares only `wfc = "workflow_coordinator.frontdoor.cli:main"`, so
retirement needs no packaging change and the plan's scope-ceiling claim
(`<<config-recommendation>>`) survives this check.

=== Blocking Finding 2 -- the required effort estimates are absent: no Hop estimate and no reasoning for any sub-Commission

*Where.* `<<sequence>>`, the `|Effort` column of the sub-Commission table.

*What the plan actually contains.* The complete set of effort entries is:
C1 `S`; C1b `S`; the external Runtime promotion `--`; Proof Run 1 "Small (1
real Run; Hop count depends on the chosen task, not fixed by this plan)";
Proof Run 2 "Small"; C5 `M`. A full-document search for `Hop`, `effort`,
`small`, `medium` and `large` (case-insensitive) finds no other effort
statement anywhere in the plan: no Hop estimate for C1, C1b or C5, no
reasoning for any of the six classes, and no legend defining `S` and `M`.

*Why this is blocking.* The task's deliverable 4 requires, verbatim,
"estimated effort in Hops and a rough token/effort class (small/medium/large)
with the reasoning", and the Acceptance requires "independently testable
sub-Commissions with effort estimates". Two of the three required components
-- the Hop estimate and the reasoning -- are missing for all three real
Commissions, and the third is given as undefined abbreviations. This is a
reproduced violation of an explicit acceptance criterion, which the review
contract forbids downgrading because the fix is small or the risk low. It
also has a practical consequence inside the plan's own recommendation: the
plan commits `max_autonomous_hops: 10` as the repository ceiling
(`<<config-recommendation>>`), and `compile_commission` refuses any
`ConsumerRequest.max_autonomous_hops` above that ceiling
(`commissioning.py:705`), so whoever commissions C1, C1b and C5 must choose
a per-Commission Hop number that this plan declines to estimate.

*What would resolve it.* Inside the plan document: give each of C1, C1b and
C5 an estimated Hop range and one clause of reasoning (what drives the
estimate -- for C5, for instance, the breadth of the manual edit set plus a
required-mode suite run), spell the class as small/medium/large, and keep
the honest "depends on the chosen task" qualification for the two proof
Runs, where it is appropriate rather than a gap.

=== Verdict

*Changes required.* Two blocking Findings: C5's acceptance is unfulfillable
within its own stated scope because `tests/conftest.py`'s required-real node
ids are not named (Finding 1), and the plan omits the required Hop estimates
and effort reasoning for its sub-Commissions (Finding 2). Both are
correctable inside `docs/backlog/beta1_bp7_cutover_plan.adoc` alone, with no
product change and no new authority. Everything else this pass could test --
the gap analysis, the executed configuration recommendation, the
archive-equivalence definition, the proof-Run and retirement sequencing,
DG-4/DG-5 compliance, the tag boundary and the BP9/closure checklist -- held
up against the real code, manifests and manual.
