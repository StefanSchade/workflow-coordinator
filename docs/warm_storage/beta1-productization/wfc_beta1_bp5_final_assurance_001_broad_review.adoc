=== BF-2 -- a ported legacy conformance assertion is silently neutralised, and the behaviour change it guarded is undocumented

*Reproduced violation of an explicit acceptance criterion.*

The original BP5 task requires copying the legacy conformance tests
"preserving all applicable checks and documenting any unavoidable
non-applicable legacy-proof case"; the completion Commission's review
paragraph requires "retain full original assertions"; this Commission's
withheld authority forbids test weakening.

`tests/unit/test_archive_port.py:317` carries a permanently dead branch:

[source,python]
----
self.assertIn(f"checkout:   {CHECKOUT}" if False else f"repository: {TARGET_REPO}", proc.stdout)
----

The `if False` arm is the legacy assertion. In the legacy source
(`build/wfc/bp5-evidence-inputs/tests/test_wfc_archive_run.py:312,315`)
`test_manifest_identity_cannot_forge_run_probe_records` asserted both
`checkout:   <CHECKOUT>` *is* present and
`checkout:   00000000-dead-beef-dead-beefdeadbeef` is *not* -- i.e. that a
forged `run_id` carrying embedded `checkout_id` control text cannot forge the
report's own checkout field. Both assertions are gone from the port: the
positive one is disabled by `if False`, and the negative one is absent
entirely.

The property is now untestable because the port removed the field. The legacy
wrapper printed it (`tests/fixtures/bp5/legacy/wfc-archive-run:502`,
`printf 'checkout:   %s\n' "$checkout_id"`), whereas
`archive.py::render_report` (`archive.py:899-932`) emits no `checkout:` line
at all; `ArchiveReport.checkout_id` is populated on every path and never
rendered. `test_archive_port.py`'s module docstring enumerates four documented
porting adaptations and explicitly claims the old commit *body*'s "identity
narrative is on stdout instead" -- which is inaccurate for `checkout_id`,
which did not move but disappeared. The `H001` worker-verification artifact's
section 5 likewise asserts that every non-1:1 legacy case "is each named and
explained in the port modules' own docstrings"; this one is not.

This is bounded and cheap to resolve either way, and both ways stay inside the
authorised BP5 candidate files: render the `checkout:` line in
`render_report()` and restore both legacy assertions, or keep the report
surface as it is and document the omission explicitly in
`test_archive_port.py`'s adaptation list alongside the other four, replacing
the `if False` construct with a plain assertion. What is not acceptable under
the stated criteria is an inert assertion that reads as if it were still
checking the ported property.

== Nonblocking observations

These are recorded here and in the result summary only. They are not Finding
transitions; this Hop's `finding_authority` is `resolve` and no current-Run
Finding exists.

. *Resume reverification does not re-derive the manifest from sources.*
  `_verify_resumable_placement()` checks `attempt_id`, recorded sources and
  each file's own digest/size against the placed manifest, but unlike the
  already-committed no-op path (`archive.py:829-837`, which compares a freshly
  computed candidate manifest) it does not re-derive `facts`/`semantic`. A
  tamperer who edits a placed file *and* consistently rewrites its digest plus
  the extracted facts would resume. This is outside the properties item C
  enumerates (changed data/digest, size, attempt and source identity, unsafe
  paths), all of which are correctly refused, so it is not treated as an
  acceptance violation -- but a future hardening pass could reuse
  `_manifests_match_ignoring_archived_at()` on the resume path too.
. *Dead `resumed_commit` outcome.* `ArchiveReport.outcome` documents
  (`archive.py:614`) and `render_report()` maps (`archive.py:903`) a
  `"resumed_commit"` value that no code path ever assigns -- the resume path
  returns `outcome="archived"` (`archive.py:884`). Cosmetic dead enumeration
  text with no observable behavioural difference; already assessed nonblocking
  by the two prior independent reviews and still open. Not re-raised.
. *Cross-attempt staging leftovers block archiving.* `_assert_narrow_cleanliness`
  allows dirty paths only under the *current* attempt's destination and
  staging prefixes, so leftover `.wfc-archive-staging/<other-attempt>/...`
  from a different killed attempt is reported as "not clean outside the
  archive destination". The ported test only covers the same-attempt case
  (`test_stale_staging_from_a_prior_killed_attempt_does_not_block_a_fresh_archive`
  reuses `fx.attempt`). The behaviour errs safe (refuse, mutate nothing) and
  the operator documentation's cleanliness wording is not wrong, but the
  cross-attempt case is undocumented and untested.
. *Ignored-destination edge case.* `_path_is_tracked_clean()` infers "already
  committed" from the absence of status lines, so a destination that existed
  but was git-ignored would be reported as `no_op` with `commit: None` rather
  than refused. Not reachable in the real Evidence repository layout, where
  `archive/` is tracked.
. *Equivalence compares manifests, not raw trees.* Re-checked and still
  assessed as sufficient: the manifest carries every copied file's path,
  SHA-256 and byte count, and both sides are driven from the identical
  relocated state root and OPS directory.

=== 6. Items B and C -- guards, tests, and the Commission's own pre-fix probe

Read in the code first. `assert_no_symlink_escape()` (`archive.py:172-187`)
