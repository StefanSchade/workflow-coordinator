=== Method

. *Baseline diff reading.* `git diff --numstat 69099da..097bc64` over every

. *Mutation testing of the delivered suite.* The product tree was copied out

=== Blocking Finding

[[f001]]
==== F001 -- Git path quoting is never decoded, so in-scope work with a space or a non-ASCII character in its name is refused as "outside authorized scope"

Severity:: *Blocking.* Reproduced violation of acceptance case (1) ("in-scope
dirty and untracked work: ref `refs/wfc/preserved/<run_id>/1` created") and of
the `Deliver` item 3 capture predicate ("every changed or untracked path lies
inside the Run's authorized scope -- any dirty path outside it is refused as
unattributable provenance"), plus a false durable fact under item 5.

`git_facts.preserve_candidate` reads the changed set with

[source,python]
----
status = read_git("status", "--porcelain=v1", "--untracked-files=all", "--no-renames")
for line in status.splitlines():
    if line.startswith("?? "):
        untracked_paths.append(line[3:])
    elif line:
        tracked_paths.append(line[3:])
----

`core.quotePath` defaults to `true`, so Git emits any path containing a space,
a non-ASCII byte, a quote, a backslash or a control character as a C-quoted
string. `line[3:]` therefore yields `"src/a b.txt"` -- *including* the literal
double quotes and, for non-ASCII bytes, octal escapes -- which is never
decoded. The containment test

[source,python]
----
def in_scope(path: str) -> bool:
    return any(root == "." or path == root or path.startswith(f"{root}/") for root in scope)
----

then fails for a path that demonstrably *is* inside the authorized scope, and
capture is refused.

*Reproduction A (unit level, `preserve_candidate` directly).* Disposable repo,
authorized scope `("src",)`, `HEAD` unmoved, nothing else dirty:

[cols="1,3"]
|===
|Worktree state |Result

|untracked `src/a b.txt`
|`PreservationRefused: preservation path is outside authorized scope: "src/a b.txt"`

|untracked `src/ümlaut.txt`
|`PreservationRefused: preservation path is outside authorized scope: "src/\303\274mlaut.txt"`

|tracked, modified `src/t s.txt`
|`PreservationRefused: preservation path is outside authorized scope: "src/t s.txt"`

|untracked `src/deep/deeper/n.txt` (control)
|preserved, ref created
|===

The raw porcelain for the first row is `?? "src/a b.txt"`, confirming the
quoting rather than any scope misconfiguration.

*Reproduction B (end to end, real `wfc run`).* Using the delivered

*Why this is blocking and not a nit.*

. Acceptance case (1) is simply not met for an ordinary filename. A space in a
  path is not an exotic input; it is routine in documentation and asset paths,
  and BP4b's whole purpose is to preserve unadopted work for exactly the Runs
  that ended badly.
. The journalled reason is *false*. The task frames an out-of-scope dirty path
  as "unattributable provenance"; the record here asserts that an in-scope
  path lies outside the Run's authorized scope. BP4b's premise is that every
  durable fact it writes is honest, and this one is not. Acceptance case (15)
  requires every refusal to be journalled "with its reason"; the reason given
  misstates the repository fact that caused it.
. The refusal is *terminal*. `frontdoor.preservation.run_pending_preservation`
  returns early once any terminal `ext.preservation.*` record exists, and the
  limitations record states refusals are deliberately not retried. An affected
  Run can therefore never preserve its work, on any later `run` or `resume`.

*Not a safety hole.* The failure direction is fail-safe in every shape probed:
a quoted path can never satisfy a non-root scope root, and under a root scope
(`allowed_paths=(".",)`) `in_scope` admits it but `git add -A -- '"src/a
b.txt"'` fails and the error surfaces as
`PreservationRefused: fatal: pathspec '"src/a b.txt"' did not match any files`.
The repository was byte-identical after every one of those refusals. The
defect is availability and honesty, not a mis-capture.

*Note on precedent.* The pre-existing `salvage_inventory`,
`salvage_omissions` and `_changed_worktree_paths` helpers parse
`git diff --name-only` / `git ls-files --others` output the same way and share
the same weakness. Per the reviewer instruction, a reproduced acceptance
violation is not downgraded because the behaviour already exists elsewhere;
BP4b's own acceptance matrix is what is being gated here, and fixing it is
additive (for example `--porcelain=v1 -z` with NUL splitting, or
`-c core.quotePath=false`, inside the new function only). The frozen BP4a
contract does not require the quoted form, so a correction here needs no BP4a
change.

=== Non-blocking observations

These are reported here and in the Hop summary only. `finding_authority:
[resolve]` does not authorize residual transitions, and none of them is a
reproduced violation of an acceptance case.

O1:: *Create-only ref creation is not pinned by any test.* Dropping the empty
old-value argument from `update-ref` leaves the delivered suite green, because
the identical-tree early return fires first on the only repeat path the suite
exercises. The behaviour itself is correct.

O2:: *Refusal wording leaks salvage vocabulary.* The FIFO and symlink
refusals surface as `salvage path is not a regular in-repository file: ...`
inside a *preservation* refusal, because `_reject_unsafe_scope_special_files`
is reused verbatim. Accurate, but it names the wrong subsystem in a durable
journal record.

O3:: *A pure deletion reports `file_count: 0, bytes: 0`.* Deleted paths are
skipped by the sizing loop, so a capture consisting only of deletions
journals an `ext.preservation.result` whose counters say nothing was
captured, although a real tree and ref were created.

O4:: *Any in-scope symlink is refused, not only escaping ones.* The
`S_ISLNK` check refuses a benign in-repository symlink too. More conservative
than the stated predicate; safe, but it narrows what can ever be preserved.

O5:: *`_reject_unsafe_scope_special_files` walks the whole authorized scope,
not the changed set.* A special file anywhere under scope refuses the capture
even when it is unrelated to the changed paths, and with a root scope the walk
descends into `.git`. Correctness is fail-closed; cost and over-refusal grow
with scope size.

O6:: *A non-`PreservationRefused` exception escaping the glue would change the
BP4a exit code.* `run_pending_preservation` only catches
`git_facts.PreservationRefused`. An `OSError` from reading
`commission/request.yaml`, a plain `GitPreflightError` from
`_repository_identity`, or an `OSError` from `tempfile`/`shutil` would
propagate into `cmd_run`/`cmd_resume`, which map an unclassified error to
`refused_prelaunch` (exit 22) -- replacing, for example, exit 14
(`interrupted`). Not reproduced: every refusal path reachable in this Hop
converts correctly. A defensive catch-all around the whole step would close
it.

O7:: *The lock-held refusal writes to the journal without the ownership
lock.* When `try_acquire_lock` returns `None`, `ext.preservation.refused` is
appended anyway, concurrently with whatever the lock holder is appending.
`Journal.append` derives `seq` from a full read of the file, so two
concurrent appenders can emit duplicate sequence numbers.

O8:: *Every refusal is terminal and never retried.* Documented in the
limitations record, including the lock-contention caveat. It is what makes
F001 permanent for an affected Run, and it means a transient refusal (lock
contention) also permanently forfeits preservation for that Run.

O9:: *The observation reads do not use the trusted execution policy.*
`preserve_candidate`'s `rev-parse`/`status`/`submodule status` calls run with
`{**os.environ, GIT_OPTIONAL_LOCKS, GIT_INDEX_FILE}` and `trusted=False`, so
`core.hooksPath=/dev/null` and `core.fsmonitor=false` are not applied and
inherited `GIT_*` variables are not stripped. This matches the pre-existing
`salvage_omissions` read pattern, but `Deliver` item 4 asks for the trusted
Git execution policy; a repository-configured `core.fsmonitor` hook could run
during capture observation. The *mutating* half (`read-tree`, `add`,
`write-tree`, `commit-tree`, `update-ref`, `for-each-ref`) does use the
trusted policy.

O10:: *`wfc status` is silent when no preservation fact exists.* Truthful, but
an operator cannot distinguish "preservation does not apply to this
classification" from "preservation has not run yet".

O11:: *The delivered acceptance-(2) test is not rename-shaped.* It stages a
modification rather than a rename. The genuine rename-shaped case was
reproduced separately in this Hop and does work; the suite simply does not
pin the shape the acceptance matrix names.

O12:: *Several refusal tests are not message-pinned.*
`test_escaping_symlink_in_scope_is_refused` uses a bare `pytest.raises`, so it
cannot distinguish which of the three redundant guards fired, nor an unrelated
refusal reason.
