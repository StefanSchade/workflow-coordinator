== Non-blocking observations

. *Guidance citation precision (maintainer-owned input).* Three rules are
  grounded in existing practice but not in the source named next to them.
  "Never weaken or delete a test to make a change pass" is attributed to
  `ch03_engineering_conventions.adoc` ("same source"), which does not contain
  it; its actual grounding is
  `docs/operator_manual/ch07_diagnostics/02_failure_modes.adoc:69` ("quietly
  weaken binding criteria") plus repeated Commission wording ("without
  weakening the real-leak refusal"). "A review checks the whole product against
  its baseline, not only the last correction" names no source; it restates the
  standing broad-review Commission wording ("evaluate the ENTIRE product
  against the baseline and this task", e.g.
  `governance/commissions/wfc-beta1-bp6c-lifecycle-archive-wiring-001/task.md`)
  and `ch02_commissioning/03_review.adoc:39-41`, but read unqualified it
  overshoots that same chapter's normative bounded-rereview guidance
  (`03_review.adoc:41-58`: a rereview should normally narrow rather than reopen
  the full adversarial surface). "Committed artifacts contain no secrets and no
  absolute home-directory paths" names no source; it restates the BP6b
  retention/privacy practice and the cutover plan's own "No absolute `$HOME`
  path is ever written". Not blocking: each rule exists as practice in this
  repository, the document's own precedence clause subordinates it to its
  sources, and no new standard is imposed. Recommended, if the maintainer
  revisits the file: qualify the review rule as applying to an *initial*
  independent review and add the three missing citations.
. *Both default roles make a worker-only program unresolvable.* Reproduced:
  `resolve_execution(config, {}, ("worker",))` refuses with "execution config
  defaults name roles the selected program does not use:
  independent_reviewer" (`config.py:216-221`). With both bindings committed, a
  Run on a program whose role set excludes `independent_reviewer` (for example
  `simple@v1`, which also refuses an `independent_reviewer` persona) needs a
  config edit or a different program. This is a direct consequence of
  `open-decisions` item 3's recommendation, not a defect, but it is worth
  knowing before Proof Run 1 picks a program.
. *Absolute-path scan does not see list items.* The test's loop takes
  `line.split(":", 1)[-1]`, so an absolute value written as a YAML sequence
  item (`  - /abs`) would yield `- /abs` and escape the `startswith("/")`
  check. Harmless for the committed file and for any realistic mutation: the
  only list is `work_item_scope_ceiling`, whose entries must already satisfy
  the A1 repository-relative shape in `commissioning._path` (an absolute entry
  is a parse refusal), the exact ceiling tuple is asserted separately, and the
  `/home/` substring check covers the whole text.
. *"changes no behavior on its own" is precise only for the Harness path.*
  `plan.py:35`, `lifecycle.py:71` and `init.py:30` all default `--config` to
  `.wfc/config.yaml`, so committing the file is exactly what lets a no-flag
  `wfc plan`/`wfc run` against this checkout resolve a Consumer Config at all
  (previously such an invocation exited 2 with "cannot read Consumer Config").
  The sentence is accurate for what the chapter describes -- no product code
  and no current self-development path behaviour changes -- and the following
  sentence prevents a misleading reading, so this is wording precision only.
