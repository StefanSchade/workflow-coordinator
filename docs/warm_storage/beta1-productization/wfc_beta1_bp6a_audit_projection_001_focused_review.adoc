=== 3. `F001` -- resolved

The Finding: three fields of the frozen `wfc.audit/1` allow-list carried no
mutation-sensitive assertion, so the acceptance preamble and case (1) were not
met for them -- `attempt_id` was asserted nowhere, `anomaly_count` only as
`== 0` on an anomaly-free fixture, and `run.semantic_stop_present` only as
`is False` on a fixture with no semantic stop.

Reproduced as inverted, by mutation, independently of the H003 Hop's own
claims. Method: `git archive HEAD` into an ignored scratch tree outside the
product (`tmp/review-h004/`, removed afterwards); each mutation applied to
that copy's `audit.py` only; the three delivered BP6a modules then run in full
with `PYTHONDONTWRITEBYTECODE=1` and `--rootdir` pointed at the copy, so that
the copy's `src/` -- not the repository's -- is the module under test. That
substitution was *proved*, not assumed: a deliberate sanity mutation
(`"schema": SCHEMA` -> `"schema": "MUTANT-SANITY-CHECK"`) failed
`test_every_frozen_field_has_the_exact_source_value` with
`assert 'MUTANT-SANITY-CHECK' == 'wfc.audit/1'`, so a surviving mutation below
could not be an artifact of the repository's editable install shadowing the
copy. Each mutation was reverted exactly before the next, and the copy was
confirmed byte-identical to the worktree `src/` (`diff -r`) at the end.

Each of the three mutations that `F001` reported as surviving the H002 suite is
now killed, and the boolean is pinned at both values, so neither a constant
`True` nor a constant `False` survives. The anomaly test pins three distinct
counts (0, 1, 3), so a mutation that merely saturates the count
(`min(len(...), 1)`, a presence flag) is killed as well. On the unmutated
module all 75 tests in the three delivered modules pass

=== 6. Non-blocking observations

Reported here and in the Hop summary only; `finding_authority: [resolve]` does
not authorize residual transitions.

O9:: *`attempt_id`'s source is pinned only up to an equivalent mutant.* The
projection reads `manifest["attempt_id"]`; a mutation reading
`attempt_dir.name` instead survives the new tests, because the fixture names
the directory after the attempt id. That is not reachable as a defect:
`archive.py` derives the attempt id from the state-root basename, places the
archive at `.../archive/<domain>/<workstream>/<attempt_id>`, and
`_place_archive` refuses a manifest whose `attempt_id` disagrees with the
destination -- so for any archive this repository's archiver writes the two
sources are the same string. Recorded only because the assertion pins the
*value*, not the source key.
O10:: *The new anomaly test does not itself assert that the anomaly prose is
absent*, though `F001`'s suggested correction mentioned it. It supplies
`PROVIDER_PROSE_CANARY` as an anomaly and asserts only the count; the prose
exclusion for exactly that fixture shape is covered by
`test_audit_privacy.py::test_full_canary_run_leaks_nothing`. Coverage is
therefore complete across the suite, just split across two modules.
O11:: *The H003 Hop summary's test count is off.* It reports "all 78 tests
across the three delivered BP6a test modules pass"; collection at `9de0e92`
yields 75 (42 + 13 + 20), consistent with H002's 72 plus the three new test
functions. The suite itself is green; only the number in the prose is wrong.

H002's O1-O8 are carried forward unchanged; this pass found no evidence
contradicting any of them, and the H003 correction neither addresses nor
worsens any of them.

=== 7. Agent-local environment limitations

`tests/unit/test_commissioning.py` errors in the out-of-tree scratch copy
because its fixture runs `git clone --local` against the product root and the
copy is a plain `git archive` extraction, not a repository
(`fatal: repository '.../tmp/review-h004' does not exist`). That is an
artifact of this reviewer's own method, not a candidate defect; the module was
therefore re-run against the real worktree, where the clone fixture works.
`tests/unit/test_wfc_op.py` and `tests/unit/test_claude_adapter_conformance.py`
were excluded from the wider run: as recorded in the H002 pass they fail here
because a nested `pip install` cannot reach a package index
(`No matching distribution found for setuptools>=68`) and because the
adapter's temporary-directory symlink target under `/tmp` is not writable in
this sandbox. `tests/architecture/test_bp1_identity.py::test_installed_identity_and_real_preflight`
fails for the first of those two reasons and was observed, not worked around;
`tests/architecture/test_offline_distribution.py` was not run for the same
reason. Nothing was downloaded and no sandbox setting was changed.
Several reviewer conveniences were refused by the sandbox (compound `git diff`
invocations, `python -c` with a runtime-expanded path, `find -exec`); each was
worked around with a literal path or a single command and cost no evidence.

All agent-side runs above are exploratory partial runs (`--wfc-partial`) and
are *not* Coordinator-trusted evidence; the Coordinator's full task-check
remains authoritative.

No implementation, test, fixture, document or Git state was modified by this
reviewer. Every mutation ran in a `git archive` extraction of `HEAD` under the
repository's ignored `tmp/` scratch tree, which was removed afterwards (an
