== `F002` -- neutralised ported conformance assertion: resolved

=== The finding's own framing, re-checked against the sources

`F002` reported `tests/unit/test_archive_port.py:317`'s
`assertIn(f"checkout:   {CHECKOUT}" if False else f"repository: {TARGET_REPO}", ...)`
as an inert assertion whose paired negative (forged checkout id must not
appear) was missing, with the guarded property dropped because
`render_report` emits no `checkout:` line. Read against the actual sources, the
inertness and the missing negative are real, and the explanation is narrower
than "silently dropped":

* the legacy assertions at
  `build/wfc/bp5-evidence-inputs/tests/test_wfc_archive_run.py:312` and `:315`
  read the git *commit body* (`body = git(fx.repo, "log", "-1", "--format=%B")`),
  not `proc.stdout` -- confirmed by reading the whole method, whose only stdout
  assertion is the final `files:` line;
* `git_facts.NewPathCommitIntent` (`src/workflow_coordinator/git_facts.py:69-79`)
  carries `paths` and `subject` only, with no body field, and
  `archive.py:874` constructs it that way -- so the new implementation has
  no commit-body surface at all for a `checkout:` line to live on;
* `archive.render_report` (`archive.py:899-932`) emits no `checkout:` line and
  never reads the populated `ArchiveReport.checkout_id`.

The legacy proof is therefore genuinely non-applicable rather than merely
unported, which is precisely the case the original acceptance requires to be
*documented*.

=== The guarded property is covered, and more strongly

`archive.run_identity` (`archive.py:469`) resolves `checkout_id` through
`_agree("checkout_id", ("operator-summary.json", summary),
("checkout-association.json", assoc))`, which raises `ArchiveError` on
disagreement. That is fail-closed refusal of the whole archive, strictly
stronger than the legacy display-time scrubbing. It is exercised by the
pre-existing `RefusalTests.test_disagreeing_checkout_id_across_sources_is_rejected`,
which I ran directly alongside the repaired test:

[source,shell]
----
$ python -m pytest --wfc-partial -v \
    "tests/unit/test_archive_port.py::RefusalTests::test_disagreeing_checkout_id_across_sources_is_rejected" \
    "tests/unit/test_archive_port.py::IdentityConsistencyTests"
4 passed
----

The forgery test itself still asserts every *reportable* field the legacy
negative assertions guarded: `repository` and `files` positives, plus negatives
for `files:      99999`, `repository: /attacker/claimed/repository` and
`ops:        /attacker/claimed/ops` (`test_archive_port.py:328-332`). The
injection vector the legacy test defended against -- a newline-bearing
`run_id` smuggling TSV fields through the wrapper's internal protocol -- has no
analogue in the port, which reads JSON directly.

=== The remedy matches what the Finding asked for

`F002` offered two bounded remedies: render the line and restore both
