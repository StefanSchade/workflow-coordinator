==== B-2 — The secondary install path promises a `source_commit` the product reports as `null`

*Invariant.* Statements about `wfc --version --json` are verified against the
implementation (task: topics "verify each against the implementation and say
only what the implementation supports"; Default escalation: no statement you
cannot verify).

*Reproduced.* `01_quickstart.adoc:139-149` introduces the secondary path as
"Installing from a release artifact (sdist or wheel) *or a source checkout*",
shows `pip install /path/to/workflow-coordinator` into a venv followed by
`wfc --version --json`, and then states: "For a source checkout at a clean,
matching commit, `--version --json` *instead* reports that commit's SHA as
`source_commit`."

`implementation_identity._source_commit` (`:22-45`) returns `None` unless
`root.parent.name == 'src'`, where `root` is the resolved location of the
executing package. A venv install — wheel, sdist, or the plain path install
shown directly above the sentence — puts the package under `site-packages`,
so the answer is `null`, exactly as for the wheel. A SHA appears only when
the executing package *is* `<repo>/src/workflow_coordinator` (an editable or
in-place install), and then only if `git status --porcelain
--untracked-files=all` is empty and every committed file under
`src/workflow_coordinator` matches byte for byte (`:33-42`). Two independent
sources confirm it: `CLI_FACTS.txt` line 1 records an installed 0.1.0b1 built
from commit `98ac012`, and line 182 shows `"source_commit": null` for it; and
`docs/developer_guide/ch04_release_management.adoc:68-71` (C3) already states
the canonical rule — install "the *built artifact* (not an editable
checkout)" and "assert … `source_commit` is `null`".

*Why it blocks.* A reader who follows the shown command sees `null` where the
page promised a SHA, in the one paragraph whose job is to tell them what a
correct install looks like. The task required this exact check to be stated
plainly; the wheel half is right and the checkout half is wrong, which is
worse than saying nothing.

*Feasible correction.* One clause: a SHA appears only when `wfc` runs from
the checkout itself (an editable install) with a clean tree whose committed
package bytes match; every artifact install, including `pip install <path>`,
reports `null`. The canonical statement already exists at
`ch04_release_management.adoc:68-71` and can be linked rather than restated.
