== 2. Blocking Finding F-DIRENTRY -- the audit exempts every slash-terminated archive entry from the C2 allow-list

*Invariant violated.* C2, in the chapter and in plan section 3: "the audit
fails on anything *unlisted*, not only on the forbidden names ..., so a new
top-level directory cannot leak in silently"; forbidden by name in both
artifacts are `docs/`, `tests/`, `governance/`, `project_memory/`, `.wfc/`,
`scripts/`, `requirements/`, `tmp/`, `build/`. Task DO (2): "checks every
archive entry against the C2 allow-list exactly as the chapter writes it ...
fails on anything unlisted".

*What the code does.* `scripts/wfc_dist_audit.py:45-46` and `:56-57` both
begin their allow-list predicate with an unconditional exemption:

[source,python]
----
if name.endswith("/"):      # _wheel_entry_allowed
    return True
if not relative or relative.endswith("/"):   # _sdist_entry_allowed
    return True
----

Every entry whose name ends in a slash is therefore never tested against the
allow-list at all -- including the names C2 forbids outright. This single
special case produces a false pass and a false failure, in opposite
directions.

*(a) False pass, reproduced.* A wheel containing a zip entry named exactly
`docs/` and carrying a 14-byte payload audits clean:

----
wheel names: ['workflow_coordinator/__init__.py', <the four resource texts>, 'docs/']
payload size of docs/ entry: 14
wheel audit: []
----

`tests/`, `.wfc/`, `governance/` and every other forbidden or unlisted
directory name behave the same way. This is the one case C2's rationale
sentence names, and the tool's own failure message advertises those names as
enforced.

*(b) False failure on the real sdist shape, reproduced.* `tarfile` strips the
trailing slash from a directory member when reading, so for an sdist the
exemption never fires and legitimate directory members fall through to the
file rules instead. `_sdist_entry_allowed` accepts `src/...` but not the bare
directory name `src`, so the member
`workflow_coordinator-0.1.0b1/src` is reported as an unlisted entry. I could
not run `python -m build` here (<<e2-environment>>), so I built the archive
through the same archiving path setuptools uses -- distutils'
`archive_util.make_tarball`, i.e. a recursive `tarfile.add(base_dir)`, which
`shutil.make_archive(..., "gztar")` performs identically -- over a staged tree
holding only allow-listed content:

----
total members: 17  dirs: 6
VIOLATIONS: 1
   workflow_coordinator-0.1.0b1.tar.gz: unlisted entry 'workflow_coordinator-0.1.0b1/src'
----

If a real `python -m build` sdist carries directory members, as that code path
produces, then `make dist-audit` exits 1 on a conforming release artifact
(G3 cannot pass) and the extended distribution test's
`assert dist_audit.audit(archive) == []`
(`tests/architecture/test_offline_distribution.py:42-43`) fails on the
artifact it just built. The chapter's measured sdist inventory does not settle
this by itself -- 49 entries is consistent both with 43 files plus six
directory members and with 49 files including the `src/*.egg-info` set -- so
the decisive measurement on a real build belongs to Coordinator-trusted
evidence. Part (a) is reproduced unconditionally and requires the same fix
regardless of how (b) measures.

*Why the fixtures did not catch it.* `_write_sdist`
(`tests/unit/test_release_tooling.py:224-230`) writes every entry as a default
`TarInfo`, i.e. `REGTYPE`, so the synthetic sdist contains no directory member
and never exercises the real archive shape; no wheel case uses a
slash-terminated name. The Worker's "rejects a forbidden entry" case uses
`docs/evil.adoc`, which the file rules catch on the file name, not on the
directory.

*Feasible remedy, verified here.* Drop the special case and test every entry
uniformly after normalising the trailing slash, allowing a directory name only
when it names an allowed tree: for the wheel, `workflow_coordinator`, anything
under `workflow_coordinator/` and anything under a `*.dist-info`; for the
sdist, the archive root, `src` and anything under `src/`. I applied exactly
that to a throwaway copy of the two predicates and re-ran every case:

* the `make_archive`-built real-shape sdist audits clean;
* the wheel with the payload-carrying `docs/` entry yields one violation;
* a wheel with a legitimate `workflow_coordinator/` directory entry still
  audits clean;
* the four existing audit cases are unaffected (their entries are files).

It removes a branch rather than adding mechanism, and keeps "one rule, one
implementation". Per the repository's own test rule, the fix needs a test that
fails without it: the sdist fixture should emit real `DIRTYPE` members (the
shape a build produces) and one wheel case should assert that a
slash-terminated forbidden name is rejected.

== 4. Non-blocking observations

. *The README check enforces absoluteness, not the tag pin.*
  `check_readme_links` refuses any link target that is not `http://`,
  `https://`, `#` or `mailto:`, which is exactly the refusal DO (1) specifies
  and matches the `G1` row ("README links absolute"). An absolute but
  unpinned `blob/main/docs/...` URL would therefore pass, while C5 now reads
  `must link ... only by absolute, tag-pinned repository URL`. The chapter's
  clause "it is enforced mechanically by `wfc_release_check.py`'s README-link
  check" can be read as claiming the pin itself is checked. Either narrow the
  sentence or extend the check to require `blob/<tag>/`; adding the stricter
  check is beyond what the task authorises, so this is recorded, not required.
. *In branch mode without `TAG` the tag-equals-version check is a tautology.*
  `_resolve_tag` derives `v<version>` from `pyproject.toml` and then compares
  it with the same value, so `G1`'s tag-equals-version bites only when the
  operator supplies `TAG`. This follows the chapter's wording, and the
  mismatch case is tested with an explicit tag; worth knowing when running the
  gate by hand.
. *The sdist mapping strips the first path component without asserting a root
  prefix.* An archive without the standard `<name>-<version>/` root is
  mis-mapped: a top-level file maps to the empty string and is allowed. PEP
  625 artifacts always carry the prefix, so this is not reachable from a real
  build, but a one-line assertion that all members share one root prefix would
  close it, and it sits naturally with the F-DIRENTRY fix.
. *The notes check is coupled to the `== <version> -- <status>` heading shape.*
  A frozen heading written as `== 0.1.0b1` alone would be reported as "no
  section for version". That shape is the chapter's own convention and the real
  file follows it, so this is a note about the coupling, not a defect.
. *Link targets in the README check include non-documentation links.* Any
  relative link, documentation or not, is refused, and a relative-looking link
  inside a fenced code block would be flagged. The file has no such case
  today; the broader rule is the safer direction.
