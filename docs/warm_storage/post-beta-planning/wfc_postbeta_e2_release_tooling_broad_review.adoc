==== 3.1 `wfc_release_check.py` -- modes and refusals

On the real checkout it prints one clear line per failed check and exits 1 with
exactly four accurate lines -- branch `wfc/postbeta-e2` not `main`, the
wrapper-dirty tree, HEAD not reachable from `origin/main`, and the still
`planned` notes section -- and no spurious fifth. The absent README line is a
*positive* measurement of the four repaired links, and the `origin/main` sync
line is absent because `refs/heads/main` and `refs/remotes/origin/main` agree.
With `--tag v9.9.9` it adds the fifth line
`tag 'v9.9.9' does not match the version-derived tag 'v0.1.0b1'`, so the
argument plumbing the `release-check` target uses is live.

Mode selection is `git symbolic-ref -q --short HEAD` (`:38`): attached is
branch mode, detached is tag mode. Branch mode adds branch identity, clean tree
and `origin/main` sync; tag mode drops those three and both modes assert
reachability from `origin/main`, tag-equals-version, the notes section and the
README links. Dropping the clean-tree assertion in tag mode is *specified*, not
an omission: the task's DO (1) enumerates tag mode as reachability "plus the
same version, notes and README checks", and the plan's E2 acceptance uses the
same enumeration.

All twenty-two test functions ran in-process against fresh synthetic
repositories with a local bare `origin`: *22 passed, 0 failed*. They cover the
branch-mode pass and every branch-mode refusal the task lists (not `main`,
dirty tree, out of sync, HEAD unreachable, tag/version mismatch, missing notes
section, `planned` notes, repository-relative README link), the tag-mode pass
and the tag-mode refusals (unreachable commit, no exact tag, explicit tag
mismatch, `planned` notes plus relative README link). No case touches the
network or this checkout's state.

Fail-closed behaviour, measured: pointed at a directory that is not a
repository, the tool degrades to tag mode and prints four clear `FAIL:` lines

`README.md` not found) rather than crashing or passing. The notes parser is not

=== 4. Non-blocking observations

Observations 1--5 are carried from `H002`/`H005` because I re-checked them and
they are still accurate; 6--8 are stated here.

. *The README check enforces absoluteness, not the tag pin.*
  `check_readme_links` refuses any target that is not `http://`, `https://`,
  `#` or `mailto:` -- exactly the refusal DO (1) specifies and what the `G1`
  row says. An absolute but unpinned `blob/main/docs/...` URL would pass, while
  C5 now reads "must link ... only by absolute, *tag-pinned* repository URL"
  and adds that it "is enforced mechanically". Narrowing that sentence or
  extending the check would both work; the stricter check is beyond what the
  task authorises, so this is recorded for the maintainer, not required.
. *In branch mode without `TAG`, tag-equals-version is a tautology.*
  `_resolve_tag` derives `v<version>` from `pyproject.toml` and compares it
  with the same value, so `G1`'s tag-equals-version bites only when the
  operator supplies `TAG`. This follows the chapter's wording ("derived as the
  chapter specifies") and the mismatch case is tested with an explicit tag.
. *`*.dist-info` admits arbitrary content at any depth.* Measured again here:
  a wheel entry `weird.dist-info/anything/at/all.ods` audits clean, because
  the predicate allows any top-level component ending in `.dist-info` (a
  near-miss such as `evil.dist-info.x/F` is rejected). That is a faithful
  transcription of C2's literal `*.dist-info` row, not an implementation
  defect; it is the same chapter-internal tension as "`src/**` allowed" versus
  "any `*.ods` forbidden", and belongs to the maintainer rather than to added
  mechanism in the tool.
. *`_read_version` raises instead of reporting.* A missing or malformed
  `[project] version` in `pyproject.toml` produces a traceback rather than one
  clear `FAIL:` line. Exit status is still non-zero, so no gate passes
  wrongly; only the output shape degrades.
. *The new files are outside `format-check`'s file list.* Correct under the
  withheld authority, which caps Makefile changes at the two targets and their
  `.PHONY`; `lint` (`ruff check .`, `select = ["F"]`) does cover them. A later
  package that widens the format baseline should add the three new files
  deliberately rather than by accident.
. *Residual: a payload-carrying slash-terminated wheel entry inside the package
  tree is tolerated.* Measured: a wheel entry named
  `workflow_coordinator/leak/` carrying a payload audits clean, because
  `_wheel_entry_allowed` treats any slash-terminated name under
  `workflow_coordinator` as a directory. I weighed this as a blocking Finding
  and concluded it is not one: allowing directory entries inside the package
  tree *is* the remedy `F001` was accepted with, no builder emits such an entry
  (a real wheel carries file entries only, measured), the payload is discarded
  as a directory on extraction, and every leak that would actually ship as a
  file is caught (`workflow_coordinator/data.json`, a fifth resource text and
  `workflow_coordinator/docs/x.adoc` each yield a violation). Closing it would
  mean adding a rule the chapter's row does not state -- e.g. rejecting a
  slash-terminated entry whose payload is non-empty -- so it is flagged for the
  maintainer rather than waived or fixed by new mechanism.
. *An entry named `/` normalises to the empty string and is accepted.*
  `_wheel_entry_allowed` returns `True` for a name that is empty after
  stripping slashes. Unreachable from any builder and carries no content;
  mentioned only so the branch is on the record.
. *`./`-prefixed sdist member names would be rejected.* An archive whose
  members are named `./<root>/...` yields violations, because the root is
  compared literally. No builder on this path produces that shape --
  `setuptools`' archiving path and the trusted `task-check`'s real
  `python -m build` artifact both audit clean -- and failing closed is the safe
  direction, but a future change of build backend is worth re-measuring rather
  than assuming.

Two smaller notes that are not defects: `--tag` has two independent sources
(the Makefile's `$(if $(TAG),...)` and the script's `os.environ.get("TAG")`
default), of which only the Makefile path is exercised by
`make release-check TAG=...` since `make` does not export command-line
variables; and the extended distribution test reuses the local name `archive`
for both the `git archive` bytes and the loop's `Path`, which is harmless here
because the earlier value is not read again.

[source,python]
----
def audit_sdist(path: Path) -> list[str]:
    prefix = path.name[: -len(".tar.gz")]
    violations = []
    with tarfile.open(path, "r:gz") as archive:
        for member in archive.getmembers():
            if member.name == prefix:
                continue
            if not member.name.startswith(prefix + "/"):
                violations.append(_violation(path, member.name))
                continue
            if not _sdist_entry_allowed(member.name[len(prefix) + 1 :], member.isdir()):
                violations.append(_violation(path, member.name))
    return violations
----

artifacts are `docs/`, `tests/`, `governance/`, `project_memory/`, `.wfc/`,
`scripts/`, `requirements/`, `tmp/`, `build/`. Task DO (2): "checks every
archive entry against the C2 allow-list exactly as the chapter writes it ...
fails on anything unlisted".

*What the code does.* `scripts/wfc_dist_audit.py:45-46` and `:56-57` both
begin their allow-list predicate with an unconditional exemption:

[source,python]
----
if name.endswith("/"):      # _wheel_entry_allowed
    return True
if not relative or relative.endswith("/"):   # _sdist_entry_allowed
    return True
----

Every entry whose name ends in a slash is therefore never tested against the
allow-list at all -- including the names C2 forbids outright. This single
special case produces a false pass and a false failure, in opposite
directions.

*(a) False pass, reproduced.* A wheel containing a zip entry named exactly
`docs/` and carrying a 14-byte payload audits clean:

----
wheel names: ['workflow_coordinator/__init__.py', <the four resource texts>, 'docs/']
payload size of docs/ entry: 14
wheel audit: []
----

`tests/`, `.wfc/`, `governance/` and every other forbidden or unlisted
directory name behave the same way. This is the one case C2's rationale
sentence names, and the tool's own failure message advertises those names as
enforced.

*(b) False failure on the real sdist shape, reproduced.* `tarfile` strips the
trailing slash from a directory member when reading, so for an sdist the
exemption never fires and legitimate directory members fall through to the
file rules instead. `_sdist_entry_allowed` accepts `src/...` but not the bare
directory name `src`, so the member
`workflow_coordinator-0.1.0b1/src` is reported as an unlisted entry. I could
not run `python -m build` here (<<e2-environment>>), so I built the archive
through the same archiving path setuptools uses -- distutils'
`archive_util.make_tarball`, i.e. a recursive `tarfile.add(base_dir)`, which
`shutil.make_archive(..., "gztar")` performs identically -- over a staged tree
holding only allow-listed content:

----
total members: 17  dirs: 6
VIOLATIONS: 1
   workflow_coordinator-0.1.0b1.tar.gz: unlisted entry 'workflow_coordinator-0.1.0b1/src'
----

If a real `python -m build` sdist carries directory members, as that code path
produces, then `make dist-audit` exits 1 on a conforming release artifact
(G3 cannot pass) and the extended distribution test's
`assert dist_audit.audit(archive) == []`
(`tests/architecture/test_offline_distribution.py:42-43`) fails on the
artifact it just built. The chapter's measured sdist inventory does not settle
this by itself -- 49 entries is consistent both with 43 files plus six
directory members and with 49 files including the `src/*.egg-info` set -- so
the decisive measurement on a real build belongs to Coordinator-trusted
evidence. Part (a) is reproduced unconditionally and requires the same fix
regardless of how (b) measures.

*Why the fixtures did not catch it.* `_write_sdist`
(`tests/unit/test_release_tooling.py:224-230`) writes every entry as a default
`TarInfo`, i.e. `REGTYPE`, so the synthetic sdist contains no directory member
and never exercises the real archive shape; no wheel case uses a
slash-terminated name. The Worker's "rejects a forbidden entry" case uses
`docs/evil.adoc`, which the file rules catch on the file name, not on the
directory.

*Feasible remedy, verified here.* Drop the special case and test every entry
uniformly after normalising the trailing slash, allowing a directory name only
when it names an allowed tree: for the wheel, `workflow_coordinator`, anything
under `workflow_coordinator/` and anything under a `*.dist-info`; for the
sdist, the archive root, `src` and anything under `src/`. I applied exactly
that to a throwaway copy of the two predicates and re-ran every case:

* the `make_archive`-built real-shape sdist audits clean;
* the wheel with the payload-carrying `docs/` entry yields one violation;
* a wheel with a legitimate `workflow_coordinator/` directory entry still
  audits clean;
* the four existing audit cases are unaffected (their entries are files).

It removes a branch rather than adding mechanism, and keeps "one rule, one
implementation". Per the repository's own test rule, the fix needs a test that
fails without it: the sdist fixture should emit real `DIRTYPE` members (the
shape a build produces) and one wheel case should assert that a
slash-terminated forbidden name is rejected.

== 4. Non-blocking observations

. *The README check enforces absoluteness, not the tag pin.*
  `check_readme_links` refuses any link target that is not `http://`,
  `https://`, `#` or `mailto:`, which is exactly the refusal DO (1) specifies
  and matches the `G1` row ("README links absolute"). An absolute but
  unpinned `blob/main/docs/...` URL would therefore pass, while C5 now reads
  `must link ... only by absolute, tag-pinned repository URL`. The chapter's
  clause "it is enforced mechanically by `wfc_release_check.py`'s README-link
  check" can be read as claiming the pin itself is checked. Either narrow the
  sentence or extend the check to require `blob/<tag>/`; adding the stricter
  check is beyond what the task authorises, so this is recorded, not required.
. *In branch mode without `TAG` the tag-equals-version check is a tautology.*
  `_resolve_tag` derives `v<version>` from `pyproject.toml` and then compares
  it with the same value, so `G1`'s tag-equals-version bites only when the
  operator supplies `TAG`. This follows the chapter's wording, and the
  mismatch case is tested with an explicit tag; worth knowing when running the
  gate by hand.
. *The sdist mapping strips the first path component without asserting a root
  prefix.* An archive without the standard `<name>-<version>/` root is
  mis-mapped: a top-level file maps to the empty string and is allowed. PEP
  625 artifacts always carry the prefix, so this is not reachable from a real
  build, but a one-line assertion that all members share one root prefix would
  close it, and it sits naturally with the F-DIRENTRY fix.
. *The notes check is coupled to the `== <version> -- <status>` heading shape.*
  A frozen heading written as `== 0.1.0b1` alone would be reported as "no
  section for version". That shape is the chapter's own convention and the real
  file follows it, so this is a note about the coupling, not a defect.
. *Link targets in the README check include non-documentation links.* Any
  relative link, documentation or not, is refused, and a relative-looking link
  inside a fenced code block would be flagged. The file has no such case
  today; the broader rule is the safer direction.
