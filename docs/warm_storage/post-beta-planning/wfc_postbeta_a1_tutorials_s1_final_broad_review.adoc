  file under `docs/operator_manual/` uses `anchor:id[]` or `+[#id]+` at all
  today, and the tree passes, so nothing is wrong now; `doc_conventions.adoc`
  does use the macro form, but it is in another book and outside the guard's
  decided scope (D4). I would not add mechanism for this: the guard matches
  its specification, and the one-line extension is obvious if a future leaf
  ever needs it.

  lines of the long replaced references start at column 0 inside an indented
  list item or sentence. AsciiDoc continues the item's paragraph regardless,
  and I verified the rendered structure is correct (section 4), so this is
  style only, not a defect; it differs from the surrounding file's habit of
  indenting continuations.
