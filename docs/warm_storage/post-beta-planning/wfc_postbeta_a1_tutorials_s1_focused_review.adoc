. *The guard covers `+<<…>>+` only.* `xref:` macro references and anchors
  declared with the `+anchor:id[]+` inline macro are outside it. I confirmed
  there is no live instance: no manual leaf declares an `+anchor:id[]+`
  anchor, and the single `xref:` in the manual
  (`ch02_commissioning/02_authoring.adoc:175`) targets a relative file path
  with no fragment, which works standalone. The FTR named only the
  `+[[target]]+` and `+[#target]+` forms, so the implementation matches its
  specification; this matters only if D4 later extends the guard to a book
  that uses the macro form, as `docs/ai_info/doc_conventions.adoc` does.
. *Wrapped `link:` macros start continuation lines at column 0* in
  `02_first_run_example.adoc` and `02_worked_sequence.adoc`. It renders
  correctly — verified above — and the long macro leaves little choice, but
  it makes those paragraphs harder to re-wrap later. Recorded as the earlier
  pass recorded it, not as a request.

  pointing at the chapter file as the Commission required; the pre-existing
