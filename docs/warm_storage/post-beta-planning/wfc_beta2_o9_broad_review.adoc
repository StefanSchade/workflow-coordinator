=== 2. The design, judged before the code

The `Design` section is dated 2026-11-27, sits in the record the slice names
(not in a review artifact), states the decision first, and names the rejected
alternatives and the preserved property for each. I judge it sound and the
decision correct, for three reasons of my own:

* *It refuses the only form with a benefit, on the right ground.* The
  evaluation does not reach "do not ship" by deferring to AD-6 -- which the
  Beta rule would not have allowed -- but by showing that the single
  Hop-saving entry removes the second party from a two-party assurance. The
  substitute's Worker Hop is not overhead; in every precedent it wrote the
  verification record the independent review then judged, which I verified in
  the P1 final-assurance record's own header
  (`Sections 1-6 were written by …{nbsp}H001 (Worker) … The independent
  reviewer re-verifies the whole final plan from scratch after this Hop`).
  Shipping AD-6's shape would have delivered precisely the form this
  Commission's withheld authority forbids.
* *It does not substitute new mechanism for the missing object of review.*
  The tempting repair -- widen the review phase's `authorized_scope` so the
  entering reviewer can produce what it reviews -- is identified and rejected
  because it merges the Worker and reviewer roles. The alternative that is
  kept (C: a reviewed commit range pinned in the Commission, admission-checked
  and projected as trusted context) is honestly priced as new trusted request
  *and* Run state rather than "one request field", and deferred on proportion
  with three named reopening triggers. That is a deferral a later Run can act
  on, not a silent drop.
* *It corrects two of its own prior claims instead of inheriting them.* The
  earlier "review entry interacts with durable-artifact admission" is narrowed
  to the legacy `--durable-artifact` path, because the mapped admission the
  renderer always produces is entry-independent; and the "`durable_artifacts`
  needs per-entry population" line of the `Possible shape` section is marked
  superseded. Both corrections are right (section 1), and the record marks the
  superseded text at the text rather than leaving a reader to reconcile it.

I also agree with what the slice deliberately did *not* do. AD-6 is not
amended: its decision already says the capability is "revisited after a
renewed cost-benefit assessment", this is that assessment and it upholds the
deferral, and an accepted versioned ADR with drifted citations is the
maintainer's to change -- the record names the single dated pointer and the
four stale citations a maintainer would refresh. `Status::` and `Priority::`
stay as the maintainer wrote them, and no acceptance or closure is claimed.

=== 4. Simplicity and maintainability

The cheapest possible realisation of this slice is the one it chose: no new
mechanism, no new state, no new refusal, no new public surface, and one
durable document that explains why. I looked for the opposite failure -- an
evaluation that quietly leaves work for later -- and did not find it:

* The decision is *reversible on named evidence*, not on taste. Three triggers
  with thresholds (O10 integrated and a case left over; three recorded
  recurrences in the friction log; the AD-1 two-table collapse) and one kept
  shape mean a later Run re-opens this from a stated position instead of
  re-deriving it. I verified that AD-1 does name those two tables as the
  simplification it leaves open and that its boundary table already lists a
  non-default entry phase among the things needing compiler changes there.
* The effort section is the honest version of AD-6's estimate rather than a
  restatement of it. Two of its load-bearing details I checked myself: the
  Consumer Request parser does support an `optional` set and the Consumer
  Config uses it (`commissioning._mapping`, `frontdoor/config.py:127`,
  `:166`, `:191`) while `frontdoor/request.py` passes none, so the field would
  be the grammar's first optional one and would also have to amend the ADR's
  own closure statement ("exactly twelve named fields and no optional ones");
  and exactly twelve test modules touch a Consumer Request, which is the
  figure the record uses.
* No document grew a parallel copy of the decision. The plan, the manifest
  card and the operator-guidance row each carry the decision in the form their
  own reader needs and link to `#design` as the single source; the record's own
  superseded `Possible shape` section is annotated in place rather than
  rewritten or deleted, which keeps the provenance a reader of AD-6 will look
  for.

=== 5. What I tried to break

* *Could a narrower ship have been both safe and beneficial?* No. Entering at
  `correct` or `focused_review` is the only safe set, and I recomputed that it
  saves nothing (3 and 2 Hops against the default's 2); a fresh Run also has
  no Findings for either phase to act on, and inter-Run Finding transfer does
  not exist (`SuccessorProvenance` carries no Finding state and the successor
  descriptor is `untrusted_context_only`). The candidate's alternative B is
  correctly priced as cost without benefit.
* *Could the record's motivating Run have been served by the field after
  all?* No. `RUN-6ebce1ac10df4e099e93848d6c292f8b` stopped
  `reconcile_required` with `semantic_stop: null` between a trusted-committed
  `implement` Hop and its `broad_review` Hop; `_predecessor_for_successor()`
  refuses it by name at `operator.py:1711-1712`, and re-expressing it as a
  fresh Run would discard the candidate and the Finding state that make the
  review meaningful. It is a same-Run continuation and O10's subject, as the
  candidate says.
* *Is the capability already reachable where the record says it is?* Yes, and
  this is the one place where I would have expected an over-claim and found
  none: `wfc prepare-successor` admits hand-authored inputs at pinned paths
  through `_admit_a1`, so a prepared successor can already carry any declared
  `initial_phase`; the gap is confined to `commission render` / `wfc plan` /
  `wfc request`.
* *Does the plan's slice table now lie?* No. The `o9` row still states the
  planned Hop budget and class, which is what every integrated slice's row
  (O1-O8) also does; the outcome lives in the slice section, which is this
  plan's established convention.

=== 6. Non-blocking observations

. *One cost of the retained substitute is not weighed.* The task named it
  explicitly -- the substitute is "one extra Worker Hop *and a Worker that can
  write*". The `Design` section answers the Hop and answers the mirror-image
  question for the reviewer (the review phase's scope is the artifact slot
  `A`), but it never counts the residual risk that a verification-only
  Commission's `H001` runs with `authorized_actions: [edit, commit]` over the
  whole `S` scope (`src/`, `tests/`, four documentation roots here). Counting
  it does not change the decision -- alternative A stays forbidden and B stays
  benefit-free, and it is at most a further mild argument for the deferred
  alternative C -- which is why this is an observation and not a Finding. It
  is the one line I would add at the next touch of the record, because an
  evaluation that keeps a substitute should price the substitute completely.
. *"The 77 rendered bundles under `.wfc/governance/`" is 76.* The directory
  holds 76 bundle directories, each with a `request.yaml`, plus the single
  file `repository-policy.md`; 77 is the entry count. The effort argument is
  unaffected.
. *For `robust@v1` the legacy durable-artifact path refuses a review entry one
  check earlier than the one cited.* The record attributes the refusal to
  `operator.py:575-582` (direct initial-phase re-entry). With a `broad_review`
  entry in `robust@v1`, `:560-564` fires first, because the still-required
  `focused_review` is a later phase legacy input cannot satisfy -- in fact that
  check means the legacy path cannot serve `robust@v1` at *any* entry. The
  record's conclusion ("the legacy path is entry-dependent and already refuses
  a review entry") is true and in fact stronger than stated; only the
  attribution is imprecise.
. *One shipped-skill sentence is strictly true only of the rendered path.*
  `agent_skill/wfc/references/stops-and-evidence.md:183` says a separately
  authorized successor "always enters at the implementation phase today",
  while the record's own `#design-successor` establishes that a
  `prepare-successor` run over hand-authored inputs can already carry any
  declared entry. The sentence is accurate for the Front Door path an operator
  or agent is told to use, it predates this slice, and no Front Door behaviour
  changed here, so the docs-sync clause imposes no edit; a qualifier ("through
  the Front Door") would remove the ambiguity whenever that file is next
  touched.
