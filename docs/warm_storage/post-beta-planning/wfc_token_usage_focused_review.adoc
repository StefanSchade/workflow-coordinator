[[token-usage-h004-blocking]]
=== Blocking Findings

B-1 -- usage parsing can still raise out of `execute()` and change an
invocation's fate:: The task's DO item 1 requires that "missing or malformed
JSON/events ... must yield unknown for the affected figure and never raise
into the Hop and never alter candidate acceptance, routing or any existing
outcome", and Acceptance repeats it: "usage parsing cannot affect any Hop
outcome". Both parsers catch only `JSONDecodeError`/`ValueError` around
`json.loads`, so a single stdout line of *valid* JSON nested beyond the
interpreter's recursion limit raises `RecursionError` instead.
+
Reproduced at the real boundary, not only in the parser: driving the actual
`CodexCliAdapter.execute()` with a fake `codex` that writes a perfectly valid
result envelope to `--output-last-message` and prints one 200000-deep nested
JSON array to stdout, `execute()` raised `RecursionError`, so the valid
candidate never reached the engine; the same adapter with a well-formed
`turn.completed` line returned `returncode=0`, the candidate and
`coverage=complete`. In `slice4.py::run_real_one_hop` an exception out of
`execute()` is caught by the broad `except Exception: return
recover_uncertain(None)`, which charges an `uncertain` Hop
(`invocation_status="acceptance_not_disproved"`) and forces
`RECONCILE_REQUIRED` -- i.e. parsing the usage figures, and nothing else,
turned an acceptable invocation into a charged, human-reconcile Hop.
+
The exposure is attributable to this slice: the pre-change
`codex_adapter.py` contains no `json.` use at all and never parsed stdout,
and in `claude_adapter.py` the pre-change `json.loads(stdout)` ran only on
the zero-exit path, whereas `_usage_from_wrapper_stdout` now runs
unconditionally, including after a non-zero exit or a timeout. Both parsers
raise `RecursionError` on that input (verified directly).
+
Feasible correction, no new mechanism and no new state: broaden the two
existing `except` clauses in `claude_adapter._usage_from_wrapper_stdout` and
`codex_adapter._usage_from_stdout` so that any failure of the usage parse
yields `NO_USAGE_REPORTED` (for example
`except (json.JSONDecodeError, ValueError, RecursionError)`, or `except
Exception` with the reason stated in the docstring), plus one test per
adapter asserting the record is `NO_USAGE_REPORTED` rather than an exception.
+
H002 reproduced the same fact and recorded it as non-blocking `O-4` on the
ground that "no provider plausibly emits such a line". I do not adopt that
downgrade: the criterion is unconditional, the agent-authored prose and
provider transport output are explicitly untrusted input in this repository's
own conventions, and the correction is a one-line widening of an `except`
that already exists. New material evidence in this pass: the violation is
reproduced at the `execute()` boundary and traced to the charged-`uncertain`
Hop outcome, not only to the parse function.

B-2 -- the Front-Door docs-sync check misses an in-scope owner it falsified,
and the table asserts the opposite:: DO item 6 names
`docs/backlog/_open.adoc` explicitly as an owner to check and to "record what
is now delivered and what remains"; Acceptance requires the check "performed
over all owners with a complete table and every inaccurate statement
corrected". The verification record's table row for that file reads
"Unchanged because none exists / Searched; no existing passage references
token usage."
+
That is factually wrong. `docs/backlog/_open.adoc:259` says "Token-consumption
evidence remains undesigned. October 21 called it MUST-HAVE; the reviews
recommend fast-follow with an honest nullable usage field." The first sentence
is exactly a token-usage statement and exactly the statement this change
falsifies -- capture, persistence, projection and reporting are now
implemented, with a design recorded in the verification record. The file is
inside the WorkItem scope (`.wfc/governance/wfc-token-usage-s1-001/
work-item.yaml:26`), so the correction needs no scope widening: record what is
delivered and what remains (the release-gate question stays open) without
inventing acceptance, and correct the table row to the truth.
+
Second instance in the same family, also in scope:
`docs/backlog/beta1_productization.adoc:75` still says "Token-usage
implementation effort and its release-gate status are open" eleven lines
below the bullet this candidate added at 60-66 stating that
