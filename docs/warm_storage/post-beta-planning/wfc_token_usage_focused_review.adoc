`F004` required that usage parsing never raise into the Hop and never alter

widened clause are both necessary.

=== Blocking Findings

B-1 -- usage parsing can still raise out of `execute()` and change an
invocation's fate:: The task's DO item 1 requires that "missing or malformed
JSON/events ... must yield unknown for the affected figure and never raise
into the Hop and never alter candidate acceptance, routing or any existing
outcome", and Acceptance repeats it: "usage parsing cannot affect any Hop
outcome". Both parsers catch only `JSONDecodeError`/`ValueError` around
`json.loads`, so a single stdout line of *valid* JSON nested beyond the
interpreter's recursion limit raises `RecursionError` instead.
+
Reproduced at the real boundary, not only in the parser: driving the actual
`CodexCliAdapter.execute()` with a fake `codex` that writes a perfectly valid
result envelope to `--output-last-message` and prints one 200000-deep nested
JSON array to stdout, `execute()` raised `RecursionError`, so the valid
candidate never reached the engine; the same adapter with a well-formed
`turn.completed` line returned `returncode=0`, the candidate and
`coverage=complete`. In `slice4.py::run_real_one_hop` an exception out of
`execute()` is caught by the broad `except Exception: return
recover_uncertain(None)`, which charges an `uncertain` Hop
(`invocation_status="acceptance_not_disproved"`) and forces
`RECONCILE_REQUIRED` -- i.e. parsing the usage figures, and nothing else,
turned an acceptable invocation into a charged, human-reconcile Hop.
+
The exposure is attributable to this slice: the pre-change
`codex_adapter.py` contains no `json.` use at all and never parsed stdout,
and in `claude_adapter.py` the pre-change `json.loads(stdout)` ran only on
the zero-exit path, whereas `_usage_from_wrapper_stdout` now runs
unconditionally, including after a non-zero exit or a timeout. Both parsers
raise `RecursionError` on that input (verified directly).
+
Feasible correction, no new mechanism and no new state: broaden the two
existing `except` clauses in `claude_adapter._usage_from_wrapper_stdout` and
`codex_adapter._usage_from_stdout` so that any failure of the usage parse
yields `NO_USAGE_REPORTED` (for example
`except (json.JSONDecodeError, ValueError, RecursionError)`, or `except
Exception` with the reason stated in the docstring), plus one test per
