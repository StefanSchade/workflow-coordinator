== The 17 findings, by class, and the fix

F401 (2), unused imports::
`journal.py:36` (`typing.Iterator`) and `fake_engine.py:19` (`json`). Confirmed
unused by `grep -n` for `Iterator` / `json` in each file before removing: each
name appeared only on its own `import` line, never elsewhere (no `__all__`,
no string reference). Fixed by deleting the unused name from the import
statement. No behavior change: nothing read these names.

F841 (13), unused local bindings in two test files::
`test_lifecycle_controller.py:388-389` and 11 sites across
`test_lifecycle_crash_matrix.py` (203, 215-216, 237-238, 272-273, 311-312,
328-329). Each assigns the result of `L._do_prelaunch(...)` or
`L._do_probe(...)` to a local (`prelaunch` / `probe`) that no later line in
the same test reads; both functions have side effects relied on by the
test (they write journal records and advance on-disk lifecycle state that
later calls in the same test, or `resume_lifecycle`, observe). Fixed by
keeping every call exactly where it was, in the same order, only changing
the assignment to a bare expression statement (`L._do_prelaunch(...)` instead
of `prelaunch = L._do_prelaunch(...)`). No fixture, assertion or control flow
was touched; the call sequence and its side effects are identical.

F401 + F811 (2), the pytest fixture re-export idiom::
`test_operator_admit_parsed.py:16` imports `repository` from
`tests.unit.test_operator` only so pytest can resolve it as a fixture when a
local fixture's parameter is also named `repository` (line 22); ruff sees an
unused import (F401) and a parameter that "redefines" it (F811). Deleting the
import or renaming the parameter would break fixture resolution (pytest
matches a fixture to a parameter by name), so this was *not* autofixed and the
import was *not* removed. Instead, two narrowly scoped, commented `# noqa`
suppressions were added, one per violation, each on the line ruff actually
reports it on: `# noqa: F401 -- pytest fixture re-exported by import` on the
import line (16), and `# noqa: F811 -- pytest fixture param shadows the
re-exported import` on the fixture definition line (22). +
Correction against the task text: the task's suggested example combined both
codes (`# noqa: F401, F811`) on the single import line. This Hop verified
empirically that `ruff check` still reports F811 on line 22 when the
suppression sits only on line 16 (`noqa` is a strictly per-line directive in
ruff, as in flake8); a single combined suppression on the import line does
not clear the F811. Two per-line suppressions, not a configuration-level or
file-level ignore, were required to reach zero findings.

configuration rather than assumed; one claim in the task text is corrected.
