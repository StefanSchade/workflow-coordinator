== What this document is

Slice SK consolidates the shipped WFC Operator Skill
(`src/workflow_coordinator/agent_skill/wfc/SKILL.md` and its three
`references/*.md`). The problem it addresses is not the word count: it is
that the four files mixed (1) general operator rules, (2) WFC Runtime
contracts, (3) WFC-self-development experience and (4) historical workarounds
that slices O1-O10 have since automated. The structure -- a lean entry file
plus references followed on demand -- was sound and stays.

Base of the measurement and of every "before" citation: `main` at `1aa5beb`,
the state this Commission started from.

=== Why the shipped total did not fall, stated plainly

Three topics the order requires did not exist in the skill before and account
for more than the whole delta: the Level-0/Level-1 separation and the
corrected multi-Run statement (~200 words, `SKILL.md`), the operator-notes
convention (~90 words in `SKILL.md`, ~180 in `setup.md`), and the
versioned-reference strategy (~150 words across `SKILL.md` and `setup.md`).
Removed against that: ~250 words of WFC-specific text, ~120 words of
duplicated execution-binding precedence, ~110 words of duplicated recovery and
`wfc report` prose, ~85 words of hand-authoring guidance O5 made obsolete,
and five of the six duplicated manual links. The result is a skill that says
more with slightly more text, and says nothing about anybody's stack.

No reduction quota was set and none was invented. What the slice optimised is
what an agent actually loads, below.

[[inventory-c]]
== Inventory C: versioned references, and the strategy

Before: eleven occurrences of `v0.1.0b1`, ten of them inside six distinct
tag-pinned manual links, five of which were duplicated between `SKILL.md`
and the reference that already linked the same page. After: six tag-pinned
links (one in `SKILL.md`, one in `setup.md`, one in `commission.md`, three in
`stops-and-evidence.md`), four explicit "as released with v0.1.0b1" labels,
and one install pin.

The strategy, stated in `SKILL.md` ("Where exact facts come from") and in
full in `setup.md` ("Install and version discovery"):

. The **installed Runtime** is authoritative for what will happen: each
  subcommand's own `--help`, and `plan`/`status`/`report` output.
. **This skill** ships with that Runtime, so it describes that same version.
. The **Operator Manual at the release tag** is supplementary and labelled
  with the version it describes. A development tree runs ahead of it, so a
  function the installed CLI has and a pinned page does not mention is
  normal -- and such a page is never cited as that function's documentation.

This is compatible with the release step by construction: the pins remain
`/blob/v<VERSION>/...`, every file carrying one is enumerated in the
version-bearing surface that
link:../../backlog/FTR-WFC-RELEASE-PREPARATION.adoc[the scripted
release-preparation slice] owns (`scripts/wfc_release_prepare.py`,
`surface()`), and the new test
`test_every_tag_pinned_skill_file_is_covered_by_the_release_bump_surface`
fails if a future file carries a pin the bump would miss. `blob/main` links
were rejected: they would silently track an unreleased tree and defeat the
exact-match rewrite.

[[pinned]]
== Pinned expectations changed, and tests added

Two pinned expectations in `tests/unit/test_agent_skill_content.py` were
changed deliberately, both in `test_skill_md_body_order_and_line_limits`:

* the bound on where the fourth heading may begin rose from line 80 to line
  95, because section 1 now carries the Level-0/Level-1 separation (about
  twelve lines of load-bearing text it did not have). Compressing the
  authority rules to stay under 80 would have been the wrong trade;
* a *new, tighter* assertion was added beside it: `## Authorization` must
  begin within the first 45 lines (it begins at 39). That is the guard's real
  intent -- the authority rules are reached before anything operational --
  expressed directly rather than through a total-length proxy.

The heading list, the 300-line cap on `SKILL.md`, the 200-line cap on each
reference, the classification/`EXIT_CODES` cross-check, the CLI drift guard,
the tag-pin check and every authority-phrase assertion are unchanged. No test
was weakened, skipped or deleted.

Added (non-fragile: they pin structure, location and contract, not wording):

* `test_generic_skill_names_no_consumer_stack_or_repository_layout` -- the
  stack-agnosticism guard, parametrized over the four files and a list of
  tokens that can only ever describe one consumer's stack;
* `test_every_authority_rule_is_still_stated_somewhere_in_the_skill` -- the
  mapping table above, made durable: each rule as a small set of meaning-
  bearing substrings, matched against the whole skill so a rule may move
  between files but cannot vanish;
* `test_operator_notes_convention_is_documented_with_its_boundaries`;
* `test_skill_states_level_0_and_level_1_and_sequential_multi_run_operation`,
  which also asserts the retired "chaining several Commissions" claim is
  gone;
* `test_loop_section_says_which_reference_and_the_notes_check_belong_where`
  -- progressive disclosure: the entry file must say at which step to open
  each reference;
* `test_every_tag_pinned_skill_file_is_covered_by_the_release_bump_surface`;
* `tests/architecture/test_operator_notes_convention.py` -- the convention
  across documents: this repository's notes exist and carry the facts that
  left the generic skill, they state their own standing, they contain no
  absolute home path, their relative links resolve, and the Operator Manual's
  consumer chapter documents the convention with both boundaries.
