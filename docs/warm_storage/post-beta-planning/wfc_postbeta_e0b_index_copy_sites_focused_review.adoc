==== 4.2 What it still leaves, measured

`except Exception` does not cover the exception classes the pre-fix `finally`
blocks covered. Injecting `KeyboardInterrupt` into the copy instead, same probe:

[cols="3,1,1"]
|===
|Site |pre-E0b (`b47c39b^`) |committed (`2f54da2`)

|`salvage_inventory`  |0 |*1* (`wfc-salvage-index-…`)
|`salvage_omissions`  |0 |*1* (`wfc-salvage-omissions-index-…`)
|`observe_repository` |0 |*1* (`wfc-observe-index-…`)
|`preserve_candidate` |1 |1
|===

This is the same reproduced behaviour change `F002` names, not a new
requirement: before E0b each site created the temp file and copied into it
*inside* its `try: … finally: os.unlink(…)`, so *any* exception — including
`KeyboardInterrupt` and `SystemExit` — was cleaned up; after the correction only
`Exception` is. `Ctrl-C` during a Hop is an ordinary event and
`observe_repository` runs at every Hop boundary, so the window, while short, is
one that real operation reaches; the consequence is one leaked index-sized file
per interrupt in the process temp directory.

The feasible correction is the repository's own idiom for precisely this
situation, which already exists twice and would make the deviation disappear
rather than add mechanism:

[source,python]
----
    except BaseException:
        try:
            os.unlink(copied_index)
        except FileNotFoundError:
            pass
        raise
----

`persistence.py:109-114` (atomic write) and `operator.py:1368-1372` (descriptor
publication) are byte-equivalent; `ruff` selects only `F` here
(`pyproject.toml:59-63`), so no lint rule argues for the narrower clause, and
the module's five existing `finally` blocks (`git_facts.py:125`, `:269`,
`:569`, `:963`, `:1056`) all guard the unlink with `except FileNotFoundError`.
The blocking half is only the exception class; the inner guard is the
non-blocking half (<<e0b-f-o1,O1>>) and comes free with the idiom.

=== 6. Non-blocking observations

[[e0b-f-o1]]
O1 — the bare `os.unlink` in the new handler can replace the diagnostic it was added to preserve:: If
the unlink itself fails, its exception propagates instead of the copy's. The
realistic path is narrow but not imaginary and it coincides with the one
recorded production failure: `/tmp` is full, an operator or a `tmpfiles` sweep
removes the file, the copy raises `ENOSPC`, and the caller sees `FileNotFoundError`
rather than the `ENOSPC` that
`docs/operator_manual/ch07_diagnostics/02_failure_modes.adoc:352` tells the
operator to look for. The module's own five `finally` blocks already guard this
with `except FileNotFoundError: pass`; adopting the idiom quoted in section 4.2
settles it in the same edit. Non-blocking on its own — it degrades a diagnostic,
it does not produce a wrong result.

[[e0b-f-o2]]
O2 — no test guards the restored cleanup:: The cleanup is now required behaviour
(it is what `F002` is about) and it regressed once inside this very package, yet
nothing fails if it is dropped again. A guard would be fully deterministic —
inject an exception into the copy, assert the temp directory is empty, no timing
involved — and parameterizing it over `OSError` and `KeyboardInterrupt` would
pin section 4.2 as well. `ch03`'s "a behavior change needs a test that fails
without it" points this way and the cost is about a dozen lines; I record it
rather than require it, because the task's test obligation was written about the
mtime invariant, not about this error path.

[[e0b-f-o3]]
O3 — the helper docstring explains the mtime but not the unlink:: Fifteen lines
say why `copy2` and not `copyfile`; the three lines that keep a failed copy from
leaking say nothing about themselves, and the `finally` that used to do the job
is now at the caller. One short sentence in the existing docstring would keep
the next reader from simplifying the handler away. Editorial only.

[[e0b-f-o4]]
O4 — line numbers in the older records have drifted:: The helper moved from
`:899` to `:881` when the three sites were routed through it, so the citations
in the E0 record and in the P3 update records now point one screen off. Those
are frozen passes and provenance, correct as of their own base HEAD; nothing to
correct, worth knowing when following a reference.

[[e0b-f-o5]]
O5 — the broad pass's measurements reproduce, at this host's rate:: My natural
pre-fix rates (1/100 for `preflight_hop`, 0/100 for the other two) sit at the
low end of the broad pass's 1–3/300 and well under O1's original 8/300, for the
reason the model predicts: the window is the index-write-to-copy gap over one
second, and the exact-mtime deltas measured here are 4–8 ms. The rate is
host-dependent; the exact-mtime guards are not, which is why they carry the
regression signal and the behaviour tests merely corroborate it.
