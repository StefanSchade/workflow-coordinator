=== 12. New blocking Finding — a refusal after the mutation point leaves the Run unresumable

*The defect.* `_attempt_mechanical_recovery` performs its mutations —
`journal.append("mechanical_recovery_intent")`, `write_run_snapshot`,
the `checkpoint.json` write and `journal.append("mechanical_recovery_
resumed")` (`frontdoor/lifecycle.py:906`–`919`) — *before* its last two
failure points: the ownership-lock acquisition (`lifecycle.py:921`–`923`)
and the continuation launch (`lifecycle.py:924`–`930`). Both of those
report `refused_not_recoverable`, and both leave the Run rewritten to
`ready` with `stop_reason` and `anomalies` cleared. Nothing can then
recover it.

*Reproduced, probe A — the continuation engine cannot be spawned.* This is
the ordinary case of the `wfc` console script being absent, renamed or off
`PATH` between the stopped Run and the operator's `wfc resume`; the product
treats "no engine" as a first-class expected condition elsewhere
(`launch_failed_no_engine` with its own retry budget), and the recovery
path deliberately excludes itself from that bookkeeping
(`lifecycle.py:824`–`827`). With `_ENGINE_COMMAND` pointed at a
non-existent file:

[source,text]
----
raised: recovery continuation engine failed to launch: [Errno 2] No such
        file or directory: '.../definitely-not-an-engine'
        classification='refused_not_recoverable'

run.status       = 'ready'
run.stop_reason  = None
run.anomalies    = ()
reconcile_reason = 'mechanical_recoverable'
journal          = ..., 'mechanical_recovery_intent',
                   'mechanical_recovery_resumed',
                   'mechanical_recovery_launch_intent',
                   'mechanical_recovery_launch_failed'

second `wfc resume`, with a working engine restored:
  classification = 'awaiting_human'
  message        = 'lifecycle already classified (no-op)'
`wfc status`     = 'awaiting_human'   (while run.json says 'ready')
----
