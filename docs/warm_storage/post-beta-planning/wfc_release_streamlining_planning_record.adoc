=== Extended: the real version-bearing surface

37 line sites in *thirteen* distinct files must change at a version bump
(1 + 1 + 1 + 12 + 6 + 6 + 1 + 4 + 5), against the four version-bearing files
the basis names. Full enumeration, with what enforces each, is in
link:../../backlog/FTR-WFC-RELEASE-PREPARATION.adoc#problem[the R1 record].
Two gaps carry the economic case for W2 -- the first new here, the second
named by the basis itself:

. *`pyproject.toml` and `implementation_identity.VERSION` can disagree while
  the whole required suite stays green.* *[I]* No test imports both: the only
  consumers of `implementation_identity.VERSION` are
  `src/workflow_coordinator/frontdoor/skill.py`,
  `tests/architecture/test_package_boundaries.py`,
  `tests/unit/test_agent_skill_content.py` and
  `tests/unit/test_frontdoor_skill.py`, and no test module reads
  `pyproject.toml` with `tomllib` except `test_wfc_test_inputs.py` (for an
  unrelated purpose). The equality is asserted only in CI, in
  `release.yml:122` with `:139-140` and again at `:230` with `:246`. A
  half-done bump is therefore invisible locally and surfaces as a red hosted
  job.
. *`README.md` can keep links to the previous tag and `make release-check`
  passes.* *[I]* `check_readme_links` (`wfc_release_check.py:126-137`) rejects
  only targets that do not start with `http://`, `https://`, `#` or
  `mailto:`. No check compares the `blob/v<x>/` segment with the released
  version. The Agent Skill files have exactly that check
  (`test_agent_skill_content.py:237`); `README.md`, with ten such URLs, does
  not.

Both gaps are closed by W2 as adopted. Provenance, corrected after the renewed
broad review: the first is new here -- a `pyproject`/`VERSION` divergence
invisible to the required suite -- while the second is the basis's own
observation (`comparison:251-252`, "The README check only rejects
non-absolute links. It does not assert that the pinned `blob/<tag>/` links
name the tag being released", repeated inside the W2 limitation at `:737`).
What this record adds to the second is the asymmetry with the Agent Skill
guard at `test_agent_skill_content.py:237`, which already makes exactly that
assertion for the skill files.

[[design-decisions]]
== Design decisions of this plan, with rejected alternatives

D-A -- Four slices, not ten:: W1-W10 group by *where the recurring cost
sits*: the preparation commit (W2), the release chapter (W1 docs, W4, W8), the
pipeline's own robustness (W1 workflow, W4, W5, and W7 only as a conditional
one-line edit) and the placement of the consumer smoke (W3, W10). _Rejected:_ one slice per recommendation -- six of
the ten are one-to-three-line changes and would spend a Run each on
commissioning overhead. _Also rejected:_ one single release-streamlining
slice -- it would merge a documentation relocation, a new writing tool and a
change to the publication chain into one Run and one review, which is exactly
the merged-risk the commissioning brief warns against.

D-B -- R2 writes chapter 4 first, and every later slice retires the "planned"
wording its own work makes real:: R2 reduces the chapter and names R1's and
R3's work *as planned*; R1 then owns three line groups (the runbook's prepare
step and the two enumerations of what `release-check` asserts) and R3 owns
four statements (the recovery exception, the idempotent `release` job, the
attached `SHA256SUMS.txt` and the summary block). _Precedent, not invention:_
this is exactly how E1 specified E2 and E3 ("planned tooling is named as
planned, not as existing") and how E2, the implementing slice, closed it
("chapter 4 updated") -- `_open.adoc`'s E1 and E2 cards.
_Rejected:_ keeping chapter 4 out of R1 and R3 altogether, which an earlier
draft of this plan did to buy a second parallel lane. It left the chapter
stating five existing things as planned after the plan's own order had run --
including a prepare command the autonomy list tells the operator to use -- and
pinned that state with acceptance criteria ("no other line of the chapter
differs", "`git diff` touches only the files in scope") that forbade repair.
The repository's rule is that the owning documentation is maintained when
behaviour changes (`ch03_engineering_conventions.adoc:35-36`), so the lane was
given up instead: the file is the unit of conflict, not the section, and the
schedule gain for a single maintainer running one Commission at a time is
near-zero.
_Also rejected:_ a separate chapter-4 upkeep step after each slice, or an
operator-performed flip. Both move documentation truth out of the slice that
changes the behaviour, which is what the rule exists to prevent, and the
second would put a developer-guide chapter into Level-1 autonomy, which the
plan's autonomy list deliberately limits to the controlling records and
`_open.adoc`.

D-C -- R2 first:: It is the only slice that corrects a defect with an
operational consequence and no behaviour change at all, and it writes the
specification the other two implement. _Rejected:_ R1 first -- the plan's own
economics favour it, but it would then have to write the chapter sections R2
is reducing and relocating in the same place, which is the merged risk the
slicing avoids; after R2, R1 touches only the three line groups its own tool
makes true.

D-D -- R4 stays conditional:: Implementing either variant before D1 would
either reverse a recorded decision without authority or foreclose the
maintainer's choice. _Rejected:_ writing only Variant B as "the safe one" --
it pre-decides D1 by making A more expensive to choose later.

D-E -- Two economic rejections are stated as rejections:: W6 and W9 are the
two recommendations whose own recurring cost plausibly exceeds the cost they
remove. Saying so, with the arithmetic, is more useful than adopting them and
quietly never doing them. _Rejected:_ "defer with no reason", which is how a
backlog accumulates machinery.

D-F -- The scope-ceiling problem is named, not worked around:: R3 and R4 touch
`.github/workflows/release.yml`, outside `.wfc/config.yaml`'s
`work_item_scope_ceiling` (`src`, `tests`, `scripts`, `docs`, `README.md`,
`pyproject.toml`, `Makefile`, `examples/consumer-demo`). _Rejected:_ moving
the logic into a script under `scripts/` to stay inside the ceiling -- it
would put release-pipeline control flow in a second place to avoid a
configuration entry the maintainer has granted before and removed again
(`_open.adoc`'s E3 card).

D-G -- R1 is the writing tool *and* the two guards, not the guards alone::
The two guards (`pyproject` versus `VERSION`, README pins) close both
*invisible* drift paths on their own, without adding the repository's first
release tool that writes to the tree; they are the cheaper half of R1.
_Rejected as the whole of R1:_ they leave the 37 hand edits across thirteen
files in place, which is W2's actual recurring cost and R1's stated purpose. A
guard turns a forgotten edit from a silent defect into a red test, which is
better, but the edits are still made by hand every release. Worth recording
for the opposite direction: if R1 ever has to be cut down, the guards are the
part to keep.
