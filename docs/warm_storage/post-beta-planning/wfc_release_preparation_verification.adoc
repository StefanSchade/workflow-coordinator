== Guard proof: before/after, on a copied tree

Both guards in `tests/unit/test_release_version_surface.py` pass against
this checkout today (`pyproject.toml`'s version equals
`implementation_identity.VERSION`; every `README.md` `blob/v<x>/` URL names
that version) and were each demonstrated to fail by copying the single
relevant file into a `tmp_path` and reverting one site:

* Guard 1 (`check_version_consistency`): copying `pyproject.toml` and
  `implementation_identity.py`, then rewriting the copy's `VERSION = "..."`
  literal to `"9.9.9"`, produces
  `"pyproject.toml version '0.1.0b1' does not match
  implementation_identity.VERSION '9.9.9'"`.
* Guard 2 (`check_readme_blob_versions`): copying `README.md`, then
  rewriting one `/blob/v0.1.0b1/` occurrence to `/blob/v9.9.9/`, produces
  `"README.md has blob link(s) pinned to version(s) other than '0.1.0b1':
  ['9.9.9']"`.

Both guard tests, and the two non-negative assertions against this
checkout's real state, were executed (see <<checks>>); neither guard was
merely asserted without running it.

Before this slice, no such guard existed at all (the test file is new), so
the gap the FTR names -- `pyproject.toml`/`VERSION` disagreement and a
stale `README.md` tag surviving a hand-edited bump -- was visible only to a
hosted CI run or an Operator's own eyes; the required suite could not have
caught either. After this slice, both are mechanical and local.
