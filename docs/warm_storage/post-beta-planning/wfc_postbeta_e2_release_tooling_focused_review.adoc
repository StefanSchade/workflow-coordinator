== 2 F002 — resolved

F002 held that `audit_sdist` derived each member's allow-list key by stripping
the first path component *positionally*, without establishing what that
component should be, and that `_sdist_entry_allowed` then accepted an empty key
unconditionally — so a member with no slash was read as "the archive root" and
never examined, and a member under a second top-level component was judged as
if that component were the package root.

The remedy applied is the one the Finding named, and it removes a branch rather
than adding mechanism. `_sdist_root` (`scripts/wfc_dist_audit.py:87-89`) derives
the expected root once from the archive filename (PEP 625:
`<name>-<version>.tar.gz` without the suffix); `audit_sdist:92-105` skips the
root member itself, reports any member that is neither the root nor under
`<root>/` as a violation, and only then applies the unchanged
`_sdist_entry_allowed` to the remainder. The unconditional accept for an empty
key is now reachable only for a literal `<root>/` member and is dead for
anything else. One rule, one implementation, still shared by the CLI and the
architecture test.

archive containing a conforming `workflow_coordinator-0.1.0b1/` tree plus the
named addition, audited through `audit()`:

  — the exact case C2's rationale sentence names.

The fix's load-bearing assumption is that the sdist's filename base and its
root directory agree. They do by construction: `setuptools` derives both the

normalisation change, and the operator-measured real artifact is
`workflow_coordinator-0.1.0b1.tar.gz` (normalised, from the hyphenated project
name `workflow-coordinator`, setuptools 84.2.1 —
`build/wfc/postbeta-inputs/ARTIFACT_FACTS.txt`). The assumption is also
guarded: `tests/architecture/test_offline_distribution.py:42-43` asserts
`audit(archive) == []` on the sdist it really builds, so a divergence fails the
suite loudly instead of silently. `make dist-audit` globs the freshly built
`dist/*.tar.gz`, so it sees the same name the backend wrote.

== 4 Non-blocking observations

Observation 1 of the H004 revision (the sdist root) is now the resolved F002
and is dropped. The remainder stand, with two restated against the corrected
code. None of them blocks, and none should be closed by adding mechanism.

. *A directory-typed entry inside the package tree is still accepted
  regardless of name.* `_wheel_entry_allowed` accepts a payload-carrying zip
  entry named `workflow_coordinator/docs/` or `workflow_coordinator/leak.ods/`
  because a directory under the package tree is allowed by name alone
  (measured: 0 violations each, while `docs/` at top level, an in-package
  `.pyc` and a `workflow_coordinator.data/scripts/x` entry each yield 1). This
  does not reach C2's stated rationale — a new *top-level* directory can no
  longer leak in silently — the entry stays inside the row's own package tree,
  the `*.ods` spelling only matches with a trailing slash, and no builder emits
  directory entries into a wheel at all, so no build path reaches it. Closing
  it would mean requiring a directory entry to name an existing allowed
  subtree or inspecting entry payload sizes: more mechanism than the criterion
  asks for, for a hand-crafted-archive-only case. Recorded for the maintainer
  as an optional uniformity tightening, not required here.
. *The sdist root is coupled to the filename.* Auditing a conforming sdist that
  has been *renamed* (measured: `renamed-copy.tar.gz`, and a hyphenated
  pre-PEP-625 filename over a normalised root) reports every member — 9
  violations — rather than one "root does not match the archive name" line. The
  direction is fail-closed and the release paths always use the name the
  backend wrote, so this is a message-quality point only; the
  filename-independent variant was measured in H005 and does not close the
  foreign-root case.
. *The README check enforces absoluteness, not the tag pin*, and flags *any*
  repository-relative markdown link target, not only documentation ones
  (stricter than C5's wording, and it cannot see reference-style links, of
  which `README.md` has none); *in branch mode without `TAG` the
  tag-equals-version comparison is a tautology*; *the notes check is coupled to
  the `== <version> -- <status>` heading shape* — all unchanged from H002 and
  all following the chapter's own wording.
. *Duplicate line when `origin/main` is unknown.* In branch mode with no
  `origin/main`, `check_local_main_sync` and
  `check_head_reachable_from_origin_main` both return the identical
  "origin/main is not known locally" sentence, so the operator sees it twice.
  Two checks failing for one cause; cosmetic.
. *`*.ods` under `src/` would be accepted by the sdist row.* The chapter lists
  `src/**` as allowed and `any *.ods` as forbidden in both artifacts; for a
  hypothetical `src/x.ods` those clauses disagree, and the implementation
  follows the allow-list, which is what DO (2) prescribes. No `.ods` exists
  under `src/`, and the repository's `project_memory.ods` sits at the root
  where both rules refuse it. A question for the chapter's owner, not a defect
  to fix here.
. *Two near-dead branches remain in the audit.* `_sdist_root` falls back to the
  whole filename when it does not end in `.tar.gz` (unreachable through
  `audit()`, which dispatches on that suffix), and `_sdist_entry_allowed`'s
  empty-key accept is now reachable only for a literal `<root>/` member. Both
  are one line each and harmless; folding them in would be churn in code the
  gate has just measured.
