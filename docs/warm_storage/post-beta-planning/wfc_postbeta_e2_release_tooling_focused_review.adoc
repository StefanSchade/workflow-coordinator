== 2 F001 — resolved

F001 held that both allow-list predicates exempted every slash-terminated
entry name before any rule ran, which produced a false pass on a
payload-carrying forbidden wheel directory entry and — because `tarfile` does
not preserve the trailing slash — a false failure on a real-shaped sdist whose
legitimate `src` directory member fell through to the file rules.

The remedy applied is the one the Finding named: the blanket exemption is
gone. `_wheel_entry_allowed` (`scripts/wfc_dist_audit.py:44-58`) normalises the
trailing slash and then applies the C2 rules to every entry, allowing a
directory name only where it names an allowed tree (`workflow_coordinator` or
a `*.dist-info`); `_sdist_entry_allowed` (`:61-68`) takes directory-ness from
`tarfile`'s own `member.isdir()` (`:92`) instead of inferring it from a slash,
and allows a directory only at the archive root, `src` or under `src/`. That
is one branch fewer than before, not extra mechanism, and it stays one rule in
one implementation shared by the CLI and the architecture test.

Verified by execution at the candidate HEAD:

* *Direction (a), false pass, closed.* A wheel carrying a zip entry named
  exactly `docs/` with a payload now yields
  `unlisted entry 'docs/' is not in the C2 allow-list (forbidden by name: ...)`.
  I repeated the probe for `tests/`, `.wfc/`, `governance/`,
  `project_memory/`, `scripts/` and `build/`: every one is rejected, one
  violation each. A legitimate `workflow_coordinator/` directory entry still
  audits clean.
* *Direction (b), false failure, closed.* An sdist staged as an
  allow-list-only tree and archived through the path `setuptools` uses
  (`shutil.make_archive(..., 'gztar')`, i.e. recursive `tarfile.add` of the
  `<name>-<version>/` base directory) produces 15 members of which 5 are real
  directory members, and `audit()` returns `[]`. The bare `src` member that
  previously produced `unlisted entry 'workflow_coordinator-0.1.0b1/src'` is
  now correctly allowed.
* *The fixture no longer hides either case.* `_write_sdist`
  (`tests/unit/test_release_tooling.py:224-239`) writes a `DIRTYPE` root
  member plus the requested directories, and the two added cases
  (`test_dist_audit_rejects_a_forbidden_wheel_directory_entry:276-284`,
  `test_dist_audit_rejects_a_forbidden_sdist_directory_entry:304-315`) fail
  against the pre-correction predicates and pass here, so the regression is
  detectable.

== 4 Non-blocking observations

The five non-blocking observations of the broad review (section 4 there)
stand; the one that touches the corrected code is restated with its current
state, and three observations are new. None of them blocks.

. *The sdist mapping still strips the first path component without asserting a
  root prefix* (broad-review observation 3). `audit_sdist:91` maps a member
  without a `/` to the empty string, which `_sdist_entry_allowed:62-63` allows
  as the archive root. In an archive lacking the PEP 625
  `<name>-<version>/` root a top-level file or directory would therefore be
  accepted. Not reachable from a real build; the one-line root-prefix
  assertion remains available and was explicitly non-blocking in H002.
. *A directory-typed entry inside the package tree is still accepted
  regardless of name* (new, narrower residual of the same family).
  `_wheel_entry_allowed` accepts `workflow_coordinator/evil.txt/` and
  `workflow_coordinator/sub/` because a directory under the package tree is
  allowed by name alone, so a hand-crafted wheel could carry payload bytes in
  such an entry. This does not reach C2's stated rationale — a new *top-level*
  directory can no longer leak in silently, which is what F001 reproduced —
  the entry stays inside the package tree the row allows, and no build
  produces such an entry. Recorded, not required; closing it would mean
  requiring a directory entry to name an existing allowed subtree, which is
  more mechanism than the criterion asks for.
. *The README check enforces absoluteness, not the tag pin*; *in branch mode
  without `TAG` the tag-equals-version comparison is a tautology*; *the notes
  check is coupled to the `== <version> -- <status>` heading shape* — all three
  unchanged from H002, all three following the chapter's own wording.
. *Duplicate line when `origin/main` is unknown.* In branch mode with no
  `origin/main`, `check_local_main_sync` and
  `check_head_reachable_from_origin_main` both return the identical
  "origin/main is not known locally" sentence, so the operator sees it twice.
  Two checks failing for one cause; cosmetic.
. *`*.ods` under `src/` would be accepted by the sdist row.* The chapter lists
  `src/**` as allowed and `any *.ods` as forbidden in both artifacts; for a
  hypothetical `src/x.ods` those two clauses disagree, and the implementation
  follows the allow-list, which is what DO (2) prescribes ("fails on anything
  unlisted", the forbidden set being named in the message). No `.ods` exists
  under `src/`, and the repository's `project_memory.ods` sits at the root
  where both rules refuse it. This is a question for the chapter's owner, not
  a defect to fix here, and no additional mechanism should be added for it.
