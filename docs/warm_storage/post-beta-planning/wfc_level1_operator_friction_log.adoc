= WFC Level-1 operator friction log

Maturity::  working log
Authority:: informative; non-authorizing
Updated::   2026-11-26
Owns::      Dated observations of friction a Level-1 operator met while using the WFC Front Door and the Agent Skill, each with evidence, who is affected and an improvement candidate. It decides nothing and grants no authority.

The log collects friction so that it can improve the Agent Skill, the Operator
Manual and the product. An entry that becomes concrete work becomes an FTR or
a BUG in the link:../../backlog/_open.adoc[backlog] and keeps only a pointer
here. Entries describe what happened and what it cost; they do not assign
fault. Add new entries at the end of the section of their date.

== 2026-11-26 -- Execution Boundary rework (AB) and the lint residue

[cols="1,3,2,2,2",options="header"]
|===
|# |Observation |Evidence |Affects |Improvement candidate

|18
|The Coordinator's deterministic gate is exactly one `task-check` command per Commission, chosen by the Level-1 operator at authoring time. For this repository the operator wrote `python -m pytest -q`, although the repository's own gate is `make check` (`lint`, `format-check`, `test`; `ruff` is configured in `pyproject.toml`, `select = ["F"]`). The Run therefore had a deterministic gate for behaviour but none for lint. The Worker's retirement of the started-marker machinery removed a test and left its import (`EXTERNAL_SCRATCH_DESTINATION`, `tests/unit/test_execution_launcher.py:6`, ruff F401) behind. Ten Hops, six task-checks and two Opus Broad Reviews did not see it, because no pytest node runs `ruff`; the final Broad Review (H010) found it by running `ruff check .` itself and raised it as a blocking Finding (F005, review section B5). `ruff check .` was clean on `main` before the Run, so a lint-inclusive baseline probe would have passed and the error would have surfaced at the first Hop's task-check at the cost of one Worker correction and no reviewer. The repository's `format-check` target covers only five files (`ruff format --check .` would reformat 119 of 332 files), so a whole-tree format gate is not available and was not used.
|Run `RUN-f5b02c7990aa4a4b8343ec74e0016c77` (Commission `wfc-exec-boundary-rework-ab-001`): H010 Broad Review, `docs/warm_storage/post-beta-planning/wfc_execution_boundary_rework_ab_broad_review.adoc` section B5; `ruff` 0.17.5 reproduced exactly one error on the candidate and none on `main`; the name occurred twice in the file at the Commission baseline (import plus one use in a retired test).
|Operator (evidence choice), Agent Skill (commission authoring), Product (single-command evidence)
|(a) Operator rule: the evidence command must cover the repository's own deterministic gates (at least lint and tests), not only the tests; when the repository defines a `check` target, use it or a wrapper script that runs lint and tests in order, provided the baseline passes on the clean tree. (b) Product candidate raised by the maintainer: allow a *list* of evidence commands run in order (cheap ones first, fail-fast) instead of one command, so lint, format and tests can be separate named gates; the baseline probe then runs the same list. (c) Skill candidate raised by the maintainer: name this case in `commission.md` as the example of what a deterministic gate must prevent, with the principle that agents (Worker corrections, Focused and Broad Reviews) must not be spent on what a cheap deterministic check decides. Not verified in this session: whether `make check` as a single evidence command passes its baseline in the Coordinator environment (the `PYTHON` variable, the `format-check` file list).

|19
|Cost shape of a correction cycle under `robust@v1`: one Worker correction, one Focused Review and one Broad Review are three Hops, so a Hop upper limit of 10 buys one implementation Hop, one review round and about two correction cycles. Here the cycles were H003/H004/H005/H006 (B1 deterministic test failure, then F003 stale statements), H007/H008/H009 (F004, docs-sync in two places no earlier pass had examined) and H010 (F005, lint). Every later finding was smaller than the one before (a failing test setup, then stale documentation, then one import), so the loop converged, but the budget ran out one Broad Review before acceptance. The `awaiting_human_budget` stop text says "a human must authorize additional hop budget, then run `wfc resume`"; no in-place way to raise the budget was found, so the operator-side options are a successor Commission or leaving the stop. A successor Commission with its own review chain for a one-name import is out of proportion: a Worker Hop plus a Focused and a Broad Review (three agent Hops, about an hour with the 6-minute task-check each) for a mechanical defect.
|Same Run; the run log (`HOP USED: 10`, `stop reason autonomous_hop_budget_exhausted`, `findings open blocking: F005`).
|Operator planning, Product (budget raise), Manual (stop dispositions)
|Budget a retire-heavy rework (removing a mechanism and its tests, plus docs-sync) above the usual double of the expected Hop count, or avoid the case with the gate of #18. Product candidate: let a purely mechanical residue Finding (deterministic check failing, no behaviour change) be closed by a Worker-only correction without the Focused and Broad Review chain, or allow the maintainer to raise the budget of a stopped Run in place. Operator disposition used here: the maintainer approved, as a deliberate and recorded exception to "never edit an in-scope file once the task is routed through WFC", that the operator cherry-picks the reviewed candidate and removes the single import in its own chore commit (lint clean, the test file run, the full suite run on `main`); the prepared successor Commission was discarded unstarted.

|20
|The `--hop-timeout-seconds` default of 900 s was too low for the block sizes now commissioned and cost two failed attempts of Slice A (entry 16) and a per-run override on every launch. Resolved: the default is now 14400 s (4 h) and a repository default can be set with the optional `hop_timeout_seconds` key in `.wfc/config.yaml` (flag, then config key, then built-in default), through Commission `wfc-hop-timeout-default-001` (`RUN-561b19e253f74a09aea7e0fb14036c8b`), integrated locally on `main`; the installed Runtime and the installed Agent Skill do not carry it until the maintainer's promotion and `wfc skill install`.
|`DEFAULT_HOP_TIMEOUT_SECONDS` in `src/workflow_coordinator/frontdoor/lifecycle.py`; Operator Manual ch03 and ch09; Skill `setup.md`.
|Operator, Front Door
|Until promotion keep passing `--hop-timeout-seconds` explicitly. Entry 16's advice (7200 s) is superseded.
