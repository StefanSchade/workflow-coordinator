=== 4. Findings

[horizontal]
F-A (blocking, new):: *The "Run it live" command sequence cannot be followed as
printed, in all three tutorials.* Two independent mechanical defects in the
same block:
+
. `cd ../greeter-live-tN` is wrong. The preceding lines are `cd ~/wfc-demo`
and `git -C greeter worktree add ../greeter-live-tN …`, which creates the
worktree *inside* the workspace at `~/wfc-demo/greeter-live-tN`; from
`~/wfc-demo` the reader's next command therefore resolves to
`~/greeter-live-tN`. Reproduced: `cd: ../greeter-live-t1: No such file or
directory`, and no such directory exists. Every later relative path in the
block (`../requests/…`) assumes the cwd *is* the worktree, so the sequence is
internally inconsistent; the FTR's own live pattern reads `cd
greeter-live-t1`. Affects `02_first_run_example.adoc:202`,
`03_tutorial_program_change.adoc:204`, `04_tutorial_stops.adoc:189`.
Incidentally this is also the one place where a page's command would, if
anything existed there, operate outside the demo workspace (SI-6).
. The `wfc plan` invocation omits the execution bindings the real CLI
requires and exits `2`. Reproduced in the kit's own workspace with the
working-tree `wfc` (0.1.0b1), with each page's command copied verbatim:
`wfc plan: execution binding for role worker is missing: adapter, model,
reasoning` for Tutorials 1 and 3, and the same for `worker` in Tutorial 2 (the
reviewer role is reported once the worker one is supplied). Adding
`--execution-override worker.adapter=claude_cli`,
`--execution-override worker.model=<your model>` and
`--execution-override worker.reasoning=medium` (and the matching
`independent_reviewer` triple in Tutorial 2) makes the identical command exit
`0`. The task requires that "every file name, command, option, layout and
output in the pages must be what the kit and the real `wfc` of this tree
actually do", and the FTR's page contract requires the page to show "the
complete `wfc plan` command"; a command that refuses before printing anything
is neither. This is the reader's *first* live step, so the failure is the
first thing a tutorial reader meets. The remedy for both parts is inside the
three authored leaves: one word in the `cd` line and three (six in Tutorial 2)
additional `--execution-override` lines, with Tutorial 1's quoted preview then
matching its own command exactly.
F-B (blocking, new):: *Tutorials 1 and 2 claim an execution that cannot have
happened as described.* `02_first_run_example.adoc:226` states "The `wfc plan`
command above was actually executed, read-only, against this exact kit
workspace. Abridged real output:", and its `What was verified` section
(`:313`) states that "`make_workspace.py`, `rehearse.py t1-hello-page`, and
the `wfc plan` preview above were all executed against this exact working tree
and succeeded"; `03_tutorial_program_change.adoc:229` states that its own
`wfc plan` command "was actually executed, read-only, against this kit
workspace and exited `0`". By F-A the command as printed exits `2`. The quoted
output itself shows what was really run: it contains `worker:
adapter=claude_cli model=your-model-here reasoning=medium` and
`execution envelope digest:
sha256:4e924203d1da4f8429a28d63b034b9501dce9a783eb92919506edfe3356cc394`,
neither of which the printed command can produce, and I reproduced that exact
digest only by adding the three `--execution-override` flags
(`worker.model=your-model-here`). So the executed command and the printed
command differ, and the page attributes the output to the printed one. AC-7
requires each `What was verified` section to name truthfully "which commands
were executed for this page", and the task requires that where page and reality
differ "the page shows what is real". The remedy follows F-A's: once the
printed command carries the bindings, both sentences become true (with
`<your model>` reconciled against the `your-model-here` the preview shows, or
the preview re-taken).
F-C (blocking, new):: *A false statement about the chapter.*
`02_first_run_example.adoc:222` reads "`rehearse.py` is the only place `--yes`
appears in this chapter." It is not: `01_quickstart.adoc:324-330`, in this same
chapter and immediately above this page in the assembled book, is headed
"Unattended `wfc run --yes`" and shows `wfc run … --yes` in a shell block. The
sentence is one a reader disproves by scrolling, and the surrounding point
(the live `wfc run` here is shown without `--yes` so the reader answers the
prompt) survives without it. The remedy is this one sentence inside an
authored leaf — for example naming the rehearsal and the quickstart's
unattended/CI example as the only two places, or scoping the claim to the
tutorials. The underlying tension with AC-8/SI-1 is observation O1 and is the
maintainer's, not this correction's.
