=== 6. Non-blocking observations

O1 — AC-8/SI-1 cannot be met literally inside this scope:: AC-8 asks for a
test that "`--yes` occurs in no shell block of the chapter" and SI-1 says
"`--yes` appears only inside `rehearse.py`", but `01_quickstart.adoc`'s
pre-existing `quickstart-run` section is headed "Unattended `wfc run --yes`"
and is explicitly out of this Commission's scope ("unchanged except one
pointer"). The candidate narrows `WORDING_CHECKED_FILES` to the overview plus
the three tutorials and documents why in a comment, which is the honest
resolution available in scope, and the FTR's intent (a tutorial never shows
`--yes` for a live Run) is fully enforced for the four pages this Commission
controls. It is nonetheless a deviation from AC-8's literal wording and
belongs to the maintainer: either `quickstart-run` is reworded in a later
slice and the test widened to the directory, or AC-8/SI-1 are amended to say
"the tutorials". I record it rather than block on it because no in-scope
change can satisfy the literal text; F-C covers the one place where the
candidate asserted the literal reading as fact.
O2 — a pre-existing, unrelated `wfc plan` example that also refuses:: while
reproducing F-A I measured the quickstart's own preview command
(`01_quickstart.adoc:295-302`), which passes `worker.adapter` and
`worker.model` but no `worker.reasoning`: it exits `2` with `wfc plan:
execution binding for role worker is missing: reasoning`. That is pre-existing
(`66fa9d7` and earlier), outside this Commission's authority, and not
introduced here — but it is the same class of defect as F-A and the maintainer
may want one bounded follow-up for both. Note why no guard caught either: the
`BP9` quickstart guard validates subcommands, flag spellings and
argparse-required flags only, and `--execution-override` is an optional
repeatable flag whose *content* requirement is enforced later, after parsing.
I ran that guard's own flag checks over the three new tutorial pages as well:
every flag they use is a real flag and no argparse-required flag is missing.
O3 — abridgement markers are not quite uniform:: Tutorial 1 and the two
Tutorial 3 blocks mark omissions visibly (`[... digests and state-root paths
omitted ...]`, `[... banner as in Tutorial 1 ...]`, `...`), but two trailing
lines are dropped silently: the real `t3-scope-stop` report ends with
`not done    limits: usage_not_reported` and the real `t3-probe-refusal`
transcript continues with the `wfc status` block the page describes in prose
instead. Tutorial 2 additionally shortens the five 40-character commit hashes
of the `commits` line to seven characters, which no marker announces. None of
this changes a fact and no line is invented; it is one marker away from being
exact.
O4 — machine-specific hashes survive in the pages:: the task asked for
machine-specific values to be replaced by placeholders and the pages do that
for paths and run ids (`~/wfc-demo`, `greeter-run-<run-id>`), but
`02_first_run_example.adoc` keeps a payload commit hash
(`7bc2332a8fc6…`), a guidance commit (`28d31582926…`) and a manifest digest,
and `04_tutorial_stops.adoc` keeps the two seed commit hashes (`86cbda3`,
`28d3158`). These are real output from the author's run, but the kit's seed
commits are not byte-reproducible — my own workspace produced `8ceffb5` and
`9e69637` — so a reader comparing hashes will always see a difference. A
`<commit>`-style placeholder, as the `archive` line already uses, would avoid
the only invitation to a false mismatch in the chapter.
O5 — the quote guard's self-tests assert the parser, not the failure:: the two
`test_guard_self_test_*` functions construct a leaf with a missing or diverging
quote and then assert what `find_kit_quotes` returned plus, separately, that
the kit file is absent or the text differs. They never exercise the comparison
that would fail. The real check does fail on both cases — the missing-file
branch appends a failure and a removed branch would raise on `read_text` — so
the guarantee holds today; factoring the comparison into one function the
self-tests call would make the guard's own failure mode tested rather than
implied.

says "`rehearse.py` itself prints these", but the fourth bullet

O7 — the live placeholder is not shell-parseable:: `--guidance-commit <the

fix is only to drop the possessive, e.g. `<the guidance commit of the kit>`.
