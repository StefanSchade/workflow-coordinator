=== 4. The slice re-derived at my own hand

Everything below is my own execution against the installed package outside
the checkout, not a reading of the earlier passes. 110 checks, 0 failures.

Marker and idempotence:: Two independent installs into two different homes
produce *byte-identical* markers; the keys are exactly `schema`,
`wfc_version`, `files`, `schema` is `1`, and no key contains `time`, `date`
or `stamp` — the "no timestamp, equal inputs give equal bytes" requirement,
measured rather than inferred. A second install reports `STATE: current` and
changes not one byte.

The five states, both hosts:: `absent` → created; `current` → no write;
`stale` → replaced without `--force`, marker now carrying this tree's
`VERSION`; `modified` and `foreign` → return 3, `DIFFERING FILES:` listed,
and the destination byte-identical afterwards; `--force` → replaced, and the
result equals the packaged bytes exactly.

Symbolic links:: A symbolic-link destination returns 2 for both hosts, with
*and* without `--force`; the link is still a link afterwards, still points at
the same target, and the target's own file is untouched in content and in
directory listing. I also attacked the inside of an installation: replacing a
packaged file with a symbolic link to a file *outside* the destination makes
the state non-`current` (refused with 3), and `--force` then replaces the
link with a regular file while the outside file keeps its original content —
the link is never written through.

`--dry-run`:: On `absent` it returns 0 and prints `WOULD INSTALL:`; on
`modified` it returns 3; in both cases a full before/after tree snapshot of
the whole temporary home is identical, so it writes nothing and returns what
the real call returns.

Staging:: After an install no `*wfc-skill-staging*` entry exists anywhere
under the home, the skills root contains exactly `wfc`, and the home contains
exactly `.claude`. With the parent of the skills root made unwritable and a
`stale` installation present, the staging allocation fails and the old
installation is still *complete and byte-identical* afterwards — the "never a
partial one" invariant, measured on the failure path (the exit code on that
path is O1 below).

Destination table:: `CLAUDE_CONFIG_DIR` is honoured for `claude` user scope
(the install lands in `<dir>/skills/wfc` and `$HOME/.claude` is never
created) and ignored for `codex`; `--skills-dir DIR` addresses `DIR/wfc`;
`--skills-dir` together with `--scope` returns 2.

Status (AC-4, SI-11):: A missing host returns 2. Every state returns 0,
`absent` included. `--scope` and `--skills-dir` each select exactly one
block. Outside a Git work tree the default call prints one block, `user`
only. The JSON payload has exactly `host`, `packaged_version`,
`installations`, and each installation exactly `scope`, `path`, `state`,
`installed_version`. Independence, both directions and four states deep:
with one host `current`, I made the other host in turn `current`, `stale`,
`modified` and `absent` and the held host's `status` output was
byte-identical every time, for `claude` held and for `codex` held. `status`
wrote nothing: a whole-home snapshot before and after two calls is identical.

Project scope (SI-5):: Outside a Git work tree both `install` and `status`
return 2 and the plain directory stays empty. Inside a seeded repository the
install returns 0, prints `NEXT EXPLICIT ACTION:`, and afterwards
`git status --porcelain` is exactly `?? .claude/`, `HEAD` is unchanged,
`git ls-files -s` is unchanged, the reflog is unchanged, `.wfc/` does not
exist, the repository root contains exactly `.claude`, `.git` and
`README.md` — no `CLAUDE.md`, no `AGENTS.md`, no `.gitignore` — and the user
scope was not touched. From a nested subdirectory the destination is the Git
*top level*, and the subdirectory stays empty.

Dispatcher:: Nine invocations through the console entry: `skill`,
`skill nonsense`, `skill install`, `skill status`, `skill install mistral`
each exit 2; `skill --help` and the `--help` of all three subcommands each
exit 0; all nine print `usage: wfc skill …` and none reaches the legacy
operator path. The codes arrive as process exit codes through argparse's
`SystemExit`, which is what the CLI contract observes (O6).

`show`:: Default prints `SKILL.md`, byte-equal to the tree's packaged file;
`--list` prints four lines, each with a `sha256:` digest; a named reference

Hostile shapes, nine of them:: destination a *regular file* → `foreign`, 3,
still a file; `--force` → replaced by the directory. Skills root a symbolic
link to another directory → install lands in the relocated root, no staging
leftover. Unwritable parent, with and without an existing installation →
fails closed, nothing partial (O1). Marker unparsable, wrong `schema`, or
missing `wfc_version`, over byte-identical content → `current` with
`installed_version: null`, which is what the state table defines (`current`
is decided by the files, `foreign` only for a non-`current` directory), and
`install` correctly does nothing; the stale marker therefore survives (O7).
Marker replaced by a symbolic link to an outside file → read as absent
rather than followed, state `current`, and the outside file is untouched.
An extra file inside an otherwise current installation → `modified`, 3, the
extra file listed and preserved; `--force` removes it with the directory.
`--repository` at a nonexistent path under project scope → 2 with the
