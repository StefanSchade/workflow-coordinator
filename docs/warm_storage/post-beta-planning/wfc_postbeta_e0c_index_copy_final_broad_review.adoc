=== 2. How I measured

`pytest` is not installed in this review sandbox (`python3 -c "import pytest"` ->
`ModuleNotFoundError`; no virtual environment in the worktree, no network,
`WFC_TEST_INPUTS`/`WFC_TEST_PROFILE` unset), so I restate no pytest count from the
Worker's summary as my own. Every number below comes from my own execution on this
host (Git 2.47.3, Python 3.13.5, ext4), with one disposable repository per trial
under the sandbox `TMPDIR`. Two sources were used: the committed one (`src/`) and
the pre-E0b one (`git show 22e18b5:src/.../git_facts.py` materialized into a
scratch copy of the package outside the checkout). No probe wrote into the
repository worktree or index, and no probe path is part of this commit.

Where the committed tests wrap `shutil.copy2` to observe the copy, my site probe
instead intercepts the module's *own* `os.unlink` cleanup and stats the copy as it
is actually left on disk at the end of the real call — a different seam, so a
mistake in the committed instrumentation (E0b broad O2) cannot hide behind it. The
live index's mtime is forced far into the past (`2001-09-09`) before each trial,
so "carried" and "fresh" are unmistakable rather than a nanosecond coincidence,
and the worktree always holds a committed-then-same-size-edited file (`v1\n` ->
`v2\n`), the exact racy-clean situation under test.

* The four `mkstemp` prefixes are byte-identical to the pre-E0b ones and

* No refusal, limit, message or return shape is touched anywhere in the range; the

Simplicity and maintainability, assessed on purpose: one helper plus one required
keyword replaces four byte-identical idioms and removes more product lines than it
adds, and the single `BaseException` handler is three lines in one place instead of
four restored `finally` blocks — the arrangement with the *least* lasting
mechanism that still holds both invariants. The two cleanup mechanisms are not
redundant: the helper covers the window before ownership passes to the caller, the
sites' `finally` covers the rest. I found no abstraction, state or safeguard here
that earns its keep only hypothetically. One consolidation remains possible but is
out of scope and not a defect: <<e0c-o3,O3>>.

=== 6. Non-blocking observations

[[e0c-o1]]
O1 — the `0600` -> `0664` mode widening is real at the three new sites, and I agree
it is immaterial:: Measured directly: `mkstemp` creates the file `0600`, and
`copy2`'s `copystat` then carries the index's own mode onto it (`0664` on this
host, `umask 002`); pre-E0b the three sites left `0600`. E0's O3 and E0b broad O3
already recorded this for one and then three sites. The copy holds index metadata
— tracked path names, object ids, stat data — that is already readable to anyone
who can read the checkout's own `.git/index`, no site promises `0600`, and the
file lives for the duration of one read. Nothing to change; recorded so that a
future move of these temporaries somewhere with a stricter expectation is made
with open eyes, and so the next reader does not rediscover it as a surprise.

[[e0c-o2]]
O2 — two wording slips in the E0c verification record:: Its section 4 says "five"
non-blocking observations while citing seven labels and describing four
substantive items, and its header says `git status --short -uall` "is empty" at
entry and exit, whereas `-uall` in this worktree lists 22 untracked wrapper-injected
paths besides this pass's own new artifact (`/dev/null` device nodes for
`.bashrc`, `.claude/*`, `.idea`, `.mcp.json` and similar, all dated before H001). The substantive statement — no tracked
modification, nothing under `src/` or `tests/` touched — is true and I verified it
with `git status --porcelain -uno` and the range diff. Worth noting only because
the Commission's own commit mechanics tell the next agent to derive
`commit_intent.paths` from `git status --short -uall`, where those 22 entries are
present and must not be mistaken for Hop output.

[[e0c-o3]]
O3 — six copies of the guarded-unlink idiom now live in one module:: `git_facts.py`
contains the `try: os.unlink(...) except FileNotFoundError: pass` shape at `:126`,
`:270`, `:570`, `:906`, `:967` and `:1060` — four call-site `finally` blocks, the
helper's new handler and `_build_candidate_tree`. Five of the six predate E0b, so
this is not a cost E0b created, and the module-wide idiom is deliberate. A
`contextlib.contextmanager` version of `_isolated_index_copy` used as
`with _isolated_index_copy(identity, prefix=...) as index:` would fold four of them
into one and make the ownership window explicit in the type rather than in a
comment. That is a separate, behaviour-preserving refactor of a working
arrangement, not a defect, and I do not request it inside this package; it is the
natural next simplification if these sites are touched again.

[[e0c-o4]]
O4 — for the maintainer: DO step (3)'s premise did not hold in the agent sandbox::
