=== 5. Simplicity, and the safety properties the task names

The whole change is 101 added source lines across three modules
(`git show --numstat`: 14 + 75 + 12), and I could
not find a materially simpler realisation that keeps the same guarantees. The
O3 half replaces a `raise` with a collected tuple and one print line -- the
minimum. For O2(a) the shape predicate is reused rather than reproduced, and
it sits at the two places where `--config` first arrives as a filesystem
argument; putting it only in `cmd_run` would leave the `run_lifecycle`
library seam unguarded, and putting it in both would be the redundant
safeguard this review is asked to look for. For O2(b) the only state added is
a two-entry constant; the adapter is read from the already-pinned envelope
rather than by widening the `authorized` journal record, which would have
touched a persistence seam for a diagnostic. For O2(c) the limit is imported,
not duplicated.

The four named safety properties survive. An unused default does not become
evidence that a review happens: the program selection still decides, the plan
preview states the inert default unconditionally, and an unknown role name is
still refused at parse time. No classification or exit code moved. The
trusted/untrusted split is intact -- the tail exists only in the refusal
message, is labelled untrusted, and no probe byte is persisted as or
presented as evidence. And the fail-closed launch path is not eroded: every
new check refuses, none permits, and the one check that was narrowed was
narrowed on the axis D2 Option A authorises.

=== 6. Non-blocking observations

N-1 `wfc run` still dereferences a malformed `--config` before naming it:: `cmd_run` resolves the Hop timeout first
(`lifecycle.py:1374` calling `_resolve_hop_timeout_seconds`, `:1356-1366`),
and that reads `inputs.repository / args.config`, which for an absolute or
`../` value is a file *outside* the repository. If that read succeeds the new

behaviour and neither mutates anything, so no criterion is violated, but
`docs/operator_manual/ch03_running/01_preparation.adoc`'s new sentence

extent. Validating `args.config` once at the top of `cmd_run` -- in addition
to, not instead of, the `_authorize` check that guards the library seam --
would close it.
N-2 two verbatim transcripts in chapter 9 were not refreshed:: `ch09_consumer_quickstart/02_first_run_example.adoc:254-256` quotes a real
`wfc plan` preview that now gains the unconditional `role defaults ignored by

and `ch09_consumer_quickstart/04_tutorial_stops.adoc:105` quotes the probe

N-3 prelaunch is now an earlier site for `refused_drift`:: `_envelope_adapter`
reads the pinned envelope through `_pinned_envelope_text`, whose two
`refused_drift` refusals could previously first fire only at step 4 (the
Commission commit). The classification, message and exit code are unchanged
and firing earlier is strictly more fail-closed, so this is an improvement
rather than a defect; it is simply not mentioned in the record's Design
section, which describes the read as if it were free.
N-4 `_ADAPTER_KNOWN_BASENAME` compares against *all other* adapters:: `other_basenames` is "every entry except mine", so if a third adapter is ever
added that legitimately drives the `claude` or `codex` binary, the check
turns into exactly the false positive the record's mitigation forbids.
Harmless today (`_ADAPTERS` has exactly these two), and a one-line guard
(`if adapter not in _ADAPTER_KNOWN_BASENAME: return`) or an explicit
pair-wise table would keep it harmless after the next adapter.
N-5 the printed tail reaches `stderr` without this module's own encoding guard:: `cmd_run`/`cmd_resume` print the exception with plain
`print(f"wfc run: {error}", file=sys.stderr)`, while the module elsewhere
routes operator text through `_stdout_safe` (`lifecycle.py:1313-1321`)
precisely because a refusal reason can carry bytes a strict-encoding stream
rejects. A non-ASCII probe tail on an ASCII-encoded `stderr` would therefore
raise `UnicodeEncodeError` in place of the refusal report. This is a
pre-existing exposure -- the neighbouring `baseline probe mutated the
repository (changed: …)` message interpolates arbitrary filenames, which can
even carry lone surrogates, whereas the new tail cannot -- so the candidate
does not regress it; applying `_stdout_safe` to those two prints would close
both at once.
N-6 only `wfc plan` names the ignored defaults:: `wfc run` prints the two
digests and launches; an operator who skips the preview and passes `--yes`
never sees that a committed `independent_reviewer` default is inert. The
plan's own mitigation names `wfc plan`, so the criterion is met as written;
worth remembering if the inertness ever needs to be visible without a
preview.
N-7 the reverse cross-adapter direction has no test of its own:: a
`codex_cli` envelope with `--executable claude` is refused by the same
dict-driven branch as the tested `claude_cli` + `codex` case, and the
acceptance list names the pair. I verified the symmetry by reading the code
rather than by executing it; a parametrisation would have made it
mechanically evident.
