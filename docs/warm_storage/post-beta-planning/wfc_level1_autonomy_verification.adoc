== 2. Exact formulations changed in this Hop, and why

. *`docs/operator_manual/ch10_level1_orchestration/02_worked_sequence.adoc:61`*
 -- `## Default escalation` changed from
+
____
Stop and ask on any ambiguity.
____
+
to
+
____
Stop and ask if the task cannot be completed inside the authorized scope.

Reason: this is the literal phrase the task document names as a known
autonomy-inhibiting instance; it is a Worker (Level 0) escalation default
inside an illustrative task document, not the Level-1 operator's own rule,
but an unqualified "any ambiguity" trigger still reads as exactly the
overbroad default-stop sentence the rest of this chapter was rewritten to
remove, and the review focus explicitly asks to grep the whole Level-1
documentation for a surviving one. The replacement matches the bounded
phrasing already used, verbatim or near-verbatim, in every other worked
example in ch09 (`01_quickstart.adoc`, `02_first_run_example.adoc`,
`03_tutorial_program_change.adoc`, `04_tutorial_stops.adoc`), so the manual
now uses one consistent escalation-default example everywhere instead of
two different ones.

 places: the `Status::` line, the `Settled by` heading, and the closing

== 3. Boundaries confirmed unchanged and still binding

Checked directly in `SKILL.md`'s ``Authorization`` item 5 and ``Always stop
and ask before`` list, and in Operator Manual ch10's standing-instructions
template and human-decisions section:

* a push, tag, publication or configuration change;
* a Runtime promotion, or a change of installed WFC version;
* widening scope, authority, program or Hop budget beyond what the human
  set, for a first launch or after a stop;
* judging a stop's disposition (salvage into a successor, forensic
  preservation only, or discard) whenever that judgment is genuinely open;
* acting on an open Finding or working around a negative review -- only the
  independent reviewer opens or resolves a Finding, and the Worker/
  Reviewer-never-self-accept rule is untouched;
* discarding a branch, worktree, stash entry or preserved ref the operator
  did not itself create for this task;
* the Trusted Git boundary (the skill's own ``Never`` list: no commit
  inside a Run's checkout, no hand-edit of `.wfc/` state or Evidence) and
  the sandbox -- untouched, out of this Commission's scope regardless.

Each of these is stated as a binding rule (not a soft suggestion) in both
`SKILL.md` and ch10, in the same wording as before this Hop; this Hop did
not weaken, remove or qualify any of them. No sentence anywhere read lets
an agent override a technical WFC prohibition or a mandatory safety
control "by its own interpretation" -- every delegated freedom in both
documents is paired with the specific classification(s) or fact(s) it
applies to, never a general license.
