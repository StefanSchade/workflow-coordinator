* `operator.py:945-950`, the first statement of `run_serial_hops`, raises
  `OperatorPreflightError` with message `"execution boundary mode
  mismatch: ..."` whenever `run.boundary != execution_configuration.boundary`,
  strictly before `checkout_state_root` is called -- i.e. before any dispatch
  marker could be written. The new parametrized test constructs a Run with
  one boundary mode via `new_run(..., boundary=...)`, calls `run_serial_hops`
  with an `execution_configuration` resolved to the other mode, and asserts
  both the raised message (`match="boundary mode mismatch"`) and that
  `dispatch.json` was never created and the repository working tree is
  unchanged. This is the exact shape F1 required, covering both mismatch
  directions.
* `execution_boundary.py`'s `validate()` bind-source loop raises
  `BoundaryConfigurationError("bind sources must be inside repository")` via
  `source.relative_to(repository)` for any non-scratch `Mount` whose source
  does not resolve under the repository root. The new test constructs a
  plain, undesignated `Mount` (not the external-scratch, provider-channel,
  or provider-authentication parameter) whose source is an existing sibling
  file entirely outside the repository tree, asserts the refusal
  (`match="inside repository"`), and asserts the host-side file's content is
  unchanged afterward. This is exactly N16's companion assertion that F2
  named as missing.
