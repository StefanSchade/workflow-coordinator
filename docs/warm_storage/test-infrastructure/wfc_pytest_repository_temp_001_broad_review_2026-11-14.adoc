== Storage, fixtures, concurrency and retention

The hook configures pytest allocation, rather than replacing fixtures or
changing Runtime, adapters, direct `tempfile` configuration, or subprocess
environments. The first nonempty `TMPDIR`, `TMP`, or `TEMP` is selected and
resolved; a supplied root must exist, be writable, and resolve outside
`/tmp`. A supplied checkout path must be under ignored `tmp/`. Allocation
uses a dedicated `wfc-pytest` child. Without supplied scratch, the default is
the ignored checkout `tmp/pytest`, writable within the worker's authorized
checkout. Symlink checks and resolution reject redirection to unsuitable
storage. Allocation errors identify the attempted root and fail clearly.

Existing `--basetemp` and `PYTEST_DEBUG_TEMPROOT` bypass this selection and
retain pytest semantics, including explicit basetemp reset. Normal selection
uses pytest's existing numbered bases, owner checks, locks and retention;
it does not share a destructively reset basetemp. The temporary environment
override is removed immediately after allocation. Existing fixture behavior
and failure-path reporting remain pytest-owned. The added verbose header
identifies the selected base for ordinary repository configuration.

The committed subprocess tests passed: three parent tests passed and the
probe was skipped in the parent, as intended. Child probes actually execute
the fixture and Git-repository assertions. They cover the no-Harness,
no-temp-variable checkout default, supplied scratch, simultaneous processes,
explicit basetemp, explicit debug root, and unsuitable missing scratch.
