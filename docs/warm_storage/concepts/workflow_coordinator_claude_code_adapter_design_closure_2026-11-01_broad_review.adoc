== 1. Disposition

Outcome:: `accept`
Route:: `accept`

The committed correction is sound and exactly bounded.  It changes only the
final sentence of the design's “Model and effort” row (`design:83-84`).  The
sentence no longer predicts that an unavailable provider selection must produce
a nonzero process exit.  It instead requires fail-closed handling without
`--fallback-model`, replay, or binding substitution; makes the separately
authorized pinned-CLI qualification record the actual process status and wrapper
behavior; and applies the design's already defined transport, wrapper, and

mandate.  In particular, the one-line correction does not regress the closed

special case, or unnecessary abstraction remains blocking.

== 3. Predecessor-Finding closure

=== 3.1 Historical F002 -- observable provider outcomes

Disposition in this design:: *SUBSTANTIVELY CLOSED.*

Invariant rechecked:: The design may classify transport from observed process
facts, but it must not turn a desired fail-closed provider rejection into an
invented exit status, wrapper value, fallback, retry, or provider-error oracle.

The corrected sentence satisfies all three required parts (`design:84`):

. An unavailable selected model/effort pair must fail closed, with
  `--fallback-model`, automatic replay, and binding substitution explicitly
  prohibited.
. The separately authorized pinned-CLI qualification records actual process
  status and wrapper behavior rather than requiring a nonzero exit.
. Rejection uses the existing gates: an observed nonzero exit or timeout is a
  transport failure; a zero exit without a successful, valid structured
  candidate fails wrapper or semantic validation.

This is not a cosmetic rewording of the old assertion.  The provider-neutral
mechanics it names already exist elsewhere in the design:

* `run_one_hop` rejects nonzero and timeout before candidate trust and rejects an
  absent candidate before `validated_result` (`design:23`);
* the Claude adapter must require a successful structured-output wrapper member
  and must never fill or repair correlation or contract fields
  (`design:146-154`);
* the adapter classifies only observed process facts, sends a zero exit through
  wrapper decoding and WFC validation, and does not infer a nonzero outcome for
  refusal or sandbox loss (`design:164-166`);
* the failure table rejects nonzero/timeout before parsing and rejects absent,
  malformed, unsuccessful, or wrongly correlated zero-exit output without
  repair or retry (`design:218-234`); and
* the fake and separately authorized pinned-CLI qualifications record observed
  behavior and explicitly prohibit manufacturing a transport result or tool-
  execution oracle (`design:239-251`).

The whole-document search found no surviving equivalent of “must surface as a
nonzero transport failure.”  The other status statements are conditioned on an
observed result or expressly leave the provider behavior to later qualification.
The correction adds no router, registry, provider-status parser, telemetry,
fallback, or retry mechanism.

=== 3.2 Historical F001 -- controlled noninteractive startup

Disposition in this design:: *SUBSTANTIVELY CLOSED; NO REGRESSION.*

The H001 diff changes only `design:84`; it cannot itself reopen the predecessor
ambient-configuration defect.  The complete design still retains the controls
whose composition was rechecked here:

* exact `--restricted --safe-mode --strict-mcp-config`, explicit six-tool
  surface, generated closed settings, denied permission prompts, and no session
  persistence (`design:104-140`);
* no user/project/local settings, `CLAUDE.md`, skill, hook, plugin, custom
  agent/command, workflow, memory, or MCP source, with administrator-managed
  policy honestly retained as a residual host prerequisite rather than pinned
  binding evidence (`design:140-144`);
* required sandbox availability, no unsandboxed-command retry, repository-only
  intended file reach, no configured network domains, and no claim that this
  provider control is a Coordinator-verified OS boundary
  (`design:121-144,205-209`); and
* fake-CLI assertions plus a release-gating, separately authorized real-smoke
  strategy for the closed startup profile, required edit/test behavior,
  planted customization, out-of-workspace read, network attempt, startup
  unavailability, and post-start refusal (`design:239-251,259-265`).

The design continues to distinguish silent settings rejection from a local
not-started error and assigns effective-profile qualification to the pinned
smoke (`design:166`).  It therefore neither assumes that a flag is an OS
boundary nor silently substitutes ambient behavior when the requested profile
cannot be qualified.
