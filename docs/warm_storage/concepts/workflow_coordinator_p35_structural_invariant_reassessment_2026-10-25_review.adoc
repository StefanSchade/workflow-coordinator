=== P35SIR-001 -- path quantifier and guarantee strength are incorrect

Assessment section 1 defines the target mismatch as one in which "every
post-invocation path toward completion lacks authority." The accepted rule is
universal in the opposite direction: every checkpoint-reaching path must
encounter a later disposer, so the profile is invalid when *any one* such path
can reach a checkpoint without one (design sections 4.4--4.5). A branching
profile with one safe branch through a later resolve gate and one unsafe branch
directly to a completion phase is therefore rejected even though not "every"
path lacks authority. Determination 1 must state that actual failure class and
its quantifier precisely.

Determinations 4 and 7 then call the accepted property a "universal guarantee
that every capability-allowed opening history has an autonomous later
disposition" and an "autonomous-recoverability guarantee." It proves neither.
The static predicate proves only that a later phase *holds* one closing
operation before every enumerated checkpoint; it cannot require that a
particular invocation uses that operation. `reduce_result` accepts an empty
Finding delta from that gate and proceeds to `_apply_route`
(`reducer.py:1705-1725,1835-1836`). An agent-local two-phase probe instantiated
the minimal counterexample:

[source,text]
----
open [may open, no disposition] --G--> close [finding_authority:resolve] --C-->

H1 open:  creates F001, GOTO close                 => READY at close
H2 close: emits no disposition delta, requests C  => AWAITING_HUMAN,
                                                     F001 remains OPEN
----

This topology satisfies the accepted strict-after authority shape, yet its
actual history does not recover autonomously. The runtime guard correctly
prevents completion. Correct sections 1, 3--4, 6--8, and the conclusion as
needed so the cost/benefit analysis consistently describes P3.5 as a static
authority-opportunity/path-conformance property, not guaranteed disposition.

=== P35SIR-002 -- component-level conclusion is incomplete

The opening conclusion says only the proposed new-launch admission check is
affected; determination 8 defers the static ordered-reachability check; and
the final recommendation retains the design as a post-MVP option. The accepted
design, however, has separable components beyond that check: section 3.1's
schema-v4 required `may_open_findings` declaration and runtime enforcement,
section 3.2's additive runtime clean-`GOTO` guard, section 4's static validator,
and section 6's legacy admission/migration consequences. The reassessment does
not say whether the first two are also deferred, independently retained for
Level 0, or rejected, nor how its no-migration recommendation applies to them.

Item C requires the conclusion to name exactly which parts of the design each
component affects. Add an explicit, internally consistent disposition of at
least: (1) explicit creation declarations and their runtime enforcement,
(2) the clean-`GOTO` guard, (3) static ordered-reachability validation and its
preflight placement, and (4) legacy new-launch admission/profile migration.
Align determinations 6--8 and the summary recommendation with that disposition;
no implementation or migration is requested.

=== P35SIR-001 -- RESOLVED

The corrected assessment now states that one uncovered checkpoint-reaching
path is enough to reject a profile (sections 1 and 4), and it consistently
describes a strictly later disposer as an authority *opportunity*, not proof
of an emitted disposition (sections 1, 3, 4, 6, and 7). The correction therefore
survives both H002 counterexamples: the branch with one safe and one dangerous
continuation is rejected, while a topology containing a later authorized gate
is not misrepresented as guaranteeing autonomous closure when that gate emits
no Finding delta.
