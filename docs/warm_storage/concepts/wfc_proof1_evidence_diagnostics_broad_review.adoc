== What the change satisfies (independently reproduced)

`pytest` is not installed in this review shell and cannot be downloaded (no
network), so each claim below was re-derived with a stdlib-only harness under
`tmp/review-h002/` (review scratch, git-ignored, not committed): a direct
behavior driver, a baseline/candidate resolution-parity probe, a minimal
`pytest` API shim that executes the committed test modules, and a mutant
generator. The authoritative suite run remains the Coordinator-owned
`task-check`.

=== The three required message facts are present

A bare authored `python` that does not resolve on a snapshotted `PATH`
containing `python3` now raises, with the pre-existing type
(`ExecutableResolutionError`, still an `OSError`) and the pre-existing
prefix:

----
executable does not resolve to an executable regular file: python; discoverable
PATH siblings (informational only, not selected): python3; supply a conforming
environment by prepending its prepared bin/ directory to PATH
----

`prepare_evidence_commands` still wraps it unchanged, so the operator-facing
form additionally carries the policy-authored command name:
`evidence command task-check: executable does not resolve to an executable
regular file: python; ...`. With no discoverable sibling the probe reports
`no discoverable PATH siblings` instead of omitting the clause.

=== Resolution, fingerprinting, alias handling and preflight are unchanged

* A 13-case matrix (bare resolvable/unresolvable, symlinked `argv[0]` and its
  canonical target, non-executable regular file, relative `PATH` entry rooted
  at the repository, absolute `argv[0]` present and missing, slash-containing
  `argv[0]` present and missing, `PATH=""`, absent `PATH` key falling back to
  `os.defpath`, multi-entry first-match, multi-entry unresolvable) produces
  byte-identical outcomes on the base and candidate trees, comparing
  invocation path, canonical path, every `StatFingerprint` field and the
  raised exception type.
* `src/workflow_coordinator/operator.py` and
  `src/workflow_coordinator/commissioning.py` are untouched, so `_preflight`
  still refuses fail-closed; the refusal now simply carries a longer message.
* No alias substitution: with `python3` present and `python` authored,
  `python3` resolves on its own and authored `python` is still refused. The
  forbidden behavior was injected as a mutant (resolve the first discoverable
  sibling) and the committed tests kill it.
* The probe is reached only after the resolution loop has exhausted every
  candidate, i.e. only on the terminal refusal path. It introduces no new
  uncaught failure class: `OSError` from `os.listdir`/`os.stat` and a
  non-executable or vanished candidate are all swallowed; the pre-existing
  `ValueError` behavior for an embedded NUL in `PATH` is identical on both
  trees because the candidate loop reaches `os.stat` first.

=== The probe is bounded, read-only and quiet

* *Read-only.* A sibling whose body would `touch` a marker file is listed but
  never executed; after both `_discoverable_path_siblings` and the full
  `resolve_executable` refusal, the marker does not exist, the directory
  listing is unchanged and every entry's `st_mtime_ns` is unchanged.
* *Bounded.* With `limit + 7` matching executables the result is exactly
  `DISCOVERABLE_SIBLING_PROBE_LIMIT` (5), and the bound also holds when the
  matches are spread across four `PATH` directories. Worst-case message
  length with five 200-character sibling names is 1256 bytes.
* *Selective.* The authored name itself, unrelated names, non-executable
  regular files, directories named like a sibling and dangling symlinks are
  all excluded; names are deduplicated across `PATH` entries and the order is
  deterministic across repeated calls.
* *Tolerant.* A `PATH` containing a missing directory, a regular file and a
  mode `0o000` directory is skipped without raising, and the later entries
  are still probed.
* *No path disclosure.* Only basenames enter the message: a `PATH` entry
  `.../secret-dir` contributes `python3` and neither the entry nor the
  repository path appears in the text.

== Non-blocking observations

* *The bound test derives its expectation from the constant.*
  `test_sibling_probe_is_bounded` reads
  `evidence.DISCOVERABLE_SIBLING_PROBE_LIMIT` and creates `limit + 5` files,
  so raising the constant to 10000 survives while removing the enforcement is
  killed. Behaviorally the bound is tested; the intended small *value* is not
  pinned. An absolute assertion (for example `len(siblings) <= 8`) alongside
  the existing one would pin both.
* *The path-like guard is not actually pinned.*
  `test_sibling_probe_is_empty_for_path_like_authored_commands` still passes
  with the `os.path.isabs(...) or "/" in authored_argv0` early return removed,
  because a `listdir` name can never start with `./python` or
  `/usr/bin/python`. The guard is an equivalent-output optimization that
  avoids pointless directory listings, so this is a weak test rather than an
  untested behavior.
* *Cross-directory de-duplication is uncovered.* Removing `name in seen`
  passes the committed suite. It is an implementation nicety, not a
  BUG-record obligation.
* *The `_open.adoc` card is stale and out of scope.*
  `docs/backlog/_open.adoc:398-400` still reads "investigate actionable
  missing-tool/environment messages before selecting a correction". The
  overview is the maintainer's to update and is not in this WorkItem's scope,
  so it is reported here rather than changed. Its "never silently substitute
  `python3`" constraint remains honored by the implementation.
* The informational clause matches on name prefix, so for a different authored
  token it can list non-interpreter siblings (`git` -> `git-lfs`). The clause
  labels them "informational only, not selected", which is what the BUG
  record's desired direction asks for.
