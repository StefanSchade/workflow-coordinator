== Acceptance criteria, independently re-derived

=== The three required message facts are present

A bare authored `python` that does not resolve on a snapshotted `PATH`
containing `python3` raises `ExecutableResolutionError` -- the pre-existing
type -- with the pre-existing prefix intact (220 bytes):

----
executable does not resolve to an executable regular file: python; discoverable
PATH siblings (informational only, not selected): python3; supply a conforming
environment by prepending its prepared bin/ directory to PATH
----

So (a) the unresolved authored command is named, (b) the discoverable siblings
are listed and explicitly marked as information rather than a selection, and
(c) one sentence states how a conforming environment is supplied.
`prepare_evidence_commands` wraps it unchanged, so the operator-facing form
additionally carries the policy-authored command name (`evidence command
task-check: ...`, 249 bytes). With no discoverable sibling the clause reads
`no discoverable PATH siblings` rather than being omitted.

=== Resolution, fingerprinting, alias handling and canonical identity are unchanged

`tmp/review-h008/diffmatrix.py` loads the `16a3034` module and the candidate
module side by side against the same freshly built filesystem world and compares
the *full* observable outcome of each: on success the invocation and canonical
basenames plus all five `StatFingerprint` fields; on failure the exception class
and its immediate base; and in both cases what the admission seam sees, by
calling `prepare_evidence_commands` under the very `except ValueError` that
`operator._preflight` uses at `src/workflow_coordinator/operator.py:517`.

Twenty-six worlds, *zero* divergences: empty directory; sibling only; twelve
matching siblings; exact match alone and alongside a sibling; self-referential
symlink; two-hop mutual symlink loop; dangling symlink; symlink to a real
executable; FIFO named like a sibling; mode `0o000` `PATH` directory; sibling
not executable by us; regular file used as a `PATH` entry; non-existent `PATH`
entry; `PATH=""`; embedded NUL in the only and in a later `PATH` entry; embedded
NUL in `argv[0]`; relative, absolute and empty `argv[0]`; invalid-UTF-8 sibling

No alias substitution: with `python3` present and `python` authored, `python3`

=== The probe is bounded, read-only and quiet

* *Reached only on refusal.* The call sits after the candidate loop is exhausted
  (`src/workflow_coordinator/evidence.py:182`), so a resolvable command never
  triggers a directory listing.
* *Read-only.* Only `os.listdir`, `os.stat` and `os.access` are used; a sibling
  whose body would `touch` a marker is listed but never executed, and a mutant
  that adds a `subprocess.run` of the probed candidate is killed.
* *Bounded.* `DISCOVERABLE_SIBLING_PROBE_LIMIT` is 5, enforced across `PATH`
  entries rather than per entry. Worst case measured with five maximal-length
  (255-byte) filenames: 1496 bytes of message, 1525 at the seam.
* *Selective and deterministic.* The authored name itself, unrelated names,
  non-executable regular files, directories, FIFOs and dangling symlinks are all
  excluded; names are de-duplicated across entries and ordered by `sorted`.
* *Tolerant of a broken `PATH`.* Missing directories, a regular file used as an
  entry and a mode `0o000` directory are skipped without affecting the refusal.
* *No path disclosure.* Only basenames enter the message; neither the `PATH`
  entry nor the repository path appears.
* *Cheap.* Over this host's real five-entry `PATH` (2230 listable names) the
  whole refusal including the probe costs 1.3 ms per call, and only on the
  failure path.

== Non-blocking observations

* *The path-like early return is covered only vacuously.* Removing
  `if os.path.isabs(authored_argv0) or "/" in authored_argv0: return ()`
  (`src/workflow_coordinator/evidence.py:128-129`) still passes the committed
  suite -- the single surviving mutant. The guard is nonetheless not wrong: for
  a path-like `argv[0]` no `PATH` basename can start with a slash-bearing token,
  so the probe would return `()` anyway, and the only behavior the guard
  protects is a `KeyError` on a snapshot without a `PATH` key -- unreachable,
  since `EnvironmentSnapshot` is constructed in exactly one place
  (`src/workflow_coordinator/evidence.py:98`) and `snapshot_environment` always
  sets `PATH`. So the test is vacuous rather than the code defective.
* *Hostile-but-legal sibling filenames reach the refusal text unsanitised.* A
  file named `python3\n\x1b[2Jevidence command task-check: OK` on a `PATH`
  directory is reproduced verbatim in the message, and an invalid-UTF-8 name is
  reproduced surrogate-escaped. Every reachable sink is safe, which is why this
  is not blocking: all refusal prints in `scripts/` and `src/.../frontdoor/` go
  to `sys.stderr`, whose handler is `backslashreplace`; `json.dumps` defaults to
  `ensure_ascii=True`; the preflight seam decides on exit status, not text; and
  the refusal class, the fail-closed outcome and the 5-name bound are unaffected.
  The precondition also subsumes itself -- anyone who can create that filename in
  a snapshotted `PATH` directory can create an executable `python` there and own
  the evidence command outright. Writing the message to a *strict* UTF-8 stream
  would raise `UnicodeEncodeError`; no such sink exists today.
* *The prefix rule is one-directional.* Authored `python3` on a host exposing
  only `python` reports `no discoverable PATH siblings`, because the probe
  matches `name.startswith(authored_argv0)`. The BUG record's own scenario is
  the covered direction, so this is a bounded-usefulness note, not a gap.
* *Only the reported names are bounded, not the directory read.* Each `PATH`
  entry is fully `listdir`-ed and sorted before the five-name bound applies.
  Measured cost on a real `PATH` is 1.3 ms on the refusal path only, so this is
  noted for completeness rather than as a concern.
* *`limit=0` would report one sibling,* because the bound is tested after the
  append. The parameter is keyword-only, internal and never passed by production
  code, so the default 5 is the only reachable value.
* *The bound test derives its expectation from the constant.*
  `test_sibling_probe_is_bounded` reads `DISCOVERABLE_SIBLING_PROBE_LIMIT`, so
  raising the constant survives while removing the enforcement is killed. An
  absolute assertion alongside it would pin the intended small value too.
* *`repository.resolve()` and the `PATH`-entry rooting are computed twice* on the
  refusal path, once in the probe and once in `resolve_executable`. Harmless, and
  noted only because that duplication is how the earlier narrow `except` tuple
  came to be copied in the first place.
* *The BUG record's line pointers are now stale.* `:35` and `:104` still read
  `src/workflow_coordinator/evidence.py:109-141` and `:109-184`; after `+47`
  lines `resolve_executable` is at `:153-192` and `prepare_evidence_commands` at
  `:195-237`. Both pointers sit in sections describing the 2026-10-30
  observation, so they are provenance rather than a current claim; reconciling
  them is optional maintainer upkeep.
* *The `_open.adoc` card is stale and out of scope.* `docs/backlog/_open.adoc:398-400`
  still reads "investigate actionable missing-tool/environment messages before
  selecting a correction". The overview is the maintainer's to update and is not
  in this WorkItem's scope, so it is reported here rather than changed. Its
  "never silently substitute `python3`" constraint remains honored.
