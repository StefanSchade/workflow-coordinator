=== Blocking Finding

*B1 -- Five cited repository facts are wrong.* The task's acceptance criterion
is that "every path, symbol, count and commit it cites was verified against the
repository", and the task names misattribution as the specific failure mode the
BP7 planning reviews hit. Five instances are reproduced below. Each is wrong as
written, each is a one-line correction, and none of them changes a scope path,
Hop budget, dependency, acceptance criterion, recommendation or decision -- so
this is a bounded accuracy correction, not a redesign.

. *"6 routes" is wrong under every consistent reading.* Section 3.2, criterion
  "Contract surface size": "the consumer compiler admits 2 programs, 5 distinct
  phases, 6 routes". Counting the two closed programs: 5 phase definitions
  (robust 4 + simple 1) -- which is the basis for the "5 distinct phases" figure
  -- but *7* route edges (robust `implement`→1, `broad_review`→2, `correct`→1,
  `focused_review`→2, simple `implement`→1) and *5* distinct route names
  (`accept`, `broad_review`, `correction`, `focused_review`,
  `renew_broad_review`). 6 is the robust-only edge count and is inconsistent
  with the phase figure beside it. This is the measurable baseline the ADR
  Commission is told to evaluate alternatives against, so it should be exact.
  (The adjacent claim that `finding_authority` values are drawn only from `()`
  and `('resolve',)` is exact.)
. *`prompt.py:138` is the wrong line, cited twice.* `finding_authority` occurs
  in `src/workflow_coordinator/prompt.py` only at `:140` (the assignment from
  `phase.review.finding_authority`) and `:154` (the projected text). Line 138 is
  a closing parenthesis. The citation appears in the section 1 reconciliation row
  for brief 3.3 and again in AD-4's evidence; both need `:140`.
. *"the eight marked maintainer-owned" undercounts its own table.* Section 2.3
  marks *nine* rows `maintainer-owned`: the six accepted BUGs, plus
  `BUG-WFC-CLAUDE-ADAPTER-WRITE-PERMISSION-MISMATCH`,
  `FTR-WFC-AGENT-PUBLIC-INTERNET-CAPABILITY` and
  `FTR-WFC-OPERATIONAL-PROVENANCE-PILOT`. The substantive claim that no proposal
  touches them is true for all nine.
. *BP4b's H010 focused review cannot have "returned accept".* Section 1, brief
  4.2(3) row: "`RUN-4b9a2863` (BP4b) ... stopped `autonomous_hop_budget_exhausted`
  immediately after its H010 focused review returned accept". The rendered
  profile for that very Run,
  `governance/commissions/wfc-beta1-bp4b-candidate-preservation-001/profile.yaml`
  lines 128-134, gives `focused_review` exactly two routes, `correction` and
  `renew_broad_review`; there is no `accept` route, and
  `beta_runs_facts.json` records only a per-Hop classification
  (`completed` versus `changes_required`), never a route. The supportable
  statement is that H010 was the first focused review in that Run not to return
  `changes_required`, after which the 10-Hop budget was exhausted. The point the
  row is making is unaffected -- arguably strengthened, since the program needs a
  further `broad_review` Hop to complete at all.
. *`14ee89c` did not add `src/workflow_coordinator/resources/roles/worker.txt`.*
  Section 2.3 / the brief 4.2(2) row reads "`14ee89c` added the ... paragraph to

=== Non-blocking observations

. *Three acceptance criteria compare against `HEAD` rather than the Run's base
  HEAD.* ADR criterion (f) (`git diff --name-only HEAD -- src tests governance`
  prints nothing), H1 criterion (c) and H3 criterion (c) all detect only
  *uncommitted* divergence. Once a Hop's work is committed by the Coordinator,
  they pass regardless of what was changed, so as written they cannot prove the
  property claimed ("no file under `src/`/`tests/` differs", "the reducer
  negatives are unmodified"). Phrasing them against the Run's base HEAD, e.g.
  `git diff --name-only <base_head>..HEAD -- ...`, makes them genuinely
  checkable. The exact-leaf `trusted_commit` reconciliation already enforces
  scope far more strongly than any of these three commands, so nothing is
  actually unguarded. Related: `git diff --name-only` prints path names, so H3's
  "only additions appear" cannot be observed from that command, and H1's "fails
  on `git stash`-reverted product code" names a mutating Git operation an agent
  may not run -- "fails without the product change" states the same
  mutation-sensitivity requirement without prescribing a forbidden mechanism.
