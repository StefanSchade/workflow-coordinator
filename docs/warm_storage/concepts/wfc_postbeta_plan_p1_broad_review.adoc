=== Blocking Finding

*Proposed new Finding (local label B2 in this record; no run-local ID is
allocated by me) -- four claims are attributed to sources that do not state
them, and one archive count is wrong.* The task's acceptance criterion is that
"every path, symbol, count and commit it cites was verified against the
repository", and the task names misattribution as the specific failure mode of
the BP7 planning reviews. Items 2 and 3 each appear at four separate sites and
each is load-bearing for a conclusion the maintainer is asked to act on. Items
1 and 4 are local. None of the five changes a scope path, Hop budget, severity,
shortlist entry, recommendation or decision, so this is again a bounded
accuracy correction.

. *"one to four correction cycles" is wrong; the archive shows one to three.*
  Section 0.1 (file lines 101-106), which the plan calls "the empirical basis
  for every Hop budget", says of the eight completed Runs not accepted at
  their first review: "The other eight needed one to four correction cycles,
  each cycle costing two Hops." Counting `correct` phases in those eight Runs
  gives `1,1,1,2,2,2,2,3` -- maximum *three*, in the 9-Hop `RUN-d0883c96`.
  Four correction cycles occur exactly once in the archive, in `RUN-4b9a2863`
  (BP4b), which is `awaiting_human_budget`, not completed, and therefore not
  one of "the other eight". H1's own budget rationale states the BP4b figure
  correctly, so section 0.1 contradicts the section that uses it. Related and
  in the same sentence: one cycle costs two Hops *plus* the renewing
  `broad_review` Hop -- the observed sequences are `IBCFB` (5), `IBCFCFB` (7),
  `IBCFBCFB` (8), `IBCFCFCFB` (9) -- so "each cycle costing two Hops" does not
  account for the printed totals.
. *`tests/unit/test_consumer_compiler.py:233-238` does not establish that a
  scope may not overlap `governance/`.* The plan makes that claim at four
  sites: the brief-3.3 reconciliation row ("A consumer scope may not overlap
  `governance/`"), the brief-4.2(4) row ("`governance/` is maintainer-owned
  Consumer-Config territory: a Commission scope may not overlap it ... Any
  removal under `governance/` is therefore a maintainer action"), H2's scope
  cell ("*`governance/` is read-only for this Commission:* a Commission scope
  may not overlap it"), and the dependency table's H2 basis ("`governance/`
  edits are maintainer-only per `test_consumer_compiler.py:233-238`").
  `test_consumer_compile_rejects_scope_overlapping_governance_dir` passes a
  request scope of `.wfc/commissions` against a fixture config whose
  `governance_dir` is `.wfc/commissions` (`test_consumer_compiler.py:112-124`),
  and the refusal it triggers is `commissioning.py:305-308`, which tests the
  *configured* `governance_dir` and the guidance path -- not the tracked
  `governance/` tree. In this repository `.wfc/config.yaml` sets
  `governance_dir: .wfc/governance`, and `frontdoor/init.py:31` makes
  `.wfc/governance` the product default, so `governance/` is never the
  Consumer-Config governance directory. The conclusion is nevertheless true
  here, by a different and stronger mechanism the plan does not cite:
  `.wfc/config.yaml` declares `work_item_scope_ceiling: [src, tests, scripts,
  docs]`, enforced at `commissioning.py:301-302` ("Consumer Request scope
  exceeds the Consumer Config work-item scope ceiling"), so no Consumer Request
  in this repository can name a `governance/` or `project_memory/` path at all.
  Section 5.2 item 8 states the wrong reason for the same correct conclusion.
. *`FTR-WFC-FRONT-DOOR-PHASE-ENTRY-CONTINUATION` does not reject a free
  initial-phase field; its `Next action::` recommends that shape.* The plan
  says so at four sites: the AD-6 evidence row ("records the gap and explicitly

  broad-review entry" appears in the record. The statement is true and
  verifiable, but it belongs to `docs/backlog/_open.adoc:567-571`: "neither a
  free initial-phase field nor the third review's derived broad-review entry is

  implementation." (`beta1_productization.adoc:117-119` carries the same
  "derived broad-review entry" item.) As written, a maintainer checking H4's
  dependency against the FTR finds the opposite of what the plan reports; the
