subprocess, and all verification used real `git`. *The real Evidence

Per mode (`local`, `commit`, `discard`), fresh archive::

* `git rev-list --count <before>..HEAD` == *1* -- one commit per Attempt;
* `git diff-tree -r HEAD` touches only paths under
  `archive/unclassified/<attempt>/`;

  `audit.json`, `manifest.json`, the per-Attempt `.gitignore`, `run/**` and

== Non-blocking observations

Recorded here and in the Hop summary only. None is a Finding.

. *Two of the five mutants are detected through a collateral failure mode
  rather than through the semantic assertion the test also carries.*
  Mutation 2 makes the `commit`-mode resume fail with the trusted-commit
  layer's own `unexpected dirty path` refusal rather than, as `F001`'s prose
  predicted, reporting `ARCHIVED` with a partial commit; mutation 4 makes the
  mutant raise `FileNotFoundError` instead of the structured refusal. In both
  cases the test *does* fail against the mutation, which is exactly the
  acceptance standard ("a test that fails against a mutation of the guarded
  behavior"), and both tests additionally assert the semantics that matter --
  the full per-mode tracked set including `manifest.json`, `run/**` and
  `ops/**`, and the refusal message -- so an exit-0 variant would also be
  caught. Worth knowing when reading the tests, not a defect.
. *The new `discard` crash-resume test asserts only that `git status
  --porcelain` is non-empty* at the crashed-but-not-committed point, where
  the analogous `local` test asserts something about the reported paths. This
  Hop's own reproduction checked the stronger property directly (the placed
  `audit.json` is specifically absent from `git ls-files`), and it holds. A
  future tightening is optional, not required by any acceptance case.
. *The four non-blocking observations carried by the `H002` broad review
  remain open by design and remain non-blocking*: the legacy `None` path
  reporting `ALREADY UP TO DATE` against a retention-aware destination
  (operator error the limitations record already warns against), mode-switch
  refusals naming a structural rather than the real cause, `wfc init`'s
  bootstrap commit not being rolled back on failure, and the environment-bound
  test families. The correction neither addresses nor worsens any of them,
  and acting on them is outside this Commission.
. *Pre-existing style, untouched by the correction*: one assertion in
  `LocalRetentionTests::test_only_audit_json_and_gitignore_are_tracked_and_raw_files_are_on_disk`
  uses a bare `assert` rather than `self.assertEqual`, so it would vanish
  under `python -O`. The project does not run tests under `-O`; noted only
  for completeness.
