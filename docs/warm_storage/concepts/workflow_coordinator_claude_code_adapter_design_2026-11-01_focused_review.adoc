== 1. Disposition

Outcome:: `changes_required`
Route:: `correction`

The H007 correction resolves the concrete qualification defect reported in the
previous rereview.  Section 7 now uses three isolated, separately authorized
pinned-CLI processes: ordinary success, startup sandbox unavailability, and a
post-start sandboxed-command refusal.  It does not use success as evidence of a
failure state and does not prescribe exit status or wrapper presence for either
failure scenario (`design:245-251`).  The bounded WorkItem acceptance criterion
now requires those states to be observed separately (`design:259-265`).

F002 nevertheless remains open because the whole-design regression found one
remaining instance of the prohibited outcome assumption.  The model/effort row
says that availability of every pair is unverified, but then requires an
unavailable pair to “surface as a nonzero transport failure” (`design:83-84`).
Neither the installed CLI help nor the cited CLI interface establishes that a
provider-side availability rejection must produce a nonzero process status.
This conflicts with the corrected general rule that the adapter classifies
only observed process facts and that a zero status proceeds to wrapper decoding
and fail-closed validation (`design:164-166`).

The bounded correction is textual: replace the nonzero prediction with a
requirement that an unavailable selected model/effort pair fail closed, while
the pinned-CLI qualification records its actual process status and wrapper
behavior.  A nonzero observation is rejected as transport; a zero exit without
a successful structured result is rejected by wrapper/candidate validation.
Do not add retry, fallback-model behavior, a model router, or a provider-error
oracle.

The inspection and checks recorded here are reviewer-side diagnostics.  They
do not replace Coordinator-owned `task-check` evidence.

== 3. Finding disposition

=== 3.1 F002 -- observable provider outcomes

Severity:: *BLOCKING.*
Disposition:: *OPEN; one bounded correction remains.*

Invariant:: The adapter design must classify only observable provider process
and wrapper facts as transport outcomes.  A provider-side tool refusal must
remain fail-closed without being promoted to a guaranteed nonzero exit when the
documented CLI can continue.

==== 3.1.1 H007 correction accepted

The prior qualification counterexample is resolved:

. The smoke is now a suite of isolated processes rather than one process asked
  to exhibit mutually exclusive startup and post-start states
  (`design:245-249`).
. Startup unavailability records actual status and any wrapper; post-start
  refusal records actual status/wrapper and proves no unsandboxed retry
  (`design:248-249`).
. Neither failure scenario prescribes nonzero or wrapper presence, and ordinary
  success is explicitly excluded as evidence for either (`design:251`).
. Fake coverage still includes nonzero-with-valid-JSON,
  timeout-with-partial-JSON, malformed/absent output, correlation mismatch, and
  zero-exit post-refusal behavior without manufacturing a transport failure or
  tool oracle (`design:241`).

This part of the H007 correction is implementable, minimal, and consistent with
the runtime classification and failure table (`design:166,218-231`).

==== 3.1.2 Remaining counterexample

The design correctly marks model/effort availability as unverified, but then
states that an unavailable pair “must surface as a nonzero transport failure in
later smoke” (`design:84`).  Local help proves flag syntax only.  It does not
prove whether a selected but unavailable model is rejected by a nonzero exit,
a zero-exit error wrapper, or another fail-closed provider result.

This is not harmless wording.  The implementation and qualification plan must
not convert a desired failure into an invented process observation.  The same
design already supplies the sufficient provider-neutral behavior: observed
nonzero or timeout is rejected before candidate parsing; zero proceeds to
wrapper extraction; and absent, malformed, unsuccessful, or semantically
invalid structured output cannot be accepted (`design:23,146-154,166,218-225`).
No nonzero guarantee is needed.

==== 3.1.3 Required correction

Correct the final sentence of the model/effort row (`design:84`) so that:

. an unavailable selected model/effort pair must fail closed and must never
  trigger `--fallback-model`, automatic replay, or binding substitution;
. later pinned-CLI qualification records actual process status and wrapper
  behavior rather than requiring nonzero; and
. rejection follows the existing gates: observed nonzero/timeout is transport
  failure, while zero without a successful valid structured candidate fails
  wrapper or semantic validation.

No production, test, governance, schema, Runtime, Evidence, programme,
telemetry, registry, router, or fallback change is needed in this design Hop.
This is new material evidence on existing Current-Run Finding `F002`, whose
first clause already governs all provider process/wrapper classification; it is
not a new Finding.

Current-Run Finding `F001` remains resolved.  H007 changed only the real-smoke

managed-policy exposure.  The closed argv/settings/environment profile and the
provider-control-versus-OS-boundary distinction remain intact
(`design:106-144,205-209`).  No F001 disposition change is proposed.
