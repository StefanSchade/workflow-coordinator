This record does not propose, and must not be read as proposing:

* blanket deletion of any existing test;
* bulk migration of historical Commission/profile fixtures;
* weakening the gate-only required-evidence invariant from
  Evidence-Failure-Disposition-Hardening; or
* a new Front Door framework or authoring mechanism.

It explicitly affirms that `fb62262` (2026-10-10,
`WI-WFC-EVIDENCE-FAILURE-DISPOSITION-HARDENING-INTEGRATION-CLOSURE` H001) was
a *justified preservation of historical inspection coverage* -- adapting
historical admission assertions so they continue to exercise old-version
parsing/replay correctly -- and was *not* an authorization to weaken the
newer gate-only required-evidence invariant it coexists with. Any future
corrective work must preserve both: the invariant, and genuine historical
provenance/reproducibility coverage.
====

== 1. Why this record exists

2026-10-21 planning decisions §6 reframes Front Door Stage 1 as "make today's
workflow legible and reproducible first" and explicitly asks for "small
missing pieces" to be recorded "based on evidence from actually trying to
reproduce Stage 1 end-to-end," rather than assuming new authoring software is
needed. While exercising that workflow, the governing architecture-test
module for self-development governance was observed to have grown into a
large, still-growing, per-Commission regression suite whose long-run
performance and maintenance characteristics have not yet been assessed
against Level-0 MVP needs.

This is recorded as a Stage-1 dogfooding finding, not as a P3.5/P4/P5 item
and not as a new BUG defect: nothing observed here is a known-incorrect
behavior. The concern is sustainability and scaling of the *test authoring
pattern itself*.

== 2. Evidence

* `tests/architecture/test_self_development_governance.py` is currently
  7,731 lines and contains 44 pytest tests, of which 39 are
  Commission-specific (named after, or asserting admission/replay facts
  about, one specific historical Commission/WorkItem).
* The module contains 42 calls to a shared `_materialize_bundle()` helper.
  Each call materializes a temporary Git repository using six Git
  subprocesses, i.e. at least 252 Git subprocesses for one full execution of
  this module alone.
* The file has accumulated 51 modifying Git commits.
* It is exercised by the normal `pytest` suite, including WFC's own repeated
  trusted-review evidence gates (every gate-review phase that requires
  `pytest` evidence re-runs this module in full).
* Individual historical Commission assertions currently run against the
  *current* production preflight and the *currently checked-out* governance
  files. This couples old, closed Commissions' test assertions to ongoing
  governance changes, creating a potential unintended forward-compatibility
  obligation: a correctly-motivated future governance change could require
  touching many old, already-closed Commission tests merely to keep them
  green, independent of whether those tests still protect anything load-bearing.
* On 2026-10-10, commit `fb62262` deliberately adapted historical admission
  coverage after Evidence-Failure-Disposition-Hardening landed. Per §1 above,
  this was a justified preservation of historical-inspection coverage, not a
  precedent for loosening the gate-only required-evidence invariant itself.

== 3. Bounded investigation scope

A future, separately authorized, bounded investigation (not authorized by
this record) should cover at least:

. Measured performance contribution of this module and how it scales with a
  growing number of historical Commissions, including the cost of repeated
  WFC review-gate re-execution (not just a single standalone run).
. A classification of the module's existing tests into: reusable
  behavioral/security regressions; explicit, supported legacy-compatibility
  tests; and tests whose value was one-time Commissioning validation only.
. Whether creating a permanent, bespoke pytest test for every Commission is
  itself a justified standing practice, or whether it should be bounded
  going forward.
. Historical-evidence and reproducibility requirements, with old-version
  parsing/replay of a closed Commission's history kept explicitly distinct
  from admission of a *new* launch under current governance.
. A lean Stage-1 procedure for validating and retaining Commissioning
  evidence that does not require an unbounded, O(number of historical
  Commissions) permanent pytest test burden.
. If, and only if, the above analysis justifies action: minimally invasive
  corrective options and their acceptance criteria. Essential safety tests
  and historical provenance must be preserved by any such option.

== 4. Non-goals (restated)

* No blanket test deletion.
* No bulk profile/fixture migration.
* No weakening of the gate-only required-evidence invariant.
* No new Front Door framework or authoring mechanism.
* No implementation Commission is authorized by this record.
