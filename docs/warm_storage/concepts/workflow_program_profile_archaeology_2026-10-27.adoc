= Workflow-program profile archaeology

Status:: Assessment candidate -- evidence survey, not architecture authority

This read-only survey classifies present profiles and recorded history. It does
not select a Front Door architecture, DSL, binding grammar, migration, P3.5
guard, or Level-1 implementation. The functional, semantic and technical model
records and working briefs are DRAFT/NON-AUTHORIZING under docs/README.adoc;
they supply comparison questions, not settled requirements.

== Method and limits

The reproducible inventory command is find governance/self-development -name
'*-profile.yaml' | sort, followed by direct YAML inspection and resolving every
WorkItem profile_ref. It finds 46 current profiles, all schema_version: 2. Each
has a paired task (governance/work-items/<stem>-task.txt) and dedicated policy
(governance/self-development/<stem>-policy.yaml), except standalone below. The
parser and model define their actual meaning: workflow_profile_from_yaml
(src/workflow_coordinator/serialization.py:650-978), WorkflowProfile, Phase,
Route and ReviewDescriptor (src/workflow_coordinator/model.py:222-276).

“Topology equivalent” means only the same directed phase/route graph after
renaming. “Semantic equivalent” additionally requires the same roles, review
descriptor (authority, breadth, context, blocking policy and Finding
authority), evidence/failed-evidence obligation, durable-artifact rule, and
scope/action capability. No common shape is claimed semantically equivalent
unless stated.

The external selected Run Ledger was accessible at
../workflow-coordinator-run-evidence/project_memory/run_ledger.adoc. Its
introduction says it is a curated selected-Run index, not complete code or
launch history: an entry supports recorded use, silence does not prove non-use.

F4 is worker -> independent review -> complete or correction -> rereview ->
complete or correction. It is topological equivalence only. F2 is correction ->
rereview -> complete/correction; F3 begins at review; both are continuation
states, not evidence of distinct reusable programs. F5 differs: clean first
review goes to rereview rather than complete (standalone profile review.routes).

All reviews are gates with trigger profile_selected and exit declared_route;
normally blocking_policy blocking_only and fresh context. This does not erase
semantics: projected-result-contracts-p1-profile.yaml gives independent_review
Finding authority []; P3 gives [resolve]. The first cannot close its own
current-Run Finding; the latter can. Required evidence is also enforced:
_admit_evidence_disposition (operator.py:123-136) rejects evidence on a
non-gate review or without failed_evidence_route. F4 is therefore not semantic
equivalence.

Phase scopes/actions, WorkItem scope/task/hop budget, policy ceiling, review
purpose, evidence choice, and durable output destinations are present
Commission values. Compare P3 source/test scope with the document-only scope
in docs-architecture-consolidation-design. Whether any are future parameters is
unresolved.

=== Interpreter, test-only and historical material

The interpreter supports profiles v2/v3 (serialization.py:670-978). The model
has convergence plus convergence_role, normal_correction_route and escape_route
(model.py:243-276). All 46 live profiles are v2: no live
convergence-bearing profile. V3 requires five corrector/evaluator/diagnosis/
reframe/strategy-gate roles and constrains routes (serialization.py:840-978).
tests/fixtures/convergence_curriculum.yaml is a material test fixture, cited
by tests/architecture/test_self_development_governance.py:462 and S4 scope.
It is implementation/test evidence, not a current profile or actual consumer
Run. Schema-3 policies do not make their profiles v3.

The architecture test is also an explicit historical-fixture consumer, not a
new-launch census. Its _preflight wrapper (lines 32-57) first requires the
current evidence-admission failure, then suppresses only that predicate so
archived standalone bundles remain structurally inspectable. The test constants
at lines 59-122 retain older standalone WorkItems, and lines 122-140 retain
the old immutable-finding-echo profile. The removed, historical
governance/self-development/immutable-finding-echo-profile-002.yaml is still
materialized from commit 3e937cf by its paired test; it is schema 2, revision
1, F4, has reviewer authority [], and was a dedicated successor Commission.
It must not be counted as one of the 46 present profiles or treated as
new-launch-admissible merely because the test reads it.

Preflight parses pinned WorkItem/profile/policy/components and checks profile
reference, role bindings, scope/actions, durable artifacts, A1 and evidence
admission (operator.py:_preflight, _admit_a1, _admit_evidence_disposition,
lines 123-190 and 281 onward). This is current implementation, not a program
catalogue or separate Commission-binding object.

== C. Historical archaeology

53d0109 introduced standalone's four-phase profile. 0ba506c changed
review-artifact identity/scope, and cb41c8b deliberately changed clean review
to rereview rather than complete; git show of each commit and the current
standalone routes verify this. Per-Commission bundles later arrived at ef8a4d0
(design), 272e2b2 (S1), 68979eb (S2), 6db337a (S3), 6720c31 (S4), and d03cd2b
(P1). This supports copy/adaptation pressure, not a product-versioned family.

Git history search found no profile field or phase final_review. Broad/focused
are ReviewDescriptor.breadth values, not final phases. The evidence supports
only broad-first/focused-rereview in particular profiles and the committed
standalone route change. It is insufficient to claim a broad/final phase
appeared/disappeared, or that it was deliberate program design rather than
copied Commission YAML.

Finding authority changed materially: P1 and several S1-S3 profiles use [];
P3, later S4, docs/P2/P3.5, standalone and this profile use [resolve].
This alters whether an independently opened blocker can be closed. 9b98c99
("close persona binding review minors") is supporting history, not proof of
every later policy rationale.

The accessible ledger records accepted convergence implementation work and
ordinary positive correction/review Runs, but no entry identifies an actual
schema-v3 escape. Combined with no live v3 profile, the result is
“implemented/tested; actual escape exercise not established,” not non-use.

== D. Governance implications

The reducer rejects COMPLETE while an open blocking Finding remains
(src/workflow_coordinator/reducer.py:1164-1173). That is a completion-safety
guard. It is not the proposed P3.5 GOTO guard: Route has only effect, target,
question and supervisor (model.py:235-240), not
require_no_open_blocking_findings. The latter is unimplemented and untouched.

* [resolve] versus [] changes whether an F4 reviewer can close its own blocker;
  compare P3 and P1 exact independent_review fields.
* failed_evidence_route correction makes failed required evidence repairable and
  is enforced by preflight, not merely prompt prose.
* A correction can carry an unresolved blocker into a reviewer with accept
  complete; COMPLETE is stopped, but recovery depends on later disposition.
  F2 exposes this carried-Finding case; checking only openers is inadequate.
* Scope/action compose with independent policy ceilings; treating source-write
  scope or commit as generic presentation changes authority.

The P3.5 open row defers implementation behind Front Door
(docs/backlog/_open.adoc rows 140-145). Its 43/0 historical result is design
evidence, not a present validator or migration requirement. Universal versus
existential reachability remains a maintainer decision.

== E. Reuse hypotheses and prerequisite evidence

F4 is the strongest candidate reusable topology, not a proved semantic family:
its instances differ in Finding authority, review purpose/breadth, evidence
routes, scopes/actions and outputs. F2/F3 are continuation states. V3
convergence is a candidate distinct source/fixture family, not deployed.
Privileged, protected-context and simple-task remain scenario hypotheses.

Likely Commission values include task, scope, artifact destinations, policy
ceiling, review question, evidence choice and phase scopes/actions.
Counterexamples are Finding authority, evidence-failure route, phase/route
structure and mandatory defensive review: they carry guarantees and cannot be
assumed safe parameters. Model-binding granularity is explicitly open in the
functional model (section 2, lines 54-56).

Before Front Door refactoring, collect:

* Pairwise compare every review/evidence/Finding/scope/action/artifact/policy
  field of two F4 candidates and identify guarantee-preserving variation.
* Recover full diffs and archived Run evidence for any final/broad-review
  chronology claim; current history does not establish it.
* Separate present files, historical fixtures, launch-admissible Commissions
  and actual Run use; selected ledger cannot answer this exhaustively.
* Demonstrate one Commission selecting a fixed reusable revision without graph
  copying while retaining pinning, policy, evidence disposition, replay and
  completion safety. This is evidence to request, not a migration.
* For v3, connect a current admitted profile and Run to an actual escape, or
  retain test-only implementation status.
* Escalate—not decide—ownership/versioning/admission, binding variation,
  protected-context egress, defensive review and Level 1. Recursive WFC,
  LangGraph and other outer loops remain unresolved (functional model section
  5; semantic model section 6).
