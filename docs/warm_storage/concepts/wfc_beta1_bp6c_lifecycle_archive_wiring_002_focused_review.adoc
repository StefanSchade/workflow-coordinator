=== Blocking: `wfc run`/`wfc resume` never print anything in any test

Acceptance 1 requires a completed Run's consolidated *report printed*;
acceptance 4 requires a *loud `ARCHIVE SKIPPED` line*; `Deliver` item 1(d)
requires the step to "print the consolidated report (text) built from the
audit". Both are implemented in `lifecycle._print_postrun_notice`
(`lifecycle.py:1020-1027`), called only from `cmd_run` (`lifecycle.py:1046`)
and `cmd_resume` (`lifecycle.py:1060`).

No test in the repository invokes `wfc run` or `wfc resume` through the CLI.
Every assertion about the printed material reads the `LifecycleResult`
dataclass field instead (`postrun_report_text`, `postrun_notice`:
`test_postrun_lifecycle.py:224`, `:261`, `:380-382`, `:421-422`,
`:464-465`, `:498-499`, `:538`); the only `capsys` test in the file is for
`cmd_status` (`:641`). Reproduced consequence -- mutation *D5*, replacing
the whole body of `_print_postrun_notice` with `return`, leaves
`test_postrun_lifecycle.py`, `test_postrun_archive.py`,
`test_lifecycle_controller.py`, `test_lifecycle_crash_matrix.py` and
`test_preservation_lifecycle.py` entirely green. An operator would then see
*no* report after a successful archive and *no* skip line when the Evidence
repository is absent -- the opposite of "loud" -- and nothing would fail.

The product itself is correct: a three-test probe driving the real
`cli_main(["run", ...])`/`cli_main(["resume", ...])` with the repository's
own fake engine/provider fixtures confirms `wfc run` prints the
consolidated report (`WFC RUN` header), prints `ARCHIVE SKIPPED` when the
Evidence repository is absent, and `wfc resume` reprints the report on the
idempotent repeat. That same probe fails on all three tests under mutation
D5, so the gap is closable with additive tests only.

=== Blocking: acceptance 5's privacy-guard refusal is never exercised

Acceptance 5 names two triggers -- "archive/audit failure *or privacy-guard
refusal*". The delivered suite covers three archive failure shapes
(destination conflict, non-writable Evidence repository, unresolvable
default location: `test_postrun_lifecycle.py:397`, `:449`, `:479`) and
pins their reason codes exactly. No test reaches a `ProjectionError` from
the audit privacy guard, or an `AuditError`, through the installed
lifecycle, so two branches of `postrun._reason_code_for`
(`postrun.py:125-128`) are unreached: mutations *D1*
(`privacy_guard_refused` -> `archive_refused`) and *D2*
(`audit_structural_error` -> `archive_refused`) both survive the whole BP6c
suite.

The product is correct here too. Driving the real lifecycle with
`getpass.getuser()` returning `fake` -- a whole token of the Run-derived
Attempt identity `consumer-repo-run-fake-engine`, which is exactly how the
guard refuses in production -- yields `CLASSIFICATION: completed`, exit
*32*, `ext.archive.refused {"reason_code": "privacy_guard_refused"}`, the
notice `ARCHIVE FAILED (privacy_guard_refused): privacy guard refused
projection at attempt_id` (no path leak), a clean Evidence repository, and
`wfc resume` archiving exactly once after the cause is removed. That
one-test probe is killed by mutation D1, so again additive tests close the
gap.

=== What this pass independently confirmed as correct

* *Idempotency and crash resume (6).* I1/Y1 killed; the delivered tests
  pin one `ext.archive.result` record and an unchanged Evidence commit
  count across a repeat `resume`, across a crash after the archive commit
  but before the result record (outcome `no_op`, no second commit) and
  across a crash after the intent record but before any archive.
* *Run-derived identity, two Runs, one Evidence repository (13a).* The
  delivered test uses the same `repository_name` in two distinct checkouts
  with distinct Run ids and one shared Evidence repository, asserts two
  distinct destinations each with its own `audit.json` carrying its own
  `run_id`, and no second commit on repeated resume of either. I2 and I3
  are killed, so the identity is pinned as Run-derived and not state-root-
  derived.
* *Stopped Runs reported truthfully (2).* X2, X3 and E2 are all killed: a
  `stopped`/`awaiting_human`/`awaiting_human_budget`/`reconcile_required`/
  `interrupted` Run is archived, its own classification lands in the audit,
  and the BP4a exit code is never replaced by 0.
* *No archive without engine state (3).* Enforced twice over --
  `_ARCHIVABLE_CLASSIFICATIONS` and the `not run_id` guard (the `classified`
  record for `engine_exited_before_state` carries `run_id: None`,
  `lifecycle.py:730-733`). X1b, which removes both, is killed.
* *Read-only `wfc status`, no STATE mutation (8).* T1/T2 killed; the
  delivered tests compare the whole journal before/after
  `status_lifecycle`, the Evidence HEAD, and every byte of every file under
  the engine state root across `status` + a repeat `resume`. For the product
  path the OPS candidate (`~/wfc-ops/<attempt_id>`) never exists, so there
  is no OPS directory to mutate.
* *Privacy fix without weakening the real-leak refusal (11).* P1, P2, P4
  and P5 are all killed, from both directions and at both the
  `audit._string_violation` boundary and the `archive._attempt_private_strings`
  boundary.
* *Attempt-identity sanitisation.* `postrun._attempt_identity` maps
  everything outside `[a-z0-9._-]` to `-`, so no separator, control
  character or NUL can reach a destination path component, and
  `archive.validate_explicit_attempt_identity` additionally requires a
  leading `[a-z0-9]`, which rejects `.`/`..`-shaped values. A sanitisation
  collision between two different inputs is a refusal (`archive destination
  already exists with different content`), never a silent overwrite.
* *Limitations record (14).* Covers what the step proves and does not, the
  Run-derived identity, the envelope-cache/OPS distinction, Evidence as a
  destination and not a state root, `local` raw files not being backed up
  by Git, no push, `ARCHIVE SKIPPED` semantics, retry via `wfc resume`, the
  additive exit code and BP7's exclusion.

=== Non-blocking observations (no Finding)

. *I4* -- deriving the Attempt identity from the Run id alone, dropping the
  `repository_name` component, survives. Decision (a) calls
  `<repository_name>-<run_id>` a "suggested shape" and acceptance 13a only
  requires the identity to come from the Run identity and never from the
  state-root directory name, which still holds; Run ids are globally unique,
  so no collision follows. Outside the acceptance list.
. *X1* is an equivalent mutant, not a gap: the `not run_id` guard
  independently blocks `engine_exited_before_state`. X1b, the only
  non-equivalent form, is killed.
. *E3* -- `ARCHIVE_FAILED_EXIT_CODE` can be changed to `13` (the pinned
  `stopped` value) with the suite green, because the refusal tests compare
  against the symbol rather than the number and nothing asserts the new code
  is disjoint from `EXIT_CODES.values()`. The delivered value 32 *is*
  unused and documented, so acceptance 5 holds as shipped; a one-line
  disjointness assertion would pin "additive" itself. Recommended alongside
  the corrections above.
. *N1* -- removing the `ext.archive.intent` append survives. The record is
  required by `Deliver` item 2 and is written correctly; only its presence
  on the success path is unpinned (the negative assertion for
  `engine_exited_before_state` exists at `test_postrun_lifecycle.py:345`).
  Not named in the acceptance matrix.
. *R2* -- hardcoding `"retention": "local"` in the `ext.archive.result`
  record survives, even though acceptance 9 runs all three modes: the mode
  tests check `git ls-files`, and the one assertion on the recorded value is
  in the `local` `cmd_status` test. The pass-through that actually governs
  retained bytes (R1) is killed, so the retention property itself is pinned;
  what is unpinned is the truthfulness of the reported field in `commit`
  and `discard` mode.
. *P3* -- removing `_PATH_COMPONENT_RE` from
  `audit._whole_component_or_token_match` survives, because `_TOKEN_RE`
  already splits on `/` and `\`. The path-component split is still
  load-bearing for an OS user name containing a non-word character
  (`first.last`, `svc-ci`), where only it produces the matching piece. The
  acceptance list names short word-only examples (`ci`, `ops`), both pinned,
  so by the task's edge-case rule this is an observation rather than a
  Finding -- but the one-line test would be cheap.
. The `ops`-as-a-whole-token rule means a consumer whose `repository_name`
  shares a hyphen-delimited token with the OS user name (user `ops`,
  repository `ops-tools`) still refuses every archive. This is the specified
  behaviour ("whole token"), explicitly pinned by
  `test_audit_user_name_match.py:38` (`owned-by-ops-today` matches), and it
  errs toward refusing rather than leaking. Noted only so a future reader
  does not read it as a regression of the BP6b observation.
