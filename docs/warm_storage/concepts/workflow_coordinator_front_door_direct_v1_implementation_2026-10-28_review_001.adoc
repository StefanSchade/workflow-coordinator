== 3. Blocking requirements

=== B1 -- derive the WorkItem repository from pinned policy identity, not the checkout basename

Invariant:: Rendering must be a deterministic projection of the Intent and
the pinned program/policy/component source objects.  `WorkItem.repository` is
a logical identity admitted by `RepositoryPolicy.scope`; it is not the local
filesystem directory name.

`render_commission` currently emits `repository: repository.name`
(`commissioning.py`, line 353).  A disposable probe rendered the same Intent
and the same source commits once in this checkout and once in a clone named
`renamed-checkout`.  The WorkItems contained `workflow-coordinator` and
`renamed-checkout` respectively, and both the WorkItem bytes and render
manifest bytes differed.  The second value is also outside the pinned basis's
`scope: [workflow-coordinator]`; `_preflight` happens not to call `new_run`, so
the candidate's round-trip test does not expose that later logical-identity
failure.

Correction requirement:: deterministically select and validate the logical
repository identity from the pinned policy basis (for this basis,
`workflow-coordinator`) and add a renamed-checkout regression proving byte-
identical projection and a WorkItem repository contained in policy scope.

=== B2 -- verify the complete immutable policy-basis record

Invariant:: `repository-standard@v1` is an immutable closed source.  A pin to a
same-ID/revision but changed object must be refused before rendering; the only
per-Commission policy change is narrowing `work_item_scope_ceiling` to the
Intent scope.

The program object is checked against a complete literal record, but the
policy object is accepted after checking only ID/revision and the one
`task-check` command (`commissioning.py`, lines 283--292).  Rendering then
copies every other basis field, including repository scope, governance paths,
hop ceiling, actions, and all evidence commands (lines 344--350).  Therefore a
historical or locally introduced source object with the same identity and
correct `task-check`, but widened actions/scope, changed governance paths, a
higher hop ceiling, or an extra command, is treated as
`repository-standard@v1` and projected.  That defeats the immutable-basis
check and lets a user-selected source pin change fields the Intent is
forbidden to author.

Correction requirement:: validate the entire supported policy-basis semantic
record before using it, then test a same-ID/revision source-object mutation
which preserves `task-check` but changes another basis field.  It must fail
before any rendered-tree comparison or `_preflight` call.

=== B3 -- make the `--check` report show the effective evidence command

Invariant:: Design section 3.3 and the task require the render report to show
effective evidence commands with their `policy` provenance, so a maintainer
can inspect what will actually run rather than only the program's command
reference.

`_commission_report` prints each phase's evidence-name list, labelled
`program`, but never prints the selected policy command's argv or timeout
(`scripts/wfc_op.py`, lines 103--117).  For `task-check-v1`, the report thus
shows `task-check` but omits `python -m pytest -q` and `900` seconds.  The
committed CLI test uses the `none` profile and asserts only that the authority
label is present, so this omission is not exercised.

Correction requirement:: report every effective selected command definition,
including argv and timeout, as a `policy` fact; add a `task-check-v1` CLI
assertion for those values and their provenance label.

=== B4 -- implement the mandated minimum acceptance-test matrix

Invariant:: The acceptance matrix is a required deliverable, not optional
future hardening.  It must make each closed-program and equivalence property
independently falsifiable.

The candidate adds three commissioning tests and one CLI test.  Important
required cases are absent:

* exact field-for-field equality of both rendered phase records, rather than
  assertions for only evidence placement, one failure route, and absence of a
  reviewer;
* widening/omission attempts for scope, actions, artifact mapping, review
  descriptor, components, failure route, and each other named forbidden
  semantic class;
* policy and component source-object mismatch/tampering cases;
* proof that equivalence failures occur before `_preflight` is called;
* `commission render` without `--check`; and
* CLI refusal for a tampered rendered artifact and a tampered source pin.

The missing policy-source case would have caught B2, and a render in differently
named checkouts would have caught B1.  Correction must add the section 6/task
matrix without adding a permanent self-development-governance test or invoking
a provider.
