== 1. Disposition

Outcome:: `accept`
Route:: `accept`

The corrected architecture is a small, implementable one-invocation vertical
slice.  It uses one terminal Worker phase and one provider dispatch, makes the
same-invocation self-check an immutable Simple-only prompt component, reuses the
existing post-provider/pre-reduction trusted-evidence seam, and stops every
failure class without an agentic correction or verification invocation.

The F004 correction closes the last blocking provenance gap.  The design now
requires `render_commission` to enumerate the same role, modifier, and
repository-policy component categories that runtime `_selected_ids` already
loads.  The existing render-manifest digest generation and Front Door
pinned-blob comparison then cover the `simple-self-check` bytes.  The original
changed-modifier counterexample is required as a negative test before dispatch.

No new blocking Finding was found.  `F001`, `F002`, `F003`, and `F004` remain
resolved; this Hop proposes no Finding state change.

== 2. Independent adversarial method

This review did not treat the focused verdict or the passing task check as
semantic proof.  It re-walked the design against the current compiler,
preflight, prompt selection, strict result projection, provider transport,
trusted commit/scope boundary, evidence execution, reduction, Finding, Hop
budget, and recovery seams.  It attempted to construct failures in which:

* a terminal or recovery path dispatches a second provider invocation;
* a failed/timed-out provider leaves a valid candidate that is accepted;
* a Worker failure cannot be represented by the selected result family;
* evidence runs too late, is treated as agent testimony, or can be overridden;
* an open blocking Finding completes or requires an undocumented correction Hop;
* the Simple-only self-check is dispatched from bytes outside the pinned source
  object;
* an unauthorized path, untrusted commit, dirty evidence subprocess, or changed
  governing input is accepted; or
* the proposed exception broadens Direct-v1, Robust-v1, P3.5, schema, or Runtime
  behavior.

The Development source baseline named by the design remains the source baseline
for the reviewed code: the commits after it change only the design and its two
review artifacts.

== 3. Prior Finding verification

=== 3.1 F001 -- Worker-reported failure is representable

Disposition:: *Remains resolved.*

Simple selects existing generic routing v1 only for its exact closed terminal
shape.  That family projects `Outcome.FAILED`
(`src/workflow_coordinator/codex_adapter.py:197-205`), parses it strictly
(`serialization.py:1214-1287`), and persists the selected family/version before
reduction.  The reducer checks that identity (`reducer.py:1541-1581`) and stops
`FAILED` at `result_failed` before route or Finding proposals can act
(`:1660-1663`).  No Work-result widening or new technical schema is needed.

The design's sentence that only `completed` may _request_ `accept` remains a
wording imprecision: generic routing requires its sole `accept` route field on
all outcomes.  The enforceable property is that only a completing outcome can
have that route applied; failure, block, escalation, and changes-required guards
preempt route application.  The strict projection and proposed tests rely on
that safe behavior, so this is non-blocking.

=== 3.2 F002 -- failed transport controls a valid candidate

Disposition:: *Remains resolved.*

The design places the return-code/timeout guard immediately after
`adapter.execute`, before candidate validation, trusted commit, evidence,
`record_hop`, or reduction (`vertical.py:324-341` is the current insertion
boundary).  Raising the existing `ExecutionResultValidationError` enters the
no-replay uncertain-dispatch recovery in `run_real_one_hop`
(`slice4.py:332-354,390-399`).  The marker and charged uncertain H001 remain;
the candidate cannot complete, and no H002 is dispatched.  Separate nonzero-
with-valid-candidate and timeout-with-valid-candidate tests preserve the
original counterexample.

=== 3.3 F003 -- the self-check is mandatory in the one invocation

Disposition:: *Remains resolved.*

The closed programme selects `simple-self-check` as its sole modifier.  Its
specified text requires the Worker to self-check before its sole result and
does not grant evidence authority.  Prompt selection already includes role,
modifier, and repository-policy components (`model.py:243-254` and
`operator.py:107-112`).  Direct and Robust retain their unchanged shared Worker
selection.

=== 3.4 F004 -- every selected prompt component is source-pinned

Disposition:: *Remains resolved.*

The current mismatch is correctly identified: `render_commission` traverses
only role components (`commissioning.py:442-460`), whereas `_selected_ids`
traverses role, modifiers, and repository policy (`operator.py:107-112`).  The
corrected design changes only the renderer's existing traversal, retaining
first-reference ordering and feeding the complete set into the existing digest
and `sources.selected_components` producers.  The existing Front Door loop then
byte-compares each selected path at expected HEAD with the Intent's pinned
component source object (`commissioning.py:490-518`) before `_preflight`.

This defeats the concrete counterexample: a pinned component manifest plus a
changed expected-HEAD `simple-self-check.txt` now creates a selected-component
byte mismatch before provider dispatch.  Direct-v1 and Robust-v1 have empty
modifier and repository-policy lists, so the required byte-identical manifest
regression is precise.

== 5. Terminal and trust-boundary conclusions

The lifecycle is finite and enforceable with current primitives:

`admit -> dispatch H001 once -> trusted Git/scope observation -> trusted
evidence -> reduce -> COMPLETED | AWAITING_HUMAN | RECONCILE_REQUIRED`.

`COMPLETE` requires a valid correlated result, no controlling mechanical
anomaly, passing mandatory evidence, a legal terminal route, and no open
blocking Finding.  `FAILED`, `BLOCKED`, escalation, invalid result, commit/scope
fault, and evidence failure use existing human-stop semantics.  Provider
uncertainty uses the existing reconciliation state and retained marker.  None
of those states authorizes another Simple provider call.

The programme record declares the closed phase/components/evidence/routes; the
maintainer-authored Intent supplies task, scope, personas, bindings, and pinned
source objects; runtime preflight and reduction enforce the admitted shape and
mechanical facts.  Those layers remain distinct, as do capability identity,
programme revision, representation schema, and Runtime Git revision.

== 6. Acceptance boundary

This acceptance covers only the architecture and review artifacts.  It does
not authorize production source, tests, governance records, a new programme,
schema or Runtime promotion, P3.5, dogfood execution, cleanup, or a nested WFC
invocation.  The proposed implementation remains a separately authorized
WorkItem with the bounded scope in design section 11.

Coordinator-owned `task-check` is the trusted route evidence.  The source
inspection and review artifact are reviewer-side diagnostic evidence and do
not replace it.
