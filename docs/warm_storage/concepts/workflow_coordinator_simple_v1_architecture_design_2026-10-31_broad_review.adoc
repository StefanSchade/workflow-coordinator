== 1. Disposition

Outcome:: `changes_required`
Route:: `correction`

The correction genuinely resolves the three earlier blockers.  Generic routing
v1 can represent Worker-reported failure; failed provider transport is made
controlling before candidate-dependent mechanics; and a Simple-only modifier
projects the mandatory self-check without changing the shared Worker prompt.
The one-phase lifecycle, terminal failure paths, evidence seam, Finding stop,
and focused negative tests are otherwise coherent and implementable.

One newly discovered blocking provenance gap prevents acceptance.  The design
claims that the new `simple-self-check` modifier prompt automatically enters the
render manifest's selected-component digests and Front Door pinned-blob check.
Current source does not do that: `render_commission` enumerates only
`components.role`, not modifiers or repository-policy components.  Consequently
the self-check prompt can be read from Development HEAD and dispatched while its
bytes differ from the Intent's pinned component source commit.  That violates
the design's own closed-program and source-provenance boundary.

Review-local blocking identifier:: `SBR-004`.
Open review-local blocking identifiers:: `SBR-004` only.

`SBR-004` is a durable cross-Hop reference, not a preallocated Coordinator
Finding ID.  The structured H005 result proposes one new Current-Run Finding
with `finding_id: null`; the Coordinator owns its authoritative identifier.
`F001`, `F002`, and `F003` remain resolved and are not reopened.

== 2. Renewed review method

The rereview did not treat the H004 focused verdict as proof.  It independently
walked the corrected design against current model, strict-result projection,
parser, reducer, transport/recovery, operator preflight, compiler/render
manifest, prompt assembly, and Finding code.  It specifically falsified:

* whether every path performs at most one provider call and no failure path
  requires an undocumented H002;
* whether generic routing v1 represents the claimed terminal outcomes and its
  persisted family identity is enforced on reduction/replay;
* whether evidence runs after the Worker and trusted commit/scope observation
  but before completion reduction;
* whether a review-less Worker can create an undisposable blocker and whether
  that blocker can be silently completed;
* whether the Simple-only self-check is both dispatched and pinned to its
  claimed source object; and
* whether scope, Git, executable, source, and existing-programme provenance
  remain controlling rather than agent-asserted.

Current source confirms the corrected result and transport design:

* `model.py:654-702` is the single family/version selection seam, while generic
  routing v1 projects all `Outcome` values and the phase route enum
  (`codex_adapter.py:105-121, :197-205`) and parses `failed`
  (`serialization.py:1214-1287`).
* The persisted contract kind/version is checked before reduction
  (`reducer.py:1541-1581`), and `Outcome.FAILED` stops before route or Finding
  authority (`:1660-1663`).
* Return code and timeout are available immediately after `adapter.execute`,
  before result parsing, trusted commit, evidence, Hop recording, or reduction
  (`vertical.py:324-341`); `ExecutionResultValidationError` already enters
  no-replay uncertain recovery (`slice4.py:332-354, :390-399`).
* Evidence remains in the correct existing boundary: trusted commit/scope
  observation, current-phase evidence, post-evidence repository observation,
  Hop recording, then reduction (`vertical.py:342-445, :519-563`).

== 3. Prior Finding verification

=== 3.1 F001 -- Worker-reported failure

Disposition:: *Remains resolved.*

The corrected design selects existing generic `structured_result_v1` only for
the closed terminal Simple shape instead of widening Work-result v1.  Generic
routing admits `failed`; strict parsing preserves it; persisted family identity
fails closed on mismatch; and the reducer reaches `result_failed` without route
application or another invocation.  The test plan explicitly covers this path.

The sentence that only `completed` may _request_ `accept` remains imprecise:
generic routing always requires a route and its only value is `accept`.  The
enforceable fact is that only `completed` can have `accept` applied, because
failed, blocked, human, and changes-required guards preempt route application.
The surrounding design relies on that correct behavior, so this wording does
not reopen F001.

=== 3.2 F002 -- failed provider transport

Disposition:: *Remains resolved.*

The design now requires a guard immediately after provider return and before a
leftover candidate can cause trusted commit, evidence, Hop acceptance, or
completion.  Raising the existing validation exception enters charged
uncertain-dispatch recovery, retains the marker, and does not replay the
provider.  Separate nonzero-with-valid-candidate and timeout-with-valid-
candidate tests now make the original counterexample observable.

=== 3.3 F003 -- mandatory same-invocation self-check

Disposition:: *Remains resolved as an instruction-projection issue.*

The literal programme selects `simple-self-check` as a modifier and the design
defines its mandatory, non-authoritative text.  Prompt assembly already selects
role, modifier, and repository-policy components (`model.py:243-254` and the
component assembly exercised by `tests/unit/test_slice3_vertical.py:123-126`).
Thus the Worker would receive the instruction.  SBR-004 is distinct: the
dispatched modifier's bytes are not yet bound to the pinned source object the
design claims.

== 4. Blocking finding

=== SBR-004 -- the Simple-only modifier prompt is not source-pinned

Invariant:: Every prompt component that supplies closed programme behavior must
be recorded in the render manifest with its pinned-source digest and must be
byte-compared against the Intent's pinned component source object before
admission.  Development HEAD must not silently substitute different instruction
bytes.

The corrected design relies on a new modifier at
`governance/self-development/prompts/simple-self-check.txt` (design lines
131-139).  It says the prompt's "ordinary selected-component digest" and Front
Door comparison protect its exact text (lines 266-270 and 336-340), and requires
negative digest/provenance tests (lines 346-351).  Those claims do not match the
current compiler:

* `commissioning.py:442-447` builds `selected_components` by traversing only
  `phase["components"]["role"]`;
* source digests and render-manifest entries are created only for that truncated
  mapping (`:448-460`);
* `verify_render_manifest` byte-compares the component manifest itself and only
  the paths present in `selected_components` (`:513-518`); and
* operator preflight does load every selected role/modifier/repository-policy
  component from expected HEAD and treats it as governing
  (`operator.py:107-112, :440-451`), but that proves only the current-HEAD bytes.
  It does not compare an omitted modifier blob with
  `components_ref.source_commit`.

A concrete counterexample is therefore possible: keep the pinned component
manifest byte-identical, change only `simple-self-check.txt` between the pinned
component commit and expected Development HEAD, render a Simple Commission, and
run Front Door verification.  The modifier is absent from the manifest's
selected-component digest list and pinned-blob loop, while preflight loads and
dispatches the changed HEAD text.  The intent's component source pin no longer
identifies the behavior the Worker receives.

Correction requirement:: explicitly extend the renderer's selected-component
traversal to all three ordered component categories (`role`, `modifiers`, and
`repository_policy`) across all phases, retaining deterministic first-reference
deduplication.  Require a digest and manifest entry for every selected ID, and
retain the existing Front Door pinned-blob byte comparison over that complete
set.  Add a negative test with a pinned manifest plus a modifier prompt whose
HEAD bytes differ from its pinned commit; it must be rejected before operator
dispatch.  Also prove Direct-v1 and Robust-v1 render manifests remain unchanged,
because their modifier and repository-policy lists are empty.  `commissioning.py`
and its focused tests are already in the candidate implementation scope, so no
new subsystem, schema, or programme revision is needed.
