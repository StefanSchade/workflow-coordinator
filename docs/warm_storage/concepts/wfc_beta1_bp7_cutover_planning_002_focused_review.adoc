=== Method

Four passes, deliberately not organised around the plan's own narrative.

. *Delta pass.* `git show cb81900` read in full; each of the 94 added lines
  checked for a claim that can be falsified.
. *Citation pass.* Every file, function and line range the delta newly cites
  was opened at the review base HEAD and checked on three axes: the symbol
  exists, it is in the named file, and it does what the plan says.
. *Independent-search pass.* `tests/`, `scripts/`, `src/`,
  `docs/operator_manual/`, `docs/developer_guide/`, `Makefile` and
  `pyproject.toml` were searched for every reference to the retiring Harness
  and to the required-real machinery, independently of the plan's own text,
  to find what the plan does *not* mention. The new blocking Finding came
  out of this pass.
. *Consistency pass.* All `<<...>>` cross-references in the plan were
  extracted and matched against all `[[...]]` anchor definitions.

Reviewer-side limitation, reported rather than hidden: `asciidoctor` could
not be invoked in this Hop (the session's permission layer denied both the
tool lookup and the render command; the action was not performed and is not
claimed). Cross-reference integrity was therefore verified textually
instead: the plan defines eleven anchors (`gap-analysis`,

=== Disposition of `F001` (acceptance fulfillable in C5's own scope)

* `tests/conftest.py:21-29` is exactly the six-name
  `"tests/unit/test_wfc_op.py::" + name` frozenset, and `:30-33` exactly the

Why this is blocking rather than polish:

. *The acceptance is not fulfillable inside the stated scope.* "Manual
  guidance agrees with implemented behavior" cannot be true at C5's end
  while seven tracked files still instruct operators and developers to run a
  deleted script and a deleted compile path. This is the identical defect
  class as the now-resolved `F001`, which the task names explicitly
  ("an unfulfillable acceptance").
. *It is not excused by the governing scope.* The execution plan's BP7 entry
  bounds the manual work as "No change to the manual beyond the sections
  this cutover *actually affects*"
  (`docs/backlog/beta1_execution_plan.adoc:518-520`) and introduces its
  chapter list as "per the second-pass review's own chapter list" -- an
  inherited enumeration, not an exhaustive one. The files above are affected
  by the cutover on any reading. The Commission task for this planning
  WorkItem asks for "the manual changes with the exact affected sections",
  so completing the enumeration is in this plan's own deliverable 4, not a
  future Commission's discovery problem.
. *It is a missing essential package, not a wording nit.* `ch08_examples/
  03_commission_to_archive.adoc` is the manual's complete worked
  commission-to-archive walkthrough, and `ch02_commissioning/
  02_authoring.adoc` is its authoring chapter; leaving both out of the
  retirement Commission's scope while the plan explicitly schedules seven
  other files is an omission a reader cannot repair from the plan, because
  the plan asserts its list is "the manual sections named in the execution
  plan" and gives C5 a seven-file Hop estimate built on that list
  (`:671` onward).

Correcting this is a bounded documentation edit inside the already-granted
planning scope: extend C5's scope and acceptance cells (and, if the effort
reasoning changes, its Hop estimate) to name the additional files, or state
an explicit, reasoned carve-out for any file whose reference is to be kept
deliberately as history. Either form resolves the Finding; the reviewer does
not prescribe which.

A related, cheap robustness suggestion the plan may adopt, non-blocking in
itself: make C5's acceptance include a repository-wide search for
`wfc_op`/`wfc-op` outside `governance/commissions/` and
`docs/warm_storage/`, so the check is a verifiable step rather than a
judgement. The historical Commission inputs under `governance/commissions/`
and the frozen review records are correctly out of scope, as the execution
plan excludes retroactive rewriting of historical Commissions.
