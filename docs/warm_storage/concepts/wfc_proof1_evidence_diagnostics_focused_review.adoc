=== Resolution, fingerprinting, alias handling and preflight are unchanged

* A 17-case matrix (bare resolvable and unresolvable, symlinked `argv[0]` both
  spellings, non-executable regular file, dangling symlink, repository-relative
  `PATH` entry, absolute `argv[0]` present and missing, slash-containing
  `argv[0]` present and missing, `PATH=""` resolvable and unresolvable, absent
  `PATH` key falling back to `os.defpath`, multi-entry first match, multi-entry
  unresolvable, embedded NUL in `PATH`) produces structurally identical
  outcomes on the base and candidate trees: same success/exception class, same
  invocation and canonical basenames, same fingerprint shape. The embedded-NUL
  case still raises `ValueError` from the candidate loop on both trees, i.e. the
  probe cannot change that path -- it is only reached after every candidate
  `os.stat` raised one of the caught exceptions.
* No alias substitution: with `python3` present and `python` authored, `python3`
  resolves on its own and authored `python` is still refused. Injecting the
  forbidden behavior (resolve the first discoverable sibling) is killed by four
  of the committed tests.
* `operator.py` and `commissioning.py` are untouched, so `_preflight` still
  refuses fail-closed; the refusal simply carries a longer message. No consumer
  compares the message for equality -- the only textual assertion anywhere,
  `pytest.raises(EvidencePreparationError, match="executable regular file")` at
  `tests/unit/test_a2_evidence_commands.py:259`, is a `re.search` and still
  matches.

=== The probe is bounded, read-only and quiet

* *Read-only.* A prefix-matching sibling whose body would `touch` a marker is
  listed but never executed; after the full `resolve_executable` refusal the
  marker does not exist and the directory listing, sizes and `st_mtime_ns` of
  every entry are unchanged.
* *Bounded.* `DISCOVERABLE_SIBLING_PROBE_LIMIT` is 5 and is enforced across
  `PATH` entries. Worst case measured with five ~250-character sibling names:
  1456-byte message.
* *Selective.* The authored name itself, unrelated names, non-executable
  regular files, directories named like a sibling and dangling symlinks are all
  excluded; names are de-duplicated across `PATH` entries.
* *Tolerant.* A `PATH` made of a missing directory, a regular file and a mode
  `0o000` directory is skipped without raising and the later entries are still
  probed.
* *No path disclosure.* Only basenames enter the message; neither the `PATH`
  entries nor the repository path appear. Committed material contains no
  absolute home-directory path.

== Non-blocking observations

* *Undecodable sibling names reach the message verbatim.* A prefix-matching
  executable whose filename is not valid UTF-8 (for example `python\xff3`) is
  listed through `os.listdir`'s surrogate-escaped name, so `str(error)` holds a
  lone surrogate and raises `UnicodeEncodeError` when printed to a UTF-8
  console. The refusal itself is unaffected -- the same exception type is still
  raised and the outcome stays fail-closed -- and the journal is safe because
  `frontdoor/journal.py` serializes with `json.dumps(..., ensure_ascii=True)`.
  Reproducing it needs an invalid-UTF-8 executable name sharing the authored
  token's prefix on `PATH`, which a conforming environment does not have.
  Encoding probed names with `errors="replace"`, or skipping names that fail to
  round-trip, would remove the case if the maintainer wants it closed.
* The bound test derives its expectation from the constant, so the intended
  small value is not pinned; an absolute upper assertion alongside it would pin
  both. (Carried from H002, independently reproduced.)
* Cross-`PATH`-entry de-duplication (`name in seen`) is uncovered by the
  committed tests. It is an implementation nicety, not a BUG-record obligation.
* The informational clause matches on name prefix, so for a different authored
  token it can list non-interpreter siblings (`git` -> `git-lfs`). The clause
  labels them "informational only, not selected", which is what the record's
  desired direction asks for.
* *Outside this WorkItem's scope:* the overview card at
  `docs/backlog/_open.adoc:398-400` still reads "investigate actionable
  missing-tool/environment messages before selecting a correction", which the
  implementation has overtaken. The overview is the maintainer's to update and
  was correctly left unchanged. Its "never silently substitute `python3`"
  constraint remains honored.
