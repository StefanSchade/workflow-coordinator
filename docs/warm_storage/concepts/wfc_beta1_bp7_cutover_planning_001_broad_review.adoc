=== Method

Every file/function/line citation in the plan was opened in the real tree at
the review base HEAD and checked for three things: that the named symbol
exists, that it is in the named file, and that it does what the plan says it
does. Behavioural claims were read out of the code rather than out of the
earlier reviews the plan descends from, since the plan's own preamble makes
the stronger claim that it was verified against the source. The Harness side
(`scripts/wfc_op.py`, `governance/self-development/*`) was checked
symmetrically with the product side (`src/workflow_coordinator/frontdoor/*`,
`commissioning.py`). `tests/` and `pyproject.toml` were searched
independently of the plan, which is how both Findings below were reached.

Agent-local limitation, reported rather than worked around: the sibling
Evidence repository `../workflow-coordinator-run-evidence` and the real
Harness roots `~/wfc-ops`/`~/wfc-state` are outside this reviewer's sandbox
read set, so claims about the sibling repository's present on-disk shape
could not be confirmed directly. This limitation is itself relevant evidence
for Finding 2 and is treated as such, not as a defect in the candidate.

=== Blocking Finding 1 -- two product functions attributed to the Harness

Invariant:: Deliverable 1's "Name each missing capability with the file/
function where it lives today. Do not assume capabilities; verify", reinforced
by the plan's own preamble ("every number and file/function citation below was
checked against the source tree").

The archive-equivalence section states, at
`docs/backlog/beta1_bp7_cutover_plan.adoc:406-411`:

[quote]
____
The Harness instead uses whatever string the operator chose at `prepare
--attempt` (`derive_attempt_id`/`validate_explicit_attempt_identity`,
`scripts/wfc_op.py:545-580`).
____

Neither symbol exists anywhere in `scripts/wfc_op.py`. Both are *product*
functions:

* `derive_attempt_id` -- `src/workflow_coordinator/frontdoor/archive.py:545`
  (returns `state_root.name`).
* `validate_explicit_attempt_identity` --
  `src/workflow_coordinator/frontdoor/archive.py:567`.

The cited line range `545-580` is in fact `archive.py`'s own line range for
those two functions, so the filename is the part that is wrong. The error is
not cosmetic in context: `validate_explicit_attempt_identity` is the function
the *product* postrun path uses (`frontdoor/archive.py:1021`), and
`derive_attempt_id` implements precisely the state-root-basename derivation
that the immediately preceding sentence of the plan says the product
"explicitly *never*" does -- so the bullet as written assigns to the Harness
the one product function whose behaviour it has just denied, and hides from
the reader that the product retains a legacy-compatible derivation path
(`archive.py:1008-1022`, docstring: "every byte of BP5's legacy
`derive_attempt_id` behaviour is unchanged").

The substantive claim about the Harness is correct and was verified; only its
citation is false. The Harness's attempt identity is the operator-supplied
`--attempt` string, validated by `validate_attempt`
(`scripts/wfc_op.py:176-198`), used to name both roots (`ops_root`/
`state_root`, `scripts/wfc_op.py:201-206`, `~/wfc-ops/<attempt>` and
`~/wfc-state/<attempt>`), consumed at `scripts/wfc_op.py:778` and recorded as
`attempt_id=` by `write_preparation_pins` (`scripts/wfc_op.py:569-582`); the
legacy archiver then re-derives the same string from the state root's
basename.

Required correction:: replace the parenthetical with the Harness symbols that
exist, and state the product's own `derive_attempt_id` fallback for what it is
(retained, legacy-compatible, unused by the product lifecycle) rather than
attributing it to `wfc_op.py`.

=== Blocking Finding 2 -- C1b commissions an archive-equivalence comparison the repository already contains, with an acceptance that cannot be met

Invariant:: Deliverable 4's "independently testable Commissions with ...
acceptance and tests" and the acceptance criterion "a gap analysis verified
against the code"; the reviewer's blocking criteria "no capability is assumed
that does not exist" and "an unfulfillable acceptance".

The plan locates the legacy archiver only outside this repository --
"`scripts/archive_run.py`/`scripts/wfc-archive-run` in the sibling Evidence
repository" (`beta1_bp7_cutover_plan.adoc:189-192`, repeated at `374` and
`478`) -- and then commissions C1b
(`beta1_bp7_cutover_plan.adoc:473-487`) to "Build the offline, read-only
comparison described in <<archive-equivalence>>", scoped as "a new test module
under `tests/` plus the comparison tool it needs". A search of `tests/` shows
both halves of that work already exist, committed, and the plan names neither:

* `tests/unit/test_archive_equivalence.py` (191 lines, docstring "Old-vs-new
  equivalence on a real retained Run (BP5 acceptance)"). Its single test,
  `test_old_and_new_archivers_produce_identical_manifests_for_the_same_real_run`
  (line 154), reconstructs a disposable copy of a real retained Run, archives
  it with *both* the legacy wrapper and `frontdoor.archive.archive_run` into
  two throwaway Git Evidence repositories, and asserts the two `manifest.json`
  files are equal after stripping `archived_at` -- a *stronger* comparison
  than the fact-extraction-only check the plan's section 3 proposes
  (`beta1_bp7_cutover_plan.adoc:417-429`), and it additionally asserts exactly
  one commit per side.
* `tests/fixtures/bp5/legacy/archive_run.py` and
  `tests/fixtures/bp5/legacy/wfc-archive-run` -- a frozen copy of the legacy
  archiver, with its SHA-256 digests asserted in `setUp`
  (`tests/unit/test_archive_equivalence.py:147-152`), plus the committed
  real-Run fact set `tests/fixtures/bp5/real_run/` plus
  `tests/fixtures/bp5/PROVENANCE.txt`.

Two consequences make this blocking rather than cosmetic:

. *The stated C1b acceptance cannot be met.* It requires the comparison to
  pass "against at least one real historical Attempt's already-archived
  manifest (read-only, from the existing Evidence repository, never written
  to)". `tests/unit/test_archive_equivalence.py`'s own docstring records why
  BP5 did not do that: "the Run's actual original state root and OPS directory
  live under `/home/stefan/wfc-state` and `/home/stefan/wfc-ops`, which this
  agent's sandbox cannot read", which is why the hash-verified copy is
  committed under `tests/fixtures/bp5/`. This reviewer's own sandbox reproduces
  the same limitation for `../workflow-coordinator-run-evidence`. An acceptance
  clause that requires an agent Hop to read the live Evidence repository is
  therefore not satisfiable on the known deployment, and the already-solved
  committed-fixture route -- the one C1b should inherit -- is the thing the plan
  does not mention.
. *The effort and scope statements are wrong in a way that matters.* C1b is
  sized "S/M" for building a comparison from nothing; the real remaining work
  is narrower and different in kind (generalize an existing, fixture-pinned
  module so it can be pointed at a second and third Run, including a proof
  Run's own facts). Equally, section 3's "how equivalence is demonstrated"
  paragraph describes reusing `extract_facts`/`run_identity` when the accepted
  BP5 precedent already runs the frozen legacy archiver end to end; adopting
  the weaker method would lose evidence the project already has.

Required correction:: name `tests/unit/test_archive_equivalence.py` and
`tests/fixtures/bp5/legacy/` in the gap analysis and in section 3, restate C1b
as an extension/generalization of that module (adjusting its effort note
accordingly), and replace the "from the existing Evidence repository"
acceptance clause with one the committed-fixture route can actually satisfy.
The same substitution is needed for each proof Run's acceptance bullet
(`beta1_bp7_cutover_plan.adoc:505-508`, "C1b's comparison, re-run against this
Run's own facts"), which inherits the identical read-access assumption for the
Run's own state root under `journal.state_home()`.
