=== 2. Withheld authority and the maintainer principles are honoured

The range `f8e8e5e..c0e8408` changes one leaf, the plan. No move, rename or
deletion; nothing under `src/`, `tests/`, `governance/` or `project_memory/`; no
tag, push or Runtime promotion. No Finding operation was reported by the Worker.

Against the binding principles: the plan proposes no redirect file, stub,
compatibility shim or parallel documentation tree, and §7 reports 30 abandoned
historical paths instead of recreating any of them. It introduces no metadata
system, register, header, field or governance process; the single new file is
one `docs/warm_storage/README.adoc` holding a ten-row table, which is the "few
useful entry points" the task asks for, not a new index to maintain. R1/R2
(§3) draw the evidence boundary where the principles do, and §3's cold-storage
clause correctly limits itself to repairing a link *target* while keeping the
visible label, under the C4 precedent it cites. Moves are same-content renames
and basenames never change, so historical mentions stay searchable — which is
what carries "findable, not under the former path".

=== 3. Simplicity and proportion

I tried to find a materially simpler plan that keeps the same guarantees and
could not. The four packages are cut along the three real risk classes —
pure deletion (D1), judged fragment retargeting (D2), bulk rename (D3) — plus a
small cleanup (D4), and each depends on its predecessor for a concrete reason
(a shared `docs/README.adoc` edit; a destination that must exist; a path that
must not move while it is being retired). Dropping D1 or D4 into D3 would mix a
pure deletion or a judged retarget into a 138-file rename, which is the one
thing a rename package should not carry. The nine rejected packages in §9 are
the right rejections, and two of them — a README per warm group and a per-file
mapping table — are exactly the mechanisms a weaker plan would have added. The
verification reuses `asciidoctor`, `wfc_doc_catalog.py generate` and `check`
and `git grep` and adds no script, make target or report.

The one place where cost may exceed benefit is a maintainer question, not a
defect: D3's scope takes six model and manual directories plus `docs/backlog/`
as whole directories because the inbound links are spread across 28 files. That
is honest about where the links are, but it is a wide scope for a rename
package. I record it as an observation rather than a Finding because the plan
states the reason and the alternative (per-leaf scope across 28 files) is worse
to author and to check.

=== 5. Blocking Finding — the `tests/` consumer treatment and V4 step 2

Invariant:: A package's stated acceptance must be achievable within that
package's stated scope, and a cited consumer set must match the repository.

The plan's §2.4 asserts, for source, tests, scripts and packaging, "*No
functional consumer.*", names `tests/unit/test_wfc_doc_catalog.py` and
`tests/unit/test_archive_equivalence.py`, and then states: "The two consumers
the C4 handoff named, `scripts/wfc_op.py` and
`tests/architecture/test_self_development_governance.py`, no longer exist."
The narrow claim is true — no module or test opens or asserts a moved document.
The consumer accounting is not. `#c4-compatibility` names *three*
non-functional consumers, not two; its third is "the nested-Claude integration
test has a provenance docstring", and that one still exists:

----
tests/integration/test_nested_claude_bwrap_qualification.py:57:
    `workflow-coordinator@4b13dc22`; see `docs/run-recovery-and-salvage.adoc`'s
    authority statement -- salvage is not trusted evidence)
----

That is a live prose citation of a path D2 removes, in a file that is in no
package's scope.

This omission then breaks V4. §6 step 2 reads: "Then the same search without
the directive prefix and without the cold exclusion, to list remaining
plain-text mentions; expected: no hit under `src/`, `tests/` or `scripts/` ...".
The exclusion sentence that follows covers `governance/`, `.wfc/`, Project
Memory history notes and the Evidence repository — not `tests/`. Reproduced at
the review base HEAD, with `src` and `scripts` clean as claimed:

----
$ git grep -l -F -e "wfc_operator_manual.adoc" -e "run-recovery-and-salvage.adoc" \
    -e "self-development.adoc" -e "run-preparation.adoc" \
    -e "successor_continuation_runbook_2026-10-10.adoc" \
    -e "warm_storage/concepts" -e "docs/qualification" -- src scripts
(no output)

$ ... same, -- tests
tests/fixtures/bp5/real_run/run/checkouts/.../checkpoint.json
tests/fixtures/bp5/real_run/run/checkouts/.../run.fixture.json
tests/fixtures/bp7/real_run/run/checkouts/.../checkpoint.json
tests/fixtures/bp7/real_run/run/checkouts/.../run.fixture.json
tests/integration/test_nested_claude_bwrap_qualification.py
tests/unit/test_archive_equivalence.py
----

So V4 step 2 fails under `tests/` for *both* judged packages, and in every case
on material the plan itself declares immutable:

* *D2.* `tests/integration/test_nested_claude_bwrap_qualification.py:57` cites
  `docs/run-recovery-and-salvage.adoc`.
* *D3.* `tests/unit/test_archive_equivalence.py` carries
  `docs/warm_storage/concepts/wfc_beta1_bp3_remediation_review_001_broad_review.adoc`
  and `..._bp7_guidance_config_001_broad_review.adoc` inside the frozen
  `_BP5_*`/`_BP7_OPERATOR_*_JSON` literals — paths of surviving files that D3
  moves — and the four `tests/fixtures/bp5|bp7` archive fixtures carry the same
  strings.

This contradicts the plan in three places at once: §3 R1 lists "committed test
fixtures" among the things that are "never moved, retargeted or rewritten";
§2.4 itself records that `test_archive_equivalence.py` "holds warm paths only as
frozen JSON string literals"; and the C4 record the plan relies on concludes
"zero textual matches is not an acceptance criterion". The task asked for "a
grep proving no live reference to a removed path remains *outside immutable
evidence*", which V4 step 1 already delivers; step 2 overshoots that into a
criterion the repository cannot satisfy and that neither D2's nor D3's scope
could repair.

Concrete cost of leaving it: D2 and D3 each carry an acceptance criterion that
fails before any work is done, so the executing Worker must either stop and
escalate or quietly relax a stated criterion — the correction-cycle failure
mode this Commission was told to avoid.

Smallest sufficient correction, inside the plan only:

. In §6 V4, add `tests/fixtures/` and frozen in-test JSON literals to the
  immutable material excluded from step 2 by construction, consistent with §3
  R1, and state the expectation as the C4 precedent does: no *directive* match
  outside immutable evidence, with remaining plain-text mentions listed and
  named in the package result rather than driven to zero.
. In §2.4, correct the C4 sentence to the three consumers C4 actually named,
  record that the nested-Claude integration-test docstring still cites
  `docs/run-recovery-and-salvage.adoc`, and say which way D2 handles it: either
  take that one leaf into D2's scope (`tests/` is inside the enforced ceiling,
  so no extra authority is needed) or declare it a tolerated provenance mention
  named in D2's result. Either is defensible; a reader of the plan currently
  cannot tell which applies, and today neither is stated.

No other section needs to change, and nothing in sections 1-3 of this review is
affected.
