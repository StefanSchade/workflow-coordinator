== Blocking findings

[[output-faithfulness]]
=== Preserve arbitrary subprocess output and its exit result

Location:: `src/workflow_coordinator/execution_boundary.py:115-117`
Requirement:: The runner must return/propagate the wrapped subprocess's exit
status, stdout, and stderr faithfully.

`subprocess.run(..., text=True)` decodes using the host text encoding and
normalizes newlines. A valid sandboxed command emitting non-UTF-8 bytes
therefore raises `UnicodeDecodeError` instead of returning its exit status
and streams. CRLF output is also changed to LF. No output restriction or
lossy decoding contract was authorized for the caller-supplied executable.

Observed with a real validated boundary and real bwrap, running
`/usr/bin/python3 -c` inside the sandbox:

[source,python]
----
import os
os.write(1, b"out\r\n")
os.write(2, b"err\r\n")
raise SystemExit(17)
# Actual: returncode 17, stdout 'out\n', stderr 'err\n'.

import os
os.write(1, b"\xff")
raise SystemExit(17)
# Actual: UnicodeDecodeError: 'utf-8' codec can't decode byte 0xff
# in position 0: invalid start byte; no CompletedProcess is returned.
----

Correction needed: provide lossless capture (for example bytes, with matching
return typing), and regression coverage using real bwrap for nonzero exit
status plus binary/newline-sensitive output on both stdout and stderr.

[[scratch-observation]]
=== Observe that scratch does not write into repository temporary storage

Location:: `tests/integration/test_execution_boundary_bwrap.py:31-32,42`
Requirement:: Private temporary storage must be observed from the sandbox
and verified host-distinct from the repository's own temp handling.

The test writes `/tmp/private-file` and reads it in the sandbox, but its only
host-side check is absence of `repo/private-file`. It creates no repository
temporary directory/sentinel and does not check `repo/tmp/private-file`.
Consequently it does not prove the required distinction from repository
temporary storage.

A reviewer-only sensitivity experiment, without editing any source or test
file, loaded the integration test and replaced its `run` binding with a
wrapper around the real `build_argv`. That wrapper created `repo/tmp` and
replaced only `--tmpfs /tmp` with `--bind <repo/tmp> /tmp`, then executed the
result with real bwrap. The entire existing integration test still passed;
the host `repo/tmp/private-file` contained `scratch` afterward. Thus a
repository-backed writable scratch violating the requirement escapes the
assertions. This experiment demonstrates a test gap; the committed module
itself does currently request tmpfs.

Correction needed: use synthetic repository temp fixtures and host-side
content/absence assertions that distinguish them from the sandbox scratch
path, while retaining actual sandbox write/read observation. The test must
fail if `/tmp` is instead backed by the repository's temp directory.

== Isolation and fail-closed audit

The committed integration test invokes `run`, which invokes an actual
`subprocess.run` of bwrap. It has no mock, dry-run, skip, or capability-based
success shortcut. Its shell actually performs each of these operations:

* Read ordinary repository content and compare the real string.
* Create a writable-grant file and verify its host content afterward.
* Attempt a protected-file write, then verify unchanged host content and
  nanosecond mtime.
* Test existence of an unrelated synthetic host file and directory, attempt
  to read the file, and attempt to list the directory by their host paths.
* Attempt to read `.git/secret` and create `.git/new` inside the sandbox.
  The empty overlay is read-only; the original metadata contents are hidden.
* Write and reread scratch in the same sandbox. The host-distinction proof
  remains deficient as described above.
* Attempt a write through a grant-contained symlink to a synthetic external
  host secret and attempt `../../private/secret` traversal from the writable
  path. The external host secret is checked unchanged afterward.

Configuration tests inspect argv/rejections rather than claiming subprocess
isolation. They cover an exact existing-file grant, symlink/relative sources,
`.git` writes, remapping into a missing destination parent, overlapping
destinations, an explicit nonexistent bwrap path, and an empty command.

Additional reviewer probes called the real runner with a single writable
file grant. Writing that file succeeded, while writing its sibling and
creating a file in its containing directory failed; host observations were
`file=changed`, `sibling=keep`, `new=False`. The file grant is not widened
into a directory grant.

Additional probes directly constructed `ValidatedBoundary` instances with
relative sources, `.git` writable sources, missing destination parents,
nonexistent binaries, and existing non-executable binaries, and called
`run` with subprocess spawning patched only to count attempted launches.
Each raised `BoundaryConfigurationError`; total spawn count was zero.
`build_argv` revalidates public dataclass instances. There is exactly one
runner launch site and no unsandboxed fallback or automatic retry.

The argv includes `--die-with-parent`, read-only system roots, a read-only
repository at `/repo`, a separately read-only empty `.git` tmpfs, explicit
bind grants, and explicit scratch tmpfs. No network-namespace policy is
introduced. Source stability between validation and execution is an explicit
module precondition; concurrent hostile host mount-tree mutation is not
claimed to be solved by this slice.

== Supported subset and explicit rejections

The bounded subset accepts an existing absolute real repository with a real
`.git` directory, existing regular-file/directory bind sources beneath it
mapped to their identical `/repo/<relative>` locations, and exactly one
source-free scratch request at `/tmp`. Nested/duplicate explicit destinations
are rejected even when one is read-only. System-root/repository overlap,
symlinked sources, external sources, arbitrary remappings, `.git` source
components, non-file/non-directory bind sources, and alternate scratch shapes
are rejected.

In particular, a Commission scope naming a file that does not yet exist
cannot be translated to a writable mount by this slice: it is rejected,
without widening to its parent directory. Missing destination parents and
requested directory creation/remapping are also unsupported. Git worktrees
with a `.git` file, or repositories with a symlinked `.git`, are rejected.
These are bounded-subset limitations rather than implicit scope translation.
