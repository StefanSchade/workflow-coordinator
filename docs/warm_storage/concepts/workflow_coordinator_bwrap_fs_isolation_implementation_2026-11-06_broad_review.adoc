[[inode-alias-bypass]]
== Blocking finding: hardlinks bypass protected-path write isolation

Locations:: `src/workflow_coordinator/execution_boundary.py:42-47,77-85,106-111`;
`tests/integration/test_execution_boundary_bwrap.py:6-49`.
Invariant:: Writable grants must not modify ungranted host paths, including
read-only repository files and hidden Git metadata. Unsafe configurations
must be rejected instead of broadening effective authority.

Validation checks canonical path spelling, source type, repository ancestry,
and destination overlap, but never checks inode aliases. A regular file
with an existing hardlink passes `_real_path`, and a writable directory
containing such a file also passes. A read-only bind and the empty `.git`
overlay protect their mount paths; they do not protect a shared inode
reached through a separate writable bind.

Created all links before validation, without concurrent source mutation:

* `repo/protected` contained `protected original`.
* `repo/.git/secret` contained `git original`.
* An external synthetic `private` file contained `private original`.
* `repo/writable/{protected,git,private}-alias` were hardlinks to those
  respective files.

Production `validate` accepted a writable directory grant for
`repo/writable` plus private scratch. Production `run` executed real bwrap
with this shell payload:

[source,shell]
----
set -eu
cat /repo/writable/git-alias
cat /repo/writable/private-alias
for n in protected git private; do
    printf breached > /repo/writable/$n-alias
done
----

Observed exit 0, stdout `b'git originalprivate original'`, and empty stderr.
Host reads afterward returned `breached` for all three original protected
files, including the hidden Git file and the file outside the repository.
This is actual sandbox behavior, not an argv inference.

Next, granted only the existing file `repo/writable/protected-alias` at
`/repo/writable/protected-alias`, plus scratch. Executing
`printf file-grant-breach > /repo/writable/protected-alias` through real
bwrap exited 0; the ungranted host `repo/protected` then contained
`file-grant-breach`. No parent-directory bind is substituted, but an exact
file bind still fails to bound mutation by the authorized path when the
inode has another name.

A minimal reproduction of the single-file case is:

[source,python]
----
import os
from pathlib import Path, PurePosixPath
from tempfile import TemporaryDirectory
from workflow_coordinator.execution_boundary import Mount, MountMode, run, validate

with TemporaryDirectory() as temporary:
    repo = Path(temporary) / 'repo'
    repo.mkdir()
    (repo / '.git').mkdir()
    protected = repo / 'protected'
    protected.write_text('unchanged')
    alias = repo / 'granted'
    os.link(protected, alias)
    boundary = validate(repo, [
        Mount(alias, PurePosixPath('/repo/granted'), MountMode.WRITABLE),
        Mount(None, PurePosixPath('/tmp'), MountMode.SCRATCH),
    ])
    result = run(boundary, ['/bin/sh', '-c', 'printf breached > /repo/granted'])
    print(result.returncode, protected.read_text())  # 0 breached
----

`run`, which launches actual bwrap. Neither mocks subprocess behavior,
skips execution, nor treats missing capability as success. The filesystem
test actually exercises:

* Permitted read: compares `/repo/readable` with its fixture content.
* Permitted write: creates `/repo/writable/created` and checks host content.
* Forbidden write: attempts `/repo/protected`, then checks unchanged host
  content and nanosecond mtime.
* Unrelated host paths: tests existence of a synthetic external file and
  directory, attempts reading the file and listing the directory by their
  host paths. Those accesses fail.
* Git metadata: attempts reading `/repo/.git/secret` and creating
  `/repo/.git/new`; both fail through the overlaid root `.git` path.
* Scratch: writes and rereads `/tmp/private-file`, then checks unchanged
  repository `tmp` contents, sentinel content, and directory nanosecond mtime.

  an external synthetic secret and through `../../private/secret`; both
  fail, and the external host secret remains unchanged.

These observations hold for the committed non-aliased fixtures. They do
not establish the general write-isolation claim: the hardlink fixture
above defeats it. Integration tests contain no hardlink case or actual
single-file-grant execution case.

Overlap and invalid-specification rejection are deliberately checked

A separate real-bwrap probe with a non-aliased single-file grant changed

in its parent directory. Host observation was `file=changed`,
`sibling=keep`, `new exists=False`. The argv binds the exact file, never
its parent; inode aliasing is the distinct unresolved defect.

The supported subset requires an existing absolute real repository with a
real `.git` directory, existing regular-file/directory sources below it at
matching `/repo` destinations, and exactly one source-free `/tmp` scratch
mount. It rejects symlink sources, nonexistent file grants, arbitrary
remapping, overlapping explicit destinations, and repositories overlapping
system roots. Git worktrees with `.git` files are unsupported. These
limitations do not authorize approximation to parent-directory writes.

The constructed boundary requests read-only system executable/library
mounts, read-only repository visibility, a read-only empty root `.git`
overlay, explicit writable binds, private scratch, and `--die-with-parent`.
No network namespace policy is introduced. This is an opt-in primitive,
not an authority resolver, credential boundary, replacement for post-Hop
scope observation, or statement about provider-owned permission modes.

== H002 correction: writable inode aliases

The correction validates each writable file and recursively inspects writable
directory trees without following symlinks. It rejects regular files whose
link count is not exactly one and fails closed if the tree cannot be inspected.
Read-only grants are unaffected. The existing execution-time revalidation also
repeats this inspection immediately before launching bwrap. As before, the
caller must keep the source tree stable between validation and execution; this
does not establish protection against concurrent host-side changes. The check
relies on the filesystem reporting accurate link counts and deliberately rejects
even multiple names wholly within the granted tree.

New real-bwrap regression cases first demonstrate permitted writes for both
file and directory grants, then introduce a hardlink to an ungranted repository
file, Git metadata, or an external host file. Both validation and the runner's
pre-launch revalidation reject all six combinations, and the protected contents
remain unchanged. A separate real sandbox attempts to create a new hardlink
from the read-only repository into the writable grant and observes failure and
unchanged host contents. A unit test checks that an inspection error prevents
subprocess launch. These agent-local checks are not Coordinator-trusted evidence;
the current Run's projected `task-check` pass predates this correction.
