== Diagnosis and correction

The commission states that a maintainer-run controlled A/B experiment
established the environment-scrub mechanism; it supplies the evidence for
removing the forced scrub setting. The earlier bug record documents the
CLI warning that scrubbing forced permission mode to default, and denial
with no approval surface. Inspection of the old adapter confirms that it
both requested `acceptEdits` and forced the scrub flag while passing the
whole parent environment, including possible nested `CLAUDE_CODE_*` state.
The integration-debt record also describes a distinct short-TMPDIR sandbox
bridge failure and an unexplained approval denial. Provider-specific behavior
and other permission or sandbox interactions remain possible.

The child now receives only present values of `PATH` (CLI and tool lookup),
`HOME` (file-based authentication), `USER` (user identity), and `LANG`
(locale), plus the unchanged invocation-specific `TMPDIR`, `TMP`, and
`TEMP`. No `CLAUDE_CODE_*` name is admitted. The sandbox bridge described in
the adapter derives its socket path from TMPDIR; the inspected WFC bubblewrap
boundary likewise does not depend on `XDG_RUNTIME_DIR`. There is no identified
requirement to pass that session-specific directory by default; deployments
that need additional names can explicitly add them.

At adapter construction, `WFC_CLAUDE_EXTRA_ENV_NAMES` may contain a
comma-separated list of variable names, for example `SSL_CERT_FILE,FOO`.
The adapter snapshots the names, and obtains their values from its own parent
environment at launch. Absent names are omitted. Names must be simple
environment identifiers; assignments, empty entries, `CLAUDE_CODE_*`, and
the three temporary-directory names are rejected. The constructor also
accepts a tuple of names subject to the same validation. This is a single
additive operator mechanism; it changes neither settings nor permissions.
Operators should only select variables appropriate for the deployment, since
their values will be available to the child.

== Independent assessment

The reviewer read the complete permission-mismatch bug record and the
integration-debt record, including section 2, and compared the committed
candidate with its parent `725b3297ac32ff884dd3cf1178bebeb69e7bebe1`.
The candidate changes only the adapter, the two designated test files, and
this artifact. The independent review changes only this artifact.

Environment construction iterates the literal four-name tuple and the
validated extra-name tuple, looking up only those names in `os.environ`.
There is no parent-environment copy or fallback. `PATH`, `HOME`, `USER`,
and `LANG` are the required minimal defaults for executable discovery,
file-based authentication, identity, and locale. Optional configuration,
credentials, locale overrides, and session state are not implicitly inherited.
Missing names are omitted. Both constructor input and the environment-backed
source pass through the same validation, which rejects the entire
`CLAUDE_CODE_` prefix, assignments, invalid identifiers, and all three reserved
temporary-directory names. Values are read at launch, while the selected
names are fixed at construction. The default extension is empty.

For the `XDG_RUNTIME_DIR` decision, the reviewer also inspected embedded
source in the installed Claude executable and the local
`/home/stefan/.local/share/claude/versions/2.1.270` image without executing
either. The Linux HTTP/SOCKS bridge constructs its socket paths using an
import of `tmpdir` from `os`, and discovers `bwrap` and `socat` as executables.
Its bridge initialization does not require `XDG_RUNTIME_DIR`. Other inspected
XDG runtime-directory uses concern optional IPC/daemon paths and have
fallbacks. This supports retaining the explicit TMPDIR override and omitting
an unrelated runtime-directory default; it does not qualify actual provider
startup or authentication under the corrected environment.

The existing restricted profile, repository-root read grant, home-read denial,
empty network-domain allowlist, sandbox failure behavior, and short temporary
directory lifecycle are unchanged. WFC's post-Hop scope observation remains
the boundary for accepted candidates; the provider sandbox is not a proof of
per-commission write containment. Existing settings and argv assertions and
the new fake-executable environment checks support deterministic inspection,
not a claim about the real provider's permission engine.

An independent AST comparison confirmed that `argv`, `_settings`, and
`_short_subprocess_tmp_dir` are unchanged from the parent. The unchanged
`_SHORT_TMP_ROOT`, invocation-directory creation, timeout handling, and cleanup
were also inspected. No blanket bypass, scope expansion, unsandboxed retry,
network-domain grant, or governance change was introduced. The maintainer's
established A/B evidence supplies the mechanism justification for removing
forced scrubbing; this review did not repeat that experiment.

The fake-executable regression captures the actual child environment and
compares it with a literal expected dictionary, independent of the production
allowlist constant. It plants scrub/session variables and an unrelated secret
in the test process, checks exact default keys and values, then checks that
only selected extras are added. It also checks construction-time selection,
launch-time values, and omission of a missing selected variable. Reserved-name
cases exercise rejection. These checks would detect the former full-environment
inheritance and forced scrub behavior. Existing argv/settings, resolved-root,
wrapper validation, transport, timeout, and temporary-directory cases remain.
The new opt-in smoke checks a real output file as well as the reported outcome;
its successful execution remains unestablished here.
