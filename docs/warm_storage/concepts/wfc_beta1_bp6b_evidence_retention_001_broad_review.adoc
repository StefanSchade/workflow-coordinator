=== Blocking Findings

[[f-a]]
==== F-A -- an Attempt that was never committed is reported as already archived

Invariant:: Acceptance (7) "one commit per Attempt in every mode, containing
`audit.json`" and (8) "re-archive no-op per mode, no second commit"; the
second-pass review's `Commit ownership, idempotency and integrity` ("the
controller is the only writer of archive commits. One commit touches one
attempt directory"); and the task's rule that `raw_retention=None` keeps
exactly today's behaviour. A `no_op` claim is a claim that the Attempt is
already durably archived.

Root cause:: `_path_is_tracked_clean` (`frontdoor/archive.py`) decides "this
destination is already committed" from the *absence* of a
`git status --porcelain=v1 --untracked-files=all` line under `dest_rel`.
`git status` never lists ignored paths, so "absent" means either "committed"
or "entirely ignored". BP6b is what makes that conflation reachable: before
this candidate no Evidence repository ignored anything under `archive/`.

Reproduction 1 -- the product's own two halves, default invocation::
+
[source,text]
----
ensure_evidence_repository(evidence)      # the managed .gitignore block
wfc archive <state-root> <evidence>       # no --raw-retention: the BP5 path
  -> exit 1
  -> "commit failed: commit intent path has no worktree mutation:
      archive/unclassified/<attempt>/manifest.json, .../ops/..., .../run/..."
  -> destination placed on disk (manifest.json, ops/, run/), 0 commits
wfc archive <state-root> <evidence>       # the operator simply retries
  -> exit 0
  -> "ARCHIVE ALREADY UP TO DATE" ... "manifest: valid" ... "commit: None"
  -> git rev-list --count <before>..HEAD == 0
  -> git ls-files == {.gitignore, archive/.gitkeep}
----
+
A third and every later run repeats the same false success. The destination
is also a dead end: `--raw-retention local` and `commit` then refuse with
"archive destination exists but has no audit.json", and `discard` with
"exists but is not a valid discard-retention placement", so this Attempt can
never be archived into that Evidence repository without a manual `rm -rf`.

Reproduction 2 -- inside the new retention path itself::
In an Evidence repository that keeps the managed block and adds one broad
operator rule (`*.json`), `--raw-retention local` exits 1 on the first run
("commit intent path has no worktree mutation: .../audit.json", destination
placed), and *every* later run exits 0 with `ARCHIVE ALREADY UP TO DATE` and
`commit: None` while `git ls-files` again tracks nothing for the Attempt.
Here the mode is `local`, the oracle is BP6b's own
`_resume_or_noop_kept_raw`, and the placed `audit.json` passes both the
manifest comparison and the reprojection comparison -- the only thing missing
is the commit, which is exactly what the report claims is present.

Why the delivered suite does not catch it:: `LegacyRetentionNoneTests` first
*replaces* the Evidence repository's managed `.gitignore` with
`stray/` before exercising the legacy path, so the one test that covers
`raw_retention=None` is the only configuration in which that path still
works. No test archives into a `wfc init` repository without
`--raw-retention`, and no test asserts that a `no_op` outcome corresponds to
an actual commit.

Not covered by the documented limitation:: the BP6b limitations record
(`raw_retention=None` remains the unmodified BP5 path) does say the legacy
path "is not guaranteed to succeed" against a managed repository. It does not
state, and acceptance does not permit, that a later run then *reports
success* for an Attempt with no commit, nor that the destination becomes
permanently un-archivable. Reproduction 2 is outside that limitation
altogether.

Smallest correction direction (the worker's choice, not a prescription)::
make the `no_op` verdict depend on the mode's expected committed leaves being
tracked at `HEAD` (for example `git ls-files --error-unmatch -- <audit_rel>`,
or `cat-file -e HEAD:<audit_rel>`) rather than on `git status` silence, and
resume into the commit -- or refuse with a named reason -- when they are not;
refuse `local` before any write when the destination's own `audit.json` would
be ignored (the coverage probe currently only checks that the raw paths *are*
ignored); and refuse `raw_retention=None` before placement, with a named
reason, in a repository whose `.gitignore` excludes the paths that path
commits unconditionally.

[[f-b]]
==== F-B -- the retention-aware archive supplies no private strings to the privacy guard

Invariant:: Deliver item 3: "The privacy guard of `audit.py` applies: a
refusal writes nothing and commits nothing. *Known private strings for the
guard are derived from the environment (home directory, user name, state and
ops directories of the Attempt).*" Acceptance (10): "privacy: the Evidence
history (all blobs) contains none of the known home, user name,
scratch/state/ops strings in `local` and `discard`; a guard refusal writes
and commits nothing."

Reproduction:: `archive.py`'s only projection call is
+
[source,python]
----
def _project_audit_text(attempt_dir: Path, *, raw_retention: str) -> str:
    return render_audit_json(project_audit(attempt_dir, raw_retention=raw_retention))
----
+
`project_audit`'s `private_strings` parameter defaults to `()`, so the guard
reduces to BP6a's structural heuristic: a string is refused only if it
*starts* with `/`, a drive letter or `\\`, or contains a URL/`git@` pattern
(BP6a's own broad review recorded that prefix-only property and noted that an
embedded path "is caught only through a caller-supplied private string").
With an `operator-plan.json` whose `governing_inputs` carries the
repository-relative key `docs/canary-private-user/governance.adoc` -- the one
field BP6a copies wholesale, and a shape an operator can legitimately author:
+
[source,text]
----
wfc archive <state> <evidence> --raw-retention local    -> exit 0
  "canary-private-user" in the committed audit.json          -> True
  history blobs (rev-list --objects --all) carrying it        -> 1
wfc archive <state> <evidence> --raw-retention discard  -> exit 0
  history blobs carrying it                                   -> 1
----
+
With the private strings the task requires (home directory, user name, state
root, OPS directory) the same input is refused by `_guard_privacy` before
anything is written -- the behaviour the task specifies. Nothing in the
delivered suite would detect the omission, because there is nothing to mutate:
`test_archive_retention.PrivacyAcrossHistoryTests` plants the home path and
the user name only in a *raw* OPS file (`ops/run.log`), which `local` and
`discard` never commit for reasons independent of the guard, so both tests
stay green with the guard entirely absent.

Second half of case (10), untested:: a guard refusal is in fact correct today
-- a forged absolute `governing_inputs` key yields exit 3 with
`privacy guard refused projection at governance.governing_inputs.<key>`, no
destination, no staging residue, no commit and a clean `git status` -- but no
test asserts it, so acceptance case (10) has no mutation-sensitive test for
the refusal path either (removing the `ProjectionError` handling in
`archive.main` changes only the exit code, which nothing asserts).

Smallest correction direction:: derive the strings where the archiver already
has them (`home_dir`, the OS user name, `str(state_root)`,
`str(ops_dir_resolved)`), pass them through `_project_audit_text` to
`project_audit`, and add two tests: one planting a known private string in a
*projected* field and asserting refusal (which fails if the argument is
dropped), one asserting that a refusal leaves no destination, no staging
residue and no commit. Note the intended consequence: with the user name
among the private strings, a project whose governance paths legitimately
contain it will be refused rather than published -- that is what "a refusal
writes nothing and commits nothing" asks for, and it is worth stating in the
limitations record.

=== Non-blocking observations

Observations, not Findings; recorded here and in the Hop summary only.

. *The `local` coverage probe tests effective ignore status, not the managed
  block.* `check-ignore --no-index` is satisfied by `.git/info/exclude` or a
  global `core.excludesFile` just as well as by the committed `.gitignore`.
  That is arguably the more useful test, but coverage that lives outside the
  repository does not travel with a clone, so a cloned Evidence repository
  can silently lose the protection the probe certified.
. *`.wfc-archive-staging/` is not covered by the managed block.* The managed
  patterns are all `archive/**`. Leftover staging from an interrupted archive
  is therefore visible, not ignored -- harmless for commits
  (`bounded_path_commit` refuses on unexpected dirty paths) but it means an
  interrupted archive of attempt A blocks a later archive of attempt B with
  the BP5 "not clean outside the archive destination" refusal until it is
  removed by hand.
. *`discard` does copy every raw file into the Evidence repository,
  transiently.* `_manifest_candidate` must stage and digest the raw files
  before they can be described, so they are written under
  `.wfc-archive-staging/<attempt>/` inside the Evidence repository and then
  removed. The task mandates exactly that ("the Attempt is staged and
  verified as today"), and nothing is ever committed, but the limitations
  record's "never places a raw file at the Evidence destination at all -- not
  transiently, not then removed" is true only of the *destination*: an
  interruption leaves raw bytes in the Evidence worktree.
. *An un-projectable Attempt can no longer be archived at all.* An Attempt
  without `run/checkouts/<id>/run.json` -- the shape a launch that never
  reached checkout registration leaves, and BP6a's own observation 5 -- is
  refused in all three retention modes with "no run.json found among the
  archived files; not a projectable attempt". The refusal is clean (nothing
  placed, nothing committed, exit 1), and this input is outside the
  acceptance list, but BP6c should decide what a lifecycle-wired archive does
  with the Runs that are most worth keeping raw.
. *Mixed-mode re-archive refuses with a slightly misleading reason.*
  Re-archiving a `local` destination with `--raw-retention commit` (or the
  reverse) is refused by the `audit.json` reprojection comparison, reported as
  "placed audit.json does not match a projection of its own manifest ...
  tampered"; the real cause is only the `raw.retention` field. Refusing is
  right; naming the retention mismatch would be kinder.
. *The `git_facts` trusted policy is duplicated in `init.py`.* The
  justification is sound (no HEAD exists yet for `bounded_path_commit` to
  anchor on) and the duplicate is faithful (same three `-c` flags, same
  `GIT_*`-stripped environment), but it is now a second copy that can drift
  from `git_facts._run_git(trusted=True)`.
. *An interrupted `wfc init` can leave an Evidence repository that is adopted
  but has no commit.* `ensure_evidence_repository` adopts any directory with
  `.git` and `archive/`; if the bootstrap commit never happened (for example
  no usable Git identity, or an interruption between `git init` and `git
  commit`), the next `wfc init` reports "reusing existing" and exit 0 without
  ever creating the initial commit, and a later `wfc archive` fails at HEAD
  resolution. Read from the code; the commit step could not be made to fail in
  this sandbox, so this is unverified.
. *One config test is tautological.*
  `test_config_without_evidence_block_digests_identically_to_the_pre_bp6b_shape`
  compares `sha256(config.raw_text)` with `sha256(text)`, which cannot fail
  while `raw_text` is stored verbatim. The real protection for "digests
  exactly as before" is the unchanged consumer-compiler suite, which does pass.
. *Environmental test failures in this sandbox.*
  `tests/architecture/test_offline_distribution.py` and
  `test_bp1_identity.py` need PEP 517 build isolation (`No matching
  distribution found for setuptools>=68`); `tests/unit/test_wfc_op.py` runs a
  nested `pip install`; `tests/unit/test_claude_adapter_conformance.py` needs
  a writable `/tmp` symlink target. All four fail identically regardless of
  this candidate. Agent-local limitation, not a product defect, and no
  substitute for the Coordinator's own full `task-check`.

=== Verdict

Changes required. Two blocking Findings (*F-A*, *F-B*), nine non-blocking
observations. The configuration block, `wfc init`'s Evidence-repository
creation, the three retention modes' placement and commit shape, the report
observations and the limitations record are otherwise what the task
specifies; the corrections needed are confined to the idempotency oracle and
the early refusals around it, the private strings handed to the privacy
guard, and the tests that pin both.
