== Blocking issue: the allowance omits Write

`src/workflow_coordinator/claude_adapter.py:78` grants the bare tool rule
`Edit`, while the unchanged explicit tool list contains both `Edit` and
`Write`. The installed CLI distinguishes bare tool allowances from
path-scoped file-edit rules. In particular:

* Rule parsing preserves bare `Edit` and `Write` as distinct names; the
  legacy-name alias map does not merge them.
* Whole-tool allow matching compares the actual tool name. The Write tool
  has name `Write`, without an Edit family-parent declaration.
* Both tools call the shared file-write permission check, but its Edit-path
  allow matching requires a rule with path content. A bare `Edit` rule is
  excluded from that matching.
* Under default mode, an ordinary repository-local Write with neither a
  matching path rule nor a whole-tool Write allowance therefore still asks
  for approval. `--permission-prompts none` denies that request.

Thus the correction can allow Edit while leaving the exact Write tool
used in the recorded failure ungranted. This is a static implementation
gap, not a demand for live-provider certainty. Edit's ability to create some
files is not evidence that the separately exposed Write tool has permission.
The handoff's uncertainty about whether Edit covers Write can be narrowed
using locally available implementation evidence; it should not be left
entirely to the deferred live qualification.

Required correction: provide the narrowest supported allowance covering
both repository-local Edit and Write while retaining restricted mode and
the resolved repository boundary. Explicitly allowing Write alongside Edit
is one bounded option; a supported repository-scoped Edit path rule is
another approach to assess. Do not grant general Bash access to compensate.
The installed Write implementation requests parent creation itself, so the
observed Bash mkdir denial alone does not justify a separate Bash grant.
Extend the deterministic configuration tests to reject a missing Write
authorization as well as unintended widening, and update the explanation
and residual uncertainty. No change outside the adapter and its conformance
tests is needed to address this Finding.
