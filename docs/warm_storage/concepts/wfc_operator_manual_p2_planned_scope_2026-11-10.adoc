== Why two Commissions

`wfc-operator-manual-consolidation-001` (Run `RUN-deb3a4f3765346c6ae247488c5efddae`,
Attempt `wfc-operator-manual-consolidation-001-20261110-01`, baseline `17c6c05a`)
combined structure, migration, new failure-mode chapters and a new end-to-end
walkthrough in one task. Its Worker returned `blocked` after one Hop with no
change and no CommitIntent; the Run stopped `awaiting_human` with a clean
worktree. The predecessor Commission, Run and evidence stay unchanged.

The work is split into two independently reviewable Commissions.

* *P1* -- `wfc-operator-manual-structure-migration-002` (supersedes the
  prepared, never launched `...-001`): establish `docs/operator_manual/` and
  move the operator manual, operator guide, run-preparation and
  self-development content into it, leaving pointer stubs. No new
  failure-recovery chapters, no new walkthrough, and `run-recovery-and-salvage.adoc`
  and the successor-continuation runbook are left untouched for P2.
* *P2* -- planned id `wfc-operator-manual-procedures-recovery-002`: built on the
  accepted P1 result.

== P2 scope

P2 adds new, source-verified content inside the manual P1 delivered:

. Failure modes and status semantics: unsatisfiable or overly strict Worker
  acceptance criteria; `blocked` versus `completed` and what each implies for
  CommitIntent admission; `awaiting_human` (semantic versus mechanical stops);
  exact CommitIntent subject rule (Conventional Commit syntax plus WorkItem ID
  and Hop ID tokens) and exact leaf-file path rule, including newly created
  and deleted files and Git rename detection; Coordinator rejection of a
  candidate after a successful provider invocation; the dirty worktree left by
  a failed commit admission; non-interactive provider permission denials;
  model/CLI compatibility and the difference between executable availability
  and effective provider behavior; provider-evidence limits when tool
  transcripts are not persisted; `TMPDIR` and external-scratch behavior.
. Escalation, recovery, successor handling and archiving, as one coherent
  operator procedure. This includes moving the content of
  `docs/run-recovery-and-salvage.adoc` and
  `docs/successor_continuation_runbook_2026-10-10.adoc` into the manual and
  leaving pointer stubs, and replacing P1 material where it is superseded.
. One complete Commission-to-archive walkthrough based on Attempt
  `wfc-claude-haiku-live-smoke-20261110-03` (Commission
  `wfc-claude-haiku-live-smoke-003`, Development commit `aac9ae5c`), showing a
  valid CommitIntent with subject and path representation.
. Validation of every documented behavior against `src/`, `scripts/wfc_op.py`
  and tests.

Out of scope for P2, as for P1: `src/`, `scripts/`, `tests/`, `governance/`
(other than P2's own Commission), Runtime and Evidence repositories, historical
records.

== Admission gate

P2 must not be authored against, prepared on or launched from an unaccepted P1
baseline. Preconditions:

. P1 Run completed through a fresh broad review `accept`, with no blocking
  Finding open.
. P1's final Coordinator-owned commit is identified and every P2 source pin is
  taken from that baseline.
. The maintainer separately authorizes P2 authoring and launch.

== Lessons carried into both Commissions

* `completed` means every acceptance criterion is met; no partial completion.
  If a task is too large, reduce its binding scope instead of weakening result
  semantics. `blocked` carries no CommitIntent.
* Keep acceptance criteria measurable and satisfiable with the Hop's own tools;
  Coordinator evidence (`python -m pytest -q`) is the trusted test gate.
* Superseded files become in-place pointer stubs; no `git mv` or delete in the
  same Hop as similar new files (rename detection can fail commit admission).
