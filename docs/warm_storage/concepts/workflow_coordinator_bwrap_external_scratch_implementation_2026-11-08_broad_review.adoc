== Substitution surface: the bind is genuinely restricted to one root

The source can only come from `validate(..., external_scratch=...)`. A
directly constructed `Mount` carrying `MountMode.EXTERNAL_SCRATCH` is
rejected unconditionally at the top of the mounts loop
(`execution_boundary.py:108-110`), before destination, source, or mode
handling -- so the enum member exists only as a typed trap, never as a usable
`Mount` mode. Probed independently; every attempted substitution route was
rejected before any subprocess:

* `Mount(repo_subdir, /repo/w, EXTERNAL_SCRATCH)` ->
  `external scratch mounts must be requested via the external_scratch
  parameter, not constructed directly`.
* The same forged mount alongside a legitimate `external_scratch=` ->
  same rejection (the parameter is not an escape hatch for the mounts list).
* An ordinary `WRITABLE` mount aimed at the external destination,
  `Mount(repo_subdir, /tmp/s, WRITABLE)` -> rejected by the pre-existing
  destination-overlap rule, `overlapping destinations: /tmp/s`.
* Any out-of-repository `READ_ONLY`/`WRITABLE` source still hits the
  unchanged `source.relative_to(repository)` rule
  (`execution_boundary.py:124-127`), and the destination must still equal
  `/repo/<relative>` (`:128-129`). The repository-only bind-source rule is
  provably unchanged for every other mount kind.

`build_argv()` still revalidates (`:163`) and now passes
`external_scratch=boundary.external_scratch`, so a hand-forged
`ValidatedBoundary` cannot smuggle a root past validation. Verified by
constructing `ValidatedBoundary(..., external_scratch=X)` directly for
`X in {relative path, nonexistent path, /usr, a regular file}` and calling
both `build_argv()` and `run()`: each raised `BoundaryConfigurationError`
(`source must be an absolute real path`, `source does not exist`,
`external scratch root overlaps a system mount`, `external scratch root must
be a directory`) with no subprocess spawned.

== Fail-closed behaviour for every named invalid configuration

Independently observed rejections (all `BoundaryConfigurationError`, all
before any spawn):

[cols="2,3"]
|===
|Configuration |Observed rejection

|external root is a parent of the repository |`external scratch root overlaps the repository`
|external root equals the repository |`external scratch root overlaps the repository`
|external root inside a repository subdir |`external scratch root overlaps the repository`
|external root `= /` |rejected (overlap)
|external root `= /usr` (system root) |`external scratch root overlaps a system mount`
|external root is a relative path |`source must be an absolute real path`
|external root is a symlink |`source must be an absolute real path`
|external root does not exist |`source does not exist`
|external root is a regular file |`external scratch root must be a directory`
|hardlinked regular file inside the root |`writable entry has hardlink aliases: .../ext/alias`
|hardlinked FIFO inside the root |`writable entry has hardlink aliases`
|forged `EXTERNAL_SCRATCH` mount (one or two) |`...must be requested via the external_scratch parameter...`
|external scratch with no private scratch |`exactly one private scratch mount is required`
|===

The ordering of checks matters and is correct: the
exactly-one-private-`/tmp`-scratch invariant is evaluated *before* the
external-scratch block (`:137-140`), so the external bind can never stand in
for the private tmpfs. `_check_writable_aliases()` is applied to the external
root with exactly the discipline every other writable grant already requires
(`:156`), including under revalidation inside `build_argv()`/`run()`. There
is no unsandboxed fallback anywhere: `run()` executes only
`build_argv(...)`, which revalidates first.

"More than one external scratch mount" is structurally impossible rather than
merely checked: the only channel is a single optional parameter. The
committed unit test asserts the rejection of the only expressible attempt
(two forged `EXTERNAL_SCRATCH` mounts). I regard the typed impossibility as
stronger than a count check and accept it.

== Mount ordering actually nests the bind inside the private tmpfs

Not accepted from argv shape. Observed with a real sandboxed subprocess, with
the `SCRATCH` mount placed *first* in the mounts sequence and a writable
repository mount after it, to defeat any accidental dependence on caller
ordering:

----
... --tmpfs /tmp --bind <ext_root> /tmp/s --chdir /repo -- ...
----

Inside the sandbox: `stat -c %d /tmp` = 62 (the private tmpfs) while
`stat -c %d /tmp/s` = 35, the same device as the host-backed writable bind.
`/tmp/s` is therefore a distinct, host-backed mount nested *inside* the
private tmpfs, not shadowed by it and not racing it. `printf ext > /tmp/s/f`
appeared on the host at `<ext_root>/f`; `printf priv > /tmp/p` did not appear
at `<ext_root>/p`. The `build_argv()` append happens after the mounts loop
(`:178-181`), so this holds for any caller-supplied mount order.

== Non-blocking observations

Recorded for the future wiring WorkItem; none is a blocking Finding and none
is in this Commission's scope to fix.

* Two branches of the external-scratch overlap check are unreachable through
  the public API and therefore untested: overlap with another mount's
  *destination* (any `/tmp` subtree destination is already rejected by the
  pre-existing destination-overlap rule, confirmed by probe) and overlap with
  another mount's *source* (all other sources must be repository-internal,
  which the repository-overlap check already covers). They are harmless
  defence in depth. The required-test item is satisfied by the reachable
  cases.
* `validate()` applies no classification model to the designated root beyond
  repository, system-root, and other-mount overlap, which is exactly what the
  Commission authorizes and what its withheld authority forbids extending.
  Consequently `/opt` and `/srv` are accepted as external scratch roots in
  this environment, and `/etc` and `/var` are rejected only incidentally, by
  `cannot inspect writable source` permission errors during the alias scan
  rather than by policy. Designation authority rests with the caller, and no
  live caller exists in this WorkItem; whichever WorkItem wires this in owns
  choosing and justifying a single WFC-controlled root.
* `_check_writable_aliases()` walks the entire external root. For a
  large-capacity scratch tree this is an O(entries) cost on every `validate()`
  and again on every `build_argv()` revalidation. The same TOCTOU caveat the
  module header already states applies; no new weakness, but relevant to
  sizing the eventual real scratch root.
* The `EXTERNAL_SCRATCH` enum member is never a legal `Mount.mode`. That is
  deliberate and fail-closed, and the comment at `:30-32` explains the fixed
  destination; worth keeping in mind if the enum is ever iterated over.
