=== Blocking Finding 2 -- `ch03_running/01_preparation.adoc`'s normative contract still requires `launch.sh` and an OPS envelope

The same page's generic, *normative* contract was left with the Harness's
own artifacts, while its steps 4/5 and its illustrative shape were amended.
The result contradicts both the page's own retirement subsection and the
model page this Run rewrote:

* `[[three-boundaries]]`, second boundary (lines 52-57, 64-65): "`launch.sh`
  execution:: Only the maintainer's explicit execution of `launch.sh` enters
  the provider-capable execution path ... Executing `launch.sh` does not
  itself cross the provider boundary". Nothing produces `launch.sh` any
  more; the corresponding act is `wfc run ... --yes`.
* `[[deterministic-preparation]]` (lines 72-75): preparation is defined as
  "exporting pinned commits, creating virtual environments, installing
  frozen exports, ... and writing `launch.sh`" -- the exact provisioning
  DG-5 removed and which amended step 4 now says WFC "does not export,
  build, or otherwise provision".
* `[[ops-and-state]]` (lines 85-94): the OPS root "comes to contain the
  Runtime export/environment, the target/evidence export/environment,
  `execution-bindings.yaml`, preparation logs, and `launch.sh`", while the
  rewritten `ch01_orientation/01_model.adoc` deletes OPS from the identity
  model entirely and says "There is no separate 'prepared but not yet
  launched' directory distinct from the checkout itself".
* canonical sequence step 9 and the closing paragraph (lines 121, 124-128):
  ". Materialize deterministic `launch.sh`." / "Only the maintainer's
  explicit execution of `launch.sh` ...".
* `[[target-export-rule]]` (lines 135-143): "Current preparation practice
  ... deriv[es] that environment from a `git archive`/export of the exact
  pinned target baseline commit", the opposite of amended step 5.

The page is `Authority:: normative` and is the contract every other chapter
defers to, so the stale half is not harmless background: it is the manual's
authoritative definition of what preparation is. The Worker's own rewrite of
the illustrative shape ("materialize the deterministic launch record and
stop") shows the intended generalization; it was simply not carried into the
boundary, OPS, step-9 and export-rule text.

*Correction shape (bounded):* generalize these five places the same way the
illustrative shape was generalized -- the second boundary is the explicit
`wfc run` authorization/launch confirmation; the OPS paragraph becomes the
checkout's own journal/`commission/`/`engine-state` layout already described
in `ch01_orientation/01_model.adoc`; step 9 becomes materializing the
journaled launch record; and the target-export rule is marked as the
historical, Harness-era strengthening it now is (or restated as the DG-5
consumer-provided-environment requirement). No generic-contract semantics
need to change.

=== Blocking Finding 3 -- `ch07_diagnostics/02_failure_modes.adoc`'s "current scratch layout" still describes the Harness allocator and its removed flag
