=== Non-blocking observations

. *Two `ext.archive.result` details are unpinned.* Mutation `N1` (deleting
  the `journal.append("ext.archive.intent", ...)` call, required by `Deliver`
  item 2 *before* the archive effect) and `N2` (hard-coding
  `"retention": "local"` instead of `settings.raw`, so `wfc status` would
  misreport the mode for a `commit` or `discard` consumer) both survive the
  whole BP6c suite. The shipped product does both correctly, and the
  acceptance list pins the intent record only negatively (absent when no
  archive happens) and retention only through `git ls-files`; two short
  assertions in `test_postrun_lifecycle.py` would close the gap.
. *A tampered placed `audit.json` whose top level is `null` or a JSON array
  crashes `wfc resume` with an uncaught `AttributeError`.*
  `postrun._read_report_text` guards `OSError`/`ValueError` around
  `json.loads` but then hands whatever it parsed to `report.build_report`,
  which calls `.get` on it. Every realistic tamper shape fails safe instead
  -- an empty file, invalid JSON and a truncated object all give exit 0 with
  a truthful `status is unknown -- not reported as success` report -- and the
  crash is unreachable without rewriting the package's own committed output
  into a non-object, which is outside every boundary the acceptance list
  names. A single `isinstance(audit_doc, dict)` check would remove it.
  Relatedly, `postrun._cached_config` reads and parses the checkout's cached
  Consumer Config outside any `try`: a corrupt or deleted
  `<checkout>/commission/config.yaml` makes `wfc resume` exit 22
  (`refused_prelaunch`) printing no classification for a Run the journal
  records as `completed` -- the F001 shape at a boundary F001's two named
  triggers did not cover. It needs state-home corruption to reach, and BP4a's
  own frozen stages read that same file just as unguarded, so this is
  consistency with the frozen design rather than a new defect; the
  limitations record's claim that the step is caught "at every call site that
  can raise them" is nonetheless slightly broader than the code.
. *Carried forward from H002, still accurate.* A `repository_name` beginning
  with `.` or `_` derives an identity
  `validate_explicit_attempt_identity` rejects, so archiving refuses
  permanently with `archive_refused` (observation 1 of H002, re-reproduced in
  `p02_identity.py`); the OS user name occurring as a whole token of
  `repository_name` refuses permanently with `privacy_guard_refused`
  (observation 2); and a hyphenated or dotted OS user name
  (`gitlab-runner`, `stefan.schade`) can match only as a whole path component
  or whole value, never as a free token in prose, because `_TOKEN_RE` splits
  on `-` and `.` (observation 3). All three fail closed, all three follow the
  maintainer-specified rule literally, and the acceptance-named real-leak
  case is still refused.
. *The set of plausible OS account names that now cause a false refusal is
  small and structural.* Against a complete product-path `audit.json`
  (`raw: commit`, `interrupted`, preservation `result`), the only names out of
  fifty tested that still refuse are ones equal to an audit schema key or a
  fixed structural token: `schema`, `run`, `governance`, `hops`, `findings`,
  `lifecycle`, `raw`, `limits` (matched as a `<key>`) and `wfc` (matched
  inside `refs/wfc/preserved/...`). `ci`, `ops`, `dev`, `build`, `runner`,
  `jenkins`, `git`, `deploy`, `ubuntu`, `gitlab-runner` and the rest are all
  accepted. These residual collisions fail closed, never leak, and are
  outside the acceptance list's "short OS user name (for example `ci` or

=== Blocking Finding F-A: an unhandled post-run failure reports a completed Run as `refused_prelaunch`

`frontdoor/postrun.py` guards only the archive call, and only against four
exception types:

[source,python]
----
    except (archive.ArchiveError, audit_module.ProjectionError,
            audit_module.AuditError, GitPreflightError) as error:
----

`_cached_config`, `resolve_evidence`, every filesystem operation inside
`archive_run` and `_read_report_text`'s report construction can raise outside
that set. Because `run_lifecycle`/`resume_lifecycle` call the step *after*
they already hold the engine's classification, such an exception propagates
out of the lifecycle entry point and is swallowed by `cmd_run`'s own
`except (LifecycleError, CommissionError, GitPreflightError, JournalError,
OSError)` clause, which then reports `getattr(error, "classification",
"refused_prelaunch")`.

Reproduced twice, independently:

[cols="1,3"]
|===
|Trigger |Observed

|Evidence repository directory not writable by the running user (a shared or
root-owned Evidence location, a read-only mount; `staging =
identity / ".wfc-archive-staging" / attempt_id` is created inside it)
|`wfc run: [Errno 13] Permission denied: .../evidence/.wfc-archive-staging`;
`cmd_run` returns *22*; the journal holds
`classified{classification: completed}` and *no* `ext.archive.*` record at
all; the classification is never printed.

|Consumer Config without an `evidence` block (the `wfc init` default) and no
`HOME`/`XDG_DATA_HOME`, with `XDG_STATE_HOME` set (a hardened CI runner)
|`CommissionError: cannot resolve the default Evidence location: HOME is not
set` escapes `run_lifecycle`; journal `classified = completed`, no
`ext.archive.*` record.
|===

This is a reproduced violation of acceptance case (5) ("archive/audit failure
or privacy-guard refusal: `ext.archive.refused`, additive `archive_failed`
exit code, engine classification unchanged") and of `Deliver` item 3 ("the
engine outcome stands, the classification is unchanged and printed, `wfc
resume` retries the step ... the step never converts ... a completed Run into
a failure of the engine outcome"): exit 22 is both a BP4a code with an
entirely different meaning and a false report about the engine outcome.

Required outcome (implementation choice is the Worker's): every failure of
the post-run step -- including the configuration resolution and the ordinary
`OSError` surface of a filesystem/Git operation -- is recorded as
`ext.archive.refused{reason_code}`, reported through
`ARCHIVE_FAILED_EXIT_CODE` with the engine classification printed unchanged,
and retried by `wfc resume`; with a mutation-sensitive test for at least one
such failure. `KeyboardInterrupt`/`SystemExit` must keep propagating.

=== Non-blocking observations

. *A `repository_name` starting with `.` or `_` disables archiving
  permanently.* `postrun._attempt_identity` strips only `-`, so
  `_private-repo` and `.hidden-repo` derive identities that
  `validate_explicit_attempt_identity` rejects: every `run`/`resume`
  refuses with `archive_refused` and exit 32 until the Consumer Config is
  edited. Fail-closed, loud and outside the acceptance list; a one-character
  change to the strip set would remove it.
. *The OS user name as a whole token of `repository_name` disables archiving
  permanently.* The new Run-derived identity puts `repository_name` into the
  audit's own `attempt_id`, where the (maintainer-specified) whole-token rule
  matches it: with OS user `stefan` and `repository_name: stefan-notes`,
  every archive refuses with `privacy_guard_refused`. The same holds for the
  very names item 5 was written for (user `ci` + `ci-pipeline`, user `ops` +
  `ops-tools`). The implementation follows item 5 literally; worth a
  maintainer decision on whether the caller-supplied identity should be
  exempt from token matching, or validated at `wfc init`.
. *A hyphenated OS user name can no longer match as a token.* `_TOKEN_RE`
  splits on `-`, so a user name such as `ci-user` is matchable only as a
  whole path component. The real-leak case the acceptance list names (a path
  component) is still refused.
. *`audit.lifecycle.preservation.reason_code` carries BP4b's free text.* For
  example `preservation path is outside authorized scope: GUIDANCE.md`. BP4b's
  record is frozen and the privacy guard still fails closed on anything
  path-shaped, so this is a field-naming observation only -- but a Git
  stderr-derived refusal reason containing `HOME` would turn a `stopped` Run
  into an `archive_failed`.
. *`ext.archive.skipped` is appended on every call while the Evidence
  repository is absent.* Intentional per the limitations record (nothing is
  cached before success), at the cost of unbounded journal growth for a
  checkout that is resumed repeatedly.
. *No test pins that `wfc status` performs no write while the step is
  pending.* Mutation M12 (making `cmd_status` call `run_pending_postrun`)
  survives, because the only `cmd_status` test runs after a successful
  archive, where the step is a cached no-op. `status_lifecycle`'s read-only
  property is pinned.
. *The `engine_exited_before_state` exclusion is redundant.* Mutation M10
  (adding it to `_ARCHIVABLE_CLASSIFICATIONS`) survives, because that
  classification never carries a `run_id` and the `not run_id` guard already
  returns `absent`. Acceptance case (3) holds either way.
. *The limitations record slightly overstates the `resolve_ops_dir`
  narrowing* as changing "no existing behavior": it changes no in-tree
  fixture's behaviour, but it does narrow the recorded-OPS refusal for any
  Run whose plan names a differently-named bindings leaf.
. *Pre-existing environmental test failures.* `test_wfc_op.py` (pip cannot
  reach `setuptools>=68` without the offline wheel bundle),
  `test_claude_adapter_conformance.py` (fixture executable launch refused in
  this sandbox) and `test_bp1_identity.py` fail identically on the baseline
  tree; none of them touch a file this candidate changes. Agent-side runs
  were `--wfc-partial` and are not required-suite acceptance.
