== `F001`: resolved

=== The reproduction, rebuilt independently

`H002` reported the defect from in-process reasoning plus three controller
processes. This Hop rebuilt the reproduction from scratch as a *real crash*,
because the invariant at stake -- acceptance case (6), "crash before the
Commission commit: resume commits exactly once" -- is about surviving process
death, not about an exception being caught.

The driver authorizes, runs pre-launch and the baseline probe, enters
`_do_commit`, and then hard-kills the process with `os._exit(137)` at the exact
instant `bounded_path_commit` would have been called: after
`commission_commit_intent` is journaled and after the compiled Commission and
request file are materialized in the worktree, before any commit exists.
Nothing is unwound, no `finally` runs, the lock file descriptor dies with the
process. A second, fresh process then invokes the installed `wfc resume` entry
point.

=== Against the pre-correction code the reproduction fails

`src/workflow_coordinator/frontdoor/lifecycle.py` and `frontdoor/cli.py`
restored from `1a2fede` (read-only `git show`), everything else at the review
base:

----
CRASH: hard exit at the bounded_path_commit call site
wfc resume: refusing to overwrite existing compiled file: .wfc/governance/bp4-crash/work-item.yaml
RESUME_EXIT=22
COMMISSION_COMMITS=0
STATUS_PORCELAIN='?? .wfc/governance/'
----

Exit 22 is `refused_prelaunch` -- the `getattr(error, "classification",
"refused_prelaunch")` default in `cmd_resume`, because `CommissionError` is not
a `LifecycleError` and carries no classification. Zero Commission commits
exist, and the lifecycle cannot progress. The reproduction is therefore not
vacuous: it genuinely fails against the code `H002` reviewed.

=== The fix does not weaken the invariant it relaxes

`_materialize_commission` (`lifecycle.py:432-449`) replaces
`compiled.write_to(repository, overwrite=False)` plus the separate request
write. It is a faithful re-expression of
`CompiledCommission.write_to` (`commissioning.py:655-663`) over
`compiled.texts` plus the request leaf, with one relaxation: a destination that
already exists with *byte-identical* content is a no-op instead of a refusal.
Anything else raises `LifecycleError(classification="inconsistent")`.

Three checks that the relaxation is safe:

. *It is not reachable outside the crash window.* `_do_prelaunch`
(`lifecycle.py:327-331`) refuses unless `observe_repository(...).clean`, and
`GitFacts.clean` (`git_facts.py:45-46`) is false when there is any non-ignored
untracked path. A fresh `wfc run` with a pre-planted `.wfc/governance/...`
tree is refused at pre-launch with `refused_prelaunch` before materialization
is ever entered. The relaxed path is reachable only on `resume`, where
`prelaunch_passed` and `probe_passed` are already journaled -- i.e. precisely
the crash window.
. *Identical content changes nothing that gets committed.* The tolerated bytes
are by definition the bytes the controller would otherwise have written, and
the authorized Commission digest is re-checked first (`lifecycle.py:459-463`,
`refused_drift`) so a drifted Commission never reaches materialization.
. *Non-identical leftovers still refuse, and do not auto-clean.* Verified by
crashing as above, then appending one comment line to an already-materialized
leaf, then resuming:
+
----
TAMPERED=.wfc/governance/bp4-crash/components.yaml
wfc resume: unexpected content already present at .wfc/governance/bp4-crash/components.yaml; refusing to overwrite
RESUME_EXIT=18
COMMISSION_COMMITS=0
STATUS_PORCELAIN='?? .wfc/governance/'
----
+
Exit 18 is the documented `inconsistent` code, no commit is created, and the
controller does not clean the tree -- consistent with the task's "never
auto-cleaned" rule.

== Non-blocking observations

Recorded for the maintainer. Neither is proposed as a Finding and neither
blocks acceptance.

=== O1: argparse prefix abbreviations of `--state-root` no longer reach the operator

As the table above shows, `wfc status --state-ro <path>` and the other
unambiguous prefix abbreviations of `--state-root` were accepted by the legacy
operator at baseline (argparse's `allow_abbrev` is on by default, including for
the `status` subparser at `operator.py:280-281`) and now hit the new lifecycle
status, which rejects them with a usage error and exit 2.

Not raised as blocking, for three reasons. The failure is loud and inert -- a
usage error, no lifecycle effect, nothing silently misdispatched. Acceptance
case (19) names the option `--state-root`, whose two standard, guaranteed
spellings both behave as at baseline after the correction; prefix abbreviation
is an argparse convenience that is itself unstable under any future option
addition. And the clean fix is to set `allow_abbrev=False` on the legacy
parser, which is in `operator.py` -- explicitly withheld from this Commission;
approximating argparse's abbreviation algorithm inside the `cli.py` guard would
be worse than the problem. This is a maintainer design call, best taken
together with BP7.

=== O2: a non-UTF-8 leftover at a Commission destination escapes as a traceback

`_materialize_commission` reads a pre-existing destination with
`destination.read_text(encoding="utf-8")` (`lifecycle.py:442`). If that file is
not valid UTF-8, the resulting `UnicodeDecodeError` is a `ValueError`, which
`cmd_resume`'s `except (LifecycleError, CommissionError, GitPreflightError,
JournalError, OSError)` does not catch. Reproduced by crashing at the
materialization boundary, overwriting one materialized leaf with `b"\xff\xfe
not utf-8 \x00"`, and resuming: a traceback instead of the documented
`inconsistent` exit 18.

The safety invariant still holds -- it refuses, creates no commit, dispatches
no provider and mutates nothing -- so only the exit code and the message
quality degrade, on a path that requires planting a non-UTF-8 file at an exact
Commission destination inside the crash window. It is also not a class the
correction invented: `_do_commit` already reads the cached request and config
with `read_text(encoding="utf-8")` at `lifecycle.py:453-454` with the same
exposure, present since `H001` and unflagged by the broad review. Wrapping the
comparison read in `except (OSError, ValueError)` and raising
`classification="inconsistent"` would close it.

== Scope of this review

This Hop verified the `H003` correction and that it did not disturb the
invariants `H002` had reproduced -- the latter largely by showing that the
touched surface is four files with pure-addition test diffs and no engine or
Git-primitive change. A full fresh adversarial pass over the whole controller
(engine boundary, every crash-matrix case against a mutation,
launch-uncertainty rules, lock inheritance, BP4b independence) against the
corrected HEAD is what the requested `renew_broad_review` route exists for and
is not claimed here.
