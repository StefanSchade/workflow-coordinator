== `H007`: `F003` resolved

=== The reproduction, rebuilt independently and at the real boundary

`F003` is about an instruction window *inside* the unmodified
`bounded_path_commit`: between its own real `git add` (`git_facts.py:879`) and
its `git commit` (`git_facts.py:893`). The candidate's own regression test
reaches that window by substitution. This Hop deliberately did not reuse it.
Instead the window was reproduced with real processes end to end:

* a disposable consumer repository built from scratch, its Consumer Config
created through the installed `frontdoor.cli` `init` command and committed by
the harness (never implicitly by the controller);
* the Consumer Request authored *outside* the repository, and the lifecycle
journal root in an external `XDG_STATE_HOME`, disjoint from the repository;
* the crash injected by wrapping `git_facts._trusted_git` so that the *real*
Git command runs first and the process then dies with `os._exit(137)` the
instant the real `git add` returns. `os._exit` is unmaskable: no exception
propagates, no `finally` runs, no lock is released, the process simply ends;
* every subsequent command run as a brand-new process through
`frontdoor.cli:main`.

=== Why the relaxation does not weaken anything

. *It is unreachable outside the crash window.* `_do_prelaunch` refuses unless
`observe_repository(...).clean` (`lifecycle.py:330-331`), and `GitFacts.clean`
(`git_facts.py:43-45`) is computed from `git status --porcelain=v1
--untracked-files=all` (`git_facts.py:502-509`), which reports staged index
entries as tracked changes. A fresh `wfc run` against a repository with any
pre-staged state is therefore refused at pre-launch before `_do_commit` is
entered. The reconciler is reachable only on `resume`, where
`prelaunch_passed` and `probe_passed` are already journaled -- precisely the
crash window.
. *It sees exactly the set the trusted primitive refuses on.* The listing
command is `git diff --no-ext-diff --cached --name-only`
(`lifecycle.py:463`), identical in form to `git_facts._staged_paths`
(`git_facts.py:465-471`), whose non-empty result is what raises
`TrustedCommitError("pre-existing staged state")` (`git_facts.py:868-869`).
There is no divergent view between reconciler and primitive, so the reconciler
cannot unstage something the primitive would not have seen, and cannot leave
staged something the primitive would have accepted.
. *Every deviation fails closed, by name, with no auto-clean.* A staged path
that is not one of this lifecycle's own expected leaves, a staged path that
already exists at `base_head`, or a staged blob whose bytes differ from the
authorized expected text each raise
`LifecycleError(classification="inconsistent")` naming the path
(`lifecycle.py:466-482`); `inconsistent` is exit 18 in the documented table
(`lifecycle.py:116`). The authorized Commission digest is re-checked before
any of this (`lifecycle.py:493-497`, `refused_drift`), so a drifted Commission
never reaches reconciliation at all.
. *Nothing in the worktree is discarded.* `git reset -q HEAD -- <paths>`
(`lifecycle.py:483`) rewrites index entries from HEAD only; the materialized
Commission files stay on disk and are exactly what the unmodified
`bounded_path_commit` then re-stages and commits -- confirmed by the single
resulting commit above.
. *The primitive is neither modified nor re-implemented.* The controller
restores the clean index the unmodified `bounded_path_commit` requires and
then calls it normally. `git_facts.py` is byte-identical to baseline.

== `H007`: non-blocking observations

Recorded for the maintainer. Neither is proposed as a Finding and neither
blocks acceptance. `O1` and `O2` from the `H004` record below are unaffected

=== O3: the reconciler's `git reset` uses ordinary Git policy, not the hardened helper

`_reconcile_stray_staged_state` is the controller's only *mutating* Git call
outside `bounded_path_commit`, and it issues it through `lifecycle._git`
(`lifecycle.py:188-192`), which runs `git` with the ambient environment, rather
than through `git_facts._trusted_git` (`git_facts.py:352-370`), which strips
inherited routing/configuration controls, points hooks at `/dev/null` and
disables signing and fsmonitor. No concrete exposure was found: `git reset
--mixed <paths>` runs no hook and applies no clean/smudge filter when
restoring index entries from HEAD, and `bounded_path_commit` re-checks
configured external filters immediately afterwards (`git_facts.py:843-847`).
The house rule in `_trusted_git`'s own docstring is that read-only observation
keeps ordinary Git policy; an index mutation is not read-only, so a maintainer
may prefer the hardened environment here. `_trusted_git` is private to
`git_facts.py`, so doing so cleanly would mean touching a withheld module --
which is why this is an observation and not a correction request.

=== O4: refused resumes accumulate unterminated `commission_commit_intent` records

Each re-entry of `_do_commit` appends a fresh `commission_commit_intent`
(`lifecycle.py:505`) before the checks that may refuse, so a repeatedly
refused lifecycle accumulates intents with no completion record -- three of
them in the reproduction above. This is harmless today: nothing reads that
count, unlike `launch_intent`, which `_continue_after_launch` counts for the
bounded relaunch rule (`lifecycle.py:818-823`). It is noted only because a
human reading the journal sees three unterminated intents for one commit, and
because any future rule that counts commit intents would inherit the
ambiguity.

== `H004`: `F001` resolved

=== The reproduction, rebuilt independently

`H002` reported the defect from in-process reasoning plus three controller
processes. This Hop rebuilt the reproduction from scratch as a *real crash*,
because the invariant at stake -- acceptance case (6), "crash before the
Commission commit: resume commits exactly once" -- is about surviving process
death, not about an exception being caught.

The driver authorizes, runs pre-launch and the baseline probe, enters
`_do_commit`, and then hard-kills the process with `os._exit(137)` at the exact
instant `bounded_path_commit` would have been called: after
`commission_commit_intent` is journaled and after the compiled Commission and
request file are materialized in the worktree, before any commit exists.
Nothing is unwound, no `finally` runs, the lock file descriptor dies with the
process. A second, fresh process then invokes the installed `wfc resume` entry
point.

=== The fix does not weaken the invariant it relaxes

`_materialize_commission` (`lifecycle.py:432-449`) replaces
`compiled.write_to(repository, overwrite=False)` plus the separate request
write. It is a faithful re-expression of
`CompiledCommission.write_to` (`commissioning.py:655-663`) over
`compiled.texts` plus the request leaf, with one relaxation: a destination that
already exists with *byte-identical* content is a no-op instead of a refusal.
Anything else raises `LifecycleError(classification="inconsistent")`.

Three checks that the relaxation is safe:

. *It is not reachable outside the crash window.* `_do_prelaunch`
(`lifecycle.py:327-331`) refuses unless `observe_repository(...).clean`, and
`GitFacts.clean` (`git_facts.py:45-46`) is false when there is any non-ignored
untracked path. A fresh `wfc run` with a pre-planted `.wfc/governance/...`
tree is refused at pre-launch with `refused_prelaunch` before materialization
is ever entered. The relaxed path is reachable only on `resume`, where
`prelaunch_passed` and `probe_passed` are already journaled -- i.e. precisely
the crash window.
. *Identical content changes nothing that gets committed.* The tolerated bytes
are by definition the bytes the controller would otherwise have written, and
the authorized Commission digest is re-checked first (`lifecycle.py:459-463`,
`refused_drift`) so a drifted Commission never reaches materialization.
. *Non-identical leftovers still refuse, and do not auto-clean.* Verified by
crashing as above, then appending one comment line to an already-materialized
leaf, then resuming:
+
----
TAMPERED=.wfc/governance/bp4-crash/components.yaml
wfc resume: unexpected content already present at .wfc/governance/bp4-crash/components.yaml; refusing to overwrite
RESUME_EXIT=18
COMMISSION_COMMITS=0
STATUS_PORCELAIN='?? .wfc/governance/'
----
+
Exit 18 is the documented `inconsistent` code, no commit is created, and the
controller does not clean the tree -- consistent with the task's "never
auto-cleaned" rule.

=== O1: argparse prefix abbreviations of `--state-root` no longer reach the operator

As the table above shows, `wfc status --state-ro <path>` and the other
unambiguous prefix abbreviations of `--state-root` were accepted by the legacy
operator at baseline (argparse's `allow_abbrev` is on by default, including for
the `status` subparser at `operator.py:280-281`) and now hit the new lifecycle
status, which rejects them with a usage error and exit 2.

Not raised as blocking, for three reasons. The failure is loud and inert -- a
usage error, no lifecycle effect, nothing silently misdispatched. Acceptance
case (19) names the option `--state-root`, whose two standard, guaranteed
spellings both behave as at baseline after the correction; prefix abbreviation
is an argparse convenience that is itself unstable under any future option
addition. And the clean fix is to set `allow_abbrev=False` on the legacy
parser, which is in `operator.py` -- explicitly withheld from this Commission;
approximating argparse's abbreviation algorithm inside the `cli.py` guard would
be worse than the problem. This is a maintainer design call, best taken
together with BP7.

=== O2: a non-UTF-8 leftover at a Commission destination escapes as a traceback

`_materialize_commission` reads a pre-existing destination with
`destination.read_text(encoding="utf-8")` (`lifecycle.py:442`). If that file is
not valid UTF-8, the resulting `UnicodeDecodeError` is a `ValueError`, which
`cmd_resume`'s `except (LifecycleError, CommissionError, GitPreflightError,
JournalError, OSError)` does not catch. Reproduced by crashing at the
materialization boundary, overwriting one materialized leaf with `b"\xff\xfe
not utf-8 \x00"`, and resuming: a traceback instead of the documented
`inconsistent` exit 18.

The safety invariant still holds -- it refuses, creates no commit, dispatches
no provider and mutates nothing -- so only the exit code and the message
quality degrade, on a path that requires planting a non-UTF-8 file at an exact
Commission destination inside the crash window. It is also not a class the
correction invented: `_do_commit` already reads the cached request and config
with `read_text(encoding="utf-8")` at `lifecycle.py:453-454` with the same
exposure, present since `H001` and unflagged by the broad review. Wrapping the
comparison read in `except (OSError, ValueError)` and raising
`classification="inconsistent"` would close it.
