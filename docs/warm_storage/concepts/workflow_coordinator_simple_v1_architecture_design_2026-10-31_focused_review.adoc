== 3. Finding dispositions

=== 3.1 F001 -- Worker-reported failure is representable

Disposition:: *Resolved.*

The correction no longer selects Work-result v1 for Simple.  It identifies the
current `WorkStatus` limitation and instead selects existing generic routing v1
only for the exact closed Simple shape (design lines 69-82, 141-146, 213-230,
261-313).  This is mechanically representable:

* generic strict projection includes `Outcome.FAILED`
  (`codex_adapter.py:197-205`);
* `routing_result_from_data` parses it (`serialization.py:1214-1287`);
* persisted result-family identity makes reducer/replay disagreement fail
  closed (`reducer.py:1541-1581`); and
* `Outcome.FAILED` stops at `result_failed` before route or Finding proposals
  can take effect (`reducer.py:1660-1663`).

The design explicitly avoids a technical-schema bump, a new result family, and
a silent widening of Work-result v1.  Its focused tests require the dispatched
generic family, a correlated failed result, `result_failed`, and no second
invocation (design lines 356-359).  The implementation scope now includes the
model selector and adapter-facing tests (lines 386-398).

One wording precision is non-blocking: line 146 says only `completed` may
_request_ `accept`, while generic routing v1 requires `requested_route` for
every outcome and the sole enum value is `accept`.  Mechanically, a failed or
blocked result carries that inert route value, and the reducer stops it before
route application (`reducer.py:1660-1663, :1738-1740`).  The enforceable claim
is therefore that only completed can have `accept` applied.  The surrounding
contract and required tests use that safe behavior and do not depend on a
conditional route field, so this imprecision does not reopen F001.

=== 3.2 F002 -- failed provider transport controls valid leftover candidates

Disposition:: *Resolved.*

The correction identifies the exact present hole and requires an immediate
guard after `adapter.execute`: either nonzero `returncode` or `timed_out` raises
`ExecutionResultValidationError` before candidate parsing, trusted commit,
evidence, `record_hop`, or reduction (design lines 90-99, 172-186, 279-284,
315-319).  This is the correct lifecycle boundary.  It makes the transport fact
controlling even when the candidate bytes are otherwise valid.

The selected recovery behavior is already available and preserves the
one-invocation contract: `run_real_one_hop` catches that exact exception and
calls `recover_uncertain` (`slice4.py:390-391`); recovery observes the repository,
records an uncertain dispatch and checkpoint, retains the marker, and returns
without another adapter call (`:332-354`).  The correction does not misclassify
the leftover candidate as Worker failure or qualifying evidence.

The negative tests now separately require nonzero-with-valid-correlated-
candidate and timeout-with-valid-correlated-candidate cases.  Each must prove
no trusted commit, evidence, or completion reduction, exactly one charged
provider call, retained recovery state, and transport diagnostics (design lines
364-369).  That directly closes the broad-review counterexample.

=== 3.3 F003 -- the closed programme projects the mandatory self-check

Disposition:: *Resolved.*

The corrected programme selects `[simple-self-check]` as its sole modifier
(design lines 112-139).  The proposed immutable component text requires the
bounded self-check before the sole result, distinguishes task failure from an
authority/dependency block, and explicitly does not claim trusted evidence.
This makes self-check programme-declared behavior rather than optional task
prose.

The future scope includes the new prompt, component-manifest entry, literal
Simple record, compiler requirement, and normal source digest/equivalence
protection (design lines 266-270, 336-339, 386-395).  The tests reject a
missing/altered component or digest, assert its presence in the dispatched
Simple prompt, and assert unchanged Direct/Robust projection (lines 346-351).
The shared Worker component and both existing programme revisions remain
untouched.

== 4. Complete nine-point mandate ledger

[cols="2,5",options="header"]
|===
|Mandate |Focused-review result

|Exactly one agent invocation
|Pass.  The one-phase profile has one terminal route and no `goto`, supervisor,
reviewer, retry, or continuation.  `max_autonomous_hops` is one.  The tests
instrument adapter calls separately from the evidence runner and require one of
each; an evidence subprocess is not counted as an agent invocation.

|No undocumented second invocation on failure
|Pass.  Worker block/failure, escalation, mechanical preemption, evidence
failure, and an open blocking Finding stop.  Invalid/missing results and failed
transport enter charged uncertain-dispatch recovery with no replay.  No stated
failure path targets another phase.

|Evidence lifecycle boundary
|Pass.  The selected alternative reuses `vertical.run_one_hop`: provider result,
trusted commit/scope observation, Coordinator evidence, post-evidence repository
check, Hop recording, then reduction.  Evidence failure reaches the existing
fail-closed no-route human stop and cannot apply `accept`.

|Representable and enforceable result/route contract
|Pass.  F001's generic routing v1 selection represents `failed`; persisted
contract identity and strict parsing protect replay; reducer failure, blockage,
human, changes-required, evidence, Finding, and completion guards enforce the
finite outcomes.  No new status or schema is required.

|No FD-08-shaped Finding dead end
|Pass.  The design does not falsely promise an in-Run disposer.  It accurately
allows legacy Finding creation, blocks completion on an open blocker, and makes
human authority or a new Commission the explicit terminal governance boundary.
No second Simple Hop is presented as a correction/disposition path, and P3.5
remains deferred.

|Self-assessment is not trusted evidence
|Pass.  The new component makes the self-check mandatory but agent-attributed.
Prepared command identity, observation, evidence-failure truth, and post-command
repository checks remain Coordinator-owned and controlling.

|Scope, Git, executable, and provenance invariants
|Pass.  Existing Front Door byte equivalence, source digests, clean-HEAD and
scope preflight, trusted commit, allowed-path check, prepared executable/stat
identity, post-evidence cleanliness, and staged execution identity remain in
force.  The transport guard now precedes every candidate-dependent mutation or
qualification step.

|Minimality, P3.5 deferral, and existing revisions
|Pass.  The design adds one closed programme/template/component, two closed
Intent/compiler bindings, one shared exact-shape predicate, one transport guard,
and focused tests.  It adds no orchestration subsystem, evidence type, terminal
state, technical schema, reducer behavior, DSL, registry, or profile migration.
Direct v1, Robust v1, and P3.5 remain unchanged.

|Concrete negative regression tests
|Pass.  The plan now covers result-family failure, both valid-candidate transport
failures, evidence fail/error/not-run, unauthorized paths/intent, malformed
Simple shapes, Findings, prompt provenance, provider interruption, executable
identity, invocation-versus-command counts, and Direct/Robust regression.  The
first dogfood is required to be a bounded real maintenance change with its real
task check.
|===
