== Finding F001 -- resolved

F001's recorded invariant has three clauses. Each is now satisfied by the
H003 correction, verified against the code rather than the commit message.

=== Clause 1: a dedicated external scratch target, no privileged host action, as the ordinary case

`_external_scratch_root()` (`claude_adapter.py:61-77`) takes the first
non-empty ambient `TMPDIR`/`TMP`/`TEMP`, else `tempfile.gettempdir()`, and
then -- this is the correction -- compares `root.resolve()` against
`_SHORT_TMP_ROOT.resolve()` (`:75`) and substitutes
`_WFC_FALLBACK_SCRATCH_ROOT` (`:58`, `Path.home() / ".wfc-claude-scratch"`)
when they coincide. The degenerate case H002 blocked on is therefore
structurally impossible rather than merely unlikely:

* stock Ubuntu/WSL shell with `TMPDIR`/`TMP`/`TEMP` unset ->
  `gettempdir()` returns `/tmp` -> guard fires -> `~/.wfc-claude-scratch`;
* operator-set `TMPDIR=/tmp` (or a symlink resolving there, since the
  comparison is on `resolve()`, not on the raw string) -> same;
* ordinary WFC dispatch -> the launcher's Attempt-scoped
  `TMPDIR`/`TMP`/`TEMP` (FD-08) is used unchanged.

No privileged host action is required in any branch: `~/.wfc-claude-scratch`
is created by the invoking user under their own home, mirroring
`create_attempt_scratch()`'s own unprivileged `~/wfc-scratch` default
(`scripts/wfc_op.py:229`, read-only). Nothing is hardcoded to the FD-08
self-development layout -- the adapter consults the generic ambient
convention, which is exactly the candidate source the Commission authorized
investigating, and degrades to a WFC-owned root when that convention is
absent or degenerate. The controlling record's Round-1/Round-2 live
qualification is what makes the home-rooted fallback safe to grant despite
`denyRead: ["~/"]`: Round 1 failed precisely because a `$HOME`-side target
had *no* corresponding `allowRead`, and Round 2 demonstrated that a scoped
`allowRead`/`allowWrite` naming one dedicated untrusted subpath re-opens
exactly that path and nothing else (controlling record lines 158-199). The
candidate's grant has that shape.

=== Clause 2: a derived-path coincidence or leftover is deterministic, with no escaping non-contract exception and no new accumulation path

The two cleanup steps are now independent through `_remove_scratch_path()`
(`:96-107`), which dispatches on `is_symlink()` and swallows `OSError`, and
is called twice in the `finally` block (`:275-276`). Traced by inspection
over every exit:

* `symlink_to()` raising (the H002 reproduction) is wrapped into
  `ClaudeCliError` (`:255-256`); the `finally` block then sees `tmp_dir` as a
  *directory*, takes the `rmtree` branch, and removes it -- so the
  `IsADirectoryError` that previously replaced the contract exception can no
  longer be raised at all, and the created directory no longer survives. The
  fix is robust beyond the specific guard of clause 1: any future path
  collision degrades to a `ClaudeCliError` plus complete cleanup.
* `real_dir.mkdir()` raising (unwritable root) -> `ClaudeCliError`; both
  `_remove_scratch_path()` calls are no-ops on non-existent paths
  (`is_symlink()` false, `rmtree(..., ignore_errors=True)`), so nothing
  masks the in-flight exception.
* A failure removing the symlink can no longer forfeit removal of the real
  target, which was the mechanism by which H002's accumulation path arose.

Leftover handling (`_supersede_or_reject_leftover()`, `:80-93`, called for
both derived paths at `:223-224`) remains `lstat()`-based, so a leftover
*symlink* is unlinked without ever being followed, and a uid mismatch raises
a clear `ClaudeCliError` naming the path instead of touching it. Genuine
concurrency is safe by construction and independently re-checked here: the
path token is `sha256(run/hop/invocation)[:16]` (`:171-176`), so two
concurrent invocations cannot derive the same pair; the leftover branch is
reachable only for a repeated dispatch of the *same* invocation, which is
the unclean-shutdown case the mandate asks to be handled deterministically.
Ordering is also correct for that case: `real_dir` is superseded first, which
merely leaves the leftover `tmp_dir` symlink dangling, and `lstat()` still
succeeds on a dangling symlink.

=== Clause 3: both the symlink and its real target are removed on success, local failure, and timeout

The `finally` block (`:268-276`) wraps the whole post-provisioning body,
including `communicate()` and the timeout kill path (`:257-267`), so all
three outcomes pass through the same two independent removals. The grant
itself is unchanged in shape and still narrow: `_settings()` (`:148-169`)
names `str(external_scratch_dir)` where the caller passes the *resolved*
per-invocation target (`real_dir = real_dir.resolve()` at `:229`, used at
`:238`), i.e. `allowRead == [resolved repository, resolved target]` and
`allowWrite == [resolved target]` -- never the symlink (the symlink is used
only for `TMPDIR`/`TMP`/`TEMP`, `:244`), never an ancestor, never the
Attempt's whole scratch root. `network.allowedDomains` stays `[]`,
`permissions.allow`/`deny` and `blockReadsOutsideWorkingDirectories` are
untouched, and `argv()` (`:137-146`) gained no bypass flag.
