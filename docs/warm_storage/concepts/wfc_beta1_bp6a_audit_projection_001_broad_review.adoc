=== Method

Five kinds of evidence were produced.

. *Baseline diff reading.* `git show --stat` over the single candidate
  commit and the full text of every new or changed leaf, to establish what
  the candidate did and did not touch.
. *Source-of-truth cross-reading.* Every projected field was traced back to
  the engine writer that persists it, not to the fixture: `model.Run`,
  `model.HopSummary`, `model.Finding`, `model.Observation`,
  `model.StagedQualificationAttempt`, `model.StatFingerprint`,
  `serialization.run_to_json`/`_json_value`, `operator.py`'s
  `operator-plan.json`/`operator-summary.json` construction and
  `_prepared_evidence_plan`, and `frontdoor/archive.py`'s manifest and
  allow-lists.
. *Mutation testing of the delivered suite.* The product tree was copied out
  of the repository; one guarded behaviour at a time was removed in that copy
  and the three delivered BP6a test modules were run against it. Nineteen
  mutations were applied; sixteen were killed, three survived (F001). Every
  survivor was re-verified with `__pycache__` removed and
  `PYTHONDONTWRITEBYTECODE=1`, and each surviving mutation's presence in the
  mutated source was asserted, after two mutations initially "survived"
  because my own line anchors had missed by one line and sed had changed
  nothing.
. *Direct behavioural probes* of `project_audit`, `write_audit` and the
  `wfc audit`/`wfc report` dispatch against synthetic attempt trees built
  with the delivered `tests/fixtures/bp6` helper and then tampered with
  outside it.
. *Suite execution.* The three new modules (72 tests) plus
  `tests/architecture`, the five archive modules, the BP4a lifecycle
  controller, BP4b candidate preservation and preservation lifecycle modules
  and the doc catalogue; then all of `tests/unit`.

The real Evidence repository was never read (it is not present in this
environment at `../workflow-coordinator-run-evidence`), and no test touches
it. Field shapes were therefore established from the engine writers, as the
task's fallback directs.

=== Blocking Finding

[[f001]]
==== F001 -- three fields of the frozen allow-list have no mutation-sensitive assertion

Invariant:: Acceptance preamble and case (1): "Each case is covered by a test
with a mutation-sensitive assertion: (1) completed Run projects every field
of the frozen list with the exact source values." The frozen list names
`schema`, `attempt_id`, `run {...}`, `governance {...}`, `hops [...]`,
`findings [...]`, `anomaly_count`, `lifecycle`, `raw {...}`. The task also
requires the synthetic fixture set to include "a Run with an anomaly".

Reproduction:: Each mutation below was applied to an out-of-tree copy of
`src/workflow_coordinator/frontdoor/audit.py`; the three delivered modules
(`tests/unit/test_audit_projection.py`, `tests/unit/test_audit_privacy.py`,
`tests/unit/test_report.py`) were then run in full.

[cols="3,2,1",options="header"]
|===
|Mutation |Projected result |Suite

|`"attempt_id": attempt_id` -> `"attempt_id": "REDACTED-ATTEMPT"`
|every `audit.json` reports a constant attempt identity
|green, 72 passed

|`anomaly_count = len(run_doc.get("anomalies") or [])` -> `anomaly_count = 0`
|a Run with anomalies reports none
|green, 72 passed

|`"semantic_stop_present": run_doc.get("semantic_stop") is not None` ->
 `"semantic_stop_present": False`
|a semantic stop is reported as absent
|green, 72 passed
|===

Why no test catches it::
`attempt_id` is never asserted anywhere in the three modules (`rg
'attempt_id'` over them returns no assertion; the report renderer puts it on
the `WFC RUN` line, but `test_report.py` only asserts the literal `"WFC
RUN"`). `anomaly_count` is asserted exactly once, as `== 0`, on a fixture
with no anomalies -- the degenerate value, so the assertion has no
discriminating power; the only fixture that does supply an anomaly is
`test_audit_privacy._canary_attempt`, which asserts only that the anomaly
*prose* does not leak, which is insensitive to the count. The fixture builder
does support `anomalies=`, so the "Run with an anomaly" tree the task asks for
is buildable but never built with an assertion on its count.
`run.semantic_stop_present` is asserted exactly once, as `is False`, on a
fixture with no semantic stop; `_canary_attempt` does build a semantic stop
but asserts only that its question text does not leak.

Not an implementation defect:: the projection itself is right. Against the
unmutated module, a probe attempt built with
`attempt_id='probe-attempt-20261120-01'`, three anomalies and a semantic stop
projects `attempt_id='probe-attempt-20261120-01'`, `anomaly_count=3` and
`semantic_stop_present=True`. F001 is a matrix gap: the suite does not pin
three fields it is required to pin.

Smallest correction:: extend `tests/unit/test_audit_projection.py` only --
assert `audit["attempt_id"]` against a non-default `attempt_id` in the
completed-projection test, add an anomaly-bearing Run asserting
`anomaly_count` equals the number of anomalies supplied (and that the anomaly
strings do not appear), and assert `semantic_stop_present is True` for a Run
carrying a semantic stop. No implementation change is needed or wanted.

=== Non-blocking observations

These are observations, not Findings. They are recorded here and in the Hop
summary only.

. *`wfc report` on an attempt directory does not map a guard refusal to an
  exit code.* `report.main` catches `ReportError` and `AuditError` but not
  `ProjectionError`, and `_load_audit_source` calls `project_audit` for a
  directory argument. Reproduced: with an absolute path injected as a
  `governing_inputs` key, `wfc audit` exits 3 naming
  `governance.governing_inputs.<key>`, while `wfc report` on the same
  directory propagates `ProjectionError` as an uncaught traceback. No value
  leaks and the guard still refuses; only the documented exit code is lost.
  Reaching it needs an archive whose plan records an absolute governing-input
  path, which admission (`_admit_a1`, `_relative_path`) does not produce, so
  this is outside the acceptance list rather than a defect in it.
. *`governing_inputs` is the one bulk copy.* `dict(plan_doc.get("governing_inputs")
  or {})` copies the plan's map wholesale instead of rebuilding it entry by
  entry. It is safe for the shape the engine writes (repository-relative path
  -> digest string) and both keys and values pass through the guard, but it is
  the single place where the "never copy a source object" rule is satisfied by
  the source's shape rather than by construction.
. *The absolute-path test is prefix-only.* `_string_violation` flags a string
  that *starts* with `/`, a drive letter or `\\`; an absolute path embedded
  inside a longer string is caught only through a caller-supplied private
  string. This matches the task's wording ("any string value is an absolute
  path") and no allow-listed field can carry such a string today.
. *Several real statuses read as `unknown`.* `model.RunStatus` also has
  `ready`, `running`, `awaiting_supervisor` and `suspended`, and
  `frontdoor.lifecycle.EXIT_CODES` also has `inconsistent`, `engine_active`,
  `engine_exited_before_state`, `not_launched` and the `refused_*` family.
  All of them fall outside the task's frozen six-entry table and are reported
  as `unknown`. That is the specified and honest behaviour, but an archived
  mid-flight or refused Run reads as `unknown` rather than as what it is.
. *An Attempt with no `run.json` is refused, not nulled.* `_find_checkout`
  raising `AuditError` ("not a projectable attempt") is the right call for a
  core source, but it means an archive of a Run that never reached checkout
  registration -- the shape a true `uncertain_launch` can leave -- cannot be
  projected at all, even to carry the supplied lifecycle facts.
. *Determinism is only pinned within one process.* Both determinism tests
  compare two renderings made in the same interpreter. The code is in fact
  cross-process stable (`limits` is `sorted(set(...))`, lists are explicitly
  ordered, `sort_keys=True`), but a mutation dropping only the `sorted()`
  around `limits` would not be caught by the delivered suite, since `set`
  iteration order is stable within a process.
. *`audit.json` is created mode 0600.* `tempfile.mkstemp` creates the
  temporary file with owner-only permissions and `os.replace` preserves them,
  so the published record is less readable than the manifest beside it
  (0644). Harmless for BP6a, worth a thought when BP6b commits the file.
. *Environmental test failures in this sandbox.* Four modules cannot run
  here: `tests/architecture/test_bp1_identity.py` and
  `test_offline_distribution.py` need PEP 517 build isolation, which needs a
  package index; `tests/unit/test_wfc_op.py` runs a nested `pip install`;
  `tests/unit/test_claude_adapter_conformance.py` needs a writable `/tmp`
  symlink target. All four fail with `No matching distribution found for
  setuptools>=68` or `[Errno 30] Read-only file system`, independent of this
  candidate. This is an agent-local limitation, not a product defect, and
  does not substitute for the Coordinator's own full task-check.
