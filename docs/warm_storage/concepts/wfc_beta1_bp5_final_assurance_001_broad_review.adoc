== Blocking findings

=== BF-1 -- the fixture-collision fix (item A) is incomplete: the required full suite still fails

*Reproduced violation of an explicit acceptance criterion.*

`WI-WFC-BETA1-BP5-ARCHIVE-COMPLETION-001` item A requires fixing the test
fixture collision "without weakening `tests/unit/test_wfc_op.py`" and states
"Full Coordinator suite must pass"; its Acceptance requires "existing
preparation test and full suite pass". This Commission's Acceptance likewise
requires "original applicable conformance" and a passing Coordinator full
task-check.

The candidate renames only the checkout's `run.json` to `run.fixture.json`.
`tests/unit/test_wfc_op.py::test_prepare_never_creates_a_run_or_checkout`
makes **three** assertions, not one:

[source,python]
----
tests/unit/test_wfc_op.py:358    assert not list(ops.glob("**/run.json"))
tests/unit/test_wfc_op.py:359    assert not list(ops.glob("**/operator-plan.json"))
tests/unit/test_wfc_op.py:360    assert not list(ops.glob("**/operator-summary.json"))
----

The candidate commits two fixture files whose basenames match assertions 2
and 3:

[source,shell]
----
$ git ls-tree -r --name-only HEAD \
    | grep -E '(^|/)(run\.json|operator-plan\.json|operator-summary\.json)$'
tests/fixtures/bp5/real_run/run/operator-plan.json
tests/fixtures/bp5/real_run/run/operator-summary.json
----

These reach `ops/` by construction. `tests/unit/test_wfc_op.py`'s
`make_runtime()` is a full local clone of *this* repository
(`test_wfc_op.py:138-144`), and `prepare` exports the pinned Runtime commit's
whole tracked tree into the OPS directory --
`scripts/wfc_op.py:400-422`, `src = ops / "runtime-src"`, populated by
`git archive <head> | tar -x -C <ops>/runtime-src`. Nothing in
`scripts/wfc_op.py` ever removes `runtime-src` (no `rmtree` exists in that
module), so it is still present when the assertions run. There is no
`.gitattributes` in the repository and `export-ignore` is `unspecified` for
both fixture paths, so `git archive` includes them.

Reproduced directly, by materialising exactly what `export_runtime()` writes
and then running the test's own `glob` expressions against it:

[source,shell]
----
$ mkdir -p tmp/h002-export-probe/runtime-src
$ git archive HEAD | tar -x -C tmp/h002-export-probe/runtime-src
$ python -I tmp/h002-probe/glob_probe.py tmp/h002-export-probe
assert not list(ops.glob('**/run.json')) -> assertion holds
assert not list(ops.glob('**/operator-plan.json')) -> ASSERTION FAILS
    .../runtime-src/tests/fixtures/bp5/real_run/run/operator-plan.json
assert not list(ops.glob('**/operator-summary.json')) -> ASSERTION FAILS
    .../runtime-src/tests/fixtures/bp5/real_run/run/operator-summary.json
----

`glob_probe.py` is a three-line throwaway that runs the test's own three
`ops.glob("**/<name>")` expressions against the directory given to it and
prints whether each `assert not list(...)` would hold; it was written under
the ignored `tmp/` tree and removed afterwards, so the reproduction above is
re-runnable with nothing but `git archive` plus
`find <dir> -name operator-plan.json -o -name operator-summary.json -o -name run.json`,
which returns the same two paths.

The same probe against the pre-implementation baseline is clean, so this is
introduced by the BP5 candidate and is not pre-existing:

[source,shell]
----
$ mkdir -p tmp/h002-export-probe-base/runtime-src
$ git archive 54b99ba788206fe61ea89cdeee96db434d4a1c79 \
    | tar -x -C tmp/h002-export-probe-base/runtime-src
$ python -I tmp/h002-probe/glob_probe.py tmp/h002-export-probe-base
assert not list(ops.glob('**/run.json')) -> assertion holds
assert not list(ops.glob('**/operator-plan.json')) -> assertion holds
assert not list(ops.glob('**/operator-summary.json')) -> assertion holds

Assessment: the original failure was masked by assertion ordering. Assertion 1
fails first on the pre-rename fixture, so renaming `run.json` alone makes the
test fail one line later instead of passing. The collision class is the
basename, not the single file: any committed fixture file named
`operator-plan.json` or `operator-summary.json` anywhere in the tracked tree
breaks this test. `test_wfc_op.py` itself is untouched by the candidate
(confirmed: it is not in `git diff --name-only 54b99ba..HEAD`), so this is not
test weakening -- it is an unfixed collision.

This finding is blocking regardless of presumed risk: it is a reproduced
failure of a named existing regression test and therefore of the mandatory
full suite.

Minimal remedies available inside the already-authorised BP5 fixture scope
(the choice is the implementer's, and none of them require new design
authority or touching `test_wfc_op.py`): apply the same neutral-name treatment
already used for `run.json` to the other two colliding basenames and
materialise them back in the disposable relocated state root
(`tests/unit/test_archive_equivalence.py::_relocate_real_run` already does
exactly this for one file), updating `tests/fixtures/bp5/PROVENANCE.txt`
accordingly while preserving the original bytes and SHA-256 of each file. Any
remedy must keep every digest in `PROVENANCE.txt` equal to the real archived
`manifest.json`'s own `copied_files[].sha256`, and must not introduce a new
rename-shaped trusted-commit change beyond what
`docs/backlog/BUG-WFC-TRUSTED-COMMIT-RENAME-RECONCILIATION.adoc` already
tracks.

=== BF-2 -- a ported legacy conformance assertion is silently neutralised, and the behaviour change it guarded is undocumented

*Reproduced violation of an explicit acceptance criterion.*

The original BP5 task requires copying the legacy conformance tests
"preserving all applicable checks and documenting any unavoidable
non-applicable legacy-proof case"; the completion Commission's review
paragraph requires "retain full original assertions"; this Commission's
withheld authority forbids test weakening.

`tests/unit/test_archive_port.py:317` carries a permanently dead branch:

[source,python]
----
self.assertIn(f"checkout:   {CHECKOUT}" if False else f"repository: {TARGET_REPO}", proc.stdout)
----

The `if False` arm is the legacy assertion. In the legacy source
(`build/wfc/bp5-evidence-inputs/tests/test_wfc_archive_run.py:312,315`)
`test_manifest_identity_cannot_forge_run_probe_records` asserted both
`checkout:   <CHECKOUT>` *is* present and
`checkout:   00000000-dead-beef-dead-beefdeadbeef` is *not* -- i.e. that a
forged `run_id` carrying embedded `checkout_id` control text cannot forge the
report's own checkout field. Both assertions are gone from the port: the
positive one is disabled by `if False`, and the negative one is absent
entirely.

The property is now untestable because the port removed the field. The legacy
wrapper printed it (`tests/fixtures/bp5/legacy/wfc-archive-run:502`,
`printf 'checkout:   %s\n' "$checkout_id"`), whereas
`archive.py::render_report` (`archive.py:899-932`) emits no `checkout:` line
at all; `ArchiveReport.checkout_id` is populated on every path and never
rendered. `test_archive_port.py`'s module docstring enumerates four documented
porting adaptations and explicitly claims the old commit *body*'s "identity
narrative is on stdout instead" -- which is inaccurate for `checkout_id`,
which did not move but disappeared. The `H001` worker-verification artifact's
section 5 likewise asserts that every non-1:1 legacy case "is each named and
explained in the port modules' own docstrings"; this one is not.

This is bounded and cheap to resolve either way, and both ways stay inside the
authorised BP5 candidate files: render the `checkout:` line in
`render_report()` and restore both legacy assertions, or keep the report
surface as it is and document the omission explicitly in
`test_archive_port.py`'s adaptation list alongside the other four, replacing
the `if False` construct with a plain assertion. What is not acceptable under
the stated criteria is an inert assertion that reads as if it were still
checking the ported property.

=== Tamper refusal and intact retry (test C)

`_load_existing_manifest()` + `_safe_manifest_relpath()`
(`archive.py:665-710`) validate every manifest-recorded path before any
filesystem access: non-string/empty/whitespace-padded/backslash, absolute,
`.`/`..`/empty component, non-canonical, duplicate, and symlink-escape under

attempted. The eleven tests in `InterruptedRetryTamperTests` reproduce each of

genuinely intact interruption still resumes to exactly one commit.
`StagingAndRetryTests` proves the same half end to end through the real CLI:

`archive_run()` commits only through
`bounded_path_commit(..., allowed_paths=(dest_rel,), intent=NewPathCommitIntent(paths=<exact sorted leaf list> + manifest.json))`
(`archive.py:873-879`). Reading that primitive (`git_facts.py:814-916`)

== Nonblocking observations

These are recorded here and in the result summary only. They are not Finding
transitions; this Hop's `finding_authority` is `resolve` and no current-Run
Finding exists.

. *Resume reverification does not re-derive the manifest from sources.*
  `_verify_resumable_placement()` checks `attempt_id`, recorded sources and
  each file's own digest/size against the placed manifest, but unlike the
  already-committed no-op path (`archive.py:829-837`, which compares a freshly
  computed candidate manifest) it does not re-derive `facts`/`semantic`. A
  tamperer who edits a placed file *and* consistently rewrites its digest plus
  the extracted facts would resume. This is outside the properties item C
  enumerates (changed data/digest, size, attempt and source identity, unsafe
  paths), all of which are correctly refused, so it is not treated as an
  acceptance violation -- but a future hardening pass could reuse
  `_manifests_match_ignoring_archived_at()` on the resume path too.
. *Dead `resumed_commit` outcome.* `ArchiveReport.outcome` documents
  (`archive.py:614`) and `render_report()` maps (`archive.py:903`) a
  `"resumed_commit"` value that no code path ever assigns -- the resume path
  returns `outcome="archived"` (`archive.py:884`). Cosmetic dead enumeration
  text with no observable behavioural difference; already assessed nonblocking
  by the two prior independent reviews and still open. Not re-raised.
. *Cross-attempt staging leftovers block archiving.* `_assert_narrow_cleanliness`
  allows dirty paths only under the *current* attempt's destination and
  staging prefixes, so leftover `.wfc-archive-staging/<other-attempt>/...`
  from a different killed attempt is reported as "not clean outside the
  archive destination". The ported test only covers the same-attempt case
  (`test_stale_staging_from_a_prior_killed_attempt_does_not_block_a_fresh_archive`
  reuses `fx.attempt`). The behaviour errs safe (refuse, mutate nothing) and
  the operator documentation's cleanliness wording is not wrong, but the
  cross-attempt case is undocumented and untested.
. *Ignored-destination edge case.* `_path_is_tracked_clean()` infers "already
  committed" from the absence of status lines, so a destination that existed
  but was git-ignored would be reported as `no_op` with `commit: None` rather
  than refused. Not reachable in the real Evidence repository layout, where
  `archive/` is tracked.
. *Equivalence compares manifests, not raw trees.* Re-checked and still
  assessed as sufficient: the manifest carries every copied file's path,
  SHA-256 and byte count, and both sides are driven from the identical
  relocated state root and OPS directory.

== Conclusion

The BP5 product is close, and most of what this Commission asked to be proved
is genuinely proved: provenance, real old/new archive parity on the actual
retained Run, symlink/destination containment with real filesystem evidence,
tamper and identity refusal with placed data and HEAD preserved, intact
single-commit retry and no-op repeat, unmodified trusted Git authority, and
documented conformance coverage. But BF-1 is a reproduced failure of an
existing named regression test and therefore of the mandatory full suite, and
BF-2 is an inert ported assertion with an undocumented behaviour change behind
it. Both are explicit acceptance criteria of the Commission the candidate
descends from, so neither can be downgraded for low presumed risk or legacy
parity. Verdict: **changes_required**, route `correction`, scoped to the BP5
fixture/provenance and `frontdoor/archive.py`/`test_archive_port.py` files
already authorised -- no new design, architecture or authority is needed.
