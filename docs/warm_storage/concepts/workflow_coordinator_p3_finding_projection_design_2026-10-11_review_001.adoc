== 1. Verdict

*B -- BOUNDED CORRECTION REQUIRED.*

The correction's central architecture direction is sound:

* `adapter.py` and `prompt.py` are genuinely required P3 compatibility seams;
* version 3 must be admitted only for `WORK_RESULT` and `REVIEW_VERDICT`, not
  globally;
* this admission work belongs to P3 plumbing, not P3.5 authority composition;
* `vertical.py` needs no route-selection change;
* the preserved candidate is non-authoritative salvage and demonstrates why a
  global `{1, 2, 3}` admission is unsafe; and
* the proposed production seam set is otherwise sufficient and bounded.

Two defects must be corrected before a successor Commission is authored:

[cols="1,2,5",options="header"]
|===
|ID |Class |Summary

|P3-CORR-001
|Compatibility / replay
|The design protects persisted version-1/2 pairs but omits the accepted legacy
replay path for historical Hops with no persisted contract pair. The proposed
kind-aware version-3 selector can reinterpret such a generic v2 Hop as expecting
version 3 and reject it.

|P3-CORR-002
|Historical accuracy / evidence strength
|The correction calls the need for both `adapter.py` and `prompt.py`
"Run-reproduction-backed" and describes the Run/Hop stop as
`status=blocked`. Preserved evidence shows a source-inspection report about
`adapter.py` only, a v1 semantic result with `status=blocked`, Hop outcome
`blocked`, a separate dirty-worktree mechanical preemption, and final Run
status `awaiting_human`. `prompt.py` is established by current-source
inspection, not by the historical Run.
|===

Both are finite textual/design corrections. Neither requires a new subsystem,
a P3.5 expansion, or a production file outside the corrected seam set.

== 4. Blocking findings

=== P3-CORR-001 -- Pairless historical replay is omitted

Exact locations:: Design section 7, especially lines 380-399; section 9,
lines 503-505; section 14, lines 676-678; and section 16.4, lines 788-794.

Claim challenged:: The design says replay "trusts only" the persisted
`(kind, version)` pair, and its compatibility/test requirements cover
historical `WORK_RESULT`/`REVIEW_VERDICT` pairs at versions 1/2. It then permits
the shared selector to begin returning version 3 for current work/review
families.

Repository evidence:: The governing concept at lines 610-623 and 655-671
explicitly preserves another accepted case: historical Hops carrying no pair
fall back to the shared selector/version seam. Current
`reducer.py:1286-1312` implements that behavior. For a pairless historical
generic v2 result in a schema-v3 profile, current selection can produce
`WORK_RESULT`; today the shared version remains 2, so replay succeeds. If P3
changes the family version to 3, the same branch expects 3 and rejects the
historical generic v2 result as `unsupported result schema version`.

This was reproduced provider-free against current source by substituting only
the proposed family-v3 answer at the shared version seam: the same pairless v2
fixture changed from accepted behavior to `awaiting_human` with
`mechanical_preemption:unsupported result schema version`.

The existing tests do not close this gap. `tests/unit/test_reducer.py` proves
only that the no-pair branch calls the shared helpers, and
`tests/architecture/test_replays.py` covers a complete persisted pair and an
incomplete half-pair. Neither pins a pairless historical generic v2 Hop across
the future family-v3 selector change.

Why it matters:: This violates the governing promise that historical Runs are
not reinterpreted from mutable current configuration. It also means the
candidate's apparent kind-aware selector is not safe to reuse. A successor
Commission following the current text could pass every named replay assertion
while breaking an explicitly accepted legacy class.

Smallest sufficient correction:: Amend the compatibility section to distinguish
three cases: (1) a complete persisted pair governs replay; (2) a missing half
fails closed; (3) complete absence denotes legacy generic history and must keep
its pre-P3 v1/v2 meaning rather than receiving current family-v3 semantics.
Require a replay regression for a pairless schema-v3/profile-v3 generic v2 Hop
whose current phase facts would now select a v3 work or review family. State
that the implementation may preserve this in the already-in-scope reducer/model
seam without prescribing a generic migration framework. Also make explicit
that the legacy `ExistingFindingDelta` parsing/type path remains available for
versions 1/2; the new citation/transition variants apply to version 3.

=== P3-CORR-002 -- Run evidence, Hop outcome, mechanical stop, and final state are conflated

Exact locations:: Header/caution lines 9-11 and 30-42; section 10 lines
548-550; section 16.1 lines 738-747; section 16.5 lines 802-819.

Claim challenged:: The strongest overstatement is that the necessity of
changing both `adapter.py` and `prompt.py` "is Run-reproduction-backed, not
merely inspected." The history paragraph also attaches `status=blocked` to an
ambiguous Run/Hop subject and omits the distinct final Run and mechanical
states.

Repository evidence:: The archived semantic result and H001 summary identify
only `adapter.py`. They show contract version 1, so neither version-3 gate was
executed by the Run. Current source independently proves both gates are real and
that `prompt.py` is reached first. The archive separately records semantic
result status `blocked`, Hop outcome `blocked`, a scope `semantic_stop`, dirty-
worktree mechanical preemption, and final Run status `awaiting_human`. The run
ledger expressly keeps these levels separate and records P3/WorkItem as
incomplete.

Why it matters:: The record itself says evidence strength controls mechanism
admission. Calling current-source inspection a Run reproduction overstates the
evidence and obscures which defect H001 actually escalated. Collapsing the
result, Hop, mechanical, Run, and WorkItem levels also weakens the historical
example the correction relies on to justify a successor boundary.

Smallest sufficient correction:: Replace "Run-reproduction-backed" with an
exact provenance split: H001 recorded an implementation-time source-inspection
finding about `adapter.py`, later independently verified against the historical
baseline/current source; `prompt.py` is an additional required seam established
by this correction's current-source execution-path inspection. Restate the
disposition as: semantic result status `blocked`; Hop outcome `blocked`; scope
semantic stop; separate dirty-worktree mechanical preemption; final Run status
`awaiting_human`; no independent review; WorkItem/P3 incomplete. Do not describe
either gate as dynamically reproduced by a version-3 Run path.

== 5. Other adversarial conclusions

=== 5.1 Root diagnosis and production seam set

The root diagnosis is correct after current-source inspection. `prompt.py` is
the earliest blocker and `adapter.py` is a later provider-neutral blocker.
`codex_adapter.py`, `serialization.py`, `model.py`, and `reducer.py` also need
coordinated P3 changes, but were already inside the historical Commission.
`vertical.py` already threads the selected pair and needs no route-selection
change. No additional currently withheld production path was found.

=== 5.2 Narrow admission and P3/P3.5 boundary

The corrected rule is appropriately pair-specific. Generic routing retains
versions 1/2 and every unadmitted pair must fail closed. The candidate's global
Codex widening concretely demonstrates the risk the correction now prohibits.

Admission of P3's own wire contract grants no Finding authority and performs no
workflow-graph reachability analysis. It is P3 compatibility plumbing, not
P3.5. Conversely, the correction does not pull the P3.5 ordered-reachability
check or `test_self_development_governance.py` into P3.

=== 5.3 Successor scope and tests

After P3-CORR-001 is fixed, the named production surface is sufficient. The
test matrix correctly requires positive v3 work/review admission, negative v3
generic admission, unchanged v1/v2 behavior, direct prompt assembly and
`validated_result` coverage, schema projection, reducer semantics, and replay.

For minimality, `tests/unit/test_slice3_vertical.py` already calls both
`assemble_prompt` and `validated_result` directly, and
`tests/unit/test_codex_adapter_conformance.py` covers provider projection and
dispatch. `tests/unit/test_slice4.py` and
`tests/unit/test_a3_operating_contract.py` also exercise those production
functions, but need be added to a successor scope only if the successor actually
needs to modify them. The correction's phrase "whichever tests exercise those
seams" permits that least-diff choice and does not itself require broad test
churn.

=== 5.4 Candidate and implementation design level

The candidate is characterized correctly as untrusted salvage with no inherited
review credit. It contains useful work and demonstrably unsafe choices; neither
fact converts it into implementation precedent.

The corrected design does not require an unnecessarily generic compatibility
framework. An explicit admitted-pair check or another equally small kind-aware
form is adequate. P3-CORR-001 requires one legacy-replay rule, not a migration
system or registry.
