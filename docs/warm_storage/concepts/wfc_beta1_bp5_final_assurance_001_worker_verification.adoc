== 4. Containment and retry/tamper refusal (tests B and C)

`tests/unit/test_archive_safety.py` closes the two safety properties the
Commission named explicitly, with real-filesystem-effect assertions (not
merely "an error was raised"):

* **B -- symlink/destination escape.** A tracked `archive/` symlink and a
  tracked `.wfc-archive-staging/` symlink, each pointing outside the Evidence
  repository, are both refused by `assert_no_symlink_escape` *before* any
  write; the tests assert the outside tree's listing and file contents are
  byte-identical before/after, HEAD is unchanged, the index is clean, and no
  `archive/unclassified` or staging directory is created inside the
  repository.
* **C -- interrupted-retry tamper refusal.** A placed-but-uncommitted
  destination (the exact state a kill between copy and commit leaves, per
  `test_archive_port.py`'s `StagingAndRetryTests`) is reverified before
  resume: tampered file content (same length, different digest), tampered
  size, a manifest `attempt_id` naming a different attempt, a manifest
  `sources.run_dir` naming a different source, an absolute `copied_files`
  path, a `../`-traversal path, a duplicate path, and a symlink-escape path
  under the destination are each refused with a specific, distinct message;
  each refusal leaves HEAD unchanged, the index clean, and (where checked)
  the placed data on disk exactly as it was -- not reverted, not deleted. A
  positive control shows a genuinely intact interruption still resumes to
  exactly one commit.

`tests/unit/test_archive_port.py::StagingAndRetryTests` independently proves
the retry/idempotence half of C end to end through the real CLI: a kill
between placement and commit resumes to exactly one commit on retry with an
unchanged `copied_files` list; a kill before placement leaves no destination
and a clean retry; a second archive of the same attempt is a no-op that
leaves HEAD unchanged; an existing destination from a genuinely different Run
(same attempt id, different identity) is refused, not overwritten, and the
pre-existing manifest/HEAD are left untouched; an unrelated dirty path
elsewhere blocks archiving and is left exactly as it was; stale leftover
staging from a prior killed attempt does not block or merge with a fresh
attempt; a pre-existing unrelated staged index entry is refused and left
staged, not swept into the archive commit.

== 6. Git scope, hook and filter controls

The commit path is `git_facts.bounded_path_commit` (unmodified, pre-existing,
outside this Commission's scope), the same primitive the Commission commit
itself uses: it refuses a configured clean/process filter, refuses unexpected
HEAD movement, refuses any intent path that already names a blob at base
HEAD (so modification/deletion of a tracked path is impossible through this
path), refuses a directory-shaped intent, requires staged paths to equal the
intent set exactly, and verifies the resulting commit by independent
post-commit observation before returning. `archive_run()` calls it with
`allowed_paths=(dest_rel,)` and an exact, sorted leaf-file list plus
`manifest.json`; `tests/unit/test_archive_port.py::GitBehaviourTests` proves
only the new destination's own paths are ever staged/committed, even with
other dirty/untracked repository state present, and that no push is
attempted. No global Git configuration is read or written by `archive.py`.

=== F002 -- dead `if False` branch in `test_archive_port.py`

Before changing anything, the legacy source and the actual new behavior were
read, not assumed. `build/wfc/bp5-evidence-inputs/tests/test_wfc_archive_run.py`'s
`checkout:` assertions (lines 312/315) read the git commit **body**
(`git log -1 --format=%B`), not stdout -- confirmed by reading the test
method directly, which binds its own `body` variable from that command and
asserts against it, never against `proc.stdout`. The legacy wrapper's
`report()` stdout function (`wfc-archive-run:453-463`) never printed a
`checkout:` line either; only the separately-generated commit-message block
(`wfc-archive-run:496-508`) did. `src/workflow_coordinator/frontdoor/archive.py`'s
commit is made via `NewPathCommitIntent(paths=paths, subject=...)` --
subject-only, no body at all (confirmed by reading `git_facts.NewPathCommitIntent`,
which has no body field) -- so there is no commit-body surface in the new
implementation for a `checkout:` line to live on, and `render_report`'s
stdout format never had one either.

The forged-`checkout_id` protection this guarded is not missing from the
port: `archive.run_identity`'s `_agree("checkout_id", ...)` call refuses the
entire archive (`ArchiveError`, `"checkout_id disagrees..."`) when
`operator-summary.json` and `checkout-association.json` disagree, which is
fail-closed and strictly stronger than the legacy display-time scrubbing the
dead branch's sibling test was modeled on. This is already exercised by the
pre-existing `RefusalTests.test_disagreeing_checkout_id_across_sources_is_rejected`
in the same file, confirmed present and passing before this Hop touched
anything.

Fix: the dead `f"checkout:   {CHECKOUT}" if False else f"repository: {TARGET_REPO}"`
ternary in `test_manifest_identity_cannot_forge_report_fields` is replaced
with the plain `self.assertIn(f"repository: {TARGET_REPO}", proc.stdout)`
assertion it always actually executed, with a one-line comment pointing at
the refusal test that covers `checkout_id`'s own property. The module
docstring's documented-adaptations list gets one new bullet stating
explicitly that `checkout_id` is the one identity field that moved from
commit-body display to a fail-closed upstream refusal rather than to stdout,
so no reviewer re-reads this as an unexplained gap. No test assertion was
weakened; the one dead/inert branch was replaced by the assertion it already
silently reduced to, and the property it nominally guarded is independently,
already covered elsewhere.
