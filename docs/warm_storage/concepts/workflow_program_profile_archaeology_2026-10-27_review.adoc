=== WPA-001 -- the grouped census is not the required per-profile semantic inventory

The exact metadata readout supplies path, ID, revision and schema for the 46
files matching `governance/self-development/*-profile.yaml`, and the earlier
table supplies a coarse F2/F3/F4/F5 classification. It does not record, per
profile, the other fields the Commission expressly requires: roles and review
purpose; Finding creation and disposition capability; required evidence and
failure routing; durable-artifact and mandatory-review guarantees; authorized
actions and scope; Commission-specific bindings; and notable differences from
otherwise similar profiles. The two general paragraphs after the table say
these values matter, but do not map them back to each profile.

This is not merely a presentation preference. The row grouping the four P2
profiles as `F4; [resolve]` hides distinct current YAML guarantees:

* `projected-result-contracts-p2-profile.yaml` has worker `evidence: [pytest]`,
  a focused first review, and no `review.failed_evidence_route` in either gate.
* `projected-result-contracts-p2-integration-continuation-profile.yaml` and
  `projected-result-contracts-p2-integration-closure-profile.yaml` retain that
  focused/no-failure-route evidence shape while changing Commission purpose,
  paths and scope.
* `projected-result-contracts-p2-integration-completion-profile.yaml` has no
  worker evidence, a broad first review, and
  `review.failed_evidence_route: correction` in both gates.

Those are exact fields in the four named YAML files. They affect production
admission because `_admit_evidence_disposition` rejects every evidence-bearing
phase that is not a gate or lacks `failed_evidence_route`
(`src/workflow_coordinator/operator.py`, lines 123-135). A common graph and
common `[resolve]` value therefore do not communicate the different mandatory
process guarantees. Similar omissions occur in the row grouping documentation
profiles (broad versus focused first review), and scopes/actions are reduced to
two examples rather than inventoried.

The correction need not duplicate long prose or every path repeatedly. It must
make the inventory reproducible and complete at per-profile granularity, for
example through explicit semantic signatures plus a lossless profile-to-
signature mapping and separately listed Commission bindings. At minimum it
must expose each required category above and identify exact YAML fields behind
every grouped equivalence/difference. It must also state accurately which
phases may propose a new open Finding versus which may disposition an existing
one; `finding_authority` alone records only the latter operation set
(`src/workflow_coordinator/model.py`, lines 222-231;
`src/workflow_coordinator/reducer.py`, lines 588-617 and 1693-1719).

=== WPA-002 -- available history answers the final-review chronology that the survey leaves open

Section C says the evidence is insufficient to claim when a broad/final phase
appeared or disappeared. That conclusion results from searching for a literal
`final_review` field rather than following the relevant route semantics and
their recorded rationale.

The chronology is directly recoverable:

* `53d010933242a4e031d833bc9224710ff6f285eb` introduced the four phases, but
  its first review had only `correct -> correct`; a clean result still had to
  spend a correction Hop before rereview.
* The repository's Attempt-4 record explicitly proposed `clean review ->
  rereview` to preserve four-eyes review without the no-op correction
  (`cb41c8b^:docs/backlog/first_wfc_on_wfc_dogfood_attempt_4_2026-09-23.adoc`,
  lines 60-66). Commit
  `cb41c8be7648342fc5ebbb4d3e89438c5fc455ab` then deliberately added exactly
  the `review.routes.rereview` edge, with subject "allow clean review to
  proceed to rereview" and tests asserting that `review` has no `accept`
  route. This is an additional mandatory fresh final rereview on the clean
  path; both review descriptors are focused rather than broad.
* Commit `f6d1d8ddddb67eb847546ef65a7a98cbba973696`, the first dedicated
  Commission profile after that shared-profile history, records Git copy
  similarity from `standalone-development-profile.yaml` to
  `immutable-finding-echo-profile.yaml` and changes the first review to
  `accept: complete | correct: goto correct`. Its task says a sound first
  review requests `accept` and that rereview runs only if correction ran
  (`governance/work-items/immutable-finding-echo-fix-task.txt`, lines 40-80 at
  that commit). The commit message calls the bundle a dedicated narrow profile
  because the shared profile's scope was unsuitable. This supports a copied,
  Commission-specific adaptation, not a versioned reusable-program decision.

The survey instead starts its per-Commission chronology at `ef8a4d0`, omitting
the earlier `f6d1d8d` counterexample, and concludes only that no phase was
literally named `final_review`. Correction must record the route-semantic
appearance and disappearance above, distinguish focused final rereview from
the draft UC-02's proposed fresh *broad* final review, and delimit the inference:
the cited evidence establishes intent for each concrete Commission edit but
does not establish a consciously versioned reusable workflow family.

=== WPA-001 -- OPEN (residual defect)

The correction does not yet provide the required lossless per-profile
inventory. It defines the “YAML semantic record” as the complete
`phases.<phase>.*` field set in the source YAML, but the table does not copy or
encode that complete record. Its scope column repeatedly says only “literal
scope”, “literal source/test scope”, or “YAML semantic record”; the exact
metadata readout similarly maps each path back to that unevaluated field set.
Those are reproducibility pointers to the source, not an inventory of each
profile's literal authorized scope, role/components, complete review purpose,
and Commission binding as H002 required.

More decisively, values that the table does attempt to encode are not lossless
or reliable. Direct comparison with the named current YAML files gives these
counterexamples:

* The `correction-convergence-escape-implementation-s1-003-profile.yaml` row
  says `[resolve]`, but `phases.rereview.review.finding_authority` is `[]`.
  The row's claim that this profile “differs by resolved Finding capability”
  is therefore false.
* The `finding-delta-compatibility-shim-fix-profile.yaml` row says
  `N/R/N/R` and `EC/REC/EC/REC`. Its `rereview` phase actually declares
  `durable_artifact: none` and `authorized_actions: [review]`, so the sequence
  is `N/R/N/N` and `EC/REC/EC/R` under the survey's own key.
* The `p35-finding-reachability-design-review-003-profile.yaml` row says
  evidence `p/p`. Its correction phase declares `evidence: []`; only rereview
  declares `[pytest]`, making the sequence `-/p`.
* The `projected-result-contracts-p1-profile.yaml` row says evidence
  `-/p/-/p`. All four phases actually declare `evidence: [pytest]`, making the
  sequence `p/p/p/p`.

These are material to the exact mandatory-process and Finding-capability
categories WPA-001 was opened to protect. The correction must replace the
source-pointer placeholders with a faithful per-profile representation of the
required values (a genuinely defined semantic signature plus a lossless
mapping remains sufficient), correct these counterexamples, and check every
other row against its YAML rather than fixing only the four examples.
