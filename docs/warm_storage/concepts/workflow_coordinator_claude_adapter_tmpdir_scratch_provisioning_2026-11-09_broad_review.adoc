== Blocking finding: the scratch root is not guaranteed distinct from the short root, and the degenerate case fails hard, leaks, and escapes as a non-contract exception

Locations:: `src/workflow_coordinator/claude_adapter.py:52-61,155-158,191-200,238-243`.
Invariant:: The adapter must obtain a dedicated large-capacity external
scratch target without a privileged host action and *as the ordinary
case*, at minimum on Ubuntu under WSL; a leftover or derived-path
coincidence must be handled deterministically rather than causing an
unhandled exception or a new accumulation path; cleanup must remove both
the symlink and its real target on success, local failure, and timeout.

`_external_scratch_root()` has no guarantee of returning anything other
than `_SHORT_TMP_ROOT` itself. When `TMPDIR`, `TMP`, and `TEMP` are all
unset -- the default on a stock Ubuntu/WSL shell, and on any host where
WFC's own launcher is not the parent -- `tempfile.gettempdir()` returns
`/tmp` on an ordinary host, which is exactly `_SHORT_TMP_ROOT`. The same
coincidence occurs whenever an operator or environment sets `TMPDIR=/tmp`
explicitly. `_external_scratch_dir()` and `_short_subprocess_tmp_dir()`
then derive the *same* path from the same token, and three things follow
from one driving of production `execute()` (reviewer probe, roots made
coincident; `/tmp` itself is unwritable in this shell, so a writable
stand-in root was bound to both sides -- the only property under test is
root equality):

----
short tmp dir : .../short/wfc-claude-9bf71f9d70463242
external dir  : .../short/wfc-claude-9bf71f9d70463242
paths equal   : True
CASE A raised : IsADirectoryError [Errno 21] Is a directory: '.../short/wfc-claude-9bf71f9d70463242'
CASE A cause  : None None
leftovers short: ['wfc-claude-9bf71f9d70463242']
----

. *Every invocation fails.* `real_dir.mkdir()` succeeds, then
  `tmp_dir.symlink_to()` necessarily raises `FileExistsError` on the path
  just created. The adapter cannot launch at all in this configuration, so
  the required "ordinary case" portability property does not hold: it
  holds only where something upstream already exported `TMPDIR` -- i.e. it
  still assumes the self-development launch layout, merely indirectly.
. *A non-contract exception escapes `execute()`.* The intended
  `ClaudeCliError` (`:225-226`) is raised, but the `finally` block then
  calls `tmp_dir.unlink()` on what is now a directory, and the resulting
  `IsADirectoryError` *replaces* it (note the empty `__cause__` above).
  Callers see a raw `OSError` subclass that is neither `ClaudeCliError`
  nor `ExecutionNotStartedError` -- precisely the "unhandled exception"
  the mandate forbids for a derived-path collision.
. *A new accumulation path is introduced.* Because the `unlink` raised,
  `rmtree(real_dir, ignore_errors=True)` on the next line never runs, so
  the created directory survives the invocation (`leftovers short` above).
  The two cleanup operations are sequentially coupled: any failure of the
  first silently forfeits the second and masks the in-flight exception.

A related consequence of the same unvalidated root: in a sandboxed shell
where `/tmp` is not writable, `tempfile.gettempdir()` falls back further
down its candidate list and can return the *current working directory*.
Confirmed in this shell: with `TMPDIR`/`TMP`/`TEMP` unset,
`tempfile.gettempdir()` returned
`/home/stefan/repos/spreadsheet-handling/workflow-coordinator` -- the
repository checkout. In that case the adapter would create its untrusted
scratch, grant `allowWrite` on it, and later `rmtree` it *inside the
repository working tree*, which is both the wrong trust placement and a
Git-status hazard mid-Hop. No privileged action is needed to fix this;
`create_attempt_scratch()`'s own unprivileged default
(`Path.home() / "wfc-scratch"`, `scripts/wfc_op.py:229`) shows the shape
of a WFC-owned fallback.

Suggested correction, kept inside the authorized three files: derive the
real target so it can never equal the short symlink path (for example a
distinct, WFC-owned subpath such as `<root>/wfc-claude-scratch/<token>`),
and when the resolved root is `_SHORT_TMP_ROOT` -- or otherwise not usable
as external scratch -- provision from an unprivileged WFC-owned root
instead (e.g. `~/.wfc-claude-scratch`, mode `0o700`, mirroring the FD-08
default) rather than silently placing bulk material back on the `tmpfs`
this Commission exists to protect. Guard the two cleanup steps
independently so neither can suppress the other or the original
exception. Add deterministic coverage for the `TMPDIR`/`TMP`/`TEMP`-unset
and `root == _SHORT_TMP_ROOT` cases; their absence is why this reached
review -- every unit test and two of the three live tests inherit the
ambient `TMPDIR` the harness happens to export
(`tests/unit/test_claude_adapter_conformance.py` sets it only at
`:212-224`; `tests/integration/test_claude_adapter_live_smoke.py:104,138`
set none).

== Non-blocking observations

* No committed test asserts the real target's `0o700` mode or ownership;
  the reviewer verified both directly. Worth a one-line assertion in the
  placement test.
* `_external_scratch_root()` validates nothing about the ambient value --
  not that it exists, is a directory rather than a symlink, is writable,
  or does not overlap the repository -- where `create_attempt_scratch()`
  validates all of these before use. A same-shaped (but non-coincident)
  bad ambient value therefore surfaces only as a generic
  "local pre-acceptance executable launch failure".
* An ambient `TMPDIR` that is itself *under* `/tmp` satisfies the current
  code but leaves bulk subprocess material on the `tmpfs`; nothing in the
  adapter distinguishes a large-capacity root from a small one. Acceptable
  under the authorized candidate direction, but the degenerate case in the
  finding above shows why a WFC-owned fallback is the safer default.
* Supersession in `_supersede_or_reject_leftover()` is gated on uid only,
  not on a WFC ownership marker, so a same-user non-WFC directory sitting
  at exactly `/tmp/wfc-claude-<16 hex>` would be removed. The path is
  WFC-namespaced and the mandate explicitly permits "safely superseded",
  so this is residual, not blocking. Genuine concurrency is safe by
  construction: the token derives from run/hop/invocation, so two
  concurrent invocations cannot share a derived path, and the leftover
  branch is reachable only for a repeated dispatch of the *same*
  invocation.
* `rmtree(..., ignore_errors=True)` in both the cleanup and the
  supersession path can fail silently; a failed supersession is at least
  caught downstream, since `mkdir()` is now exclusive (no `exist_ok`) and
  turns into a deterministic `ClaudeCliError`.
* All conformance tests share the invocation `("RUN-C", "H001", "INV-C")`
  and therefore one derived path pair, so the file is not safe under
  parallel test execution. The repository does not use `pytest-xdist`, so
  this is an observation only.
