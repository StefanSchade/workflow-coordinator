== Interfaces and behaviour

[source,sh]
----
python3 scripts/wfc_test_inputs.py fetch  --profile cp313-linux-x86_64 --bundle NEW_DIR [--from-dir TRANSFERRED_DIR]
python3 scripts/wfc_test_inputs.py verify --profile cp313-linux-x86_64 --bundle DIR
python3 scripts/wfc_test_inputs.py exec   --profile cp313-linux-x86_64 --bundle DIR -- COMMAND ARG...
----

* `fetch` without `--from-dir` is the only operation that contacts a network. It uses `urllib` with default TLS validation, only the profile's `https://files.pythonhosted.org/...` URLs, refuses redirects to any other host or scheme, bounds reads to the pinned size, checks size, SHA-256, tags and embedded metadata, builds a private staging directory and renames it to the new target only after a complete re-verification. Any failure removes the staging directory. An existing target is refused. `--from-dir` copies only the pinned names from transferred bytes, refuses symlinks, ignores (and reports) non-profile files, and applies identical checks.
* `verify` needs the host standard library only. It accepts exactly the twelve pinned files: no missing, extra, hidden, nested, symlinked, FIFO or other non-regular, or world-writable entries; the directory itself may not be a symlink or world-writable; size and SHA-256 equal; wheel-tag pairs accepted by the profile and installable on the host (`any`, `linux_x86_64`, `manylinux1/2010/2014`, `manylinux_X_Y` against the probed glibc; musllinux, other architectures and other Python/ABI tags rejected); archive members free of absolute or parent paths; exactly one top-level `.dist-info` whose name, version, Requires-Python, Requires-Dist and WHEEL tags equal the profile. Files are opened `O_NOFOLLOW`, hashed from the same bytes that are inspected. Host mismatch (implementation, 3.13, machine, system, SOABI, glibc floor, `ensurepip.version()` seed pip) is refused with an explanatory message; another host needs its own reviewed profile. No ARM or other profile is claimed.
* `exec` verifies, then runs the literal argv (`shell=False`) under a sanitized environment, then verifies again. It exits 125 when the tool, the pre-check or the post-check fails, 127 when the command cannot be executed, otherwise with the child's status. The environment drops every inherited `PIP_*` (case-insensitive) and sets `PIP_CONFIG_FILE=/dev/null` (pip then ignores global, user and site configuration), `PIP_NO_INDEX=1`, `PIP_FIND_LINKS=<absolute bundle>`, `PIP_NO_CACHE_DIR=1`, `PIP_DISABLE_PIP_VERSION_CHECK=1`, `PIP_NO_INPUT=1`, plus `WFC_TEST_INPUTS` and `WFC_TEST_PROFILE`. PATH, HOME, TMPDIR, proxies and all other variables are preserved. This is a no-index, no-cache configuration, not a network block. Build isolation is not disabled or altered.
* `tests/conftest.py`: by default every pytest run (including the unchanged `python -m pytest -q`) requires `WFC_TEST_INPUTS` and `WFC_TEST_PROFILE`, verifies the bundle against the repository profile, rewrites `os.environ` so that all nested venv, `pip install`, `wfc_op` prepare/launch and PEP-517 build subprocesses inherit the sanitized settings (relative paths become absolute), and verifies again at session end, turning a changed bundle into a failing exit status. Absent, half-set, unknown, incompatible or corrupt inputs raise a pytest usage error (exit 4) with remedies, before any test; there is no skip, xfail or fallback. `--collect-only`, `--help` and `--version` do not verify and run no tests.
* Fast/unit-only boundary: `--wfc-partial` is the only subset mode. It is honoured only when literally present in the command line (not via `PYTEST_ADDOPTS` or ini), needs explicit test paths below `tests/`, refuses the repository or `tests` directory itself, prints partial-run banners in header and summary, forces pip offline without find-links when no inputs are supplied (so a real-install test fails rather than reaching an index), and still fully verifies inputs when they are supplied. The standard task-check argv cannot select it. Known bypasses outside this design: a caller who controls the literal command may use pytest options such as `--noconftest` or `-p`; the required acceptance remains the fixed authored command.

== Prepare, launch and the Coordinator task-check

`scripts/wfc_op.py` is unchanged. Its `prepare` runs pip with the process environment; `launch.sh` freezes PATH and TMPDIR/TMP/TEMP only and otherwise inherits the launching shell. Hence prepare and launch must each be given their bundle selection by the operator, for example `exec --bundle DIR -- python3 scripts/wfc_op.py prepare ...` and the same for `launch`, or by exporting `WFC_TEST_INPUTS`/`WFC_TEST_PROFILE` in both shells. The Coordinator task-check (`python -m pytest -q`) then inherits those two variables through the existing environment; it needs no modified Coordinator, adapter or evidence policy. That the production evidence runner passes inherited variables was shown by P1 only as an isolated software seam; this P2 does not prove it for a full Run. If it does not pass them the task-check fails with the explicit message above, never by skipping.

== Staged-input lifecycle

. Operator (or a connected maintenance host) obtains the twelve wheels: `fetch` over HTTPS, or transfer of bytes. The original external wheelhouse is read only and is never modified or adopted as a trust anchor.
. The operator stages exactly those files into a disposable, ignored directory the worker may read (here `build/wfc/offline-p2-staged`, covered by `.gitignore` `build/`) and checks it.
. Each consumer (worker shell, prepare, launch, task-check) verifies the directory against the committed profile itself. Location confers no trust.
. Verification is repeated after use (`exec` post-check, pytest session end, and the manual re-verifications below).
. The directory is deleted after the Run. It is not part of any CommitIntent and holds no secrets.

== Residual limits and review focus

* Provenance remains official-metadata match plus local byte identity; the pinned bytes were also re-downloaded once here (see above), still no signature attestation.
* Closure is proven for this profile by the P1 measurements, the closure test, and the successful offline installs. A different backend/hook version, Python, libc or architecture needs its own profile; nothing is inferred from a tag.
* The seed-pip equality check uses the running interpreter's `ensurepip.version()`, not a hash of the seed wheel; the seed wheel SHA-256 is recorded in the profile only as reference text.
* `pip install` of a local directory builds in place and can pick up stale ignored `build/lib` content (observed above); this is existing behaviour, not changed here. P3 should use clean exports for installation coverage.
* Profile pins are deliberately coupled to `pyproject.toml` by a test: any dependency change fails until the profile is re-reviewed.
* `exec` and the conftest hook verify the bundle, but pip reads the directory after verification; the re-verification after use detects, not prevents, a concurrent change. Staging directories should be private to the Run.
