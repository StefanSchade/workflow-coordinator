[[evidence-disagreement-coverage]]
=== Preserve the existing Evidence-record disagreement security test

At `tests/unit/test_wfc_op.py:1181-1193`,
`test_archive_refuses_disagreeing_evidence_facts()` constructs preparation
records without any scratch facts. The new guard at
`scripts/wfc_op.py:1173-1175` refuses immediately with
`preparation facts disagree on scratch_root`. The test asserts only exit 2
and the substring `disagree`, so it passes without reaching an Evidence-path
agreement check. Its pre-existing admission-check intent is no longer
preserved, contrary to the explicit review mandate.

An independent probe reproduced the fixture twice: first with different
Evidence paths, then with identical Evidence paths. Both yielded exactly:

[source,text]
----
returncode=2
wfc-op: REFUSED: preparation facts disagree on scratch_root
original test assertions pass: True
----

Correction required: give this test a valid scratch directory and complete,
agreeing preparation facts for every unrelated field, vary only the
Evidence path, and assert an Evidence-specific disagreement plus zero wrapper
invocations. Preserve its original security purpose; a missing scratch key
must not satisfy it. This is a test regression, not a claim that the current
production Evidence disagreement checks are absent.

[[explicit-root-positive-coverage]]

An independent in-memory mutation wrapped `create_attempt_scratch()` so
that every non-null `value` raised `HarnessRefusal`, leaving default-root
behavior intact. Running all five new scratch tests with
`-k 'scratch or prepare_preflight_inherits'` still passed, exit 0. No source
or test file was edited for this experiment. A completely broken explicit
root option therefore escapes the new coverage.

Correction required: add a successful creation using a test-local absolute
root different from the default and a fresh validated Attempt ID, asserting
the selected root, exact child, ownership, and mode. Exercise that explicit
option through the existing preparation/preflight test seam as well, so
ignoring or unconditionally rejecting the CLI value fails the test. The
independent unmutated helper probe succeeds today; this finding concerns
missing required regression coverage.

== Implementation and security assessment

[cols="1,3",options="header"]
|===
|Boundary |Observed implementation
|Resolution and early creation
|`cmd_prepare()` validates the Attempt ID, derives OPS/STATE without allocating them, and creates scratch before repository pinning or any subprocess. The root is expanded and required absolute; the default is created if absent. An explicit root must already be a directory, consistent with the investigation's instruction to create the default if absent; no additional provisioning decision is required here.
|Filesystem refusal rules
|Root `lstat()` rejects symlinks and non-directories. Exclusive child `mkdir()` rejects existing directories, files, and leaf symlinks without reuse or deletion. `chmod(0700)` and post-creation ownership/mode checks fail closed. Resolved scratch paths are rejected for equality, containment, or ancestry against each supplied repository path; those same resolved repository paths are subsequently pinned. OPS and STATE equality is rejected as specified. Ancestor-replacement race hardening is outside this slice.
|Preparation environment
|All three variables are installed in `os.environ` before pinning/bootstrap, inherited by bootstrap subprocesses, copied into the canonical preflight environment beside frozen PATH, and restored for the embedding caller on return or failure. Generated `launch.sh` exports literal `shlex.quote()` values before `exec`; its existing digest check remains active.
|Records and status
|Both preparation files contain root and effective child. JSON and human-readable status project `scratch_path`. Scratch is not used as STATE, accepted evidence, or agent authority.
|Archive
|Both preparation files must agree on root and effective child, the child must equal root/Attempt, and recorded repository paths must agree. Retained root/child type, child uid/mode, repository overlap, and OPS/STATE distinctness are revalidated before either wrapper invocation. `_scratch_environment()` copies all caller variables and replaces only TMPDIR/TMP/TEMP. Both dry-run and real `subprocess.run()` receive this copy through additive `env=` arguments. Wrapper argv, Evidence selection, and dry-run-before-real sequencing remain intact.
|Lifecycle and exclusions
|No scratch deletion, retention policy, quota, capacity guessing, Runtime scratch option, recovery/retry, mixed-adapter interface, or provider-independent isolation mechanism appears in the diff. Scratch is retained across launch and refusal. No claim of provider-enforced filesystem containment is made.
|Existing security checks
|Repository-pin revalidation, launch/execution-bindings digest checks, A1 checks, executable provenance, and existing source-level admission behavior remain intact. No existing test was removed or newly skipped. The Evidence disagreement test nevertheless lost its effective coverage through the earlier guard, as documented above.
|Temp consumers
|The three inspected `git_facts.py` helpers use default `tempfile.mkstemp()` without an explicit `dir`, so a fresh Runtime process honors the inherited temporary-directory environment. Codex's `Popen` inherits the Runtime environment; evidence receives the immutable environment snapshot. No consumer-source change is necessary.
|===
