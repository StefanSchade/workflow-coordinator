== Isolation and fail-closed verification

Both committed integration tests run actual bwrap subprocesses through the
production runner. There are no mocks, dry-run flags, skips, or capability
shortcuts in either test. The combined filesystem test actually performs
every required in-sandbox filesystem operation:

* Reads ordinary read-only repository content and compares its real value.
* Writes a file in the explicit writable directory grant and verifies the
  resulting host content.
* Attempts a write to a protected file and verifies unchanged host content
  and nanosecond mtime.
* Tests existence of an unrelated synthetic host file and its directory,
  attempts reading the file, and attempts listing the directory at their
  original host paths. Those accesses fail inside the sandbox.
* Attempts reading `/repo/.git/secret` and creating `/repo/.git/new`.
  Both fail inside the sandbox; the repository's real metadata is hidden
  by an empty read-only tmpfs overlay.
* Writes and reads private scratch in the same sandbox, with the corrected
  host-side repository-temp distinction checks described above.
* Attempts writing through a writable-directory symlink whose target is
  the external synthetic host secret, and attempts a
  `/repo/writable/../../private/secret` traversal. Both fail, and the
  external host secret remains unchanged.

The two configuration tests are intentionally construction/rejection tests,
not claims of subprocess isolation. They verify exact file binding,
symlinked and relative source rejection, `.git` grant rejection, a missing
destination parent/remapping, overlapping destinations, missing bwrap, and
an empty command. Their invalid-configuration checks assert no subprocess
was spawned.

Additional reviewer probes exercised the actual runner with a single
writable file: writing that file succeeded, writing its sibling failed,
and creating a new file in the parent directory failed. Host observation
confirmed the granted file changed, the sibling remained unchanged, and
the new file did not exist. File authority is not widened to its directory.

Eight additional invalid-boundary probes directly constructed the public

== Bounded subset and trust claims

The supported subset is an existing real repository containing a real
`.git` directory, existing regular files/directories beneath it bound at
their identical `/repo/<relative>` destinations, and exactly one explicit
source-free scratch tmpfs at `/tmp`. Duplicate/nested explicit mounts,
external sources, symlinked sources, `.git` source components, arbitrary
remappings, system/repository overlap, and alternate scratch shapes are
rejected. Existing destination parents follow from the identical-path
mapping; automatic parent creation is unsupported.

A Commission grant naming a file that does not yet exist cannot be
translated by this version and is explicitly rejected rather than widened
to its parent. Git worktrees with a `.git` file and symlinked `.git`
directories are unsupported. Host sources must remain stable between
validation and execution, as the module documents; concurrent hostile host
mount-tree mutation is not a claimed guarantee.

The argv requests die-with-parent, read-only system executables/libraries,
read-only repository visibility, hidden/read-only Git metadata, exact
writable grants, and private scratch. There is no network-namespace flag
or network policy. This remains an opt-in provider-neutral library. It
does not resolve visibility/mutation/execution authority, change provider
permission behavior, replace authoritative post-Hop Git/scope checks, or
cross into the deferred elevated-surface workflow.
