== Current-Run F001: resolved within the supported stable-source model

`_check_writable_aliases` uses `lstat` and rejects every non-directory entry
whose link count is not exactly one. It walks directories without following
symlinks, so a symlink's own shared inode is checked independently of its
target. Regular files, symlinks, and special-file descendants now share the
same rejection branch. Direct writable regular-file grants are checked too.
Directory link counts are exempt because they include subdirectories and
ordinary Linux users cannot create directory hardlinks. Inspection errors
raise `BoundaryConfigurationError`. The existing `build_argv` revalidation
repeats the inspection immediately before the single bwrap launch site;
there is no unsandboxed fallback or retry.

All sixteen committed targeted instances passed: four unit cases and twelve
real-bwrap integration instances. The three new symlink cases each first run
actual bwrap to change the timestamp of an ordinary, unaliased symlink. They
then install a hardlinked symlink to an ungranted repository, root Git, or
external synthetic entry. Both validation and execution-time revalidation
reject the configuration, and the protected host symlink mtime is unchanged.
The existing six regular-file combinations and sandbox hardlink-creation
rejection also pass. Unsafe configurations must be rejected before spawn;
executing the unsafe command is not the expected success observation.

Independent probes, using the production validator and runner imported from
this checkout, exercised twelve static-fixture combinations: regular files
with file/directory grants, symlinks with directory grants, and FIFOs with
directory grants, each targeting protected repository, Git, and external
synthetic paths. Every non-aliased fixture first performed a successful
metadata write through actual bwrap. After installing a hardlink, all twelve
were rejected at both initial validation and execution-time revalidation;
a launch counter stayed zero. Host inode, link count, mode, nanosecond mtime,
and ctime stayed unchanged across those rejection attempts, and regular-file
contents stayed unchanged.

For sensitivity, replaced only the helper in memory with the H003 candidate's
regular-file-only check. All six symlink/FIFO fixtures then ran actual bwrap
successfully with `touch -h -d @123 /repo/writable/alias`; each ungranted
original's host mtime changed to `123000000000`. Separately called each of
the three committed symlink regression cases with that old helper. Each
failed with `DID NOT RAISE`, proving the regressions detect the old admission
bug. No source or test file was changed for these experiments.

An optional Unix-socket fixture could not be created: after shortening its
path, `socket.bind` returned `PermissionError: [Errno 1] Operation not
permitted` in the agent environment. No socket behavior is claimed tested.
This does not prevent checking the Finding: the general non-directory branch
is inspected, and real symlink and FIFO metadata bypasses and their rejection
were independently exercised. No capability or security setting was changed.

The documented source-stability precondition remains: callers must prevent
hostile concurrent changes to the source/mount tree during validation and
execution. Accurate filesystem link counts and ordinary Linux directory-link
semantics are assumed. This focused verdict does not extend that model to
concurrent hostile host mutations or broader execution/network containment.
