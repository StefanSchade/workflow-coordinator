[[regular-file-correction]]
== Regular-file aliases: correction independently verified

`_check_writable_aliases` recursively inspects writable directory entries
using `lstat` and rejects regular files whose link count differs from one.
Writable direct-file sources receive the same check. Inspection errors are
converted into configuration errors, and `build_argv` repeats validation
before the single subprocess launch site. No unsandboxed fallback exists.

All twelve focused tests passed locally: three configuration tests and nine
real-bwrap integration instances. The six new parameterized cases cover
file/directory grants crossed with protected repository files, Git metadata,
and external synthetic files. Each first performs an allowed write through
actual bwrap, then installs a regular-file hardlink and observes rejection by
both validation and execution-time revalidation. Unsafe configurations must
be rejected before launch; a successful sandbox launch is not the expected
observation for them. The other new integration test actually attempts to
create a hardlink from the read-only repository into the writable grant and
checks failure and unchanged host content.

Independent static-fixture probes exercised all six regular-file combinations.
The corrected validator rejected each with zero subprocess launches and
unchanged protected bytes and nanosecond mtime. Disabling only the helper in
memory allowed each identical fixture to execute through real bwrap and
change the ungranted target to `breached`. Separately, each committed
parameterized regression rejected the disabled helper with `DID NOT RAISE`.
These sensitivity experiments changed no source or test file.

Additional independent checks confirmed that writable-file `lstat` inspection
errors fail closed before launch for both grant types, aliases wholly within
a writable directory are conservatively rejected, and read-only aliased
regular-file grants cannot write their targets. Real-bwrap probes also
confirmed that a direct single-file grant permits that file's write while
denying sibling writes and parent-directory creation. An ordinary directory
symlink to an external file remains inaccessible for content writes.

[[symlink-inode-alias-bypass]]
== Blocking F001 remains open: hardlinked symlink metadata bypass

Location:: `src/workflow_coordinator/execution_boundary.py:51-68`, especially
line 62; writable-grant admission at lines 107-108.
Invariant:: Writable grants must not modify ungranted host paths, including
protected repository metadata, hidden Git metadata, and external host state.

The new link-count rejection is conditional on `stat.S_ISREG`. A symlink
inside a writable directory can itself have hardlink aliases. Not following
its target prevents a content escape, but does not prevent mutation of the
shared symlink inode with operations that explicitly do not follow symlinks.
This distinction is relevant to the governing FTR's write authority over
files, paths, metadata, and Git-adjacent surfaces.

Created three independent synthetic fixtures, with every link installed
before validation and no concurrent source mutation. The ungranted original
symlink was respectively `repo/protected-link`, `repo/.git/secret-link`, or
an external `external-link`. Each pointed to a nonexistent target. Created
`repo/writable/alias` using `os.link(original, alias, follow_symlinks=False)`;
`lstat` confirmed a shared inode and link count two. Production validation
accepted the writable-directory grant in every case. Production `run`
then executed actual bwrap with:

[source,shell]
----
touch -h -d @123 /repo/writable/alias
----

All three executions returned zero with empty stderr. Host `lstat` proved
that the corresponding ungranted original symlink's nanosecond mtime changed
from its current fixture timestamp to `123000000000`. The hidden root Git
overlay and read-only repository mount did not protect the shared inode
against mutation through the writable alias. An inaccessible symlink target
does not prevent this metadata write.

Minimal reproduction using the current candidate, no mocks:

[source,python]
----
import os
from pathlib import Path, PurePosixPath
from tempfile import TemporaryDirectory
from workflow_coordinator.execution_boundary import Mount, MountMode, run, validate

with TemporaryDirectory() as temporary:
    repo = Path(temporary) / 'repo'
    repo.mkdir()
    (repo / '.git').mkdir()
    writable = repo / 'writable'
    writable.mkdir()
    protected = repo / '.git' / 'secret-link'
    protected.symlink_to('nonexistent-target')
    os.link(protected, writable / 'alias', follow_symlinks=False)
    before = protected.lstat().st_mtime_ns
    boundary = validate(repo, [
        Mount(writable, PurePosixPath('/repo/writable'), MountMode.WRITABLE),
        Mount(None, PurePosixPath('/tmp'), MountMode.SCRATCH),
    ])
    result = run(boundary, ['/bin/sh', '-c',
                            'touch -h -d @123 /repo/writable/alias'])
    print(result.returncode, before, protected.lstat().st_mtime_ns)
    # Observed: 0, original timestamp, 123000000000.
----

Correction needed: reject unsupported shared symlink inodes in writable
directory trees without following their targets, and audit the same inode
alias assumption for other supported descendant types. Add regression cases
covering protected repository, Git, and external symlink aliases, including
execution-time revalidation and unchanged host symlink metadata. Preserve
ordinary symlink behavior and every existing case. This remains within the
module and two test files; no maintainer authority or scope expansion is
needed. The regular-file-only regressions all pass while this bypass exists,
so their success cannot resolve the general inode-alias Finding.
