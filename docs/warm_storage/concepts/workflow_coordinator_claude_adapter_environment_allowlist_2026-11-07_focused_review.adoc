== H004 assessment: diagnosis and bounded correction

The reviewer read the full permission-mismatch bug record and section 2 of
the execution-integration-debt record, the commission's recorded authority
source, the candidate diff against `725b329`, and the H002 broad review.
H003 produced no implementation correction; this review assesses the same
committed candidate independently.

The maintainer's established controlled A/B experiment used identical
adapter helpers and an explicit child-environment allowlist. With the scrub
variable present, Claude reported forced-default permission mode and denied
the authorized Bash command without an approval surface; its marker file
was absent. Omitting that variable allowed the command to succeed and
produce the expected marker. This is the supplied mechanism justification
for removing forced scrubbing; this review did not reproduce the live
experiment. Inspection independently confirms that the previous adapter
both requested `acceptEdits` and forced scrubbing, while inheriting the
entire parent environment and potentially its Claude session state.

The replacement constructs a fresh dictionary from present values of exactly
`PATH`, `HOME`, `USER`, and `LANG`, plus validated operator-selected names.
These defaults cover executable discovery, file-based authentication, user
identity, and locale. There is no environment copy, wildcard, fallback, or
implicit inheritance of other names. The unchanged per-invocation temporary
directory supplies `TMPDIR`, `TMP`, and `TEMP` separately.

Omitting `XDG_RUNTIME_DIR` is supported by inspection, not assumed. Without
executing it, the reviewer inspected embedded source in the installed
`/home/stefan/.local/share/claude/versions/2.1.270` image. The Linux sandbox
bridge imports `tmpdir` from `os`, constructs its HTTP/SOCKS sockets from
that function, and discovers `bwrap` and `socat` as executables. That bridge
does not require an XDG runtime directory. No additional default variable
is justified for this mechanism. Host-specific needs can use the explicit
extension rather than expanding every invocation's default environment.

`WFC_CLAUDE_EXTRA_ENV_NAMES` is one comma-separated source of additional
names, read at adapter construction; an explicit constructor tuple follows
the same validation. Selected values are obtained from the orchestrating
process at launch. Missing names are omitted. Identifier validation rejects
assignments and malformed entries; prefix validation rejects every
`CLAUDE_CODE_*` name, including a previously unknown name or the bare prefix.
All three temporary-directory names are reserved. Selection is additive,
defaults to empty, and has no settings, permissions, or scope interface.
This is a narrow name-selection mechanism, not a general environment or
permissions framework. Its operator documentation is present in the broad
review artifact.
