== The blocking finding from the broad review is resolved

H005 found that `_discoverable_path_siblings` tolerated only
`(FileNotFoundError, NotADirectoryError, PermissionError,
ExecutableResolutionError)` around its `_fingerprint` call -- a tuple copied
from the resolution loop -- while, unlike the loop, the probe stats *other*
names it discovered by listing the `PATH` directory. A plain `OSError` from
`os.stat` on such a name (for example `ELOOP`) therefore escaped
`resolve_executable`, bypassing the `except ExecutableResolutionError` at
`src/workflow_coordinator/evidence.py:224` and the `except ValueError` that
`operator.admit_parsed` (`src/workflow_coordinator/operator.py:516`) relies on
to produce an operator-facing preflight refusal. H006 widened the clause to
`except OSError` (`:144`).

== Independently reproduced behavior

=== The three required message facts are present

An authored bare `python` that does not resolve on a snapshotted `PATH`
containing `python3` raises the pre-existing type (`ExecutableResolutionError`,
still an `OSError`) with the pre-existing prefix, followed by the new clauses:

----
executable does not resolve to an executable regular file: python; discoverable
PATH siblings (informational only, not selected): python3; supply a conforming
environment by prepending its prepared bin/ directory to PATH
----

`prepare_evidence_commands` still wraps it unchanged, so the operator-facing
form keeps the policy-authored command name: `evidence command task-check:
executable does not resolve to an executable regular file: python; ...`. With no
discoverable sibling the clause reads `no discoverable PATH siblings` rather
than being omitted, so the message shape is stable.

=== Resolution, fingerprinting, alias handling and preflight are unchanged

(`16a3034`, before the probe existed) and this candidate on the *full*

No alias substitution: with `python3` present and `python` authored, `python3`

=== The probe is bounded, read-only and quiet

* *Read-only.* Only `os.listdir`, `os.stat` and `os.access` are used. A
  prefix-matching sibling whose body would `touch` a marker is listed but never
  executed, and the marker does not exist after the full refusal (committed
  test, plus the mutant that makes the probe execute candidates is killed).
* *Bounded.* `DISCOVERABLE_SIBLING_PROBE_LIMIT` is 5 and is enforced across
  `PATH` entries. Worst case measured with the bound saturated by eight
  255-character names: a 1496-byte message.
* *Selective.* The authored name itself, unrelated names, non-executable
  regular files, directories named like a sibling and dangling symlinks are all
  excluded; names are de-duplicated across `PATH` entries (two `PATH` entries
  each holding `python3` yield `('python3', 'python3-config')`).
* *Tolerant.* A missing directory, a regular file used as a `PATH` entry and an
  unreadable directory are skipped without raising, and later entries are still
  probed.
* *No path disclosure.* Only basenames enter the message; neither the `PATH`
  entries nor the repository path appear.

== Non-blocking observations

* *Hostile-but-legal sibling names reach the refusal text verbatim.* A
  prefix-matching executable may be named with a newline, an ANSI escape
  sequence or bytes that are not valid UTF-8; `os.listdir` returns it (the last
  case surrogate-escaped) and it is interpolated into `str(error)` unsanitised
  (`tmp/review-h007/hostile_names.py`). Reproduced consequences, all
  non-blocking: the refusal keeps its class and stays fail-closed in every case
  (`ExecutableResolutionError` /`EvidencePreparationError`, still caught by the
  admission seam's `except ValueError`); the message stays bounded; every
  production sink prints refusals to `sys.stderr`
  (`scripts/wfc_op.py:530`, `:1329`), whose default `backslashreplace` error
  handler escapes a lone surrogate instead of raising; and JSON serialisation is
  safe because `json.dumps` defaults to `ensure_ascii=True` (explicitly at
  `src/workflow_coordinator/operator.py:551` and
  `src/workflow_coordinator/frontdoor/audit.py:505`, by default at
  `src/workflow_coordinator/frontdoor/journal.py:125`). What a crafted name can
  do is forge extra lines or terminal escapes in operator-facing stderr; nothing
  machine-readable parses that text (the canonical preflight seam keys on the
  child's exit code), and writing such a file into a `PATH` directory already
  requires write access there. Encoding probed names with
  `errors="backslashreplace"` and rejecting names outside a conservative
  character class would close it if the maintainer wants it closed.
* *The prefix rule is one-directional.* Siblings are names that start with the
  authored token, so the record's observed case (authored `python`, host has
  `python3`, also `python3.13`) is covered, while the inverse (authored
  `python3`, host has only `python`) reports `no discoverable PATH siblings`.
  That is a diagnostics limitation, not a contradiction of the record's desired
  direction.
* *Empty `argv[0]` lists arbitrary executables.* Every name starts with the
  empty string, so `resolve_executable("", ...)` reports up to five unrelated
  `PATH` executables. Unreachable through admission -- the policy parser rejects
  an empty `argv[0]` (`tests/unit/test_a2_evidence_commands.py:150-157`) -- and
  the refusal class is unchanged.
* The bound test derives its expectation from the constant, so the intended
  small value is not pinned; an absolute upper assertion alongside it would pin
  both. (Carried from H002 and H004, independently reproduced.)
* The probe recomputes `repository.resolve()` and re-derives each `PATH` entry's
  base directory, duplicating four lines of the resolution loop. It is on the
  refusal path only and the parity matrix shows identical rooting, but a shared
  helper would keep the two rootings from drifting apart.
* *Outside this WorkItem's scope:* the overview card at
  `docs/backlog/_open.adoc` still frames the item as "investigate actionable
  missing-tool/environment messages before selecting a correction", which the
  implementation has overtaken. The overview is the maintainer's to update and
  was correctly left unchanged; its "never silently substitute `python3`"
  constraint remains honored.
