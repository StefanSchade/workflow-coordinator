[[command-flow]]
== Quick-reference command flow

Use this index from a WFC Development source checkout (one fresh checkout
per Run; see
link:{operator-docs}/operator_manual/ch05_self_development/01_topology_budget.adoc#self-development-checkout-rotation[checkout rotation]).
The command names below are navigation, not a second preparation recipe.

[cols="2,4",options="header"]
|===
|Command |Owning procedure and interpretation

|`wfc init --scope-ceiling ...`
|link:{operator-docs}/operator_manual/ch03_running/01_preparation.adoc#harness-preparation[the product Front Door]
owns input selection and the complete invocation. Writes the Consumer
Config (`.wfc/config.yaml`) once per repository; never commits it.

|`wfc plan <task-file> --program ... --persona ... --evidence-command ... --evidence-argv ...`
|link:{operator-docs}/operator_manual/ch03_running/01_preparation.adoc#harness-preparation[preparation]:
a read-only preview of the Commission/execution-envelope projection the
authored Consumer Request would compile. Writes nothing.

|`wfc run --request <request.yaml> --yes`
|link:{operator-docs}/operator_manual/ch03_running/02_launch_status.adoc#launch[LAUNCH]:
authorize and launch; the first real provider dispatch crosses the
provider boundary.

|`wfc resume [--preview]`
|link:{operator-docs}/operator_manual/ch03_running/02_launch_status.adoc#launch[LAUNCH]:
continue an already-authorized checkout after an interrupted controller, or
recover the same Run for one of the two eligible stop classes
(link:{operator-docs}/operator_manual/ch06_recovery/01_outcomes.adoc#mechanical-recovery[mechanical]
and
link:{operator-docs}/operator_manual/ch06_recovery/01_outcomes.adoc#quiescent-interruption[quiescent
interruption]); never starts a new lifecycle. `--preview` states the recovery
decision and changes nothing.

|`wfc status`
|link:{operator-docs}/operator_manual/ch03_running/02_launch_status.adoc#status[STATUS]:
inspect persisted lifecycle/preservation/archive facts and
link:{operator-docs}/operator_manual/ch03_running/02_launch_status.adoc#terminal-states[terminal states].

|`wfc audit <attempt-dir>` / `wfc report <source>`
|link:{operator-docs}/operator_manual/ch04_evidence/02_archive.adoc[ARCHIVE]:
project and render the sanitized record of an archived Attempt; usually
automatic, see below.

|`wfc archive <state-root> <evidence-repo> --dry-run`
|link:{operator-docs}/operator_manual/ch04_evidence/02_archive.adoc#archive[ARCHIVE]:
automatic as part of `wfc run`/`resume`'s own postrun step; direct
invocation (optionally `--dry-run` first) remains available for the cases
named there.

|`wfc skill install (claude\|codex)` / `wfc skill status (claude\|codex)` / `wfc skill show`
|link:{operator-docs}/operator_manual/ch09_consumer_quickstart/01_quickstart.adoc#quickstart-skill[install
the agent skill]: install, inspect or print the packaged `wfc` Agent Skill
into an agent host's own skill directory; for an agent session operating
WFC, not a WFC lifecycle step itself.

|`python3 examples/consumer-demo/make_workspace.py` / `rehearse.py`
|link:{operator-docs}/operator_manual/ch09_consumer_quickstart/00_overview.adoc#consumer-overview[the
consumer overview] and its
link:{operator-docs}/operator_manual/ch09_consumer_quickstart/00_overview.adoc#consumer-overview-tutorials[three
tutorials]: build a disposable demo workspace and rehearse one Run offline,
with no provider call; a companion kit, not this index's own commands.
|===

Continue with link:{operator-docs}/operator_manual/ch04_evidence/02_archive.adoc#semantic-ledger[semantic ledger curation].
Any open authority/Finding gap requires a fresh maintainer decision under
link:{operator-docs}/operator_manual/ch03_running/02_launch_status.adoc#terminal-states[stop interpretation]
and link:{operator-docs}/operator_manual/ch06_recovery/01_outcomes.adoc[recovery].
Only then, separately and explicitly, consider
link:{operator-docs}/operator_manual/ch05_self_development/02_promotion.adoc[Runtime promotion]
and push; the command index grants no such authority.
