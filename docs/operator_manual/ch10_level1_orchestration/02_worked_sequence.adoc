[[level1-worked-sequence]]
== Example sequence on a demo-style repository

This walks three small, consecutive Commissions on a tiny demo repository
(`greeter`), in the shape of the operating pattern above. The setup and the
first Commission's preview below were actually executed against a real
scratch repository with the installed `wfc`; launching a Run was not, since
that needs an authenticated provider CLI not available when this material
was verified. Where a step was not executed, this says so and describes
what to expect and check instead of inventing output.

=== Setup (verified)

A tiny repository, already on branch `main` with a non-mutating check
command committed:

[source,shell]
----
# greeter/checks/check.py: every AsciiDoc file under docs/ starts with a level-0 title
python3 checks/check.py            # exit 0 on the clean tree

wfc init --repository . --scope-ceiling docs --evidence-repository ../greeter-evidence
----

This printed (abridged): `wrote Consumer Config: .wfc/config.yaml`;
`NEXT EXPLICIT ACTION: ... wfc init never commits it.`; `Evidence
repository (created new): ...`; `NOTHING WAS PUSHED: the Evidence
repository has no remote configured.` `.wfc/config.yaml` was then edited by
hand to add a `worker` binding and committed with the check script and a
one-line `.wfc/governance/repository-policy.md`.

=== Commission 1 -- add a hello page

Task document (`../scratch/task.md`, outside the repository):

[source,text]
----
# Add a hello page

Create docs/hello.adoc: a short AsciiDoc page whose first line is `= Hello`
followed by one sentence of your choice.

## Acceptance
The task-check passes and docs/hello.adoc exists with the title line as its
first line.

## Withheld authority
No change outside docs/hello.adoc.

## Default escalation
Stop and ask if the task cannot be completed inside the authorized scope.
----

Preview (executed, read-only, exit 0):

[source,shell]
----
wfc plan ../scratch/task.md --repository . --scope docs/hello.adoc \
  --commission-id hello-page-001 --work-item-id WI-HELLO-PAGE-001 \
  --authority-source "Repository owner authorizes this bounded demo task." \
  --program simple@v1 \
  --persona worker="Bounded worker: create exactly the requested file, nothing else." \
  --evidence-argv python3 --evidence-argv checks/check.py \
  --guidance-path .wfc/governance/repository-policy.md
----

This printed the projected scope (`docs/hello.adoc`), the persona, the Hop
ceiling, the evidence command, the guidance commit, a projected Commission
manifest digest and a resolved execution envelope digest, confirming that
nothing was written or run by the preview itself. Check that the printed
scope, evidence and guidance are exactly what the task intends *before*
authoring the Consumer Request YAML from the same fields.

Launching was not executed in the verified material. The next step would
be, following
link:{operator-docs}/operator_manual/ch10_level1_orchestration/01_operating_pattern.adoc#level1-loop[the
launch loop] above:

[source,shell]
----
wfc run --repository . --request ../scratch/request.yaml --executable claude --yes
----

What to expect: either `CLASSIFICATION: completed`, meaning the task-check
passed and (`simple@v1`) the Worker's self-check was satisfied, or a
legitimate stop such as `awaiting_human`. What to check before integrating:
`docs/hello.adoc` exists, its first line is `= Hello`, nothing outside
`docs/hello.adoc` changed, and `wfc report` on the archived Evidence agrees.

=== Commission 2 -- add a goodbye page

`greeter`'s checkout already authorized Commission 1's lifecycle once
`wfc run` actually launches it, so this Commission needs a *fresh*
worktree, per
link:{operator-docs}/operator_manual/ch05_self_development/01_topology_budget.adoc#self-development-checkout-rotation[one
fresh checkout per Run]:

[source,shell]
----
git worktree add ../greeter-wt2 -b work/goodbye-page main
cd ../greeter-wt2
wfc plan ../scratch/task2.md --repository . --scope docs/goodbye.adoc \
  --commission-id goodbye-page-001 --work-item-id WI-GOODBYE-PAGE-001 \
  --authority-source "Repository owner authorizes this bounded demo task." \
  --program simple@v1 \
  --persona worker="Bounded worker: create exactly the requested file, nothing else." \
  --evidence-argv python3 --evidence-argv checks/check.py \
  --guidance-path .wfc/governance/repository-policy.md
----

`task2.md` is the same shape as `task.md`, asking for `docs/goodbye.adoc`
with first line `= Goodbye`. Not executed here; expect the same preview
shape as Commission 1 (projected scope, digests, "nothing was run or
written") with its own digests -- check the printed scope is exactly
`docs/goodbye.adoc`, author the Consumer Request, then launch
and wait exactly as in Commission 1. Verify `docs/goodbye.adoc`, its first
line, and that nothing else changed; then fast-forward and clean up exactly
as in
link:{operator-docs}/operator_manual/ch10_level1_orchestration/01_operating_pattern.adoc#level1-loop[the
launch loop]'s own integration step.

=== Commission 3 -- an index page linking both

This Commission genuinely depends on the first two: it links
`docs/hello.adoc` and `docs/goodbye.adoc`, so it should not launch before
both are integrated into `main`. Fresh worktree again; task scope
`docs/index.adoc` only (a new file, so neither existing page is touched);
acceptance: the task-check passes and `docs/index.adoc` links both pages.
Preview, author, launch, wait and verify exactly as above; because the
Withheld authority on this task denies any change outside `docs/index.adoc`,
a Worker that finds it needs to edit `docs/hello.adoc` or
`docs/goodbye.adoc` to satisfy the task is expected to stop and ask rather
than widen its own scope -- that is correct behavior, not a defect, per
link:{operator-docs}/operator_manual/ch02_commissioning/01_authority.adoc#mutation-scope[Commission
mutation-scope granularity].

This sequence shows the real preview mechanics and the checkout discipline
three consecutive small Commissions need; it does not show an actual
`wfc run` transcript, which depends on an authenticated provider and the
bound models, and it is not a claim that any of the three would complete in
one Hop -- read the real classification each time, not this chapter.
