[[consumer-overview]]
== Start here: what WFC does

A Run is one bounded, independently authorized task that WFC's engine
carries out against a single repository, Hop by Hop, under a Commission it
cannot exceed; see
link:{operator-docs}/operator_manual/ch01_orientation/_chapter.adoc#orientation[the
orientation chapter] for the full mental model. The rest of this page, and
the three tutorials it points to, show that in a disposable demo workspace
before you try it on your own repository.

Two commands build that workspace and rehearse its middle tutorial, offline
and in seconds:

[source,shell]
----
python3 examples/consumer-demo/make_workspace.py ~/wfc-demo
python3 examples/consumer-demo/rehearse.py ~/wfc-demo t2-farewell
----

[[consumer-overview-workspace-map]]
=== The workspace map

[source,text]
----
~/wfc-demo/                       the demo workspace; not a Git repository
├── greeter/                      (1) the repository being modified
│   ├── checks/check.sh           (4) the one trusted check
│   ├── docs/reviews/             (4) review artefacts, written by the reviewer
│   └── .wfc/
│       ├── config.yaml           (3) scope ceiling, Hop ceiling, Evidence location
│       └── governance/
│           ├── repository-policy.md
│           └── <commission-id>/  (2) the Commission, committed by `wfc run`
├── greeter-run-<name>/           one worktree of greeter per Run; (5) its Git log
├── greeter-evidence/             (6) the Evidence repository
├── requests/                     (2) task documents and Consumer Requests
└── rehearsal-home/               (6) lifecycle state of rehearsals
----

[cols="1,3,5",options="header"]
|===
|No. |What |Rule to remember

|1 |The repository being modified
|link:{operator-docs}/operator_manual/ch09_consumer_quickstart/01_quickstart.adoc#quickstart-next[One
fresh worktree per Run]; a checkout holds one lifecycle.

|2 |Commission and authorized scope
|link:{operator-docs}/operator_manual/ch02_commissioning/01_authority.adoc#inputs-and-ownership[Written

|3 |Execution configuration and provider bindings
|link:{operator-docs}/operator_manual/ch09_consumer_quickstart/01_quickstart.adoc#quickstart-init[Adapter,

|4 |Checks and review artefacts
|link:{operator-docs}/operator_manual/ch09_consumer_quickstart/01_quickstart.adoc#quickstart-request[The

|5 |Trusted commits
|link:{operator-docs}/operator_manual/ch04_evidence/01_acceptance.adoc#commit-intent-admission[Made

[[consumer-overview-rehearsal-vs-live]]
=== Rehearsal and live Run

A *rehearsal* (`rehearse.py`) calls no model, costs nothing and always ends
the same way; it demonstrates WFC's control flow, authority boundaries and
evidence, and nothing about model quality. Its archived record names the
model `rehearsal-no-model`. A *live* Run needs an installed, authenticated
provider CLI (see
link:{operator-docs}/operator_manual/ch09_consumer_quickstart/01_quickstart.adoc#quickstart-prerequisites[prerequisites]),
costs usage (see
link:{operator-docs}/operator_manual/ch10_level1_orchestration/01_operating_pattern.adoc#level1-cost[starting
small, and what it costs]) and may end differently. The two never mix on one
page without a clear, separately labelled heading.
