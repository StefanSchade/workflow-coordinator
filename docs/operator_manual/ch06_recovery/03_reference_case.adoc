== 2. Worked reference case

Authority:: historical

Primary reference attempt::
`wfc-evidence-failure-disposition-hardening-20261009-01`

Primary reference Run::
`RUN-c661748adf434e74bcf0e15f2b05ff9f`

Predecessor implementation H001::
`f274db058ecb92c607de086c374c2050dc87c821`

Predecessor independent-review H002::
`dbfdea7262e1ecd72fea2f65c8fbefdd5e241f40`

Observed stop::
H002 semantically accepted the candidate; Coordinator-owned full `pytest`
failed and correctly followed `failed_evidence_route` to correction. H003 then
corrected two unit-test regressions but stopped because the remaining failure
was in `tests/architecture/test_self_development_governance.py`, outside its
authorized scope.

Predecessor archive Evidence commit::
`b076fd714232329c16f77f9c98f527a81797ee41`

Preserved H003 salvage commit::
`02c08ad` (`wip(wfc): preserve stopped evidence-disposition H003 candidate`)

Non-authorizing architecture-disposition concept recorded while handling the
case::
`0240a68` (`docs(wfc): record level-1 architecture disposition concept`)

This case is a worked example, not a template whose semantic conclusion may be
copied into unrelated Runs.

Historical storage note::
`02c08ad` predates the CandidateSnapshot refinement recorded on 2026-10-11 and
remained in ordinary Development history. The later P3 case used a dedicated
candidate ref off `main`. These are historical storage choices, not a requirement
to rewrite `02c08ad` or any existing salvage history. Current exact preservation
is owned by link:{operator-docs}/operator_manual/ch06_recovery/01_outcomes.adoc#_canonical_salvage_procedure_outcome_2[the
normative salvage procedure]; optional manual refs are explained in
link:{operator-docs}/operator_manual/ch06_recovery/02_successors.adoc#_3_3_salvage_is_not_a_run[current successor guidance].

Secondary reference attempt::
`wfc-projected-result-contracts-p3-20261011-03`

Secondary reference Run::
`RUN-8875175a2ea343adbaf47c105699f91e`

Original trusted Run baseline::
`d2adf082b23f41fe0ae63b6b92e2c72e98dba414`

Observed semantic stop::
H001 discovered through fresh source inspection that P3's required
`result_contract_version` 3 execution path could not complete because
`src/workflow_coordinator/adapter.py` still rejected versions outside `{1, 2}`.
That file was explicitly withheld from the Commission. The worker therefore
returned a scope escalation instead of silently widening authority.

Observed mechanical stop::
The worker had already produced useful in-scope changes. Because the blocked
result carried no trusted `CommitIntent`, those changes remained dirty tracked
state. The Coordinator separately fail-closed on that dirty worktree. This
mechanical preemption was a consequence of the semantic scope stop, not its root
cause.

Predecessor archive Evidence commit::
`4b5261a2ecafc03bb9cc2478119bdba522cf7a47`

Preserved H001 CandidateSnapshot commit::
`ccd1d57ee28c666a4724ff512a500639b1c6dc1b`

Candidate ref::
`refs/wfc/candidates/RUN-8875175a2ea343adbaf47c105699f91e/H001`

Candidate authority::
None. The CandidateSnapshot preserves useful work only. It is unreviewed,
unaccepted, and not a trusted Product Increment. The candidate commit was
removed from `main` after the dedicated ref was established.

This second case demonstrates a different but complementary continuation
condition: the Commission itself can contain an incorrect implementation-boundary
assumption. Level 0 behaved correctly by discovering and escalating that
mismatch rather than repairing its own authority boundary.

[[_6_experience_captured_from_the_reference_case]]
== 6. Experience captured from the reference case

Authority:: historical

[cols="2,3,3",options="header"]
|===
|Observation |Implication |Status

|H002 semantic `accept` was followed by Coordinator-owned `pytest` failure and automatic correction routing.
|Semantic review outcome and trusted evidence are distinct; the evidence-failure route is load-bearing.
|Observed and desired.

|H003 could fix in-scope unit regressions but not an architecture-test failure.
|Narrow authority can prevent "make tests green" from silently becoming "rewrite architecture".
|Observed and valuable.

|The architecture test was stale only with respect to *new-launch preflight*; historical parsing/salvage remained intentional.
|A future continuation intent needs semantic rationale, not merely `extra_scope`.
|Observed; target-architecture input.

|The stopped Run had useful dirty work.
|Archive and salvage are different operations; archive preserves Run evidence, salvage preserves candidate work.
|Observed; runbook invariant.

|Manual continuation required archive, diff inspection, CandidateSnapshot preservation, semantic disposition, four governing files, validation, commit, PREPARE, and LAUNCH.
|This is too much ceremony for long-term routine operation, even though the authority boundaries are useful.
|Automation candidate.

|The maintainer could make the architecture disposition without modifying Level 0.
|A higher orchestration layer can classify/authorize successor work while Level 0 remains bounded.
|Supports Level-1 hypothesis.

|A generic "give worker more scope" continuation would have been semantically weaker than the actual decision.
|Successor automation must encode authority rationale and bounded delta, not mechanically widen scope.
|Hard target constraint.

|P3 H001 discovered through fresh source inspection that a Commission-withheld file was nevertheless required for the commissioned implementation path.
|Architecture-adjacent Commissions cannot always know their complete implementation file surface in advance; a typed scope escalation is a valid successful L0 outcome.
|Observed and desired.

|P3 preserved the semantic scope escalation even though useful worker changes subsequently caused dirty-worktree mechanical preemption.
|Semantic stop and mechanical preservation/cleanliness facts must remain distinct; the later mechanical stop must not obscure the architectural question that caused the Run to stop.
|Observed and load-bearing.

|P3's worker did not widen its own scope when the Commission boundary proved wrong.
|Level 0 can safely execute an imperfect Commission because discovering an authority-boundary defect is itself a legitimate result; disposition belongs above Level 0.
|Positive Level-0 evidence.

|The P3 dirty candidate was manually preserved off `main` as commit `ccd1d57...` under `refs/wfc/candidates/RUN-8875175a2ea343adbaf47c105699f91e/H001`.
|Useful stopped-Hop work can be preserved without making it accepted Development history or granting it implementation authority.
|Observed manual practice in this case; future automation candidate at the time.
|===
