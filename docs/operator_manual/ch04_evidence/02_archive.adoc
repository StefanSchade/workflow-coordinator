[[archive]]
== ARCHIVE

[source,shell]
----
python3 scripts/wfc_op.py archive "$ATTEMPT" --dry-run
python3 scripts/wfc_op.py archive "$ATTEMPT"
----

Run these commands from the WFC Development source checkout after the Run
reaches a terminal state; `ATTEMPT` identifies its prepared envelope.
`archive` is a deterministic, delegating wrapper around the canonical
`workflow-coordinator-run-evidence/scripts/wfc-archive-run`. Harness derives
the wrapper's two positional arguments -- STATE root and Evidence repository
-- from the Attempt's own preparation facts, refusing if the two preparation
records disagree on the Evidence path. Default behavior is always
*canonical dry-run, then canonical real archive*; passing `--dry-run` to
`wfc-op archive` stops after the plan. `--semantic-json /absolute/path/to/semantic.json`, if given, is
forwarded to the canonical wrapper on both calls without interpreting the
JSON; Harness resolves the supplied path to an absolute path. Harness implements none of the copying, hashing,
manifest, or fact-extraction logic itself.

The following layers have different owners and purposes:

[source,text]
----
STATE              persisted WFC execution state
mechanical archive copied evidence and manifest with file hashes
archive Run index  derived inventory of archived Runs, reproducible from
                   manifests; not a source of Run-state authority
semantic ledger    selective curated history and interpretation
external research  non-Run experiments, with their own evidence boundaries
project history    narrative Cold-Storage context, not current authority
----

The Harness delegates mechanical archiving; it does not regenerate the derived
index or curate the ledger. Index regeneration and semantic curation are
separate operator tasks, and neither replaces the mechanical archive.

[[installed-archive]]
=== Installed `wfc archive` (ported capability)

[source,shell]
----
wfc archive <state-root> <evidence-repo> [--semantic-json PATH] [--dry-run]
----

`frontdoor/archive.py` ports `scripts/archive_run.py`/`scripts/wfc-archive-run`
into the package itself: the allow-list, source isolation, digest-verified
copy and mechanical fact extraction are unchanged, and a freshly written
`manifest.json` is byte-compatible with the one the ported scripts would
have produced, apart from `archived_at`. Two things are new: the copy lands
in a staging directory and is renamed into place only after verification (a
partial copy is never visible at the destination), and the command is
retry-safe -- a destination already placed but not yet committed resumes to
the commit only after reverifying the placed attempt id, recorded sources
and every copied file's own digest and size against the manifest, *and*
reverifying the placed manifest itself (identity, per-file provenance,
facts and semantic payload, `archived_at` aside) against a manifest
freshly derived from the current authoritative Run/OPS sources; a file
tampered together with a matching altered digest in its own manifest, or a
falsified fact/source/semantic field with every file left untouched, is
refused just as a plain content/size mismatch is. An identical repeat is a
no-op; the commit itself uses the same bounded,
hook-free primitive (`git_facts.bounded_path_commit`) the Commission commit
uses, so the old wrapper's descriptive commit *body* is reported on stdout
instead. The destination and staging paths are refused outright, before any
file is written, if any component of either escapes the Evidence repository
through a symlink (for example a tracked `archive/` symlink pointing
outside it). This is currently a standalone, directly invoked capability;
self-development itself continues to archive through `wfc-op archive` above
until a later Commission switches it over, and `wfc run`'s own lifecycle
does not yet call it.

[[semantic-ledger]]
== Semantic ledger curation

After a mechanical archive exists, current project convention adds a
curated entry to `workflow-coordinator-run-evidence/project_memory/
run_ledger.adoc`: Runtime version, domain exercised, what happened across
Hops, model/role bindings, related commits/BUGs, predecessor/successor
links, lessons, evidence location. This is maintainer-owned, commonly
LLM-assisted, and performed separately against the already-archived
mechanical facts -- not automated by `wfc-op archive` or designed here.

The ledger explicitly covers *selected* Runs and external experiments, not the
full population of all Runs. In the sibling Evidence repository,
`project_memory/archive_run_index.adoc` documents a separate derived
`archive_run_index.jsonl`, exclusions and regeneration command. It groups
archived copies by Run ID and preserves unknowns; use its documented population,
status and time-window conventions for any count. An archive-only success rate
is not a rate for all Runs ever started. At the 18 November 2026 snapshot, 133
unique archived WFC Runs were indexed; 30 other locally retained Run summaries
had no matching archived ID and had not been individually checked for archival
eligibility. These are dated observations, not a completeness guarantee or an
authorization to bulk-archive.

External experiments under Evidence `experiments/` are not WFC Runs and do not
become Coordinator-trusted evidence by being retained. The
link:{operator-docs}/cold_storage/project_history/README.adoc[project history]
is a narrative source, not an admission or acceptance record. Preserve the
identity and outcome of each stopped predecessor when curating a successor.

[[evidence-architecture]]
== Evidence architecture: current state vs. future direction

*Current state (implemented today).* For self-development, mechanical
archive evidence lives in the sibling `workflow-coordinator-run-evidence`
repository under `archive/<classification>/<attempt>/`, each with a
`manifest.json` of copied files and SHA-256 digests. The curated semantic
ledger lives in the same repository at `project_memory/run_ledger.adoc`.
`wfc-op archive` delegates to its `scripts/wfc-archive-run`; Harness owns
none of its copy/manifest/commit logic.

One practical limitation of the current archive, confirmed by the
link:{operator-docs}/cold_storage/backlog/pre-0.1.0b1/projected-result-contracts/wfc_p2_stagnation_audit_2026-10-09.adoc[historical P2 stagnation audit]: a trusted evidence
observation persists its exit classification, exit code, and byte-count/
SHA-256 digests of stdout and stderr, but not the full output body. A failed
(`"fail"`-status) observation additionally carries a bounded, explicitly
untrusted diagnostic capture (at most a 16 KiB tail of each of stdout/
stderr, with truncation metadata), giving a subsequent correction Hop
(link:{operator-docs}/operator_manual/ch04_evidence/01_acceptance.adoc#review-topology[review/correction topology]) a recoverable signal of *which* assertions or tests failed
without re-running the command itself. This capture is never produced for a
`"pass"` observation, is never fabricated for an `"error"` observation that
captured no real bytes, and is never merged into or treated as trusted A2
evidence -- it does not change what WFC-EVID-08 requires of the digest/
body-omission fields above. Beyond this bounded tail, the full output body
still is not persisted; a correction Hop may still need to re-run the
command itself for anything the tail does not cover.

*Future direction (design intent only -- not implemented).* Evidence
archival should eventually be a WFC *product capability*, not merely a
self-development add-on: a consumer repository might configure durable
archival as disabled, repository-local, or external (a sibling/central
Evidence repository, as self-development already uses). Motivation:
long-term auditability favors curated, machine-readable records over
uncontrolled raw logs; future retrieval tooling may be as simple as
deterministic `jq`/scripts before anything more elaborate is justified.
Nothing here designs or implements this; it is recorded so a future
maintainer does not mistake today's self-development-specific arrangement
for the final product shape.
