=== H004-R1 -- Canonical manifest mutation after export is accepted at preparation

The accepted lifecycle states that mutating any bundle byte after export or
preparation invalidates it and blocks later use. `_load_manifest()` now
compares the manifest bytes with a canonical rendering of their parsed value.

but it is not an integrity anchor to the bytes produced by the successful
export. A changed value can simply be written in the same canonical form.

The direct probe changed only the `omissions` array after export, preserved the
closed shape and every object/source fact, and canonically rewrote the file.
Preparation accepted it, freshly digested the changed manifest, and published
a descriptor. Consequently an operator did not receive fail-closed evidence
that the supplied bundle was byte-identical to the completed export, and
changed omission metadata could enter the successor inventory as though it
were export truth. The later descriptor digest protects only the already
changed bytes selected at preparation.

Required correction: bind preparation to the exact manifest identity produced
by the successful export and reject every post-export byte change, including a
canonical structurally valid metadata change. Keep launch bound to the exact
manifest admitted at preparation. Add public export/prepare/launch tests for
canonical metadata mutation as well as non-canonical and object-byte mutation,
and prove rejection before descriptor publication, state creation, or provider
execution.
