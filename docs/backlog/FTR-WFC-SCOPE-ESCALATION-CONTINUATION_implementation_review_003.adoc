== H002-R1 -- The mandatory acceptance matrix remains incomplete at required public boundaries

H001 closes substantial portions of H008-R1, but the following parts of the
one complete obligation remain open.

=== Legacy identity and layered replay

The actual v1 reconcile/resume transition and atomic v2 write are now covered.
The read-only tests, however, use the generic `RUN-legacy` fixture or convert a
newly generated v2 predecessor into a synthetic v1 shape. They never exercise
the explicitly named historical version-1/no-back-patch case for
`RUN-76e153b40ef1459db4587446b18e02d5`.

The real operator/vertical layered-stop test loads `run.json` and compares its
semantic stop and anomalies with checkpoint and summary projections, but does
not serialize and replay that complete real Run or assert identity of every
layered-stop field after the round trip. Generic serializer coverage does not
substitute for the required real-boundary replay.

Required correction: add the named historical no-back-patch case and a complete
serialization/replay identity assertion for the real operator/vertical layered
semantic-plus-mechanical stop. Preserve the already-green v1 transition and
read-only byte-preservation cases.

=== Salvage wording, inventory, and omission diagnostics

The new public lifecycle covers out-of-scope content, an escaping symlink, a
FIFO, untracked text and binary objects, count/per-object/aggregate limits,
salvage-tree modes, selected and unselected objects, binary exclusion, and
render-limit overflow. It does not create an ignored omitted path or assert
that its diagnostic remains visible in the successor prompt. Thus the
``complete inventory and omission diagnostics`` part of H008-R1 is still not
proved at the public prompt boundary. The manifest contains the new warning,
but the public tests assert only `potentially sensitive`, not the required
prompt-injection/no-sanitization language across help, manifest, and success
output.

Required correction: add a public export/prepare/launch case with a real
omitted ignored path and assert complete prompt inventory plus omission
diagnostics without raw omitted content. Assert the explicit potentially
sensitive, prompt-injection, and non-sanitization wording in the manifest and
successor context, and assert that help and success output make none of the
prohibited credential-free, sanitized, or disclosure-safe claims.

=== Publication effects for both artifacts

H008-R1 requires the complete public write, rename, permission, verification,
invalidation/removal, cleanup, existing-entry, and destination-race matrix for
both salvage and descriptor publication. The current suite still exercises
most of those facts only by directly calling `_rename_no_replace()`,
`_discard_export_bundle()`, or `_write_descriptor_no_clobber()`. The public
coverage combines only selected failures and therefore cannot establish the
effect of each operation at each command boundary.

The production descriptor primitive itself has no permission-establishment or
verification step (`operator.py:995-1023`). Unlike salvage publication, its
`open(..., "xb")` mode is inherited from process umask. The umask-`000` probe
published mode `0666`, so the descriptor side cannot presently satisfy the
required permission/verification cases.

Required correction: make descriptor permissions explicit and verified, then
exercise write, rename, permission, verification, invalidation/removal,
cleanup, existing file/directory/symlink, and destination-race effects through
the public `export-salvage` and `prepare-successor` commands for both artifact
types. Helper tests may remain supplemental but cannot replace those public
assertions. Every reported failure must prove that no production consumer can
use a final or stranded temporary artifact.

=== Source mutation and immutable lifecycle evidence

The new launch matrix rejects mutated predecessor, authority, descriptor,
governing input, successor HEAD, and repository association. Separate existing
coverage rejects changed object bytes. No case mutates the salvage manifest
itself as the distinct preparation and pre-provider input required by H008-R1,
and the public preparation boundary does not cover all applicable mutated
predecessor/manifest relationships.

Successful lifecycle tests compare predecessor `run.json` and operator-summary
bytes, but still do not snapshot and prove byte identity for the predecessor's
governing inputs and evidence across export, preparation, and launch as the
accepted Authority and predecessor immutability criterion requires.

Required correction: add manifest-byte mutation at preparation and launch,
cover every applicable predecessor/manifest relationship at both boundaries,
and assert byte-identical predecessor governing inputs and evidence across one
successful public lifecycle.

=== Mechanism-separation ergonomics

The implementation continues to use successor/salvage names and the existing
same-Run recovery tests remain green. The mandatory ergonomic assertions are
still absent: no test inspects CLI help and command outputs for the prohibited
`resume`, `reconcile`, `retry`, `checkpoint`, or provider-session framing, and
no test proves each command reports only its next explicit operator action.

Required correction: add public CLI help/output assertions for the accepted
successor/salvage vocabulary, separate semantic/mechanical status projection,
and explicit non-implicit next actions. Do not change same-Run recovery names
inside the distinct recovery mechanism itself.

The ordinary successor evidence-failure and invalid-`CommitIntent` cases are
now present under successor provenance, so no further correction is requested
for that H008-R1 bullet unless later changes regress it.
