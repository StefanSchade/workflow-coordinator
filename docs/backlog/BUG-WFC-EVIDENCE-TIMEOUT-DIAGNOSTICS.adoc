== Boundary and scope

At the recorded Runtime `6c88e47646c697dfe4f7c4e83e474092609df1ba`,
`ProductionEvidenceRunner.observe` catches `subprocess.TimeoutExpired`,
kills and waits for the process, closes its pipes, and returns a timeout
observation without stdout/stderr or untrusted diagnostic capture. Thus the
record cannot establish whether any output existed before termination. This
is narrower than the earlier clean nonzero-exit diagnostics gap in
link:BUG-WFC-EVIDENCE-FAILURE-DIAGNOSTICS.adoc[BUG-WFC-EVIDENCE-FAILURE-DIAGNOSTICS],
whose bounded untrusted capture was implemented and independently accepted;
the timeout path is not that `fail` branch. Executable lookup failures before
spawn are separately covered by
link:BUG-WFC-EVIDENCE-COMMAND-RESOLUTION-DIAGNOSTICS.adoc[the command-resolution BUG].

Investigate what information, if any, should be available for diagnosing a
timed-out evidence command while respecting the existing distinction between
trusted observation and untrusted diagnostics. This record selects no
capture method, storage, timeout value or routing change, and does not decide
whether a timeout should be treated as a clean test failure. It neither
changes the original Run nor asserts a root cause.
