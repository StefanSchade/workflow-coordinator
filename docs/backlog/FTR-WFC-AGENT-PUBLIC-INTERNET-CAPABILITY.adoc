== Thesis

Public internet access -- for research, documentation lookup, dependency
downloads, public APIs, and experimentation -- is a regular capability of
an ordinary development agent, not a privilege requiring case-by-case
justification. WFC must not withhold it through a blanket restriction
merely because that restriction is easy to apply by default.

== Decision

For ordinary WFC operation, restricting an agent's public internet access
requires justification weighed against its cost to development quality and
productivity (`GOAL-WFC-004`); it is not applied as a default stance. This
holds provider-neutrally for both the Codex and Claude Code adapters.

== Current state and why it is a gap

The Claude Code adapter currently generates a settings file with
`network.allowedDomains: []` and `permissions.deny: ["WebFetch",
"WebSearch"]`, closing ordinary public internet access entirely
(`src/workflow_coordinator/claude_adapter.py`; see
`docs/technical_model/claude_code_adapter_architecture.adoc` Section 2 for
the as-implemented mechanics). Under this decision, that current default is
a Beta-1-relevant functional gap to investigate, not a deliberate target
state.

== Not yet decided

This record intentionally leaves open:

* concrete network profiles and their defaults;
* Commission-driven, per-task network authorization;
* the technical enforcement mechanism (adapter settings, a network
  sidecar/proxy, or another mechanism);
* any additional isolation or mediation layer between an agent and the
  public internet; and
* the eventual relationship, if any, to
  `FTR-WFC-EXECUTION-TRUST-BOUNDARIES`'s deferred network-capability
  concerns (that record's independent-elevation and information-flow
  sections remain unaffected and are not reopened by this one).

The network architecture itself is deliberately not anticipated here. A
later investigation must account for each provider's own existing
capabilities and the network boundary of the agent VM.

== Non-goals
