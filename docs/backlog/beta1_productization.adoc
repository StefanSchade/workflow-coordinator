== Planning constraints and decisions still open

Business Commission and concrete execution bindings remain separate. A change
of model must not change the business Commission bundle; the actual bindings
must be frozen and visible in execution/audit evidence. One interactive
confirmation or `--yes` covers the authorized lifecycle. `wfc plan` runs no
project command; any baseline probe belongs after authorization. Prefer a
separate Git-backed Evidence repository with a sanitized audit projection.
Historical Commissions need intelligible provenance, not perpetual launch or
recompile compatibility with current APIs.

The third review's Linux host/subreaper, comprehensive quiescence machinery,
mandatory BP4a dependency and associated extra refusals are *superseded for
Beta 1*. Initially document Coordinator crashes and potentially surviving
provider processes as limitations. Process observations/questions remain in
link:../research/README.adoc#r2[R2]. Automatic preservation on *regular stops*
is a Beta-1 candidate; convenient continuation can follow shortly after the
release. The third review's full crash-preservation/lineage schema is not
therefore a mandatory foundation. Keep additions proportional to concrete
product goals and plausible failure cases.

Open decisions, using historical review labels only as navigation:

* R2 Q2: guidance-slot binding versus a new program revision; resolve before
  BP2 guidance compilation. R2 Q7: whether `direct@v1` can ship, given its
  unreconciled acceptance and known authority defect; reviews recommend
  `simple@v1`/`robust@v1` only, not a newly accepted catalogue decision.
* R2 Q3's archive preference is settled toward separate Evidence plus sanitized
  projection. Exact raw retention/defaults, projection fields and destination
  ergonomics still need bounded design. R2 Q5 preparation-contract amendment
  and Q6 cutover/tag timing remain open for BP7.
* R2 Q8: token usage as release gate or fast-follow remains unresolved.
  The October MUST-HAVE and later review recommendation are both provenance;
  no gate is silently changed here.
* R3 C1/C2/C3 settle the planning boundary for bindings, unattended execution
  and non-executing plan. R3 M1/M2 need a narrower preservation disposition
  before implementation; no automatic adoption of alternative B. M3's
  supervision platform choice is not a Beta-1 prerequisite. M4/M5 (candidate
  adoption and derived broad-review entry), X5 (no-change worker behavior)
  and M6 (old descriptor relationship) belong to later continuation design.

[[bp1]]
== BP1 — Installed entry point, resources and implementation identity

Outcome/classification:: *Mandatory*: installed WFC usable outside its source
checkout, identifiable release/implementation and packaged product resources.
Dependencies/status:: No technical predecessor; planned. Preserve the current
self-development route while building the replacement. No source change since
the reviewed implementation establishes delivery of this package.
Sources:: link:../warm_storage/concepts/wfc_beta1_product_boundary_review_second_pass.adoc#identity[Identity]
and its BP1; link:FTR-WFC-CONTRACT-HISTORICAL-RECONSTRUCTABILITY.adoc[historical identification],
link:FTR-WFC-ARCHITECTURAL-CORE-AND-CONSOLIDATION-BOUNDARIES.adoc[core boundaries],
link:BUG-WFC-NESTED-PREPARE-OFFLINE-BUILD-ISOLATION.adoc[offline packaging risk].
Remaining investigation:: Package identity for wheel/source/editable installs;
resource pinning, installed CLI dispatch and the temporary old-launch bridge.
Do not turn an offline build limitation into a product defect or promise an
unknown source commit.
Acceptance direction:: Install a built wheel in a clean environment; from an
unrelated directory exercise help/version and the legacy provider-free
preflight seam. Resource tampering must be detected and the executing identity
recorded in the plan. Keep provider/model choice outside Commission identity.

== BP3 — Initialization, read-only plan and bounded Git mechanics

Outcome/classification:: *Mandatory*: initialize consumer configuration, inspect
an effective plan and supply narrow Commission/archive commit mechanics.
Non-authoritative regular-stop candidate preservation is a *candidate* addition.
Dependencies/status:: BP2; planned. Preservation needs its own bounded decision
and recovery-rule reconciliation before it can be included.
Sources:: link:../warm_storage/concepts/wfc_beta1_product_boundary_review_second_pass.adoc#packages[BP3],
link:../warm_storage/concepts/wfc_beta1_implementation_readiness_review.adoc#c3[plan/probe boundary],
link:../warm_storage/concepts/wfc_beta1_implementation_readiness_review.adoc#c5[preservation proposal];
link:BUG-WFC-COMMISSION-RENDER-CHECK-WRITES-BUNDLE.adoc[preview BUG],
link:BUG-WFC-COMMIT-INTENT-DIRECTORY-PATH-RECONCILIATION.adoc[path mismatch].
Remaining investigation:: Bounded hook-free commits outside a Run, with exact
path ownership and no unintended staging. Clarify old render/check behavior
separately. If preservation is selected, investigate exact/stable capture,
private-index/filter/attribute effects, idempotency and fallback on regular
stops; do not import crash supervision as a dependency.
Acceptance direction:: Plan leaves HEAD, index and worktree unchanged and does
not run a check that would create a marker file. Bounded commits reject extra
paths/staged state and do not run hooks. If selected, preservation must leave
branch/index/worktree unchanged, label work unaccepted and make no crash-safety
or acceptance claim. The open directory-intent design is not silently resolved.

== BP4 — Unattended lifecycle, execution envelope and status

Outcome/classification:: *Mandatory*: request to terminal outcome, honest status
and restartable mechanical finishing, with one authorization. Comprehensive
provider-process supervision is *later/research*, not mandatory BP4a work.
Dependencies/status:: BP3; planned. Separate envelope follows C1; `--yes` and
non-executing plan follow maintainer decisions. Candidate preservation is not
on this package's mandatory critical path.
Sources:: link:../warm_storage/concepts/wfc_beta1_product_boundary_review_second_pass.adoc#lifecycle[Lifecycle proposal],
link:../warm_storage/concepts/wfc_beta1_implementation_readiness_review.adoc#c2[unattended execution],
link:../warm_storage/concepts/wfc_beta1_implementation_readiness_review.adoc#c3[authorized baseline probe];
link:BUG-WFC-OPERATOR-PREPARE-EXECUTABLE-VALIDATION.adoc[executable validation],
link:BUG-WFC-EVIDENCE-COMMAND-RESOLUTION-DIAGNOSTICS.adoc[resolution diagnostics],
link:BUG-WFC-EVIDENCE-TIMEOUT-DIAGNOSTICS.adoc[timeout observability],
link:FTR-WFC-ATOMIC-HOP-RECOVERY.adoc[same-Run distinction].
Remaining investigation:: Specify bounded journal/retry predicates and truthful
classification from engine state; summary-file existence alone does not prove
completion. Check pre-launch executable/environment/destination prerequisites.
A baseline probe executes project code after authorization and must report
failure or tree mutation honestly. Generic preparation does not build a payload
environment. Provider descendants after Coordinator death remain a documented
limitation, without speculative additional refusal/override protocols.
Acceptance direction:: Scripted non-terminal `--yes` reaches terminal state
without another prompt; no-terminal/no-authorization exits promptly. Fake-provider
crash-injection tests cover controller step boundaries and prevent duplicate
Commission, launch and dispatch. A launched/interrupted engine is not relaunched
or called completed. Failed probes/prelaunch steps report that no provider ran.
Lifecycle resume finishes mechanics; it does not resume the old Run or session.

== BP5 — Installable mechanical archive port

Outcome/classification:: *Mandatory*: one installed archiver, compatible raw
manifest/copy behavior and retry-safe destination publication.
Dependencies/status:: BP1 for port/tests; BP3 bounded commit primitive for
write integration. Can start alongside BP2; planned. The existing reviewed
Evidence-repository archiver is the reusable source, not packaged delivery.
Sources:: link:../warm_storage/concepts/wfc_beta1_product_boundary_review_second_pass.adoc#evidence[Archive design and port sequence].
No separate active BUG/FTR owns this port; do not create a duplicate issue.
Remaining investigation:: Bring the existing Evidence conformance tests and
implementation into a bounded port; parameterize destination/OPS, staging and
copy-to-commit retry. Keep projection/retention changes in BP6. External source
access is a concrete prerequisite for that implementation, not work performed
by this documentation candidate.
Acceptance direction:: Compare old/new archives from a retained Run in
temporary destinations: file digests and facts agree except documented timestamp
variation. Partial-copy/commit retry makes one archive commit, repeat is a no-op,
and identity/no-clobber/destination-only staging checks remain intact.

Dependencies/status:: BP6, maintainer Runtime promotion, Q5 preparation-contract

Remaining investigation:: Real supported-provider behavior and an unfamiliar
user's setup friction. Internet investigation follows Claude completion; own
firewall research is not its prerequisite. State limitations for the actual
release, including crash/surviving-provider behavior, one adapter per Run,
evidence ceiling, scope/clean-tree rules and incomplete recovery conveniences.
Acceptance direction:: Neutral non-Python fixture with fake provider exercises
success, correction/review, stops, archive retry and a script's `--yes` path.
Installed-wheel live qualification per supported adapter and a short consumer
quickstart establish real usability. Neither an agent check nor a successful
manual documentation Run substitutes for this product evidence.

== Later continuation and capabilities outside the packages

R3's RP1 `wfc continue` is a fast-follow proposal, not a tenth Beta package.
link:FTR-WFC-FRONT-DOOR-PHASE-ENTRY-CONTINUATION.adoc[Phase entry] needs its
own bounded decision; existing
link:FTR-WFC-SCOPE-ESCALATION-CONTINUATION.adoc[semantic continuation]
still has R1A open. Preservation does not accept a candidate, adopt it, widen
scope or transfer Run-local Findings. Any successor must review retained work
against its real assurance baseline. Same-Run recovery, broader isolation,
dynamic routing, MCP and orchestration stay with their existing records and
link:../research/README.adoc[open research questions]. No anticipatory compiler
framework or additional governance procedure is part of this map.
