== Problem

The release pipeline's strict-render gate (G5) enumerates eight entry
documents and nothing else
(`.github/workflows/release.yml:150-157`): the Operator Manual, the Developer
Guide, the Functional, Semantic and Technical Models, `docs/README.adoc`,
`docs/backlog/_open.adoc`, `docs/ai_info/_ai_info.adoc` and
`docs/ai_info/doc_conventions.adoc`.

Outside it: every individual `BUG-*`/`FTR-*` record, every backlog plan, and
all of `docs/warm_storage/`. That is where nearly every documentation
Commission writes. The observed consequence, recorded as friction entry 9: an
independent reviewer's durable artifact under `docs/warm_storage/` was
committed with an incomplete table row and failed the strict render, and
nothing noticed, because no gate rendered it.

The `check` target does not close the gap either -- it is `lint format-check
test` (`Makefile:28`) and runs no renderer. A Commission's own deterministic
gate therefore cannot see the one class of defect a documentation Commission
is most likely to introduce.

== Direction (not a chosen design)

A `docs-render` target that renders every `.adoc` under `docs/` with the
strict invocation the repository already uses elsewhere
(`asciidoctor --safe-mode=safe -a assembled -o /dev/null
--failure-level=WARN`), plus a *separate* aggregate target that runs `check`
and then `docs-render`, so a documentation Commission can name a single
evidence argv. A Commission declares exactly one evidence command
(`commissioning.py:362-364`), which is why the aggregate matters.

The gap is deliberately *not* closed in `.github/workflows/release.yml`: that
file is outside `.wfc/config.yaml`'s `work_item_scope_ceiling` and would need
a maintainer-granted temporary, file-exact entry for a gate a Make target
provides without one. A workflow-only gate would also leave local Runs
ungated, which is where the defect was introduced.

== Open decisions

* link:beta2_operator_efficiency_plan.adoc#d3[D3] -- whether the render joins
  `make check`. The plan recommends *not*: it would make the repository's own
  gate, and therefore every Commission's mandatory baseline probe, fail on a
  host without Ruby -- a cost paid by every Run to catch a defect in some. A
  gate that silently skips when its tool is absent is not a gate and is not
  proposed.
* The aggregate target's name (`check-docs` is the plan's placeholder).
* Whether `docs/cold_storage/` is in or out of the render set. Not analysed;
  cold storage is provenance and some of it may predate current conventions,
  so including it may surface pre-existing failures that are not this
  record's subject.
