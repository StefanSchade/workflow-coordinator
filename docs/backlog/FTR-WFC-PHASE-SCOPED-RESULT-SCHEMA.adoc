The closed `docs/cold_storage/backlog/done/BUG-WFC-FINDING-AUTHORITY-PROMPT-PROJECTION.adoc`

== Core idea

Where mechanically practical, derive the structured-result surface from the
admitted CURRENT PHASE:

----
admitted profile / current phase
    |
    +-- permitted routes
    +-- authorized actions
    +-- Finding disposition authority
    +-- applicable escalation surface
    +-- commit-intent capability where mechanically meaningful
    |
    v
phase-scoped structured result schema
    |
    v
agent
    |
    v
reducer
----

Schema narrowing is usability and error prevention, not authority. The reducer
remains the final authoritative, fail-closed enforcement boundary. An adapter
that ignores or violates the schema must not gain authority.

== Declarative derivation

The feature must not hard-code workflow phase names. Designs such as the
following are explicitly rejected:

----
if phase == "correct":
    forbid_resolve()
----

Instead, derive the result schema from admitted configuration and current Run
state. For example, `finding_authority = []` may structurally prevent or
narrow authoritative Finding disposition, while
`finding_authority = [resolve]` may expose the corresponding disposition
shape. Similarly, constrain route values to the current permitted routes where
practical.

Future investigation should identify which existing result fields can safely
be narrowed without making the schema brittle or duplicating reducer semantics.
Changes to configuration/data -- phase names, routes, Finding authority, and
authorized actions -- should automatically alter the projected schema.
Protocol/semantic changes, such as a new authority kind or Finding operation,
may instead require product, contract, and schema evolution.

== Three-layer model

. Prompt projection tells the model what it may do.
. A phase-scoped result schema makes locally invalid structured actions harder
  or impossible to express where practical.
. The reducer remains authoritative and rejects any unauthorized operation,
  regardless of prompt or schema behavior.

These layers are defense in depth and must not be collapsed.

== Activation criterion

This FTR remains *deferred / low priority* while explicit prompt/contract
projection provides reliable agent compliance. Promote it when dogfood or
production runs show materially recurring schema-valid but
phase-authority-invalid outputs despite correct, explicit prompt/contract
projection. Examples include repeated unauthorized Finding dispositions,
impossible route selections, unauthorized commit-intent behavior, or similar
locally invalid structured outputs. A single isolated model error is not by
itself sufficient to justify immediate implementation.

== Automatic reducer repair is considered, but not preferred

The reducer could theoretically sanitize or ignore an unauthorized field and
continue with a remaining valid result; for example, ignore
`F001 -> resolved` while applying `route -> rereview`. This is not the target
behavior. The current preference is prompt assistance, schema narrowing, and
a fail-closed reducer.

Automatic repair risks turning the reducer from an authority validator into an
interpreter of intended agent meaning. That distinction remains explicit.

== Acceptance direction, not implementation commitment

Likely future proof points include:

* phase-specific allowed routes appearing in generated schema;
* Finding disposition shape following configured Finding authority;
* a disposition-free phase being unable to normally emit an authoritative
  state change;
* an authorized gate emitting its configured operation;
* reducer negative tests continuing to reject forged unauthorized output;
* generic profiles with different phase names working without product changes;
  and
* adapter/provider schema-conformance failure not widening authority.

== Non-goals

This FTR does not:

* weaken reducer enforcement;
* automatically repair malformed or unauthorized agent intent;
* encode the current `review -> correct -> rereview` choreography in product
  code;
* require every semantic invariant to be expressible in JSON Schema;
* replace prompt projection or the Agent Operating Contract;
* expand phase authority; or
* modify the current Finding-authority BUG.

== Deferred priority

The immediate Finding-authority prompt BUG should be fixed independently
first. This FTR becomes implementation-relevant only when empirical agent
behavior shows prompt/contract projection alone is not sufficiently reliable.
