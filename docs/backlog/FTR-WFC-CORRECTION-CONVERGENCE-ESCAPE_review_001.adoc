== Verdict

*CHANGES_REQUIRED; route `correct`.*

The proposal gets the main architecture right. It keeps one authoritative
Finding ledger, separates worker coverage from gate disposition, derives a
semantically qualified per-Finding goalpost instead of treating a failure count
as correctness, reserves escape selection to Core while profiles declare only
finite routes, keeps diagnosis read-only and agent-attributed, preserves all
existing authority boundaries, leaves simple profiles unchanged, and gives
legacy wire versions an explicit no-backfill rule. It remains domain-neutral
and neither assumes nor attempts to solve R1A.

Two state-machine gaps prevent implementation as written. First, the proposed
correction-obligation wire is not closed over the Finding lifecycle it extends:
an ordinary agent can still create an untracked open blocker, an authorized
`residual` disposition has no matching assessment value, and the result cannot
name a Coordinator-allocated successor that is created atomically in that same
result. Second, strategy-generation advancement is not bound exactly and
causally to the set that triggered escape. A diagnosis can select only part of
that set, and a later revision can name an unrelated open Finding, allowing an
old-strategy goalpost to be carried back into correction or a below-limit count
to be reset without its own escape.

These are ordinary design-review defects. This review creates no WFC
Current-Run Finding and requests no Finding disposition.

== Open blocking design requirements

=== D001 -- The tracked-Finding lifecycle must be total and wire-enforceable

Underlying invariant:: Every blocker that participates in a convergence-aware
profile must have one unambiguous authoritative lifecycle, and every lifecycle
transition the profile permits must have an exact representable assessment and
enforceable identity relation.

The proposal says only an evaluator gate or human operation may introduce a
_tracked_ obligation, but it leaves ordinary result-v2 Finding creation
otherwise untouched. In the current reducer an agent without disposition
authority may create an open blocking Finding. Such a Finding would have null
`correction_obligation` metadata, would block completion, and would be excluded
from mandatory coverage and convergence facts. The next evaluator is not
defined to adopt it, so a convergence-aware Run can acquire a permanently
untracked blocker through an admitted result.

The assessment enum is also incomplete relative to the retained Finding state
machine. It offers `closed`, the two carried results, and `superseded`, while
the design expressly preserves authorized `residualize` behavior. `closed` is
defined only as a matching `resolved` delta. An evaluator that validly changes
an entered open obligation to `residual` therefore cannot satisfy the rule that
every such obligation receive one matching assessment.

Finally, the design requires a superseded tracked obligation to reference an
existing _or atomically created_ tracked successor. Existing successors are
representable. Atomic new successors are not: a new-Finding delta has a null ID
until the reducer allocates it, but the superseding delta must already contain a
string `successor_ref`. Predicting the allocator's next `Fxxx` value would turn
an implementation detail into agent-authored identity and is not a valid
correlation mechanism.

Required correction:

. Define the result-v2 rule for every new open blocking Finding in every
  convergence role. Either reject creation outside evaluator/human authority,
  define an explicit gate-adoption transition, or provide another closed rule
  that cannot leave an admitted open blocker outside mandatory coverage. Do
  not silently track a worker assertion as a gate-owned blocker.
. Make convergence assessments total over every Finding disposition an
  evaluator may advertise. Either add and define a `residualized` assessment
  matched to an authorized residual delta, or statically prohibit residual
  authority for tracked obligations and explain the compatibility choice.
. Make successor correlation implementable. Either require a successor to
  exist before supersession, or add a bounded transaction-local reference that
  the reducer resolves atomically to the newly allocated ID. Specify ordering,
  duplicate/unknown-reference rejection, cycle checks, persistence, and replay.
. Add deterministic tests for non-evaluator blocker creation/adoption or
  rejection, residual handling, existing and same-result successor linkage,
  allocation without prediction, and self/cycle/unknown reference failures.

This correction fits the proposed model/serialization/reducer and focused test
scope; no product-scope widening is presently demonstrated.

=== D002 -- Escape, diagnosis, revision, and generation advancement need one exact causal ID set

Underlying invariant:: A strategy generation may advance only for the
goalpost Finding identities whose escape was diagnosed and whose replacement
strategy was independently accepted; no triggering identity may disappear and
no unrelated identity may have its count reset.

The evaluator records a sorted set of triggering Finding IDs in
`route_reason`, but `DiagnosisReport.finding_ids` is required only to be a
non-empty subset of those IDs. `StrategyRevision` has no diagnosis-hop
correlation and is constrained only to open Findings. `StrategyAssessment`
correlates to a revision Hop and advances generation for its named IDs.
Together these rules admit two invalid histories:

* when two Findings reach the goalpost together, diagnosis/reframe can name
  only one, return to correction, and make the other undergo another local
  correction under the already exhausted strategy generation; and
* a reframe can name an open below-limit Finding that did not trigger escape,
  allowing an accepted strategy assessment to reset its derived count without
  a corresponding goalpost or diagnosis.

The test statement that records correlate to “the same open IDs” does not
define which originating event owns that set, whether equality or subset is
required, or what happens to omitted triggering IDs. Finding IDs alone are not
enough to reject a stale or unrelated diagnosis/revision chain.

Required correction:

. Define a persisted correlation from the escape-producing evaluator Hop (or
  an equivalent immutable escape event) through diagnosis, strategy revision,
  and strategy assessment.
. Define exact set semantics. The smallest rule is equality with the complete
  sorted triggering set throughout the chain. If partial diagnosis/reframe is
  intentionally supported, persist the remaining set and prohibit return to a
  corrector until every triggering ID has an accepted strategy disposition.
. Require generation advancement to apply exactly once, only after an accepted
  assessment of the correlated current revision, and only to that correlated
  set. Reject stale, duplicate, omitted, added, closed, superseded, or
  non-triggering IDs without resetting any count.
. Add multi-trigger tests for subset omission, unrelated-ID injection, stale
  revision/assessment correlation, duplicate acceptance, and successful exact-
  set generation advancement. Preserve the already required case in which one
  non-converging Finding escapes while other below-limit Findings retain their
  histories.

This is a Core correlation/validation correction within the already proposed
model, reducer, serialization, persistence, and test seams. It adds no
executable profile condition and grants no new authority.
