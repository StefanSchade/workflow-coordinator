= FTR-WFC-CROSS-REPOSITORY-READ-ACCESS -- Controlled Read Access To A Second Repository For A Run

Type:: future technical record -- Front Door capability gap
Status:: proposed / backlog; not a Beta or release item
Current controlling source:: This record; see link:_open.adoc[the active-work manifest] for its current card.
Next action:: None before the maintainer decides to treat this as product work; the interim pattern below stays the documented workaround.
Not authorized here:: Any change to `src/`, to the sandbox boundary or to the Run's authority model; any Run.
Priority:: medium; recurrence is evidenced (the BP7 Evidence fixtures, the post-Beta planning inputs and the release-engineering comparison with `spreadsheet-handling` each needed it).
Date:: 2026-11-21.

== Observation

A Worker or reviewer sees only the repository its Run is bound to. Work that must read a second repository (a release reference such as
`spreadsheet-handling`, the sibling Evidence repository, a consumer under qualification) therefore needs a copy inside the Run's checkout.

== Interim pattern (documented workaround, not a capability)

Before the launch the Operator stages a read-only snapshot of committed files (`git show <commit>:<path>`, never a working tree) under an
ignored `build/wfc/<topic>/` directory of the Run's checkout, with a digest manifest and a provenance file that lists only what is present.
The task text names the staged material. Limits: the Worker sees only what was staged (selection risk), cannot run the other repository's
tools, and a missing input costs a stopped Run and a successor (observed once, BP7 C1b).

== Maintainer remark (2026-11-21)

A regular, controlled way to give a Run read access to a named second repository is a topic of its own, beyond the release. Any design must
keep the Run's single-repository authority intact: read-only, pinned to a commit, declared in the Commission, and recorded in the Run
evidence, without a general filesystem or network opening.

== Entry conditions for a design

* Read-only and commit-pinned; the pin is part of the authorized Commission and of the archived evidence.
* No widening of the write scope or of the sandbox beyond the declared repository.
* The staging pattern above is the baseline to beat: a design must cost less ongoing complexity than a documented snapshot step.
