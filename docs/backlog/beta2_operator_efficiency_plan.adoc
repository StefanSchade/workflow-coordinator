== Revision of 2026-11-26: the Beta rule, the maintainer's decisions and the revised cut

This section was added after the maintainer read the plan and decided it. It
supersedes the first version's recommendations to defer, where they rested on
the existence of an accepted contract.

=== The Beta rule

The maintainer's guideline for Beta, recorded as stated:

* There is no obligation to keep existing schemas, programs, contracts, CLI
  surfaces or persistence formats stable. The Beta phase exists to find and
  remove unsuitable contracts and architectural couplings.
* The existence of an accepted contract or of an earlier architecture decision
  is, by itself, no argument against a change. AD-5 and AD-6 are not
  principled obstacles.
* What is to be preserved are the *intended safety and governance properties*,
  not necessarily their present technical realisation.
* A change is judged on benefit, effort, risk and dependencies.

The first version of this plan deferred the evidence-command list, the
non-default phase entry and the budget raise partly because they touch an
accepted program literal, an accepted ADR or the admitted governing truth.
That reasoning pattern was wrong for this phase and is withdrawn. A candidate
may still be deferred, with the reason stated, for a *safety or authority*
reason (see D7b), for cost out of proportion to benefit, or for a missing
dependency; "it changes a contract" is none of them. The rule is also recorded
as an engineering convention in
link:../developer_guide/ch03_engineering_conventions.adoc[the Developer Guide].

[[target]]
== The target picture

The operating model does not change. A Level-1 operator still authors one
bounded Commission at a time, previews it, launches one Run per fresh
checkout, reads the classification and integrates what an independent review
accepted. This plan removes mechanics and recoverable mistakes from that loop
and adds no stage, gate class, agent role, program or governance layer.

Six states of the operator's own loop, and what each costs today:

[cols="1,3,2",options="header"]
|===
|State |What it is, and today's cost |Where it lives

|*1 Prepare the checkout*
|A fresh worktree at a *fresh path*, its own venv with an editable install,
the verified offline bundle in the environment, a scratch `TMPDIR` outside
the worktree, and -- until <<o3,O3>> -- a second committed config file that
must never be integrated. All manual; five friction entries; each omission
costs a refused probe and the checkout's single lifecycle.
|<<o4,O4>> (new command), <<o1,O1>> (the recipe)

|*2 Author the Commission*
|A task document, scope, program, personas, Hop budget and one evidence
command. The judgement is irreducible; the mechanics are not: the operator
writes a build script and a shell wrapper per Commission for a Consumer
Request `wfc plan` already assembles and discards.
|<<o5,O5>>, <<o1,O1>>

|*3 Choose the deterministic gate*
|One evidence argv, freely chosen. The highest-leverage decision in the
system and the one with no guidance: omitting lint cost ten Hops and two
Opus Broad Reviews for one unused import.
|<<o1,O1>> (the rule), <<o6,O6>> (the docs half of the gate)

|*4 Launch*
|`wfc plan`, then `wfc run --yes`. Three refusals arrive late or incomplete
and each one spends the checkout: a config path checked only after
authorization, an `--executable` never compared with its adapter, and a
probe refusal that discards the output it captured.
|<<o2,O2>>

|*5 Read the stop*
|Classifications are documented and accurate. Two things the operator needed

`prepare-successor --authority-decision` is the answer channel for an

|<<o1,O1>>

|*6 Verify and integrate*
|Unchanged, and deliberately so. Independent verification before
integration, and the reviewer's sole Finding authority, are the safeguards
this plan is built to protect rather than to cheapen.
|no slice
|===

What is *deliberately absent* from the target picture, each with the
recurring cost it leaves in place: a list of evidence commands, an in-place
Hop-budget raise, Worker-only closure of a mechanical Finding, a non-default
phase entry, mechanical CommitIntent enumeration and checkout reuse. All six
are category B; <<decisions>> and <<not-done>> state why none is proposed.

[[slices]]
== The slices

Six slices. They group the analysis's eight candidates into six because
`C7` and `C8` are category B and carry no slice at all. Each slice is
independently commissionable, independently useful and sized for one Run.

*Authority class* is the analysis's A/B classification. Every slice below is
*class A*: none changes a trust or authority boundary. That is a property of
the proposed cut, not a coincidence -- the class-B candidates were
deliberately left out of it.

*Program and model recommendation* follows the shift-left rule: the strongest
model where the work is design judgement or a completeness argument over a
list, a cheaper one where the work is mechanical and a deterministic gate
decides. The repository's committed default is already Sonnet worker and Opus
reviewer; where a slice says *default*, it asks for that and not for an

effect is a genuine operator error and should stay refused. The residual risk
of Option A, stated plainly, is a consumer reading a committed reviewer
default as evidence that review happens; printing the ignored defaults is the
mitigation, not a cure.

[[d3]]
D3 — Does the documentation render join `make check`?::
*Option A — a separate `docs-render` target plus an opt-in aggregate* that
documentation Commissions name as their one evidence command. *Option B —
make `docs-render` a prerequisite of `check`.* *Option C — extend the release
workflow's G5 list instead.*
+
*Recommendation: Option A.* Option B would make the repository's own gate, and
therefore every Commission's mandatory baseline probe, fail on a host without
Ruby -- a cost paid by every Run to catch a defect in some. Option C needs a
maintainer-granted temporary ceiling entry for a file outside the ceiling, for
a gate a Make target provides without one; it also leaves local Runs
ungated, which is where the defect was introduced.

[[d4]]
D4 — Does the preparation command also clean up?::
*Option A — prepare only* (<<o4,O4>> variant A). *Option B — prepare and
remove what it created* (variant B).
+
*Recommendation: Option A for Beta 2, Option B considered afterwards on the
evidence of A's use.* Removal is destructive, and the skill already withholds
discarding anything the session did not create; AD-5 does name "controlled
cleanup" as part of the preferred direction, so Option B is the eventual
target rather than a rejected idea. Taking A first means the command's
recording of what it created -- which is what makes a safe removal possible
at all -- is in place and exercised before anything is removed.

[[d5]]
D5 — Is the 900-second evidence hard cap raised or made configurable?::
Category B: `COORDINATOR_HARD_MAX_EVIDENCE_TIMEOUT_SECONDS = 900`
(`model.py:27`) is a kernel limit enforced on every Consumer Request
(`frontdoor/request.py:81`). It binds the lint-inclusive evidence command
<<o1,O1>> recommends: the plain suite has reached 896.96 seconds on this
repository without the verified bundle, and 171 seconds with it.
+
*Option A — leave it.* *Option B — make it configurable below a higher hard
ceiling.*
+
*Recommendation: Option A.* The cap is doing a real job as a stall detector --
link:BUG-WFC-EVIDENCE-TIMEOUT-DIAGNOSTICS.adoc[the open timeout BUG] exists
because a gate ran to that limit with no retained output -- and the measured
fix for the duration is the prepared environment, not a longer limit. Revisit
only if `make check` is measured to exceed it on the qualified profile *with*
the bundle in place, which <<unverified-dep>> records as unmeasured.

[[d6]]
D6 — Is the evidence-command *list* adopted or deferred?::
Category B. The kernel already models several named evidence commands
(`model.py:232`) and the accepted programs already declare an evidence list
(`commissioning.py:140`, `:155`), but adopting it means changing the Consumer
Request schema *and* the accepted program literals -- and `model.py:699`
requires `phase.evidence == ("task-check",)` exactly for the terminal
Worker shape that `select_result_contract` uses, so extending `simple@v1`'s
list changes which result contract its sole phase is admitted under.
+
*Recommendation: defer*, recorded as
link:FTR-WFC-EVIDENCE-COMMAND-SEQUENCE.adoc[FTR-WFC-EVIDENCE-COMMAND-SEQUENCE]
with the coupling named, and take the benefit now through <<o1,O1>>'s rule
plus `make check`, which already gives ordered, fail-fast lint-then-test at
the cost of one conflated exit code. A design investigation first (Hop budget
10) if the maintainer wants it opened; the accepted `robust@v1` program is out
of bounds regardless.

[[d7]]
D7 — Is the economy of continuing a stopped Run addressed?::
Category B on three counts: a budget raise changes an admitted WorkItem's
governing truth against the recorded rule that used Hops are never reset;
Worker-only closure of a "mechanical" Finding moves disposition away from the
independent reviewer; a lighter answer channel re-opens what truth a
continuation admits.
+
*Recommendation: defer*, recorded as
link:FTR-WFC-STOPPED-RUN-CONTINUATION-ECONOMY.adoc[FTR-WFC-STOPPED-RUN-CONTINUATION-ECONOMY].
The erosion to weigh is that "a deterministic check failing with no behaviour
change" is not mechanically distinguishable from "a blocking Finding the
Worker would rather close itself". The interim remedy prevents the case
instead of cheapening its repair: <<o1,O1>>'s gate rule would have caught the
observed residue at the first Hop, and its budget guidance covers the
retire-heavy shape. Measured recurrence so far: once.

*Revised on 2026-11-26:* the evidence-command list, the budget raise and the non-default phase entry are no longer "not done": see <<revision>> (O7, O8, O9; Worker-only Finding closure stays rejected, D7b). Each with the recurring cost it leaves in place.

* *A list of evidence commands* (<<d6,D6>>). Leaves lint, format and tests
  behind one conflated exit code. Not done because it reaches the accepted
  program literals and, through `model.py:699`, result-contract selection.
  Recorded.
* *An in-place Hop-budget raise, and Worker-only closure of a mechanical
  Finding* (<<d7,D7>>). Leaves a successor Commission with its own review
  chain as the price of a one-import residue. Not done because the first
  changes admitted governing truth and the second moves Finding disposition
  away from the independent reviewer. Recorded.
* *A non-default phase entry for a successor Run.* Leaves a verification
  Commission entering at `implement` as the substitute. Not done because AD-6
  defers it deliberately, its substitute demonstrably works, and nothing in
  the 21 entries shows a Run that needed it. The analysis adds that entering
  at a review phase also interacts with durable-artifact admission
  (`operator.py:561-576`), so it is not the cosmetic renderer change it
  resembles.
  *Re-decided on the slice's own evidence, 2026-11-27* (<<o9,O9>>,
  `WI-WFC-BETA2-O9-001`): still not done, but no longer because AD-6 defers
  it. The decisive reason is that the only entry that saves a Hop is an entry
  at `broad_review`, and the Hop it saves is the one that produces the object
  of review; every other declared entry is no cheaper or dearer than the
  default. The durable-artifact claim is refined: the *mapped* admission the
  renderer always produces is entry-independent, and the interaction is
  confined to the *legacy* `--durable-artifact` path, which already refuses a
  review entry. See
  link:FTR-WFC-FRONT-DOOR-PHASE-ENTRY-CONTINUATION.adoc#design[the record's
  Design section].
* *Mechanical CommitIntent enumeration.* Leaves a probabilistic model
  reproducing a long deterministic list.
  link:FTR-WFC-COMMIT-INTENT-ENUMERATION.adoc[Its record] already holds the
