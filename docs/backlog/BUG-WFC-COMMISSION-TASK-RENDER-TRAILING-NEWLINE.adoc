== Observed behavior

`git diff --cached --check` reports a trailing-blank-line whitespace defect
when a freshly rendered Commission bundle is staged. Directly confirmed in
the committed rendered
`governance/commissions/wfc-doc-authority-index-001/task.md`: the file's
final section ends with two consecutive newlines (one blank line before
EOF) rather than exactly one trailing newline.

== Root cause

`commissioning._task_text` (`src/workflow_coordinator/commissioning.py`,
around lines 359-365) builds the file as:

----
f"# {task.title}\n\n{task.body}\n\n## Acceptance\n\n{task.acceptance}\n\n"
f"## Withheld authority\n\n{task.withheld_authority}\n\n## Default escalation\n\n{task.escalation_default}\n"
----

The Commission Intent's `task.body`, `task.acceptance`,
`task.withheld_authority`, and `task.escalation_default` fields are authored
in `intent.yaml` as YAML literal block scalars (`|`), which under YAML's
default clip chomping already end in exactly one trailing newline. The
template then appends its own trailing `"\n"` after the last such field, so
the rendered text ends in `"...\n" + "\n"` -- two consecutive newlines, i.e.
one blank line at EOF.

== Desired behavior

Deterministic clean formatting: the rendered `task.md` should end in exactly
one trailing newline, with a small regression test asserting this (e.g.
comparing the rendered text's last two characters, or against a fixture).

== Non-scope

This record authorizes no implementation. A future correction must not:

* change `task.md`'s four-section content structure; or
* change the `intent.yaml` literal-block-scalar authoring convention for
  `task.body` / `task.acceptance` / `task.withheld_authority` /
  `task.escalation_default`.
