== Decision summary

The accepted convergence-escape architecture correctly requires evidence
failure not to increment a qualified-cycle count, but its Slice-2 read model
cannot enforce that requirement. The persisted Run/Hop/Finding history contains
the semantic assessment and Finding state; it does not contain the trusted
required-evidence outcome that was available transiently during reduction.

This revision selects solution family B. A qualified convergence cycle is a
composite derived fact:

----
qualified_cycle(h) = semantic_cycle_predicate(Run, h)
                     AND trusted_evaluator_qualification(Evidence, h)

ConvergenceFact = f(
  Run semantic history,
  trusted execution-evidence qualification input,
  qualified_cycle_limit
)
----

`h` is the exact evaluator Hop whose `carried_new_counterexample` assessment
would otherwise be counted. The semantic predicate remains owned by the
accepted Run/Finding history. The mechanical predicate is supplied by the
Coordinator-owned execution-evidence surface. Neither surface substitutes for
the other, and evidence machinery receives no Finding disposition or semantic
acceptance authority.

The current `execution-evidence.json` schema version 3 is almost the required
surface, but it is not sufficient as a replay input: it does not bind the
document to a Run identity and it does not preserve the exact required-command
set against which its observations must be judged. A later, separately
commissioned implementation shall introduce the bounded schema-version-4
extension specified below. It shall not add a qualification field to Run,
or Finding and shall not add a mutable convergence counter. It does add one
immutable, Coordinator-created *pre-route correlation anchor* to a v3
HopSummary. That anchor is neither a mechanical pass/fail fact nor a route;
it is the stable identity by which the separately owned evidence row is joined
to the semantic Hop without waiting for route-dependent finalization.

This revision is architecture-convergence input only. Independent acceptance
makes it additional accepted design authority for the narrow superseded
contract below. Acceptance does not implement the contract, accept Slice 2,
close `S2-IR-001`, fix the source BUG, authorize S2-002, promote Runtime, or
authorize another Run.

== Narrow supersession boundary

If independently accepted, this record supersedes only these portions of the
accepted FTR:

* the statement in _Convergence facts and bounded goalpost_ that all inputs
  needed to qualify a cycle are mechanically observable in accepted Run state;
* the Slice-2 contract that derives `ConvergenceFact` from ordered
  Run/Hop/Finding history plus a finite limit alone;
* the related persistence/checkpoint/test statements insofar as they assume
  that `run.json` alone can prove the required-evidence qualification
  predicate; and
* the Slice-2 implementation boundary that excluded the existing operator
  execution-evidence seam from the derivation input.

All other accepted architecture remains in force, including stable Finding
identity, correction-obligation lifecycle, evidence freshness, exact
corrector/evaluator correlation, profile grammar, route precedence, escape
events, diagnosis/reframe semantics, strategy generations, authority limits,
legacy Run parsing, and the implementation slicing not expressly amended here.
This is forward-moving semantic correction, not historical rollback:

----
Fachlich darf man zuruckgehen. Prozessual geht man immer vorwarts.
Backtracking is semantic, never historical.
----

The original FTR and its acceptance history remain the truthful authority under
which the stopped Slice-2 attempt was commissioned.

== Falsified assumption and empirical counterexample

=== Falsified prior assumption

The falsified simplified contract was:

----
ConvergenceFact = f(
  Run/Hop/Finding semantic history,
  qualified_cycle_limit
)
----

The accepted design named evidence failure as a non-qualifying case, but no
durable field in `Hop` or `HopSummary` records
`MechanicalFacts.required_evidence_failed`. `vertical.py` computes that value
from Coordinator-executed `Observation` values for the current Hop and passes
it to `reduce_result`; `reducer.py` may use it to select the configured
`failed_evidence_route`. The value is then lost from Run history. A later pure
`derive_convergence_facts(run, limit)` therefore cannot distinguish a
mechanically qualified evaluator assessment from the same semantic assessment
whose required evidence failed.

Agent-authored `evidence_refs` cannot repair the gap. They are attributed
semantic references, not trusted command observations.

=== S2-001 H002 empirical counterexample

The stopped Slice-2 implementation attempt produced a factual but unaccepted
candidate at `830bdf5536e28a52502bb6faf9172e57093150cb`. Fresh independent
review established the following counterexample, reproduced here as this
revision's grounding rather than by resurrecting its unpublished review draft:

* an evaluator Hop can carry a structurally valid correlated
  `carried_new_counterexample`;
* the corresponding Finding may remain open and blocking;
* the Coordinator's required trusted evidence for that Hop may fail;
* reduction knows this as
  `MechanicalFacts.required_evidence_failed=True`;
* persisted semantic Run/Hop/Finding history does not retain enough
  information for later `derive_convergence_facts(run, limit)` to distinguish
  that evidence-failed evaluator cycle from a qualified one; and
* the reproduced history derived a qualified-cycle count of 1 even though
  failed required evidence must not qualify.

That is an input-sufficiency defect, not a defect in Slice-1 semantic
admission. `S2-IR-001` remains open until a later implementation and its own
independent implementation review close it.

== Existing authority surfaces

Semantic history owns Hop identity, attributed coverage and convergence
assessments, Finding lifecycle, semantic outcome, and applied route. It answers
whether the accepted semantic cycle predicate exists. It does not establish
whether Coordinator-required commands passed.

Trusted mechanical evidence owns the admitted required-command plan and the
Coordinator-executed observations for one invocation: command identity,
pass/fail/error/not_run, and Hop/invocation correlation. It answers only the
mechanical qualification predicate.

The current operator already writes `execution-evidence.json` outside `Run`,
atomically replacing a document shaped as
`{"schema_version": 3, "attempts": [...]}`. Each candidate-bearing row already
contains `hop_id`, `invocation_id`, phase, workflow role, semantic/repository
anchors, and `trusted_observations`. Reusing and narrowly completing that
surface is smaller than either copying a boolean into semantic state or
inventing another evidence ledger.

== Alternatives considered

=== A -- durable qualification inside Run/Hop semantics

Rejected for this correction. Persisting `required_evidence_passed` or an
equivalent summary on Hop would make Run-only derivation convenient, but would
copy a fact whose detailed authority already lives in execution evidence. It
would change Run/Hop wire, collapse a mechanical execution predicate into the
semantic ledger, and create two durable representations that can disagree.
Persisting only a boolean would also discard the exact required-command set
needed to explain missing, partial, or multiple-command cases. Persisting all
observations inside Hop would duplicate the existing evidence substrate and
substantially widen the semantic wire.

This family is not incoherent in principle, but it is larger and creates more
authority ambiguity than the selected use of the existing surface.

=== B -- semantic Run history plus trusted execution evidence

Selected. The surfaces remain separately owned and are joined by strict
Coordinator correlation. Execution evidence becomes an authoritative input
only to the mechanical qualification predicate. It does not become semantic
Finding, acceptance, route, or strategy authority. The resulting
`ConvergenceFact` is a composite projection, not a new ledger.

The current schema-3 document cannot simply be treated as sufficient. A narrow
schema-4 addition must bind it to the exact Run and retain the exact required
command identities for each attempt. Without those fields, empty, partial,
stale, or cross-Run observations cannot be interpreted replay-deterministically.

=== C -- prevent failed-evidence semantic records from becoming authoritative

Rejected. The evaluator did make a semantic claim, and the Coordinator did
accept and validate that correlated result before mechanically selecting the
failed-evidence route. Suppressing or rolling back the assessment/Finding
history would make the audit trail untruthful and would entangle Slice-1
Finding transactions with evidence execution and publication ordering. It
would also risk changing the meaning of accepted Slice-1 output merely to make
a later read model simpler. The correct distinction is “semantic assessment
recorded” versus “mechanically qualified for convergence counting.”

=== Other -- infer failure from route or stop reason

Rejected. `applied_route`, `failed_evidence_route`, and stop reasons are lossy
routing effects, not a complete record of command identity or status. A phase
may have no failed-evidence route; other preemptions can control; and route
names are profile-specific. Inference from an absent failure route would fail
open. No materially smaller coherent alternative to B was found.

== Revised authoritative input contract

=== Exact input set

The authoritative inputs to revised convergence derivation are exactly:

. the accepted, ordered schema-version-3 Run semantic history, including
  tracked Findings, coverage claims, convergence assessments, Finding delta
  correlations, and evaluator Hop order;
. the presence or absence of one Coordinator-written `execution-evidence.json`
  surface, represented for derivation by either a strictly validated
  schema-version-4 document for that exact Run or an explicit empty
  qualification index when the document is absent/legacy;
  and
. the finite `qualified_cycle_limit` supplied from the pinned profile by the
  separately accepted integration layer.

No agent prose, agent `evidence_refs`, checkpoint value, route name, stop
reason, result file, mutable count, or inferred historical value is an input.
The execution-evidence row itself durably snapshots the admitted required
command set used for that attempt, so replay does not consult a later mutable
policy/profile file to reconstruct it.

The pure derivation API may express the second input as a strictly parsed
immutable `TrustedQualificationIndex` rather than raw JSON. That index must be
a lossless validation product of the schema-4 document, not a cache or an
independent persistence surface. Conceptually:

----
derive_convergence_facts(
  run,
  trusted_qualification_index,
  qualified_cycle_limit,
) -> tuple[ConvergenceFact, ...]
----

For every semantic cycle candidate at evaluator Hop `h`, the current accepted
semantic predicate remains unchanged. The candidate contributes `h` to
`source_evaluator_hops` if and only if the qualification predicate below is
also true. Counts, source-Hop ordering, and `goalpost_reached` are then derived
exactly as before.

This revision qualifies the source evaluator Hop only. It does not add the
corrector Hop's command outcomes to the convergence predicate. The empirical
defect and the convergence event both concern the evaluator assessment; any
future decision to require a two-Hop mechanical conjunction would be a wider
semantic change requiring separate authority.

=== Execution-evidence schema version 4

Schema version 4 retains the existing bounded schema-3 attempt fields and
trusted Observation wire and adds only the identity and plan facts necessary
for deterministic qualification:

[source,json]
----
{
  "schema_version": 4,
  "run": {
    "run_id": "RUN-...",
    "work_item_id": "WI-...",
    "profile_id": "...",
    "profile_revision": "..."
  },
  "attempts": [
    {
      "hop_id": "H002",
      "hop_sequence": 2,
      "invocation_id": "INV-...",
      "pre_route_anchor_sha256": "...",
      "phase": "review",
      "workflow_role": "independent_reviewer",
      "outcome": "changes_required",
      "base_head": "...",
      "end_head": "...",
      "actual_commits": [],
      "candidate_result_present": true,
      "candidate_result_sha256": "...",
      "publication": "staged",
      "required_evidence": [
        {
          "command_name": "pytest",
          "argv_digest": "...",
          "timeout_seconds": 900
        }
      ],
      "trusted_observations": [
        {
          "command_name": "pytest",
          "argv_digest": "...",
          "timeout_seconds": 900,
          "status": "pass"
        }
      ]
    }
  ]
}
----

The abbreviated Observation above does not remove existing schema-3 fields;
schema 4 retains their strict validation. `required_evidence` is the ordered,
Coordinator-prepared phase selection, not an agent field. Each command name is
unique. Its identity is the tuple `(command_name, argv_digest,
timeout_seconds)`. An empty list truthfully means that the admitted phase
required no command. The writer obtains this list from the same prepared
commands it actually executes; it must not reconstruct it from observation
presence after execution.

The document-level Run identity is mandatory. `hop_sequence` and
`pre_route_anchor_sha256` are mandatory. The anchor is a SHA-256 over the
canonical closed JSON object constructed by the Coordinator *before route
selection*. It contains exactly: the document Run identity; Hop ID and
sequence; invocation ID; phase and workflow role; candidate semantic outcome;
base HEAD, end HEAD, and ordered actual commits; the mandatory
`candidate_result_sha256` over canonical validated candidate structured-result
bytes; and the ordered prepared required-command identity tuples. It deliberately
excludes applied route, route reason, stop reason, Run status, checkpoint
material, and Observations. The row retains `candidate_result_sha256` so replay
can recompute the anchor without relying on a transient result file. The
Coordinator creates the same anchor once, writes it into the staged evidence
attempt, and persists its digest as the immutable `pre_route_anchor_sha256` on
the final v3 HopSummary if reduction succeeds. Canonical JSON and SHA-256 rules
are the existing closed Run-wire rules. Thus the anchor is available when the
live predicate is consumed and remains exactly checkable after route selection.

`invocation_id` remains mandatory and must be unique in the document. Unknown
fields or malformed values fail strict parsing. Schema 4 does not add a mutable
`qualified` boolean; qualification remains derived from plan plus
Observations. The evidence attempt has the immutable publication value
`staged`: it records a complete pre-route fact, and is eligible only when it
has the exact paired Hop below. Recovery deterministically classifies a staged
row belonging to a charged uncertain Hop as abandoned for qualification without
rewriting its evidence bytes. This publication provenance is not a qualification
truth field and cannot turn a failing or missing command into a pass.

=== Exact durable and live correlation rule

An execution-evidence attempt correlates to semantic evaluator Hop `h` only
when all of the following hold:

. the document `run_id`, `work_item_id`, `profile_id`, and
  `profile_revision` equal the Run's pinned identities;
. exactly one attempt row names `h.hop_id` and `h.sequence`;
. that row's non-empty `invocation_id` is unique in the document;
. the row's `pre_route_anchor_sha256` equals `h.pre_route_anchor_sha256`, and
  that digest recomputes from the exact pre-route tuple defined above;
. the row's workflow role, semantic outcome, base HEAD, end HEAD, and ordered
  `actual_commits` exactly equal both the pre-route tuple and the Hop summary;
. the row records a validated candidate (`candidate_result_present=true`).

The accepted convergence assessment in `h` already proves Slice-1 evaluator
provenance; derivation does not re-admit that semantic record from the attempt
row. The row's retained `phase` is audit context, while its workflow role and
complete pre-route anchor are checked as above. This avoids both a mutable live
profile file as replay input and the impossible dependence on a final
route-bearing HopSummary digest.

Every pair-qualified attempt row must correlate to exactly one Hop in the
identified Run. During the bounded evidence-before-Run interval, the one staged
row named by the live dispatch marker is permitted to be temporarily unpaired;
it is usable only by that in-flight reduction and not by any durable replay.
A row for an unknown Hop outside that interval, a duplicate row for one Hop,
duplicate invocation identity, reordered/mismatched commit anchors, cross-Run
document, or conflicting provenance is inconsistent input. It must never be
selected by best effort, first/last wins, route inference, or nearest-sequence
matching.

Missing and inconsistent input differ operationally but both fail closed. No
row for an otherwise valid evaluator Hop means that candidate is simply
unqualified. Structurally malformed, duplicate, cross-Run, contradictory, or
unpaired `staged` input raises one deterministic qualification-input error; a
consumer must not publish a new convergence checkpoint or take a convergence
route from it. The existing mechanical/human stop boundary handles such an
integration error when live routing is later commissioned. It is not converted
to count zero and silently ignored, because doing so would conceal corrupted
trusted input.

The sole retained-unpaired exception is recovery's own exact record: when the
marker identifies the staged row but no accepted Hop was persisted, recovery
charges that exact Hop as `uncertain_dispatch` and persists the same anchor on
the uncertain Hop solely to classify the row abandoned. That row is audit-only,
not an index member. A staged row without this exact uncertain-Hop record, or
with a different Run, Hop, invocation, sequence, or anchor, remains an error.

=== Current evaluator Hop live trusted input

For the current evaluator Hop only, the integration layer constructs a frozen
`StagedQualificationAttempt` after it has validated the candidate result,
observed the repository end state, prepared and executed the admitted required
commands, and computed the pre-route anchor. The object contains precisely the
schema-4 row's Run/Hop/invocation identity, candidate/repository tuple,
prepared command plan, and trusted Observations. It is strict-parsed by the
same schema-4 attempt validator used for durable replay; it is not an agent
object, a reducer inference, or a mutable overlay.

The Coordinator atomically publishes that exact row in
`execution-evidence.json` before calling the route-selecting reduction. It
then supplies the parsed immutable index for the already durable rows plus
that same parsed staged row to `reduce_result`. The current evaluator's
mechanical predicate is therefore the same exact plan/Observation conjunction
that replay later uses, not a shortcut from `MechanicalFacts` or agent prose.
The reducer may use this current-Hop input only after the normal semantic
predicate has been established; a mechanical pass cannot create an assessment,
Finding disposition, or route on its own.

=== Mechanical qualification semantics

After exact Hop correlation, the attempt's required plan and observations are
matched by the exact command-identity tuple above:

Pass:: Every required command has exactly one matching, strictly valid trusted
Observation with `status=pass`, and there is no extra Observation. The
mechanical predicate is true.

Fail:: Any matching required Observation has `status=fail`. The predicate is
false. The semantic assessment remains in history but its evaluator Hop is
absent from `source_evaluator_hops`.

Error:: Any matching required Observation has `status=error`. The predicate is
false. Existing evidence-error preemption remains unchanged.

Not run:: Any matching required Observation has `status=not_run`. The
predicate is false.

Missing evidence:: The evaluator has no exactly correlated schema-4 attempt,
or one required command has no Observation. The predicate is false.

Partial evidence:: Some but not all required commands have observations. The
predicate is false regardless of the observed subset's statuses.

Multiple required commands:: Qualification is the conjunction over the exact
required plan. All must pass exactly once. One fail, error, not_run, missing,
duplicate, or mismatched observation prevents qualification.

No required commands:: The predicate is true only when an exactly correlated
schema-4 attempt durably records both an empty required plan and an empty
trusted-observation list. Absence of the attempt cannot be interpreted as a
vacuous pass.

Extra, duplicate, or identity-mismatched observations are inconsistent input,
not optional successes. Unsupported status values and malformed Observation
wire are likewise input errors. Agent references and prose are never used to
fill a missing Observation.

== Authority and invariant preservation

No shadow ledger:: The revision adds no counter, goalpost flag, or mutable
qualification state. The schema-4 attempt is an immutable execution record;
`ConvergenceFact` remains recomputed.

Replay determinism:: Identical Run bytes, identical validated schema-4
execution-evidence bytes, and the same finite limit produce identical facts
and ordered source Hop IDs.

Live/replay equivalence:: For a current evaluator Hop, reduction receives the
strictly parsed staged row that has already been atomically published. The final
Hop persists the same pre-route anchor, so replay validates and evaluates the
identical row, semantic predicate, and finite limit. A route selected from that
cycle is authoritative only if this equality holds; otherwise recovery stops
fail-closed and the route is not usable.

Fail closed:: Missing qualification is false; ambiguous or inconsistent
trusted input blocks its consumer. None can cause qualification.

No semantic authority from evidence machinery:: A pass can only satisfy the
mechanical conjunct of an already valid semantic cycle. It cannot create an
assessment, resolve/supersede/residualize a Finding, accept work, advance a
strategy, or select a route by itself.

No agent authority over trusted qualification:: Agents cannot write the
external Coordinator state, declare the required plan, or self-certify with an
`evidence_ref` or summary.

Stable correlation:: Run identity, Hop ID/sequence, invocation uniqueness,
role/outcome, repository anchors, and commit list must agree exactly.

No historical rewrite:: No old Run or evidence document is migrated or
backfilled. No failed-evidence route or prose is mined to synthesize status.

Slice-1 acceptance remains intact:: Slice 1 continues to admit and preserve
semantic coverage, assessments, Finding deltas, and freshness. This revision
does not contradict or reopen `S1-IR-001` or `S1-IR-002`.

Checkpoint remains derived:: It is a replaceable projection over both
authoritative inputs, never a third source.

No premature Slice-3/4 behavior:: This record adds no escape substitution,
diagnosis/reframe behavior, generation advancement, or profile grammar.

Truthful failed-evidence history:: The semantic claim remains visible while
the mechanically unqualified evaluator Hop is excluded from the count.

Minimal scope:: The existing execution-evidence surface is extended narrowly;
there is no generalized event store, provenance framework, or persistence
substrate.

All twelve required invariants are therefore preserved without revision.

== Crash, recovery, replay, and publication

The semantic Run snapshot and execution-evidence document remain separately
atomic files; this revision does not introduce a cross-file transaction,
general event store, or new persistence substrate. It extends the existing
dispatch marker with the expected invocation and pre-route-anchor digest, and
makes a valid Run/evidence *pair* the authority for a convergence-dependent
route. An isolated `run.json` containing such a route is not route-authoritative
until the exact qualifying evidence row validates against its immutable Hop
anchor. This pair rule prevents a persisted route from surviving as authority
when replay excludes its source cycle.

The finite publication sequence for every candidate-bearing evaluator Hop is:

. Persist the ordinary dispatch marker before provider invocation, as today.
. Validate the candidate result; observe final repository facts; execute the
  admitted required-command plan; construct and strictly validate the immutable
  staged attempt and pre-route anchor; record that anchor in the marker.
. Atomically replace `execution-evidence.json` with all prior rows plus the
  complete `publication: staged` schema-4 row. This is the durable current-Hop
  qualification input.
. Reduce using the strict index containing that same staged row. If it selects
  a convergence/escape route, atomically persist the reduced Run with the same
  immutable anchor on its HopSummary. The route is authoritative only with the
  already-published, exactly matching row.
. Atomically regenerate the derived checkpoint from paired Run/evidence bytes,
  then remove the dispatch marker.

No state permits Run publication before evidence publication. Thus the former
“Run published but evidence absent” state is not normally reachable; discovery
of it after storage loss or tampering is pair-validation failure, not an
unqualified route that may continue. A staged row deterministically abandoned
because its Hop was charged uncertain retains raw trusted observations for audit
but is excluded from the qualification index and cannot be reused by a later
Hop.

The schema-4 writer must preserve already durable rows when continuing a Run;
it must not initialize an empty array and erase predecessor attempts.

Checkpoint identity shall bind both inputs, using the existing Run snapshot
digest plus an `execution_evidence_sha256` of the exact schema-4 bytes. A
checkpoint with either digest mismatch is stale and cannot supply routing or
qualification truth. Rebuilding it is mechanical and changes no authority.

Replay validates the complete execution-evidence document first, validates the
Run/evidence pair and every immutable anchor, builds the immutable
qualification index, and then derives facts in Run Hop order. It does not
depend on filesystem enumeration, JSON member order, live policy files, or
observation arrival order. `source_evaluator_hops` remains ordered by semantic
Run Hop order. A pair failure is not repaired by checkpoint regeneration and
cannot leave a convergence/escape route usable.

== Legacy and compatibility semantics

Run wire versions 1 and 2 remain non-convergence Runs and derive no facts, as
already accepted. Run wire version 3 remains readable without change.

Execution-evidence schema versions 1 through 3 remain readable for audit but
are ineligible to prove the revised mechanical predicate because they lack the
complete Run/required-plan binding. They are never silently upgraded. For a
schema-version-3 Run with absent or legacy execution evidence, derivation uses
an explicit empty qualification index: every open tracked Finding projects a
zero-count `ConvergenceFact`, and no historical evaluator Hop enters
`source_evaluator_hops`. It must not reuse the old semantic-only count.

No operator, migration, or human may backfill a pass from an applied route,
test log, agent evidence reference, repository state, or remembered command
result. If historical qualification is operationally needed, a separately
authorized fresh Run must create new trusted records.

== Wire and checkpoint consequences

Run/Hop/Finding wire change:: Narrow HopSummary addition only. A v3
HopSummary gains the immutable Coordinator-created `pre_route_anchor_sha256`.
It is a correlation digest over pre-route candidate and repository facts, not
`required_evidence_failed`, an Observation, an invocation field, mutable
qualification boolean, count, or goalpost truth. Finding wire and the existing
`ConvergenceFact` shape remain unchanged.

Execution-evidence wire change:: Yes. Schema version 4 adds the mandatory Run
identity, `hop_sequence`, `pre_route_anchor_sha256`, immutable publication
provenance, and exact per-attempt `required_evidence` plan while retaining
strict existing attempt and Observation facts. Older versions remain
audit-readable but mechanically ineligible for revised qualification.

Checkpoint change:: The optional convergence projection consumes the paired
qualification index and includes `execution_evidence_sha256` beside the Run
digest. It continues to serialize only derived `ConvergenceFact` values and
source evaluator Hop IDs. It does not persist a qualification decision as
authority, repair an invalid pair, or authorize an isolated Run route. Missing
evidence produces no qualified source Hop; inconsistent evidence prevents a
fresh projection and makes a convergence-dependent route unusable.

== Slice implications

=== Slice 1

No Slice-1 implementation change is required. Its records truthfully retain
the evaluator's semantic claim and Finding lifecycle even when evidence fails.
Its accepted correlation, totality, freshness, transactionality, and strict
Run-v3 wire remain prerequisites to the semantic conjunct. The new required
plan/Observation correlation belongs to revised Slice 2's mechanical read
model and operator evidence publication, not to Slice-1 semantic admission.

=== Exact amendment to Slice-2 implementation authority

The stopped S2-001 candidate is factual but unaccepted. This design does not
modify it and grants no authority to do so. A future S2-002 or equivalent
Commission must explicitly replace the Run-only Slice-2 derivation contract
with this composite contract. It must:

* strictly model/parse schema-4 execution evidence and construct the immutable
  qualification index;
* make convergence derivation require that index and apply the exact
  evaluator-Hop conjunction, including the current evaluator's immutable
  staged attempt before its route is selected;
* make the operator publish Run identity, Hop sequence, pre-route anchor, and
  prepared per-attempt required-command plan before a convergence-dependent
  Run route, without losing prior rows;
* extend the dispatch/recovery path to validate the Run/evidence pair,
  recognize a completed marked publication idempotently, and classify an
  unpaired staged attempt as abandoned rather than guessing a pass;
* bind checkpoint projection to both authoritative input digests;
* preserve the absence of routing, escape, diagnosis, reframe, and generation
  advancement in Slice 2; and
* undergo a fresh independent implementation review that explicitly disposes
  `S2-IR-001`.

Acceptance of this design revision neither supplies that Commission nor closes
the implementation blocker.

=== Slice 3 integration

Slice 3, when separately authorized, must supply the same validated
qualification index and pinned finite limit to its convergence projection
before considering escape substitution. For the current evaluator it receives
the strictly parsed, already-published staged attempt; for history it receives
only exact Run/evidence pairs. An unavailable evaluator row makes that cycle
non-qualifying; inconsistent or unpaired trusted input mechanically preempts
convergence routing. Slice 3 must not recreate the old Run-only overload,
infer evidence state from the failed-evidence route, treat a checkpoint as
authority, or finalize a route before the required staged attempt exists. No
Slice-3 behavior is implemented or otherwise revised here.

== Deterministic tests required before Slice-2 acceptance

A later implementation must keep the complete repository suite green and add
deterministic coverage for at least:

. one correlated semantic cycle plus one exact all-pass evaluator attempt
  increments once and records that evaluator Hop;
. a current evaluator Hop whose all-pass staged attempt reaches the goalpost
  takes the live convergence/escape route, persists its pre-route anchor, and
  produces the identical qualification fact and route authority on replay;
. the S2-IR-001 counterexample: the same semantic history with evaluator
  `status=fail` yields count zero and no source Hop;
. `error` and `not_run` each yield count zero;
. a missing evaluator attempt yields count zero. Boundary injection follows
  the normative evidence-before-Run order: an unpaired staged row after
  evidence publication and before Run publication is abandoned and
  non-qualifying. Separately injected storage loss or tampering that makes a
  paired row absent after Run publication is pair-validation failure and stops
  fail-closed; it is not a permitted Run-before-evidence publication window;
. a required plan of two commands qualifies only when both exact observations
  pass;
. one missing observation, one pass plus one fail, one pass plus one error,
  and one pass plus one not_run do not qualify;
. duplicate, extra, command-name-mismatched, argv-digest-mismatched, and
  timeout-mismatched observations fail closed;
. an exactly correlated empty required plan plus empty observation set
  qualifies, while an absent row does not;
. cross-Run evidence, wrong WorkItem/profile revision, wrong Hop ID/sequence,
  duplicate Hop rows, duplicate invocation IDs, role/outcome/head/commit
  mismatch, unknown Hop rows, and malformed schema fail deterministically and
  cannot publish a convergence route or fresh checkpoint;
. two qualified evaluator cycles retain Run order and reach a limit of 2 with
  no off-by-one error; changing only one observation to fail removes only its
  source Hop and adjusts the count deterministically;
. `carried_unmet`, stale semantic evidence, uncorrelated assessment,
  resolved/superseded Finding, different Finding ID, and uncertain/rejected
  history remain excluded independently of mechanical pass;
. a mechanically passing attempt without the accepted semantic predicate does
  not create a cycle, Finding disposition, or semantic acceptance;
. replay from byte-identical Run and schema-4 evidence produces identical
  facts and checkpoint bytes;
. injection at every publication boundary: before staged-evidence replacement,
  after staged evidence before Run replacement, after paired Run replacement
  before checkpoint replacement, and after checkpoint replacement before marker
  removal. Each case proves the matrix's precise recovery result, no partial
  qualification, and no convergence/escape route usable without replayable
  paired authority;
. atomic replacement failures for both prior-row-preserving evidence writes
  and Run writes leave only the prior complete file version visible; a later
  missing, duplicate, malformed, cross-Run, stale, or anchor-mismatched row
  stops recovery fail-closed rather than preserving an isolated route;
. a dispatch marker left by a fully paired Hop is recognized idempotently and
  does not recharge the Hop; a marker with no paired Run Hop charges uncertain,
  classifies any staged row abandoned, and never allows it to qualify;
. duplicate publication with byte-identical Hop/invocation/anchor is idempotent,
  while duplicate or differing Hop/invocation/anchor content is rejected;
. checkpoint digest mismatch for either Run or execution evidence is rejected
  and reconstruction restores the same derived view;
. atomic evidence-publication failure leaves the previous complete document
  and cannot expose a partially qualifying row;
. continuation preserves existing attempts and rejects duplicate append;
. schema versions 1 through 3 are not backfilled or treated as proof of pass;
  legacy/simple Runs remain unchanged; and
. the sole new Run/Hop/Finding semantic-wire field is the immutable
  `HopSummary.pre_route_anchor_sha256`. Revised Slice 2 introduces no
  mechanical qualification boolean, Observation, or invocation ID in semantic
  wire; no mutable count, goalpost flag, route substitution, escape event,
  diagnosis/reframe record, or non-zero strategy generation.

These tests are necessary, not independent-review acceptance by themselves.
