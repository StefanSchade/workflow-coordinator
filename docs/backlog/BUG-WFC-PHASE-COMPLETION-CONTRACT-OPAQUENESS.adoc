= BUG-WFC-PHASE-COMPLETION-CONTRACT-OPAQUENESS -- Phase-Completion Contract Opaqueness Across Distributed Result/Effect/Artifact Surfaces

Type:: bug -- agent/Coordinator phase-completion contract ergonomics (not a
Coordinator fail-closed defect, not a reducer defect, and not a single
specific-mechanism authority defect)
Status:: open (documentation only; no correction authorized by this record)
Current controlling source:: This record; see link:_open.adoc[the active-work manifest] for its current card.
Next action:: Investigate the recorded opacity before proposing bounded work.
Not authorized here:: Contract redesign, implementation, or a Run.
Date:: 2026-10-05
Classification:: workflow friction / autonomy reliability -- the agent-facing
phase-completion contract is distributed across several independently
expressed surfaces and is opaque/combinatorial enough that a semantically
competent agent can still produce a locally plausible, globally inadmissible
result
Discovery:: repeated real WFC self-development Runs in the
Correction-Convergence-Escape implementation lineage: S3-002, S4-001, and
S4-002 H004 (see "Primary reproductions" below)

== What this is not

* This is not a claim that Coordinator fail-closed behavior is wrong. In
  every reproduction below the Coordinator (or, for S3-002, the reducer's
  Finding-authority boundary) correctly refused to admit a result that could
  not satisfy the complete operational contract of its phase. None of those
  refusals is characterized as a defect.
* This is not a claim that agents are generally incapable. In every
  reproduction below the agent performed materially useful semantic work --
  partial implementation, a sharper adversarial counterexample, or a
  technically correct corrected-implementation judgment -- and the mechanical
  stop happened despite that useful work, not because the work was wrong.
* This is not `BUG-WFC-SELF-DEVELOPMENT-GATE-FINDING-AUTHORITY.adoc`. That
  open record concerns one specific authority mismatch: a self-development
  Commission *profile* whose rereview gate was authored with a
  disposition-bearing purpose but `finding_authority: []`, a Commission-
  authoring defect with no engine or product change required. This record is
  broader and does not reduce to that mismatch alone: S4-002 H004 (below)
  shows the same class of mechanical stop arising from a missing durable
  artifact, not from missing Finding-disposition authority, under a profile
  that *did* grant `resolve` authority. This record treats the S3-002
  Finding-authority case as one instance of a wider pattern, not as a
  restatement of that BUG, and does not modify, reopen, or extend that BUG.
* This is not `BUG-WFC-CORRECTION-BLOCKING-SET-CARRYOVER.adoc`. That open
  record concerns a correction Hop silently dropping a long-lived named
  blocker while fixing only the latest reviewer counterexample -- a
  convergence-behavior concern about which blockers get addressed. This
  record concerns whether a phase's completion obligations are even legible
  and jointly satisfiable in the first place, independent of which blockers
  a Hop chooses to address.
* This is not `BUG-WFC-SCOPE-ESCALATION-CONTINUATION-GAP.adoc`. That open
  record concerns the missing operator continuation path *after* a Hop
  correctly, deliberately stops to ask for authority it does not have. This
  record concerns Hops that do not deliberately escalate at all: the agent
  believes (often correctly, on the merits) that it has completed the phase,
  and the mismatch is discovered only by mechanical preemption against a
  surface the agent did not fully reconcile.
* This is not the already-closed `BUG-WFC-FINDING-AUTHORITY-PROMPT-PROJECTION`
  or `BUG-WFC-PROFILE-DURABLE-ARTIFACT-INSTANCE-COUPLING`. Those fixed
  specific projection/coupling defects within single surfaces. This record
  does not claim either fix is incomplete; it observes that even with those
  fixes in place, the number of independently correlated surfaces a result
  must jointly satisfy remains large enough to produce recurring mechanical
  preemption against otherwise-useful work.

== Problem statement

A WFC Hop's successful phase completion is currently distributed across
several independently expressed surfaces, including some combination of:

* the provider structured-result payload (outcome, requested route, scope
  change, human requirement, escalation);
* Finding proposals and the phase's projected Finding-lifecycle authority;
* `CommitIntent`;
* `authorized_actions` for the current Hop;
* worktree mutations actually made;
* required/optional/none durable-artifact obligations for the current phase;
* trusted Coordinator-owned Git materialization; and
* post-effect repository observations (clean/dirty tracked state, the exact
  changed-path set, the resulting HEAD).

The Coordinator correctly fails closed when these surfaces disagree. The
problem is not that fail-closed behavior is wrong, and not that agents are
generally incapable. It is that the agent-facing phase-completion contract
has become unnecessarily opaque and combinatorial: too many locally
plausible agent-produced combinations of these surfaces are globally
inadmissible, and the agent has no single place to check, before responding,
whether its otherwise-sound semantic result actually satisfies every
obligation its current phase independently declares.

== Primary reproductions

=== S4-001 -- worker returns a review-style disposition instead of completing

WorkItem `WI-WFC-CORRECTION-CONVERGENCE-ESCAPE-IMPLEMENTATION-S4-001`, Run
`RUN-3efc7eb2aa374263a2b12954213642f1` (archived as
`wfc-correction-convergence-escape-implementation-s4-001-20261005-03` in the
`workflow-coordinator-run-evidence` repository). Its sole Hop, H001
(`role: worker`), performed useful partial implementation work atop the
Slice-4 scope but returned `outcome: changes_required` -- a review-style
disposition the `worker` role's phase does not produce as a completing
result -- made no commit, and left the worktree dirty. The Coordinator
mechanically preempted it with a layered stop recorded as
`mechanical_preemption:dirty tracked state; post-evidence worktree is not
clean with resolved submodules` together with
`trusted_commit:commit intent is not permitted for this result disposition`.
The partial candidate was separately preserved as non-authoritative salvage
(`workflow-coordinator@15102e6b17a3180e2650ac1cb2a5e4bffe3822f8`, "wip
(convergence): preserve preempted S4-001 H001 candidate") and granted no
correctness or review credit; a fresh successor Run, S4-002, began from
committed history containing that salvage.

This reproduction supports phase-/role-specific result projection: the
`worker` phase's result surface should ideally not have made a
review-disposition outcome locally expressible in the first place.

=== S4-002 H004 -- valid adversarial finding, missing durable-artifact effect

Run `RUN-198ad6957b1b4dc7a0d2fe63f9e0e391`
(`wfc-correction-convergence-escape-implementation-s4-002-20261005-01`),
continuing S4-002. H004 (`role: independent_reviewer`, invocation
`INV-86a73cea69f14e739d5d87ec9079de94`) is a fresh rereview with
`finding_authority` including `resolve` (it correctly proposed `F002 ->
resolved`). It performed materially useful adversarial analysis and
identified a sharper valid replay counterexample against `F001` (a forged
run-v3 history with two unconsumed escapes and a later causal accepted
assessment, which `_validate_v3_run`/`derive_convergence_facts` wrongly
admits and advances to generation 1). It returned `outcome:
changes_required`, `requested_route: correct`, `commit_intent: null`,
`claimed_commits: []`, and made no worktree modification (`actual_commits:
[]`). The Run's profile declared `durable_artifacts.rereview` as
`required`, naming
`docs/cold_storage/backlog/history/FTR-WFC-CORRECTION-CONVERGENCE-ESCAPE_implementation_review_001.adoc`.
Because H004's result neither modified nor committed that required durable
artifact, the Coordinator correctly failed closed with
`mechanical_preemption:required durable artifact is missing, unrepresented,
or uncommitted`. (Contrast H002 in the same Run, also a `changes_required`
rereviewer-equivalent disposition, which satisfied the same obligation by
appending `S4-IR-001`/`S4-IR-002` to that same artifact and committing the
result.)

This reproduction demonstrates that projected payload typing alone (S4-001's
concern) is not the full problem: some phase-completion obligations are
effects/postconditions -- a required durable artifact actually being
written and committed -- rather than merely result fields the provider could
get right by filling in the correct JSON shape.

=== S3-002 -- valid disposition judgment, no Finding-lifecycle authority to express it

Commission `7738078f0905af78dfffe56d081062c58409c2d2`, WorkItem
`WI-WFC-CORRECTION-CONVERGENCE-ESCAPE-IMPLEMENTATION-S3-002`, Run
`RUN-2bc443f24ec642a3ae1f4d1da462a336`. Its H003 rereview (invocation
`INV-d4ed8e692ea442bf8220916ad36050d6`), a fresh independent rereview, trusted
the green `pytest` evidence, technically judged all three corrected defects
(`F001`/`F002`/`F003`) sufficient, and requested `accept`. It could not
resolve those Findings because the profile's `rereview.review.finding_authority`
was `[]`: a gate authority (whether `accept`/`complete` is reachable) that
does not imply Finding-lifecycle authority (whether `OPEN` can become
`RESOLVED`). The Run stopped `awaiting_human` with all three Findings still
open. Full detail, including why this is a Commission-authoring defect
distinct from this record, is in
`docs/backlog/BUG-WFC-SELF-DEVELOPMENT-GATE-FINDING-AUTHORITY.adoc`.

This reproduction demonstrates the same narrow common property through yet a
third independent surface: Finding-lifecycle authority, correctly enforced,
correctly projected, and still unsatisfiable by an otherwise sound and
truthful agent disposition.

=== Common property across all three

Do not flatten these into one root cause; the immediate mechanical surface
differs in each (worker/phase-role result typing, durable-artifact effect
completion, Finding-lifecycle authority). What they share, and what this
record is narrowly scoped to, is:

----
Semantically coherent agent output cannot satisfy another independently
declared phase-completion obligation.
----

In each case the agent's semantic judgment was not the problem: S4-001's
partial implementation was useful, S4-002 H004's counterexample was a real
and sharper defect, and S3-002 H003's technical acceptance judgment was
correct on the merits. In each case a different, independently expressed
surface of the same phase's completion contract -- result-shape/role typing,
required durable-artifact effect completion, or Finding-lifecycle authority
-- made that otherwise-sound result globally inadmissible, and only
mechanical preemption (or, for S3-002, a correctly empty authority
projection) caught the mismatch.

== Existing architecture to preserve

This record does not characterize any of the following as defective, and no
candidate direction below may contradict them:

* agent cognition and trusted effects are separate;
* mutating Git ownership belongs to the Coordinator, not the agent;
* `authorized_actions` describe permitted workflow effects/capabilities, not
  shell commands handed to the agent;
* `CommitIntent` is a proposal to Coordinator-owned trusted Git handling, not
  evidence that a commit occurred;
* reducer/domain semantics remain deterministic and effect-free;
* effects occur in the controlled shell and their consequences are
  re-observed; and
* authority must not be inferred from prose.

== Candidate directions -- explicitly not accepted design

These are recorded only as candidate directions requiring separate
refinement/design. This record authorizes none of them.

=== A. Phase-/role-specific projected result contracts

Compile the concrete current phase, role, route envelope, Finding authority,
and other relevant static constraints into the narrowest provider-neutral
semantic result schema before provider invocation, so invalid combinations
become syntactically unrepresentable where practical. A deferred, low-
priority record already exists in this space,
`docs/backlog/FTR-WFC-PHASE-SCOPED-RESULT-SCHEMA.adoc`, whose own stated
activation criterion is "materially recurring schema-valid but
phase-authority-invalid outputs despite correct, explicit prompt/contract
projection." This record's reproductions are offered as evidence relevant to
that criterion; this record does not itself decide whether that threshold is
met, does not promote that FTR, and does not alter its scope or priority.

=== B. Explicit Phase Completion Contract

Consider one declarative contract combining permitted semantic result shape,
permitted routes, Finding lifecycle authority, required durable artifacts,
permitted/required effects, and required postconditions -- not necessarily
one new monolithic runtime object, but something WFC can reason about as one
coherent contract rather than relying on the provider to correlate several
separate surfaces from prose.

=== C. Coordinator-materialized deterministic effects

Where an effect is fully derivable from admitted phase authority and a
structured semantic result, investigate removing the effect choice/mechanics
from provider responsibility -- for example, a reviewer produces structured
semantic review content/Finding proposals/verdict, the phase contract already
names the required durable review artifact, and WFC deterministically
renders/appends the authorized artifact representation, observes the exact
changed-path set, and performs the trusted local commit, so the provider does
not need to independently remember or invent artifact paths or Git mechanics.
This generalizes the existing principle that WFC, not the LLM, owns trusted
Git commits. This does not assert that all artifacts can or should be
Coordinator-rendered; free-form authored design/document artifacts may remain
semantic work, and any refinement must distinguish semantic artifact
authorship from deterministic persistence/materialization.

=== D. Preserve fail-closed safety

Success means reducing avoidable mechanical preemption, not weakening checks.
The desired property is roughly: for an admitted phase and a valid semantic
provider result, every deterministic effect required by that phase is either
derived and materialized by WFC, or explicitly represented by a narrow
contract the provider cannot accidentally contradict. Any failed effect or
failed postcondition still fails closed.

== Priority / motivation

This is high-priority workflow friction / autonomy reliability work. The
practical pain is real: completed Runs are currently uncommon relative to
Runs that require a fresh successor or maintainer intervention, even though
agent semantic work is often useful, as the three reproductions above
illustrate. No numerical completion rate is asserted here; none has been
independently derived from authoritative complete Run history for this
record. The purpose is not a vanity success metric. It is to make a bounded
Commission with sufficient Hop budget much more likely to run through its
intended evaluator/optimizer lifecycle without operator intervention when no
genuine semantic/human-authority issue arises. This refinement is expected
before substantial new workflow complexity such as a future Slice 5, if the
maintainer later authorizes it.
