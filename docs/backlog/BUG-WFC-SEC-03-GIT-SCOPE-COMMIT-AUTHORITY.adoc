== Defect and correction boundary

Before the correction, Git rename detection could cause the range diff used by `_observe_hop` to show only the destination, hiding an out-of-scope deleted source. Equivalent delete-plus-similar-add changes and `diff.renames` configuration can produce the same ambiguity. Salvage inventory and operator reporting have related path-observation gaps. Disable rename detection explicitly on the affected observation, salvage and reporting diffs so both leaves remain visible. Preserve the trusted commit staged-path behavior: rename-shaped CommitIntents remain a documented limitation.

Before the correction, the no-CommitIntent branch accepted otherwise valid agent-authored commits, contrary to the decided Coordinator-only contract. Use the existing observation safety cap `max_commits=0` if current contracts and tests confirm it is appropriate. Preserve successful Coordinator-owned commits and the trusted-commit admission path. No general Git authorization redesign is authorized.

== Acceptance

Cover out-of-scope rename and delete-plus-add, in-scope rename, `diff.renames` true/false/copies, salvage and reporting, agent commits in implementation and review phases, clean no-commit Hops, valid Coordinator commits and unchanged trusted-commit rename behavior. Update historical tests only where they assert newly excluded agent commits. Update the Operator Manual and Technical Model as necessary. Focused checks, full repository suite and independent review without blocking findings are required; local checks do not substitute Coordinator evidence. If a genuine contract conflict arises, stop for maintainer disposition.
