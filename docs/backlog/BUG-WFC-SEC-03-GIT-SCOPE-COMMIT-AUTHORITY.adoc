= BUG-WFC-SEC-03-GIT-SCOPE-COMMIT-AUTHORITY

Type:: bug -- Git scope observation and commit authority
Status:: candidate implemented; independent review, Coordinator evidence and acceptance pending
Source:: Independent security assessment, 2026-11-16, SEC-03 and its follow-up; currently an uncommitted read-only document in the security-review worktree, not present on Development main. Its separate adoption remains a maintainer matter.
Decision:: Since Slice 4B, agents propose CommitIntents and only the Coordinator creates commits. Agent-authored commits are not a supported alternative.

== Defect and correction boundary

Git rename detection can cause the range diff used by `_observe_hop` to show only the destination, hiding an out-of-scope deleted source. Equivalent delete-plus-similar-add changes and `diff.renames` configuration can produce the same ambiguity. Salvage inventory and operator reporting have related path-observation gaps. Disable rename detection explicitly on the affected observation, salvage and reporting diffs so both leaves remain visible. Preserve the trusted commit staged-path behavior: rename-shaped CommitIntents remain a documented limitation.

The no-CommitIntent branch currently accepts otherwise valid agent-authored commits, contrary to the decided Coordinator-only contract. Use the existing observation safety cap `max_commits=0` if current contracts and tests confirm it is appropriate. Preserve successful Coordinator-owned commits and the trusted-commit admission path. No general Git authorization redesign is authorized.

== Acceptance

Cover out-of-scope rename and delete-plus-add, in-scope rename, `diff.renames` true/false/copies, salvage and reporting, agent commits in implementation and review phases, clean no-commit Hops, valid Coordinator commits and unchanged trusted-commit rename behavior. Update historical tests only where they assert newly excluded agent commits. Update the Operator Manual and Technical Model as necessary. Focused checks, full repository suite and independent review without blocking findings are required; local checks do not substitute Coordinator evidence. If a genuine contract conflict arises, stop for maintainer disposition.

== Non-scope and follow-up

No Evidence sandbox, general hardening, new rename CommitIntent support, product-goal change or removal of legacy result fields. The low-priority link:TECH-DEBT-WFC-LEGACY-COMMIT-MECHANICS.adoc[legacy commit mechanics item] tracks later compatibility-aware cleanup without authorizing it. Implementation, review, acceptance and Runtime promotion are separate milestones.

detection. Fallback post-Hop observation applies the zero-commit safety cap.
Trusted staged-path handling remains unchanged, including the documented
rename-shaped intent limitation. The synthetic repository regression set covers
