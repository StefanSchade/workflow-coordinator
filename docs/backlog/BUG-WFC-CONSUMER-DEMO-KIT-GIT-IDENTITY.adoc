== Verified cause

Verified by the Level-1 Operator on 24 November 2026 against the
implementation, the job log and two local reproductions.

. The hosted workflow provides the test identity only through
  `$XDG_CONFIG_HOME/git/config` and sets `GIT_CONFIG_NOSYSTEM=1`. This is the
  set-up the
  link:../operator_manual/ch09_consumer_quickstart/01_quickstart.adoc[quickstart]
  recommends for an environment whose `HOME` changes; it is not at fault.
. The kit's tests use a `throwaway_home` fixture that points `HOME` at an
  empty directory and removes `XDG_CONFIG_HOME`, `XDG_DATA_HOME` and
  `XDG_STATE_HOME`. This is intended: the tests exist to show that the kit
  needs nothing from the host. It also hides the identity the workflow
  provisioned.
. `make_workspace.py` gives the demo repository `greeter` a repository-local
  identity (`WFC Demo`). It gives none to the Evidence repository
  `greeter-evidence`, which `wfc init` creates and commits to in the same
  step. That first commit therefore needs an identity from outside the
  workspace.
. `rehearse.py` runs `wfc run` with `HOME` set to the workspace's
  `rehearsal-home` and without `XDG_CONFIG_HOME`. The archive commit into the
  Evidence repository then again finds no identity.
. On the development host the tests pass only because Git falls back to the
  account's name in the password database when no identity is configured.
  The hosted runner's account has no such name, so Git refuses. The tests'
  result thus depends on a host property they do not control.

Reproduction 1 (workspace creation): an empty `HOME` containing only a
`.gitconfig` with `user.useConfigOnly = true`, no `XDG_*` variables:
`make_workspace.py` exits 1 with the message above (Git's wording then is
`no email was given and auto-detection is disabled`).

Reproduction 2 (rehearsal): a workspace created with an identity available,
then `user.useConfigOnly = true` placed in `rehearsal-home/.gitconfig`:
`rehearse.py <workspace> t1-hello-page` exits 1; `wfc run` reports
`CLASSIFICATION: completed` and then `ARCHIVE FAILED (archive_refused):
commit failed: ... Author identity unknown`, exit code 32.
`t3-probe-refusal` still passes, because it archives nothing.

The Operator's earlier attempt to imitate the runner (history chapter of
`e9b120e`) did not reproduce the failure, because it kept the host account's
name; it did not disable Git's fallback.

== Where the correction belongs

* *Not in WFC's Evidence repository initialization.* `wfc init` and the
  archive commit use WFC's trusted Git execution, which removes inherited
  `GIT_*` variables and takes the identity from Git configuration files. A
  missing identity is refused with Git's own diagnostic. That is the
  documented consumer prerequisite and part of the Trusted Git Boundary; it
  stays as it is.
* *Not in the hosted workflow.* Providing the kit's tests with the host's
  identity would hide the defect and reduce the isolation the tests assert.
* *In the kit.* The kit promises a self-contained workspace with its own
  rehearsal home; it must provide, through Git configuration files it owns
  inside the workspace, every identity that workspace creation and rehearsal
  need.
* *In the kit's tests.* They must make the absence of a host identity
  deterministic, so that the defect also fails on a host whose account has a
  name.

An observation outside this defect, not pursued here: when the Evidence
commit fails, `wfc init` has already written `.wfc/config.yaml`.

== Implementation

=== What changed

* `examples/consumer-demo/make_workspace.py`: a new `_create_evidence_repository()`
  step, called right after `_create_greeter_repository()` and before
  `_run_wfc_init()`. It creates `greeter-evidence` itself -- `git init -b
  main`, a repository-local `user.name`/`user.email` identical to
  `greeter`'s, `archive/.gitkeep`, a root `.gitignore` carrying the exact
  managed raw-retention block a freshly created Evidence repository
  carries (a new module constant `EVIDENCE_GITIGNORE_BLOCK`, duplicated
  from `workflow_coordinator.frontdoor.config.evidence_gitignore_block()`
  because the kit imports only the standard library), and one commit
  (`chore: initialize WFC Evidence repository`). The module docstring and
  the printed workspace-layout line for `greeter-evidence/` were updated
  to say the Evidence repository is seeded by the kit and adopted by
  `wfc init`, not created by it.
* `tests/integration/test_consumer_demo_kit.py`: a new helper
  `_disable_git_identity_fallback(home)` (writes `home/.gitconfig` with
  `user.useConfigOnly = true`, the configuration-file mechanism this record
  verifies the cause with -- never a `GIT_*` environment variable); a new
  test `test_workspace_creation_and_evidence_identity_do_not_depend_on_a_host_git_identity`
  (AC-1, AC-2); a new parametrized test
  `test_rehearsal_does_not_depend_on_a_host_git_identity` over all four
  scenarios (AC-3), which additionally disables the fallback in the
  workspace's own `rehearsal-home` before rehearsing.
* No other file changed; `src/`, `.github/`, the tutorial-quoted kit files
  and `examples/consumer-demo/requests/` are byte-identical (confirmed by
  `git status --short -uall -- src .github examples/consumer-demo/requests`
  printing nothing).

=== Mechanism and reason

`wfc init --evidence-repository` creates a new Evidence repository or
*adopts an existing valid one* -- a Git repository root with an `archive/`
directory -- and this is a documented outcome
(`docs/operator_manual/ch09_consumer_quickstart/01_quickstart.adoc`:
"creates or adopts"), not a new behaviour introduced here. The kit now pre-
creates a repository that satisfies that check, with its own identity, so
`ensure_evidence_repository()` takes the "reused" branch and `wfc init`
never has to make a commit itself. The one commit the kit does make for
`greeter-evidence` uses the same repository-local `git config user.name` /
`user.email` mechanism `_create_greeter_repository()` already uses for
`greeter` -- no `GIT_*` variable, no read or write of the host's real Git
configuration, nothing outside the workspace.

This is also why `rehearse.py` needed no change at all. `wfc run`'s archive
commit (`bounded_path_commit`, `git_facts.py`) and `wfc init`'s own bootstrap
commit both run `git -C <evidence repository> ...` under WFC's trusted
execution policy, which strips every inherited `GIT_*` variable but leaves
`HOME` (and the rest of the process environment) alone. A `git -C <path>`
invocation reads that path's own repository-local `.git/config` regardless
of `HOME`, so once `greeter-evidence` carries its own identity, every later
commit into it -- made under `rehearsal-home` as `HOME`, with no `XDG_*`
variable set, exactly as `rehearse.py` already runs it -- resolves identity
from the Evidence repository itself, never from the rehearsal's `HOME`.

This was the smallest mechanism available inside the stated boundary: it
changes nothing in `wfc init`, the Evidence repository initialization, or
the trusted Git execution (all fixed points), uses only an already-
documented `wfc init` outcome, and supplies identity exactly the way
`greeter` already does -- through a Git configuration file inside the
workspace, never an environment variable.

=== Whose identity, and when a host identity exists too

Every commit the kit or a rehearsal makes into `greeter-evidence` carries
the repository-local identity `WFC Demo <wfc-demo@example.invalid>` -- the
same identity `greeter` carries, set the same way. Because Git's local
repository configuration always takes precedence over global/system
configuration, this holds even when the host (or `rehearsal-home`) also has
an identity of its own; the kit's commits never depend on, and never read,
any host-provided identity.
