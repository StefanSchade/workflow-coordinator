== 1. Objective and the two problems

One outcome: a *smaller, more consistent, navigable current documentation
surface* with all relevant content and evidence preserved and findable.

. *Dead surface.* Thirty files exist only to keep a historical path resolvable:
  five root shims and 25 pointer bridges, the latter created for a
  trusted-commit limitation that hardening H3 has since fixed.
. *A flat set nobody can place.* `docs/warm_storage/concepts/` holds 152 files in
  one directory and `docs/` holds nine loose root files.

Binding principle: historical *content* is preserved, historical *paths* are not
entitled to exist. No redirect, stub, shim, parallel tree, new metadata system,
register or governance process is proposed; moves are plain renames.

== 3. Immutable evidence versus restructurable documentation

*R1 — Immutable.* Archived Run evidence, archive manifests, the Evidence
repository's ledger and index, frozen Commission/profile/policy/program bundles
and committed test fixtures — including the operator-JSON literals frozen inside
`tests/unit/test_archive_equivalence.py` — are never moved, retargeted or
rewritten. A path string inside them is historical fact, not a live reference.

*R2 — Restructurable.* Everything under `docs/` is ordinary documentation. It may
be moved, grouped, consolidated or deleted once its content survives at a
canonical or archived location. Active internal references are updated with the
move; archived bodies are not rewritten so that old paths resolve.

Applied to the real classes:

Review artifacts (117 in the warm set, 105 once the bridges go):: R2. A published
review body is durable content, not Run evidence — the Run evidence is the
archived Attempt. Move with its workstream, never edit the body.
Concept, design and decision records (18 warm files):: R2. Move with their
workstream; a Project Memory citation moves with the file (<<decisions,MD-1>>).
Runbooks, operating contracts and backlog records:: R2 for location, but no
normative Operator Manual section owner moves in P2, and `docs/backlog/` keeps its
flat shape, only the 11 bridges leaving.
Cold storage:: R2 in principle, untouched in practice, with one exception:
repairing a link *target* while keeping the visible label is a mechanical repair,
not a rewrite (C4 precedent, `FTR-WFC-DOCUMENTATION-CURATION.adoc#c4-compatibility`).
Six such targets exist (<<retirement>>). No cold body text changes.
The five root shims:: R2, and they hold no content: a title, metadata, an anchor
list and two pointer sentences each. Deleting them removes indirection — today a
manual chapter links to a stub that links back to the manual.
`docs/qualification/` (3 files):: R2. Historical by its own README; belongs in
cold storage.

== 4. Target taxonomy

=== 4.1 `docs/warm_storage/`

Ten workstream subdirectories one level deep, named as the equivalent cold group
would be, plus one `README.adoc` holding a single ten-row table:

----
agent-public-internet/            10   operator-manual-consolidation/     1
beta1-productization/             51   p35-finding-reachability/          4
claude-adapter-and-sandbox/       20   post-beta-planning/                8
coordinator-mechanics/            11   test-infrastructure/              10
documentation-and-knowledge/      16   front-door-and-program-lifecycle/  7
----

Why this shape: workstream grouping matches the established cold convention, so
later retirement is a directory-to-directory move; it keeps a review beside the
work it reviewed; and it is derivable from the filename, so no index must be
maintained to place a file. Grouping by artifact kind was rejected — it scatters
each workstream across three directories. The `concepts/` level is dropped;
everything in warm storage is a concept, investigation or review. One directory
deliberately holds a single file, so the one still-active manual review keeps its
group identity and its later retirement is one move.

Root reduces to three files: `README.adoc`, `architecture.md`,
`project_memory.adoc`. Top-level directories reduce from eleven to ten
(`qualification/` folds into cold storage). `docs/backlog/` keeps its flat
shape; 54 records in one directory are navigable by ID and are not a P2 problem.
