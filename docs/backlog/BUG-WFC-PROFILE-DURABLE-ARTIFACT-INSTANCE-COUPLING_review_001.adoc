== Findings

=== I1 (IMPORTANT) -- the namespace, not the mapping, is the write ceiling

Under Option B the `review` phase may create or modify *any* path under
`docs/backlog/wfc_reviews`, not only the mapped artifact.
`_durable_artifact_anomalies` requires the mapped path to be *present* in the
commit; it does not require the commit to be *limited* to it, and
`trusted_commit` validates intent paths against `Phase.authorized_scope`, which
is the namespace.

The BUG's acceptance criteria require that the authority review acknowledge this
explicitly. The candidate ships no document that does so. *This artifact
discharges that obligation*: the widened write ceiling is the namespace, it is
shared by every WorkItem that uses profile revision 2, and it is accepted on that
understanding.

Forward constraint, not a change required of this candidate: once more than one
review artifact lives in the namespace, a `review` hop of one WorkItem is
authorized to mutate another WorkItem's accepted review evidence. Accepted or
frozen review evidence should therefore be kept outside the namespace, or a
per-WorkItem subdirectory adopted when the continuation WorkItem is created.
This review is deliberately filed outside the namespace for that reason.

Not blocking: the namespace is currently empty and exactly one WorkItem exists.

=== M1 (MINOR) -- architecture proof no longer reads committed text

`_committed_text` (`git show HEAD:<path>`) was replaced by `_current_text`
(`Path.read_text`). The docstring was honestly updated from "committed" to
"current", and the change is what lets the negative test synthesize mutated
bundles -- but that goal was reachable while keeping committed reads for the
positive proof.

Materiality: *not* a production weakening. Production `_preflight` refuses a
dirty worktree (`facts.clean`) and reads every governing input pinned at
`expected_head` via `git show`, so an uncommitted governance mutation that made
the test green would also make the real Run refuse to start -- it cannot reach
dispatch. The residual risk is a misleading local green, and the repository has
no CI workflow to enforce a clean tree. The accepted bootstrap section 7.3 also
speaks of "the committed policy ceiling".

Smallest bounded correction (optional, non-blocking): keep the worktree read and
add, for each `GOVERNING_PATHS` entry, an assertion that it equals
`git show HEAD:<path>` whenever `git status --porcelain` is empty.

Independently compensated here: this review re-ran the full bundle proof from
`git show 0ba506c:<path>` (case A below) and confirmed the committed worktree is
byte-identical to HEAD for all three governance files.

=== M2 (MINOR) -- negative test cannot name the decisive containment leg

Both legs of the double-containment check raise the same message,
"durable artifact for phase review is outside WorkItem or phase scope", so the
test's `pytest.raises(match=...)` cannot by itself distinguish a phase-authority
rejection from a WorkItem-scope rejection. The test is nevertheless sound -- it
widens `WorkItem.scope` and the policy ceiling first, leaving phase authority as
the only possible cause -- and this review proved that independently with a
positive control (case C). Optional strengthening: add that control as a third
case so the proof is self-contained.

=== M3 (MINOR) -- namespace convention is undocumented

`docs/backlog/README.adoc` is untouched and no decision note records what
`docs/backlog/wfc_reviews` is, who may write to it, or how its files are named.
Suggested at BUG closure: one line in the backlog README. Deliberately not
bundled into the candidate, which the BUG restricted to narrowly necessary
governance and proof coverage.
