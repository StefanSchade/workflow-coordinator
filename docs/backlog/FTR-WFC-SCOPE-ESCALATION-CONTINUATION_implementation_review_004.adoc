== H002-R1A -- Post-publication canonicalization can still turn successful export into reported failure

Classification:: *carried requirement* (`R1A`)

H001 correctly removes the final-path `read_bytes()` call. It does not move all
fallible digest work before publication. `_export_salvage()` completes the
no-replace rename at `operator.py:1139`, exits the guarded publication block,
and only then calls `_canonical_json_bytes(manifest)` and `hashlib.sha256()` at
`operator.py:1149` to produce the success-output digest.

The direct fault probe demonstrates the observable consequence rather than a
merely theoretical ordering concern. Injecting an `OSError` from that
post-publication canonicalization caused public `export-salvage` to return 2
while the requested final bundle remained present and its manifest passed
`_load_manifest()`. Thus the operator sees failure even though a production-
consumable artifact was already published. This is exactly the R1A state that
the correction was required to eliminate.

Required correction: derive and retain the exact canonical manifest bytes and
their digest before the no-replace rename, and perform no new fallible
canonicalization/readback/finalization operation after publication that can
change a successfully published export into a reported failure. Add a public
fault probe at this exact post-publication canonicalization seam (or remove the
seam so the probe is impossible) and prove that every reported failure leaves
no final production-consumable bundle.

=== H004-R1A -- Success-output failure can still follow final publication

Classification:: *carried requirement* (`R1A`)

H003 correctly derives `manifest_digest` before `_rename_no_replace()` and
performs no later manifest read, serialization, hashing, permission change, or
cleanup. After the final directory becomes production-consumable, however,
`_export_salvage()` still writes its multiline success output. Python output
is fallible. An `OSError` from that `print()` propagates to `main()`, which
reports `OPERATOR ERROR` and returns 2 without invalidating the already-final
bundle.

The direct probe established the complete public effect: return code 2, final
bundle present, and production manifest consumer acceptance. The H003
regression injects readback and canonicalization faults, but it does not inject
the remaining success-output fault. Consequently the command still violates
R1A's explicit rule that no fallible operation after final publication may
make the command appear to have failed and that every reported failure must
leave no production-consumable artifact at the requested destination.

Required correction: make success-output failure incapable of changing a
completed publication into a reported command failure, without moving a
truthful success claim before publication or weakening the fail-closed behavior
of any pre-publication fault. Add a public probe which injects the success-
output failure after the final rename and proves the command does not report
failure while retaining a consumer-valid final bundle.
