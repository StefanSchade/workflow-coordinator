== Core idea

As WFC's governance and wire contracts (Commission `intent.yaml`,
WorkItem/Profile/Policy bundles, Finding/Result wire schemas, and similar
artifacts) evolve, archived instances accumulate in
`workflow-coordinator-run-evidence` and `cold_storage/` with no documented
way to identify, after the fact, which schema/semantic contract revision and
which implementation revision were current when a given artifact was
produced. A bounded *identification* mechanism should let a later reader
determine both facts for any archived artifact, sufficient to reconstruct the
artifact's original intended meaning without needing current code to execute
or interpret it directly.

== Non-goals

This FTR explicitly excludes:

* long-term executable backward compatibility;
* parallel support for multiple old contract versions at runtime;
* migration infrastructure;
* a general version-management framework;
* any 0.1.0b1 release requirement; and
* designing or implementing any versioning mechanism in this record -- this
  record is documentation only.

== Activation criterion

Revisit only when a concrete need arises to interpret an archived artifact
under a contract revision the current code no longer matches -- for example,
when a governance or wire `schema_version` first advances past its current
pinned value and an old archived instance must still be read with confidence
in its original meaning.
