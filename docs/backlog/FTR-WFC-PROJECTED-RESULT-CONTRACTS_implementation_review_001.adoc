== Verdict

*CHANGES_REQUIRED; route `correction`.*

The implementation itself establishes the intended P1 infrastructure:
`ResultContractKind` is a provider-neutral closed identity;
`select_result_contract()` reads only admitted phase/profile/Run facts and
uses no phase-key string; the version computation is centralized in
`result_contract_version()`; and the former inline computations in both
`vertical.py` and `reducer.py` no longer survive.  The vertical boundary puts
the selected kind on `AgentExecutionRequest`, and `CodexCliAdapter` rejects a
kind it does not support before it builds or launches a provider command.

New accepted Hops retain both the selected kind and selected wire version.
`Hop.compact()` preserves them, serialization parses them as optional closed
fields, and the reducer uses a persisted complete pair rather than deriving a
new-Hop identity from a subsequently changed profile.  A missing half-pair or
an unsupported pair fails closed; a no-pair historical Hop retains the legacy
selector path.  No P2 strict result types, Finding-authority change,
provider-registry work, prompt change, or operator/Harness work was added.

The candidate cannot yet be accepted because its tests omit several explicit,
load-bearing P1 coverage obligations.  Passing current tests do not replace
