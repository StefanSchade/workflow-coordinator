== 1. What P3 decides

WFC is already installable and its artifacts are already tidy, so P3 is not a
build-out: seven contract decisions, eight human actions the Operator cannot
perform, three packages that make the contract *checkable*, and one separate
consumer-qualification package. Two verified facts set its shape: WFC's required
suite *cannot* run on a hosted runner as the reference's does, and WFC needs *no
repository secret* at all.

== 3. Release-contract decisions

[[c1]]C1 — Versioning scheme and the tag:: Static `version`, tag `v<version>`,
preflight asserting `tag == "v" + version`. *Recommendation: publish `0.1.0b2`,
not `0.1.0b1`* — the latter is the identity the built artifacts and
`test_bp1_identity.py:41` already assert, and the brief reserves `v0.1.0b1` for
the separate Beta-closure decision. The bump costs one line and one test
literal.
[[c2]]C2 — What an artifact contains, and must not:: Wheel: the
`workflow_coordinator` package (`.py` files plus exactly the four reviewed
resource texts) and `*.dist-info`. Sdist: `pyproject.toml`, `setup.cfg`
(setuptools writes it into the archive; no such file is tracked, so the entry is
not a mistake), `PKG-INFO`, `README.md`, `LICENSE`, `src/**`. Forbidden by name
in both: `docs/`, `tests/`, `governance/`, `project_memory/`, `.wfc/`,
`scripts/`, `requirements/`, `tmp/`, `build/`, any `*.ods`, any Evidence or Run
artifact. *Recommendation:* fail on anything *unlisted*, not only on the
forbidden list, so a new top-level directory cannot leak in silently.
[[c3]]C3 — The install check from a clean environment:: *Recommendation:* install
the *built artifact* into a fresh venv and run `wfc --help` and
`wfc --version --json` from a directory *outside* the checkout, asserting the
reported version equals the tag and `source_commit` is `null`. The suite already
proves the mechanism, so the release adds only the outside working directory and
that assertion.
[[c4]]C4 — Release notes:: *Recommendation:* preflight fails when the tag has no
matching section or its heading still says `planned`. Content for the first
release: what changed since Beta, the limitations the consumer quickstart already
enumerates, and the one qualified platform profile.
[[c5]]C5 — Version-pinned documentation:: *Recommendation: publish no HTML for
the first release.* Link documentation from `README.md` by absolute, tag-pinned
repository URL, keep the strict render as a gate, revisit Pages when a second
consumer exists. Depends on <<md3,MD-3>>: tag-pinned URLs are useless while the
repository is private, which is the one case where a Pages repository or a docs
subset in the sdist becomes necessary — reopening <<c2>>.
[[c6]]C6 — What runs on a hosted runner:: *Recommendation:* everything in E3's
`check` job — but *not* the required suite, which would need a verified bundle
for that host and a reviewed profile with its own dependency-closure review, for
a gate the qualified host already gives. The release record names the host and
the suite result, so a green runner is never mistaken for acceptance.
[[c7]]C7 — Distribution destination:: *Recommendation:* TestPyPI once as a
rehearsal, then PyPI, both through a Trusted Publisher with no stored token, plus
a GitHub Release carrying the same two artifacts. Publication is irreversible —
PyPI refuses to re-upload a version — so the rehearsal makes the first real
upload safe.

== 4. Actions that need human access

The Operator cannot and will not perform these. Each is separable: a package can
be completed and accepted while its matching human action is still open.

H1 — repository visibility (before <<c5>>, E1):: Decide and set the visibility of
`StefanSchade/workflow-coordinator`, read today through a read-only *deploy key*
from the reference's CI; such a key fits either visibility, so <<md3,MD-3>>
settles it, not this observation.
H2 — index project and publisher (before E3, first publish):: Create the PyPI and
TestPyPI project and its Trusted Publisher entry (publisher GitHub Actions,
owner, repository, workflow filename, environment); confirm the name
`workflow-coordinator` is available. No token is created.
H3 — repository settings (before E3):: Enable GitHub Actions, accept its minute
consumption, settle the Dependabot alert/update setting once.
H4 — Pages, only if <<c5>> is reversed (a later package):: Create the Pages
repository, generate the deploy key pair, store the private half as a secret, set
branch and folder.
H5 — the tag (before first publish):: Create and push the annotated release tag
on `main`.
H6 — publication (<<g8>>):: Authorize the irreversible publication; verify the
index page and the Release.
H7 — consumer access (before Q1):: Provide a clean `spreadsheet-handling`
checkout, an authenticated provider CLI for it and its one committed check
command; confirm its Git config carries no clean or process filter (git-lfs),
which WFC refuses on commit.
H8 — disposition (<<g8>>):: Disposition the qualification outcome and the release
decision.

== 5. Execution packages

Three Commissions in order, each `robust@v1` with worker plus independent
review. Budgets follow the 32 archived Beta Runs: 126 Hops, 18 `completed`, 10
`awaiting_human`, 3 `reconcile_required`, 1 budget-exhausted, 31 of the 126 Hops
`correct` — one correction cycle is the norm. This planning Run itself was
authorized at 12 Hops.

[[e2]]
=== E2 — Release preflight and artifact audit

Scope:: `scripts/wfc_release_check.py` (new), `scripts/wfc_dist_audit.py` (new),
`tests/architecture/test_offline_distribution.py`,
`tests/unit/test_release_tooling.py` (new), `Makefile`,
`docs/developer_guide/ch04_release_management.adoc`, `README.md`.
Hop budget:: 8 — two standard-library tools (one script with two subcommands is

Dependencies:: E1 accepted — its chapter is the specification both tools
implement.
Acceptance:: `wfc_release_check.py` is read-only, performs no writing Git
operation, and exits 1 on each of: not on `main`, dirty tree, local branch out of
sync with `origin/main`, HEAD or named tag unreachable from `origin/main`,

`wfc_dist_audit.py` takes the two artifact paths and fails on any entry outside

[[e3]]
=== E3 — The pipeline

Scope:: `.github/workflows/release.yml` (new),
`docs/developer_guide/ch04_release_management.adoc`.
Hop budget:: 6 — one workflow file whose every step is an already-existing
command, plus the chapter's CI section.
Dependencies:: E2 accepted (the workflow calls its targets); H2 and H3 for the
publish job to be *exercised*, though the file can be authored and the check job
can run without them.
Acceptance:: The `check` job runs on every push to `main` and on `v*` tags:
lint, format-check, the documented partial subset, `python -m build`,
`make dist-audit`, <<c3>>'s clean-venv install smoke, <<g5>>'s strict render and
`make release-check`. The `publish` job runs on `v*` only, needs `check`,
elevates only `id-token: write`, re-runs both checks before uploading and uses
the PyPA publish action. Top-level `permissions: contents: read`; no secret is
referenced anywhere in the file; `make wfc-setup`, any sibling-checkout
assumption and any provider credential are absent. The chapter records which
host runs the required suite and why the runner does not.
Non-goals:: No `publish-docs` job, Pages repository, Python or architecture
matrix, scheduled or non-release workflow, or Dependabot configuration; no
attempt to run the required suite on the runner.

== 6. Final consumer qualification

A separate package with its own gate: *not* the BP9 neutral installed-wheel
qualification and *not* release-engineering readiness. E1–E3 and <<gates>> can be
green while Q1 fails, which is the point of keeping them apart.

[[q1]]
=== Q1 — One real WorkItem in `spreadsheet-handling`

Prerequisites:: A release candidate built from a tagged commit and installed
*from the artifact* into an isolated environment, never an editable checkout of
this repository; H7 for access, provider CLI and check command; a *fresh*
checkout, because one authorized lifecycle per checkout is the Beta contract
(ADR AD-5) and a reused checkout refuses every later `wfc run`.
Scope of the Run:: One bounded change in the *consumer* repository, chosen close
to execution time, with a real test assertion. No WFC repository change belongs
to Q1; defects it reveals become their own records.
Acceptance:: The Run reaches a terminal state through the installed product path
— `init`, `plan`, `run --yes`, `status`, `report`, archive — with the Commission
and execution-envelope digests re-derived; the consumer repository carries a real
modification inside the authorized scope and nothing outside it; its own check
command is the trusted evidence and passes; the independent review is real and
dispositions itself; archive facts match the actual outcome; and the record names
the candidate version, the implementation tree digest and the provider models.
Stop rules:: Stop and report, never repair, when the pre-launch baseline probe
refuses (`refused_probe`, exit 23 — it consumes the checkout's one lifecycle, so
retry needs a fresh checkout); the check command exceeds the 900-second evidence
cap; WFC refuses the commit over a clean or process filter; or the Run stops
`awaiting_human`. A truthful stop is a *valid* outcome dispositioned by the
maintainer (H8): neither a failure to work around nor silent satisfaction of the
gate.
Explicitly not acceptance:: a passing fake-provider test, a green consumer CI run
alone, or a change contrived to produce a green Run.

[[q0]]
=== Option Q0 — the DMC resumption plan as a planning WorkItem first

The input:: The staged review ends already partitioned: treat its
ingress-fidelity defect (its R1) as a bug-level change with its own tests, write
the documentation slice separately, retire the family-cycle program as a
schedule. It names what WFC could support — "bounded execution and evidence
capture for R1" — and what must stay independent of WFC: the whole-suite gate,
per-push CI, the in-repository acceptance record and the ingress-rule decision.
For and against:: Genuine work the consumer's own review recommends, so not a
contrived demo; one document keeps blast radius near zero while still exercising
installation, the Front Door, authority checks, review and archive against a
foreign repository; and it surfaces H7's environment problems — filter config,
check-command runtime against the 900-second cap, scope ceiling — before a code
change depends on them. *Against:* it yields no test evidence and no regression
assertion, precisely what the qualification must demonstrate; as the gate it
proves less than it appears to.

*Recommendation: run Q0 as a rehearsal only, and leave Q1 as the gate.* Q0
produces the defect's bug record and acceptance-test sketch in the consumer
repository; Q1 then implements it with those tests. If access is the scarce
resource, skip Q0 and take the defect directly as Q1's subject. Either way the
review's remaining recommendations — a whole-suite gate and per-push CI, which
the consumer has neither of — stay outside WFC's scope and this plan's.

[[gates]]
== 7. Gates, risks, and what is not in this release

Every gate is release-blocking; there is no advisory class. Each is named as
*gate — owner — verification evidence*.

[[g1]]G1 Preflight clean — Operator:: branch, tree, topology, tag-equals-version,
notes frozen, README links absolute; `make release-check TAG=v<version>` exit 0.
[[g2]]G2 Required suite green on the qualified host — Operator::
`python -m pytest -q` with `WFC_TEST_INPUTS`/`WFC_TEST_PROFILE` set; the host and
profile recorded with the result.
[[g3]]G3 Both artifacts contain exactly the allow-list — CI and Operator::
`make dist-audit` exit 0 on the sdist and on the wheel.
[[g4]]G4 Clean-environment install and CLI identity — CI and Operator::
fresh-venv wheel install outside the checkout, `wfc --help`, and
`wfc --version --json` reporting the tag's version.
[[g5]]G5 Documentation renders strictly — CI::
`asciidoctor --safe-mode=safe -a assembled -o /dev/null --failure-level=WARN`
over the assembled books: exit 0, no output.
[[g6]]G6 Runbook rehearsed end to end, TestPyPI included, publishing nothing —
Operator:: a recorded rehearsal naming each step's outcome.
[[g7]]G7 Consumer qualification dispositioned — Maintainer:: the Q1 archive and
the review disposition.
[[g8]]G8 Release authorized — Maintainer:: explicit authorization recorded with
the tag; never inferred from a green job.

*Risks.*

R-1 The runner cannot run the required suite:: Verified, not speculative: the
profile compares the seed pip version exactly. *Mitigation:* <<c6>>; never
present the runner's partial subset as acceptance.
R-2 Static version drifts from the tag:: `test_bp1_identity.py:41` asserts the
literal `0.1.0b1`, so every bump touches a test. *Mitigation:* G1, plus that
literal named in C1's and E1's checklists.
R-3 Publication is irreversible, and the name may be taken:: PyPI refuses to
re-upload a version, a published version is never retagged, and name
availability is not checkable from a Run. *Mitigation:* H2 early; <<c7>> and G6.
R-4 A private repository makes tag-pinned links useless:: and an index-page
reader then sees four dead links. *Mitigation:* <<md3,MD-3>> precedes <<c5>>; if
the repository stays private, reopen <<c2>>.
R-5 Q1's environment refuses the Run:: filter config, the 900-second cap against
a large consumer suite, or one lifecycle per checkout. *Mitigation:* H7 measured
first; Q1's stop rules make each a reportable outcome.
R-6 Correction cycles consume the budget:: 10 of 32 archived Runs stopped
`awaiting_human`. *Mitigation:* the budgets include one correction cycle; a
second needs a successor Commission, not a raised ceiling.

*Not in this release.* Published HTML, a Pages repository, a `latest` alias and
their immutability machinery; any second repository; signing or provenance
attestation; a Python or OS matrix; ARM64 or a second qualified profile; conda,
Homebrew or a private index; Dependabot configuration; documentation inside the
artifacts; automation beyond the single workflow; a new workflow program or
kernel change (ADR AD-1 makes that release work of its own); lifecycle rotation
(AD-5).

*Rejected packages.*

A reviewed offline-input profile for a runner host:: The only way to run the
required suite in CI, at the cost of a dependency-closure review per runner
image, for a gate the qualified host already gives. Reopen only if that host
stops being available.
A separate README-link tool and bake procedure:: The reference needs a
substitution procedure because its URLs are versioned; WFC's rule is one
assertion inside `release-check`.
A test asserting the workflow matches the documented gates:: Parsing YAML to
restate prose, while missing the only interesting failure — a gate that passes
while proving nothing.
A release-automation Commission:: Tagging and publishing are H5 and H6 by
design; automating the irreversible step removes the human stop that matters.

[[decisions]]
== 8. Decisions only the maintainer can take

MD-1 — Distribution destination (<<c7>>):: *Recommendation: TestPyPI rehearsal,
then PyPI, plus a GitHub Release with the same artifacts*, through a Trusted
Publisher with no stored token. GitHub Releases alone avoids H2 but leaves
`pip install workflow-coordinator` unavailable — the quickstart's implied path.
MD-2 — The first published version (<<c1>>):: *Recommendation: `0.1.0b2`*,
leaving `v0.1.0b1` for the Beta-closure decision the brief keeps separate;
publishing `0.1.0b1` is coherent and cheaper, but spends a tag whose meaning the
maintainer reserved.
[[md3]]MD-3 — Repository visibility:: *Recommendation: public at the tag* — the
only option under which <<c5>>'s tag-pinned links work for a consumer, and it
removes the reference's need for a read-only deploy key to install WFC. Staying
private is coherent, but then a Pages repository (H4) or a documentation subset
in the sdist becomes necessary and <<c2>> must be reopened.
MD-4 — Version-pinned documentation publishing (<<c5>>):: *Recommendation: not
for this release.* The reference's Pages machinery is earned by three
repositories; WFC has one and no slide decks.
MD-5 — Must the required suite run on a hosted runner? (<<c6>>)::
*Recommendation: no* — the deviation most likely to be questioned later, so the
chapter records it as a decision with its reason, not as an omission.
MD-6 — The qualification subject, and whether Q0 runs first (<<q0>>)::
*Recommendation: Q0 as a rehearsal, then the review's ingress-fidelity defect as
Q1's subject* — a real regression assertion, a known reproduction, low blast
radius. Confirm the choice close to execution time; a consumer need that has
arisen by then outranks this one.
