Priority:: bounded Level-0 correction-strategy control
Date:: 2026-10-02
Source BUG:: `docs/backlog/BUG-WFC-CORRECTION-BLOCKING-SET-CARRYOVER.adoc`
Recorded now:: Preserve stable blocking-requirement identity while detecting a
bounded, semantically qualified pattern in which local correction repeatedly
leaves the same invariant open, then route through a pinned profile's finite
diagnosis and strategy-reframe path without granting acceptance or authority.

== Decision summary

WFC should implement convergence escape as an opt-in extension of its existing
Finding ledger and finite profile reducer. It should not add a second blocker
ledger, infer a root cause from a failure count, mutate the profile of a live
Run, or add a Level-1 planner.

An open blocking `Finding` remains the one authoritative correction obligation:
its Coordinator-allocated ID, invariant, blocking flag, state, evidence, and
existing gate-controlled lifecycle remain authoritative. A convergence-aware
gate marks a newly created open blocking Finding as a gate-owned correction
obligation. Correctors make structured coverage claims against that same ID;
independent evaluators record structured assessments against it. Coverage and
assessment records are attributed observations, not another semantic status.
A worker's `addressed` claim cannot resolve, supersede, or otherwise dispose the
Finding. Result-v2 reduction rejects a new open blocking Finding from every
agent role except an evaluator, so an admitted convergence-aware Run cannot
contain an untracked blocker.

The Core derives a convergence fact only from a semantically qualified cycle:
the corrector claimed the same open obligation `addressed`, and the next gate
kept it open while explicitly reporting a new counterexample to the same
invariant with new evidence. The count is per Finding and per accepted strategy
generation. A convergence-aware profile declares a finite qualified-cycle
limit, a normal correction route, and an escape route to a diagnosis phase.
When the limit is reached, the reducer deterministically substitutes the
profile-declared escape route for the normal correction route. The limit bounds
how long one correction strategy is repeated; it is not a correctness score
and never causes acceptance.

Diagnosis is normally read-only with respect to the subject artifact. It emits
a typed, agent-attributed classification plus prose and evidence references.
A later reframe phase proposes a structured correction-strategy revision, and
an independent strategy gate may accept only that strategy revision. Acceptance
of a strategy returns to correction with the original Findings still open and
a new strategy generation. One persisted escape event binds the complete
triggering ID/generation set through diagnosis, revision, assessment, and
exactly-once generation advancement. Only a later independent evaluation with
ordinary Finding disposition authority may close or supersede an original
obligation.

Existing schema-version-2 profiles retain their current bounded iterative
behavior. Convergence-aware profiles use a new closed schema-version-3 grammar
and remain pinned for the Run. A future Level 1 or maintainer may select such a
profile before commissioning a Run, but Level 0 neither discovers profiles nor
changes one at runtime.

This record is architecture-convergence input only. Its independent review may
make it accepted design authority, but neither this record nor that acceptance
implements the mechanism, establishes R1A's root cause, fixes R1A, closes the
source BUG, changes Runtime, or authorizes another Run. Product implementation
requires a separate explicit maintainer Commission.

== Empirical problem and the identity/convergence distinction

Runs 001 and 002 documented by the source BUG repeatedly carried the same broad
acceptance-matrix obligation while correction Hops fixed narrower defects. The
obligation was renamed at successive reviews and both Runs exhausted their Hop
budgets. Run 003 sharpened the task-level completion mandate, but related open
concerns were again renumbered and split across reviews. Those Runs show a
requirement-identity/carryover problem.

Run 004 deliberately held identity constant. `R1B`, `R2`, and `R3` remained
visible under the same names and were repeatedly confirmed addressed. `R1A`
also remained one carried requirement at H002, H004, and H006. H003 closed the
post-publication canonicalization counterexample raised at H002; H005 closed
the synchronous success-output counterexample raised at H004. Fresh reviewers
then found progressively deeper counterexamples to the same broad R1A
invariant, ending with deferred stdout flush failure at H006. The Run exhausted
6/6 Hops with only R1A open.

That evidence separates two problems:

. stable identity and complete carry-forward of a known obligation; and
. failure of repeated local correction to close the broader invariant even
  when identity and carry-forward are preserved.

Stable identity is necessary input to this mechanism, not its convergence
answer. R1A supplies empirical evidence for the second problem and is reserved
as later dogfood. This design does not assume whether R1A reflects requirement
ambiguity, a solution-model mismatch, insufficient fault exploration, or any
other root cause, and it proposes no R1A implementation change.

== Boundary and ownership (question A)

=== Generic WFC Core

Core owns only domain-neutral mechanics:

* Coordinator allocation and validation of stable Finding IDs;
* the authoritative Finding lifecycle and existing disposition authority;
* correlation, role/phase validation, persistence, and replay of typed coverage,
  evaluation, diagnosis, and strategy records;
* derivation of per-Finding, per-strategy convergence facts from those records;
* validation of the closed convergence-profile grammar; and
* deterministic route substitution, existing preemption precedence, budget
  enforcement, prompt projection, and fail-closed behavior.

Core does not decide whether a curriculum objective is pedagogically complete,
a business-analysis requirement is evidenced, or a software behavior is safe.
Terms such as refactor, cyclomatic complexity, Python, unit test, and code smell
are not Core vocabulary.

=== Workflow profile / workflow strategy

The pinned profile declares whether convergence support is enabled, which
phases are corrector, evaluator, diagnosis, reframe, and strategy gate, the
finite qualified-cycle limit, and the already-declared normal and escape route
keys. It declares topology and a bounded strategy choice; it contains no
expression language, executable condition, callback, computed graph, or
user-defined program.

=== Domain work semantics

The domain defines the substance of an invariant, what counts as a
counterexample, what evidence is meaningful, and what a revised correction
strategy means. Those statements remain agent-attributed semantic judgments
subject to the profile's independent evaluation. They do not become
Coordinator-trusted merely because Core stores them.

=== Project policy, evidence, and conventions

RepositoryPolicy and other independently admitted governing inputs continue to
own path ceilings, actions, evidence commands, trust constraints, and local
conventions. A project may specialize task prose or evidence, but may not add
executable convergence logic to YAML or reinterpret a typed Core record.

=== Task payload and acceptance requirements

The WorkItem/task names the artifact, domain requirements, acceptance
obligations, and any relevant historical evidence. Task prose can narrow work
and guide semantic judgment. It cannot grant Finding disposition, expand
scope, change routing precedence, or alter the pinned profile.

=== Future Level 1

A future Level 1 may select a WorkItem/slice, profile, execution binding, and
other inputs within separately governed authority before launching Level 0.
That selection is outside this mechanism. This record adds no planner,
registry, automatic profile discovery, workflow invention, provider router, or
dynamic profile mutation.

== One blocker ledger, with structured correction facts (question B)

=== Chosen representation

Extend existing Finding state; do not introduce a distinct
`BlockingRequirement`, `CorrectionCoverage` status ledger, or second acceptance
model. `Finding` already has the required load-bearing semantics: a stable
Coordinator-owned identity, an immutable invariant, blocking state, evidence,
and authority-controlled resolution/supersession. Duplicating those fields
would permit the two ledgers to disagree about whether work is blocking.

For Run wire version 3, add nullable metadata to each Finding:

----
CorrectionObligation {
  owner: gate | human
  introduced_by_hop: Hop ID
}

Finding.correction_obligation: CorrectionObligation | null
----

In a convergence-aware evaluator phase, a gate-created, open, blocking Finding
is automatically tagged as a gate-owned correction obligation. An ordinary
Finding or every Finding in an older Run has `null` metadata and does not
silently become convergence-tracked. A future explicit human ledger operation
may create a human-owned obligation; no agent result may claim human ownership.

For a result-v2 convergence Hop, the reducer rejects every new open blocking
Finding unless the source role is `evaluator`. An admitted evaluator-created
open blocker is always tagged; the evaluator cannot opt out. Corrector,
diagnosis, reframe, and strategy-gate results therefore cannot create an
untracked blocker, even though ordinary result-v1/profile-v2 Finding creation
remains unchanged. New non-blocking informational Findings retain existing
semantics and do not become correction obligations. The v3 Run validator also
requires every open blocking Finding to carry valid correction-obligation
metadata. Because old Runs never upgrade to v3, this invariant neither adopts
nor fabricates ownership for a legacy blocker. An explicit human creation path
must assign `owner: human` atomically; there is no later agent-driven adoption
transition.

The existing Finding `state` remains the only lifecycle state. The metadata has
no open/closed field. The invariant remains immutable. Existing `successor_ref`
continues to record supersession. For tracked obligations the successor must be
an existing tracked obligation or an open blocking Finding created by the same
evaluator result and atomically tagged as one. A bounded transaction-local
reference makes the latter case representable without predicting the next
Coordinator ID.

Result v2 extends each new-Finding delta with nullable `local_ref`. A non-null
value must match `N[1-9][0-9]*`, be unique within that result, and have meaning
only during that reduction. An existing-Finding supersession delta may use
either a concrete `Fxxx` ID or `local:Nxxx` as `successor_ref`; no other field
may contain a local reference. Reduction is atomic and ordered:

. validate all new deltas, local-reference syntax/uniqueness, authority, and
  convergence-role rules without changing Run state;
. allocate concrete Finding IDs to valid new deltas in their result order and
  build the local-to-concrete map;
. resolve every local successor reference, rejecting missing references or a
  target that is not a same-result open blocking tracked obligation;
. validate every resulting supersession edge against the complete prospective
  Finding graph, rejecting self-reference and direct or transitive cycles; and
. apply the concrete new and existing deltas as one transaction.

Duplicate or unknown local references, references to a non-blocking/untracked
new Finding, concrete unknown IDs, ID prediction in `local_ref`, and every
self/cycle case reject the whole result without consuming IDs or changing
state. Persisted Findings and Hop summaries contain only the resolved concrete
IDs; `local_ref` remains result evidence, not durable identity. Replay performs
the same validation against the persisted concrete graph and never reallocates
or reinterprets a local token.

=== Result records

Structured result version 2 adds five explicit fields. Strict output schemas
require them on every v2 result, using empty arrays or `null` when inapplicable:

----
coverage_claims: [
  {
    finding_id: string,
    disposition: addressed | blocked | escalation,
    evidence_refs: [string]
  }
]

convergence_assessments: [
  {
    finding_id: string,
    correction_hop_id: Hop ID,
    result: closed | carried_new_counterexample |
            carried_unmet | residualized | superseded,
    evidence_refs: [string]
  }
]

diagnosis: DiagnosisReport | null
strategy_revision: StrategyRevision | null
strategy_assessment: StrategyAssessment | null
----

The last three records are defined below. These values are typed annotations
on the authoritative Finding history, never substitute Finding states.

=== Ownership and validation

Introduction:: Only an independent gate in a convergence `evaluator` phase, or
an explicit human ledger operation, may introduce a tracked correction
obligation. The Coordinator allocates its `Fxxx` ID. Newly discovered blockers
receive new IDs; they are never appended as counterexamples to an unrelated
obligation merely to reach a goalpost.

Coverage:: A `corrector` phase must submit exactly one coverage claim for every
open tracked obligation projected into that Hop. It may not claim an unknown,
closed, or superseded ID. `addressed` permits the declared evaluation route.
`blocked` must accompany `outcome: blocked`; `escalation` must accompany the
existing human/escalation fields. Neither permits a false rereview request.
Coverage claims add attributed evidence but never mutate Finding state.
For a tracked obligation, a corrector must use this claim record rather than a
same-state Finding delta; this keeps worker evidence from looking like an
authoritative gate disposition.

Carry-forward and evaluation:: The next `evaluator` must assess every open
tracked obligation that entered the correction Hop under the same ID. `closed`
is valid only with an authorized Finding delta resolving that ID;
`residualized` only with an authorized residual delta leaving that ID residual
and non-blocking;
`superseded` only with an authorized superseding delta and valid successor;
both carried values require the post-reduction Finding to remain open and
blocking. `carried_new_counterexample` additionally requires a non-empty new
evidence reference not already present before the evaluator Hop.
`carried_unmet` means the same obligation is still unmet without asserting a
new counterexample. Every assessment is cross-checked against a corresponding
existing-Finding delta: a carried assessment uses the same open state, while
closure, residualization, and supersession use their matching lifecycle state.
The gate may also create new IDs in the same Hop.

Closure, residualization, and supersession:: Only existing Finding disposition
authority may resolve, residualize, supersede, or reopen. A residualized
obligation remains durably represented under its original ID but is no longer
open or blocking and is not an escape candidate. In particular, a corrector's
`addressed` record is never translated into `resolved`. A diagnosis,
strategy-revision author, strategy gate, counter, or route substitution also
has no Finding disposition authority. The initial `repeated_counterexample_v1`
protocol does not admit agent-driven reopening of a tracked obligation: profile
validation rejects `reopen` authority on its evaluator phases. A later protocol
would need explicit generation semantics before allowing it. Existing simple
profiles retain current reopen behavior, and an authorized human may introduce
a new human-owned obligation instead of silently resetting an old generation.

Evidence and provenance:: Finding evidence remains in the Finding ledger.
Coverage and evaluation records retain their own references, source Hop, and
attribution in the Hop summary. Coordinator trust extends only to correlation,
schema validation, accepted-Hop provenance, role, and deterministic
derivation. The claim, classification, prose, and cited semantic content remain
agent-attributed unless independently supplied by an existing trusted evidence
mechanism.

== Convergence facts and bounded goalpost (question C)

=== Qualified local-correction cycle

For one tracked Finding and one strategy generation, a cycle is qualified only
when all of the following are mechanically observable in accepted state:

. a `corrector` Hop made an `addressed` coverage claim for that open Finding;
. the next applicable `evaluator` correlated its assessment to that correction
  Hop and the same Finding ID;
. the evaluator recorded `carried_new_counterexample` with a previously absent
  evidence reference; and
. after the evaluator's authorized Finding delta, the Finding is still open and
  blocking.

A newly allocated blocker, a renamed prose label, a worker `blocked` or
`escalation` claim, evidence failure, an uncorrelated record, `carried_unmet`,
or a cycle from an earlier strategy generation does not increment this count.
History is retained even when it does not qualify.

Core derives and projects:

----
ConvergenceFact {
  finding_id: string
  strategy_generation: non-negative integer
  qualified_cycle_count: non-negative integer
  qualified_cycle_limit: positive integer
  goalpost_reached: boolean
  source_evaluator_hops: [Hop ID]
}
----

`goalpost_reached` means only that the pinned normal strategy has consumed its
declared allowance of semantically qualified local-correction cycles for that
still-open obligation. It does not mean the requirement is false, correct,
resolved, impossible, or accepted, and it does not diagnose why convergence
failed.

=== The four independent dimensions

Autonomous Hop budget:: A Run-wide ceiling on provider invocations. Every
charged Hop continues to consume it. Escape neither refunds nor extends it.

Semantic acceptance:: A gate's authorized complete route and Finding
dispositions. No counter or goalpost can synthesize acceptance.

Correction-obligation lifecycle:: The ordinary Finding state machine for each
stable ID. It can remain open across diagnosis and reframe.

Convergence-strategy goalpost:: A per-Finding, per-generation fact that limits
repetition of one local correction strategy. It can be true while budget
remains and while other obligations are closed, new, or below their limits.

The initial `repeated_counterexample_v1` profile protocol permits a declared
limit from 2 through the Coordinator hard Hop maximum. Two is the minimum
because one counterexample after one correction is ordinary falsification;
the second establishes repetition under the same strategy. This is not the
rule “three failures imply root cause.” A profile may choose a larger finite
limit for its domain and budget, but no value turns the count into a quality or
correctness metric.

== Finite profile grammar and deterministic escape (questions D and H)

=== Opt-in schema-version-3 profile

Schema-version-2 profile parsing and behavior remain unchanged. A
convergence-aware profile uses version 3 and one closed top-level declaration:

[source,yaml]
----
convergence:
  protocol: repeated_counterexample_v1
  qualified_cycle_limit: 2
----

Each phase has exactly one closed role:

----
convergence_role: none | corrector | evaluator |
                  diagnosis | reframe | strategy_gate
----

An evaluator additionally declares two keys that must name existing finite
routes on that phase:

[source,yaml]
----
convergence_role: evaluator
normal_correction_route: correct
escape_route: diagnose
----

The normal route must be `goto` a corrector. The escape route must be `goto` a
diagnosis phase. The escape route is Coordinator-reserved: it is omitted from
agent `permitted_routes`, and an agent that requests it directly is rejected.
Corrector evaluation routes must target an evaluator. Diagnosis, reframe, and
strategy-gate edges must form declared finite routes; the validator does not
compute or generate phases. Evaluator phases must be gate reviews with the
Finding operations needed by their advertised lifecycle choices. Profile
validation requires diagnosis and reframe to be non-review phases and requires
a strategy gate to have an empty Finding-disposition authority list. The
initial protocol rejects `reopen` authority on evaluator phases because it has
no reopen assessment or implicit generation-reset rule. It rejects missing
roles, invalid route targets, incoherent authority, unbounded limits, or mixed
v2/v3 shapes.

This is finite declarative data. There is no YAML predicate such as “if count
greater than N,” embedded source, template, expression, plugin callback, or
dynamic route creation. Core alone defines `repeated_counterexample_v1` and
derives its facts; the profile chooses the bounded constant and finite edges.

=== Reducer precedence

The new decision point preserves current fail-closed ordering:

. validate correlation/profile/state and capture semantic stop observation;
. apply mechanical, repository, policy, evidence-command, and human-authority
  preemptions exactly as today;
. reject failed results, scope-change attempts, unknown/forbidden routes, and
  malformed convergence records;
. atomically apply authorized Finding deltas and validated annotations;
. apply the existing required-evidence-failure route, when configured;
. if and only if an evaluator returned `changes_required`, requested its
  declared normal correction route, and the post-Hop facts contain at least
  one still-open goalpost Finding, substitute the declared escape route;
. apply the existing Hop-budget and supervisor checks to the selected route;
  then apply it normally.

The Hop records both `requested_route` and `applied_route`, plus
`route_reason=convergence_escape:<sorted Finding IDs>` when substitution
occurs. It also persists the immutable structured event that later phases must
correlate:

----
ConvergenceEscape {
  evaluator_hop_id: Hop ID
  triggers: non-empty [
    {
      finding_id: Finding ID
      strategy_generation: non-negative integer
    }
  ]
}
----

The evaluator Hop ID is the escape-event identity. `triggers` is sorted by
Finding ID, contains exactly once every still-open Finding whose derived
goalpost caused this substitution, and records the generation in which each
goalpost was reached. The reducer, not the agent, creates this event; the agent
cannot submit or edit it. Sorting IDs makes multiple-requirement behavior
deterministic. If the relevant Finding was resolved, residualized, or
superseded in the evaluator Hop, it is not a goalpost candidate and escape does
not occur. If several obligations are open but only one reached the goalpost,
the escape event names only that ID while all others remain in the ledger. A
newly discovered blocker begins with zero qualified cycles under its own ID.

Escape happens before the ordinary route's budget check but does not override
that check. If no Hop remains to enter diagnosis, the existing
`autonomous_hop_budget_exhausted` stop controls. A later commissioning profile
must therefore allocate a finite budget that can contain its advertised path.

== Diagnosis semantics (question E)

A `diagnosis` phase analyzes why the normal strategy is not converging. It is
normally non-mutating with respect to the subject artifact: its authorized
actions omit `edit` and `commit`, its subject scope is read-only, and its
durable artifact is normally `none`. A profile may authorize a separate
diagnostic record artifact, but that does not authorize subject mutation. Any
exception would need an independently commissioned scope/action grant and is
not part of `repeated_counterexample_v1`.

Result v2 permits exactly one report:

----
DiagnosisReport {
  escape_hop_id: Hop ID
  finding_ids: non-empty [Finding ID]
  classification: requirement_ambiguity |
                  problem_solution_model_mismatch |
                  decomposition_mismatch |
                  evidence_gap |
                  capability_gap |
                  authority_scope_gap |
                  regression_chain |
                  unknown
  analysis: non-empty string
  evidence_refs: [string]
}
----

`escape_hop_id` must identify the current unconsumed `ConvergenceEscape` event,
and `finding_ids` must equal its complete sorted trigger-ID set: no subset,
addition, duplicate, or reordering is valid. Every ID must still be open and
tracked at its recorded generation. The closed taxonomy is deliberately
domain-neutral. Prose supplies nuance; the enum permits bounded comparison and
routing context. The Coordinator trusts the report's correlation, schema,
phase provenance, and stored bytes. It does not trust the diagnosis as
established fact and grants no authority from its classification.

Diagnosis does not resolve Findings, accept the subject, reset a count, or
select a new profile. If the report identifies missing authority, scope,
visibility, trust, public-surface judgment, capability, or prerequisite work
not already granted, the phase must use the existing matching escalation and
human stop. Merely choosing `authority_scope_gap` does not make an otherwise
unauthorized reframe route valid.

== Strategy reframe and return (question F)

A `reframe` phase proposes how to change the correction strategy, not the
truth of the requirement. Its v2 result may contain:

----
StrategyRevision {
  escape_hop_id: Hop ID
  diagnosis_hop_id: Hop ID
  finding_ids: non-empty [Finding ID]
  kind: clarify_requirement_interpretation |
        change_problem_solution_model |
        redecompose_work |
        change_evidence_strategy |
        use_authorized_capability |
        address_regression_chain |
        other
  plan: non-empty string
  evidence_refs: [string]
}
----

The revision must reference the current escape event and a successfully reduced
diagnosis Hop correlated to that event. Its IDs must exactly equal the diagnosis
and escape trigger set, and all referenced Findings must remain open at the
escape event's recorded generations. `use_authorized_capability` means only a
capability already present in the pinned envelope; it cannot request or imply a
grant. A plan that needs more authority must escalate instead.

The next `strategy_gate` independently evaluates the proposed revision:

----
StrategyAssessment {
  escape_hop_id: Hop ID
  diagnosis_hop_id: Hop ID
  revision_hop_id: Hop ID
  finding_ids: non-empty [Finding ID]
  result: accepted | changes_required
  evidence_refs: [string]
}
----

The assessment must reference the current escape, its successfully reduced
diagnosis, and the current revision Hop. Its IDs must exactly equal the
immutable escape set;
the revision must be the latest revision on that diagnosis path and must not
already have a terminal accepted assessment. This gate accepts or rejects only
the strategy proposal. It carries no Finding disposition authority by
implication and cannot complete the Run. On `accepted`, its declared finite
route returns to a corrector; Core consumes that escape event and derives
generation `g + 1` exactly once for every `(Finding ID, g)` trigger pair. The
prior counts and all events remain historical, while each qualified count in
the new generation starts at zero. Findings that did not trigger the event
retain their existing generations and histories. On `changes_required`, the
profile routes to reframe again without consuming the event or advancing any
generation.

Core rejects the complete result atomically if any chain reference is stale,
unknown, duplicated, omitted, added, already consumed, or points to a Finding
that is now closed, residualized, superseded, or no longer at the event's
recorded generation. A rejected result changes no generation. There is at most
one unconsumed escape event on the active finite diagnosis/reframe path, so an
old event cannot be reused to reset a below-limit or unrelated Finding.

The intended finite sequence is therefore:

----
normal correction -> independent evaluation
  -> goalpost -> diagnosis -> reframe -> independent strategy evaluation
  -> normal correction of the original still-open Finding
  -> independent requirement evaluation
----

Neither diagnosis nor strategy acceptance is semantic acceptance of the
subject. Only the final ordinary evaluator can resolve or supersede the
Finding and take a complete route.

== Authority and trust boundary (question G)

Convergence mode changes strategy, never authority. Every phase remains
bounded by the WorkItem, RepositoryPolicy, profile, execution boundary, and
existing Finding authority. The mechanism cannot add a path, action, evidence
command, trust label, provider capability, network grant, public/API decision,
or governance decision.

The trust distinctions in
`FTR-WFC-EXECUTION-TRUST-BOUNDARIES.adoc` remain controlling. In particular:

* an agent diagnosis is not an authority source;
* a reframe cannot self-authorize broader visibility, mutation, execution, or
  egress;
* a strategy gate cannot approve a public surface or governance decision it
  was not granted;
* prompt instructions and committed agent output are not technical
  containment or authority provenance; and
* existing `scope`, `semantic_authority`, `public_surface`, `trust_boundary`,
  `prerequisite`, and `operational` escalation stops remain fail closed.

If the only plausible next strategy exceeds the pinned envelope, the Run
stops. A separately authorized successor WorkItem/Run may later act, using the
already designed semantic-continuation mechanism where applicable. Convergence
escape is not “root-cause mode” with privileged powers.

== Coexistence and profile selection (question H)

The existing simple `correct -> rereview -> {accept, correct}` profile remains
useful and unchanged. It is smaller, has less structured-output overhead, and
is appropriate when the commissioned work is likely to converge within a few
cycles or when ordinary Hop-budget exhaustion is the desired boundary.

A convergence-aware profile is a separate later governance artifact. Profile
choice is external commissioning policy (and potentially future Level-1
policy), made before `new_run()`. The admitted profile ID, revision, bytes, and
topology stay pinned. Level 0 never upgrades a simple Run, injects diagnosis
phases, discovers an alternative profile, or mutates topology in response to
history.

== Persistence, wire, replay, and compatibility (question I)

=== Profile and structured-result wire

Profile schema version 2 retains its exact current closed shape and semantics.
Version 3 requires the closed convergence declaration and phase roles above.
Unknown protocol names, keys, roles, or route combinations fail parsing.

The structured-result envelope gains version 2 alongside version 1. Version 1
retains its exact existing result shape and remains the contract for ordinary
v2 profiles. A v3 convergence profile dispatches only result v2, whose exact
shape adds the five fields above and the bounded `local_ref` extension to new-
Finding deltas. The prompt and adapter project the selected contract explicitly;
adapters strictly validate both the envelope version and the phase-appropriate
result version. No optional/unknown-field weakening of v1 is permitted.

=== Run and Hop wire

New convergence-aware Runs use Run schema version 3. Its closed shape adds:

* nullable `Finding.correction_obligation` metadata;
* Hop-summary `phase`, `requested_route`, `route_reason`, coverage claims,
  convergence assessments, diagnosis, strategy revision, and strategy
  assessment;
* the Core-created `ConvergenceEscape` event, including its evaluator-Hop
  identity and exact sorted `(Finding ID, strategy generation)` trigger set;
  and
* no persisted `goalpost_reached` boolean or mutable strategy counter.

Goalposts, generations, and counts are pure derived projections from the
ordered Hop/Finding history plus the pinned profile. Avoiding a persisted
mutable counter prevents replay drift and makes the event source inspectable.
The escape event is not a mutable counter: it is an immutable routing decision
and correlation anchor derived and recorded at the evaluator boundary. An
accepted, exactly correlated strategy assessment is the sole event from which
the next generation is derived.
`run.json` remains authoritative; result files remain invocation evidence.

The Run parser accepts three closed versions:

* v1: the historical pre-semantic-stop shape;
* v2: the current shape with `semantic_stop` and `successor_provenance`; and
* v3: the new convergence-capable Finding/Hop shape.

Read-only load/status/replay of v1 or v2 preserves its exact wire shape and
bytes and synthesizes no obligation metadata, claims, assessments, diagnosis,
strategy, generation, count, or goalpost. In memory, absent new values are
empty/null only as compatibility representation, never historical facts.
There is no in-place v1/v2-to-v3 migration: an existing Run's pinned v2 profile
cannot gain convergence semantics. Existing legitimate v1 transitions retain
the current atomic v1-to-v2 rule, and v2 transitions remain v2. Only `new_run()`
against an admitted v3 profile creates Run v3. A later desire for convergence
on historical work therefore requires a separately commissioned fresh Run;
no prose or historical result is mined to backfill state.

The serializer must omit the new nested Finding and Hop fields when writing v1
or v2, just as it currently omits v2-only Run fields when round-tripping v1.
An injected v1-to-v2 write failure continues to preserve the exact v1 file.

=== Checkpoint, summary, and prompt projection

Checkpoint and operator summary project, but do not own:

* the complete open tracked-obligation set;
* the latest coverage and evaluation per ID;
* derived per-generation convergence facts and source Hop IDs;
* each immutable escape-Hop identity, its exact trigger ID/generation set,
  whether it is unconsumed or consumed by an accepted assessment, and the
  requested/applied routes; and
* any current diagnosis, proposed strategy, and independently accepted
  strategy generation with explicit attribution.

Fresh prompt reconstruction supplies the same complete bounded set, not only
the latest counterexample. Diagnosis, reframe, and strategy-gate prompts also
project the current immutable escape correlation and require exact-set output.
Core-derived identities/counts/routes/correlation are labelled Coordinator-
derived. Invariants, coverage prose, classifications, plans, and semantic
evidence references are labelled agent-attributed. If bounded prompt limits
cannot include the complete structured obligation or escape set, dispatch
fails closed or includes a complete retrievable Coordinator reference; it must
not silently omit an open obligation or trigger ID.

`persistence.py` needs only the new checkpoint projection and atomic v3 write;
no second state file is introduced. `operator.py` needs projection/context
support but no new imperative convergence command. Interruption and uncertain
dispatch retain the atomic-Hop-recovery semantics: only accepted, correlated
records affect convergence; an uncertain Hop never fabricates a coverage or
evaluation event. Replay over the same v3 Run and pinned profile must derive
byte-equivalent convergence projections and the same next route. Historical
Runs remain truthfully readable without gaining convergence state.

== Required deterministic tests and acceptance (question J)

The later implementation is acceptable only if the complete repository suite
and the following focused cases pass. Green tests do not grant Runtime
promotion or close the source BUG.

=== Stable identity and authority

* A gate creates one open blocking obligation; two corrector/evaluator cycles
  carry the same Coordinator ID into every prompt, Hop, checkpoint, and replay.
* An evaluator-created open blocker is atomically tracked. New open blockers
  from corrector, diagnosis, reframe, or strategy-gate roles are rejected, as
  is a v3 Run containing an open blocker without obligation metadata; ordinary
  v1-result/v2-profile creation remains unchanged.
* A corrector must cover every open tracked ID before requesting evaluation;
  unknown, missing, duplicate, closed, or superseded coverage fails closed.
* `addressed` with evidence does not close a gate-owned blocker and cannot take
  a complete route. Only configured gate/human Finding authority can resolve,
  residualize, supersede, or reopen it.
* A `residualized` assessment requires an authorized residual delta, preserves
  the original record as residual/non-blocking, and removes it from escape
  candidacy; missing, mismatched, or unauthorized residual assessments fail.
* Supersession to an existing tracked successor preserves both records. Same-
  result supersession resolves a unique `local:Nxxx` reference to the newly
  allocated tracked successor without predicting an `Fxxx` ID and persists
  only concrete IDs. Duplicate/unknown local refs, illegal targets, concrete-ID
  prediction, self-reference, and direct/transitive cycles reject atomically
  without consuming an ID; replay never reallocates the successor.
* A new blocker receives a new ID and zero cycles; it is not counted as a new
  counterexample for an older Finding.

=== Goalpost and routing

* One qualified cycle below the declared limit takes the normal correction
  route. A second qualified cycle at limit 2 deterministically applies the
  reserved diagnosis route and records the sorted triggering IDs.
* A worker `addressed` claim followed by `carried_unmet`, a failed evidence
  run, an uncertain Hop, an uncorrelated assessment, or old/duplicate evidence
  does not increment `repeated_counterexample_v1`.
* If the relevant Finding is resolved or validly superseded in the threshold
  evaluator Hop, no escape occurs. Semantic acceptance remains gate-owned.
* With multiple simultaneous Findings, only the non-converging ID triggers the
  escape; closed and below-limit IDs retain truthful independent histories.
* Direct agent request of the reserved escape route fails closed. Mechanical,
  human-authority, scope, policy, and required-evidence preemptions retain their
  current precedence. Hop-budget exhaustion still stops entry when no budget
  remains.

=== Diagnosis, reframe, and authority

* Diagnosis accepts only triggering open IDs and a closed generic
  classification. A two-ID escape rejects a diagnosis that omits either ID,
  adds an unrelated ID, duplicates or reorders IDs, or names a stale escape.
  The valid report is persisted as agent-attributed, cannot mutate the subject
  under a read-only phase, and cannot disposition Findings.
* An `authority_scope_gap` diagnosis with an unauthorized proposed action
  stops through the existing escalation boundary; no route, profile field, or
  strategy record widens authority.
* Revision and assessment reject an omitted triggering ID, unrelated below-
  limit ID, stale diagnosis/revision Hop, duplicate acceptance, consumed escape,
  or a trigger that became closed/residual/superseded. A rejected strategy
  resets no count. An exactly correlated accepted assessment advances every and
  only triggering generation exactly once, returns through a finite route,
  retains all history, leaves each original Finding open, and leaves every
  non-triggering Finding's generation and history unchanged.
* Profile validation rejects executable/unknown YAML, invalid roles, a limit
  outside bounds, agent-selectable escape, non-goto targets, incomplete
  diagnosis/reframe topology, insufficient evaluator Finding authority, and
  `reopen` authority under the initial protocol.

=== Wire, persistence, replay, and simple profiles

* Result v1 and profile v2 retain their exact current closed schemas and
  behavior. Result v2/profile v3 accept only the new closed shapes.
* Run v3 strictly validates every new record and cross-reference, including the
  immutable escape event, local-to-concrete successor resolution, and complete
  diagnosis/revision/assessment chain. Checked-in v1 and v2 fixtures load and
  round-trip without new wire fields or fabricated convergence facts. Read-only
  status/replay is byte preserving.
* Existing legitimate v1 persistence transitions still atomically write v2,
  with injected failure preserving exact v1 bytes. V2 never upgrades in place,
  and only a fresh v3-profile Run can acquire v3 convergence state.
* Checkpoint, summary, prompt, and replay derive identical counts, generations,
  goalpost IDs, escape correlations/consumption, requested/applied routes, and
  attribution. Interruption before accepted correlation adds no convergence
  event or generation advancement.
* Existing simple bounded review-loop fixtures and all current self-development
  profiles remain behaviorally unchanged.

=== Domain neutrality and real evidence

* A fixture about curriculum construction uses an open requirement such as
  “each learning objective is supported by an assessed activity.” Successive
  local revisions and independent counterexamples trigger diagnosis/reframe
  without any software-development vocabulary in the fixture or Core output.
* A static genericity assertion rejects software-only terms from the new Core
  enums and protocol field names.
* After implementation acceptance, a separately commissioned dogfood Run uses
  the still-open R1A case. It must show stable identity, normal correction
  before the configured goalpost, deterministic diagnosis escape, an
  independently reviewed strategy revision, and return to R1A still open. The
  dogfood acceptance is about mechanism behavior; it must not predeclare
  R1A's diagnosis or require this design Run to fix it.

== Rejected alternatives and deliberate non-scope

Distinct BlockingRequirement ledger:: Rejected. It duplicates Finding
identity, blocking state, evidence, and disposition and can become a shadow
acceptance model.

Use only Hop prose or task-local IDs:: Rejected for the implemented mechanism.
Run 004 shows task discipline can preserve identity, but Core cannot derive or
replay convergence from untyped prose. The Dxxx discipline used by this design
Run remains task-local and is not evidence that the generic mechanism exists.

Treat every failed rereview or three failures as root cause:: Rejected. Generic
failure counts mix new blockers, missing work, evidence failures, and the same
invariant. The chosen fact requires a same-ID addressed/new-counterexample
cycle, and the threshold changes strategy only.

Let the worker close its own obligation:: Rejected. Coverage is a claim;
Finding disposition remains with the configured gate/human authority.

Persist a mutable convergence counter or goalpost flag:: Rejected. Ordered
typed events plus the pinned profile are sufficient and replayable; a second
mutable value could drift.

Put conditions or scripts in YAML:: Rejected. The profile selects one closed
Core protocol, a bounded number, roles, and finite routes only.

Mutate the current profile or add Hops when the goalpost is reached:: Rejected.
The profile and budget are pinned authority. If the declared escape cannot run
within remaining budget, the existing budget stop controls.

Make diagnosis privileged or self-authorizing:: Rejected. Diagnosis is
attributed analysis under the same scope/trust envelope and normally read-only.

Accept the requirement when a strategy is accepted:: Rejected. Strategy
viability and subject correctness are separate evaluations.

Automatically continue in another Run or select another profile:: Rejected.
That is external commissioning/future Level-1 policy and may require new
authority. The current semantic-continuation mechanism remains separate.

Implement Level 1, profile discovery/registry, dynamic workflow generation,
provider selection, recovery redesign, or R1A itself:: Deliberately out of
scope.
