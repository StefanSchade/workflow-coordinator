. *The brief is a dated input, not a baseline.* Statements in it are reconciled
  in <<reconciliation>> and labelled `current`, `narrowed`, `contradicted` or
  `obsolete`. No brief statement is rewritten, and the brief file is untouched.

  re-derived: Beta-1 packages BP1-BP9 are independently accepted at Run level;
  the legacy Harness is retired; the Runtime is promoted to `4af5927`; DG-4

  and no Operator or Commission may set it
  (link:beta1_execution_plan.adoc#closure-versus-tag[closure versus tag]).

  importable in the planning agent's sandbox (`No module named pytest`), so
  every acceptance criterion below is expressed as a command plus its expected
  result for a later Coordinator-trusted run, never as an agent-observed pass.
  `asciidoctor` is available and was used to check this document's own
  rendering. The staged input digest was verified with `sha256sum`.

directory contains only `beta_runs_facts.json`, `MANIFEST.sha256` and

=== 5.3 Risks this plan carries forward

* *R1* G2 is never given, and the hardening offensive stalls with an accepted
  ADR and no authorized change. Verification: the ADR's acceptance is
  observable; G2's absence is observable. Stop behavior: nothing starts; no
  Commission may infer authorization.

  unintegrated. This plan neither narrows nor widens that boundary. Any
  Commission above runs under whatever provider configuration the maintainer

* *R5* P3 cannot start from the current staging set, because
  `spreadsheet-handling-4acca3da/` is absent. Verification: list the staged
  directory. Recovery: the Operator re-stages before the P3 Commission.

=== AD-1 The product's workflow-generality contract

Question:: Does WFC's public product contract commit to closed, product-owned,
versioned workflow programs on a generic kernel (C), to consumer-definable
phases, routes, authorities and topology (A), or to hard-coded programs (B)?
Options:: A, B, C as in brief 3.2.
Evidence in the repository:: C is already implemented on the consumer path
(`commissioning.py:215-235`) while the kernel stays data-driven and
phase-name-free (`reducer.py:1693-1703`). The benefit of A is unexercised: 4
phase kinds in 126 Hops, 0 uses of `direct@v1` or of any convergence role. The
cost of a broad contract is measured: 13 of 126 Hops lost to
`invalid_finding_delta`. B would duplicate the reducer, evidence, recovery and
archive machinery that 18 completed Runs exercise.
Consequences:: Under C the public configuration boundary is "task inputs,
scope and execution parameters, plus a choice from a product-owned program
set"; the 107 self-development governance YAML files become declared historical
archive rather than a public surface; a new program family becomes a versioned
release. Under A, P3.5 must guard arbitrary topology and the schema narrowing
in AD-4 becomes much harder to bound.
Recommendation:: *C*, recorded as a decision with A and B named as rejected,
and with the explicit statement that declarative internal implementation does
not imply an open public DSL (brief 3.3).
Who decides:: The maintainer, on the ADR.
Blocks:: The whole ADR; G1; indirectly P3.5, `PHASE-WRITE-SCOPE`,
`INVESTIGATION-WORKFLOW` and `DECISION-ANALYSIS-WORKFLOW`.
