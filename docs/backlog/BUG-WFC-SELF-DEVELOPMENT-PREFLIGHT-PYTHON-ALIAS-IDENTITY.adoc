== Observed behavior

The repository Makefile now correctly defaults developer commands to
`python3`. Consequently, `make check` starts pytest through the Development
environment's `python3` entry. The self-development RepositoryPolicy
intentionally retains trusted pytest evidence as:

----
python -m pytest -q
----

Production preflight resolves that policy command against the captured
Development/evidence `PATH`. In the observed environment, it selected the
same interpreter through the sibling `python` alias. The permanent architecture
test instead compared the literal selected invocation path with
`sys.executable`, so it rejected `.../bin/python` versus `.../bin/python3`
despite their canonical executable identity being the same.

== Root cause and intended invariant

This is an architecture-test defect, not a RepositoryPolicy, production
preflight, PATH-selection, Makefile, Runtime, or Agent Operating Contract V5
defect. The test treated an invocation-path spelling as interpreter identity.

The intended invariant is that trusted evidence resolution selects the same
intended Development/evidence Python interpreter that started pytest. It is not
an invariant that policy `python` must use the same literal basename or
unresolved path spelling as the pytest launcher.

The existing evidence-resolution model records both `invocation_path` and an
alias-independent `canonical_path`. The bounded correction should use the
model's authoritative canonical identity surface, rather than weaken the proof
to executable existence, basename, directory, or command-success checks.
