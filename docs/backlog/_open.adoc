== Beta-1 productization and immediately required work

The product goal is an installable, payload-neutral path from a bounded task
through execution, trusted checks, mechanical archive and an understandable
result. The link:beta1_productization.adoc[BP1–BP9 planning and source map]
owns package detail, prerequisites and acceptance directions. These packages
(BP1, BP2a/BP2b, BP3, BP4a/BP4b, BP5, BP6a-c, bounded BP8, BP7 and BP9 parts 1
and 2) are all independently accepted at Run level, BP5 with a separate
maintainer product-acceptance exception; see the "Beta-epic closure readiness"
record below and the
link:../cold_storage/backlog/pre-0.1.0b1/beta1-delivery-chronicle/beta1_delivery_chronicle.adoc[Beta-1
delivery chronicle] for the per-package Run evidence.
link:beta1_execution_plan.adoc[A proposed execution plan] decomposes BP1–BP9
into ordered Commission specifications, batches and release acceptance; it
recommends Commissions and grants no execution authority, and this overview
remains the sole priority/readiness authority.

The main chain is BP1 packaging/identity → BP2 configuration/compiler → BP3
initialization/planning and bounded Git → BP4 lifecycle → BP6 audit/report →
BP9 external-user qualification. BP5 archive port can start from BP1; its
commit wiring needs BP3's primitive. BP8 universal-test extraction can start
independently. BP7 self-development cutover follows BP6 and a maintainer
Runtime promotion; its timing against the tag remains open.

The Commission describes business work independently of concrete provider/model
bindings. `wfc run --yes` must finish the authorized mechanical lifecycle
unattended; `wfc plan` must execute no project command. A separate Git-backed
Evidence repository with sanitized audit projection is preferred. Old
Commissions must stay understandable, not indefinitely executable against
current APIs. These are current planning constraints on the reviews.

Coordinator crashes and potentially surviving provider processes are an initial
known limitation. Comprehensive supervision and a Linux subreaper are not
Beta-1 prerequisites. Automatic candidate preservation on regular stops is a
Beta-1 *candidate*, with design/acceptance still open; convenient continuation
can follow shortly after Beta 1. Neither adds a crash-safety promise or
speculative extra refusal mechanism.
