= BUG-WFC-EVIDENCE-COMMAND-CONSUMER-NEUTRALITY -- The Only Supported Policy Basis Hardcodes a Python-Specific Evidence Command

Type:: architecture -- closed consumer/language-neutrality boundary gap
(observed by direct source inspection; the existing fail-closed exact-match
admission itself is not characterized as a defect)
Status:: open (documentation only; no correction authorized by this record)
Current controlling source:: This record; see link:_open.adoc[the active-work manifest] for its current card.
Next action:: Design a consumer-supplied evidence-command configuration path under a separately authorized bounded Commission.
Not authorized here:: Any `commissioning.py`, policy-basis, or `evidence.py` implementation change.
Date:: 2026-11-02
Discovery context:: Commission-authoring process preparing
`wfc-simple-v1-maintainer-principles-001`, the first Claude Code (Opus)
`simple@v1` qualification Commission -- a documentation-only task in this
same repository, with no actual dependency on the Python test suite, that
is nonetheless gated on `python -m pytest -q` passing because that is the
only evidence command the compiler currently admits.

== Observed behavior (source-inspected)

`governance/policy-bases/repository-standard-v1.yaml`, the sole policy
basis accepted by every currently supported workflow program, authors
exactly one evidence command:

[source,yaml]
----
evidence_commands:
  task-check:
    argv: [python, -m, pytest, -q]
    timeout_seconds: 900
----

`src/workflow_coordinator/commissioning.py`'s `_repository_standard_v1_record`
(around lines 306-328) admits a pinned policy basis as the immutable
`repository-standard@v1` record only if, among its other closed fields,
`set(policy.evidence_commands) == {"task-check"}`,
`policy.evidence_commands["task-check"].argv == ("python", "-m", "pytest", "-q")`,
and `.timeout_seconds == 900` -- a literal identity check against this exact
argv and timeout, not a configurable field. `_load_sources` (same file,
around lines 331-363) in turn requires every supported program
(`direct@v1`, `robust@v1`, `simple@v1`) to use `repository-standard@v1`
specifically: `if (intent.policy_basis.id, intent.policy_basis.revision) !=
("repository-standard", "v1"): raise CommissionError(...)`. No other policy
basis currently exists in `governance/policy-bases/`. Separately,
`governance/workflow-programs/simple/v1.yaml`'s own `source` provenance
field states this is deliberate for `simple@v1`: "`evidence: E` is replaced
by `evidence_profiles[intent.evidence_profile].evidence`, which is always
`[task-check]` because `task-check-v1` is the only permitted
evidence-profile value -- unlike `direct@v1`, there is deliberately no
`none` entry."

The practical effect: any Commission compiled today, regardless of the
consumer repository's actual implementation language or the task's actual
nature (documentation, configuration, a non-Python consumer repository,
or a special-purpose task with no meaningful automated check at all), is
compiled against this one hardcoded Python test invocation. This
Commission's own task -- authoring one AsciiDoc document -- has no
dependency on the Python test suite's outcome, yet is gated on it passing
purely because the compiler offers no other option.

== Why this is undesirable

WFC's reusable-program design (workflow programs, Profiles, Policy bases)
is meant to separate *what may happen* from *which concrete repository/
command performs it*; `docs/wfc_operator_manual.adoc` states this
explicitly for role/model/reasoning bindings, and the same separation is
the intended purpose of a Policy basis for evidence commands. Hardcoding
one Python-specific `argv` as a literal identity check inside
`commissioning.py` itself violates that separation at the evidence-command
layer specifically:

* WFC cannot anticipate the validation commands required by arbitrary
  consumer repositories, languages, documentation projects, or
  special-purpose tasks; a second, non-Python consumer repository could
  not be admitted today without a source change to `commissioning.py`
  itself, which is exactly the per-consumer hardcoding the Policy/Program
  split exists to avoid.
* `simple@v1` has no `none` evidence-profile entry, so a genuinely
  evidence-free task (e.g. this one, or any task where no automated check
  is meaningful) cannot be expressed at all under the only supported
  policy basis.
* A reusable workflow program (`direct@v1`, `robust@v1`, `simple@v1`) is
  advertised as language-independent, but in practice every admitted
  Commission today inherits the same one Python test command regardless
  of program or task shape.

== Desired direction (not committed)

* Evidence commands originate in consumer-supplied configuration or
  policy, not product-specific hardcoding in `commissioning.py`.
* WFC validates and executes the configured commands through its existing
  trusted evidence mechanism (`evidence.resolve_executable` /
  `evidence.prepare_evidence_commands`), not through a new ad hoc path.
* A configurable allowlist is one possible shape for bounding which
  commands a policy basis may author; it is not selected here.
* Empty evidence configuration should be supported where the selected
  workflow program and policy permit it (parallel to `direct@v1`'s
  existing `none` evidence-profile entry; `simple@v1` deliberately has no
  such entry today).
* Reusable workflow programs should remain usable independently of the
  consumer repository's implementation language.

== Non-scope

This record authorizes no implementation. A future correction must not:

* be treated as authorized by this first Claude/Opus qualification
  Commission's continued use of `python -m pytest -q`; that Commission's
  own `task.md` names it "an intentional temporary compromise," not a
  defect in that Commission;
* select a specific mechanism (allowlist, consumer-policy schema, or
  otherwise) in advance of a separately authorized design; or
* weaken `evidence.py`'s existing fail-closed executable-resolution or
  preflight semantics.
