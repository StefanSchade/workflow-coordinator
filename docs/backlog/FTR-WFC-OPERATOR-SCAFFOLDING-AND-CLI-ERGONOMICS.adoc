== Problem

=== (a) The Consumer Request is assembled, then discarded

`wfc plan` takes the task document and a dozen fields, assembles the exact
Consumer Request YAML they imply and re-parses it through the closed schema
precisely so the preview exercises the same refusals a committed request
would (`frontdoor/plan.py:121-154`). It then prints a preview and throws the
YAML away. `wfc run` needs that same file (`--request`), so the operator
writes it again -- in practice a Python build script plus a shell wrapper per
Commission, carrying the long `--scope`/`--persona`/`--durable-artifact`
argument lists a second time.

Every re-typing is an opportunity for the preview and the launched Commission
to differ. The Front Door catches that (`frontdoor/lifecycle.py:304-307`
refuses a digest drift between plan and authorization), which is a refusal
the operator then has to diagnose -- the check exists because the duplication
exists.

=== (b) `wfc report` cannot resolve the Evidence location

`wfc report` takes only a positional source path
(`frontdoor/report.py:328`), while `plan`, `run` and `status` accept
`--repository` (`frontdoor/plan.py:229`, `frontdoor/lifecycle.py:1201`,
`:1222`). The operator learned the asymmetry from
`unrecognized arguments: --repository` (friction entry 5). The Evidence
location is mechanically derivable from the same Consumer Config the other
subcommands already read (`frontdoor/config.py:304-337`,
`resolve_evidence`), and `wfc report` does not use it.

== What is deterministic, and what is the operator's judgement

The distinction this record is built on, so that no scaffold is mistaken for
a decision aid:

Deterministic, and therefore automatable:: the YAML assembly from the
previewed fields, its field-for-field correspondence with the preview, the
resulting Commission digest, and the Evidence repository's path.
The operator's judgement, which no scaffold may supply:: the scope, the
program, the personas, the Hop budget, the evidence command and the authority
source. These stay inputs the operator decides and the human authorizes.

== Direction (not a chosen design)

(a) An emission path over the existing `consumer_request_from_plan_inputs`,
writing the request the preview describes to an operator-named path outside
the repository. Which surface -- a flag on `wfc plan` or a separate
subcommand -- is link:beta2_operator_efficiency_plan.adoc#d1[D1].

(b) Let `wfc report` resolve an archived Attempt from `--repository` via
`resolve_evidence`, keeping the positional form working unchanged. Note that
`--repository` on `wfc report` would name the *consumer* repository while the
command reads the *Evidence* repository; the flag must therefore mean "the
repository whose config names the Evidence location", not "the repository to
read the report from", or it is a worse surface than the positional path.

== Authority, and the contract this touches

No trust boundary. The emitted request grants no authority: `wfc run` reads
it from `--request`, re-parses it under the closed schema, re-digests it, and
the drift check is unchanged. Nothing is committed by the emitting command
and no provider is invoked.

There is a *contract* question that is not a trust question. `wfc plan` is
documented as writing nothing -- in the source (`frontdoor/plan.py:1-16`,
`:222-225`), in the Operator Manual and in the Agent Skill
(`references/commission.md:19-20`). Emission must not become part of a bare
`wfc plan`. That is the substance of D1, and it is why this record is not
commissionable before it.

== Open decisions

* link:beta2_operator_efficiency_plan.adoc#d1[D1] -- a flag on `wfc plan`, a
  separate subcommand, or no emission. The plan recommends a separate
  subcommand: `wfc plan`'s write-nothing promise is load-bearing for how an
  operator reasons about previewing an unauthorized Commission and is
  repeated in three shipped texts.
* Whether emission refuses a destination inside the repository. An untracked
  file anywhere in the repository makes the tree dirty and refuses launch, so
  defaulting outside and refusing inside would be consistent with the rest of
  the Front Door; not analysed further here.
