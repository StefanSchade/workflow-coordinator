== Problem and possible direction

K1's query currently returns complete JSON records, including links and potentially long multiline raw source declarations. For simple navigation this can consume unnecessary output and agent context. After observing representative real queries, consider concise default results (path, title, optional section heading and relevant identity) with explicit full records, for example `--json`. Preserve search semantics and assess consumers and compatibility before selecting the interface. No change is required merely because compact output is conceivable.

K1's `check` reports paths absent from the docs-only catalog, including four Project Memory `source_path` references to existing `src/workflow_coordinator/` Python files. Absence from a docs-only catalog is not an integrity failure. A bounded future diagnostic could distinguish: existing path outside catalog scope; path actually missing; and path that could not be reliably checked. Unresolved links could likewise be classified by supported evidence and cause rather than one undifferentiated message. Do not claim a cause where it cannot be established; do not turn informational reports into an automatic Run failure.

== Future assessment and boundaries

Before commissioning, record representative retrieval use and its costs; assess output compatibility, failure/error handling, tests and any effect on the separately planned provenance pilot. A future implementation should cover existing/out-of-scope, missing and uncheckable paths and representative unresolved-link categories with fixtures, retain accessible full records, and preserve the non-authoritative source-declaration boundary. Link remediation belongs to link:FTR-WFC-DOCUMENTATION-INFORMATION-ARCHITECTURE-FOLLOWUP.adoc[the later information-architecture follow-up], not this tooling item. No catalog schema, search semantics, Runtime, Project Memory, historical documents, automatic freshness or product-goal change is selected here.
