== Open blocking implementation requirement

=== S1-IR-001 -- Reduction must reject reassessment of an already assessed correction Hop atomically

Underlying invariant:: Each corrector coverage record has exactly one next
evaluator assessment. Result reduction must enforce the same single-use
correlation accepted by the durable Run-v3 parser, before any Finding mutation
or route application, so every admitted Run remains persistable and replayable.

`_validate_convergence_records_before_apply()` currently builds
`prior_correction_hops` from every prior Hop with coverage and unconditionally
selects the latest one. It does not remove or reject correction Hop IDs already
named by an earlier convergence assessment. A later evaluator can therefore
reuse that correction Hop ID, pass totality and matching-delta validation,
mutate the Finding, persist another assessment into the in-memory Hop summary,
and take an autonomous route. In contrast, `_validate_v3_run()` explicitly
tracks assessed correction Hop IDs and rejects the second use. This makes
reducer acceptance and authoritative wire validation disagree.

The defect is observable at:

* `src/workflow_coordinator/reducer.py`, the prior-correction selection and
  assessment correlation around lines 626-646; and
* `src/workflow_coordinator/serialization.py`, the Run-v3 single-use check
  around lines 1209-1215.

Required correction:

. Before applying any result-v2 delta, derive the correction Hop IDs already
  assessed by prior accepted Hop summaries and reject reuse of any such ID.
. Keep selection/correlation deterministic: an evaluator may assess only the
  current unassessed correction Hop that its claims name; it may not fall back
  to an older already consumed coverage record.
. Preserve transactionality. Rejection must leave Findings, Hop convergence
  records, IDs, and route state unchanged.
. Add a focused reducer regression that performs one valid assessment, attempts
  a second assessment of the same correction Hop, and proves fail-closed state
  with no route application. Also prove that a later distinct corrector Hop can
  still be assessed normally and persists through `run_to_json()`.

This correction fits the already authorized `reducer.py` and
`tests/unit/test_reducer.py` paths. No scope or semantic-authority expansion is
required.

for that Finding is not included in the freshness set. Consequently, a
reference stored on that prior coverage claim passes the current subtraction,
is appended by the same-state Finding delta, and can later appear to Slice-2
derivation as a new evaluator counterexample.

  already present on the correlated correction Hop's coverage claim for the

  assessment reference remains.

  used to establish freshness also occurs in the matching Finding delta.

=== Open blocking Slice-3 implementation requirements

==== S3-IR-001 -- Persisted escape routing truth is not replay-closed

Underlying invariant:: Every claimed convergence substitution must be
durably attributable to the exact evaluator phase and must be replay-provable
from that phase's pinned normal/escape routes, the trusted qualification pair,
the post-Finding-delta open set, and the exact sorted goalpost IDs. Unknown
trigger identities or invented route names must never become
Coordinator-derived truth.

`Hop` records `phase`, but `Hop.compact()` discards it and `HopSummary` has no
phase field. The v3 serializer consequently cannot establish which historical
phase owned a requested route or whether the requested/applied pair equals that
evaluator's declared normal/escape keys. `_validate_v3_run()` checks only that
`route_reason` has the prefix `convergence_escape:`, contains sorted
Finding-shaped strings, has a non-null requested route, and does not name the
same non-null applied route. It does not require the trigger IDs to exist in the
Finding ledger, require the source Hop to be an evaluator, or correlate the
route pair and trigger set to trusted derived facts. Pair-aware checkpoint
projection then copies those unchecked values into its
`coordinator_derived` convergence block.

The direct reproduction admitted `F999` although the Run contained only
`F001`, and admitted arbitrary requested/applied route names. This is not only
a defensive-parser concern: route reason, trigger identity, and evaluator
attribution are the durable Slice-3 mechanism by which later prompts,
checkpoints, summaries, and replay distinguish the agent request from the
Coordinator substitution.

Required correction:

. Persist the source phase in the v3 HopSummary as required by the accepted Run
  wire, while continuing to omit new fields from v1/v2 serialization.
. Make strict v3 validation reject escape trigger IDs absent from the durable
  Finding graph and reject structurally impossible route truth.
. At the pair-aware profile/replay boundary, validate that an escape record
  came from an evaluator phase, requested that phase's declared normal route,
  applied its declared escape route when application occurred, and names the
  exact sorted still-open goalpost set derived from authoritative semantic and
  trusted qualification inputs at that decision boundary. Do not infer the
  decision from prose or checkpoint bytes.
. Add corruption/replay tests for an unknown trigger, wrong phase, wrong normal
  route, wrong escape route, omitted/additional trigger, and a route reason
  unsupported by the paired qualification history. Preserve the valid
  requested-normal/applied-escape round trip and budget-exhaustion case.

This correction fits the authorized model, serialization, persistence,
reducer, prompt/operator, and focused test paths. It does not require Slice-4
typed escape-chain semantics.

==== S3-IR-002 -- Pre-dispatch projection weakens trusted pair validation

Underlying invariant:: Production prompt construction must consume the same
strictly validated Slice-2 qualification authority as live reduction and
replay. Once a v3 Hop carries a pre-route anchor, a missing, legacy, malformed,
cross-Run, duplicate, or otherwise inconsistent evidence document is a pair
error that prevents further dispatch; it is not an empty qualification index
or a zero-count history.

The local `qualification_index()` closure in `operator.run_serial_hops()`
returns `TrustedQualificationIndex.empty()` whenever the v3 execution-evidence
file is absent or parses as a legacy document. It then supplies that empty
index to `convergence_prompt_context()` and proceeds to
`run_real_one_hop()`. In contrast, persistence's accepted
`_qualification_index_for_inputs()` correctly raises when an anchored v3 Hop
lacks paired schema-4 evidence. The operator therefore has two qualification
policies: strict for checkpoint publication after a Hop, but permissive for the
fresh prompt that is allowed to dispatch the next provider.

If schema-4 evidence is lost, replaced by legacy bytes, or otherwise becomes
ineligible after an anchored Hop, the next prompt silently projects no source
Hops and lower counts. The provider can be invoked before later evidence
publication or checkpoint validation discovers the inconsistent pair. That
weakens the binding Design Revision's evidence-before-route and live/replay
equivalence rule and consumes a Hop under context that was not authoritative.

Required correction:

. Use one strict qualification-input function for production pre-dispatch
  projection, live reduction, checkpoint construction, and replay. Preserve
  the accepted distinction between a genuinely unanchored historical v3 Run,
  for which absent/legacy evidence yields an explicit empty index, and an
  anchored Run/evidence pair failure, which stops fail-closed.
. Ensure every inconsistent pair is rejected before prompt delivery/provider
  invocation and cannot be converted to fabricated zero facts.
. Add serial-operator regressions that remove or replace schema-4 evidence
  after an anchored first Hop, then prove absent, legacy, malformed,
  cross-Run, duplicate, and anchor-mismatched inputs cause zero additional
  provider calls and no new Hop/route/checkpoint authority. Retain the valid
  exact-pair continuation and legitimate unanchored no-backfill cases.

This correction fits the authorized persistence, operator, vertical, and
focused test paths. No new evidence substrate or authority is needed.

This contradicts the accepted FTR's profile-v3/result-v2 rule and creates a
mixed profile-v3 wire in which the result lacks the mandatory v2 fields and
uses the legacy Finding path.

Required correction:

  phase whose declared convergence role is `none`; continue selecting result
  v1 for profile-v2/simple Runs.
. Define the `none` role's result-v2 reduction narrowly: convergence records
  and Slice-4 typed placeholders remain empty/null, non-evaluator creation of
  an open blocker remains rejected, and ordinary non-blocking informational
  Finding semantics remain as accepted. Do not grant disposition authority.
. Add a parser-to-prompt-to-adapter-to-reducer integration test for a valid
  profile-v3 `none` phase and retain byte/behavior regressions proving that
  profile-v2 phases still dispatch and validate result v1.

This correction fits the authorized prompt, vertical, reducer, and focused
test paths. It adds no Slice-4 semantic record.
