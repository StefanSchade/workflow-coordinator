= BUG-WFC-CLAUDE-ADAPTER-SHORT-TMPDIR-RESOURCE-EXHAUSTION -- The Claude Adapter's Short, `/tmp`-Rooted Subprocess `TMPDIR` Lets Agent-Launched Test Processes Exhaust the Host `tmpfs`

Type:: bug -- Claude adapter resource-isolation gap.
Status:: open.
Date:: 2026-11-07.
Discovery:: Maintainer-operator monitoring of Run
`RUN-b112595129b34f4c97806f634a0b7133`
(`WI-WFC-EVIDENCE-FAILURE-DIAGNOSTICS-001`), interactive session 2026-11-07.

== What happened

`/tmp`, a `tmpfs`, reached **1,048,576 / 1,048,576 inodes (100%)** during
Hop H002 of `WI-WFC-EVIDENCE-FAILURE-DIAGNOSTICS-001`, almost entirely
(530,457 files) under three `pytest-of-stefan` session directories
(`pytest-10`, `pytest-11`, and their `pytest-current` symlink target), each
around 265,000 files. Every `Bash` tool call in the *interactive*
maintainer-operator session (separate from the Run itself) began failing
with `ENOSPC: no space left on device` for several minutes. The Run's own
trusted `task-check` evidence was unaffected (it executes in the
Harness-built `dev-env`, not under the agent's `TMPDIR`), and the Run
completed normally at Hop 2 with no anomaly recorded. The `pytest-of-stefan`
material was removed afterward as a one-off operational cleanup, after
confirming no process still referenced it.

The independent reviewer's own broad-review artifact for the same Hop
independently reports the same symptom from inside the Run itself: denied
`pypi.org:443` egress for real venv installs, and "exhaustion of the
sandbox temporary filesystem; repeat runs could not complete once that
filesystem filled, and redirecting or clearing it was not permitted" --
correctly classified there as an agent-local environmental limitation, not
a candidate defect
(`docs/warm_storage/concepts/workflow_coordinator_evidence_failure_diagnostics_2026-11-07_broad_review.adoc`).

== Why it happened

The Claude adapter gives the Claude CLI subprocess a short, invocation-
scoped `TMPDIR` rooted at the ambient system `/tmp`
(`src/workflow_coordinator/claude_adapter.py:39-47`,
`_SHORT_TMP_ROOT = Path("/tmp")`; `_short_subprocess_tmp_dir()` at
`:110-116`; applied at `:149,166`). That exists because Claude Code derives
its Bash-tool sandbox's `AF_UNIX` IPC-bridge socket path from `TMPDIR`, and
`sockaddr_un.sun_path` is capped at 108 bytes; a long, human-readable,
Attempt-scoped `TMPDIR` reliably breaks sandbox initialization (fixed by
commit `4776fd0`).

Bash-tool commands the Claude CLI launches during a Hop inherit that same
short, `/tmp`-rooted `TMPDIR` unless a command sets its own. During H002,
the agent's own exploratory validation ran `pytest` via the Bash tool;
`pytest`'s temporary-directory machinery honors inherited `TMPDIR`, so its
session/fixture material -- including fixtures in
`tests/unit/test_wfc_op.py` that materialize real exported repository trees
and `pip`-installed virtual environments -- landed on the small host
`/tmp` `tmpfs` instead of the Attempt's own large-filesystem scratch
(`$HOME/wfc-scratch/<attempt>`, established by FD-08,
`WI-WFC-FD08-ATTEMPT-SCRATCH-001`). FD-08 moved the *Harness*'s own
`TMPDIR`/`TMP`/`TEMP` away from `/tmp` for an earlier, distinct incident
(`docs/cold_storage/backlog/pre-0.1.0b1/infrastructure-and-incidents/2026-10-28_tmpfs_exhaustion.adoc`);
the socket-path fix (`4776fd0`), solving a narrower, locally correct
problem, reintroduced a `/tmp` dependency one level deeper, inside the
Claude adapter's own subprocess environment, without revisiting that.

`FTR-WFC-SELF-DEVELOPMENT-EXECUTION-INTEGRATION-DEBT.adoc` already named
this exact tension as an open, unconfirmed evaluation question ("Should a
provider adapter's own short-lived, short-path temp-directory need be
requested from a Harness-owned allocator... rather than each adapter
hardcoding `/tmp` independently?"); this is the first confirmed incident
realizing it.

`BUG-WFC-PYTEST-TEMP-RESOURCE-EXHAUSTION` documents a prior `/tmp`
exhaustion with the same symptom shape (607,722/1,048,576 inodes, also
concentrated in `pytest-of-stefan`) but explicitly declines to attribute a
cause. This record is narrower: it identifies one concrete, sufficient
causal path -- the Claude adapter's short `TMPDIR` inherited by
agent-launched test processes -- without claiming it is the only
contributor to that record's own, still-open question. The two are kept
separate rather than merged.

== Required product behavior

WFC must be able to give a provider subprocess (today, the Claude CLI) a
short temporary path for socket/IPC purposes without that short path also
becoming the destination for unrelated, potentially large volumes of
temporary material the subprocess or its own child processes (such as an
agent-launched `pytest` run) may create. The two needs -- a short *path*
(bytes, for `sun_path`) and a large-capacity, Attempt-isolated *filesystem*
(for bulk material) -- are presently conflated onto one `TMPDIR` value and
should not be. The functional requirement is short socket paths; today's
`_SHORT_TMP_ROOT = Path("/tmp")` is one implementation of that, not a
constraint a correction must preserve as-is.

**Portability:** a correction should assume as little as possible about the
host environment, and in particular should not need, as the ordinary case,
a privileged or administrative host change (a system-wide `/tmp` resize, an
administrator-installed symlink, a mount performed outside WFC's own
process tree). It needs to work, without such a precondition, at minimum on
Ubuntu under WSL and in restrictive corporate environments where the
operator cannot assume elevated host privileges.

== Candidate directions (open hypotheses, nothing selected)

* Point `pytest` fixture/session material at the existing Attempt scratch
  root (FD-08) via `PYTEST_DEBUG_TEMPROOT`, possibly reinforced by explicit
  worker-prompt instruction not to rely on ambient `/tmp` for exploratory
  test runs. Open question: whether and how this reaches a `pytest`
  invocation the agent itself launches, which WFC does not control.
* An explicit `--basetemp` convention, including the known risks of nested
  or parallel `pytest` invocations sharing or colliding over one fixed
  `--basetemp` path.
* A short symlink (or similar short indirection) under `/tmp` pointing at
  the real Attempt scratch root -- unverified whether the Claude sandbox's
  own socket-path resolution follows symlinks the way this would require.
* A bind mount inside a WFC-owned bubblewrap namespace, where available --
  not to be assumed available, since an unprivileged mount namespace is
  itself a host capability some environments may not grant.

Each trades off differently against the portability requirement above;
none is known to satisfy it yet.
