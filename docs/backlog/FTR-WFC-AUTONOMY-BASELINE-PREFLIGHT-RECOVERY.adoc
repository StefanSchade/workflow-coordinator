= FTR-WFC-AUTONOMY-BASELINE-PREFLIGHT-RECOVERY -- Baseline preflight and deterministic recovery

Status:: Open; investigation only.

== Observation

During the phase-specific execution bindings Commission, the Level-1 operator
launched an authorized Run without the `WFC_TEST_INPUTS` and `WFC_TEST_PROFILE`
environment variables required by the repository's offline test contract. The
baseline probe failed before any provider Hop; `wfc status` reported
`not_launched`. The installed WFC skill required a human decision before
resolving the stop even though the required test inputs and their verification
procedure were determinable from the repository contract. The maintainer then
authorized verification of the offline inputs and resumption of the existing
Run without changing its request, bindings, or baseline requirement.
A second probe with verified inputs exited 1 and left a test-generated
`.claude/skills/wfc/` in the checkout; the runtime reported the exit code
but did not retain the captured test output in its diagnostic. A scratch
directory outside the checkout and the same verified inputs allowed the
unchanged full baseline to pass. The exact failing assertion of the second
probe is unconfirmed.

== Investigation

* How can a Level-1 operator identify and prepare required test inputs before
  starting a Run, while respecting the repository's verification contract?
* Can explicitly defined, safe preflight corrections be made autonomously, and
  under what precise preconditions?
* Should a failed baseline surface or preserve its captured diagnostic output,
  and should status distinguish a failed probe from an unattempted launch?
* How should deterministic preflight correction be distinguished from genuine
  reconciliation, changed authority, or decisions requiring a human?
* What evidence must record the initial failure, verified inputs, unchanged
  authorization, corrective action, and resulting baseline outcome?

Any future proposal must preserve Human Authorization and the trusted baseline;
this item grants no authority to weaken either. It does not commission an
implementation or change the current phase-bindings feature scope.
