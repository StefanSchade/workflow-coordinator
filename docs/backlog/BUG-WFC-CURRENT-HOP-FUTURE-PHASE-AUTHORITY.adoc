== Observed behavior

== Root cause and intended invariant

The agent-facing authority semantics do not sufficiently distinguish the current Hop from a route-target Hop.

* `authorized_scope` and `authorized_actions` describe effects permitted *during the current Hop*.
* `requested_route` selects a future workflow transition; requesting `correct` does not perform correction work in the current rereview Hop.
* Authority for the correction phase is projected separately only if and when that next Hop executes.

A reviewer must therefore be able to request `correct` from review/rereview without possessing correction-phase edit scope or actions. The current review Hop must not demand mutation authority merely because the reviewer anticipates that a future correction may need other paths.

The reducer behaved correctly: it received an explicit scope escalation and stopped fail-closed. This BUG must not weaken reducer authority enforcement or move authority from the pinned phase/profile into consumer task prose.

== Future acceptance intent

Do not implement this specification in this BUG record.

* Current-Hop scope/actions and future route-target authority are explicitly distinguished in the agent-facing prompt / Operating Contract semantics.
* A review or rereview Hop can request `correct` without correction-phase edit scope.
* Future correction authority is separately projected only when that phase actually executes.
* Reducer fail-closed behavior remains unchanged.
* Regression coverage demonstrates this current-Hop versus future-phase distinction.
* Attempt-4 historical Run evidence remains frozen.
* The fresh developer-ergonomics observation is not retroactively inserted into Attempt-4 Run state or assigned an F-number.

The implementation mechanics are intentionally not prescribed beyond these semantics. Repository inspection should retain this as primarily an agent-facing prompt / Operating Contract defect unless stronger contrary evidence emerges.
