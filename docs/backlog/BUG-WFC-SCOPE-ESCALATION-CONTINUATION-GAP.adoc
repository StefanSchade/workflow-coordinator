== What this is not

This record does not characterize the outcome as the agent failing to
understand its scope. In this Run the worker respected its authorized scope
correctly: it made no unauthorized change, and it asked rather than silently
widening authority. Do not read this BUG as a repeat of the earlier
Contract-projection or authority-misunderstanding defect classes recorded by
`SIG-ACT-WFC-DOGFOOD-CONTRACT-DEFECTS`.

Separately -- and this is a distinct, secondary observation, not the main
mechanism finding -- H001's own diagnosis of what remained stale was
incomplete: it correctly named the out-of-scope Slice-4 staleness but did not
surface the two in-scope Slice-5b fixture failures that operator reproduction
later found. This is a diagnostic-completeness gap in what the worker's
evidence surfaced, not a scope or authority defect.

This is also not:

* a crash;
* uncertain-dispatch recovery (the structured result correlated and applied
  normally; nothing was reconciled as an uncertain acceptance);
* a same-Hop retry;
* an automatic replay; or
* provider-session continuation.

It is a legitimate mid-Hop authority/scope escalation, raised correctly by
the worker, whose useful uncommitted work then had no defined continuation
path once a later mechanical preemption (dirty tracked state, forbidden
`CommitIntent`) took over the stop.

== Mechanism finding (narrow)

Fail-closed authority enforcement worked. The reducer correctly refused to
accept a partial or unauthorized candidate once tracked state was dirty, and
the worker correctly refused to widen its own scope into
`tests/unit/test_slice4.py` rather than silently mutating it. Neither of
those behaviors is the defect.

The gap is narrower and purely operational: WFC has no first-class operator
continuation path for the case where (a) useful, authorized-scope mutations
already exist in an uncommitted candidate, and (b) the same Hop legitimately
discovers that finishing the work requires authority the current WorkItem
does not grant. Today, the only available path is manual: an operator must
preserve the candidate outside of Run state, restore the target checkout to
a clean known baseline, decide on and grant new authority (a revised or new
WorkItem/Commission), and commission a fresh successor Run -- mirroring, at
smaller scale, the bounded-scope-grant pattern already exercised for the
Latin Story-2 chain (`latin-story02-c0-20260928-02` ->
`latin-story02-c0-20260929-03`).

A second, related gap: the semantic human question that motivated the stop
can be obscured by a later mechanical preemption. In this Run, the worker's
own scope-escalation question survived only in the structured result; the
published Run/operator-facing summary exposed the mechanical dirty-state and
forbidden-`CommitIntent` reasons instead, with `human_question: null`. An
operator reading only the published operator-facing state would not see that
a real, answerable scope question was ever raised.

== Relationship to existing concerns and future-technical-records

`FTR-WFC-ATOMIC-HOP-RECOVERY.adoc` and Project Memory concern
`CONC-WFC-ATOMIC-HOP-RECOVERY-WIRING` already name an operator-wiring gap,
but that gap is about *same-Run* technical interruption recovery: charged-Hop
suspend/reconcile/resume semantics that are modeled and unit-tested in the
reducer but not wired into the production operator for a real interrupted
Run. That FTR explicitly scopes out a generic outer loop and explicitly
treats persistent provider-session continuation and generalized
process-loss recovery as deferred, out of its own scope.

This BUG's continuation gap is a different mechanism and must not be
conflated with it: it is not about resuming the *same* Run after an
interruption, and it is not about provider-session continuation. It is about
what happens *next*, semantically, when a Hop inside a Run correctly and
deliberately stops because it needs authority it does not have, after
already producing useful uncommitted work -- a *successor*-Run concern, not
a same-Run recovery concern. The two are adjacent (both are "what does the
operator do when a Hop does not cleanly complete" questions) but are
distinct mechanisms and should remain tracked distinctly.

== Future backlog requirements/questions (not authorized by this record)

This record documents the gap only. It authorizes no implementation, no
Runtime change, no governance change, and no Run. If and when this gap is
addressed, any design must at minimum preserve the following properties,
recorded here as open backlog requirements/questions rather than as accepted
design:

* Preserve the original semantic escalation (the worker's actual scope
  question) in operator-visible published state, even when a later
  mechanical preemption also applies to the same stop.
* Never auto-widen a WorkItem's authorized scope in response to a worker's
  escalation; a scope grant remains an explicit, separately authorized
  maintainer act, exactly as already practiced for the Latin Story-2 chain.
* Never auto-commit or auto-accept a blocked or dirty candidate.
* Preserve candidate material, when preserved at all, only as explicitly
  non-authoritative salvage -- never as trusted WFC evidence, a checkpoint,
  or an implicit grant of authority.
* Allow a separately authorized successor Run to consume such salvage only
  as untrusted context (for example, as background for a fresh worker
  invocation), never as a substitute for that Run's own evidence or trusted
  commit.
* Never mutate a predecessor Run's governing inputs (WorkItem, Profile,
  Policy, Commission) to retrofit continuation; a scope change is a new,
  explicit governing-input revision, as already practiced.
* Never infer acceptance of a candidate from the mere existence of preserved
  salvage material.
* Keep this semantic successor-continuation concern distinct from same-Run
  technical crash/reconcile recovery (`FTR-WFC-ATOMIC-HOP-RECOVERY.adoc`) and
  from provider-session continuation, in any future design or naming.

None of the above is an implementation plan; it is the minimum set of
invariants a future design must not violate.
