== Observed behavior

As recorded in full in the linked incident report: `/tmp`, a 5.7 GiB
`tmpfs`, was found completely full while `/` had over 400 GB free.
`/tmp/pytest-of-stefan` alone accounted for the full 5.7 GiB, across
528,603 files concentrated in six `pytest` session directories (`pytest-216`,
`pytest-222`, `pytest-227`, `pytest-228`, `pytest-229`, `pytest-230`). Inode
usage on the `/tmp` tmpfs stood at 607,722 of 1,048,576 (58%). Recurring
test-environment and repository-copy-shaped material is visible under these
session directories, consistent with fixtures that materialize a fresh
environment or repository checkout per test or per session -- but this is an
observation about the shape of the retained material, not an identified
cause.

This resource pressure was not merely latent: it materially interrupted a
real WFC Run. The Front Door Direct-v1 successor Commission reached its
sixth and final Hop with a well-formed, agent-reported `accept` review
result, but the Coordinator's own post-invocation Git observation
(`src/workflow_coordinator/git_facts.py`'s `observe_repository()`, which
copies `.git/index` to a `tempfile.mkstemp()` path under the ambient system
`/tmp`) failed with `ENOSPC`, and the Run stopped `reconcile_required`
rather than completing. Full facts are in the incident report; this BUG
record does not repeat them beyond what is needed to state the defect.

== What this is not

This record does not establish, and does not authorize anyone to assert,
which specific fixture(s), test module(s), or invocation pattern(s) are
responsible for the bulk of the retained files or file count. It does not
claim that `pytest`'s own default temporary-directory retention behavior is
misconfigured, that a particular fixture leaks, or that repeated local test
runs alone explain six concurrently retained sessions rather than some
smaller number of invocations each leaving more than one session behind.
Each of these remains an open question in the incident report's §4 and is
not resolved here.

This record also does not characterize the Coordinator's `ENOSPC` handling
itself (the fail-closed `uncertain_dispatch` charge and `reconcile_required`
stop) as defective; that behavior is the Coordinator correctly failing closed
on an unexpected I/O error, not a Coordinator defect, and is out of scope for
this BUG.

This is related to, but is a distinct concern from, the already-recorded
link:../warm_storage/concepts/workflow_coordinator_front_door_stage1_commission_test_burden_finding_2026-10-25.adoc[Front
Door Stage 1 Commission test-burden finding], which is about permanent
per-Commission test *count* and *runtime* (7,731 lines, 44 tests, 42
`_materialize_bundle()` calls per full run), not about temporary-file
*retention*. The two may share an underlying contributor -- repeated
environment/repository materialization -- but neither finding established
that relationship, and this BUG does not assume it.

== Why this is undesirable

Local test execution is ordinarily expected to be a closed loop: temporary
material it creates should not accumulate to the point of affecting
unrelated operations on the same host, let alone interrupting a WFC Run that
has nothing to do with the test suite's own temporary-file usage beyond
sharing the same `/tmp`. A full `/tmp` is a shared-resource failure mode
that can recur with any process that writes there, not only a WFC Run; this
particular incident happened to surface it, but the underlying resource
pressure is a test-infrastructure concern independent of WFC.
