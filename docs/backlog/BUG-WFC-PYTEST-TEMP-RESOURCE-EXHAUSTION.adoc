= BUG-WFC-PYTEST-TEMP-RESOURCE-EXHAUSTION -- Retained `pytest` Temporary Material Exhausted the `/tmp` tmpfs and Interrupted a WFC Run

Type:: bug -- test-infrastructure resource-exhaustion defect (not a
Coordinator, Runtime, or Commission-design defect)
Status:: open -- near-term self-development infrastructure work; see
link:_open.adoc[the active-work manifest].
Current controlling source:: This record.
Next action:: Independently review and accept the repository pytest storage correction and its evidence.
Priority:: suitable for BP8, or earlier if recurring failures continue to block work;
a general scratch-management framework is not a Beta-1 prerequisite.
Date:: 2026-10-29.
Classification:: repository-specific test-infrastructure robustness defect, surfaced
while diagnosing the 2026-10-28 operational incident recorded in
link:../cold_storage/backlog/pre-0.1.0b1/infrastructure-and-incidents/2026-10-28_tmpfs_exhaustion.adoc[the `/tmp`
tmpfs-exhaustion incident report].
Discovery:: maintainer diagnosis of the 2026-10-28/29 `/tmp` exhaustion that
interrupted Run `RUN-c358b544417c4a33a0d040a0d8c38656`.

== Observed behavior

As recorded in full in the linked incident report: `/tmp`, a 5.7 GiB
`tmpfs`, was found completely full while `/` had over 400 GB free.
`/tmp/pytest-of-stefan` alone accounted for the full 5.7 GiB, across
528,603 files concentrated in six `pytest` session directories (`pytest-216`,
`pytest-222`, `pytest-227`, `pytest-228`, `pytest-229`, `pytest-230`). Inode
usage on the `/tmp` tmpfs stood at 607,722 of 1,048,576 (58%). Recurring
test-environment and repository-copy-shaped material is visible under these
session directories, consistent with fixtures that materialize a fresh
environment or repository checkout per test or per session -- but this is an
observation about the shape of the retained material, not an identified
cause.

This resource pressure was not merely latent: it materially interrupted a
real WFC Run. The Front Door Direct-v1 successor Commission reached its
sixth and final Hop with a well-formed, agent-reported `accept` review
result, but the Coordinator's own post-invocation Git observation
(`src/workflow_coordinator/git_facts.py`'s `observe_repository()`, which
copies `.git/index` to a `tempfile.mkstemp()` path under the ambient system
`/tmp`) failed with `ENOSPC`, and the Run stopped `reconcile_required`
rather than completing. Full facts are in the incident report; this BUG
record does not repeat them beyond what is needed to state the defect.

== Recurrence and current evidence (2026-11-14)

`WI-WFC-MINIMAL-DOCUMENTATION-LIFECYCLE-001`,
`RUN-c20a6f5556404b339c2876aebb032c11`, stopped `reconcile_required` after
H002 returned a blocking Finding and H003 failed during resource exhaustion.
The committed candidate remains unaccepted. The
link:../warm_storage/concepts/wfc_minimal_documentation_lifecycle_001_broad_review_2026-11-14.adoc[H002 review]
records the Finding and candidate; the resource-exhaustion account is the
reported Run outcome, not a diagnosis of its source.

The desired behavior is that test-heavy WFC self-development does not
repeatedly exhaust a host's small default `/tmp` when suitable external
scratch is available. Static inspection establishes the following boundaries:

* `scripts/wfc_op.py` sets `TMPDIR`, `TMP` and `TEMP` to the fresh Attempt
  scratch during preparation and freezes them in `launch.sh`; the default
  root is `~/wfc-scratch`. Existing `tests/unit/test_wfc_op.py` checks
  preparation and launch propagation.
* `codex_adapter.py` starts Codex without an `env` override, so the CLI
  inherits the Coordinator environment, including Harness scratch when
  launched that way. This does not establish what an agent-launched command
  actually receives after any Codex or sandbox changes.
* `evidence.py` snapshots the Coordinator environment and supplies that
  snapshot to Coordinator-owned evidence subprocesses; the selected policy
  determines the command. This supports propagation, but is not an
  observation of the incident's pytest process.
* The Claude adapter separately uses a short `/tmp` symlink to an
  invocation-specific backing directory selected from ambient scratch (or a
  fallback); its conformance tests inspect that arrangement. The resolved
  link:BUG-WFC-CLAUDE-ADAPTER-SHORT-TMPDIR-RESOURCE-EXHAUSTION.adoc[Claude BUG]
  does not establish the cause of this recurrence.
* The repository's `pyproject.toml` pytest settings do not specify a `/tmp`
  base directory. Some sandbox tests explicitly use a private `/tmp`; that
  alone does not identify host pytest retention as their effect. Command-line
  options, environment, subprocesses and external configuration may differ.
* Earlier retained pytest directories and their size and file count are
  documented above. Their existence does not establish which files were present
  or active at this latest failure, or which execution created them.

The repository's `tmp_path` and `tmp_path_factory` fixtures are used by
`tests/unit/test_wfc_op.py` to construct test repositories, and many
architecture tests also construct Git repositories. This establishes a
repository-specific exposure to pytest's temporary storage, not the identity
of every process that produced the previously retained files. Neither a Codex
adapter defect nor a failure to propagate `TMPDIR` in the affected process is
confirmed.

The implementation under review selects external supplied scratch or the
ignored repository `tmp/pytest` default for pytest-owned paths, with pytest's
numbered directories and retention. Explicit pytest temp configuration takes
precedence. Direct `tempfile` calls and external tools remain independently
configured. Tests exercise the ordinary command, supplied scratch, concurrent
runs and fixtures; acceptance and independent review remain pending.

== What this is not

This record does not establish, and does not authorize anyone to assert,
which specific fixture(s), test module(s), or invocation pattern(s) are
responsible for the bulk of the retained files or file count. It does not
claim that `pytest`'s own default temporary-directory retention behavior is
misconfigured, that a particular fixture leaks, or that repeated local test
runs alone explain six concurrently retained sessions rather than some
smaller number of invocations each leaving more than one session behind.
Each of these remains an open question in the incident report's §4 and is
not resolved here.

This record also does not characterize the Coordinator's `ENOSPC` handling
itself (the fail-closed `uncertain_dispatch` charge and `reconcile_required`
stop) as defective; that behavior is the Coordinator correctly failing closed
on an unexpected I/O error, not a Coordinator defect, and is out of scope for
this BUG.

This is related to, but is a distinct concern from, the already-recorded
link:../warm_storage/concepts/workflow_coordinator_front_door_stage1_commission_test_burden_finding_2026-10-25.adoc[Front
Door Stage 1 Commission test-burden finding], which is about permanent
per-Commission test *count* and *runtime* (7,731 lines, 44 tests, 42
`_materialize_bundle()` calls per full run), not about temporary-file
*retention*. The two may share an underlying contributor -- repeated
environment/repository materialization -- but neither finding established
that relationship, and this BUG does not assume it.

== Why this is undesirable

Local test execution is ordinarily expected to be a closed loop: temporary
material it creates should not accumulate to the point of affecting
unrelated operations on the same host, let alone interrupting a WFC Run that
has nothing to do with the test suite's own temporary-file usage beyond
sharing the same `/tmp`. A full `/tmp` is a shared-resource failure mode
that can recur with any process that writes there, not only a WFC Run; this
particular incident happened to surface it, but the underlying resource
pressure is a test-infrastructure concern independent of WFC.

== Disposition

The repository correction is implemented for review; the BUG remains open
until independent review and trusted acceptance evidence support closure.
The broader link:FTR-WFC-SELF-DEVELOPMENT-EXECUTION-INTEGRATION-DEBT.adoc[execution integration debt]

== Observation, 2026-11-19 (scratch retention)

The root filesystem reached 100% inode use (31.1 million of 31.2 million)
with 280 GB in `~/wfc-scratch`; a completed Attempt retained roughly 0.5-1.5
million inodes of test fixtures and clones. Removing the scratch of 74
archived Attempts reduced use to 22%. Moving scratch from `/tmp` had earlier
displaced the same exhaustion to the new location. Operational consequence:
the Operator removes an Attempt's scratch after a successful archive (see the
operator manual, scratch cleanup after archival). The retention cause itself
remains open here.
