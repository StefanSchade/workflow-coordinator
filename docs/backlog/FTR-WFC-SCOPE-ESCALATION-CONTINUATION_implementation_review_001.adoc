== Blocking implementation defects

=== B1 -- The layered stop loses the required mechanical-anomaly publication and is tested only synthetically

`reduce_result()` captures `SemanticStop` before it selects a mechanical stop,
which is the correct ordering. However, mechanical facts are passed only into
`_stop_for_human()` as `stop_reason`; they are never appended to
`Run.anomalies`. A direct reduction with a scope escalation and
`repository_anomaly="dirty tracked state; trusted_commit:commit intent is not
permitted"` yielded:

[source,text]
----
status=awaiting_human
stop_reason=mechanical_preemption:dirty tracked state; trusted_commit:commit intent is not permitted
anomalies=()
semantic_stop=SemanticStop(kind='scope', question='May scope widen?', source_hop_id='H001')
----

Consequently `run.json`, checkpoint, status, and operator summary publish an
empty mechanical-anomaly list for the observed failure class, contrary to the
task's explicit requirement that mechanical anomalies be present alongside the
semantic stop.

The added reducer test does not exercise the required boundary. It manually
places both dirty-state and forbidden-CommitIntent prose in one synthetic
`MechanicalFacts.repository_anomaly`; it supplies no `CommitIntent`, creates no
dirty tracked candidate, does not pass through `vertical.run_one_hop()` or the
operator, and checks neither `Run.anomalies` nor durable publication, replay,
route/Finding non-application, or commit absence. `tests/unit/test_operator.py`
and `tests/architecture/test_replays.py` are unchanged.

Required correction: retain the controlling mechanical stop while durably
recording its structured diagnostic facts, and add the exact operator/vertical
regression required by the FTR: `scope_changed=true`, `requires_human=true`, a
scope escalation with its exact question, real dirty tracked state, and a
forbidden CommitIntent. Assert the complete `run.json`, checkpoint, operator
summary, serialization/replay, no-route, no-Finding, no-commit, and
same-Run-recovery behavior.

=== B2 -- Successor launch accepts forged or changed descriptors and fabricates provenance

`_successor_context()` checks only that four descriptor-supplied successor
values equal the newly admitted repository, HEAD, path map, and governing
digest map. It does not strictly parse the descriptor, reject unknown fields,
locate and digest the predecessor `run.json`, validate the predecessor status
or semantic stop, or re-read and digest the authority decision. It also has no
expected descriptor digest against which to detect descriptor mutation after
preparation. Instead it hashes whatever bytes exist at launch and records that
new digest as provenance.

A direct probe added an otherwise forbidden `permitted_routes` field and used
`RUN-invented`, `WI-invented`, a `completed` predecessor, a null semantic stop,
a false predecessor-state digest, and a nonexistent authority-decision
reference with an invented digest. `_successor_context()` accepted the
descriptor and returned `SuccessorProvenance` carrying the invented identities.
The launch path then installs this record on a fresh Run. `run_to_json()` does
not validate a constructed dataclass before the provider-capable path writes
it, so this is not repaired by the strict JSON loader.

This violates the backward-provenance truth boundary, the requirement that
descriptor changes after preparation fail digest validation, and the rule that
a descriptor cannot become semantic authority or fabricate historical truth.

Required correction: give the descriptor a closed, strictly validated shape
including all accepted content, revalidate predecessor identity/status/semantic
stop/state digest and the authority-decision bytes/reference at launch, reject
any post-preparation descriptor mutation, and construct provenance only from
those revalidated facts. Add pre-provider rejection tests for every mismatch,
unknown field, source mutation, and forged provenance case.

=== B3 -- Salvage is not bound to its predecessor and the successor context is incomplete

`prepare-successor` validates object hashes in a supplied manifest but never
compares the manifest's `source.run_id`, `source.hop_id`, repository, base/current
HEAD, or `run_json_sha256` with the predecessor being prepared. A structurally
valid bundle from another Run or repository can therefore be attached to the
descriptor and exposed as though it were this predecessor's salvage.

At launch, the context contains only a warning, five authority labels, and the
selected decodable object text. It omits the required predecessor provenance,
manifest omission diagnostics, complete file/object inventory, and the
`automatic application/execution: forbidden` classification that every context
projection must repeat. There is no stable manifest-level binary
classification; any selected bytes that happen to decode as UTF-8 and contain
no NUL are treated as textual content. The accepted boundary requires omitted,
unselected, binary, and over-limit bytes to remain out of the prompt while the
inventory and omission facts remain visible.

Required correction: bind a manifest and every selected hash to the exact
validated predecessor and repository facts during both preparation and launch;
strictly validate the complete manifest; render the mandatory provenance,
inventory, omissions, and full trust classification; and prove that only
explicitly selected, classified-text, within-limit objects contribute raw
bytes.

=== B4 -- `export-salvage` violates the no-index-mutation and publication-verification contract

`_export_salvage()` calls `observe_repository()` while building its manifest.
That helper runs ordinary `git status` without disabling optional locks. Git may
refresh and rewrite the index even when repository content is unchanged. A
disposable-repository probe changed only a tracked file's timestamp and then
called `observe_repository()`; the `.git/index` SHA-256 changed. The accepted
export contract explicitly forbids HEAD, index, worktree, and predecessor-state
mutation.

Publication checks are also incomplete: export sets modes on object paths but
verifies only the top-level temporary directory and `manifest.json`, not the
objects directory and every published object. The manifest always records an
empty omissions list, including when ignored content is deliberately excluded.
No test covers index identity, HEAD/worktree/predecessor byte identity,
directory and object modes, partial/finalization failure, unsafe destinations,
symlink/special-file refusal, limits, stable object identities, or tamper
detection.

Required correction: make every export Git observation genuinely non-mutating,
capture and assert pre/post HEAD/index/worktree/predecessor identity, verify
owner-only modes for the final directory tree and every regular file, publish
accurate omission diagnostics, and implement the accepted containment,
atomic-finalization, limit, and tamper tests in the authorized operator and
Git-fact test paths.

  `RUN-76e153b40ef1459db4587446b18e02d5`;
* backward-only provenance, different Run identity, and absence of inherited

The green full suite therefore establishes only that the sparse new tests and

Required correction: add the complete accepted test matrix within the six
already authorized ordinary test paths. Do not weaken those criteria to mirror
the current implementation.

=== R1 -- Tracked salvage bypasses the symlink and binary-exposure boundaries

`salvage_inventory()` applies `resolve()`, symlink, regular-file, and byte-size
checks only to untracked files. Changed tracked paths are admitted wholesale
through one `git diff --binary` object. A changed tracked symlink can therefore
point outside the repository and still be exported, contrary to the explicit
escaping-symlink refusal requirement.

The same aggregate tracked-diff representation defeats the new content
classification. Git's binary patch is printable UTF-8 without a NUL byte, so
`_export_salvage()` labels an object containing a tracked binary change as
`content_kind=text`. `_successor_context()` consequently renders it when its
hash was selected. The accepted design requires binary content to remain
referenced but never injected.

The manifest also still hard-codes `omissions: []`; it does not publish the
accepted omission diagnostics for deliberately excluded ignored or other
non-captured material. Thus the inventory visible to a successor is not a
complete account of capture omissions.

Required correction: classify and validate every tracked candidate path before
publication, reject escaping tracked symlinks and unsafe tracked objects, keep
binary patches out of raw successor context, and publish truthful omission
diagnostics. Add real export/prepare/launch tests for tracked and untracked
text, binary data, symlinks, special files, scope, limits, selection, omission,
tampering, and prompt projection.

=== R2 -- Export finalization failure can leave a consumable bundle

`_export_salvage()` renames the temporary directory to the final output and
then verifies final modes. If that verification fails, the exception cleanup
walks and removes only the old temporary path, which no longer exists after
the rename. The final output -- including `manifest.json` and all objects -- is
left in place and passes the normal manifest parser. This contradicts the
accepted rule that an unsuitable permission or finalization failure leaves no
valid bundle.

Required correction: make final publication and verification fail closed so
every reported failure leaves no consumable manifest at the requested output,
without weakening atomic new-directory publication. Cover injected write,
rename, permission, post-rename verification, and cleanup failures, and assert
the exact resulting filesystem state and owner-only modes.

=== R3 -- The continuation descriptor is still incomplete and its selection receipt is not an immutable anchor

The accepted descriptor content includes creation time. The corrected closed
shape has no creation-time field. More importantly, post-preparation integrity
depends on a mutable sibling `.sha256.json` receipt. Replacing a descriptor and
updating that sibling digest passes the receipt check and the self-integrity
check. Although predecessor, authority, and governing facts are independently
revalidated, `salvage.selected_objects` is not independently anchored; changing
both files can expand raw provider exposure beyond the hashes the operator
explicitly selected during preparation.

Required correction: include all accepted descriptor fields and bind launch to
the exact descriptor identity produced by the explicit preparation act so a
post-preparation descriptor change -- especially a changed raw-object
selection -- fails rather than becoming a new implicit selection. Add
pre-provider tests for descriptor-only and descriptor-plus-receipt mutation.

=== R4 -- The required acceptance matrix remains substantially unimplemented

The H002 B1/B5 coverage defect is not corrected by four small tests. In
particular, there is still no operator/vertical test constructing the required
real ordering of `scope_changed=true`, `requires_human=true`, scope escalation,
dirty tracked state, and forbidden `CommitIntent`, then asserting run snapshot,
checkpoint, summary, replay, no route/Finding/commit, and recovery rejection.

There are also no end-to-end tests for `export-salvage`,
`prepare-successor`, or a successor launch. Consequently the suite does not
exercise legacy/null/absent-Hop predecessor rejection and byte preservation;
the named historical no-back-patch case; predecessor/authority/governing/
descriptor/salvage mutation; clean baseline and identity enforcement;
backward-only provenance with no inherited Findings or evidence; restrictive
publication and failure atomicity; sensitive-content language; selected versus
unselected/binary/over-limit rendering; no-salvage launch; or independent
successor evidence and commit disposition.

The serialization/persistence additions likewise do not cover malformed or
missing non-null v2 `SemanticStop`/`SuccessorProvenance`, read-only legacy
status/replay/predecessor byte preservation, a v1 reconcile/resume transition,
or an injected failed v1-to-v2 write preserving the exact pre-change fixture.

Required correction: implement the accepted FTR's complete six-part test
matrix within the already authorized six ordinary test paths. Tests must
exercise public/operator boundaries and failure effects rather than merely
mirror helper implementation.
