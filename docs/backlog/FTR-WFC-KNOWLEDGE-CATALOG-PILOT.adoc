== Problem and practical benefit

The knowledge architecture is already documented and is not re-planned here:

* *Current documentation* — distilled present knowledge: the Operator Manual, Developer Guide, architecture overview
  and three models.
* *Warm storage* (`docs/warm_storage/concepts/`, 68 files at the baseline) — active investigations, unresolved
  alternatives, concepts in development, reviews still serving that work.
* *Cold storage* (`docs/cold_storage/`, 191 files, 94 with `review` in the name) — inactive long-term memory:
  valid earlier knowledge, rationale, rejected alternatives, historical reviews, parked ideas. Inactive does not
  mean invalid; its size is a retrieval problem, not a reason for deletion or for hiding it.
* *Project Memory* (`project_memory/canonical/`: 9 concerns, 46 concern events, 83 event-concern relations, 23
  decisions at the baseline) — curated strategic and operational memory, deliberately lossy.
* A *derived retrieval layer* — the one part that does not yet exist.

The existing homes are described in link:../ai_info/doc_conventions.adoc[the conventions' knowledge-homes section],
link:../ai_info/_ai_info.adoc[the router], link:../cold_storage/README.adoc[the cold-storage orientation] and
link:../research/context_sculpting_and_knowledge_lifecycle.adoc[the lifecycle research]. Three concrete gaps remain:

. *No lookup by identity or reference.* A reader or agent can find an inactive source through a hand-written group
  README, the narrative project history or a labelled link from a current source. There is no way to ask "which
  documents carry this WorkItem, BUG or FTR identifier", "what is the title of that file" or "what links to this
  document" without repository-wide text search and reading. Recent work paid this cost by hand (the C4 consumer
  assessment, the inbound-link inventory in the models record).
. *Convention silence.* The conventions say "No uniform metadata block or parallel index classification is required"
  and that the knowledge guidance "adds no metadata, lifecycle states, inventory or approval procedure". They do not
  say whether a *derived* index is allowed. Without a statement, either reading blocks or silently licenses it.
. *No router entry.* The router has a row for retrieving an inactive source, but none for locating a document of any
  home by title, identifier or reference.

Practical benefit: cheap, reproducible lookup over all homes (cold included), a mechanical inbound-link query that
makes later conversions and retirements verifiable, a join key set for the operational provenance pilot, and a
mechanical integrity check on Project Memory `source_path` values — without a manually maintained second copy of
anything.

[[metadata-decision]]
== Reconsidering the metadata decision for the retrieval use case

*What was decided.* Writing conventions replaced the earlier mandatory metadata model and its central classification
upkeep. Existing headers need no bulk migration; no uniform block, no parallel index classification, no lifecycle
states are required.

*What the retrieval use case changes.* At 357 documents, with 191 inactive ones outside normal reading, lookup by
identity and reference is a recurring cost, and agents (which cannot "just remember" the tree) pay it each Run. That
need is real and was not what the November plan weighed. It is, however, a need for *access*, not for *declared
status*: retrieval needs "where is it, what is it called, what does it point to", not "is it current".

*What it does not change.* The reasons for the decision still hold: hand-maintained metadata drifts, bulk migration
of historical documents is expensive and violates "historical bodies stay unchanged", and a status copy beside the
controlling source creates a second authority. The catalog therefore must be derived from repository content and
must not carry status, authority or maturity.

Candidate inputs, evaluated:

|===
|Input |Decision |Reason

|`Status::`, `Type::`, `Authority::`, `Maturity::` values

|Outgoing local links (resolved to repository-relative paths, fragments dropped)

|Do not commit; query-time only (and in the provenance pilot)

*Decision proposed by this record: keep, with a narrowing.*

. *Keep*: no mandatory or uniform metadata, no bulk migration, no hand-maintained parallel classification or status
  index, no new lifecycle states.
. *Narrow* the convention text so that a *derived, regenerated* catalog is explicitly allowed and explicitly not an
  authority, a status index or a classification. The catalog reads a fixed, small set of facts that documents already
  state (above) and requires nothing new of any document.

Affected text, to be edited only after Maintainer approval of D1 (Commission K1, not this planning Run):

* `docs/ai_info/doc_conventions.adoc`, section "Make standing clear where it matters": the sentence "No uniform metadata
  block or parallel index classification is required:" gains a following paragraph (wording below).
* The same file, section "Knowledge homes", last sentence: "This guidance adds no metadata, lifecycle states, inventory
  or approval procedure." becomes "…no metadata, lifecycle states, manually maintained inventory or approval procedure."
* `docs/README.adoc` ("does not maintain a second copy of document metadata or feature status") stays true and
  unchanged in meaning; one bullet under "Other sources" points to the catalog and repeats that it is derived.

Proposed paragraph for the conventions:

[quote]
____
A derived document catalog may index documents from repository content alone: path, title, identifiers in the title or
file name, the review identity fields a document already carries, and outgoing links. It is generated, never edited by
hand, can lag, and carries no status, authority, maturity or classification; a missing entry never means a missing
document and an entry never makes a document current. It makes no header field mandatory, and it does not read
`Authority::`, `Owns::`, `Maturity::` or `Updated::`.
____

== Catalog design

[cols="2,5",options="header"]
|===
|Aspect |Decision
|Scope
|Every `*.adoc` and `*.md` under `docs/` (warm and cold included, treated like any other), excluding the catalog's own
file type (`.jsonl`). Governance Commission artifacts, source and Project Memory are not records; the provenance pilot
reads Commission directories itself. Nothing is moved, renamed, deleted or edited by generation.
|Record fields
|`path`; `title` (or null); `home` and `group` (path-derived, location only); `name_tags` (zero or more of `bug`, `ftr`,
`review`, `readme`, `chapter`, `dated`, from the file name only); `date_in_name`; `ids` (title/file-name identifiers);
`declared` (the four identity header fields, verbatim, when present before the first section heading); `links`
(sorted unique repository-relative targets of `link:`, `xref:` and Markdown links, fragments dropped, document-level
attributes such as `{operator-docs}` expanded; external URLs ignored; an unresolvable target is omitted from the record
and reported by `check`, never fabricated). No status, authority, maturity, type, update-date or Git field.
|Format and location
|JSON Lines, one object per line, sorted by `path`, fixed key order, first line a metadata object stating "derived;
generated by `scripts/wfc_doc_catalog.py`; not an authority or status index". File:
`docs/ai_info/document_catalog.jsonl`, next to the router that links it (no new directory). Line-per-document keeps
diffs and merges line-local, greppable by agents without tooling. Expected size: a few hundred KB; the implementation
stops and reports if it exceeds 1 MiB.
|Reproducibility
|A pure function of the working-tree content of the scanned files: no network, no Git call, no clock, no environment
dependence; run on a clean checkout. Two runs are byte-identical.
|Committed versus regenerated
|The generated file is committed so that checkouts and Runs can read it and the router link works; it is never hand-edited.
Git-derived facts are never committed (query-time `--git` is left to the provenance pilot).
|Staleness detection
|`make doc-catalog-check` regenerates in memory and compares with the committed file; exit 1 with a concise added/removed/
changed-path list on drift. The catalog is stale only when a derived fact changes (new, removed or renamed file, title,
identifier, link) — a plain edit that changes none of them does not stale it, so there is no per-edit date or hash churn.
`check` also reports, informationally, links whose targets do not exist and Project Memory `source_path` values absent
from the catalog; neither fails the check. The check is *not* added to `make check`, to the default test suite, to CI or
to a Coordinator evidence profile: otherwise every documentation Commission would have to name and regenerate the
catalog. Whether to wire it into evidence later is a deferred Maintainer option, stated with that cost.
|Exposure
|(a) A router row in `docs/ai_info/_ai_info.adoc`: need "Locate a document by title, identifier or what links to it",
open first the catalog and the `query` command, "load history only when" a bounded question needs earlier sources, with
the retrieval-confers-no-authority sentence; (b) one sentence in the selective-retrieval part of
`docs/cold_storage/README.adoc`; (c) one sentence in `docs/project_memory.adoc` saying Project Memory records cite
documents by `source_path`/`commit_refs` and the catalog can locate and check those paths, with *no* new Project Memory
table or canonical-data change; (d) the one `docs/README.adoc` bullet above. The router remains the only agent-facing
entry; no second index.
|Query surface
|`python3 scripts/wfc_doc_catalog.py query` with `--id`, `--title`, `--refs-to PATH` and `--refs-from PATH`, reading the
committed catalog (`--live` regenerates in memory). Output: path and title. `generate` and `check` complete the three
subcommands.
|Authority guard
|The file header and every exposure sentence say: derived, can lag, a location or entry confers no standing. The
catalog is never an input to Run admission, never cited as authority for a Finding, route or acceptance, and has no
write path to any document.
|===

== In scope

* `scripts/wfc_doc_catalog.py` (generate, check, query; stdlib only; not imported by `src/workflow_coordinator/`) and
  `tests/unit/test_wfc_doc_catalog.py` using small fixture trees, covering: guarded and unguarded titles, Markdown titles,
  files without titles, attribute-expanded links, identifier extraction limited to title/file name/identity fields,
  deterministic ordering, exclusion of status-type fields, drift detection on title/link/rename.
* Makefile targets `doc-catalog` (write) and `doc-catalog-check` (read-only), documented briefly where the Makefile's
  other tooling targets are documented.
* The first committed `docs/ai_info/document_catalog.jsonl`.
* The convention, router, cold-storage, Project Memory orientation and authority-index edits in <<metadata-decision>>
  and the exposure row above — five small edits to existing documents, after D1.
* A retrieval walk-through and a size/drift report in the work result.

== Out of scope

* Any new header, field, lifecycle state, metadata migration or edit to a historical document; any move, deletion or
  retirement of warm or cold material.
* Status, freshness, ranking, "current/inactive" or relevance fields; Git-derived committed data; semantic search,
  embeddings, RAG, a retrieval service or MCP (all later options named in the lifecycle research, none selected).
* A new Project Memory table, a Project Memory generator or any edit to `project_memory/canonical/`.
* Any `src/workflow_coordinator/` change, new WFC runtime mechanism, Coordinator evidence command, program or profile.
* Wiring the check into `make check`, CI or evidence (deferred, see above).

== Acceptance criteria

Verified by the Worker and independently repeated by the reviewer on the candidate checkout; Coordinator `task-check`
is separate.

. `make doc-catalog` run twice produces byte-identical files, with no network access and no Git call (the test or
  review demonstrates this by running outside a Git work tree or with Git unavailable).
. The record count equals the number of `*.adoc` and `*.md` files under `docs/` at the candidate commit; every record
  `path` exists; no record exists for a missing file.
. Fixture tests pass for each case listed in "In scope"; `make check` (lint, format, tests) passes; the default test
  suite contains *no* test that compares the committed catalog with a regenerated one.
. No record contains `Status`, `Type`, `Authority`, `Maturity` or `Updated` values (test plus a reviewer search of the
  committed file); `ids` contain no token that appears only in a document body.
. `make doc-catalog-check` exits 0 on the committed state and exits non-zero, naming the path, after a title change, a
  renamed file and an added link in a scratch copy.
. The three walk-through questions are answered correctly from the catalog and verified by the reviewer against the
  repository (including that no result is presented as "current").
. Reported size is below 1 MiB, or the work stops with a report instead of committing.
. The five edited documents render without warnings, all their relative links and fragments resolve, the router row
  links the catalog and the query command, and the edited wording matches the version the Maintainer approved in D1.
. The diff touches only: the script, its test, the Makefile, the catalog file, the five named documents and the declared
  review artifacts; no historical document, `project_memory/canonical/` file, `src/` file or governance file changes.

== Risks and controls

[cols="2,4",options="header"]
|===
|Risk |Control
|Source authority: the catalog is read as a status or authority list.
|No status/authority/maturity fields; fixed disclaimer in the file header, router row and conventions; `home` is
location; excluded from admission and evidence.
|Metadata drift.
|Nothing is hand-maintained; all fields are derived; `check` detects drift; no per-edit date/hash.
|Knowledge loss.
|Nothing is moved, edited or deleted; cold material is catalogued like any other; no relevance ranking hides it.
|Misleading identifiers or links.
|Identifier extraction limited to title/file name/identity fields; unresolved links reported, never invented;
`ids` and `links` are retrieval hints, to be verified in the opened document.
|Merge conflicts and churn on a committed generated file.
|Line-per-document, sorted; conflicts resolved by regeneration; not in the default checks, so unrelated Commissions are
not forced to touch it.
|Staleness unnoticed.
|`doc-catalog-check`, an "may lag" statement everywhere the catalog is exposed, and regeneration at the next
catalog-touching Commission.
|Heavy governance creep.
|No new role, lifecycle, approval or mandatory field; one script, two Makefile targets, one data file, five small edits.
|Script lives in the same place and style as existing maintainer tooling but could be mistaken for runtime.
|Not under `src/`, not imported by the package, stated in its docstring and in the Makefile comment.
|===

== Mechanical versus human judgment
