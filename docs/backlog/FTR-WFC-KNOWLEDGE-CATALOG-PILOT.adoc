== Purpose and boundary

Enable inexpensive lookup across `docs/`, including warm and cold storage, by document identity, title and local references. A catalog entry is a navigation hint, not evidence that a document, implementation or Finding is current or accepted. Readers inspect the original source and applicable authority. The index may lag and absence of an entry does not prove absence of a document.

Do not require metadata headers, manually classify documents, migrate historical material, invent lifecycle states, or modify canonical Project Memory. Raw source declarations may be projected as labelled data; they are not inferred classifications. No embeddings, semantic retrieval, retrieval service, MCP, Coordinator or runtime changes are part of K1.

== Catalog data and operations

Scope:: Scan every `*.adoc` and `*.md` under `docs/`, including warm and cold; governance, source code and Project Memory are not document records. Do not alter scanned files. No full include expansion, AsciiDoc parser or hierarchy reconstruction is promised.
Fields:: One record per source file: repository-relative `path`, document `title` or null, first substantive `section_title` or null, path-derived `home` and `group` (location only), filename-derived `name_tags` and `date_in_name`, `ids` restricted to file name, title and supported identity header values, supported raw `source_declarations`, and sorted unique local `links`. The bounded supported headers are `WorkItem`, `Run`, `Hop`, `Candidate`, `Type`, `Status`, `Authority`, `Maturity` and `Updated`; preserve values verbatim when present, label them as source declarations and do not synthesize absent values. Actual heading detection should handle guarded standalone titles and AsciiDoc/Markdown section headings without mistaking the document title for a section. Do not classify by header value. Filename tags and location describe names and paths only.
Links:: Extract applicable local `link:`, `xref:` and Markdown links, expanding document-local attributes when resolvable; use repository-relative paths with fragments dropped. Exclude external URLs. Do not fabricate unresolved targets; report them as informational diagnostics. Include handling is explicitly limited; do not imply assembled-document dependency analysis.
Format:: JSON Lines, deterministic fixed field/key ordering, records sorted by path. A leading metadata object states it is generated, derived and non-authoritative, and source declarations are unverified. No clock, environment-dependent or Git-derived record values. Retain the existing pilot limit of 1 MiB: report and stop if exceeded; do not replace a previous successful output.
Generate:: `python3 scripts/wfc_doc_catalog.py generate`, also `make doc-catalog`, creates parent directories and writes an atomic same-filesystem replacement only when bytes differ. Failure must leave an existing successful file intact. No Git call, network or clock dependency. The existing `build/` ignore rule may be reused after verification; add a narrower ignore rule only if necessary.
Query:: `query --id`, `--title`, `--refs-to PATH`, `--refs-from PATH`, reading the existing generated file by default. `--live` explicitly regenerates in memory without writing. A missing file fails with a clear command to generate it. No automatic invalidation, regeneration or review-Hop update. Queries must not claim raw declarations are current facts.
Check:: `check`, also `make doc-catalog-check`, compares the existing file with a fresh in-memory projection and reports added/removed/changed paths on drift; missing file gives an actionable error. Report unresolved local links and Project Memory `source_path` values absent from the catalog informationally, not as drift or authoritative status. Check is not part of `make check`, default tests, CI or Coordinator evidence.

== Acceptance criteria

Worker checks and fresh independent review inspect actual behavior; Coordinator `task-check` is separate.

. Two offline/no-Git generations of identical fixture and real-tree input are byte-identical; a second unchanged generation leaves the output's existing file identity/mtime unchanged. Changed output is atomically replaced, and simulated generation/write failure preserves prior bytes. No network, Git or clock is consulted.
. Each scanned source has exactly one record and every record resolves to a source; the output remains below 1 MiB. Verify Git ignores the output and no generated JSONL is committed.
. Supported header declarations are copied as raw source-labelled values when present; missing fields are absent or null consistently, no mandatory headers appear, and no derived current status/authority/classification is asserted. Identity extraction and `--id` exclude body-only mentions.
. Fixtures cover guarded titles, Markdown and AsciiDoc section titles, no title/section, attributes, local links, limited headers, stable ordering, duplicate/unresolved inputs, missing catalog, explicit `--live`, stale catalog, changed title/section/link/rename and atomic/no-rewrite/failure behavior. No full include resolution is claimed.
. `query` with a missing file fails with explicit generation guidance; default query leaves an existing stale file untouched; `--live` uses in-memory input without changing it. `check` reports staleness and is not wired into normal tests, CI or Coordinator evidence. Informational broken-link and Project Memory reports do not imply authority.
. The walk-through verifies real identity, inbound-reference and cold-group queries against repository sources and demonstrates the body-only identity boundary. Each exposure explains local generation, possible staleness and non-authority.
. Relevant tests and `make check` pass. Render edited AsciiDoc without warnings and check local links. Diff is limited to declared scope, with no generated output, historical source or canonical Project Memory changes. Fresh independent review has no blocking Findings and Coordinator `task-check` passes.
