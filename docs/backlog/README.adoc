= WFC backlog

link:_open.adoc[The current backlog overview] is the sole authority for
current priority, ordering, readiness and dependencies. Each open task retains
one identifiable technical BUG/FTR record for scope, decisions and milestone
evidence. Overview summaries link to those sources; historical priority labels
are provenance, not today's release gate.

== Upkeep at actual milestones

Update the controlling BUG/FTR at the milestone that actually occurred,
including the affected slice and available evidence:

* *Implementation:* the implementer records what changed, the implementation
  commit when known, checks and remaining work. Say when independent acceptance
  is still outstanding; passing local checks is not acceptance.
* *Independent acceptance:* after the configured independent review and
  required Coordinator checks establish the outcome, the responsible maintainer
  records it with review/Run evidence. Preserve rejected or stopped outcomes;
  an agent's reported success alone does not establish recorded acceptance.
* *Product closure:* the responsible maintainer records closure only when the
  issue's remaining product obligations are met, including qualification,
  integration or Runtime promotion where required. Implementation acceptance
  alone does not close the issue; no new closure approval role is introduced.

Each actor edits only within their actual authority and WorkItem scope. If the
record is outside scope or the milestone occurs after the actor's Hop, identify
the exact record and needed update in the result/handoff for the responsible
maintainer to complete. Do not invent commit IDs, acceptance or closure, or
change configured Coordinator/review rules to satisfy this upkeep convention.

The maintainer updates link:_open.adoc[the overview] when current priority,
readiness or dependencies materially change, keeping any status summary
consistent with its controlling source. Do not copy every lifecycle event into
another ledger. For behavior changes, the implementer also follows
link:../ai_info/doc_conventions.adoc[documentation upkeep] in the same WorkItem;
no documentation impact means no forced documentation edit.

== Supporting sources

Keep scope, decisions and milestone evidence in the controlling record; link
to current models for durable explanations and the Operator Manual for operating
procedures. Relevant investigations, unresolved alternatives, active plans and
developing concepts can remain warm while supporting the work. A completed
review is evidence of its bounded outcome, not a second priority list or an
automatic instruction to archive its subject.

The link:beta1_productization.adoc[Beta-1 package map] connects existing
sources and open decisions without duplicating specifications or establishing
implementation acceptance. The link:../research/README.adoc[research register]
holds open technical questions about future capabilities, not another backlog.

Completed sources, reviews, plans and closure evidence -- including a fully
accepted and integrated plan, such as the Post-Beta P2 documentation plan, or
a fully resolved BUG, such as the Claude adapter short-`TMPDIR` incident --
go into the appropriate backlog archive. The
link:../cold_storage/backlog/pre-0.1.0b1/beta1-delivery-chronicle/README.adoc[Beta-1
delivery chronicle] is an existing workstream group. The
link:../cold_storage/backlog/post-0.1.0b1/README.adoc[post-0.1.0b1 backlog archive]
indexes records retired in the backlog clean-up. See
link:../cold_storage/README.adoc[the cold-storage convention]. Material not yet
curated there remains under `../cold_storage/backlog/history/` or at its
existing path. Location or an old planning header alone does not establish
current implementation status. Reconcile stale active-record text when its
owning work reaches a milestone; do not rewrite historical reviews.
Cold is inactive long-term memory, including valid parked ideas and original
rationale. Retrieval does not confer current authority; reassess conclusions
against current sources before reuse. The
link:../ai_info/doc_conventions.adoc#_knowledge_homes[knowledge-home guidance]
explains current, warm and cold placement without a separate lifecycle registry.
