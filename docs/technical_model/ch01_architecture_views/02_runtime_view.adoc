== Runtime View

== One Hop end to end

`vertical.py:run_one_hop` is the single ordering that matters:

[source,text]
----
select result contract kind + version      (model.py)
preflight_hop: repository identity, HEAD, cleanliness   (git_facts.py)
allocate hop_id = H{hop_used+1:03d}
assemble_prompt: A3 digest check, [identity] header, selected components,
    persona (authority=none), workflow_policy, task, bounded context/diff
    with visible omissions                              (prompt.py)
adapter.execute(AgentExecutionRequest with permitted_routes)  (adapter.py)
transport check: returncode/timeout, candidate present
validated_result: envelope keys, version, exact run/hop/invocation match,
    then family-specific parse                          (adapter.py)
CommitIntent (if any): disposition permitted? phase grants edit AND commit?
    -> trusted_commit, else observe_hop                 (git_facts.py)
post-acceptance anomalies: commit subject, durable artifact
evidence: run each phase evidence command, re-validate each Observation
post-evidence: HEAD unmoved, worktree still clean
reduce_result(run, result, profile, facts=MechanicalFacts(...))  (reducer.py)
checkpoint_projection + atomic persistence              (persistence.py)
----

Two deliberate properties: the transport outcome is separated from semantic
acceptance (`ExecutionResultValidationError` carries the completed outcome with
the rejection), and evidence runs *after* the trusted commit but its result can
still override the requested route, so a failing check cannot be committed away.


This view describes current Development source, not promotion of it to the
separately pinned execution Runtime. It is explanatory and grants no authority;
source and tests define behavior.

Updated:: 2026-11-20 -- commissioning, frontdoor, operator, vertical,
persistence and tests inspected after BP7 retirement.

The maintainer supplies a Consumer Request/Config; `commissioning.
compile_commission` projects governing inputs. `wfc plan` previews that
projection read-only; `wfc run`/`resume` commit it, then call
`frontdoor.verify.verify_commission` -- re-compile and compare, then
provider-free operator preflight -- before admitting anything. Once that
passes, `wfc run`/`resume` launch the pinned Runtime's own installed `wfc`
against the Development checkout. The operator admits inputs, creates Run state, and
`run_serial_hops` calls `slice4.run_real_one_hop`, which invokes `vertical.run_one_hop`, until reduction stops or completes.
`RunStatus` defines `ready`, `running`, `awaiting_supervisor`,
`awaiting_human`, `awaiting_human_budget`, `suspended`,
`reconcile_required`, `completed`, and `stopped`; only the last two are
terminal names. See the link:{tech-docs}/operator_manual/operator_manual.adoc[Operator Manual]
for procedures and the link:{tech-docs}/operator_manual/ch04_evidence/02_archive.adoc#archive[archive procedure].

For each Hop, the operator passes admitted Run, profile and prepared evidence
to `vertical.run_one_hop`. Vertical asks Git for preflight, prompt for a bounded
invocation, and the selected adapter for transport. The adapter returns an
outcome and candidate; validation binds the result to Run, Hop and invocation.
Vertical then asks Git to observe or execute a permitted Coordinator-owned
CommitIntent, asks the evidence runner to observe prepared commands, validates
observations, and passes mechanical facts and the result to the reducer.
Persistence publishes the resulting Run and checkpoint and execution evidence.
Run state and Hop observations are separate from an eventual archive; an agent's
own checks or evidence references do not become Coordinator-trusted observations.

* On accepted transport and a valid result, `reduce_result` checks authority,
  applies lawful Finding deltas and selects the declared route; completion is
  still subject to blocking Findings and other guards.
* A failed transport or rejected envelope is not semantic acceptance, even if
  a candidate exists. The serial driver records the applicable failure and
  stops; `test_failed_provider_transport_with_a_valid_candidate_recovers_uncertain_without_evidence`
  covers the separate Slice-4 recovery boundary, and
  `test_nonzero_fake_transport_failure_is_truthful_and_not_retried` covers
  transport failure.
* Required evidence is run after a trusted commit. A valid failing observation
  substitutes the declared failure route; invalid observation or mechanical
  anomalies can stop instead. `test_required_evidence_failure_route_precedes_escape_substitution`
  and `test_post_evidence_git_reobservation_preempts_normal_completion` cover
  these distinctions. `test_closed_terminal_worker_required_evidence_never_applies_accept`
  covers the closed terminal-worker exception.
