== Programs, Commissions and the Front Door

Three closed program records live at
`governance/workflow-programs/{simple,direct,robust}/v1.yaml`. Each is
hand-authored governance: `operator.py:_admit_a1` unconditionally forbids any
WorkItem or profile `authorized_scope` from overlapping the repository policy's
`governance_paths`, so no Run can ever write one. A correction is a new
revision.

`commissioning.py` turns a maintainer-authored Commission Intent into ordinary
governing inputs:

[source,text]
----
governance/commissions/<id>/intent.yaml
   | commission_intent_from_yaml  (closed key sets, duplicate-key rejection)
   v
_load_sources: read program/policy/components at their pinned source commits,
   then require the program to equal the in-source literal template exactly
   (minus its `source` provenance block), and the policy basis to equal the
   immutable repository-standard@v1 record
   v
render_commission: substitute declared slots only
   scope slot S   -> the Intent's normalized scope
   artifact slot A -> exactly durable_artifacts[artifact_key], never unioned
   evidence slot E -> evidence_profiles[<selected profile>].evidence
   v
governance/commissions/<id>/{work-item,profile,policy}.yaml, task.md,
render-manifest.json
----

Three facts follow from that code and matter for understanding:

* Program identity is checked against an *in-source template*
  (`_direct_template`, `_robust_template`, `_simple_template`), not only against
  the file. `program_specs` admits exactly the three `(id, revision)` pairs and
  rejects everything else, so editing a catalogue file alone cannot change an
  admitted program.
* The rendered profile carries `schema_version: 2` and
  `profile_id: <commission_id>-<program>-<revision>`, so one profile *file*
  still exists per Commission -- but it is a deterministic projection of a closed
  program rather than a hand-copied process. The hand-authored schema-v2 profiles
  under `governance/self-development/` predate this path.
* An Intent has no write path to phases, routes or review descriptors. It
  supplies scope, durable-artifact paths, personas, an evidence-profile
  selection and a hop limit, each separately bounded by the policy basis.

`commission check` re-renders and compares, then asks the provider-free operator
preflight to admit the bundle; it selects no provider and admits no Run. The
maintainer then prepares, inspects and authorizes launch. Procedures for all of
this are owned by
link:{tech-docs}/operator_manual/ch02_commissioning/_chapter.adoc[the commissioning chapter].
