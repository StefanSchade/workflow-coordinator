== Programs, Commissions and the Front Door

Three closed program records live at
`governance/workflow-programs/{simple,direct,robust}/v1.yaml`. Each is
hand-authored governance: `operator.py:_admit_a1` unconditionally forbids any
WorkItem or profile `authorized_scope` from overlapping the repository policy's
`governance_paths`, so no Run can ever write one. A correction is a new
revision. Only `simple@v1` and `robust@v1` are compiled by the consumer-neutral
Front Door below; `direct@v1` is deliberately withheld from it (per BP7
retirement, the historical self-development-only `direct@v1` compile path
that once existed in `commissioning.py` is removed; a `direct@v1`-shaped
WorkItem/Profile can still be hand-authored and admitted directly, like any
other governing input).

`commissioning.py:compile_commission` turns a maintainer-authored, consumer-
neutral Consumer Request/Config into ordinary governing inputs, with no
execution binding anywhere in its input or output:

[source,text]
----
ConsumerRequest (task, scope, program, personas, evidence,
                 durable_artifacts, guidance) + ConsumerConfig
   | consumer_request_from_yaml / consumer_config_from_yaml
   v
_consumer_program_template: the closed simple@v1/robust@v1 literal, with
   every phase's `repository_policy` slot filled by one shared
   `repository_policy` component id (the consumer's own committed guidance)
   v
compile_commission: substitute declared slots only
   scope slot S     -> the Request's normalized scope
   artifact slot A  -> exactly durable_artifacts[artifact_key], never unioned
   evidence slot E  -> the Request's own ordered evidence command names
   role/modifier components -> package resources (`resources/roles/*.txt`),
   digest-checked against `implementation_identity.RESOURCE_DIGESTS`
   v
<governance_dir>/<commission_id>/{work-item,profile,policy,components}.yaml,
task.md, commission-manifest.json
----

Three facts follow from that code and matter for understanding:

* Program identity comes from a Python literal (`_robust_template`,
  `_simple_template`), never a Git-pinned catalogue file: role/modifier
  component texts are package resources, not source-commit pins, so there is
  no separate per-Commission source-commit to verify against a governance
  catalogue, unlike the retired `direct@v1` compile path.
  `src/workflow_coordinator/resources/roles/*.txt` is the single live source of
  those texts; the same-named files under
  `governance/self-development/prompts/` are frozen historical copies that no
  compile path reads, and `reviewer.txt` there intentionally differs from the
  live reviewer text since that text gained the simplicity and maintainability
  review goals. A change to a role text means an edit of the package resource,
  the matching `RESOURCE_DIGESTS` pin and a new implementation identity; an
  edit of the frozen copy changes nothing.
* The rendered profile carries `schema_version: 2` and
  `profile_id: <commission_id>-<program>-<revision>`, so one profile *file*
  still exists per Commission -- but it is a deterministic projection of a closed
  program rather than a hand-copied process. The hand-authored schema-v2 profiles
  under `governance/self-development/` predate this path and remain frozen
  historical input, never compiled by it.
* A Consumer Request has no write path to phases, routes or review
  descriptors. It supplies scope, durable-artifact paths, personas, the
  ordered evidence-command sequence and a hop limit, each separately bounded
  by the Consumer Config. Since 2026-11-27 (`WI-WFC-BETA2-O7-001`) the
  program declares *which* phases are gated (`evidence: "E"` versus
  `evidence: []`) and the compiler fills every `"E"` slot with the request's
  own ordered command names -- the identical, complete list in every gated
  phase, so the Commission cannot weaken one phase's gate relative to
  another. The program literals no longer carry an `evidence_profiles`
  table.

`wfc plan` previews that compilation read-only, before anything is written;
`frontdoor.verify.verify_commission` (called by `wfc run`/`resume`) re-compiles
and compares the committed bundle, then asks the provider-free operator
preflight to admit it; it selects no provider and admits no Run by itself.
`wfc run` then authorizes and launches. Procedures for all of this are owned
by
link:{tech-docs}/operator_manual/ch02_commissioning/_chapter.adoc[the commissioning chapter].
