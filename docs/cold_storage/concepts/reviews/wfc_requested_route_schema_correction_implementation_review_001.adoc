Specific hazards checked:

Current phase versus post-result state::
The phase used for the enum is `profile.phases[run.phase]` at dispatch, and
`run.phase` cannot change before `reduce_result` (the phase moves only inside
`_apply_route`, after route resolution). The enum therefore cannot describe a
stale phase.

Routes guarded by Findings or evidence changed in the current Hop::
These guards all run *after* route lookup and either preempt or override the
agent's choice: `changes_required` + `RouteEffect.COMPLETE`, advisory-review
completion, `_apply_finding_deltas` failures,
`_validate_convergence_records_before_apply`, open-blocker completion, and the
`required_evidence_failed` override that replaces `route_key` with
`phase.review.failed_evidence_route`. None of them *adds* a route that the
enum omits, so no legitimate request is excluded. The enum is therefore a
necessary and not a sufficient condition -- schema admission still implies no
reducer authorization, which is the correct relationship.

Review, correction and rereview phases::
Probe *E1* covers a GATE review phase; probe *E6* covers a v3 convergence
`evaluator` phase with an explicit escape route. In the evaluator case the
dispatched enum is `['accept', 'correct']` while `phase.routes` is
`('accept', 'correct', 'diagnose')`: the reserved escape `diagnose` is excluded
by the schema exactly as `prompt._header` already excludes it from the
advertised `permitted_routes`. The coordinator-derived convergence escape is
applied by the reducer (`route_reason = "convergence_escape:..."`), never
requested by the agent, so nothing is lost.

Human escalation, where the reducer ignores `requested_route`::
`reduce_result` returns the human-authority stop before route resolution, so
the forced enum value is semantically inert -- confirmed by probe *E2*. One
audit-legibility consequence is recorded as O6.

== 6. Objective 3 -- pre-dispatch and failure accounting

Traced lifecycle, `slice4.run_real_one_hop` -> `vertical.run_one_hop` ->
`CodexCliAdapter.execute`:

. `dispatch_eligible` (status `ready`, budget available).
. `preflight_hop`; `write_run_snapshot`; *`write_dispatch_marker`*.
. `run_one_hop`: phase, contract selection, `preflight_hop`, prompt assembly.
. `adapter.execute(AgentExecutionRequest(..., permitted_routes=...))`:
  contract -> kind -> timeout -> version -> *route-set* checks, all before
  `atomic_write_json(schema, ...)` and before `subprocess.Popen`.
. provider; `validated_result`; trusted commit; evidence; `record_hop`;
  `reduce_result`; checkpoint; marker unlink.

The Hop is charged by `record_hop` only after the provider returned, and
`CodexCliError` subclasses `ExecutionNotStartedError`, which
`run_real_one_hop` handles by `dispatch_path.unlink(missing_ok=True)` followed
by `Slice4Error` -- the pre-existing "proven not started" path, not the
`except Exception -> recover_uncertain` path.

Probe *E5* exercises the only in-tree route to an empty projection (pinned
profile identity drift) through `run_real_one_hop`, with a fake provider that
writes a sentinel file if entered:

[source,text]
----
PERMITTED: ()   STATUS: RunStatus.READY
RAISED: Slice4Error current phase has no permitted routes; refusing to dispatch an unroutable invocation
PROVIDER ENTERED: False
MARKER RETAINED: False
RUN SNAPSHOT: ready        CHECKPOINT: False
----

So this is complete pre-dispatch safety, not merely provider non-invocation:
no Hop charge, no retained marker, no `uncertain_dispatch`, no
`reconcile_required`, and the persisted Run is unchanged. The adapter-level
test additionally pins that no schema file is written.

== 9. Non-blocking observations
[[observations]]

O1 -- a blank profile route key still admits `""` into the enum::
`serialization._mapping` constrains route keys only to "string" (unlike
`policy.evidence_commands`, which is regex-constrained), so a profile with a
route key of `""` loads. The dispatched enum then contains `""`, which
canonical validation rejects unconditionally -- the exact H001 trap.
Reproduced offline: `workflow_profile_from_yaml` with `"": {effect: complete}`
loads, `permitted_route_keys` returns `('', 'done')`, the projection emits
`{"type": "string", "enum": ["", "done"]}`, and `validated_result` then reports
`routing result.requested_route must be a non-empty string`. This is *not* a
regression of `3baaf5d` (the parent admitted `""` even more broadly, through
the unconstrained string) and such a profile is independently broken, because
`reducer` uses `phase.routes.get(phase.escape_route or "")` as a `None`
sentinel. It is nevertheless the one supported dispatch path on which the new
boundary guarantee does not hold. Smallest correction, if desired later:
reject blank route keys in `_result_openai_schema` beside the existing empty-set
check, or constrain route keys at profile admission.

O2 -- the root-cause *class* is closed for one field only::
Every other free-text string in the dispatched schema is still
`{"type": "string"}` while canonical `_string` rejects blank values:
`summary`, `escalation.question`, `invariant`, `successor_ref`, `local_ref`,
`claimed_commits` items, `evidence_refs` items, `commit_intent.subject` and
`commit_intent.paths` items. Demonstrated with `summary: ""` from a compliant
provider: `RECONCILE_REQUIRED` with a charged `uncertain_dispatch` Hop -- the
same accounting failure as H001 on a different field. This is inherent to the
selected shape, not a defect of it: the strict subset in
`codex_adapter._STRICT_KEYS` (and OpenAI Structured Outputs itself) cannot
express a minimum length, and the two general mitigations are the ones the
maintainer excluded (relaxing canonical validation) or deferred (diagnostic
preservation, forensic R7.2). Recorded so the residual is explicit.

O3 -- the preserved incident bytes remain permanently unreplayable::
Forensic R8.3 asked for a regression fixture built from the preserved
`result-message.json` bytes, reducing to `awaiting_human` with
`semantic_stop(kind="prerequisite")`. Under the chosen correction shape that
fixture is unsatisfiable by construction, and the commit substituted a
semantically equivalent one. That substitution is sound, but it should be
recorded against R8.3 rather than treated as satisfying it, and probe *E3*
shows the recurrence path (non-compliant provider) still produces
`reconcile_required` with an empty `anomalies` tuple.

O4 -- the commit message overstates its regression coverage::
The message claims the tests cover "a semantically equivalent prerequisite
escalation ... now reaches awaiting_human with its prerequisite semantic stop
(never reconcile_required)". The two tests that make that claim are reducer-only
and pass unchanged on the parent (probe *E4*). The claim is true of the system;
it is not established by those tests.

O5 -- the empty-projection refusal replaces a durable mechanical preemption::
For the only in-tree state that empties the projection (pinned profile identity
drift, or a v3 profile against a non-v3 Run), the parent charged one Hop and
reduced to `awaiting_human` with
`stop_reason = mechanical_preemption:pinned profile identity changed` and the
durable anomaly `('pinned profile identity changed',)` (verified on the parent
worktree). `3baaf5d` instead raises
`Slice4Error: current phase has no permitted routes` with no Hop, no anomaly
and no checkpoint. On balance this is safer -- no Hop charge and no provider
cost for an already-doomed Run -- and it is unreachable through
`operator.main`. Two costs remain: the message misattributes the cause, and the
durable diagnostic is lost. Also note that `prompt._header` and
`reducer.permitted_route_keys` are now two independent projections of the same
concept that agree only for `ready`/`running`; nothing pins that agreement.

O6 -- an escalating Hop now durably records a disposition route it did not intend::
`_with_hop_decision` records `hop.requested_route = result.requested_route` on
every reduction, including human-authority preemption. Under a strict enum, an
escalating reviewer must name a real route (for the P3.5 profile, `accept` or
`correction`), so the audit record of an escalation Hop now reads as a
disposition request. No mechanical consumer is misled -- the convergence
route-history validators only inspect Hops carrying a strategy record or
`route_reason`, and `_with_convergence_records` runs after the escalation
return, so a preempted Hop carries neither. This is an audit-legibility
consequence of the stricter schema, not an authority defect.

Minor, not tracked as an observation: `AgentExecutionRequest.permitted_routes`
defaults to `()`, which is safe only because the one strict-schema adapter
fails closed on it; the field comment states that obligation for future
adapters. And section 5 of
`docs/wfc_projected_result_contracts_concept_2026-10-07.adoc` still says the
adapter supplies "ONE schema per version, covering every phase/role", which is
now false (the schema is phase-derived). That document is a dated, unclassified
concept snapshot and no current authority surface contradicts the code.
