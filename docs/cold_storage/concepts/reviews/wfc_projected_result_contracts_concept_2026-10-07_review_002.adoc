== 5. Question 2 -- MATERIAL 4.2 closure

Corrected section 11 restates the target property as: for every phase
`P_open` capable of producing a new open blocking Finding, and for every
forward path from `P_open` that may reach a `complete`/`accept`-gated route
while that Finding can remain open, some phase *strictly reachable after
`P_open` on that same forward path* -- explicitly *not* `P_open` itself,
"unless a route loops back to it and a later invocation of that same phase
occurs after the Finding was opened" -- must hold the disposition
operation. It adds, directly addressing authority parked upstream:
"Authority located only at or before `P_open` does not satisfy this:
`reducer.py:1413-1423` computes `permitted_operations` from the *currently
executing* Hop's phase alone, so `P_open`'s own authority is already spent
by the time a later Hop on the same forward path needs to close the
Finding it opened."

Applying this literally to the governing task's counterexample:

[source,text]
----
independent_review [resolve]
    -> correction [no disposition]
    -> rereview [no resolve]
    -> accept -> complete
----

`P_open = independent_review` (it opens the Finding). The forward path
after `P_open` is `correction -> rereview -> accept -> complete`. Neither
`correction` nor `rereview` holds disposition authority in this topology,
and the graph does not loop back to `independent_review`. `resolve` sitting
at `independent_review` itself does not count, per the property's explicit
exclusion. No phase *strictly after* `P_open` on the forward path holds the
needed operation, so the corrected property is *not satisfied* and the
Commission must fail trusted preflight (`INVALID COMMISSION / PROFILE`).
The literal counterexample from the governing task -- and from review_001's
own 4.2 -- is now rejected by the corrected wording, not merely by intent.

The corrected text also retains the worked `independent_review -> correction
-> rereview -> accept -> complete` example and adds the sentence "Granting
`resolve` to `independent_review` itself instead of (or in addition to)
`rereview` does NOT satisfy this property," closing the exact gap review_001
identified.

Boundedness is preserved: the corrected paragraph explicitly characterizes
itself as "a static ordered-reachability condition over the existing
declarative `Phase.routes`/`finding_authority` facts -- a suffix-of-path
check relative to where the Finding becomes open, not set membership over
the whole path -- not an addition of temporal logic or a generic model
checker." The unaltered "Explicit non-overstatement" paragraph later in
section 11 (not touched by this commit, and not required to be) continues
to disclaim full formal verification, a new DSL, or a generic compiler.

*MATERIAL 4.2: CLOSED.*
