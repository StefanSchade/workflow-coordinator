=== From bounded work to an externally sequenced series (15–17.11.2026)

The documentation curation work of 15 November exposed a tension between
faster self-development and the infrastructure that made its results
credible. In C3, the developer-guide candidate `9930622` received independent
review `ed212d2`, but `RUN-3c6db523e1e64755b04b678f402aa563` stopped after
its Coordinator-owned test timed out. A later diagnostic found two nested
preparations waiting on package downloads; a locally supplied wheelhouse made
the unchanged suite substantially faster. This showed a reproducible class of
failure and a practical mitigation, not the cause of the original C3 timeout.
The subsequent C3 verification and C4 work had their own Run dispositions;
none retroactively turned the original timeout into a successful check. The
original C3 Run was retained in its operator summary and the BUG; its missing
mechanical archive was subsequently created from the original State and OPS on
18 November at sibling Evidence commit `72a5abe`, retaining `awaiting_human`.

On 16 November, documentation-memory planning proposed smaller reference
models, a catalog and provenance work (`2d4d84e`, review `7f759e3`). The next
day a series of separately commissioned self-development Runs applied that
direction. First SEC-03 (`RUN-deb3ca7ef09b473bb8f6fbcad2c366ef`, candidate
`77c994b`, review `48f0887`) closed a Git-observation gap and enforced the
Coordinator's commit authority. The fix disabled rename detection where both
the deleted source and added destination had to remain observable; it did not
redesign Git authorization. See the
link:../../backlog/BUG-WFC-SEC-03-GIT-SCOPE-COMMIT-AUTHORITY.adoc[SEC-03 record].

M1 (`RUN-b7f70ca2be104a1fa62946f544631c3c`) then modularized the Functional
and Semantic Models, and M2 (`RUN-1ac59a8cc63241eda4b275d7492a70ac`) the
Technical Model, adding component and runtime views. Each required a correction,
focused review and renewed broad review before its five-Hop completion
(`c3d3cbb` and `88bc790`); the change was primarily an organization of existing
material. The link:../../backlog/FTR-WFC-REFERENCE-MODELS-MODULARIZATION.adoc[model
record] keeps maintainer acceptance separate from the completed Run evidence.

K1 (`RUN-a5d8fcf2abae47ae8c79c5d671e44133`) followed with a local document
catalog. Independent review found a parser boundary error, followed by a
correction and renewed review (`d1a3029`); the Maintainer accepted K1. Its
catalog was an explicitly generated, ignored projection of sources, not a
new authority or inferred current status. The subsequent operational-provenance
pilot (`RUN-bda29ff3fa9b415f8007ebf3416fbadb`, `e0c8656`, review `ef956bd`)
joined mechanical provenance with an evidential sample of historical review
findings. Its annotations made later disposition discoverable without changing
the original reviews or claiming Run or acceptance authority. Its further
adoption remained a separate Maintainer decision. The
link:../../backlog/FTR-WFC-KNOWLEDGE-CATALOG-PILOT.adoc[catalog] and
link:../../backlog/FTR-WFC-OPERATIONAL-PROVENANCE-PILOT.adoc[provenance records]
explain these boundaries.

The sequence demonstrates an operator using WFC repeatedly on real project
work, with results and findings carried into the next bounded Commission. The
higher-level choice of sequence, authorization, predecessor verification and
archive remained with the external orchestrator and Maintainer. The Runs do
not demonstrate an integrated WFC multi-Commission program. Completed Runs,
independent review and Coordinator checks are distinct from any later
Maintainer acceptance or Runtime promotion.

=== Different controls for different work

A small Functional Model change exercised `simple@v1` in
`RUN-5b95c3a298b34b72a5da294a40664668` (`85809aa`). Its single Terra Medium
Worker performed a self-check, and the Coordinator `task-check` passed; the
program did not provide an independent review. The
link:../../functional_model/workflow_program_use_cases.adoc[Working Draft]
added platform portability, consumer-stack neutrality and an ARM64-native
scenario as intended functional requirements, not a claim of qualified ARM
support. The product idea was that small repository tasks could still have
explicit authority, bounded scope and an audit trail without every task
requiring an independent review. Selection of an appropriate workflow, and
any future higher-level orchestration, remained separate decisions.

The model distinguished WFC's own Python requirements from the consumer's
stack. A supported host may provide architecture-specific compilers, tests or
hardware interfaces for WFC to execute under authorization, without requiring
WFC to install or make those tools portable. Linux x86-64/Python 3.13 was the
self-development reference profile; it was not a minimum requirement on
consumer projects. The document did not change the product's Python `>=3.10`
declaration or qualify an ARM64 adapter/platform combination.

=== From the wheelhouse workaround to a development-input boundary

The link:../../backlog/BUG-WFC-NESTED-PREPARE-OFFLINE-BUILD-ISOLATION.adoc[offline
build BUG] traced the fragility to tests that genuinely create fresh WFC
Runtime and Development environments. A local source installation using
PEP-517 build isolation can need setuptools and other dependencies in a new
build environment even when the outer environment already has packages. In a
restricted or unreliable network, repeated nested installations could fail or
consume much of the trusted-check timeout. A 15 November host diagnostic with
the external wheelhouse completed the unchanged suite in 171 seconds after a
network-affected diagnostic had taken 896.96 seconds and still had two failed
installations. These were diagnostic observations, not proof of the original
C3 timeout's cause.

The separately commissioned planning Run
`RUN-30076079948348f8a522aece93a1c250` published the
link:../../warm_storage/test-infrastructure/wfc_offline_test_infrastructure_implementation_plan_001.adoc[implementation
plan] (`18ffdc9`, independent review `2159150`). The Maintainer adopted its
A1 plus conservative B1 direction: A1 supplies reproducible, verified inputs
for WFC's *own* development and test environments; B1 retains and qualifies
real package installation and integration coverage. C was the independent
Beta-1 product boundary in which the host or consumer provides the execution
environment. A1 was not a preliminary implementation of C, nor permission to
make Python packaging infrastructure a requirement on consumer repositories.
The plan was a source of requirements, not a reason to change the immutable
plan document during later implementation.

Before implementation, external E1–E4 experiments called the actual Codex
and Claude adapters in disposable workspaces, outside any WFC Run. Codex could
read the original external wheelhouse and verify twelve hashes; Claude could
not read that personal path under its existing sandbox. The tested Codex shell
received `PIP_NO_INDEX` and `PIP_FIND_LINKS`; the Claude shell did not. Real
isolated build attempts and a missing-setuptools negative control made these
process boundaries observable. These experiments did not prove outbound
network denial, and an isolated production-evidence-runner seam was not a
Coordinator Run. Their report and sanitized artifacts are in the sibling
Evidence repository under `experiments/offline-agent-sandbox-experiments-20261117/`.
They made P2's transition explicit: inputs had to be verified at a location
Claude could actually read, and pip configuration had to reach the real shell's
installation process without widening sandbox permissions.

=== Stops, preserved drafts and the authorized recovery

The first P1 input-profile Run, `RUN-3032229af76b463b8743d021763db157`,
stopped `awaiting_human` over unestablished artifact provenance. The Worker
also returned an inadmissible CommitIntent with a blocked result and left dirty
state; the Coordinator mechanically preempted the Run. The Maintainer accepted
official PyPI metadata as the primary comparison source, while distinguishing
local hashes, traceable source and stronger publisher attestation. Draft commit
`11408c0` preserved work for inspection; it was not an accepted P1 result.

In separately authorized continuation
`RUN-e8a5cba807d64d8e9681855bcc5772d1`, the Worker interpreted meeting the
implementation plan as requiring permission to edit that plan. It stopped with
dirty state; `67a9575` preserved the second draft without accepting it. The
Maintainer clarified that the plan was read-only reference material and that
the P1 handoff and profile were the authorized mutation targets. This episode
showed the scope boundary operating as designed and also exposed an ambiguity
in the task's distinction between a requirement source and an edit target.

The fresh recovery `RUN-8cba81c1968642c7b4bcd8255acea6cf` re-examined the
retained drafts as unaccepted input, rather than continuing either stopped Run.
Terra Medium produced the profile and handoff (`2b26ae0`); a fresh independent
Terra Medium review checked the complete result against the original baseline
(`bef6425`), and the Coordinator `task-check` passed. The two predecessors
remain stopped in their own mechanical archives. The
link:../../warm_storage/test-infrastructure/wfc_offline_test_inputs_p1_profile_handoff.adoc[P1
handoff] records the twelve wheel identities and PyPI metadata comparison,
seed-pip provenance, test inventory and residual limits. An HTTPS metadata match
is traceable source evidence, not a claim of independent publisher attestation.

=== Qualification, evidence and the remaining transition

P2 (`RUN-368332c701204f96a0e00d5cedbb2c18`) used Claude Sonnet High as Worker
and fresh independent Reviewer. The two-Hop Run produced the development-only
`fetch`/`verify`/`exec` tooling and suite integration (`7e5de29`, review
`297f1cd`); its Coordinator `task-check` passed. Both Claude invocations
verified staged wheel inputs and performed real isolated local installations
inside the existing sandbox. Direct shell environment assignments were denied;
the explicit `exec` child configuration worked without additional privileges.
The link:../../warm_storage/test-infrastructure/wfc_offline_test_inputs_p2_handoff.adoc[P2
handoff] distinguishes those agent-local observations from the Coordinator's
separate test. P2 did not establish actual network denial.

P3 (`RUN-a158e48df34e4015a1ee85e85ac5f2da`) used Terra High for both Worker
and fresh independent Reviewer. Its two Hops (`47bdd3a`, review `d378db5`)
completed with a passing Coordinator `task-check`. The added tests built an
sdist and a wheel from clean source, installed into a fresh environment, checked
imports and resources outside the checkout, and exercised a non-Python
consumer through the existing evidence seam. A guard checked that required real
installation cases were selected and passed; a deliberate deselection caused
failure. No unimplemented Beta-1 consumer lifecycle was inferred from that
seam test.

Three complete *agent-local* suite runs in Bubblewrap network namespaces each
reported 1,051 passed and four skipped, in 187.68, 230.39 and 189.97 seconds.
A numeric connection probe returned `ENETUNREACH`; for two runs the probe and
suite shared the namespace, while the first used the same namespace options in a
separate probe. Independent review inspected the logs and tested the boundary;
the measurements are not the separately passing Coordinator observation. The
link:../../warm_storage/test-infrastructure/wfc_offline_test_inputs_p3_handoff.adoc[P3
handoff] and link:../../warm_storage/test-infrastructure/wfc_offline_test_inputs_p3_001_broad_review.adoc[review]
record the method and limitations. The sibling Evidence repository retains
those agent-local logs under `experiments/offline-test-inputs-p3-qualification-20261117/`.

As recorded in `c778df7`, the first qualified development profile was CPython
3.13 on Linux x86-64. ARM64 remained an intended but unqualified target. A
single end-to-end transition from a fresh checkout or account through bootstrap,
Prepare and Launch without personal pre-existing inputs had not yet been
shown; the offline-build BUG remained open and the original wheelhouse remained
available as fallback. C3's original timeout cause remained unknown. These
works did not promote Runtime or release Beta 1. A previous, separate provider
networking promotion on 16 November supplied Runtime `f6de099` for these Runs;
it was not a consequence of the offline work.

The three offline Runs and their two stopped predecessors have separate
mechanical manifests in the sibling `workflow-coordinator-run-evidence`
repository, under `archive/unclassified/wfc-offline-test-inputs-*/` and the

The Evidence repository's `project_memory/archive_run_index.adoc` describes
