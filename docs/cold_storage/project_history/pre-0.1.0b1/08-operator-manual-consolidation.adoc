=== A fragmented operating path and early attempts (10–11.11.2026)

Commits: `17c6c05`, `0b0a2b7`, `b328881`, `14ee89c`, `977ee76`.

The WFC execution core was already being used for real self-development, but
its operator guidance was scattered across the manual, transitional guide,
preparation and self-development contracts and recovery runbooks. A new
operator had to reconstruct the reading path and authority boundaries. The
first consolidation Commission combined migration, new diagnosis and an
end-to-end example; a subsequent Commission reduced the scope. Both Terra
6.1 High Workers stopped `blocked` before a complete candidate or independent
review, the first with an operational escalation and the second without one.
Separately, the first bounded planning Run left an incomplete untracked draft
and stopped mechanically on the unclean worktree; the next stopped with
`result_blocked` and no changes. These remain distinct historical outcomes.

The team investigated task scope, prompt and completion semantics, prepared
environments and possible sandbox or integration causes. `14ee89c` clarified
that incomplete work alone is not a reason for `blocked`; a fresh planning
Run with the clarified Worker component still produced no candidate. That
single comparison did not establish a causal explanation. The open
link:../../backlog/BUG-WFC-WORKER-PREMATURE-BLOCKED-CONTRACT-AMBIGUITY.adoc[Worker completion-contract BUG]
and the exploratory link:../../backlog/FTR-WFC-PROGRESSIVE-WORKER-EXECUTION.adoc[progressive Worker execution FTR]
record related questions, not a demonstrated cause of the individual stops.

=== External comparison and a bounded plan (11.11.2026)

Commits: `1d035f5`, `11e54aa`, `e01a408`.

An external experiment reconstructed the earlier H001 prompts in disposable
clones; it was not a WFC Run and had no Coordinator review or trusted evidence.
Terra 6.1 High returned `blocked` without changes in three replays. Sol 6.1
High completed two and Claude Sonnet completed one, each with extensive
changes. The independently checked path sets and renders did not establish
substantive review acceptance. The small samples and differences in provider,
sandbox, temporary environment and Core-guide access limit causal inference:
missing Core access and task size alone did not explain all observations, but
no single mechanism was established. The original WFC invocations used Codex
CLI; external App-Server or Desktop reports do not prove the same cause there.

In light of the repeated stops, the preceding investigation and the replay
comparison, the maintainer chose Sol 6.1 High for both Worker and independent
Reviewer in separate fresh invocations. This was a bounded operational choice,
not a general model ranking or a permanent exclusion of Terra. A future return
to critical unattended Terra work calls for a separately authorized, repeated,
small-task qualification under comparable conditions; the maintainer retains
the decision.

The successful Sol planning Run produced and independently reviewed a
link:../../backlog/operator-manual-consolidation/FTR-WFC-OPERATOR-MANUAL-CONSOLIDATION.adoc[series charter]
and ten ordered, separately commissioned FTRs. Each package was bounded to a
coherent manual slice and required trusted evidence and independent review;
implementation was not authorized by the planning record itself.

=== Product boundary remains open (13.11.2026)

The accepted manual series improved and exercised the current operating path;
it did not establish Beta-1 readiness as an independent third-party product.
External usability, installation, payload neutrality and the product boundary
remain questions for separate work. Fable's independent review on the Docs
branch is a discussion input, not an accepted architecture decision or
implementation authority. This retrospective grants no authority or release
approval.
