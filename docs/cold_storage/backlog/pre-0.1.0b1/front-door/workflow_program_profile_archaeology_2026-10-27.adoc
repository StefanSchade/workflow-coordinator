This read-only survey classifies present profiles and recorded history. It does
not select a Front Door architecture, DSL, binding grammar, migration, P3.5
guard, or Level-1 implementation. The functional, semantic and technical model
records and working briefs are DRAFT/NON-AUTHORIZING under docs/README.adoc;
they supply comparison questions, not settled requirements.

== Method and limits

The reproducible inventory commands are `find governance/self-development -name
'*-profile.yaml' | sort` and `rg --files governance/self-development | rg
'profile.*\\.yaml$' | sort`, followed by direct YAML inspection and resolving every
WorkItem `profile_ref`. The first finds 46 name-pattern profiles; the second
finds those plus the deliberately nonconforming, tracked historical fixture
`immutable-finding-echo-profile-002.yaml` (47 current-tree profile YAML files).
All are schema_version: 2. Each has a paired WorkItem and task, and a dedicated
policy where the WorkItem says so; standalone uses `repository-policy.yaml`.
The parser and model define their actual meaning: workflow_profile_from_yaml
(src/workflow_coordinator/serialization.py:650-978), WorkflowProfile, Phase,
Route and ReviewDescriptor (src/workflow_coordinator/model.py:222-276).

“Topology equivalent” means only the same directed phase/route graph after
renaming. “Semantic equivalent” additionally requires the same roles, review
descriptor (authority, breadth, context, blocking policy and Finding
authority), evidence/failed-evidence obligation, durable-artifact rule, and
scope/action capability. No common shape is claimed semantically equivalent
unless stated.

The external selected Run Ledger was accessible at
../workflow-coordinator-run-evidence/project_memory/run_ledger.adoc. Its
introduction says it is a curated selected-Run index, not complete code or
launch history: an entry supports recorded use, silence does not prove non-use.

=== Lossless per-profile semantic ledger

This is a compact comparative ledger, not itself a lossless transcription of
the YAML. It exposes the process-guarantee dimensions used for the family
comparison. The complete, per-profile literal record is made reproducible
below in <<literal-profile-record-extraction>>: it emits the exact phase
mapping, including each full scope list, components, actions, review purpose,
routes and every review field, joined to each WorkItem and its dedicated policy
or the shared `repository-policy.yaml`. This distinction matters: a prose
label such as “literal source/test scope” is not a substitute for the actual
list. New open Findings are not a `finding_authority` capability: it governs
only disposition; a genuine new Finding may be proposed where the result
contract permits it. The rows deliberately retain one source record per
profile, even where their topology matches.

Key: `F4/F3/F2/F5` is graph only; `N/R/O` is per-phase artifact sequence
(none/required/optional); `EC/REC/R` is action sequence
(edit+commit/review+edit+commit/review); `p` is pytest, `-` none; `[]` or
`[resolve]` is the gate's literal `finding_authority`; `FER=c` means the gate
has literal `failed_evidence_route: correction` (otherwise `FER=-`). “Focused”
and “broad” are the literal `review.breadth`; purpose is identified by its
literal subject below and remains fully stated at that YAML field. Every gate
in this corpus has `authority: gate`, `context: fresh`, `blocking_policy:
blocking_only`, `trigger: profile_selected`, and `exit: declared_route` unless
the source record says otherwise.

The ledger makes no semantic-equivalence assertion merely by putting two files
in one cell: each is a separate literal source record, and the stated shared
properties are only the properties displayed. The P2 rows are a worked
counterexample: same F4 and `[resolve]`, yet P2/continuation/closure use worker
pytest and focused no-FER gates, whereas completion has no worker evidence,
broad first review, and `failed_evidence_route: correction` in both gates.
That distinction is operational because `_admit_evidence_disposition`
(`src/workflow_coordinator/operator.py:123-136`) rejects evidence on a
non-gate review or a review missing a failure route.

All reviews are gates with trigger profile_selected and exit declared_route;
normally blocking_policy blocking_only and fresh context. This does not erase
semantics: projected-result-contracts-p1-profile.yaml gives independent_review
Finding authority []; P3 gives [resolve]. The first cannot close its own
current-Run Finding; the latter can. Required evidence is also enforced:
_admit_evidence_disposition (operator.py:123-136) rejects evidence on a
non-gate review or without failed_evidence_route. F4 is therefore not semantic
equivalence.

Phase scopes/actions, WorkItem scope/task/hop budget, policy ceiling, review
purpose, evidence choice, and durable output destinations are present
Commission values. Compare P3 source/test scope with the document-only scope
in docs-architecture-consolidation-design. Whether any are future parameters is
unresolved.

=== Interpreter, test-only and historical material

The interpreter supports profiles v2/v3 (serialization.py:670-978). The model
has convergence plus convergence_role, normal_correction_route and escape_route
(model.py:243-276). All 46 live profiles are v2: no live
convergence-bearing profile. V3 requires five corrector/evaluator/diagnosis/
reframe/strategy-gate roles and constrains routes (serialization.py:840-978).
tests/fixtures/convergence_curriculum.yaml is a material test fixture, cited
by tests/architecture/test_self_development_governance.py:462 and S4 scope.
It is implementation/test evidence, not a current profile or actual consumer
Run. Schema-3 policies do not make their profiles v3.

The architecture test is also an explicit historical-fixture consumer, not a
new-launch census. Its _preflight wrapper (lines 32-57) first requires the
current evidence-admission failure, then suppresses only that predicate so
archived standalone bundles remain structurally inspectable. The test constants
at lines 59-122 retain older standalone WorkItems, and lines 122-140 retain
the old immutable-finding-echo profiles. In particular,
`governance/self-development/immutable-finding-echo-profile-002.yaml` is a
tracked current-tree historical/test fixture (not a removed file and not
materialized by the test); `git log --follow --name-status` identifies `3e937cf`
as its copy/addition. Its paired current WorkItem has the literal
`profile_ref` and the test directly includes that path in
`IMMUTABLE_FINDING_ECHO_FIX_002_GOVERNING_PATHS` (test lines 129-137). It is
schema 2/revision 1, F4, and has reviewer Finding authority []; it is outside
the 46 `*-profile.yaml` name-pattern census and is historical/new-launch
inadmissible under the newer evidence-admission predicate, not absent.

Preflight parses pinned WorkItem/profile/policy/components and checks profile
reference, role bindings, scope/actions, durable artifacts, A1 and evidence
admission (operator.py:_preflight, _admit_a1, _admit_evidence_disposition,
lines 123-190 and 281 onward). This is current implementation, not a program
catalogue or separate Commission-binding object.

=== Literal per-profile record extraction

The following is part of the inventory, rather than a suggestion for a future
tool: it is a deterministic, lossless extraction recipe for the current-tree
records at this survey's baseline. It intentionally emits values rather than
the shorthand in the comparative ledger: every path in
`authorized_scope`, every component and human gate, every action/evidence
list, the full review purpose and descriptor, and every route. It also joins
each record to the actual WorkItem(s) by literal `profile_ref`, includes each
WorkItem's literal `scope`, `durable_artifacts`, `initial_phase` and
`max_autonomous_hops`, identifies the paired task text, and identifies the
paired policy (same stem when it exists; otherwise `repository-policy.yaml`).
Thus a profile with the same F4
shape cannot silently inherit another profile's purpose, authority, evidence,
scope, or policy binding. The command deliberately includes the nonconforming
tracked fixture, and rejects any unpaired profile rather than guessing.

[source,python]
----
from pathlib import Path
import json, yaml

root = Path(".")
profiles = sorted(root.glob("governance/self-development/*profile*.yaml"))
workitems = []
for path in sorted(root.glob("governance/work-items/*.yaml")):
    value = yaml.safe_load(path.read_text())
    if isinstance(value, dict) and "profile_ref" in value:
        workitems.append((path, value))

for profile_path in profiles:
    profile = yaml.safe_load(profile_path.read_text())
    if not isinstance(profile, dict) or "phases" not in profile:
        continue
    rel = str(profile_path.relative_to(root))
    users = [(w, value) for w, value in workitems
             if value["profile_ref"] == rel]
    assert users, f"unpaired profile: {rel}"
    for workitem_path, _ in users:
        task_path = workitem_path.with_name(workitem_path.stem + "-task.txt")
        assert task_path.exists(), f"missing task: {task_path}"
    stem_policy = profile_path.with_name(
        profile_path.name.replace("-profile.yaml", "-policy.yaml")
                         .replace("-profile-002.yaml", "-policy-002.yaml"))
    policy = (str(stem_policy.relative_to(root)) if stem_policy.exists()
              else "governance/self-development/repository-policy.yaml")
    record = {
        "profile_path": rel,
        "profile_id": profile["profile_id"],
        "revision": profile["revision"],
        "schema_version": profile["schema_version"],
        "policy": policy,
        "phases": profile["phases"],
        "workitems": [{"path": str(path.relative_to(root)),
                       "task": str(path.with_name(
                           path.stem + "-task.txt").relative_to(root)),
                       "work_item_id": item["work_item_id"],
                       "initial_phase": item["initial_phase"],
                       "scope": item["scope"],
                       "durable_artifacts": item.get("durable_artifacts", {}),
                       "max_autonomous_hops": item["max_autonomous_hops"]}
                      for path, item in users],
    }
    print(json.dumps(record, sort_keys=True, ensure_ascii=False,
                     separators=(",", ":")))
----
