= Release-engineering archive: the 0.1.0b1 release record

Inactive long-term memory for the one-time record of the first beta release
(`0.1.0b1`), relocated out of
link:../../../../developer_guide/ch04_release_management.adoc[developer guide
chapter 4] by slice R2 of
link:../../../../backlog/beta2_release_streamlining_plan.adoc[the Beta-2
release-streamlining plan]
(link:../../../../backlog/FTR-WFC-RELEASE-CONTRACT-STEADY-STATE.adoc[FTR-WFC-RELEASE-CONTRACT-STEADY-STATE]).
Start current release operation at chapter 4, not here: it keeps the decided
contract, the job description, the one-page runbook and the corrected
recovery table. This group preserves the evidence behind two of chapter 4's
accepted items -- C6/MD-5 and G7 -- so the record is kept, not discarded, and
so an active release task no longer has to load it.

Every file below is a *byte-identical relocation*: no word of the original
record is edited, summarised or re-dated. Only the handful of link targets
the move itself broke are repaired, and each file's own standing note says
exactly which ones. Relocation establishes neither a new decision nor a
changed one; C1-C7, MD-1 to MD-6 and G1-G8 keep the meaning chapter 4 already
gave them.
