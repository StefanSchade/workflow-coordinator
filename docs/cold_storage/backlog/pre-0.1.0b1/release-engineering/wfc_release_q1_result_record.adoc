*Post-run verification* (read-only, outside the task-check, as specified in the
plan): `q1_postrun_verify.py` passed all checks for both Runs: terminal state
`completed` with the matching Run ID; the target is a regular blob, not a
symlink; the first line equals the expected title exactly; the leaf is added by
exactly one commit; only the target, its review artifact and the Commission
directory changed (11 paths each); manifest status, Hops used equal Hops
recorded, `anomaly_count` 0, the last independent-reviewer Hop took the accept
route, no open Finding, and the archive is committed in the Evidence
repository. A passing baseline probe alone was never taken as success.

*Observations, recorded and not acted on:* (1) the `Commission digest` that
`wfc run` prints differs from the `projected Commission manifest digest` that
`wfc plan` prints (different quantities in the code: the plan prints the digest
of the projected manifest, the run the digest of the compiled Commission); the
execution-envelope digest is printed identically by both and matched in both
Runs. (2) The Hop count and the review pattern (one broad review, no
correction cycle) reflect the deliberately trivial task. (3) The consumer
branches `wfc/q1a` and `wfc/q1b` and their worktrees are kept as the
consumer-side artifacts; whether they are removed is the maintainer's choice.

*What this shows and does not show.* It shows, for this release candidate and
this one trivial documentation task, that the installed wheel drives the
complete chain on a consumer repository through both supported adapters:
authorization with the declared scope, Worker execution, an independent review
by a different model, the Trusted Commit, status and report, and Evidence
archival. It does not show the quality of any consumer change, behaviour on
non-trivial or multi-file work, behaviour at scale, or any model other than
the four recorded; the first Haiku-model Run and the first Sol-worker /
Terra-reviewer consumer Run each ran once.
