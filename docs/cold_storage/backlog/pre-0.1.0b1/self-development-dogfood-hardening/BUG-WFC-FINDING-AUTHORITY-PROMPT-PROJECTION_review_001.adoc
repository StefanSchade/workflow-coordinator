== Independent reconstruction of the Attempt-3 failure

Reconstructed from production code without reusing the frozen state root. A
gate `review` phase with `finding_authority: [resolve]` created blocking/open
`F001`; the Run then entered a `review: null` correction phase; that phase
proposed `F001 -> resolved` alongside a valid `rereview` route request.

`reducer.reduce_result` derives authority solely from the pinned phase: a
non-review phase falls to `authority = FindingAuthority.AGENT` with
`permitted_operations = ()` (`reducer.py:378-380`), `_finding_operation`
classifies `open -> resolved` as `resolve` (`reducer.py:90`), and
`_may_dispose` returns `False` for AGENT (`reducer.py:99-108`).

Observed stop reason, byte-identical to the frozen record:

----
mechanical_preemption:invalid_finding_delta:agent cannot perform Finding operation resolve
----

`F001` remained `FindingState.OPEN` and the Hop recorded
`finding_delta_ids == ()`. The diagnosis in the BUG record is confirmed: the
reducer was correct; the gap was projection, not enforcement.

== V4 contract assessment

`src/workflow_coordinator/resources/agent_operating_contract_v4.txt` adds two
paragraphs and one invocation-fact name. It generically separates the three
concepts the BUG requires:

* identity -- "A run-local finding_id identifies an authoritative current-Run
  Finding."
* evidence -- "A Hop may report evidence or summary information concerning a
  Finding as permitted by the result protocol."
* authority -- "Only operations named by the projected finding_authority may
  authoritatively change Finding state."

Empty authority is unambiguous: "An empty projected value, finding_authority=,
means no authoritative Finding disposition operation is permitted in this Hop,
including resolve, residual, supersede, or reopen." The enumeration matches
`_finding_operation` exactly.

The non-goal is stated directly: "Correction, edit, or commit authority does
not imply Finding disposition authority."

Correction evidence is explicitly not disposition: the disposition-free
correction Hop is told to report evidence through `evidence_refs` and summary
and to "normally submit no Finding delta merely to state that the correction
addressed a Finding."

The same-state-citation sentence was checked against the reducer rather than
accepted: `_apply_finding_deltas` takes the `same_state` branch
(`reducer.py:192-216`) without consulting `_may_dispose`, so citing an existing
open Finding to append evidence is genuinely permitted without disposition
authority. The contract's preference for the cleaner no-delta form is
correctly advisory, not authority-bearing.

No concrete choreography is encoded. No phase name and no route name appears;
the text closes with "Workflow choreography remains configuration-driven; no
particular phase name or route is implied by this contract." Adversarial
re-reading found no wording that implies authority beyond the projected
configuration.

=== MINOR

*MINOR-1 -- the projection re-derives authority with a weaker rule than the
reducer.*

`prompt._header` uses `phase.review.finding_authority if phase.review is not
None else ()`. `reduce_result` instead yields `()` for an ADVISORY review
regardless of the descriptor's `finding_authority` (`reducer.py:370-380`).
Constructed directly, an advisory phase carrying `finding_authority=("resolve",)`
projects `finding_authority=resolve` while the reducer rejects the resolve --
an untruthful projection.

Non-gating and not reachable through an admitted profile:
`serialization._review` rejects advisory plus non-empty authority with
"advisory review cannot carry Finding disposition authority", and
`workflow_profile_from_yaml` is the only production profile source. The
truthfulness invariant nevertheless now rests on a validator in a different
module rather than on one shared derivation.

Suggested (not performed): a single `effective_finding_authority(phase)` helper
consumed by both `_header` and `reduce_result`, plus a guard test asserting the
projected value equals the reducer's admitted operations for gate, advisory,
and non-review phases.

*MINOR-2 -- a tautological assertion in the integrated convergence test.*

`tests/unit/test_slice5b.py:414` asserts `"finding_authority=" in
request.prompt`. The V4 contract body itself contains the literal
`finding_authority=,` (contract line 45), so that substring is present in every
prompt regardless of what the header projects; the assertion cannot fail.

Non-gating: the empty-authority acceptance criterion is proven
non-tautologically by
`test_prompt_projects_explicit_empty_finding_authority_for_non_review_phase`,
which counts exact header lines, and the neighbouring negative assertion at
line 415 is meaningful. The line should become a whole-line or count assertion.

*MINOR-3 -- no regression guard against re-introducing duplicate projection.*

The three new prompt tests count `finding_authority=` lines in the header block
only (`package.text.split("\n\n", 1)[0]`). Nothing counts machine
`finding_authority=` fact lines across the whole assembled prompt including the
operator-reconstructed `[context]` block -- which is precisely where the
removed duplicate lived. Restoring the deleted `operator.py` line would fail no
test.

Non-gating: for a gate phase the restored line would carry the same value, so
no conflicting projection would arise today. It is still the exact surface this
candidate changed and deserves a guard.

=== INFO / WATCH

*INFO-1 -- empty authority versus genuinely new Findings.* Creating a Finding
in state `open` maps to operation `None` (`reducer.py:82`) and stays permitted
without disposition authority. The new V4 paragraph enumerates only
resolve/residual/supersede/reopen, and the permission to propose a new Finding
is carried by the older V3 paragraph. Combined reading is correct; watch for an
agent in a disposition-free Hop withholding a genuinely new blocking Finding.

*INFO-2 -- ordering asymmetry.* `permitted_routes` is `sorted()`;
`finding_authority` preserves admitted profile order. Both are deterministic,
and the latter matches both the removed operator line and the reducer's
order-independent membership test. Noted so that a future "consistency" change
does not silently alter projected prompt text.

*INFO-3 -- fixture vocabulary.* `tests/fixtures/slice5b_non_dmc.yaml`
(unchanged by this candidate) uses `investigate`/`review`/`correct`/`rereview`,
mirroring the self-development choreography. Genericity is nevertheless proven
independently by replay J's distinct vocabulary, by the three new
arbitrarily-named prompt phases, and by the absence of phase-name literals in
production sources.
