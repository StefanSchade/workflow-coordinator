=== MINOR

*M-1 -- Project Memory durable constraints omit the intentional provider limit.*

Location:: `docs/project_memory.adoc`, `== Durable constraints`.
Defect:: Plan section 4.1 enumerates "provider limits" among the durable
constraints this section must carry. The section carries authority ownership,
clone and external-state separation, the intent-versus-authority boundary, the
deferred containment boundary, and the push/promotion prohibition, but records
nothing about the deliberately narrow provider binding. A fresh-context agent
reading only Project Memory could infer that the provider is selectable. This is
an omission, not a contradiction: architecture already names the Codex CLI
adapter behind the execution port, and backlog `LATER` marks broader
provider/model configuration as future work, so no current file makes a false
claim.
Smallest bounded correction:: Add one bullet to `== Durable constraints`, for
example: "The provider binding is intentionally narrow. `--executable` replaces
the Codex-CLI-compatible executable used by the concrete adapter; it is not a
generic provider selector. Widening it is a separate decision."

*M-2 -- Backlog DROP omits Core's former 5F consumer assumption.*

Location:: `docs/backlog/README.adoc`, `== DROP / SUPERSEDED`, first bullet.
Defect:: The corresponding plan section 5 row drops three items together --
the imported 5C--5E sequence, Core's former 5F consumer assumption, and
wholesale Core Project Memory replication. The backlog carries the first and
third and omits the second, so the standalone roadmap records no explicit
disposition for the 5F consumer assumption. Risk is low: the index denies
current authority to everything under `imported/core-incubator/` without
exception, so nothing can read 5F as current.
Smallest bounded correction:: Extend the first DROP bullet to "Inherited
5C--5E sequencing and Core's former 5F consumer assumption as standalone
roadmap authority."
