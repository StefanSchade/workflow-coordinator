== Blocking defect

=== The required durable invalid-result and persisted-shape coverage is incomplete

The Commission's acceptance matrix requires an invalid structured result with
a specific validation error to prove that the message is recoverable from
*durable state*. The new
`test_validation_failure_retains_its_message_in_real_hop_run` only asserts
`RealHopRun.outcome_error` in memory. No operator-level test drives that case
through `run_serial_hops`, reads the diagnostic JSON back from disk, and
asserts that the validation message and correlated artifact pointer survive
in the persisted operator records while raw stdout/stderr remain excluded.

The new tests also stop short of several expressly required persistence
assertions:

* the successful CLI-path test checks the new fields only in
  `operator-summary.json`, not in the persisted
  `execution-evidence.json` row;
* the failure tests assert the unchanged status and stop reason but do not
  assert the unchanged `human_question` required by matrix item 6; and
* the multi-Hop test exercises `run_serial_hops` and its execution-evidence
  pointer, but never constructs or reads `operator-summary.json`, so it does
  not prove that the real summary wiring selects H002's invocation rather
  than H001's.

Required correction: extend the authorized unit tests with an operator-level
invalid-structured-result case that reads durable files after completion, and
strengthen the existing success, fail-closed, and multi-Hop cases to assert
the persisted execution-evidence shape, unchanged human question, and H002
correlation in both the summary and execution evidence. Fake adapters only;
no production redesign is requested.
