== Architectural boundary applied by this review

This review evaluates the smaller Git-backed contract and expressly does not
reopen the retired strong-staging architecture. The absence of a lock,
proposal identity, approval marker, fingerprint, one-shot promotion, journal,
WAL, or cross-file crash transaction is not a finding.

The accepted contract has two persistent representations: the four canonical
JSON files and the editable ODS workbook. A temporary imported JSON directory
may exist only for the duration of one process. An imported edit becomes an
ordinary dirty Git worktree; `git diff` is review, a normal commit is
acceptance, and restore/discard is rejection. Concurrent multi-maintainer
editing and import are not supported requirements.

== Verdict

*CHANGES REQUIRED.*

* BLOCKING: 0
* IMPORTANT: 0
* MINOR: 1
* INFO / bounded observations: 1

The Git-backed architecture is correctly implemented for the documented
serial maintainer flow. The retired state machine is gone; import is
fail-closed before canonical mutation; the dirty-canonical guard works;
replacement, path, round-trip, and ordinary Git review/restore/commit behavior
passed independent probes; and the real pinned spreadsheet tool completed the
expected workflow.

Acceptance is withheld only because the current Makefile and Project Memory
README make a blanket guarantee for every Make invocation mode, including
parallel execution, that the shared workbook and canonical surfaces do not
support. A deterministic `memory-export` / `memory-import` parallel probe lost
the workbook edit while both targets reported success. This is not a request
for locking or for resurrection of the promotion protocol. The supported
serial workflow is not defective; the current concurrency claim is false.

== Findings

=== F-M1 -- MINOR -- the blanket `make -j` safety guarantee is false

Affected claim:: `Makefile` lines 46--47 and
`project_memory/README.adoc` lines 89--91 state that because no target is a
prerequisite of another and each target is one process, no Make invocation
mode, including `-j`, can act on stale output.

Concrete evidence:: A disposable clone at current truth `6a7a0f3` was exported
with the exact pinned spreadsheet-handling source
`ad91eeb067752ae4773f86927071dd6c3aaf8621`. The `concerns` sheet was then
edited through ODF to append the unique marker
`[PARALLEL EDIT MUST SURVIVE]`; the marker was confirmed in `content.xml`.

A wrapper delayed only the `ods_to_json.yaml` invocation for two seconds, then
the following was run:

[source,shell]
----
make -j2 memory-export memory-import \
  SHEETS_RUN=/tmp/.../sheets-run-delay-import
----

Both recipes started. `memory-export` overwrote the edited shared
`project_memory.ods` from canonical JSON while `memory-import` was delayed.
Import then read the newly exported no-edit workbook rather than the workbook
that existed when the invocation began. Both targets exited zero; import
reported `canonical Project Memory is byte-identical`; `git diff --
project_memory/canonical` was empty; and the marker was absent from the final
workbook.

Why this violates the current contract:: The implementation and documentation
explicitly make parallel Make safety a current guarantee. Self-contained
processes do not make their shared mutable inputs and outputs independent:
`memory-export` writes the same workbook that `memory-import` reads. Related
combinations also share canonical JSON. The probe therefore directly
contradicts the stated guarantee. It does not demonstrate a defect in the
supported serial maintainer workflow or create a requirement for concurrent
maintainers.

Smallest proportionate correction:: Remove the blanket parallel-safety claim
from the Makefile comment and `project_memory/README.adoc`, and say that memory
targets which share the workbook or canonical JSON must be invoked serially.
Do not add locking, leases, promotion identity, or transaction machinery. If
parallel target combinations are to remain claimed as supported, they instead
need explicit ordering/serialization and a regression test; that is a larger
contract than `DEC-WFC-010` requires.

Test gap:: `test_make_import_is_one_self_contained_target` invokes only one
target under `make -j`; it cannot falsify interaction between different
targets. The structural assertion that each recipe is one process is true but
does not establish isolation across the shared workbook.

=== I-1 -- INFO -- canonical-directory symlink refusal is deliberately stricter than the diagnostic wording

The canonical-directory path check refuses whenever the resolved path differs
from the fixed repository-owned spelling. The outside-repository symlink probe
was refused and no outside byte changed. A committed individual table symlink
was safely replaced at its in-repository directory entry by `os.replace`; the
outside target did not change.

An additional probe redirected `project_memory/canonical` to
`project_memory/canonical-real` inside the same disposable repository. It was
also refused, but the message called that resolved target "outside the
repository-owned location". This is a stricter-than-required refusal with
imprecise wording, not a write escape and not an acceptance finding. If the
diagnostic is touched later, "redirects away from the fixed repository-owned
path" would describe the implemented check more exactly.

== Contract reconstruction and evidence

=== Retired state machine removal

`scripts/memory_proposal.py`, `tests/unit/test_memory_proposal.py`, and
`project_memory/staging/` are deleted. The Makefile exposes only
`memory-export`, `memory-import`, and `memory-roundtrip-check`; no live target
or alias provides `memory-preview` or `memory-promote`. `.gitignore` retains
only the generated workbook rule for this feature, and snapshot exclusions no
longer name staging or proposal state.

A live-tree search found retired names only in canonical historical/decision
records, explanatory negative assertions, and tests proving absence. No
persistent proposal, baseline/proposal fingerprint, approval marker, replay
lifecycle, promotion operation, lock, lease, claim, or hidden acceptance state
remains. The `wfc-memory-import-*` and `wfc-memory-roundtrip-*` directories are
random process-local temporary buffers and are removed in `finally`; they have
no persistent identity or approval meaning.

=== Import failure boundary

Independent fake-runner probes captured SHA-256 hashes for all four canonical
tables before each import. Canonical bytes and Git status remained unchanged
after:

* runner exit 9;
* a missing whole `decisions.json` table;
* an unexpected `releases.json` table;
* malformed `decisions.json`;
* a missing workbook;
* an unavailable runner, which returned the dedicated exit 127; and
* inability to execute Git while checking canonical status.

The implementation reads and JSON-parses the exact imported table set in a
throwaway directory before entering the replacement loop. This is the promised
pre-mutation failure boundary. No cross-file crash-atomicity claim was inferred
or required.

=== Dirty-canonical refusal

Independent probes covered a valid tracked table modification, deletion of a
tracked expected table, an untracked unexpected JSON table, and an untracked
non-JSON file beneath canonical. Each refused without overwriting the existing
state. A non-zero/unavailable Git-status path also refused. The normal real-tool
workflow refused a second import after the first import had made
`concerns.json` dirty.

The deletion and unexpected-JSON cases refuse even earlier as incomplete or
unexpected canonical table sets; the untracked non-JSON case reaches the Git
guard. All satisfy the narrow contract that import must not silently overwrite
an existing canonical edit. No repository-wide cleanliness requirement was
inferred.

=== Complete replacement and filesystem behavior

The expected model is exactly these JSON tables:

[source,text]
----
concern_event_xrefs.json
concern_events.json
concerns.json
decisions.json
----

A missing whole table and an unexpected JSON table were refused. Removing one
row from a valid fake workbook succeeded and changed the `concerns` row count
from five to four, proving that whole-table completeness is not confused with
row preservation. Replacement preserved an unusual ordinary `0751` rwx mode.

The canonical-directory symlink escape and committed individual-table symlink
probes established the relevant path behavior: the former refuses before
conversion, while rename replaces the latter symlink itself rather than
following it. No outside write was observed. The implementation correctly
makes no promise of multi-file crash atomicity.

=== Round-trip invariant

With the real pinned tool, hashes of all four canonical tables and the
maintainer workbook were identical before and after
`memory-roundtrip-check`, which reported four byte-identical tables. The check
created and consumed its own temporary workbook.

A deliberately lossy fake export removed the first concern's `title`. The
check exited 1, printed a unified `concerns.json` delta containing `title`, and
reported the invariant violation. Canonical hashes stayed identical and a
sentinel maintainer workbook stayed byte-identical. This is transformation
verification only; it was not treated as content approval.

=== Git as acceptance boundary

The real-tool disposable workflow was:

[source,text]
----
memory-export
memory-roundtrip-check
ODF edit of concerns.title
memory-import
git status / git diff
second memory-import (refused because canonical was dirty)
git restore -- project_memory/canonical
memory-import again
ordinary git add + git commit
----

The first import produced only
` M project_memory/canonical/concerns.json`, and `git diff` showed exactly the
ODS title edit. Restore returned the clone to a clean canonical state. Reimport
then reproduced the same edit, and an ordinary scratch commit
`6cb24a6` accepted it. No hidden marker or staging identity was needed and the
implementation did not commit automatically.

== Test assessment

The new tests genuinely cover the main supported serial contract: edited
workbook -> Git diff -> restore, dirty tracked-canonical refusal, failed,
partial, unexpected, and malformed import preservation, directory-symlink

Independent probes supplied cases absent from the suite: missing workbook,

not expose another implementation defect. The material missing falsifier is
the cross-target parallel case in F-M1.

== Review hygiene note

All mutation and integration probes were designed for disposable clones. One
internal-directory-symlink probe was initially issued from the live WFC
directory rather than its clone. It ran export, moved the canonical directory,
created a symlink, and reached the path refusal; no import conversion or
canonical write occurred. The original directory was immediately restored,
every canonical blob was verified equal to `HEAD`, and the ignored workbook
was regenerated as a valid real export with the pinned tool. Subsequent
tracked status contained only this review artifact plus the pre-existing
`wfc_snapshots/`; final verification is recorded after the review commit.

`wfc_snapshots/` was not read for evidence, modified, deleted, or added. Core
and workflow-coordinator-runtime remained clean at their initial commits.

== Conclusion

The simplification in `871ab14` successfully removes the retired custom
promotion state machine and implements the intended Git-backed serial
maintainer workflow. The implementation safety properties and real spreadsheet
integration are sound within that contract. The repository is nevertheless
*CHANGES REQUIRED* because its current blanket `make -j` statement claims more
than the shared workbook permits. Correct that statement proportionately;
do not add concurrency machinery or revive strong staging.
