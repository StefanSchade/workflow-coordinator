== 1. Proposed release-based archive structure

[source,text]
----
docs/backlog/                                  genuinely open FTRs and BUGs + _open.adoc + README
docs/warm_storage/                             only material required by currently active work
docs/cold_storage/backlog/pre-0.1.0b1/<group>/ completed feature/workstream material, grouped
docs/cold_storage/architecture/pre-0.1.0b1/    historical architecture spanning several features
docs/cold_storage/future/pre-0.1.0b1/          proposals and hypotheses describing no delivered function
----

A group directory holds everything belonging to one finished workstream
together: its FTR and BUG records, its design and concept documents, its review
artifacts, and its closure evidence. The structure repeats per release
(`pre-0.1.0b1/`, then `0.1.0b1/`, ...), so no new convention is needed later.

Four parallel conventions exist today and are retired by this restructure:
`cold_storage/backlog/done/`, `cold_storage/backlog/history/`,
`cold_storage/concepts/history/`, `cold_storage/concepts/reviews/`, plus a
nested `backlog/history/wfc_reviews/<WI-ID>/review.adoc` form. Nothing in the
repository states the rule that puts a document in one rather than another;
`docs/cold_storage/README.adoc` is seven lines and never mentions its own
subdirectories. The new README must state one rule.

`docs/imported/core-incubator/` and `docs/provenance/` should *stay in place*.
They are already labelled non-authorizing by their own `NOTICE.adoc`, and
`provenance/carveout.yaml` records *source-repository* paths that are correct as
written and must not be "fixed".

== 5. Project Memory: capabilities and necessary additions

The canonical structure is sound and *needs no new tables*. Four flat JSON
tables -- `concerns` (9), `concern_events` (38), `concern_event_xrefs` (68, with
a typed `event_role`), `decisions` (23) -- already express feature-to-commit
(`commit_refs`, `core:`/`wfc:` prefixed), work-to-document
(`decisions.source_path`), and many-to-many event/concern relationships. The 38
events map cleanly onto the 19 proposed groups, which is the best single piece
of evidence that the grouping is right.

The real problem is *coverage, not schema*: the last event is 2026-10-27.
Nothing records `direct@v1`, `robust@v1`, FD-08, `simple@v1` design,
implementation or first real dogfood, the Claude Code adapter, or the 10-30
authority index. Five of the six most recent feature groups are invisible.
Five of nine concerns were last assessed 2026-10-12, so their posture
statements predate the entire Front Door and `simple@v1` period.

Necessary work, all of it data:

* 6-8 new `concern_events` plus xrefs covering 2026-10-27..2026-11-02.
* Refresh `last_assessed_commit` / `last_assessed_date` on all nine concerns.
* Rewrite the 11 `decisions.source_path` values that moved documents invalidate
  (`DEC-WFC-004`, `-010`, `-012`, `-015`, `-017` through `-023`).
* Fix the one stale canonical link in `concerns.json` (it points at
  `FTR-WFC-SCOPE-ESCALATION-CONTINUATION_implementation_review_004.adoc` under
  `docs/backlog/`, where it no longer is).

Deliberately *not* proposed: any new table. A `work_item_xrefs` table making
BUG/FTR traceability queryable is defensible but is a separate maintainer
decision, not part of this cleanup. Edit the canonical JSON directly and review
with `git diff`; the ODS round trip is unnecessary for this.

* *No developer guide.* There is no `docs/developer_guide/`. This is not
  cosmetic: `BUG-WFC-CLAUDE-ADAPTER-WRITE-PERMISSION-MISMATCH` exists because a
  live Run was commissioned to write into that nonexistent directory. Of the
  target entry points, "developing and maintaining WFC" has nothing filling it.
* *Orientation is spread across five surfaces* -- `README.md`,
  `docs/README.adoc` (114-line authority index), `docs/ai_info/_ai_info.adoc`
  (task router), `docs/backlog/README.adoc`, `docs/cold_storage/README.adoc`.
  Keep one index plus the router.
* *The authority index argues with history inside itself.* A 20-line paragraph
  in `docs/README.adoc` defends why three DRAFT product-model documents exist
  and litigates what a 2026-10-15 historical record did and did not prohibit.
  That argument belongs in the archive, not in the current entry point.
* *Inverted weight.* `docs/architecture.md`, declared authority for system
  responsibilities and invariants, is 36 lines. `docs/wfc_operator_manual.adoc`,
  declared to add no authority beyond the documents it summarizes, is 1285
  lines. Worth assessing which invariants exist only in the manual.
* *A concept loose at `docs/` root.*
  `docs/wfc_projected_result_contracts_concept_2026-10-07.adoc` (880 lines) is
  simultaneously historical (P1-P3 delivered) and current (the definition source
  for P3.5/P4/P5 that `_open.adoc` cites by section). It needs a stable current
  home, not archival.
* *Cold-storage conventions are undocumented*, as in SS1.

Per the task constraints, none of these manuals is rewritten now.

== 7. Risks

[horizontal]
Governance immutability (HIGH):: Accepted workflow programmes record the
documents they were compiled from in an immutable `source:` field --
`governance/workflow-programs/simple/v1.yaml` names the `simple@v1` design and
its broad review explicitly -- and repository policy forbids any Run from
writing governance paths. Moving those documents makes an immutable provenance
field stale. *Mitigation:* do not edit accepted programme YAML; leave the stale
path and add a one-line redirect note in the archive group directory.

Authority reclassification (HIGH):: `docs/README.adoc` assigns an authority
class per directory, so every move silently changes a document's declared
class. The Front Door maintainer decision records must not drift into
"historical". *Mitigation:* update `docs/README.adoc` in the same commit as each
move, never afterwards.

MVP-concept citations (HIGH):: `_open.adoc` derives live scope from the document
headed for `future/`. *Mitigation:* re-cite the roadmap against the decision
records *before* that move (batch 7 ordering).

Suspended dogfooding (MEDIUM):: None of this work passes through WFC admission,
review or evidence gates, and
`tests/architecture/test_self_development_governance.py` (7,731 lines, 44 tests)
may assert on governance and document paths. *Mitigation:* `make check` after
every batch -- it is the only gate this work has.

Pre-existing dangling links (MEDIUM):: 124 distinct referenced doc paths do not
resolve. Almost all referrers are frozen governance task records and archived
reviews, which is acceptable, but the 2026-10-15 migration left live-looking
links: its own record is cited 11 times at a `warm_storage` path that no longer
exists. Only 6 dangling targets are referenced from active backlog or warm
storage, and exactly one from a canonical surface. *Mitigation:* fix the
canonical one; adopt the rule that frozen Run records keep their original paths
and are never retro-edited. State that rule, or the next agent will "fix" 100+
historical records.

Sibling clones (LOW):: `workflow-coordinator-runtime` (`5cf0fe1a`, the accepted
Runtime), `workflow-coordinator-docs` (`076fc2e`), `wfc` (`4edcea0`, 2026-10-02)
and `workflow-coordinator-run-evidence` (`c76f9d8`) sit at different HEADs. Path
changes here do not reach them until promotion. *Mitigation:* finish the
restructure before the next Runtime promotion.
