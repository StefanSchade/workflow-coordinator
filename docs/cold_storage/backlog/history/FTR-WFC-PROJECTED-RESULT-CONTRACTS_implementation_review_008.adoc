== Verdict

*ACCEPT; route `accept`.*

The candidate implements the accepted P3 Finding Projection slice without a
blocking defect.  Version 3 makes existing-Finding citation and transition
separate structural forms.  A citation contains only `finding_id` and
`evidence_refs`; parsing and the strict provider schema reject
`proposed_state`, `successor_ref`, and `new_material_evidence` on that form.
A transition carries a typed target.  `successor_ref` exists only on the
supersede target, while resolve, residual, and reopen have their own closed
target shapes.

The v3 reducer dispatches by those types.  Citation performs only evidence
union and never enters `_may_dispose`, including citation of an already
superseded Finding without echoing its successor.  Transitions still validate
the ledger's current state and require the existing operation-specific gate or
human authority.  Reopen retains its new-material check.  The
`ConvergenceRole.CORRECTOR` tracked-obligation guard remains scoped as before.
The new-Finding branch retains v2's local-reference, authority, blocking,
atomicity, tracked-obligation, successor-resolution, and cycle checks.

Versions 1 and 2 retain the legacy `ExistingFindingDelta` parser and reducer
paths.  Version 3 is selected only for `WORK_RESULT` and `REVIEW_VERDICT` in a
schema-v3 profile.  The shared admission predicate is consulted at the
provider-neutral validator, prompt assembly, Codex schema/execute boundary,
and reducer persisted-identity boundary.  It admits versions 1 and 2 for the
three existing families, admits version 3 only for Work and Review, and keeps
generic routing version 3 and all other versions fail-closed.  Generic routing
continues to use its unchanged v1/v2 parser and schema.

The `adapter.py` change is limited to replacing its coarse version check with
that pair-aware predicate.  The `prompt.py` change makes the corresponding
pair-aware admission/default selection and does not alter component selection,
prompt ordering, vocabulary, or composition.  No P3.5 authority composition,
P4/P5 work, route-selection change, provider registry, transport redesign,
Claude support, migration, version pinning, pairless-history mechanism, or
cross-version continuation support appears in the candidate.
