Invariant:: The README's documented developer commands must be usable: `make
lint` and consequently `make check` must succeed for the committed repository,
or their scope and configuration must accurately reflect what they validate.

Evidence:: `python -m ruff check . --no-cache` reported 356 violations.  The
violations include the candidate snapshot script (`I001`) as well as existing
repository files.  `python -m ruff format --check .` also reports files that
would be reformatted.  Because the Makefile defines `lint` as `ruff check .`
and `check` depends on `lint`, both advertised commands fail on the committed
repository.

Impact:: This defeats the primary developer-ergonomics promise of a runnable
`make lint` / `make check` workflow.

Required bounded correction:: Within the existing implementation scope, make
the configured Make/Ruff workflow pass and ensure it accurately covers the
intended files.  The correction must not broaden into unrelated source,
workflow, profile, or policy changes.
