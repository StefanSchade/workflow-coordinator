= WI-WFC-DEVELOPER-ERGONOMICS-REVIEW-003 -- Independent Review

Independent review of the developer-ergonomics implementation at
`0e85a751b76cdeb2a78f1ddc55141b9656c8a814`.

== Scope and method

This fresh review independently inspected the original standalone
developer-ergonomics payload, the current Makefile and README development
instructions, Ruff/dev-tool configuration, snapshot script and its test, and
the installed-package boundary guard. Historical Attempt-4 material was not
used as a current finding or state.

== Blocking finding

The documented/default developer workflow is not runnable in a supported
environment that supplies `python3` but no bare `python`.

`README.md` tells a developer to install both the package and the development
extra with `python -m pip ...`. `Makefile` also defaults `PYTHON` to `python`.
The project requires Python 3.10 or later, but neither location documents a
bare-`python` prerequisite or a virtual-environment activation step that would
provide that command.

This was reproduced with the prepared development interpreter and all declared
development tools available as `python3`, but with no `python` executable on
`PATH`:

[source,shell]
----
env PATH=<python3-only-bin>:/usr/bin:/bin make check
----

Result:: `make` invoked `python -m ruff check .` and failed with
`make: python: No such file or directory` before linting. The README's initial
`python -m pip install ...` command has the same unavailable executable.

This prevents the documented setup and the default Make targets from working
on the stated environment, so it is blocking. It is a new current-Run finding;
its identifier must be allocated by the Coordinator.

== Other observations

The snapshot utility produced the four documented WFC-prefixed outputs, with

ergonomics payload and does not affect the reproduced Makefile/README defect.
