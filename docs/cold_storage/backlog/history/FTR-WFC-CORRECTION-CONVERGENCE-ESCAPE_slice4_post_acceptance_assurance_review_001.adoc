== OPUS-S4-001 -- Persisted Run-v3 replay validation is weaker than live reduction

*Severity: BLOCKING.*

=== Invariant

Run-v3 replay must be fail-closed over the complete Slice-4 causal chain, so
that no persisted history which valid live execution could not have produced can
reach derived strategy-generation advancement. `S4-IR-001` stated this scope
explicitly, naming *role provenance* and *Finding state/generation at the
escape* among the unproven facts. The accepted FTR (question F) additionally
requires Core to reject the complete result when a chain reference "points to a
Finding that is now closed, residualized, superseded, or no longer at the
event's recorded generation", and (question I) characterizes the escape event as
"an immutable routing decision".

=== Current code path

* `src/workflow_coordinator/serialization.py:1907-2031` -- the Slice-4 wire
  validator reconstructs the chain from `hop.diagnosis`,
  `hop.strategy_revision`, `hop.strategy_assessment` and `hop.route_reason`
  only. It never consults `hop.phase`, `hop.role`, `hop.attribution`, or
  `hop.applied_route`. Its `tracked_ids` set
  (`serialization.py:1920-1924`) tests only
  `finding.correction_obligation is not None`, not
  `state is OPEN and blocking`.
* `src/workflow_coordinator/reducer.py:824-889` -- the live validator
  `_validate_strategy_chain` is strictly stronger: it derives `open_ids` with
  `state is FindingState.OPEN and finding.blocking`
  (`reducer.py:841-847`). Reduction additionally enforces phase/role gating
  (`reducer.py:903-904`, `930-931`, `1012-1013`) and strategy-gate route
  authority (`reducer.py:989-1007`).
* `src/workflow_coordinator/reducer.py:195-281` --
  `validate_convergence_route_history`, the only profile-aware replay boundary,
  iterates *only* hops carrying a non-`None` `route_reason`. It never
  re-examines a persisted diagnosis, revision, or assessment, so it supplies
  none of the missing provenance. It also deliberately permits
  `applied_route is None` for `supervisor_judgment_required` and
  `autonomous_hop_budget_exhausted` (`reducer.py:208-226`), which is correct
  for Slice-3 escape replay but is not compensated for anywhere in the Slice-4
  chain check.

=== Independently reproduced classes of invalid persisted history

Starting from one genuine live-reduced chain (`H005` escape
`convergence_escape:F001`, `H006` diagnosis, `H007` revision, `H008` accepted
assessment, deriving `strategy_generation=1`), each mutation below was applied
to the persisted bytes alone and round-tripped through
`run_to_json()`/`run_from_json()`:

. *Phase/role relabelling.* The diagnosis and revision Hops relabelled
  `phase="correct"`/`role="worker"` and the accepted-assessment Hop relabelled
  `phase="evaluate"`/`role="independent_reviewer"` -- i.e. a chain whose records
  are authored by phases that could not author them live.
. *Supervisor judgment still pending.* The escape Hop's `applied_route` set to
  `null` with `stop_reason="supervisor_judgment_required"`, validated against
  `convergence_routing_profile(escape_supervisor=True)` -- i.e. a complete
  strategy chain anchored to an escape whose supervisor gate was never
  satisfied and whose escape route was therefore never applied.
. *Autonomous-hop-budget preemption.* The escape Hop's `applied_route` set to
  `null` with `stop_reason="autonomous_hop_budget_exhausted"` -- again a
  complete chain anchored to an escape that was never applied.
. *Trigger Finding no longer open.* On a two-Finding escape
  `convergence_escape:F001,F002` with an otherwise complete valid chain, `F002`
  persisted as `state="residual"`, `blocking=false` rather than remaining
  open/blocking/tracked.

In every one of the four cases:

----
run_from_json:                      ACCEPTED
validate_convergence_route_history: ACCEPTED
derive_convergence_facts:           F001 strategy_generation=1,
                                    qualified_cycle_count=0
----

and `convergence_prompt_context()` published the advanced fact to the next
dispatch.

=== Live controls

The same semantics attempted through `reduce_result()` on the same profile are
refused:

----
corrector phase submits a diagnosis
  -> mechanical_preemption:...:corrector cannot submit strategy records
evaluator phase submits a diagnosis
  -> rejected (reducer.py:1012-1013, "evaluator cannot submit strategy records")
diagnosis naming a resolved trigger Finding
  -> mechanical_preemption:...:escape trigger Finding is no longer open and tracked
----

Cases 2 and 3 are live-unreachable outright: while the escape is pending or
preempted the Run is not `running`, and `record_hop()` raises
`Run status prohibits invocation`.

=== Expected versus actual

Expected:: each of the four histories is rejected -- by `run_from_json()`, or at
latest by `validate_convergence_route_history()` -- *before*
`derive_convergence_facts()`, `checkpoint_projection()`, or
`convergence_prompt_context()` can observe it.
Actual:: all four parse, both replay validators accept, the derived generation
advances, the qualified-cycle count resets to zero, and the advanced fact is
projected as Coordinator-derived truth.

=== Key consequence

These malformed persisted histories can be admitted and influence
`derive_convergence_facts()`, including strategy-generation advancement,
although valid live execution could not have produced them. Case 2 is the
sharpest: a persisted history can present a complete accepted strategy chain
built on an escape whose supervisor judgment was never given, and replay treats
the resulting generation advancement as truth. That is an authority effect, not
only a bookkeeping one.

=== Why existing assurance missed it

Every S4 reproduction in the review chain (`S4-IR-001` original, `S4-IR-003`,
`S4-IR-004`) forged a chain that was *internally* non-causal: a nonexistent
diagnosis Hop, two active escapes, a same-Hop diagnosis. Each correction added
the predicate that rejected that one shape (`b5f4aba` link reconstruction,
`637614a` single-active-escape, `ea45e56` one strict comparison). None of the
three reviews tested a chain that is internally perfectly causal but externally
unauthorized -- wrong phase, unapplied escape, or a trigger Finding no longer
open. The committed tests carry the same bias: all three new
`test_run_v3_rejects_*` cases mutate internal references only. The predicate
class was never generalized, and `_validate_v3_run` and
`_validate_strategy_chain` were allowed to diverge rather than converge.

=== Required semantic correction (obligation only; not implemented here)

* Persisted replay must prove the equivalent relevant authority and provenance
  facts that live reduction proves, *before* strategy material may affect any
  derived truth or projection.
* A persisted strategy record must originate from the phase/role semantics that
  own that record type -- and, for the assessment, from an independent gate.
* The referenced escape must actually have been applied; a `route_reason` whose
  Hop has `applied_route is null` is a pending or preempted routing decision and
  must not anchor a chain.
* Every triggering Finding must satisfy the required open/blocking/tracked state
  at the relevant causal point, not merely carry a correction obligation.
* Because the first two obligations are profile-dependent, the natural home is
  `validate_convergence_route_history()` (or a sibling invoked from every path
  that reaches derivation or projection), with the wire validator retaining only
  the profile-free subset. This artifact states the obligation, not the design.
* The existing exact-sorted-trigger-set, strict temporal-order,
  latest-revision, one-current-unconsumed-escape and exactly-once rules all
  remain required and must survive the correction unchanged, and the valid chain
  must still advance exactly once.

== OPUS-S4-003 -- First-versus-latest diagnosis projection asymmetry

*Severity: NON-BLOCKING.*

Invariant:: projections must not present a consumer with a diagnosis that is not
the one the accepted assessment is correlated to (FTR question I: "any current
diagnosis, proposed strategy, and independently accepted strategy generation
with explicit attribution").

Evidence:: `persistence.py:530` and `vertical.py:176` select an escape's
`diagnosis` with `next(... for item in run.hops if ...)` -- *first* match --
while `strategy_revision` and `strategy_assessment` on the following lines use
`for item in reversed(run.hops)` -- *last* match. `_validate_v3_run` places no
cap on the number of diagnoses naming one unconsumed escape.

Reproduction:: a persisted history with two diagnosis Hops naming the same
unconsumed escape, where the revision and the accepted assessment correlate to
the second (`H007`):

----
run_from_json:                      ACCEPTED
validate_convergence_route_history: ACCEPTED
derived:                            strategy_generation=1
projected diagnosis hop:            H006 ("FIRST stale diagnosis")
chain actually used diagnosis:      H007 ("SECOND diagnosis actually used")
----

Normal live topology cannot currently create this shape: the profile permits
`diagnosis -> reframe` only, and `strategy_gate(changes_required) -> reframe`,
never back to diagnosis, so there is exactly one diagnosis per escape live.
Today it is reachable only through the same wire gap as OPUS-S4-001. It is
recorded separately because the first/last asymmetry is a real projection and
replay hardening concern in its own right and would survive a correction to
OPUS-S4-001 that merely added role provenance.

This finding is *not* promoted to BLOCKING.

Hardening obligation (obligation only):: make the per-escape record selection
single-valued and consistent -- either reject a second diagnosis for one
unconsumed escape on the wire, or select every projected record by the same
"latest, and the one the chain references" rule.

Why existing assurance missed it:: `S4-IR-002` was closed on field presence and
on agreement between checkpoint and prompt. Both projections share the same
asymmetry, so they agree with each other while both can disagree with the chain;
an agreement test cannot detect it, and no test constructs more than one
diagnosis per escape.

== OPUS-S4-004 -- Misleading mechanical-preemption stop label

*Severity: OBSERVATION.*

Every `ReductionError` raised inside `reduce_result()`'s convergence block is
stamped `mechanical_preemption:invalid_finding_delta:{error}`
(`reducer.py:1322`). Slice 4 routes all of its new error classes through it, so
an operator sees, verbatim:

----
mechanical_preemption:invalid_finding_delta:accepted strategy assessment
  requires completed outcome and a correction route
mechanical_preemption:invalid_finding_delta:strategy_gate result cannot mutate
  Findings
mechanical_preemption:invalid_finding_delta:escape trigger Finding is no longer
  open and tracked
mechanical_preemption:invalid_finding_delta:corrector cannot submit strategy
  records
----

None of these is a Finding-delta error. The label *predates* Slice 4 --
Slice-1/2/3 coverage and assessment errors already used it -- so this is not a
Slice-4 regression; Slice 4 roughly doubles the error classes it mislabels. This
is operator-legibility debt only. There is no authority or derived-truth effect,
and it is *not* a Slice-4 acceptance blocker. Its visible manifestation in the
accepted delta is the `tests/unit/test_slice3_vertical.py:386` assertion change
from `"stopped"` to `awaiting_human` plus
`mechanical_preemption:invalid_finding_delta:`.

== OPUS-S4-005 -- Result-v2 schema structurally permits strategy records in more phases than may use them

*Severity: OBSERVATION.*

Slice 4 removed the result-v2 null-only guard in `routing_result_from_data()`
and widened the dispatched strict schema from `{"type": "null"}` to
`anyOf: [null, <strict object>]` for all three records. Because
`expected_result_version` is 2 for *every* phase of a v3 profile
(`reducer.py:1167-1174`), an ordinary, corrector, or evaluator phase is now
dispatched a schema that structurally permits a diagnosis, revision, or
assessment, and the role narrowing happens only later in reduction. A provider
emitting a stray record in those phases therefore converts a formerly
schema-impossible output into a fail-closed `awaiting_human` preemption.

Explicitly:

* this is design-conformant under the current accepted Slice-4 design -- FTR
  question I specifies a single v2 result shape with phase-appropriate *version*
  validation, and requires exact-set output only of the three convergence
  prompts;
* it is *not* a Slice-4 defect;
* it is relevant to the already-separate future Phase-Completion / projected
  contract work (`BUG-WFC-PHASE-COMPLETION-CONTRACT-OPAQUENESS.adoc`), because
  it enlarges the human-stop surface for the common phases of every v3 Run;
* this review does *not* authorize that future redesign, and did not review
  projected phase-specific result schemas, Coordinator-owned deterministic
  effects, Commission generation, the Operator Harness, or future Runtime
  hard-hop-ceiling configuration.

It is also the mechanism behind OPUS-S4-004's visible symptom.

=== S4-IR-001 -- Persisted strategy records are not replay-validated as one exact causal chain

*Closure falsified.*

The identifier's own stated scope named role provenance and Finding
state/generation at the escape as unproven, and its correction obligation
required replay to reject malformed historical chains fail-closed and to prove
exactly-once advancement for a complete valid chain. At HEAD,
`_validate_v3_run` consults no phase, role, attribution, or `applied_route`, and
tests Finding membership rather than open/blocking state;
`validate_convergence_route_history` never re-examines a strategy record. Four
distinct persisted histories are admitted by both replay validators and advance
a derived generation (OPUS-S4-001). The exactly-once proof obligation is also
unmet, because the advancement code never executes in the suite
(OPUS-S4-002). The *enumerated* `H005` sentence -- exactly one active escape,
exact trigger set, temporally causal, latest completed revision -- is
individually true, and each clause was independently confirmed; it is simply a
narrower claim than the identifier it closed.

=== S4-IR-002 -- Checkpoint and operator projection omit the immutable trigger generations

*Substantive closure survives challenge, but part of its cited evidence is
factually unsupported.*

The substance was independently verified on a live two-generation chain:
`checkpoint_projection()` emits per-escape `trigger_generations` (`{F001:0}` for
the first escape, `{F001:1}` for the second), `operator.py:1677` consumes that
same checkpoint `convergence` block, `convergence_prompt_context()` emits the
identical mapping, and all three agree with
`derive_convergence_facts(... strategy_generation=2)` across a
`run_to_json()`/`run_from_json()` round trip. The requirement is met. The
closure's *evidence* -- an "added persisted complete-chain projection test" --
is not supported (OPUS-S4-002). The latent record-selection asymmetry is
recorded as OPUS-S4-003.

=== S4-IR-003 -- Multiple persisted unconsumed escapes permit an older chain to advance generation

*Closure survives challenge.*

`serialization.py:1932-1937` rejects the second unconsumed escape at the point
it is added, and `serialization.py:1948-1954` independently refuses any strategy
record unless exactly one escape is unconsumed. The committed counterexample
raises `ValidationError: Run v3 contains more than one unconsumed escape`. The
predicate was also confirmed not to be over-strict: a legitimate
consumed-escape-then-new-escape history (two full generations, escapes `H005`
and `H012`) still parses, replays, and derives `strategy_generation=2`.
Cross-escape link substitution also holds -- an assessment naming a new escape
with the previous chain's diagnosis or revision is rejected.

=== S4-IR-004 -- Persisted strategy chain permits a same-Hop escape and diagnosis

*Closure survives challenge.*

`serialization.py:1962` is the `H004` fix and it is correct. All four temporal
edges were confirmed *strictly* ordered on replay: escape < diagnosis (1962),
diagnosis < revision (1979), diagnosis < assessment (2014), revision <
assessment (2015); escape < assessment follows transitively because `diagnoses`
is populated only after edge 1962 passes. The live path enforces the same
strictness (`reducer.py:862`, `874`, `879`). No admitted same-Hop or inverted
order variant was found.

== Positive assurance evidence -- adversarial probes that did not falsify the implementation

This section is deliberately preserved. The artifact is not a defect-only
summary; absence of a finding in these areas is itself evidence, bounded by what
was actually executed.

* *Duplicate / unsorted trigger IDs rejected.* The review's strongest initial
  hypothesis -- `derive_convergence_facts` increments per *occurrence* in
  `accepted.finding_ids` (`reducer.py:153-155`), so
  `convergence_escape:F001,F001` would advance one Finding twice -- does not
  reproduce. The pre-existing Slice-3 guard `serialization.py:1842-1854`
  requires `trigger_ids == sorted(set(trigger_ids))` plus `F[0-9]{3,}` shape
  plus existence in `findings`, so parsing raises
  `Run v3 Hop H005 has malformed convergence route truth`. The profile-aware
  `reducer.py:277-281` independently pins the trigger set to the sorted
  goalpost-reached set. The "exact sorted trigger IDs" claim is sound.
* *Double consumption rejected.* A second accepted assessment for an
  already-consumed escape is rejected on both paths. No representation advanced
  twice.
* *`changes_required` does not advance generation.* Verified live: the escape
  stays `unconsumed`, the generation stays 0, the qualified count and
  `goalpost_reached` are untouched, and the route goes to `reframe`. Routing a
  `changes_required` assessment to a corrector is rejected; routing an
  `accepted` assessment to `reframe` is rejected; `RouteEffect.COMPLETE` from a
  strategy gate is rejected.
* *Stale revision rejected.* `changes_required -> new revision -> accepted`
  advances exactly once, and an accept naming the superseded revision is
  rejected with `strategy assessment must reference the latest revision`.
* *Exact trigger correlation held.* On a two-Finding escape `{F001,F002}`:
  subset `("F001",)`, reordered `("F002","F001")`, and superset `(+"F999")` are
  each rejected live with
  `diagnosis does not exactly correlate to the active escape`.
