== Blocking review finding

The committed candidate does not preserve the required unconditional rejection
of an attempt to alter an existing Finding's invariant.

`FindingDelta` remains a single public in-memory model with optional
`invariant` and `blocking` fields.  Consequently, a caller can construct an
existing-Finding delta such as
`FindingDelta(finding_id="F001", invariant="attempted rewrite", ...)`.
`_apply_finding_deltas` no longer checks that field and silently accepts the
delta, using the ledger value instead.  The newly added
`test_existing_finding_derives_immutable_and_carried_forward_ledger_values`
asserts this accepted path directly.

The strict wire parser and Codex schema correctly reject `invariant` for an
existing-Finding payload, but they do not make the reducer's public model API
safe.  The authorized correction scope expressly retains unconditional
rejection of *any* attempt to alter an invariant.  Restore that fail-closed
property for directly constructed model values (preferably by a genuinely
distinct existing-Finding model shape; at minimum, reject a non-null invariant
before applying an existing-Finding delta) and replace the acceptance test with
a fail-closed regression.  Keep ledger-derived blocking and same-state
successor behavior intact.
