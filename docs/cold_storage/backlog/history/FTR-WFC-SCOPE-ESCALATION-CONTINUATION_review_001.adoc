== Verdict

*CHANGES_REQUIRED; route `correct`.*

The design gets the central architecture right: semantic observation is kept
orthogonal to mechanical control; `awaiting_human` is a terminal disposition
for this admitted execution rather than same-Run suspension; predecessor truth
is backward-linked rather than back-patched; salvage is optional, operator-owned,
and non-authoritative; and a successor must start from a clean admitted Git
baseline and earn its own evidence and commit.

It is not yet implementation-ready. The design does not define the Run wire
transition needed by its two new Run fields, even though current parsing is
strict schema v1 and successor preparation consumes a predecessor `run.json`.
It also makes an unenforceable claim that a raw candidate bundle contains no
credentials. Both gaps sit on the mechanism's load-bearing persistence/trust
boundary and need bounded correction before acceptance.

These are ordinary design-review defects. This review creates no WFC
Current-Run Finding and requests no Finding disposition.

== Blocking design defects

=== B1 -- The Run wire-version and legacy predecessor transition is undefined

The proposed model adds `Run.semantic_stop` and `Run.successor_provenance`, and
the preparation command is defined to read and digest a frozen predecessor
`run.json`. The record never says whether this changes `Run.schema_version`, how
schema-v1 snapshots are parsed after implementation, or what successor
eligibility means when an immutable legacy predecessor has no `semantic_stop`.

This is not a cosmetic serialization detail. Current `run_from_json()` uses
`required={field.name for field in fields(Run)}`. Adding the fields naively makes
every existing schema-v1 snapshot fail because the keys are absent. Treating
the keys as optional without a version change silently changes schema v1.
Bumping the version and rejecting v1 can strand existing state and weaken the
separately tracked same-Run recovery path. Backfilling the observed frozen Run
would violate this design's own predecessor-immutability invariant, while
inventing a semantic stop from salvage or operator prose would create false Run
truth.

The proposed tests cover a new-state round trip and say existing recovery tests
remain green, but they contain no legacy `run.json` fixture, migration/load
rule, or preparation rejection for a predecessor that legitimately lacks the
new field.

Required correction:

. Choose and state an exact Run wire-version transition.
. Define strict parsing/validation for both newly written state and pre-change
  schema-v1 state, including whether old state is loadable for same-Run
  recovery and how absent new fields are represented without fabricating facts.
. Define fail-closed `prepare-successor` eligibility for a frozen predecessor
  that lacks a captured semantic stop. If the historical observed Run is not
  eligible for the new automated path, say so explicitly; do not back-patch it.
. Add exact serialization and operator tests for legacy load/rejection,
  no fabricated semantic stop or provenance, and preservation of existing
  same-Run recovery semantics.

This correction fits the already proposed production/test path set; it does not
require widening the later implementation scope.

=== B2 -- The exporter cannot guarantee that raw salvage contains no credentials

The salvage section says, “The bundle contains no credentials by design; a path
or content safety violation fails export closed.” The stated capture rules do
not and cannot establish that fact. A tracked authorized-scope file or an
eligible untracked in-scope file may contain a credential, another secret, or
adversarial prompt text. Excluding ignored files, out-of-scope paths, unsafe
symlinks, and special files is valuable containment, but it is not content
classification. Current WFC has no trusted secret detector, and hashes prove
only byte identity.

The rest of the design correctly calls the bytes untrusted and makes export and
successor inclusion explicit, but the impossible credential-free assertion
would let an implementation or operator overestimate both storage safety and
the safety of sending rendered salvage to a fresh provider invocation.

Required correction:

. Remove the credential-free guarantee and name sensitive content and prompt
  injection as residual properties of untrusted salvage.
. State the bounded fail-closed handling: export and later provider exposure
  remain separate explicit operator choices; destination permissions/retention
  must be appropriate for potentially sensitive bytes; WFC must not upload or
  expose omitted/raw objects implicitly; hashes and labels do not sanitize
  content.
. Add acceptance checks that the command makes no credential-free or sanitized
  claim, uses restrictive local publication semantics, and never injects
  non-selected or over-limit raw content into the successor prompt.

No generic containment system, secret scanner, provider-session feature, or
outer planner is required by this correction.

== Required-question disposition

Questions A through G are substantively answered: an explicit semantic-stop
record is justified; the predecessor remains terminal `awaiting_human`; WFC
exports optional operator-owned salvage without treating it as state; successor
provenance points backward through an explicit authority decision; salvage is a
separately delimited untrusted context item; the split CLI is smaller and safer
than a combined continuation command; and each named failure fails closed.

Question H is also nearly sufficient. The closed production set
(`model.py`, `serialization.py`, `reducer.py`, `persistence.py`, `operator.py`,
and `git_facts.py`) matches the existing seams. The ordinary test set covers the
right modules, and the real observed layered-stop regression is correctly
required at the operator/vertical boundary rather than only as a reducer unit.
B1 and B2 need more exact cases inside those already listed test paths; no new
implementation path is presently justified.
