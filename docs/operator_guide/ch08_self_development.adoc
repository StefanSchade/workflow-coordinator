== Self-development

*Transitional status (2026-11-05):* this chapter is the narrowed
operator-guidance slice of Batch 4, not the full fold -- see
link:ch02_run_preparation.adoc[the Run-preparation chapter]'s own
transitional note. It assembles
link:../self-development.adoc[`self-development.adoc`] into this reading
path without superseding it; that document remains the normative
Runtime-N/Development-N+1 contract (`docs/README.adoc`'s index). WFC
self-development stays the special case it has always been: here, the WFC
Operator and WFC Developer roles coincide in one maintainer
(consolidation plan §5), which is exactly why restoring this workflow is
the current priority.

=== Topology

Accepted Runtime WFC N operates on the separate Development WFC N+1 clone
(this checkout) and never mutates itself; the two have separate Git
directories and object stores. The Runtime checkout must stay detached,
clean, and push-disabled (`remote.origin.pushurl=DISABLED`) -- never
mutated by Harness or by a Run, only by explicit maintainer promotion
below. The sibling `workflow-coordinator-run-evidence` repository holds the
durable archive and the curated semantic run ledger. Full mechanics
(launch-environment `PATH` assembly, `snapshot_environment()` /
`prepare_evidence_commands()` verification, the legacy `--durable-artifact`
prohibition) are owned by
link:../self-development.adoc[`self-development.adoc`]'s "Topology and
preparation" section; not restated here. Ordinary preparation mechanics,
shared with every other WFC-operated repository, are
link:ch02_run_preparation.adoc[the previous chapter]'s job, not this one's.

=== Hop budget (`max_autonomous_hops`)

Do not set the authorized Hop ceiling equal to the happy-path expected Hop
count -- that has repeatedly produced unnecessarily tight budgets. For an
ordinary iterative implementation/review/correction Commission, prefer a
generous provisional ceiling of roughly *10 Hops* even when four or six is
the happy-path expectation; unused authorized Hops cost nothing, while a
tight ceiling reliably stops a still-converging Run. The current hard
Coordinator ceiling is `20`
(`DEC-WFC-007`/`DEC-WFC-008`). This is a provisional default, not a rule --
a concrete reason to restrict iteration, a task-specific constraint, or an
explicit maintainer decision still governs. Full rationale and the
`Run.hop_limit` reporting mechanics:
link:../self-development.adoc[`self-development.adoc`]'s "Commission Hop
budget" section and
link:../wfc_operator_manual.adoc[operator manual] §12.

=== Ownership and promotion

The maintainer owns RepositoryPolicy, profile, WorkItem, task, scope,
acceptance, push, and any later Runtime promotion; WFC coordinates only the
committed envelope and may create only its own authorized local commits.
Promotion is never automatic: it always targets the exact commit
independently accepted as the desired Runtime implementation identity --
never latest `main`, current Development HEAD, or a `git pull` -- and is a
local, maintainer-executed action requiring no push. A Development salvage
commit (see
link:../run-recovery-and-salvage.adoc[Run recovery and maintainer salvage])
never promotes Runtime automatically, even when a fresh successor
Commission is later based on Development history that contains one. The
exact mechanism, preconditions, and postconditions are owned by
link:../self-development.adoc[`self-development.adoc`]'s "Runtime promotion
runbook"; this chapter gives the one-paragraph summary a fresh agent needs
to avoid the most common operator misunderstanding (collapsing
Development HEAD with what Runtime actually executes), not the procedure
itself.
