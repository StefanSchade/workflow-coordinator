=== What preparation is, and is not

Once a semantic Commission (WorkItem, Profile, RepositoryPolicy, Components,
Task) has been reviewed and committed, preparation is deterministic
maintainer/operator mechanics -- pinning commits, materializing OPS, writing
`execution-bindings.yaml`, running provider-free preflight, and writing
`launch.sh`. It is not another agent Hop and does not require an LLM to
decide anything. Three boundaries stay distinct: the Commission commit
(semantic authority fixed), `launch.sh` execution (only the maintainer's
explicit act, entering the provider-capable path), and the first real
provider invocation (the actual provider-boundary crossing) --
link:../run-preparation.adoc[`run-preparation.adoc`]'s "Three boundaries" and
"Canonical sequence" sections own the full ten-step rationale; it is not
restated here.

=== Today's mechanism: Harness v0

`scripts/wfc_op.py prepare` mechanizes exactly that contract
(`DEC-WFC-016`; link:../wfc_operator_manual.adoc[operator manual] §7). Run it
from the Development repository root as `python3 scripts/wfc_op.py ...`.
*Verified against the current implementation (2026-11-05):* this is
repo-local today -- `pyproject.toml` packages only `workflow_coordinator*`
from `src/`, not `scripts/wfc_op.py` -- so there is no installed `wfc-op`
console command yet. The 0.1.0b1 target is a pip-installable, consumer-
neutral Operator Harness and Front Door usable against an unrelated
consumer repository without a WFC source checkout (consolidation plan,
"Maintainer decisions (2026-11-04)" §§2-3); that target is not implemented
today, and this chapter does not claim otherwise.

=== Self-development specialization, in one line

For a self-development Run, `TARGET` is the Development N+1 clone (this
checkout) and `RUNTIME` is the separately promoted Runtime N clone, with its
own detached / push-disabled invariant. Read
link:ch08_self_development.adoc[the self-development chapter] for the full
topology, Hop-budget guidance, and promotion runbook before filling in the
command below, if this is your first self-development Run.

=== The command

[source,shell]
----
ATTEMPT=wfc-<work-item-slug>-<date>-<counter>

python3 scripts/wfc_op.py prepare \
  --attempt         "$ATTEMPT" \
  --development     /home/stefan/repos/spreadsheet-handling/workflow-coordinator \
  --runtime         /home/stefan/repos/spreadsheet-handling/workflow-coordinator-runtime \
  --evidence        /home/stefan/repos/spreadsheet-handling/workflow-coordinator-run-evidence \
  --work-item       governance/work-items/<work-item-slug>.yaml \
  --profile         governance/self-development/<work-item-slug>-profile.yaml \
  --policy          governance/self-development/<work-item-slug>-policy.yaml \
  --components      governance/self-development/components.yaml \
  --task            governance/work-items/<work-item-slug>-task.txt \
  --executable      <absolute path to the provider CLI> \
  --timeout-seconds 3600 \
  --role-binding    worker=<adapter>:<model>:<reasoning> \
  --role-binding    independent_reviewer=<adapter>:<model>:<reasoning>
----

The `--work-item`/`--profile`/`--policy`/`--task` filenames above follow the
naming convention `governance/self-development/` and `governance/work-items/`
already use on disk (`<work-item-slug>-profile.yaml`,
`<work-item-slug>-policy.yaml`, a shared `components.yaml`, and a
repository-wide `repository-policy.yaml` baseline); verified against that
directory on 2026-11-05. For `--executable`, verify the absolute path on
this host with `which codex` or `which claude` -- do not assume
`/usr/local/bin/<name>`. Both `codex_cli` and `claude_cli` are implemented
`--role-binding` adapters (`src/workflow_coordinator/operator.py:85,90`);
`<adapter>` is one of those two literal strings. The flags, their exact
semantics, and every refusal condition remain owned by
link:../wfc_operator_manual.adoc[the operator manual] §7; this chapter does
not restate them.

=== Expected result

`PREPARED / NOT LAUNCHED` printed; `~/wfc-ops/$ATTEMPT` now exists; STATE
does *not* exist yet -- that absence is required, not a defect. If `prepare`
refuses, read the named mismatch; see
link:../wfc_operator_manual.adoc[operator manual] §17 (Troubleshooting).
Never hand-edit OPS or preparation records; correct the input and re-run
`prepare`.

Continue to "Launch, monitor, and archive" in
link:operator_guide.adoc[the entry document] (or, reading this chapter
standalone, in `docs/wfc_operator_manual.adoc` §§8-10).
