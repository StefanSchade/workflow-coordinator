== Handling a stopped Run

A Run or Hop that does not cleanly complete resolves into exactly one of
four maintainer-chosen outcomes (none automatic):

[cols="2,4",options="header"]
|===
|Outcome |Use when

|1. Same-Run reconcile/resume
|The accepted reconcile/resume predicates allow it (`FTR-WFC-ATOMIC-HOP-RECOVERY.adoc`).

|2. Maintainer salvage + fresh successor Run
|Useful candidate work exists but the predecessor Run/Hop cannot or should
not continue under the same authority/truth.

|3. Forensic preservation only
|The dirty worktree has unauthorized mutations, unexplained untracked
files, or an ambiguous baseline -- do not create an ordinary salvage commit.

|4. Discard
|The candidate has no preservation value.
|===

The central invariant: *salvage preserves work, not authority* -- the
historical Run record is never rewritten. The full four-outcome procedure,
the canonical salvage steps, and the current manual successor-continuation
walkthrough are owned by
link:../run-recovery-and-salvage.adoc[Run recovery and maintainer salvage]
and
link:../successor_continuation_runbook_2026-10-10.adoc[the successor-
continuation runbook] §§3-4 ("Core invariants" and "Current manual
procedure" -- its §2 worked case and §6 captured experience are
illustrative background, not the procedure itself); neither is restated
here, and this guide does not change which of them is authoritative.
