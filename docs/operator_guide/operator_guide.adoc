== Launch, monitor, and archive

Once `ch02` ends with `PREPARED / NOT LAUNCHED`:

[source,shell]
----
python3 scripts/wfc_op.py status "$ATTEMPT"   # expect PREPARED_NOT_LAUNCHED
python3 scripts/wfc_op.py launch "$ATTEMPT"   # enters the provider-capable path; the Run itself
                                               # crosses the provider boundary only at its first
                                               # real invocation, not at this command
python3 scripts/wfc_op.py status "$ATTEMPT"   # inspect state, not the return code alone
----

`launch` may run for a long time; `status` is strictly read-only and safe
to run repeatedly from a second shell while it does. A non-zero `launch`
return code does *not* by itself mean provider or Harness failure --
`awaiting_human` and other legitimate terminal states can produce one too.
Always inspect `status`'s persisted facts
(`lifecycle`, `run_status`, `current_phase`, `hop_used`/`hop_limit`,
`stop_reason`, `human_question`, `anomalies`), never the return code alone;
full field-by-field guidance is
link:../wfc_operator_manual.adoc[operator manual] §§9, 13.

Once the Run reaches a terminal state:

[source,shell]
----
python3 scripts/wfc_op.py archive "$ATTEMPT" --dry-run
python3 scripts/wfc_op.py archive "$ATTEMPT"
----

This performs only the deterministic mechanical archive (a faithful
copy-with-manifest into the sibling Evidence repository). Curating the
semantic run ledger is a separate maintainer/LLM-assisted judgment, never
automated by Harness v0 -- see
link:../wfc_operator_manual.adoc[operator manual] §§11, 16.

== Handling a stopped Run

A Run or Hop that does not cleanly complete resolves into exactly one of
four maintainer-chosen outcomes (none automatic):

[cols="2,4",options="header"]
|===
|Outcome |Use when

|1. Same-Run reconcile/resume
|The accepted reconcile/resume predicates allow it (`FTR-WFC-ATOMIC-HOP-RECOVERY.adoc`).

|2. Maintainer salvage + fresh successor Run
|Useful candidate work exists but the predecessor Run/Hop cannot or should
not continue under the same authority/truth.

|3. Forensic preservation only
|The dirty worktree has unauthorized mutations, unexplained untracked
files, or an ambiguous baseline -- do not create an ordinary salvage commit.

|4. Discard
|The candidate has no preservation value.
|===

The central invariant: *salvage preserves work, not authority* -- the
historical Run record is never rewritten. The full four-outcome procedure,
the canonical salvage steps, and the current manual successor-continuation
walkthrough are owned by
link:../run-recovery-and-salvage.adoc[Run recovery and maintainer salvage]
and
link:../successor_continuation_runbook_2026-10-10.adoc[the successor-
continuation runbook] §§3-4 ("Core invariants" and "Current manual
procedure" -- its §2 worked case and §6 captured experience are
illustrative background, not the procedure itself); neither is restated
here, and this guide does not change which of them is authoritative.
