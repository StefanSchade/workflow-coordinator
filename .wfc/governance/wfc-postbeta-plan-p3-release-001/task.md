DELIVER docs/backlog/postbeta_plan_p3_release_engineering.adoc with: (1) the disposition table described above, with the evidence for each row; (2) the release contract decisions WFC must take before any pipeline is wired (versioning scheme and the tag, what a release artifact contains and must not contain, the install check from a clean environment, release notes, whether to publish version-pinned documentation, what runs on a hosted runner given WFC's offline-input test mechanism), each with a recommendation; (3) the list of every place that needs HUMAN access or a maintainer choice (repository secrets, a PyPI or TestPyPI trusted publisher or token, repository visibility, Pages, tag creation, publication): the Operator cannot and will not do these, they are done together afterwards; (4) the small execution packages with exact scope, Hop budget with reasoning, dependencies, checkable acceptance and non-goals, in order, each separable from the human actions; (5) the final consumer qualification as its own package with its acceptance and stop rules, distinct from the BP9 qualification and from release-engineering readiness; it needs a built release candidate and human access to the second repository; assess as an OPTION with a recommendation whether the DMC resumption plan in spreadsheet-handling (docs/warm_storage/global_reviews/architecture_dmc_resumption_review_2026-11-15.adoc, committed there; one of the four staged reviews) can be turned into a planning WorkItem run through WFC as a suitable first stage; (6) the risks, a short release-gate list with owner and verification evidence, and an explicit 'not in this release' list; (7) the few decisions only the maintainer can take, each with a recommendation. PROPORTION (maintainer principle): the plan must be compact (about 450 lines at most; an operating plan, not a report), must not restate the brief or the other plans, and must introduce no new governance entity or register; every package and gate earns its place by a concrete benefit; a package whose cost exceeds its benefit is listed as rejected with the reason; do not repeat the mistake of the P1 plan (over 2,300 lines): cite only what a decision rests on and verify each citation. A Worker never reports any Finding operation (resolve, residual or any other delta); only the independent reviewer opens and resolves Findings. The CommitIntent names every changed leaf individually, never directories; no agent Git writes.

## Withheld authority

No change to any file other than the plan and its review artifacts; no CI or workflow file, no packaging change, no build or publication, no tag, release, push, merge, rebase or Runtime promotion; no credential, no network access, no write to spreadsheet-handling; no decision taken on the maintainer's behalf.

Escalate a missing staged input (name the file), a decision only the maintainer can take, or a plan that cannot be kept compact without dropping a needed package; incomplete work alone is not blocked.
