# Beta-2 O6: docs-render and check-docs targets so every documentation Commission's gate renders what it writes

GOAL. Close `docs/backlog/BUG-WFC-DOCS-RENDER-GATE-COVERAGE.adoc` (friction entry 9, plan slice O6, decision D3 Option A). Add a `docs-render` Make target that strictly renders EVERY `.adoc` under `docs/` and an aggregating `check-docs` target that runs `check` and then `docs-render`, so a documentation Commission can name one evidence command. `make check` and its prerequisite list stay byte-identical (no new prerequisite, because that would make the baseline probe of every Commission depend on Ruby/asciidoctor). No workflow file changes (`.github/workflows/release.yml` is outside the scope ceiling; its eight-entry-document gate stays as it is; mention in the record that the workflow gate is unchanged).

REQUIRED BEHAVIOUR. (1) `docs-render` renders each `.adoc` file under `docs/` (recursively, including `docs/cold_storage` and `docs/warm_storage`) with `asciidoctor --safe-mode=safe -a assembled -o /dev/null --failure-level=WARN`, continues over all files and reports every failing file by path, and exits non-zero if any file fails or if `asciidoctor` itself is missing (a gate that skips when its tool is absent is not a gate: fail with a clear message). It must not write any file into the repository. Make the documentation root overridable (for example `DOCS_ROOT ?= docs`) so the target can be tested against a temporary tree. Keep it fast enough: today the tree has 608 `.adoc` files and a serial render takes about 95 seconds on the development host; a simple loop is fine, no parallelism needed. (2) `check-docs` is `check` followed by `docs-render`, declared in `.PHONY`. (3) Put the loop in a small script under `scripts/` only if one Make line is not enough; follow the neighbouring scripts' style. (4) A guard test under `tests/unit/` runs the target against a temporary documentation tree: a passing file passes; a deliberately malformed file (an incomplete table row, as in friction entry 9) placed under `<root>/backlog/` and under `<root>/warm_storage/` makes the target fail and names the file; a missing `asciidoctor` fails (simulate it with an empty PATH if you can do it robustly). The test follows the repository's availability convention for external tools (see `tests/integration/test_execution_boundary_bwrap.py`): skip only when `asciidoctor` itself is unavailable and say so, never turn a failing target into a skip. (5) The tree must PASS `docs-render` as it stands: it does today for 607 of 608 files; the one failing file is `docs/warm_storage/post-beta-planning/wfc_release_streamlining_broad_review.adoc` (`line 362: dropping cells from incomplete row detected` -- exactly the defect of friction entry 9, still present). Repair ONLY that table row structurally (complete the row's cells so the table is well-formed) without changing its wording or meaning, and state in your result exactly what you changed; it is a historical review record and this is a formatting repair, not a content edit. (6) Document the two targets where the Developer Guide describes `make check` (`docs/developer_guide/ch01_development.adoc`), and add a dated pointer to the record `docs/backlog/BUG-WFC-DOCS-RENDER-GATE-COVERAGE.adoc` that the gate is implemented (status line and a short note), without rewriting its history. Front Door docs-sync: no Front Door behaviour changes; say so.

DESIGN. Mechanical; no design section needed. Safety property preserved: `make check` and every Commission's baseline probe stay independent of the documentation toolchain.
