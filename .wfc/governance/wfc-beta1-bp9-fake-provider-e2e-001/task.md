# BP9: permanent fake-provider end-to-end Beta acceptance test on a non-Python consumer

Implement the permanent end-to-end Beta acceptance test of BP9 as specified in docs/backlog/beta1_execution_plan.adoc section 'BP9 -- wfc-beta1-bp9-beta-gate-001' (Goal, Modules/paths, Acceptance, Tests/evidence) and docs/backlog/beta1_productization.adoc section BP9 (Acceptance direction); read both first. This Commission is only the automated, fake-provider part; the live per-adapter qualification, the Claude record reconciliation and DG-6 are maintainer-owned and out of scope; never infer a live result from a fake provider. Add tests/integration/test_beta_e2e_fake_provider.py with fixtures under the new tests/fixtures/bp9/ (do not modify tests/fixtures/bp4 or any other existing fixture; reuse their patterns). The scenario runs on a neutral NON-Python consumer repository built in a temporary directory (git init, a shell evidence script such as `sh checks/check.sh`, plain text files, no pyproject or Python files in the consumer) with a committed Consumer Config and a scripted fake provider that speaks the real adapter protocol used by tests/fixtures/bp4/fake_provider.py and can be scripted per Hop. It must cover, as separate test functions so one regression never hides another: (a) happy path: `wfc init`-style config, plan preview, `run` with `--yes` (the unattended, scripted path), `status`, `audit`, `report` and the automatic archive into a separate disposable Evidence repository; (b) correction and review cycle under robust@v1 (blocking review Finding, correction, focused and broad acceptance) with Coordinator-owned commits; (c) stops: at least a Hop-ceiling stop and a human-required stop, each classified fail-closed and reported honestly, never as completed; (d) archive retry after an interrupted archive with identical bytes and no duplicate commit; (e) a deliberate failure (evidence command failing, and a provider that returns malformed output) that must be refused or stopped, never accepted. Drive the real installed or in-repository `wfc` entry point for the `--yes` path and use the in-process lifecycle seams (as tests/unit/test_postrun_lifecycle.py does) where a subprocess adds no assurance; document in the test module docstring which parts use which. Each test must be mutation-sensitive (name the mutation it kills in a comment) and hermetic: no network, no real provider, no writes outside tmp_path and a throwaway HOME/XDG_STATE_HOME. If one scenario needs a product mechanism that does not exist, do not add a product mechanism: report the real gap instead. Keep the whole suite fast. A Worker never reports any Finding operation (resolve, residual or any other delta); only the independent reviewer opens and resolves Findings. The CommitIntent names every changed leaf individually, never directories; no agent Git writes.
