# Beta-2 operator efficiency: analysis of the Front Door, Agent Skill and Operator Manual friction, backlog records and an executable plan

GOAL. Analyse where the WFC Front Door, the shipped Agent Skill and the Operator Manual make the Level-1 operator agent's work error-prone, mechanical or token-expensive, derive concrete improvement candidates, record the worthwhile ones as FTR/BUG records in the backlog, and write an executable Beta-2 implementation plan (order, dependencies, sizing, qualification) for the ones that should still be addressed in Beta 2. This is PLANNING and DOCUMENTATION only: shift-left work (strong model for the high-consequence design judgement), no code, no test, no product change. The repository owner will read the result and decides the Beta-2 cut; the implementation Commissions follow only after that decision.

WHY NOW. The Level-1 operator (a Claude session that authors Commissions, runs `wfc plan`/`wfc run`, watches Runs and integrates results) spent a large share of a long session on avoidable mechanics and recoverable mistakes. The friction is recorded in `docs/warm_storage/post-beta-planning/wfc_level1_operator_friction_log.adoc` (entries 1-21, dated 2026-11-25/26): read ALL of it. Goal of the effort: fewer errors, less mechanics, less cognitive overhead for the operator agent, and, secondarily, fewer tokens. Stability and reliability weigh more than token savings. The repository owner's rule of proportion: do not burden agents (Workers, Reviewers) with what a cheap deterministic step decides; a mechanical defect must not cost a Worker correction plus a Focused and a Broad Review.
