# Raise the default Hop timeout to 4 hours and add the hop_timeout_seconds repository default

GOAL. Raise the Front Door's default per-Hop timeout and make it a repository default that a consumer can set in `.wfc/config.yaml`. The Hop timeout is a CAP, not a safety margin or a budget: it exists only to end a genuinely hung provider invocation, and a normal Hop must practically never reach it. Hops have become longer because larger blocks are commissioned, and the current 900-second default repeatedly stopped real work (the operator had to pass `--hop-timeout-seconds 3600` or `7200` on every run).

REQUIRED BEHAVIOUR.
1. The built-in default `DEFAULT_HOP_TIMEOUT_SECONDS` in `src/workflow_coordinator/frontdoor/lifecycle.py` becomes 14400 seconds (4 hours). Name the value once, in that constant.
2. `.wfc/config.yaml` (the Consumer Config, parsed by `src/workflow_coordinator/frontdoor/config.py`, `consumer_config_from_yaml`) accepts an OPTIONAL top-level key `hop_timeout_seconds`: a positive number (int or float; reject bool, zero, negative, NaN/infinity and non-numbers) with a clear `CommissionError` message in the style of the neighbouring keys. A config without the key behaves exactly as before except for the new built-in default. Add the field to `ConsumerConfig` with a default so every existing construction keeps working.
3. Precedence for `wfc run`: explicit `--hop-timeout-seconds` flag, then the config key, then the built-in default. The flag's argparse default must therefore become `None` (distinguishing "not given" from "given"), the help text must state the precedence and the default, and the resolved value is the one recorded in the authorization data exactly as today (`hop_timeout_seconds` in `src/workflow_coordinator/frontdoor/lifecycle.py`), so `wfc resume` and every later consumer of the recorded value stay unchanged. The flag keeps rejecting non-positive values as it does today (check current behaviour and preserve it; if it currently accepts them, keep exactly that and say so in the review artifact).
4. Do not set the key in this repository's own `.wfc/config.yaml` (not in scope, maintainer's file). Do not add runtime gates, hooks or other mechanisms; this is one optional config key plus a new default.
5. Evidence timeout (`DEFAULT_EVIDENCE_TIMEOUT_SECONDS`, the `--evidence-timeout` of `wfc plan`) is a different mechanism and stays unchanged.
