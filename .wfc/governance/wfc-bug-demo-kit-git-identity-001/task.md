# Correct BUG-WFC-CONSUMER-DEMO-KIT-GIT-IDENTITY: the consumer demo kit must not depend on a host Git identity

Read `docs/backlog/BUG-WFC-CONSUMER-DEMO-KIT-GIT-IDENTITY.adoc` first; it is the controlling record and states the observed hosted failure (workflow `release.yml`, run 45345678011, job 138279509647, commit 3379a03: 15 failed tests in `tests/integration/test_consumer_demo_kit.py`, all `wfc init: failed to create the initial Evidence repository commit: Author identity unknown`), the verified cause and where the correction belongs. The job log is external evidence and is not available inside this Run; do not claim to have read it.

THE DEFECT. `examples/consumer-demo/make_workspace.py` gives the demo repository `greeter` a repository-local identity but none to the Evidence repository `greeter-evidence`, which `wfc init` creates and commits to; `examples/consumer-demo/rehearse.py` runs `wfc run` under the workspace's `rehearsal-home` without `XDG_CONFIG_HOME`, where the archive commit into the Evidence repository again finds no identity. The kit's tests hide the host configuration on purpose (`throwaway_home`) and pass on this host only because Git falls back to the account's name in the password database; the hosted runner's account has none.

WHAT TO DO. (1) Verify the cause yourself before changing anything: disable Git's fallback with `user.useConfigOnly = true` in a configuration file Git reads (WFC's trusted Git execution removes every inherited `GIT_*` variable, so an environment variable cannot do it and must not be the mechanism) and observe both failures: workspace creation, and a rehearsal that archives. (2) Make the kit's tests deterministic first: under the tests' isolation the absence of any host identity must hold on every host, so that the affected tests fail against the unchanged kit on this host. Run them against the unchanged kit and record the red result. (3) Correct the kit so that workspace creation and every scripted rehearsal supply, through Git configuration files inside the workspace, every identity they need. Choose the smallest mechanism that respects WFC's contract (identity from Git configuration files, never from `GIT_*` variables) and say why you chose it. (4) Record the outcome in the BUG record.

FIXED POINTS. `wfc init`, the Evidence repository initialization, the trusted Git execution and the hosted workflow are correct as they are and are outside the scope. The workspace layout (directory names) stays. The kit files that the tutorials quote byte for byte (`requests/*.task.md`, `requests/*.request.yaml`; guard `tests/architecture/test_tutorial_kit_quotes.py`) stay unchanged. Kit modules import only the standard library. The kit never reads or writes the host's Git configuration and writes nothing outside the workspace.
